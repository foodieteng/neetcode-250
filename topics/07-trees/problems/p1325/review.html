重點回顧// RECAP

面向要記住的那一句
走訪順序後序:先清左右子樹,再判自己
為什麼後序是不是葉子由最終的小孩決定,要等小孩處理完才知道
連鎖刪除不用多跑幾輪 —— 後序一趟自動完成(對拍 129956 + 200000 組,0 不一致)
怎麼「刪」回傳 nullptr,父節點的 root->left = ... 把邊切掉
刪除條件!left && !right && val == target,三個缺一不可
最常見的錯前序判斷(錯 37770)、沒接回(錯 96420)—— 最小反例都是 [1,null,1], t=1
根也可能被刪回傳值才是新的根;忽略它只在「整棵刪光」時露餡(錯 1250)
成本呼叫恰好 2n+1 次 → O(n);堆疊 O(h),斜鏈 3000 層實跑正常

觀念題// CONCEPT Q&A

Q1. 題目說「刪完之後父節點若變成 target 葉子也要刪,一直做到不能再刪」。為什麼這份程式碼只走一趟就夠了?
Q2. 把判斷那一行搬到兩個遞迴前面(前序),會錯在哪裡?請給出最小反例。
Q3. 為什麼一定要寫 root->left = removeLeafNodes(...),而不是單純呼叫 removeLeafNodes(root->left, target);?
Q4. 刪除條件寫成 (!root->left || !root->right) && root->val == target 會怎樣?
Q5. 刪掉的節點越多,程式會跑得越快嗎?總共會呼叫幾次?

範例 Trace// 範例 3 · 一路往上連鎖

[1,2,null,2,null,2],target = 2:一條往左的鏈 A=1 → B=2 → C=2 → D=2。 B、C 一開始都不是葉子,全靠下一層被刪才變成葉子 —— 連鎖三層。以下是實跑的回傳順序。

// STEP 1: 一路往左下降到最底 f(A) → f(B) → f(C) → f(D) → f(D->left)=nullptr、f(D->right)=nullptr
// STEP 2: 從最底往上回傳 D(2) 左空 ✓ 右空 ✓ val==2 ✓ → return nullptr ← C->left = nullptr C(2) 左空 ✓ 右空 ✓ val==2 ✓ → return nullptr ← B->left = nullptr ★ 剛變成葉子 B(2) 左空 ✓ 右空 ✓ val==2 ✓ → return nullptr ← A->left = nullptr ★ 剛變成葉子 A(1) 左空 ✓ 右空 ✓ val==2 ✗ → return A (是葉子,但值不對 → 保留)
// STEP 3: 計數 4 個真節點 + 5 個空指標 = 9 次呼叫 = 2·4 + 1 // OUTPUT: [1]
「照字面模擬」要跑 3 輪才能剝完 D、C、B;後序在回程上一層一層剝,一趟就完成。 最後的 A 也值得注意:它確實變成了葉子,但 1 ≠ 2,所以三個條件缺一個,保留。

應用題// APPLY IT

App 1. Binary Tree Pruning(LeetCode 814):節點值只有 0 或 1,刪掉所有「不含任何 1」的子樹。能直接用這題的程式碼嗎?
App 2. 在自己的專案裡(不是 LeetCode),被刪的節點要真的釋放記憶體。delete 要加在哪裡?為什麼在這裡刪不會漏掉整棵子樹?
App 3. Find Leaves of Binary Tree(LeetCode 366):每一輪收集所有葉子並刪掉,重複到樹空為止,回傳每一輪的葉子。怎麼用「後序」一趟算出每個節點屬於第幾輪?
// ANSWERS
A1. 因為後序判斷一個節點時,它的小孩已經是「最終版本」。

一個節點該不該刪,只取決於「自己的值」和「最終有沒有小孩」;而小孩最終存不存在,只取決於各自的子樹。 後序保證兩個子樹都已經處理完、結果也接回來了,所以此刻看到的就是最終答案,不會再變。 刪掉自己只會影響父節點,而父節點的判斷本來就排在後面。

實測:和「反覆掃到沒有變化」的模擬解對拍,窮舉 129956 組 + 隨機 200000 組,不一致 0。
A2. 前序判斷時,小孩還沒被清掉,所以「之後才會變成葉子」的節點會被放過。

最小反例:[1,null,1],target = 1。
· 前序:看根時它還有右小孩 → 不是葉子,保留;接著右小孩被刪 → 根變成葉子,但沒有人回頭再看它 → 回 [1]。
· 正解:右小孩先被刪,根變成值為 1 的葉子 → 也刪 → []。

窮舉 129956 組中錯 37770 組。官方範例 2 照樣會過,只有範例 1、3 抓得到 —— 所以要自己準備連鎖的測資。
A3. 因為「刪除」就是靠回傳值完成的。

子節點被刪時,遞迴只是回傳 nullptr,並不會自己去改父節點的指標。 沒有 root->left = ... 這個賦值,父節點仍然指著舊的子節點,那條邊根本沒被切掉。

實測錯 96420 / 129956;最小反例同樣是 [1,null,1], t=1 → 回 [1,null,1](什麼都沒刪)。 450 刪除 BST 節點也是同一個模式:回傳新的子樹根,讓父節點接住。
A4. 「只缺一邊小孩」的節點會被當成葉子刪掉,連帶丟掉它保留下來的那一邊子樹。

最小反例:[1,null,2],target = 1。根只有右小孩 2(不是 target,保留), 用 || 時根被判成「葉子」而刪除 → 回 [],連 2 一起不見了;正解是 [1,null,2]。

實測錯 107544 / 129956。葉子的定義是兩邊都沒有小孩,必須用 &&。
A5. 不會。不論刪多少,都恰好呼叫 2n+1 次。

要知道一個節點能不能刪,得先把它整棵子樹處理完,所以每個節點都一定會被拜訪; 再加上 n 個節點一共有 n+1 個空指標,每個也各被呼叫一次。

實測 n = 3000:全部是 target(整棵刪光)和完全沒有 target(原樹不變),都是 6001 次。 差別只在堆疊深度:完全二元樹 13 層,斜鏈 3001 層。
A-App 1. 可以,等於 removeLeafNodes(root, 0)。

「反覆刪掉值為 0 的葉子」會把全是 0 的子樹從底部一層層剝光; 而只要子樹裡有一個 1,那個 1 永遠不會被刪,它的所有祖先也就永遠有小孩、永遠不會變成葉子,於是保留。 兩個定義刪掉的恰好是同一批節點 —— 一樣是後序、一樣是回傳 nullptr 讓父節點接住。

實測:和 814 的直接寫法(「值是 1 或還有小孩就保留」)對拍隨機 100000 組(1~14 個節點),不一致 0。
A-App 2. 在決定刪除、回傳 nullptr 之前 delete root;。

if (!root->left && !root->right && root->val == target) { delete root; return nullptr; }

為什麼不會漏:會走到這一行的節點,左右都已經是空的(條件本身就要求),它原本的小孩要嘛已經在更早的遞迴裡被 delete,要嘛根本不存在。 所以刪的一定是一個光桿節點,不會留下懸空的子樹。 原版不 delete 的後果:全 target 的 3000 節點斜鏈,3000 個節點脫離樹但沒被釋放。
A-App 3. 後序算「高度」:葉子是第 0 輪,其他節點 = max(左高度, 右高度) + 1。

一個節點會在第幾輪變成葉子,取決於它最慢被剝光的那一邊小孩,所以正好是它到最深葉子的距離。 和本題一樣,必須先知道小孩的答案才能算自己 —— 後序;把節點值 push 進 result[height] 就是答案,一趟 O(n)。 本題可以看成它的「只剝 target、剝到剝不動」版本。

// ONE-LINE TAKEAWAY
是不是葉子由最終的小孩決定,所以後序:先清小孩、接回,再判自己,連鎖刪除一趟完成。範例 3 的鏈照字面要剝 3 輪,後序在回程一層層剝完;呼叫次數永遠是 2n+1,不因刪得多而變少。
