題目簡介// THE QUESTION

QUESTION

給二元樹的根 root 和整數 target,刪掉所有值等於 target 的葉節點。
刪完之後,如果父節點因此變成葉子、而且值也是 target,它也要刪 —— 一直做到不能再刪為止。
節點數 1 ~ 3000,1 ≤ val, target ≤ 1000。整棵樹可能被刪光(回傳 nullptr)。

題目那句「一直做到不能再刪為止」聽起來像要跑很多輪。 其實只要走訪的順序選對,一趟就做完 —— 難點不在刪除本身,而在「什麼時候才有資格判斷一個節點是不是葉子」。

一個節點是不是葉子,要等它的小孩都處理完才知道。 所以判斷必須放在兩個遞迴之後 —— 也就是後序。 放在之前(前序),就會看到「還沒清理的舊小孩」而判錯。
2

為什麼是後序// WHY THIS

A 照字面模擬:反覆掃整棵樹 多輪 · 每輪 O(n)
每輪刪掉現有的 target 葉子,直到某一輪什麼都沒刪。 答案是對的(驗證時我就拿它當對拍的參考解), 但一條長度 k 的 target 鏈要跑 k 輪 —— 每一輪只能剝掉最底下那一層。
× REJECT · 輪數跟鏈長成正比
B 前序:先判自己,再遞迴小孩 一趟,但會漏
判斷的時候小孩還沒被清掉,所以「之後才會變成葉子」的節點被放過了。 實測窮舉 129956 組,錯 37770 組;最小反例 [1,null,1], target=1 → 回 [1](正解 [])。
△ REJECT · 連鎖刪不掉
BOTH FAIL · ADOPT
C 後序:先清左右子樹,接回來,再判自己 一趟 · O(n)
走到自己的判斷那一行時,root->left / root->right 已經是清理完的最終版本。 所以「因為小孩被刪才變成葉子」的節點,在同一趟裡就會被抓到 —— 連鎖刪除是順序自動帶出來的,不用額外處理。
● ADOPT · 一趟清完
3

核心策略 · 三步驟// THE SHAPE

  1. 空節點直接回 nullptr。
  2. 遞迴左、右子樹,並把回傳值接回 root->left / root->right —— 小孩被刪時,回傳的 nullptr 就是切斷那條邊的方式。
  3. 三個條件同時成立才刪自己:左空、右空、val == target。 刪就回 nullptr,否則回 root。
「回傳新的子樹根,讓父節點接住」 就是 450 刪除 BST 節點的同一套寫法。 刪除不用去找父節點,也不用記 parent 指標 —— 回傳 nullptr,父節點那一行賦值就把邊切掉了。

為什麼一趟就夠// ONE PASS LEMMA

LEMMA · 後序判斷時看到的小孩,就是最終的小孩

一個節點會不會被刪,只取決於它自己的值和它「最終」有沒有小孩。 而它的小孩最終是否存在,只取決於各自的子樹 —— 跟祖先、跟兄弟都無關。

後序保證:處理 root 的判斷之前,左右子樹都已經遞迴處理完、結果也接回來了。 刪掉 root 只會影響它的父節點,而父節點的判斷本來就排在 root 之後。 所以沒有任何節點需要「回頭再看一次」 —— 題目說的「重複到不能再刪」,在後序裡一趟就收斂了。

實測:和「反覆掃到沒有變化」的模擬解對拍, 窮舉 129956 組(1~7 個節點的所有樹形,值 ∈ {1,2})+ 隨機 200000 組,不一致 0。

複雜度// COMPLEXITY

每個節點被呼叫一次,每個空指標也被呼叫一次:n 個節點有 n+1 個空指標,所以總呼叫次數恰好 2n+1。

時間 O(n)(呼叫 2n+1 次)　·　空間 O(h)(遞迴堆疊)
情境(n = 3000)呼叫次數最大深度結果
左斜鏈,全部 = target60013001[]
左斜鏈,只有根 ≠ target60013001只剩根
完全二元樹,全部 = target600113[]
完全二元樹,沒有 target600113原樹不變
不管刪多少,呼叫次數都一樣是 2n+1 —— 刪除不會省掉任何走訪,因為要刪一個節點,得先把它整棵子樹看完。 深度 3001 的斜鏈實跑沒有問題(含 ASan/UBSan 也乾淨)。

一句洞察// INSIGHT

「是不是葉子」是由小孩決定的,所以要先處理小孩 —— 這就是後序。 後序的判斷看到的是清理完的最終小孩,連鎖刪除在同一趟裡自動完成; 回傳 nullptr 讓父節點接住,就是切斷那條邊。
