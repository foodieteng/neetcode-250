題目簡介// THE QUESTION

QUESTION

給 BST 的根節點和一個值 val,把它插入並回傳新的根。 題目說「可能有多種合法插法,回傳任何一種都可以」。
節點數 0 ~ 10⁴,值域 ±10⁸,值互不相同, 且保證 val 原本不在樹裡。

這題的下降邏輯和 235 BST LCA 一樣簡單 —— 比大小、二選一、走到底。 真正的重點在「走到底之後」:新節點要怎麼接回樹上。

這是本章第一題「遞迴會產生新節點」的題目。 前面的題目遞迴回傳的都是本來就存在的節點, 這題的 base case 會 new 一個全新的節點出來 —— 而那個新節點只存在於回傳值裡。 所以 root->left = insertIntoBST(...) 那個回寫,是它唯一的接線機會。
2

回寫這一行為什麼不能省// WHY THIS

A 遞迴但不接住回傳值 錯 4706/4707
寫成 insertIntoBST(root->left, val);(沒有賦值)。 新節點被 new 出來、回傳、然後掉在地上 —— 樹原封不動,而且那個節點洩漏了。 實測:只要樹非空,必錯。
× REJECT · 接不上去
B base case 回傳 nullptr 錯 4707/4707
連空樹都錯,零巧合。 值被安靜地吞掉,樹完全沒變 —— 不會崩、不會報錯,只是什麼都沒發生。
× REJECT · 全盤失效
ADOPT
C root->left = insertIntoBST(root->left, val); O(h) 時間 · 1 次配置
遞迴拿到的是「root->left 這個 nullptr 的副本」 —— 它 new 出來的節點沒有任何路徑能回到父節點的 left 欄位。 這個賦值就是唯一的那條路。
● ADOPT · 回寫接線
⚡ 和 226 翻轉二元樹對照,這件事就完全清楚了。 那一題的同一行 root->left = invertTree(root->left) 是冗餘的 —— 因為那個遞迴只改動既有節點的內容,回傳的永遠是傳進去的同一個指標, 所以那是個恆等賦值。 判準只有一句:「遞迴會不會產生新節點、或換掉子樹的根?」 會 → 回寫是接線;不會 → 回寫是裝飾。 實測量化:226 的回寫拿掉錯 0 組;701 的回寫拿掉錯 4706/4707。
3

核心策略 · 兩個階段// THE SHAPE

階段一 · 下降(和 BST 搜尋一模一樣)

  1. root->val > val → 往左;root->val < val → 往右。
  2. 一路走到 nullptr —— 那就是 val 該待的空位。

階段二 · 回程接線

  1. base case:return new TreeNode(val); —— 新節點誕生,但還沒接上任何人。
  2. 每一層把回傳值寫回自己的 left / right。
  3. return root; —— 把原本的根交出去(根沒有被換掉)。
整條回程上有 h 個回寫,但只有最底下那一個真的存了新東西 —— 上面每一層都是「把原本就在那裡的指標再寫一次」。 可是你事先不知道哪一層才是真的那一層,所以每一層都得寫。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 回寫什麼時候是接線、什麼時候是裝飾

node->child = recurse(node->child, ...) 這個模式在樹題裡到處都是, 但它有時必要、有時冗餘。分界線只有一條: 「這個遞迴會不會產生新節點、或換掉子樹的根?」

· 701(這題):base case new 一個節點出來, 而遞迴收到的是 nullptr 的副本 —— 新節點沒有任何路徑能自己回到父節點的欄位。 實測拿掉回寫:錯 4706/4707, 而且失敗集合以集合相等驗證恰好等於「原樹非空」(零分歧)。 唯一答對的那 1 組是空樹 —— 那時新節點由最外層直接回傳,根本沒經過賦值。
· 226 翻轉:遞迴只改既有節點的內容, 回傳的永遠是傳進去的那個指標 ⇒ 賦值是恆等的。 實測拿掉回寫:錯 0 組。
同一行程式碼,一邊 4706/4707、一邊 0/N。

LEMMA 2 · 新節點永遠是葉子(而且只配置一次)

這個作法從不重組既有結構 —— 它只是往下走到一個空位,把新節點掛上去。 所以新節點必定是葉節點,既有節點一個都不動。

實測(窮舉 n = 0..7 的全部 626 棵 BST × 每一個可能的插入位置,共 4707 組):
· 插入後仍是合法 BST → 0 違反
· 節點集合恰好等於原集合 ∪ {val} → 0 違反
· 新節點永遠是葉子 → 0 違反
· new TreeNode 恰好 1 次 → 0 違反
· 呼叫次數 == 新葉子的深度 + 1 → 0 違反
題目說「可以回傳任何一種合法插法」,但這個作法其實是唯一決定的 —— 實測與獨立的迭代版對拍 20 萬組 + 窮舉 4707 組,樹形逐位元相同。

// 八種改法的實測結果(626 棵 BST × 每個插入位置,共 4707 組) 丟掉回寫(不接住回傳值) → 錯 4706/4707,唯一對的是空樹 ← 本題主角 比較方向相反 → 錯 4706/4707,最小反例 tree=[0] val=-1 → [0,null,-1] base case 回傳 nullptr → 錯 4707/4707,零巧合,值被安靜吞掉 忘記 return root → 錯 4706/4707,回傳的是子樹的根 ⇒ 上半棵樹全丟 總是插在第一個空位 → 錯 4081/4707,巧合 626 組(每棵樹恰好 1 個值會蒙對) 缺 nullptr base case → SIGSEGV,「任何一組都會炸」,連空樹都是 新節點的子指標沒初始化 → 插入當下不炸,「下一次走訪」才 SIGSEGV ← 延遲爆炸 用 >= 而非 > → 錯 0/4707,「完全等價」(因為 val 保證不存在) // 注意倒數第二列:那種「延遲爆炸」比當場崩潰難 debug 得多

一句洞察// INSIGHT

遞迴收到的是指標的副本,所以它 new 出來的節點沒有路回家 —— node->child = recurse(...) 那個回寫,就是唯一的那條路。
判準記這一句:「遞迴會不會產生新節點、或換掉子樹的根?」 會 → 回寫是接線(這題,拿掉錯 4706/4707); 不會 → 回寫是裝飾(226 翻轉,拿掉錯 0)。
