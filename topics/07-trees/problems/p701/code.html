解法 A · 遞迴(你的寫法)// WRITE-BACK

p701_recursive.cpp C++17 
class Solution {
public:
    TreeNode* insertIntoBST(TreeNode* root, int val) {
        // 走到空位 —— 新節點在這裡誕生
        if (root == nullptr) {
            return new TreeNode(val);
        }

        if (root->val > val) {
            root->left = insertIntoBST(root->left, val);    // ← 回寫:接線
        } else if (root->val < val) {
            root->right = insertIntoBST(root->right, val);   // ← 同上
        }

        return root;   // 根沒被換掉,原樣交出去
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

沒有 else 分支處理 root->val == val —— 因為題目保證 val 原本不在樹裡。 萬一真的相等,兩個分支都不進,直接 return root —— 實測:樹完全不變、0 次配置、回傳的還是同一個物件。 不會崩,只是什麼都沒做。

解法 B · 迭代(自己記住父節點)// O(1) SPACE

p701_iterative.cpp C++17 
class Solution {
public:
    TreeNode* insertIntoBST(TreeNode* root, int val) {
        if (root == nullptr) {
            return new TreeNode(val);
        }

        TreeNode* parent = nullptr;
        TreeNode* curr = root;

        while (curr != nullptr) {
            parent = curr;
            curr = (curr->val > val) ? curr->left : curr->right;
        }

        // 迴圈結束時 parent 就是那個「該掛新節點」的節點
        if (parent->val > val) {
            parent->left = new TreeNode(val);
        } else {
            parent->right = new TreeNode(val);
        }

        return root;
    }
};
迭代版必須自己記住 parent,理由和遞迴版的回寫一模一樣 —— 走到 nullptr 的時候,curr 只是一個空指標的副本,它不知道自己是誰的小孩。 遞迴版靠「還沒返回的堆疊框」記住這件事,迭代版靠一個 parent 變數。 兩者都是在買同一份資訊。 實測:兩版在窮舉 4707 組 + 隨機 20 萬組上,樹形逐位元相同。

⚡ 回寫實測 · 同一行,兩種命運// THE CENTREPIECE

node->child = recurse(node->child, ...) 這個模式在樹題裡到處都是, 但它有時是接線、有時是裝飾。 下面是把兩題放進同一支程式跑出來的結果。

// 同一支程式、同一個窮舉宇宙,兩題各跑「有回寫」與「無回寫」兩版 === 226 翻轉二元樹:回寫 vs 不回寫 === 比較 626 棵樹,結果不同 = 0 ← 回寫是「裝飾」 === 701 插入 BST:回寫 vs 不回寫 === 比較 4707 組,結果不同 = 4706 ← 回寫是「接線」 「不回寫」意外答對的 = 1 組(而且全部是空樹) 失敗集合的特徵刻畫(以「集合相等」驗證,零分歧): { 不回寫會失敗 } ≡ { 原樹非空 } // 唯一答對的那組是空樹 —— 那時新節點由最外層「直接回傳」,根本沒經過任何賦值

但兩邊都寫它並沒有壞處 —— 它讓「這一層可能換掉子樹的根」這件事自動被處理掉, 不必在父節點裡寫一堆 if。

邊界與陷阱// PITFALLS

窮舉 626 棵 BST(值集 {0,2,4,…},n=0..7)× 每一個 odd gap 插入值 = 4707 組。

陷阱失敗數最小反例症狀
丟掉回寫(不接住回傳值) 4706/4707 tree=[0] val=-1 → [0] 新節點被 new 出來然後掉在地上,還洩漏了
比較方向相反 4706/4707 tree=[0] val=-1 → [0,null,-1] 掛到錯的一邊,結果不再是 BST
base case 回傳 nullptr 4707/4707 tree=[] val=-1 → [] 零巧合 —— 值被安靜吞掉,不崩不報錯
忘記 return root 4706/4707 tree=[0] val=-1 → [-1] 回傳的是子樹的根,上半棵樹整個丟掉
總是插在第一個空位(不比大小) 4081/4707 — 巧合 626 組 —— 每棵樹形恰好 1 個值會蒙對
缺 nullptr base case SIGSEGV tree=[] val=-1 任何一組都會炸,連空樹都是
新節點的子指標沒初始化 延遲 SIGSEGV tree=[0] val=-1 插入當下不炸,「下一次走訪」才炸 —— 最難 debug
用 >= 而非 > 0/4707 — 完全等價 —— 但這依賴題目約束,見下方走讀
「新節點的子指標沒初始化」那一列值得單獨記。 題目給的 TreeNode 建構子會把 left、right 設成 nullptr, 所以你平常不會想到這件事。但如果換成一個不初始化的 struct, 插入那一刻完全正常 —— 要等到下一次走訪(序列化、再插入、印答案) 沿著垃圾指標走下去,才會 SIGSEGV。 這種「延遲爆炸」比當場崩潰難追得多。

// PHASE 1: 為什麼新節點「沒有路回家」 關鍵在 C++ 的參數傳遞:遞迴收到的是「指標的副本」 root->left = insertIntoBST(root->left, val); ~~~~~~~~~~ 傳進去的是「root->left 這個 nullptr 的一份拷貝」 所以在遞迴內部: if (root == nullptr) return new TreeNode(val); ~~~~ 這個 root 是「副本」,把它指向新節點「不會」影響外面的 root->left 新節點誕生時,它「只存在於回傳值裡」—— · 樹上沒有任何節點指向它 · 它自己也不知道該掛在誰底下 → 唯一能把它接上去的,就是外面那個賦值 實測(集合相等驗證,零分歧): { 丟掉回寫會失敗 } ≡ { 原樹非空 } 4706/4707 唯一答對的是空樹 —— 那時新節點由「最外層」直接回傳,沒經過賦值 // 如果 C++ 有「傳指標的參考」(TreeNode*&),就可以直接改外面的欄位,回寫才真的能省
// PHASE 2: 回程上有 h 個回寫,但只有一個真的存了東西 以 [40,20,60,10,30,50,70] 插入 25 為例(實測呼叫樹): 1. insert(40, 25) 40 > 25 → 往左 [40.left 的賦值:掛起] 2. insert(20, 25) 20 < 25 → 往右 [20.right 的賦值:掛起] 3. insert(30, 25) 30 > 25 → 往左 [30.left 的賦值:掛起] 4. insert(nullptr, 25) → return new TreeNode(25) 5. ← 30.left = 新節點 ★★★ 這一個才是真的接線 6. ← 20.right = 30 (原本就是 30,恆等賦值) 7. ← 40.left = 20 (原本就是 20,恆等賦值) return 40 呼叫次數 = 4 = 新葉子的深度(3) + 1 三個回寫裡「只有一個」存下了新指標 ⇒ 但你「事先不知道」哪一層才是真的那一層,所以每一層都得寫 // 這也解釋了為什麼「丟掉回寫」在小測資上看起來好像沒事 —— 大部分賦值本來就是恆等的

// PHASE 4: >= 和 > 為什麼「這題」等價(但別養成習慣) 實測:把 > 改成 >=,4707 組「零失敗」—— 完全等價 原因:題目保證 val「不在樹中」 量測:4707 組共走訪 17138 個節點,root->val == val 出現「0 次」 ⇒ > 和 >= 唯一的分歧點(相等)永遠不可達 ⚠ 但這個等價「依賴題目約束」: 如果允許重複值,兩者行為就分岔了 —— >= 版:相等時往左插(產生重複節點) > 版:相等時兩個 if 都不進,直接 return root(什麼都不做) // 「因為約束所以等價」和「本來就等價」是兩件事 —— 面試時值得說清楚是哪一種
