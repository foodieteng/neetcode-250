解法 A · 由上往下(你的寫法)// TOP-DOWN

p110_topdown.cpp C++17 
class Solution {
public:
    bool isBalanced(TreeNode* root) {
        if (root == nullptr) return true;

        int left = depth(root->left), right = depth(root->right);
        return abs(left - right) <= 1
            && isBalanced(root->left)       // ← 「每一個節點」靠這兩行
            && isBalanced(root->right);
    }

    int depth(TreeNode* root) {
        if (root == nullptr) return 0;

        return 1 + max(depth(root->left), depth(root->right));
    }
};

解法 B · 由下往上(一趟走完)// BOTTOM-UP

p110_bottomup.cpp C++17 
class Solution {
public:
    bool isBalanced(TreeNode* root) {
        return check(root) != -1;
    }

    // 回傳高度;只要底下任何一處不平衡,就回傳 -1 並一路往上傳
    int check(TreeNode* root) {
        if (root == nullptr) return 0;

        int left = check(root->left);
        if (left == -1) {
            return -1;                   // 左邊已經壞了,不必再算右邊
        }

        int right = check(root->right);
        if (right == -1) {
            return -1;
        }

        if (abs(left - right) > 1) {
            return -1;                   // 這一層不平衡
        }

        return 1 + max(left, right);       // 平衡,回傳真正的高度
    }
};
核心手法:用一個「不可能的回傳值」兼作失敗旗標。 高度永遠不可能是負的,所以 −1 拿來表示「底下壞掉了」不會和真實高度混淆。 實測:窮舉 2056 種樹形,兩種寫法答案完全一致(失敗 0)。 更通用的做法是回傳一個 pair<int,bool> —— 可讀性更好,也不依賴「剛好有個不可能的值」這件事。

複雜度分析// COMPLEXITY

⚠ 這一節推翻一個很常見的說法。 幾乎所有題解都寫「由上往下是 O(n²),最壞情況是退化成一條鏈」。 實測結果:退化鏈反而是線性的,而真正的上限是 O(n log n)。

// 為什麼退化鏈不是最壞情況(實測) 一條長度 n 的鏈,在「根節點」就會發生什麼? depth(左) = n-1,depth(右) = 0 abs(n-1 - 0) > 1 → 第一個條件就 false → && 短路,「兩個 isBalanced 遞迴完全不會被呼叫」 實測 isBalanced() 呼叫次數:不論鏈多長,永遠是 1 次 depth() 呼叫次數(退化左鏈): n = 250 → 500 次 n = 500 → 1000 次 成長倍率 2.000 n = 1000 → 2000 次 成長倍率 2.000 n = 2000 → 4000 次 成長倍率 2.000 ← 每次加倍只變 2 倍 = 線性 若真的是 O(n^2),n=2000 應該要 n(n+1) = 4002000 次 —— 實測只有 4000 次,差 1000 倍 // 短路把「最壞情況」直接砍掉了 —— 這是紙上分析很容易漏掉的一環
// 真正的最壞情況是「平衡樹」(因為它會被完整走完) 一棵樹要被「完整探索」,代表它處處通過檢查 ⇒ 它是平衡的 而平衡樹的高度 h = O(log n) ⇒ 每個節點最多被重複走 O(log n) 次 ⇒ 上限是 O(n log n),不可能到 O(n^2) 實測 depth() 呼叫次數(完美樹): n = 143 → 由上往下 / 由下往上 = 6.5 倍 n = 1023 → 18434 / 2047 = 9.0 倍 n = 4095 → 90114 / 8191 = 11.0 倍 n = 4180(最深的合法 AVL)→ 96420 / 8361 = 11.5 倍 倍率每次加倍約 +0.7 —— 正是 Θ(log n) 的成長 // 「由上往下比由下往上慢多少」的答案是 O(log n) 倍,不是 O(n) 倍

「用節點數代替高度」那一列值得單獨記。 它只會誤殺、永遠不會漏抓(42 個失敗全部是「把平衡樹判成不平衡」)—— 因為「左右節點數差 ≤ 1」是比「左右高度差 ≤ 1」嚴格得多的條件。 知道一個 bug 的錯誤「方向」(過嚴 vs 過鬆),往往比知道它錯幾筆更有用。
