二元樹的最大深度

完整實作// TWO LINES

p104.cpp C++17 
class Solution {
public:
    int maxDepth(TreeNode* root) {
        if (root == nullptr) return 0;   // 空樹沒有節點,深度 0

        return 1 + max(maxDepth(root->left),    // 左邊有多深
                       maxDepth(root->right));  // 右邊有多深 → 取深的,加自己這層
    }
};

兩行,三個決定:0 是「空樹沒有節點」、 +1 是「算上我自己」、max 是「深度看比較深的那一邊」。 實測窮舉 626 種樹形,這三個決定各自寫錯,分別錯 626、625、622 種。

最後一列值得特別記。「把 base case 寫成葉節點判斷」在滿二元樹 (每個節點0 個或 2 個小孩)上永遠不會踩到 nullptr —— 實測 626 種樹形裡有 9 種是滿二元樹,這 9 種它全部答對、也不崩。 如果你的測資剛好都是完美/滿二元樹,這個 bug 完全隱形。

// PHASE 1: 為什麼 1 + min(...) 不是「最小深度」(LC111) 最小深度的定義:根到「最近的『葉節點』」的節點數 葉節點的定義:左右子樹「都」是空的 問題出在「只有單邊子樹」的節點: [1,null,2] 節點 1 有右小孩、沒有左小孩 1 + min(maxDepth(null), maxDepth(2)) = 1 + min(0, 1) = 1 + 0 = 1 ← 被「不存在的空子樹」吃掉了 但深度 1 的位置是節點 1,它「有小孩」,不是葉節點! 真正的 minDepth = 2(路徑 1 → 2) 實測:1+min 與真正的 minDepth 在 496/626 種樹形上不同 且 1+min == 真 minDepth ⟺ 該樹是「滿二元樹」 正確的 minDepth 必須特判「某一邊空就強制走另一邊」: if (!root->left) return 1 + minDepth(root->right); if (!root->right) return 1 + minDepth(root->left); return 1 + min(minDepth(root->left), minDepth(root->right)); // max 版不需要這個特判,因為 max 會自動忽略掉那個 0 —— 這是 max 和 min 的不對稱之處
// PHASE 2: 為什麼 base case 錯成 1 是「恆定 +1」而不是「越深錯越多」 設 H'(x) 是「base case 回 1」的版本,H(x) 是正確版本。 對 nullptr: H'(null) = 1 = H(null) + 1 ✓ 偏移 1 歸納:假設左右都偏移 1,則 H'(x) = 1 + max(H(左)+1, H(右)+1) = 1 + max(H(左), H(右)) + 1 ← max 對「同時 +1」是可以提出來的 = H(x) + 1 ✓ 偏移仍是 1 關鍵在「max 不會把偏移累加」——兩邊各 +1,提出來還是 +1。 如果換成加法(1 + 左 + 右),偏移就會「翻倍累積」,那才是越深錯越多。 實測:626 種樹形,H'(t) - H(t) 的取值集合 = {1},只有這一個值 // 這也是為什麼它「連空樹都錯」—— 偏移從最底層就開始了
// PHASE 3: max 沒有短路 —— 兩個遞迴都會被完整執行 有人以為「如果左邊已經很深,右邊是不是就不用走了?」—— 不會。 std::max(a, b) 是一個「普通函式」,它的兩個引數必須「先算完」才能傳進去。 和 && / || 那種「短路運算子」完全不同。 實測(刻意造一棵極不對稱的樹:左邊掛 5 條邊的鏈,右邊只有 1 個節點): 深度 = 6,呼叫次數 = 15 = 2×7+1 鏡像版本(左 1 個、右邊 5 條邊)也是 深度 6、呼叫 15 次 → 兩邊都被完整走完,和哪邊比較深無關 另外實測確認 max 解析到的是 std::max: &max 與 &std::max 位址相同,typeid(max(1,2)) == typeid(int) // 所以呼叫次數恆為 2n+1 —— 沒有任何節點被跳過,這正是複雜度乾淨的原因
// PHASE 4: O(h) 而不是 O(n) —— n = 10^4 的實測對照 完美平衡樹 n≈10000 → 樹高 14,最大遞迴深度 15,堆疊 1040 bytes 退化成一條鏈 n=10000 → 樹高 10000,最大遞迴深度 10001,堆疊 480000 bytes 堆疊差 615 倍 這題和前面幾題最大的差別:n 的上限從 100 變成 10^4。 前面幾題(94/144/145/226)最壞深度 101,離崩潰有 871~2613 倍餘裕 這題最壞深度 10001,在 8 MB 堆疊上餘裕約 17 倍,在 512 KB 上只剩 8% // 「遞迴會不會爆」在這題第一次成為需要真的算一下的問題
