題目簡介// THE QUESTION

QUESTION

給二元樹的根節點 root,回傳它的最大深度 —— 也就是從根到最遠葉節點那條路徑上的節點數。 節點數 0 ~ 10⁴,節點值 −100 ~ 100。

這是後序骨架的第一個「算出一個值」的應用。 和前面三題走訪不同,這題不收集東西 —— 它讓每個節點回報一個數字給父節點。

核心直覺:值是從葉子「往上長」的。 下潛的路上一個數字都沒算 —— 遞迴只是一路走到 nullptr。 每個數字都誕生於某次 return 0,然後每往上經過一層就 +1。 看懂這個「值往上傳」的方向,110、543、124 就都是同一件事。

三行的每一個字都在做事// WHY THIS

A base case 回傳 1 而不是 0 錯 626/626
全部答錯,而且是「恆定 +1」的偏移 —— 實測窮舉 626 種樹形,誤差集合只有 {1} 這一個值。 空樹 [] 也會回 1。
× REJECT · 全盤 +1
B max 寫成 min(以為在算最小深度) 錯 622/626
它算的既不是最大深度、也不是最小深度。 真正的 minDepth(LC111)必須走到葉節點, 而 1+min 會被「不存在的空子樹」吃掉。
× REJECT · 兩邊都不是
ADOPT
C return 1 + max(左, 右); O(n) 時間 · O(h) 空間
0 是「空樹沒有節點」、 +1 是「算上我自己這一層」、 max 是「深度取決於比較深的那一邊」。 三個部分各自對應題目裡的一個字。
● ADOPT · 一行遞迴
這題最好的自我檢查方式:把三個部分各自拆掉,看它會變成什麼題目。 拿掉 +1 → 恆回 0;把 max 換成 + → 變成在數節點總數(實測 626/626 與節點數完全相符,那是 LC222); base case 改成 1 → 全部 +1。三個都改對了,才是這一題。
3

核心策略 · 三步驟// THE SHAPE

  1. 終止:if (root == nullptr) return 0; —— 空樹的深度是 0。這個 0 是所有數字的起點。
  2. 問兩邊:maxDepth(root->left) 和 maxDepth(root->right) 各自回報一個數字。兩邊都一定會被完整執行(max 沒有短路)。
  3. 回報給父節點:return 1 + max(左, 右); —— 取比較深的那一邊,再加上自己這一層。
和走訪三題的差別:那三題的 helper 是 void,靠參考參數把結果帶出來; 這題的 helper 有回傳值,靠 return 把結果往上傳一層。 「回傳值 = 這棵子樹的答案」是後續所有樹形 DP 的共同語言。

兩個會被追問的「為什麼」// TWO LEMMAS

LEMMA 1 · 為什麼 base case 是 0 而不是 1

nullptr 代表「這裡沒有樹」,不是「這裡有一棵空樹佔一層」。 深度的定義是路徑上的節點數,而 nullptr 不是節點。

實測:改成 return 1,窮舉 n = 0..7 共 626 種樹形全錯, 而且誤差是恆定的 +1(626 種樹形的誤差集合只有 {1} 一個值,與樹形無關)。 連空樹都會回 1 —— 而正確答案是 0。
數學上的原因:1 + max(a+1, b+1) = (1 + max(a,b)) + 1, max 不會把偏移累加,所以它一路乾淨地傳到最上面。

LEMMA 2 · 1 + min(...) 不是最小深度

很多人以為把 max 換成 min 就得到 LeetCode 111 的最小深度。 不對。最小深度的定義是「根到最近的葉節點」, 而葉節點的定義是左右都空。

問題出在只有單邊子樹的節點:min(0, 某個正數) 會被那個 「不存在的空子樹」直接吃掉,回傳 1 —— 但那個位置根本不是葉節點。
實測:1+min 與真正的 minDepth 在 496/626 種樹形上不同。 最小反例 [1,null,2]:1+min 給 1,真 minDepth 是 2。
正確的 minDepth 必須特判:某一邊空的時候,強制走另一邊。

一句洞察// INSIGHT

下潛只是「走到底」,所有計算都發生在回程。 每個數字誕生於一次 return 0,每往上一層 +1,而 max 負責丟掉比較短的那一邊。 把這三件事拆開看,你就同時看懂了 110(把 max 換成「差值檢查」)、 543(把 max 換成「左+右並記錄全域最大」)、124(把 max 換成「負的就不要」)。
