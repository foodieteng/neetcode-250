// 輸入 [3,1,4,3,null,1,5](官方範例 1) A(3) / \ B(1) C(4) / / \ D(3) E(1) F(5) 以下每一列是一次 goodNodes 呼叫,mx 是「進來時」的值 // 只列出 root != nullptr 的 6 次;空鏈結另有 7 次,直接回 0
// STEP 1: A(3),mx 進來 = INT_MIN mx = max(INT_MIN, 3) = 3 3 >= 3 ✓ GOOD good 計數 → A 往下傳 mx = 3(左右都是 3) // root 一定是 good:沒有祖先,所以沒有人能大於它
// STEP 2: B(1),mx 進來 = 3 mx = max(3, 1) = 3 ← 沒被 1 拉低,這就是「只增不減」 1 >= 3 ✗ 不是 good 往下傳 mx = 3 // B 自己雖小,但它把「路上有個 3」這件事完整帶給了 D
// STEP 3: D(3),mx 進來 = 3　← 關鍵的平手 mx = max(3, 3) = 3 3 >= 3 ✓ GOOD good 計數 → D 左右皆 nullptr,回傳 1 // 若用 > 就會漏掉 D —— 「沒有節點大於我」不等於「我最大」
// STEP 4: C(4),mx 進來 = 3 mx = max(3, 4) = 4 ← 這次是自己贏,mx 被抬高 4 >= 4 ✓ GOOD good 計數 → C 往下傳 mx = 4(左右都是 4) // 「自己贏」的分支下,測試一定成立 —— 這正是 PHASE 1 等價證明的情況 ②
// STEP 5: E(1),mx 進來 = 4 mx = max(4, 1) = 4 1 >= 4 ✗ 不是 good 回傳 0 // E 的值和 B 一樣是 1,但它面對的門檻更高(4 vs 3)—— 門檻是路徑決定的
// STEP 6: F(5),mx 進來 = 4 mx = max(4, 5) = 5 5 >= 5 ✓ GOOD good 計數 → F 回傳 1 // 樹裡的最大值必然是 good,不管它在多深的地方
// OUTPUT 回傳值往上摺疊: D → 1 B → 0 + 1(D) + 0 = 1 E → 0 F → 1 C → 1 + 0(E) + 1(F) = 2 A → 1 + 1(B) + 2(C) = 4 good 節點 = A(3), D(3), C(4), F(5) 答案 = 4 ✓ 與官方一致 呼叫次數 = 6 個節點 + 7 個空鏈結 = 13 = 2×6 + 1 ✓ // 對拍:窮舉 10428178 組 + 隨機 200000 組,不一致 0

// ANSWERS
Q1 把 >= 改成 > 會怎樣?

答案恆為 0,不分輸入。

因為這個寫法先做了 mx = max(mx, root->val)。這一行執行完之後,mx >= root->val 是恆真的(mx 至少已經吸收了 root->val)。於是測試 root->val > mx 永遠為假,每個節點都貢獻 0。

實測:範例 1 [3,1,4,3,null,1,5] 在 > 版本下輸出 0(正解 4);連只有一個節點的 [1] 也是 0。

⚡ 關鍵是:這不是「偶爾答錯」,是「結構性地全錯」——連 root 都判不成 good。如果想用 >,就必須同時把順序換回「先比再更新」。

Q2 兩種順序為什麼等價?

設進入節點時的路徑最大值是 old。更新後 mx = max(old, val),只有兩種可能:

情況 ① val <= old(舊值贏)
mx 沒變,仍是 old。測試字面上就是 val >= old——與課本版完全相同的表達式。

情況 ② val > old(自己贏)
mx == val,測試變成 val >= val,恆真。而進到這個分支的前提正是 val > old,課本版算 val >= old 也為真。兩邊一致。

兩個分支都一致 ⇒ 等價。實測:窮舉 n=0..8 全部樹形 × 全部賦值共 10,428,178 組,加上隨機 200,000 組,不一致 0。

注意情況 ② 正是 > 版本壞掉的地方:> 把「恆真」變成「恆假」,而情況 ① 的 val > old 又恰好是情況 ② 的條件,兩邊同時失效。

Q3 2n+1 的來源,和 98 的差別?

n 個真實節點各被呼叫一次;二元樹有 n+1 個空鏈結,每個也被呼叫一次(進門就 return 0)。合計 2n+1。

實測:窮舉 n=0..8 全部 2056 種樹形,呼叫次數皆為 2n+1,零違反——與樹形完全無關。

差別在短路。 這題的 return A + B + C 是加法,三項都必須求值,沒有提早結束的機制;所以它一定走完整棵樹。98 的 && 一旦左邊為 false 就整個返回,壞樹可能只看幾個節點——那題的呼叫次數是依輸入而變的。110 的線性表現也是同一個短路效應。

實務含意:這題不能靠「早點發現不合法」加速,best case = worst case = O(n)。

Q4 傳 root->val 而不是 max(mx, root->val)?

那就退化成「只和父節點比」,而不是和整條路徑比。祖先的約束在中間被丟掉。

最小反例 [3,1,null,3](鏈 3 → 1 → 3):

正確版:D 的 mx 是 3(A 的 3 一路傳下來),3 >= 3 ⇒ good;答案 2(A 和 D)。
錯誤版恰好也給 2 —— 因為 >= 讓平手過關。改成 [3,1,null,2] 才分得開:正確 1(只有 A),錯誤版 2 >= 1 判 good 給 2。

這和 98 那題「只檢查 left<root<right 而不傳區間」是同一類錯誤:祖先施加的限制必須一路帶下去,局部檢查看不出來。兩題也共用同一個修法——把約束放進參數。

Q5 預設參數的問題?

它讓 goodNodes 的 public 簽名多了一個參數,於是呼叫端可以(而且會)傳第二個值進來,把演算法的內部不變量整個推翻。

實測(範例 1 的樹):goodNodes(root) → 4 ✓;goodNodes(root, 5) → 1 ✗。編譯全過,零警告,安靜答錯。

修法是把遞迴拆成私有 helper:

public:  int goodNodes(TreeNode* root);
private: int dfs(TreeNode* root, int mx);

這樣 goodNodes(root, 5) 變成編譯錯誤而不是執行期錯答案。兩種寫法在 1062 萬組正確性測試上完全相同——差別純粹在「呼叫端能不能不小心弄壞它」。

面試裡值得主動講一句:「LeetCode 只呼叫單參數版,所以能過;但我在正式程式碼會拆 helper。」這比被問到才解釋好。98 有完全一樣的問題。

App 1 統計 bad 節點

把計數那一項取反即可,但不能只把 >= 換成 <——因為它作用在已更新的 mx 上,會恆假。必須先存下舊值:

int old = mx;
mx = max(mx, root->val);
return (int)(root->val < old) + dfs(左, mx) + dfs(右, mx);

兩者相加一定等於 n。 對每個節點,val >= old 與 val < old 是互斥且窮盡的二分(old 是進入時的路徑最大值,固定值),所以每個節點恰好落入一邊。

更省事的寫法:直接回傳 n - goodNodes(root),先數節點數。不過上面那版只走一趟。

App 2 n 放寬到 10⁶

會 SEGFAULT。 實測本題 -O0 下 8176 KB 預設堆疊的崩潰深度是 130,723(64 B/frame);10⁶ 的退化鏈需要 10⁶ 層,超出約 7.6 倍。

就算是目前的 n = 10⁵,餘裕也只有 130723 / 100000 ≈ 1.31 倍——這是本章所有題目裡最小的(104 是 17 倍、450 是 10.4 倍、572 是 87 倍)。把堆疊縮到 ulimit -s 1024 或 512,現在的 n=10⁵ 就已經 SEGFAULT。

改法:換成顯式 stack 的迭代 DFS,把 (節點, 路徑最大值) 一起壓進去:

vector<pair<TreeNode*, int>> st{{root, INT_MIN}};
while (!st.empty()) {
    auto [node, mx] = st.back();  st.pop_back();
    if (!node) continue;
    if (node->val >= mx) ++count;
    int nmx = max(mx, node->val);
    st.push_back({node->left,  nmx});
    st.push_back({node->right, nmx});
}

這正是對拍用的參考解,1062 萬組與遞迴版完全一致。空間從系統堆疊搬到 heap,10⁶ 就沒問題了。

⚠ 別被 -O2 騙了:實測 clang 在 -O2 下會把這段遞迴改寫成迴圈,跑到 10⁸ 都不崩。但那是編譯器的恩惠,不是程式的性質——換個編譯器或加個 side effect 就沒了。

App 3 改成求「值的總和」/「最深 good 節點的深度」

值的總和:只要把 (int)(root->val >= mx) 換成 (root->val >= mx ? root->val : 0),其餘一字不動。因為「哪些是 good」這件事跟回傳的是什麼完全正交——遞迴骨架沒變,只換了折疊的量。
⚠ 型別要抬:10⁵ 個 10⁴ 相加是 10⁹,勉強在 int 內但太貼邊,用 long long。

最深 good 節點的深度:需要多一個參數 depth,而且折疊從加法換成取最大:

int dfs(TreeNode* root, int mx, int depth) {
    if (!root) return -1;                    // 沒有 good 節點
    mx = max(mx, root->val);
    int best = (root->val >= mx) ? depth : -1;
    return max({best, dfs(root->left,  mx, depth + 1),
                      dfs(root->right, mx, depth + 1)});
}

⚡ 值得注意的是:depth 和 mx 一樣是往下傳的狀態,而答案一樣是往上折疊。這個「下傳約束 + 上折答案」的骨架,就是 98、104、543 共用的形狀——換題只換兩件事:下傳什麼、怎麼折疊。

哨兵用 -1 是安全的,因為深度非負。若改成「最深 good 節點的值」就不能用 -1,得回 pair 或用 optional。
