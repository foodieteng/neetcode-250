// 輸入 [5,4,6,null,null,3,7](和動畫同一棵) 5 / \ 4 6 / \ 3 7 每個節點的小孩都「局部合法」:4 < 5 < 6、3 < 6 < 7 但 3 在 5 的右子樹裡,必須 > 5 ⇒ 答案 false 以下是對真實程式插樁後印出的呼叫序列(6 次) // 窗寫成 (L, R),−∞ / +∞ 代表 LONG_MIN / LONG_MAX
// STEP 1: valid(5, −∞, +∞) −∞ < 5 < +∞ ✓ PASS 往左 → valid(4, −∞, 5) 上界收成 5 // 根沒有任何限制
// STEP 2: valid(4, −∞, 5) 和它的兩個空小孩 −∞ < 4 < 5 ✓ PASS valid(null, −∞, 4) → true valid(null, 4, 5) → true ⇒ 左子樹整棵合法,&& 繼續往右 // 4 是葉子,兩個空呼叫各回 true
// STEP 3: valid(6, 5, +∞) 5 < 6 < +∞ ✓ PASS 下界收成 5(從根傳來) 往左 → valid(3, 5, 6) 上界收成 6,「下界 5 原封不動」 // 關鍵就在這一步:5 這個下界會跟著一起傳到 3
// STEP 4: valid(3, 5, 6) —— 撞破 5 < 3 ? ✗ FAIL 對父節點 6 來說 3 完全合法(3 < 6),但下界 5 是兩層之上的根傳下來的 ⇒ 回傳 false,&& 短路:valid(6->right = 7) 從未被呼叫 // 「只比父節點」的寫法在這裡會回 true
// OUTPUT false 一路往上傳:6 的回傳 false ⇒ 5 的回傳 false 答案 = false ✓ 正確 呼叫統計:6 次 = 5, 4, null, null, 6, 3 從未走訪:7 // 對拍 70,557,820 組,不一致 0
STEP 3 是整個 trace 的重點:往左走到 3 時,只有上界換成 6,下界 5 原封不動。 如果兩邊都換成「跟父節點比」,這個 5 就丟掉了 —— 那就是 Q1 的錯法。

// ANSWERS
Q1 只比小孩為什麼不夠?

BST 的定義是「整棵左子樹都比我小、整棵右子樹都比我大」。只比小孩,檢查的是「父子」關係,抓不到「祖孫」之間的違規。

最小反例只要 3 個節點:[2,null,3,1]。節點 1 是 3 的左小孩(1 < 3,局部合法),但它在根 2 的右子樹裡,必須 > 2。只比小孩的寫法回 true,正解 false。

實測:n ≤ 8 全部樹形 × 相異值全排列共 59,920,211 組,錯 282,713 組。

⚡ 比例不高(約 0.5%),而且官方兩個範例它都會過 —— 所以這個錯法很容易被交出去。

Q2 為什麼只改一邊?忘了抬下界會怎樣?

往左走,代表「接下來的節點都要比我小」,新增的只有一條上界;而祖先給的下界仍然有效(它們也在那些祖先的某一邊),所以原封不動傳下去。往右同理,只新增下界。

正是「另一邊原封不動」,讓根的界線能穿過好幾層,壓住很深的節點(Trace 裡的 5 → 3)。

忘了抬下界(往右仍傳 (L, R)):右子樹連「比父節點大」都沒被檢查。實測錯 2,171,569 / 59,920,211,最小反例 [2,null,1] 被判 true。

⚡ 把兩邊收反(往左傳 (val, R))也會錯:4,108 組,最小 [1,2]。

Q3 為什麼要 long long?

這段程式沒有任何加減,不是怕溢位。原因是哨兵必須站在值域之外:題目值域是完整的 int,INT_MIN 和 INT_MAX 都是合法的節點值,int 裡已經沒有位置放「無限大」了。

用 int + <:單節點 [-2147483648] 會變成 INT_MIN < INT_MIN ⇒ false。實測含極值窮舉錯 131/9,431,隨機 20 萬組錯 103,600。

改成 <=:哨兵過關了,但重複值也被放行。實測 [1,1] 回 true,{1,2,3} 窮舉錯 84,633/10,428,178。

⚡ 兩個 int 方案各壞一半,只有把邊界的型別抬到 int 之外(或完全不用哨兵,見 App 1)才能兩者兼顧。

Q4 LONG_MIN vs LLONG_MIN

LONG_MIN 是 long 的最小值,LLONG_MIN 才是 long long 的。兩者相不相等,取決於平台上 long 有多大。

本機實測(x86_64 Linux,LP64):sizeof(long) = 8,LONG_MIN == LLONG_MIN,所以你的程式正確(70,557,820 組零錯誤)。

但在 Windows / MSVC(LLP64)上 long 只有 32 bit,LONG_MIN 就等於 INT_MIN,等於又回到 Q3 的 int 哨兵版。模擬這個情況實測:和 int 版完全相同,極值窮舉錯 131、隨機錯 103,600。

⚡ 修法一個字:LLONG_MIN / LLONG_MAX(實測 0 失敗)。而且注意:不含 INT_MIN/INT_MAX 的測資(例如 {1,2,3} 窮舉)完全測不出這個 bug。

Q5 呼叫幾次?

合法的樹:恰好 2n + 1 次。要證明「沒有任何節點違規」,每個節點都得檢查;n 個節點各發出 2 個子呼叫,加上最外層 1 次。實測完美 BST n=7 → 15、n=63 → 127、n=1023 → 2047。

不合法的樹:看違規出現在哪。&& 會在第一個 false 就停下:

  • 根的左小孩就違規 → 只要 2 次(根 + 左小孩),n=7、63、1023 都一樣
  • 最右邊的葉子才違規(n=1023)→ 2045 次,幾乎走完

⚡ 「證明成立要全查,證明不成立只要找到一個反例」。

App 1 用節點指標當邊界
bool valid(TreeNode* root, TreeNode* lo, TreeNode* hi) {
    if (!root) return true;
    if (lo && root->val <= lo->val) return false;   // lo == nullptr 代表沒有下界
    if (hi && root->val >= hi->val) return false;   // hi == nullptr 代表沒有上界
    return valid(root->left, lo, root) && valid(root->right, root, hi);
}
bool isValidBST(TreeNode* root) { return valid(root, nullptr, nullptr); }

「沒有界線」用 nullptr 表示,完全不需要哨兵值,自然不會有 int / long / long long 的問題。

實測:四個測試集(共 70,557,820 組)全部 0 失敗。

App 2 中序 + O(h) 空間
bool isValidBST(TreeNode* root) {
    stack<TreeNode*> st;
    TreeNode* cur = root;
    bool hasPrev = false;
    int prev = 0;
    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }
        cur = st.top(); st.pop();
        if (hasPrev && cur->val <= prev) return false;   // 必須嚴格遞增
        prev = cur->val;
        hasPrev = true;
        cur = cur->right;
    }
    return true;
}

BST 的中序必定嚴格遞增(94 的走訪順序),所以只要記住「上一個值」就能檢查。stack 最多放 h 個節點,空間 O(h)。

注意用 hasPrev 旗標而不是哨兵:第一個值可能就是 INT_MIN,用 prev = INT_MIN 當起點會把它誤判成重複。

這正是本頁用來對拍的參考解 (b),和主解在 70,557,820 組上完全一致。

App 3 允許重複值放右邊

新的定義是「左子樹 < 我 ≤ 右子樹」。往右走時,右子樹的值可以等於下界;往左走時仍然要嚴格小於上界。

所以只需要把下界那一邊改成寬鬆:L <= root->val && root->val < R。

這正好就是陷阱表裡的「只有一邊寬鬆」:在原題(不允許重複)它是錯的(實測 {1,2,3} 窮舉錯 1,158 組,[1,null,1] 被判 true),但在這個新定義下,[1,null,1] 本來就該是 true。

⚡ 同一行程式對不對,取決於「重複值怎麼定義」。面試時看到 BST 題,第一個要問的就是這個。
