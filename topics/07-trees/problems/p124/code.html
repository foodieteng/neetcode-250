完整實作// POSTORDER TREE DP

p124.cpp C++17 
class Solution {
public:
    int maxPathSum(TreeNode* root) {
        int ans = INT_MIN;                          // 全負的樹也要能被更新
        path(root, ans);
        return ans;
    }

    int path(TreeNode* root, int& ans) {
        if (!root) return 0;

        int l = max(0, path(root->left, ans));      // 負的臂就不要
        int r = max(0, path(root->right, ans));
        ans = max(ans, root->val + l + r);           // 以自己為轉折:兩條臂

        return root->val + max(l, r);              // 往上:只帶一條臂
    }
};

// 最容易被範例騙過的是「ans 從 0 起算」

兩個官方範例的答案都是正的,ans = 0 起算完全看不出問題。

但題目的路徑必須非空:全負的樹,答案是「最大的那個單一節點」,一定是負數。 從 0 起算的話,ans 永遠不會被更新到負數,每一棵全負的樹都答錯(實測 107,724 / 107,724)。

你用 INT_MIN 起算,而且程式裡從來不對 ans 做加減(只拿它比大小),所以不會溢位。

細節走讀// LINE BY LINE

// PHASE 1: path() 回傳的到底是什麼 path(x) = 「從 x 出發、往下走的一條直線」的最大和(至少包含 x 自己) 為什麼只能是直線? 父節點 p 要接上來時,路徑是 … → p → x → … x 在這條路徑上已經用掉「往上」這個方向,只剩一個方向可以往下 ⇒ 回傳 x.val + max(l, r) 空指標回傳 0:「不往那邊走」,和截成 0 的意思一樣 // 回傳值是「可以被父節點接上的東西」,不是「這棵子樹的答案」
// PHASE 2: max(0, ·) 的意思 一條臂的值是負的 ⇒ 接上它只會讓總和變小 ⇒ 乾脆不接 範例 [2,-1](−1 是 2 的左小孩): path(−1) 回傳 −1 在 2:l = max(0, −1) = 0 ← 左臂不要 r = max(0, 0) = 0 ans = max(−1, 2 + 0 + 0) = 2 答案 2(只有節點 2 自己) ✓ 注意:截 0 只在「要不要接這條臂」時發生, 節點自己的值不能被截掉(路徑非空,自己一定在) // 所以全負的樹,答案就是「最大的那個單一節點」
// PHASE 3: 為什麼一次後序就夠 每條路徑都有唯一的最高點 x ⇒ 路徑 = x + (往左下的一段) + (往右下的一段) ⇒ 最好的「往左下一段」就是 max(0, path(x->left)) = l ⇒ 以 x 為最高點的最佳路徑 = x.val + l + r 後序走訪會把每個節點都當一次 x ⇒ 所有可能的最高點都被試過 ⇒ ans 就是全部路徑的最大值 // 這就是「在每個節點算一次候選、往上傳一個摘要」的 tree DP 模式
// PHASE 4: 為什麼 ans 用傳參考的區域變數 ans 是「所有節點共同在更新的一個值」,必須大家共用 選項 A:member 變數 —— LeetCode 可能用同一個物件呼叫多次 每次呼叫前沒重設,上一題的答案會留下來 選項 B:區域變數 + 傳參考(你的寫法)—— 每次呼叫都是新的 INT_MIN 實測 member 不重設:先算 [-1](答案 −1),再算 [-2] 第二次回傳 −1(上一題的殘留),正解 −2 n ≤ 3 的所有樹對中錯 185,131 / 462,400 // 對照 230:那題的 member rank 每次在入口重設,所以安全
PREV概念與動畫 NEXT觀念題與走讀
