二元樹的最大路徑和

題目簡介// THE QUESTION

QUESTION

樹上的一條路徑是一串沿著邊相連的節點,每個節點最多出現一次,不一定要經過根。 路徑和 = 路徑上所有節點值的總和。回傳任意非空路徑的最大路徑和。
節點數 1 ~ 3·10⁴,值 −1000 ~ 1000(可以是負的)。
範例:[-10,9,20,null,null,15,7] → 42(15 → 20 → 7)。

任何一條路徑都有唯一的「最高點」(離根最近的那個節點)。 路徑從最高點往左下延伸一段、往右下延伸一段,兩段都可以是空的。 所以只要在每個節點問:「如果最高點是我,最好的路徑是多少?」
2

為什麼用「後序 + 每個節點當轉折點」// KNOCKOUT

A 枚舉所有節點對 (u, v),加總兩點間的路徑 O(n²) 以上
答案一定對(本頁就拿它當對拍參考解),但 n = 3·10⁴ 時有約 4.5 億對節點, 每對還要再走一次路徑。
× REJECT · TLE
B 遞迴回傳「子樹裡的最大路徑和」 接不起來
父節點只能接在從小孩往下的一條直線上, 子樹裡的最佳路徑可能已經在小孩那裡轉彎了,父節點接不上去。 回傳值和答案需要的是兩種不同的東西。
△ 定義錯了
ADOPT
C 回傳「一條臂」,在每個節點用「兩條臂」更新答案 O(n) 時間 · O(h) 空間
path(x) 回傳從 x 往下走的最大直線和(可以往上接); 答案則在 x 用 x.val + 左臂 + 右臂 更新(在 x 轉彎,不能再往上)。 實測:n ≤ 7 全部樹形 × 值 {−2..2} 共 35,718,805 組,加上隨機 300,000 組,不一致 0。
● ADOPT · 兩種量分開算
3

核心策略 · 三步驟// STRATEGY

  1. 先算兩條臂(後序):l = max(0, path(left))、r = max(0, path(right))。 臂是負的就不要,當成 0。
  2. 以自己為轉折點更新答案:ans = max(ans, val + l + r)。
  3. 往上只回傳一條臂:val + max(l, r) —— 路徑不能分岔,父節點只能接其中一邊。
答案候選 = val + l + r(兩條臂)　·　回傳值 = val + max(l, r)(一條臂)

為什麼答案和回傳值不一樣// TWO QUANTITIES

// LEMMA: 轉折點只能有一個

一條路徑往上走到最高點,再往下走。最高點以外的每個節點,在路徑上都只有「一進一出」, 其中一個方向一定是它的父節點。

所以要讓父節點接上來,path(x) 回傳的只能是從 x 往下的一條直線: x.val + max(l, r)。

而「以 x 為最高點」的路徑可以兩邊都往下:x.val + l + r。這個值不能往上傳(會分岔), 只能拿去更新全域的 ans。

寫錯的地方實測失敗(n ≤ 6 × 值 {−2..2},共 2,203,180 組)最小反例
回傳 val + l + r(把分岔帶上去)105,556[1,-1,null,1,1] → 2(正解 1)
答案只用 val + max(l, r)(從不轉彎)237,383[-1,2,2] → 2(正解 3)
不做 max(0, ·)(硬接負的臂)445,195[-1,-2] → −2(正解 −1)

每個節點只被後序走訪一次,做常數次比較與加法;遞迴深度等於樹高。

一句洞察// INSIGHT

「往上傳的東西」和「要的答案」不是同一個量 —— 往上只能帶一條臂,答案卻可以在每個節點用兩條臂轉彎。 這和 543 直徑是同一個模型,只是把「邊數」換成「節點值的和」, 多了一件事:值可以是負的,所以臂可以選擇不要(max(0, ·))。
