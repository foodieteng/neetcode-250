// ANSWERS
Q1 為什麼回傳一條臂?

父節點 p 要把 x 接進自己的路徑時,路徑會是 … → p → x → …。x 已經用掉「往上」這個方向,只剩一個方向可以往下。所以 path(x) 能提供給父節點的,只能是從 x 往下的一條直線。

回傳 val + l + r 等於讓 p 接上一條在 x 分岔的東西,那已經不是路徑了。實測在 n ≤ 6 × 值 {−2..2} 中錯 105,556 組,最小反例 [1,-1,null,1,1] 回 2,正解 1(兩個 1 都是 −1 的小孩,不可能和根的 1 串在同一條路徑上)。

⚡ 兩條臂的值 val + l + r 不是沒用,是只能拿去更新答案,不能往上傳。

Q2 max(0, ·) 做什麼?

一條臂的最佳值是負的,代表接上去只會讓總和變小,不如不接。max(0, ·) 就是「這條臂可以選擇不要」。

不做這件事,就會硬接負的臂。實測錯 445,195 組,最小反例 [-1,-2](−2 是左小孩):在根算候選時被迫接上左臂,得到 −1 + (−2) = −3,「只有根自己」的 −1 從來沒被考慮;最後答案是葉子自己的 −2,正解 −1。

但節點自己不能被截掉:題目要求路徑非空,而「以 x 為最高點」的路徑一定包含 x。所以截 0 只作用在 l、r,不作用在 val。這也是全負的樹答案會是「最大的單一節點」的原因([-1,-2,-3] → −1)。

Q3 為什麼從 INT_MIN 起算?

答案可能是負數:全負的樹,最佳路徑就是最大的那個單一節點。從 0 起算,ans 永遠停在 0,但 0 不是任何一條非空路徑的和。

實測:全負的 107,724 組全部答錯;最小反例 [-1] 回 0。混合正負的 2,203,180 組中也錯了 10,066 組(答案恰好是負數的那些)。

兩個官方範例答案都是正的,所以這個錯只用範例測不出來。

⚡ INT_MIN 不會溢位,因為程式從不對 ans 做加減,只拿它比大小。另一個等價寫法是 ans = root->val(實測也 0 失敗)。

Q4 為什麼一次後序就夠?

任何一條路徑都有唯一的最高點 x,它的形狀是「x + 往左下一段 + 往右下一段」(每段可以是空的)。

往左下那段最好能拿到多少?正好是 max(0, path(x->left)) = l;右邊同理。所以以 x 為最高點的最佳路徑 = x.val + l + r。

後序走訪會把每個節點都當一次 x,所有可能的最高點都被試過,ans 取的就是全部路徑的最大值。

⚡ 後序是必要的:算 x 之前,兩個小孩的 path() 必須已經算好。

Q5 根回傳的 25 有用嗎?

沒有用。maxPathSum 呼叫 path(root, ans) 後直接回傳 ans,根的回傳值被丟掉了。

答案不經過根,是因為經過根的最佳路徑是 9 → −10 → 20 → 15 = 34,比在 20 轉彎的 15 → 20 → 7 = 42 小:根的 −10 把總和拉低了。

⚡ 這就是題目說「不一定經過根」的意思,也是為什麼答案要用全域的 ans 記,而不是看根的回傳值。

App 1 只能往下走的路徑

只能往下 ⇒ 路徑不會轉彎 ⇒ 每條路徑都是某個節點往下的一條直線,那正是 path(x) 回傳的東西。

所以把更新答案的那一行,從「兩條臂」改成「一條臂」:

int ret = root->val + max(l, r);
ans = max(ans, ret);       // 原本是 root->val + l + r
return ret;

實測:和「枚舉每個節點與它的每個子孫」的暴力解對拍 200,000 組隨機樹,不一致 0。

⚡ 同一行,在原題是錯的(陷阱表那一列,錯 237,383 組),在這題是對的 —— 差別只在路徑能不能轉彎。

App 2 不用遞迴
int maxPathSum(TreeNode* root) {
    unordered_map<TreeNode*, int> down;           // path(x) 的回傳值
    stack<pair<TreeNode*, bool>> st;              // (節點, 小孩處理完了沒)
    st.push({root, false});
    int ans = INT_MIN;
    while (!st.empty()) {
        auto [x, done] = st.top(); st.pop();
        if (!x) continue;
        if (!done) {                               // 第一次看到:先排小孩
            st.push({x, true});
            st.push({x->right, false});
            st.push({x->left, false});
            continue;
        }
        int l = x->left  ? max(0, down[x->left])  : 0;
        int r = x->right ? max(0, down[x->right]) : 0;
        ans = max(ans, x->val + l + r);
        down[x] = x->val + max(l, r);
    }
    return ans;
}

每個節點進 stack 兩次:第一次把小孩排進去,第二次(小孩都算完)才計算,這就是後序。

實測:和你的遞迴版對拍 200,000 組隨機樹(四分之一全負),不一致 0;在 n = 300,000 的斜鏈上也正常跑完(遞迴版在 -O0 約 87,000 層就會崩)。

App 3 換成邊的數量

就是 543 · Diameter of Binary Tree:最長路徑的邊數。

模型完全相同:回傳「往下最長的一條臂」,在每個節點用「左臂 + 右臂」更新答案。差別有兩個:

  • 長度不會是負的,所以不需要 max(0, ·)
  • 量的是邊,答案是 l + r(不加自己),回傳是 1 + max(l, r)(多一條往上的邊)

⚡ 本頁的極端測試也用了這個關係:值全部是 1000 時,124 的答案 = 直徑的節點數 × 1000。
