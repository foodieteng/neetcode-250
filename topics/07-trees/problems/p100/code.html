完整實作// TWO LINES

class Solution {
public:
    bool isSameTree(TreeNode* p, TreeNode* q) {
        // 至少一個是 null 時,「相等」等價於「兩個都是 null」
        if (!p || !q) {
            return p == q;
        }

        return (p->val == q->val)
            && isSameTree(p->left,  q->left)     // 左配左
            && isSameTree(p->right, q->right);   // 右配右
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

兩個關鍵決定:base case 用 return p == q(一行吃掉兩種 null 情形), 以及三個條件用 && 串(短路讓發現不同極便宜)。 而「左配左、右配右」看似理所當然,實測配錯邊會錯 365/8165 —— 那時你判斷的是「鏡像相等」,是另一題(LeetCode 101)。

複雜度分析// COMPLEXITY

時間 O(min(np, nq))　·　空間 O(min(hp, hq))
情境實測呼叫次數說明
兩棵 n=100 完全相同2012n+1 —— 沒有任何短路可用,整棵走完
根的值就不同1省 201 倍 —— 一次整數比較就結束
只有最深最右不同149仍省 26%(已匹配的左子樹要走完,之後全部砍掉)
相同時,所有樹形 n=0..8恰好 2n+1窮舉 2056 種樹形,每一種都一樣,與形狀無關
為什麼是 O(min(np, nq)) 而不是 O(n): 遞迴不可能走得比「比較淺的那棵樹」更深 —— 走到某個位置時,只要有一棵先「用完」(遇到 nullptr), 就立刻命中 base case 回傳,不會再往下。 所以一棵 10⁴ 節點的樹和一棵單節點樹比較,只要幾次呼叫就結束。

邊界與陷阱// PITFALLS

測試宇宙:n ≤ 5 全部 65 種樹形兩兩配對(4225 個有序對) + n = 1..4 同形狀、值取自 {0,1} 的全部配對(3940 個) = 8165 個有序配對。 q 一律做 deep copy,避免「相等的樹剛好是同一個指標」汙染結果。

陷阱失敗數最小反例說明
&& 寫成 || 7698/8165 p=[0] q=[1] → true 變成「任一處相同就算相同」,幾乎全錯
忘記比較值(只比結構) 3666/8165 p=[0] q=[1] → true 失敗的 3666 個「全部」是同形狀配對 —— 它變成純形狀比較
base case 只寫 !p && !q 3896 個 SIGSEGV p=[] q=[1] → 崩潰 漏掉「只有一個空」→ 掉下去解參考 p->val
base case 回 true 2816/8165 p=[] q=[1] → true 會把「p 是 q 的前綴子樹」誤判成相同
base case 回 false 339/8165 p=[] q=[] → false 失敗集合恰好 = 全部 339 個「正解為 true」的配對,永遠答不出 true
左右比錯邊(比成鏡像) 365/8165 p=[1,null,2] q=[1,null,2] → false 它在判斷「鏡像相等」——是 LeetCode 101,不是這題
只遞迴左子樹 1966/8165 p=[1] q=[1,null,2] → true 右子樹的差異全部漏判
用 p == q 比指標 338/8165 p=[1] q=[1] → false 只有字面上同一個節點才 true —— 見下方警告
⚠ 最後一列有一個測試設計上的陷阱值得記住。 如果你的測試程式讓「相等的兩棵樹」共用同一個物件(沒有 deep copy), 「用 p == q 比指標」這個嚴重的 bug 會顯示 0 失敗、完美通過。 本頁的 8165 個配對全部對 q 做了 deep copy, 才讓那 338 個「內容相等但物件不同」的配對現形。 ——「測資怎麼造」和「程式怎麼寫」一樣會決定你抓不抓得到 bug。

// PHASE 1: 那一行 base case 的真值表 if (!p || !q) return p == q; 進到這個分支的前提:「至少有一個是 nullptr」 在這個前提下窮舉三種情況: p q !p||!q 進來後 p == q 正確答案 null null true true true ✓ null 非空 true false false ✓ 非空 null true false false ✓ 非空 非空 false (不會進來) 繼續比較 實測:與明確兩行版本在 51174 個配對上比對,分歧 0 注意:第 4 列「不會進來」很重要 —— 一旦兩邊都非空, 下面的 p->val 和 q->val 就保證安全,不需要再檢查 // 這一行同時做了「終止判斷」和「安全保證」兩件事
// PHASE 2: p == q 為什麼「在裡面對、在外面錯」 在 base case 裡面(已知至少一個是 null): p == q ⟺ 兩個都是 nullptr ⟺ 這兩棵(空)樹相同 ✓ 正確 在 base case 外面(當成一般的樹比較): p == q ⟺ 它們是「同一個節點物件」 → 兩棵「內容完全相同但各自建立」的樹會被判成「不同」 ✗ 錯誤 實測:把整個函式主體換成 return p == q 錯 338/8165,最小反例 p=[1] q=[1](deep copy 的兩棵單節點樹) 唯一答對 true 的是 p=[] q=[] —— 因為兩邊都是 nullptr,指標真的相等 C++ 提醒:指標的 == 比的是「位址」,不是「指向的內容」 // 同一個運算式,換個上下文就從正確變成錯誤 —— 這正是這一行值得講清楚的原因
// PHASE 3: 兩個 && 短路點(以 p=[1,2,1] q=[1,1,2] 為例,實測) 1. 比對 (p:1, q:1) 值相等 → && 繼續,遞迴比左子樹 2. 比對 (p:2, q:1) 值「不等」 *** 短路 ① *** 這個節點自己的兩個子遞迴「完全沒被呼叫」 回傳 false 回到第 1 步:左邊回 false *** 短路 ② *** 根的「右子樹遞迴」也不會被求值 → (p 的右小孩 1, q 的右小孩 2) 這一對「從來沒有被建立過」 3. 回傳 false 總呼叫次數 = 2 (完整走訪這兩棵 3 節點的樹要 7 次) 從未被拜訪的節點:p 的右小孩、q 的右小孩,以及它們底下的 4 個空指標探測 // 7 個可能的呼叫裡有 5 個被消掉 —— 短路不是微優化,它會大幅改變實際工作量
// PHASE 4: 為什麼最壞情況是「兩棵樹相同」 一般題目的最壞情況是某種極端輸入;這題的最壞情況是「答案為 true」。 理由:只要有任何一處不同,某個 && 就會短路,底下全部不必看 而「完全相同」代表「沒有任何一處可以短路」→ 整棵樹非走完不可 實測(兩棵 n = 100 的樹): 完全相同 → 201 次呼叫 (2n+1) ← 最壞 根值就不同 → 1 次呼叫 ← 最好 最深最右處不同 → 149 次呼叫 複雜度寫成 O(min(n_p, n_q)) 而不是 O(n): 遞迴不可能走得比「比較淺的那棵」更深 —— 一邊先用完就命中 base case 所以一棵 10^4 節點的樹 vs 一棵單節點樹,幾次呼叫就結束 // 「最壞情況 = 答案為 true」在面試裡是個很好的觀察,值得主動說
