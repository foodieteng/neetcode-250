題目簡介// THE QUESTION

QUESTION

給兩棵二元樹的根節點 p 和 q,判斷它們是否完全相同 —— 結構相同且對應位置的值也相同。 節點數 0 ~ 100,節點值 −10⁴ ~ 10⁴。

這是本章第一題「兩棵樹同時遞迴」的題目。 前面的題目都只有一個 root 往下走,這題兩個指標要並排往下走。

新增的難點只有一個:兩個指標各自可能是 nullptr,所以有三種情形要處理 —— 兩個都空(相同 ✓)、只有一個空(不同 ✗)、兩個都不空(繼續比)。 而你這份寫法用一行 if (!p || !q) return p == q; 就把前兩種一起解決了 —— 這是非常漂亮的一手。
2

那一行 base case 為什麼成立// WHY THIS

A 只寫 if (!p && !q) return true; SIGSEGV
漏掉「只有一個是 null」的情形。 那時會直接掉到下一行去解參考 p->val。 實測 8165 個配對中有 3896 個觸發 null 解參考,程式當場崩潰。
× REJECT · 直接崩潰
B 寫成兩行的明確版本 完全正確
if (!p && !q) return true;
if (!p || !q) return false;
和你的一行版完全等價 —— 實測 51174 個配對,兩者零分歧。初學時寫這個更好讀。
△ 等價但囉嗦
ADOPT
C if (!p || !q) return p == q; 一行兩用
進到這個分支時,至少有一個是 nullptr。 此時 p == q 為真當且僅當兩個都是 nullptr —— 剛好就是我們要的「兩個都空 → true、只有一個空 → false」。
● ADOPT · 一行兩用
注意這裡的 p == q 是在比指標,而不是在比樹。 它之所以正確,完全是因為「已經知道至少有一個是 nullptr」這個前提。 實測把 p == q 拿到 base case 外面當作整棵樹的比較, 8165 個配對錯 338 個 —— 只有字面上同一個節點指標時才會回 true。
3

核心策略 · 三步驟// THE SHAPE

  1. 先處理 null:if (!p || !q) return p == q; —— 一行解決「兩個都空」和「只有一個空」。
  2. 比自己的值:p->val == q->val。
  3. 再比兩邊,而且是對應地比: isSameTree(p->left, q->left) 和 isSameTree(p->right, q->right) —— p 的左要配 q 的左。配錯邊就變成在判斷「鏡像相等」了。
三個條件用 && 串起來,而 && 會短路 —— 這讓「發現不同」變得非常便宜:實測兩棵 n=100 的樹, 如果根的值就不同,只要 1 次呼叫就能回答(相同時要 201 次)。 這和 104 用的 max 正好相反 —— max 是普通函式,兩個引數一定都會被算完。

兩個值得知道的性質// TWO LEMMAS

LEMMA 1 · return p == q 為什麼等價於明確的兩行

進到 if (!p || !q) 這個分支時,我們已經知道至少有一個是 nullptr。 在這個前提下:
· 兩個都是 nullptr → p == q 為 true ✓(正是我們要的)
· 只有一個是 nullptr → 一個是空、一個非空,不可能相等 → false ✓

實測:把它和明確的兩行版本 (if (!p && !q) return true; + if (!p || !q) return false;) 在 51174 個配對上逐一比對,分歧 0。
但要小心:這個 p == q 的正確性完全依賴「已經有一個是 null」這個前提。 把它搬到函式外面當成一般的樹比較,就會變成「比指標」而不是「比內容」 —— 實測 8165 個配對錯 338 個。

LEMMA 2 · 短路讓「不同」比「相同」便宜得多

&& 是短路運算子:左邊一旦為 false, 右邊連求值都不會發生。這題把三個條件串成 && 鏈, 所以任何一處不同,底下就全部不必看了。

實測(兩棵 n = 100 的樹):
· 完全相同 → 201 次呼叫(2n+1,整棵走完)
· 根的值就不同 → 1 次呼叫 ← 省了 201 倍
· 只有最深最右的節點不同 → 149 次(仍省 26%)
「最壞情況」是兩棵樹完全相同 —— 那時沒有任何短路可用。 這也是為什麼複雜度寫成 O(min(n_p, n_q)):遞迴不可能走得比較淺的那棵樹更深。

複雜度// COMPLEXITY

時間 O(min(np, nq))　·　空間 O(min(hp, hq))
維度值實測依據
時間(最壞)O(min(np, nq))遞迴不可能走得比較淺的那棵樹更深 —— 一邊先用完就命中 base case
兩樹相同時2n + 1窮舉 n=0..8 全部 2056 種樹形,每一種都恰好 2n+1,無例外
根值不同時1 次n=100 實測:201 次 → 1 次,短路省 201 倍
空間O(h)兩條 n=10⁴ 的相同鏈,實測深度 10001,正常完成

「最壞情況是兩棵樹完全相同」是這題有趣的地方 —— 大多數題目的最壞情況是某種極端輸入,這題的最壞情況卻是「答案為 true」。 因為只有完全相同時,沒有任何一個 && 能短路,整棵樹非走完不可。

一句洞察// INSIGHT

兩棵樹並排遞迴,難的不是遞迴,是「兩個指標各自可能為空」的三種組合。 if (!p || !q) return p == q; 用一行吃掉其中兩種 —— 但它成立的前提是「已經知道至少有一個是 null」,離開這個前提就變成在比指標了。
而三個條件串成 && 鏈,讓「發現不同」變得極便宜: 實測根值不同時只要 1 次呼叫,而完全相同時要 201 次 —— 這題的最壞情況是答案為 true。
