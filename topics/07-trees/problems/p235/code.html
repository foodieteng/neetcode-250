解法 A · 遞迴(你的寫法)// RECURSIVE

p235_recursive.cpp C++17 
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        if (max(p->val, q->val) < root->val) {
            return lowestCommonAncestor(root->left, p, q);   // 兩個都比我小
        } else if (min(p->val, q->val) > root->val) {
            return lowestCommonAncestor(root->right, p, q);  // 兩個都比我大
        } else {
            return root;                                       // 分岔點 = 答案
        }
    }
};

沒有 nullptr 檢查 —— 而且不需要。 因為題目保證 p 和 q 都存在於樹中,所以 遞迴一定會在走到 nullptr 之前先命中分岔點。 這是一個「靠前提換掉一行程式碼」的設計 —— 值得在面試時主動說出來,而不是讓對方以為你忘了。

解法 B · 迭代(零成本升級)// O(1) SPACE

p235_iterative.cpp C++17 
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        int lo = min(p->val, q->val);
        int hi = max(p->val, q->val);

        while (root != nullptr) {
            if (hi < root->val) {
                root = root->left;
            } else if (lo > root->val) {
                root = root->right;
            } else {
                return root;
            }
        }

        return nullptr;   // 題目保證會在上面 return,這行只是讓編譯器安心
    }
};
這題的遞迴是純尾遞迴(三個 return 都在 tail position), 所以改成迴圈是零成本的 —— 邏輯一個字都沒變,只是把「遞迴呼叫」換成「移動指標」。 實測與遞迴版在全部 118621 組上答案完全一致。 好處:空間從 O(h) 降到 O(1),而且永遠不會 stack overflow —— 在這題 n 可以到 10⁵ 的情況下,這不是理論上的好處(見下方複雜度分析)。

邊界與陷阱// PITFALLS

窮舉 2055 棵 BST(值集 {0..n-1},n=1..8)× 全部 ordered (p,q) = 118621 組。注意大多數錯法的症狀是崩潰而不是答錯。

< 寫成 <= 54283 tree=[0], p=q=0 失敗集合恰好 = LCA == max(p,q);
71% 安靜答錯、29% SIGSEGV
> 寫成 >= 54283 tree=[0], p=q=0 對稱地恰好 = LCA == min(p,q);同樣以安靜答錯為主

兩分支 left/right 對調 76986 tree=[1,0], p=q=0 SIGSEGV;巧合對的多是「根就是答案」的情形
只看 p、忽略 q 64338 tree=[1,0], p=0 q=1 → 0 實測「恆等於回傳 p 自己」 —— 退化成一次 BST search
&& 的語意寫成 || 103100 tree=[1,0], p=0 q=1 SIGSEGV;兩個分支條件不再互斥
先判「root 的值等於 p 或 q」再比較 0 — 這是對的 —— 只是把本來就會落到 else 的情況提早寫出來

最值得記的一列:< 改 <= 的失敗集合恰好等於「LCA 就是 max(p,q)」那一族 (特徵化零誤差,54283 組)。 換句話說,這個 bug 只在「p 或 q 本身就是答案」時發作 —— 正是題目那句「一個節點可以是自己的後代」所描述的情形。 而 p == q 的 15521 組會同時踩到這兩個 bug,所以兩者的最小反例都是單節點樹。
⚠ 但別把症狀記成「一定會崩」:實測 54283 組失敗裡只有 29% SIGSEGV, 71% 是安靜回傳錯的節點 —— 後者難發現得多。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼「嚴格」的比較會在寫錯時崩潰而不是答錯 正確: if (max(p,q) < root->val) go left 錯誤: if (max(p,q) <= root->val) go left 考慮 tree=[0]、p=q=0(最小反例): 正確版:max=0,「0 < 0」不成立 → 落到 else → return 節點 0 ✓ 錯誤版:「0 <= 0」成立 → 往左走 → root->left 是 nullptr → 下一層 root->val 就是解參考 nullptr → SIGSEGV 一般化:錯誤版會在「max(p,q) 剛好等於某個節點的值」時往左「走過頭」, 而那個節點正是答案。 ⚠ 但走過頭之後「不一定」會崩 —— 這是最容易誤解的一點: 左子樹裡通常還有「另一個目標」,所以它多半會落在某個真實節點上並回傳 → 安靜答錯,不會有任何徵兆 實測(54283 組失敗的分佈): 38762 組(71%)安靜回傳錯的節點 ← 大多數 15521 組(29%)走到 nullptr 而 SIGSEGV 官方那棵樹的具體例子: p=0, q=2 正解 2,<= 版回傳 0,「不崩潰」 p=2, q=4 正解 2,<= 版回傳 2 之外的節點,同樣不崩 實測失敗集合 = { LCA == max(p,q) } —— 特徵化零誤差(以集合相等驗證),54283/118621 // 這題沒有 null 檢查,所以「走到底」才會崩;但更常見的是根本沒走到底就交出錯節點
// PHASE 2: 為什麼沒有 nullptr 檢查也安全(以及前提被打破時的代價) 安全的理由:題目保證 p、q 都「存在於樹中」。 ⇒ 從 root 出發,每一步排除的都是「確定不含 p 和 q」的那一側 ⇒ p、q 永遠都還在目前子樹裡 ⇒ 必定會在走到 nullptr 之前先碰到分岔點 前提被打破時(實測,constraints 其實禁止這些): p 或 q 不在樹中: BST{3,5,7},q=100(超出值域)→ 走到 null root → SIGSEGV BST{3,5,7},q=6(值域內但不存在)→ 回傳 5,「不崩潰但靜默給出貌似合理的錯答」 實測 23020 組「缺席的內部值」:僅約 0.9% segfault,99% 安靜答錯 (查詢超出值域的值:0% 崩潰,全部安靜答錯) 輸入根本不是 BST: [5,1,9,7,3](7 被放在左子樹,違反 BST),p=7 q=9,真答案 5 → 這份程式碼回傳 9 ✗ 錯誤答案 [5,9,null,8],p=8 q=9,真答案 9 → 走到 null root → SIGSEGV // 「安靜答錯」比崩潰更危險 —— 崩潰至少會告訴你出事了
// PHASE 3: 為什麼不會溢位(值域 ±10^9,而 int 上限約 2.1×10^9) 這份程式碼「只做比較,不做算術」: max(p->val, q->val) 比較,不相減 min(p->val, q->val) 比較,不相減 ... < root->val 比較 ... > root->val 比較 實測 BST{-1e9, 0, 1e9},p=-1e9 q=1e9 → 回傳 0,calls=1,正確 max(-1e9, 1e9) = 1000000000、min = -1000000000 皆正確 壓力測試 BST{INT_MIN, 0, INT_MAX} → 回傳 0,無 UB ⚠ 但有一種「聰明」的寫法會溢位: if ((p->val - root->val) * (q->val - root->val) <= 0) return root; 這個「兩邊異號」的技巧看起來漂亮,但實測: (1e9 - (-1e9)) = 2000000000 仍然放得進 int(INT_MAX = 2147483647) ← 這一步沒事 但相乘之後 = 4000000000000000000,遠遠超過 int → 溢位,結果是垃圾值 (相減本身安全是因為 2e9 < INT_MAX;真正的殺手是那個乘法) // 值域給到 ±10^9 通常就是在暗示「別用相減或相乘」
// PHASE 4: 尾遞迴 → 迭代,為什麼是零成本的改寫 觀察三個 return 的位置: return lowestCommonAncestor(root->left, p, q); ← tail position return lowestCommonAncestor(root->right, p, q); ← tail position return root; ← 直接回傳 「tail position」的意思是:遞迴呼叫的結果「直接就是」本層的回傳值, 呼叫回來之後「沒有任何事要做」⇒ 本層的堆疊框其實可以先丟掉 所以改寫規則很機械: return f(root->left, ...) → root = root->left; continue; return f(root->right, ...) → root = root->right; continue; return root → return root; 實測:迭代版與遞迴版在全部 118621 組上「答案完全一致」 空間 O(h) → O(1),而且永遠不會 stack overflow // clang -O2 會自動做這件事(實測 4000 萬層都不崩),但 -O0 不會,標準也不保證
