題目簡介// THE QUESTION

QUESTION

給一棵二元搜尋樹(BST)和其中兩個節點 p、q, 找出它們的最近共同祖先。
注意題目的定義:「一個節點可以是自己的後代」 —— 所以如果 p 是 q 的祖先,答案就是 p 自己。
節點數 2 ~ 10⁵,值互不相同,值域 ±10⁹,保證 p、q 都存在。

這是本章第一題真正利用 BST 排序性質的題目。 前面九題都是「走訪整棵樹」,這一題完全不走訪 —— 它只是沿著一條路徑往下走。

核心轉換:把 p 和 q 看成一個區間 [min, max]。 接著每一步只問一件事:目前節點的值,在區間的左邊、右邊,還是裡面? 第一個「落在區間裡」的節點,就是答案。 實測窮舉 2055 棵 BST 的全部 118621 組 (p, q),這條性質零反例。
2

為什麼不必搜尋// WHY THIS

A 當成一般二元樹,左右都遞迴(LC236 的作法) O(n)
答案完全正確(本頁就是拿它當對拍參考解之一,118621 組零不一致), 但它每個節點都要走一次。 浪費了「這是 BST」這個題目白送的資訊。
△ 對但沒用上前提
B 各求一次「根到 p」「根到 q」的路徑再比對 O(h) 時間 · O(h) 空間
也正確(本頁的第二個對拍參考解)。 但要存下兩條路徑再取最長共同前綴 —— 多了 O(h) 的空間和兩趟走訪。
△ 對但繞路
ADOPT
C 把 [p, q] 當區間,一路往下直到「落在區間內」 O(h) 時間 · 一趟
兩個都比我小 → 答案在左邊;兩個都比我大 → 在右邊;否則我就是答案。 每一步都是「二選一」,不是「兩邊都試」 —— 所以走過的步數恰好等於 LCA 的深度 + 1。
● ADOPT · 只走一條路
「兩個都比我小,所以答案一定在左邊」——這一步就是 BST 性質的全部價值。 在一般二元樹裡你沒辦法做這個判斷,只能兩邊都找; 而 BST 的排序保證讓你可以整棵子樹直接排除。 實測:平衡 BST(n=1023)最多只走 8 步,而同樣節點數的一般樹要走 1023 個節點。
3

核心策略 · 三種情況// THE SHAPE

  1. 兩個目標都嚴格小於我(max(p,q) < root->val)—— 由 BST 性質,它們必定都在左子樹 ⇒ 往左,右子樹和我自己都排除。
  2. 兩個目標都嚴格大於我(min(p,q) > root->val)—— 同理 ⇒ 往右。
  3. 其他情況 —— 也就是 min ≤ 我 ≤ max。 此時兩個目標「一個在我左邊(或就是我)、一個在我右邊(或就是我)」 —— 我就是分岔點,回傳我自己。
⚠ 那兩個 < 和 > 必須是嚴格的。 寫成 <= 或 >=,就會在「p 或 q 本身就是分岔點」時走過頭。 而且實測顯示:走過頭之後大多數時候不會崩潰,而是安靜地回傳一個錯的節點 (54283 組失敗裡 71% 安靜答錯、只有 29% SIGSEGV)。詳見下方 LEMMA 1。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 為什麼比較必須「嚴格」—— 而且錯了會崩潰

把 < 改成 <=,意思就變成「兩個目標都小於等於我 ⇒ 往左走」。 但如果 max(p,q) 就是我自己,答案應該是我 —— 它卻往左走過頭了。

實測(窮舉 2055 棵 BST × 全部 118621 組 (p,q)):
· < 改成 <= → 失敗 54283 組,而且失敗集合恰好等於「LCA == max(p,q)」的那些組(特徵化零誤差)。
· > 改成 >= → 對稱地失敗 54283 組,恰好是「LCA == min(p,q)」。
⚠ 但「失敗」的形式大多不是崩潰:走過頭之後進到左子樹, 那邊通常還有另一個目標,所以它會落在一個真實節點上並把它交出來 —— 實測 54283 組失敗裡 38762 組(71%)安靜回傳錯的節點, 只有 15521 組(29%)真的走到 nullptr 而 SIGSEGV。
官方那棵樹的具體例子:p=0, q=2 正解是 2, <= 版回傳 0,完全不崩。
會崩的是「走到沒節點可走」的情形 —— 最小反例是單節點樹 [0]、p = q = 0。 安靜答錯比崩潰難發現得多。

LEMMA 2 · 為什麼「第一個落在區間內的節點」就是 LCA

它是共同祖先:走到節點 v 時,p 和 q 都還在 v 的子樹裡 (前面每一步排除的都是「確定不含它們」的那一邊)。而 min ≤ v ≤ max 表示一個在 v 的左半邊或就是 v、另一個在右半邊或就是 v —— 所以 v 是共同祖先。

它是「最近」的:再往下走任何一步,就會把其中一個目標甩掉 —— 往左會丟掉 max 那一側,往右會丟掉 min 那一側。 所以 v 是最後一個還能同時擁有兩者的節點。
實測:與兩個獨立參考解(一般二元樹 LCA、根到節點的路徑取最長共同前綴) 在 118621 組上比對,皆零不一致。

// 八種改法的實測結果(2055 棵 BST × 全部 ordered (p,q),共 118621 組) < 寫成 <= → 失敗 54283,恰好是「LCA == max(p,q)」那族 其中 71% 安靜答錯、29% SIGSEGV ← 大多數不會崩 > 寫成 >= → 失敗 54283,恰好是「LCA == min(p,q)」那族(對稱) max/min 對調 → 失敗 103100,p != q 時 100% 錯 → SIGSEGV 兩分支 left/right 對調 → 失敗 76986 → SIGSEGV 只看 p、忽略 q → 失敗 64338,實測「恆等於回傳 p 自己」(退化成 BST search) && 寫成 || → 失敗 103100 → SIGSEGV 先判「值相等」再比較 → 失敗 0 ← 這個是「對的」,不是陷阱 改寫成迭代(while) → 失敗 0 ← 也是對的,而且空間從 O(h) 降到 O(1) // 注意兩種症狀要分開看:走過頭「有時」撞到 nullptr(崩),「更常」落在錯的節點上(安靜答錯)

複雜度// COMPLEXITY

時間 O(h)　·　呼叫次數 = LCA 的深度 + 1　·　空間 O(h)(遞迴)/ O(1)(迭代)
情境實測呼叫次數說明
平衡 BST n=1023,p、q 是兩端極值葉1根就是分岔點,立刻停
平衡 BST n=1023,隨機 400 組的最大值8樹高 10 —— 最多就走這麼多步
退化成鏈 n=1000,p、q 在最深處999同樣的程式碼,樹形決定成本
退化成鏈 n=1000,p、q 在兩端1根就分岔了
實測驗證了一條漂亮的恆等式:呼叫次數 == LCA 的深度 + 1 —— 在全部 2055 棵樹 × 118621 組上零例外。 所以這題的成本不是由 n 決定,也不是由樹高決定,而是由答案在哪裡決定。 答案越靠近根,越快結束。
// ⚠ 堆疊:這是本章第一題 n 上限到 10^5 的遞迴 題目允許「退化成排序鏈」的 BST,所以遞迴深度最壞可達 10^5。 實測(clean build,未插樁): -O2 → clang 做了「尾呼叫最佳化(TCO)」:三個 return 全在 tail position ⇒ 遞迴被改寫成迴圈,實質 O(1) stack ⇒ 實測 n = 40000000(四千萬)在 ulimit -s 512 KB 下仍然存活,量不到崩潰點 -O0 → 沒有 TCO,才是真正的最壞情況: ulimit -s 8176 KB → 130722 存活 / 130723 崩 ⇒ 安全邊際只有 1.31 倍 ulimit -s 1024 KB → 16290 存活 / 16291 崩 ⇒ n=10^5 直接 SIGSEGV ulimit -s 512 KB → 8098 存活 / 8099 崩 ⇒ n=10^5 直接 SIGSEGV // 「有沒有開最佳化」在這題會改變答案 —— 這是前面九題都沒出現過的情況
這個發現值得記住:-O2 的尾呼叫最佳化讓遞迴實質變成迴圈,深度風險消失; 但 -O0 下 n=10⁵ 的安全邊際只剩 1.31 倍。 與其依賴編譯器幫你做 TCO,不如直接寫迭代版 —— 這題的遞迴是純尾遞迴,改成 while 迴圈是零成本的(實測 118621 組答案完全一致)。

一句洞察// INSIGHT

把 p 和 q 看成一個區間,問題就從「搜尋」變成「往下走」。 BST 的排序性質讓每一步都能整棵子樹排除,所以只走 O(h) 步 —— 而且走的步數恰好是 LCA 的深度 + 1。
而那兩個必須「嚴格」的比較,守的正是「節點可以是自己的後代」這個定義 —— 寫成 <= 會走過頭,而且七成的情況是安靜地回傳錯節點,不是崩潰。
