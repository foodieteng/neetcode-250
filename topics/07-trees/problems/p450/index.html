題目簡介// THE QUESTION

QUESTION

給 BST 的根節點和一個 key,刪掉值等於 key 的節點, 回傳更新後的根。key 可能不存在(那就什麼都不做)。
節點數 0 ~ 10⁴,值互不相同,值域 ±10⁵。

這是 701 插入的對偶題,而且明顯更難。 插入永遠是「掛一片新葉子」; 刪除卻可能要把一個有兩棵子樹的節點從中間挖掉 —— 那兩棵子樹要接到哪裡去?

整題只有一個難點:被刪的節點有兩個小孩。 0 個或 1 個小孩都可以「直接接上去」(把唯一的那個小孩頂上來就好); 兩個小孩就沒有明顯的贏家 —— 解法是「不真的刪它,而是找一個可以合法頂替它的值換上來,再去刪那個替身」。
2

替身只能是「中序後繼」// WHY THIS

A 隨便挑一個小孩頂上來 結果不是 BST
把左小孩頂上來,右子樹整棵就沒地方掛(它比左小孩大,不能當左小孩的左子樹, 當右子樹又會蓋掉原有的)。 兩棵子樹都要保住,替身就只能是那個「剛好卡在中間」的值。
× REJECT · 順序壞掉
B 用「前繼」(左子樹的最大值) 也完全正確
前繼和後繼是對稱的,兩個都對 —— 前繼是「比它小的裡面最大的」,同樣剛好卡在中間。 但要記得:選了前繼就要往左遞迴刪。 方向配錯 → 實測「兩個小孩」的情形全數 2652 組錯光。
△ 對稱地正確
ADOPT
C 中序後繼 = 右子樹一路往左走到底 O(h) · 常數 2
它是「比被刪的值大的所有值當中,最小的那一個」—— 換上來之後,左子樹全部還是比它小、右子樹全部還是比它大,BST 完好。 而且它必定沒有左小孩(它就是最左),所以刪它一定落在簡單情況。
● ADOPT · 換完再刪
「替身必定沒有左小孩」這件事非常關鍵 —— 它保證了「第二次刪除一定落在 0 或 1 個小孩的簡單情況」,不會再遞迴下去找第三個替身。 所以整個流程最多只會發生一次替換。
3

核心策略 · 三種情況// THE SHAPE

  1. 還沒找到 —— 比大小往左或往右,並且回寫 (701 的那個模式,這裡更加必要)。
  2. 找到了,而且 0 或 1 個小孩 —— return root->left ? root->left : root->right; 把唯一的小孩(或 nullptr)直接交給父節點接住。
  3. 找到了,兩個小孩 —— 找中序後繼、把 key 和後繼的值交換, 然後到右子樹再刪一次 key。
⚡ 你這份寫法用的是交換(swap),而不是課本常見的複製。 課本版:root->val = succ->val; 然後去刪「succ->val」。 你的版本:swap 之後 key 被搬到後繼的位置,然後去刪「key」。 實測兩者產生的樹完全相同 —— 見下方 LEMMA 2。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · swap 讓 BST 暫時壞掉,為什麼遞迴還找得到?

swap 之後,後繼的節點身上寫著 key —— 而 key 比右子樹裡所有其他值都小, 所以右子樹「暫時」不是合法 BST。那遞迴憑什麼還能正確下降?

關鍵:壞掉的那個節點是搜尋的「終點」,而不是路上任何一個「岔路的決策點」。
設後繼是 S(右子樹的最左節點)。路徑 右子樹根 → … → S 上的每個節點 p, 值都沒有被動過,而且 p->val > key (因為 key 比右子樹原本所有值都小)—— 所以每一步都判「往左」,而這條全左的路正好就是通往最左節點 S 的路。 走到 S 時 S->val == key,命中。
實測:窮舉 n=1..8 全部 BST 的「兩個小孩」情形共 2652 組 —— 下降路徑「全部往左」2652/2652,遞迴找不到節點的次數 0。

LEMMA 2 · swap 版與課本 copy 版,產生的樹「完全相同」

課本版寫 root->val = succ->val; 再去刪 succ->val; 你的版本 swap 之後去刪 key。 兩者不只是「都合法」,而是逐位元相同。

實測:窮舉 19633 組 (樹, key) + 隨機 20 萬組 —— 形狀差異 0。
原因:兩版物理上摘掉的是同一個節點(都是後繼那個節點物件), 差別只在「它被丟掉之前身上寫的數字」是 key 還是 succ->val —— 而它馬上就消失了,外界看不到。
更強的實測:被丟掉的節點在被丟掉的當下,值恰好等於 key —— 15521/15521 命中,零例外。

複雜度// COMPLEXITY

時間 O(h),但常數是 2(找後繼走一趟 + 再遞迴刪一趟)　·　空間 O(h)
情境遞迴呼叫後繼走的步數合計
平衡 BST n=1023,刪根(兩個小孩)10818
平衡 BST n=1023,刪最深的葉10010
退化右鏈 n=1000,刪最深端100001000
最壞:根有兩子、右子樹是長 1000 的左鏈10019992000 ≈ 2h
那兩趟走的是同一條路 —— 先為了找後繼往左走到底, 再為了刪它沿著同一條路遞迴下去。所以是 2h 而不是 h², 仍然是 O(h)。 而且課本的 copy 版工作量完全一樣 —— swap 版沒有額外成本。

一句洞察// INSIGHT

「兩個小孩」不能直接刪,所以不刪它 —— 把中序後繼的值換上來,再去刪那個後繼。 而後繼必定沒有左小孩,所以第二次刪除一定落在簡單情況,不會無限遞迴下去。
至於 swap 造成的暫時 BST 違反為什麼無害: 壞掉的那個節點是搜尋的終點,不是路上的決策點 —— 而通往它的路,每一步都判「往左」。
