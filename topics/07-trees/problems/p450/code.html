完整實作// SWAP VARIANT

p450.cpp C++17 
class Solution {
public:
    TreeNode* deleteNode(TreeNode* root, int key) {
        if (root == nullptr) {
            return root;                  // key 不存在,什麼都不做
        }

        if (root->val > key) {
            root->left = deleteNode(root->left, key);
        } else if (root->val < key) {
            root->right = deleteNode(root->right, key);
        } else {
            // 0 或 1 個小孩:把唯一的那個(或 nullptr)交給父節點接住
            if (!root->left || !root->right) {
                return root->left ? root->left : root->right;
            }

            // 兩個小孩:找中序後繼 = 右子樹一路往左到底
            TreeNode* succ = root->right;
            while (succ->left) {
                succ = succ->left;
            }

            swap(root->val, succ->val);   // key 被換到 succ 的位置
            root->right = deleteNode(root->right, key);
        }

        return root;
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

那個 if (!root->left || !root->right) return ...; 一行做了三件事: 處理葉節點(回 nullptr)、只有左子(回左)、只有右子(回右)。 而且它必定是遞迴的終點 —— 因為後繼保證沒有左小孩, 所以第二次刪除一定落在這一行,不會再找第三個替身。

驗證// CROSS CHECK

// 對拍(swap 版 vs 課本的 copy 版) 課本版:root->val = succ->val; root->right = deleteNode(root->right, succ->val); 你的版:swap(root->val, succ->val); root->right = deleteNode(root->right, key); 窮舉:n = 0..8 的全部 BST 形狀(2055 棵)× 每個 key ∈ {-1,0,...,n} (涵蓋存在與不存在的 key) → 共 19633 組 隨機:200000 組(n ≤ 13,含大量不存在的 key) 形狀差異 : 0 ← 不只是「都合法」,而是「完全一樣的樹」 為什麼會完全一樣: 兩版「物理上摘掉的是同一個節點物件」(都是後繼那個節點) 差別只在它被丟掉之前身上寫的數字是 key 還是 succ->val —— 而它馬上就消失了 // 用「不同寫法但同結果」的參考解對拍,比自己跟自己比對有意義得多
// 三個不變量(窮舉 2055 棵樹 × 19633 組) 結果永遠是合法 BST(中序嚴格遞增) → 0 違反 值集合恰為「原集合 − {key}」 → 0 違反 節點位址集合是原集合的子集,且無重複 → 0 違反(沒有遺失、沒有憑空產生、沒有成環) 官方範例: [5,3,6,2,4,null,7] key=3 → [5,4,6,2,null,null,7] ✓ 與官方期望完全相同 [5,3,6,2,4,null,7] key=0 → 原樹不變 ✓ [] key=0 → [] ✓ 邊界(全部實測): 刪葉節點 → ✓ 只有左子 → ✓ 只有右子 → ✓ 刪根(兩個小孩) → ✓ key 不存在 → 樹不變 ✓ 單節點樹 key 相符 → [] 單節點樹 key 不符 → 原樹 ✓ // 「位址集合是子集」這個檢查特別重要 —— 它同時排除了遺失節點與重複掛載

⚡ swap 讓 BST 暫時壞掉 —— 為什麼無害// THE CENTREPIECE

// 問題:swap 之後右子樹不是合法 BST,遞迴憑什麼還找得到 key? 設被刪節點 X(X->val == key),右子樹 Rt,後繼 S = Rt 的最左節點(S->val = m) swap 之後: X->val = m ← m 是 Rt 的最小值,且大於整棵左子樹 ⇒ 根這裡的 BST 性質「仍然成立」 S->val = key ← key 比 Rt 裡所有其他值都小,卻待在最左下角 ⇒ Rt「暫時違反 BST」 關鍵:違反只發生在「最左端」的那一個節點,而找 key 的路本來就只往最左端走。 對路徑上任一個「非 S」的節點 p: p->val 完全沒被動過,而且 p->val > m > key ⇒ p->val > key ⇒ 判「往左」 ⇒ 這一路的 LEFT 正好就是「X → S」那條最左路徑,一步不多一步不少 走到 S 時 S->val == key ⇒ 命中 換句話說:壞掉的那個節點是「搜尋的終點」,不是路上任何一個「岔路的決策點」—— 它那個被改壞的值,在下降過程中「從來沒有被用來做決定」。 // S 必定沒有左小孩(它是最左),所以命中時直接走「0/1 個小孩」那一支,不會再遞迴
// 實測佐證 窮舉 n=1..8 全部 BST 的「兩個小孩」情形 → 共 2652 組 遞迴進入右子樹後,下降路徑「全部往左」 → 2652 / 2652 (not-all-left = 0) 遞迴找不到節點的次數 → 0 節點層級的驗證(19633 組): key 存在的 15521 組:恰好「一個」節點變成不可達,|before| − |after| == 1 而且那個被丟掉的節點「在被丟掉的當下,值恰好等於 key」→ 15521 / 15521,零例外 key 不存在的 4112 組:零節點被丟棄 全程無節點重複、無成環 // 最後那條最有說服力:被物理摘掉的確實是「持有 key 的節點」,不是持有後繼值的節點
這個論證有一個隱藏前提:BST 的值必須唯一(本題有保證)。 如果允許重複值,key 有可能在右子樹裡另有同值節點,搜尋就可能提前命中錯的那一個 —— 但那個問題課本的 copy 版同樣有,不是 swap 版特有的。

邊界與陷阱// PITFALLS

窮舉 2055 棵 BST(n=0..8)× 每個 key ∈ {-1,0,…,n} = 19633 組。 家族切分:key 不存在 4112 組、 存在且兩個小孩 2652 組、存在且葉/單子 12869 組。

陷阱違反數最小反例壞在哪
用「前繼」但仍往右遞迴刪 2652 tree=[1,0,2] key=1 不是合法 BST;失敗集= 兩子家族全體
swap 之後遞迴刪錯邊 2652 tree=[1,0,2] key=1 key 被換到右邊卻往左找 ⇒ 什麼都沒刪,節點數多 1
用 copy 但遞迴目標沒改 2652 tree=[1,0,2] key=1 copy 後 key 已消失 ⇒ 找不到 ⇒ 留下重複值 [2,0,2]
缺少「0/1 個小孩」的處理 崩潰 15521 tree=[0] key=0 只要 key 存在必崩,但不會靜默答錯(反而較安全)
找後繼時多走一步 崩潰 1728 tree=[1,0,2] key=1 觸發條件恰為「右子沒有左子」那一族(1728 組)
忘記回寫 14270 tree=[0,null,1] key=1 失敗率 72.7% —— 比 701 的 4706/4707 低,見下方走讀
兩子分支沒有 return root 2652 tree=[1,0,2] key=1 結果「仍是合法 BST」 ⇒ 結構檢查抓不到,最陰險
單子分支的三元運算子寫反 0/19633 — 完全等價(連形狀都一樣)—— 這不是陷阱
三個最值得記的教訓:
① 最後一列是「假陷阱」 —— return root->right ? root->right : root->left; 和原版完全等價(進到那行時已保證至多一邊非空),別把它背成錯的。
② 「兩子分支沒有 return root」的錯誤通過 BST 合法性檢查 —— 截下來的子樹本身仍然合法,只有「值集合 / 節點數」才抓得到。
③ 「缺少 0/1 個小孩處理」只會崩、不會靜默錯 —— 某種意義上比 ② 安全,因為線上跑一次就會發現。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼替身只能是「中序後繼(或前繼)」 被刪節點 X 有兩棵子樹 L 和 R,要找一個值 v 頂替 X 的位置,條件是: L 裡所有值 < v < R 裡所有值 滿足這個條件的值只有兩個候選: max(L) = 中序「前繼」 —— 比 X 小的裡面最大的 min(R) = 中序「後繼」 —— 比 X 大的裡面最小的 (因為原本 max(L) < X < min(R),而 X 要被拿掉,剩下的空隙只有這兩個端點填得起來) 而且這兩個節點各有一個好性質: min(R) 必定「沒有左小孩」(它是 R 的最左) max(L) 必定「沒有右小孩」(它是 L 的最右) ⇒ 刪它們一定落在「0 或 1 個小孩」的簡單情況 ⇒ 遞迴最多再一層就結束 實測:前繼版和後繼版都正確,但「選了前繼就要往左遞迴刪」—— 方向配錯的話,兩子家族 2652 組『全數』錯光 // 兩個候選對稱地正確,這也是為什麼題目說「答案可能不只一種」
// PHASE 2: 回寫的失敗率為什麼比 701 低?(72.7% vs 99.98%) 701 插入:丟掉回寫 → 錯 4706/4707(99.98%),只有「空樹」逃得掉 450 刪除:丟掉回寫 → 錯 14270/19633(72.7%),巧合正確 5363 組 差別在於刪除多了「兩條不需要回寫的逃生路」: ① key 不存在(4112 組):樹本來就沒有任何改動,回不回寫都一樣 ② 根節點自己就是目標:回傳值「直接被呼叫端接住」,中間沒有任何一層要回寫 兩者合計恰好就是那 5363 組。 ⇒ 所以「回寫」在刪除裡同樣是必要的,只是「測資更容易矇混過關」—— 插入幾乎一測就爆,刪除卻有 27% 的組合看起來沒事 // 失敗率低不代表 bug 比較輕微,只代表它更難被隨機測資抓到
// PHASE 3: 那個「假陷阱」為什麼真的等價 原版: return root->left ? root->left : root->right; 變體: return root->right ? root->right : root->left; 進到這一行的前提是 if (!root->left || !root->right) —— 也就是「至多一邊非空」 三種情形逐一檢查: 兩邊都空 → 原版回 root->right(nullptr);變體回 root->left(nullptr) 一樣 只有左子 → 原版回 left;變體 right 為空 → 回 left 一樣 只有右子 → 原版 left 為空 → 回 right;變體回 right 一樣 兩邊都非空 → 「走不到這一行」 實測:19633 組逐對比較「精確的 level-order 形狀」→ 完全相同,0 差異 // 這種「看起來像 bug 其實等價」的東西值得明講,否則會被背成錯的
// PHASE 4: 如果要 delete 掉節點(避免記憶體洩漏) LeetCode 不要求釋放,但真實程式裡要。好消息是這個寫法很好加: if (!root->left || !root->right) { TreeNode* survivor = root->left ? root->left : root->right; delete root; // ← 就這一行 return survivor; } 為什麼安全(實測佐證): · 每次成功刪除「恰好一個」節點變成不可達 → 15521/15521 · 而且那個節點「在被丟掉的當下,值恰好等於 key」→ 15521/15521 · key 不存在時「零節點」被丟棄 → 4112/4112 · 全程無節點重複、無成環 ⇒ 不可能 double free ⚠ 但要注意順序:必須「先」把 survivor 存起來再 delete root, 否則 delete 之後再讀 root->left 就是 use-after-free // swap 版在這裡沒有額外風險 —— 被摘掉的永遠是持有 key 的那個節點

swap 造成的暫時 BST 違反無害,因為壞掉的節點是搜尋終點而非決策點 —— 通往它的路每一步都判往左(實測 2652/2652)。swap 版與課本 copy 版產生完全相同的樹(19633 組零差異),物理摘掉的是同一個節點,而它被丟掉時身上的值恰好是 key。
