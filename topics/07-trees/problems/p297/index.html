二元樹的序列化與反序列化

1

題目簡介// THE QUESTION

QUESTION

設計兩個函式:serialize 把一棵二元樹轉成字串,deserialize 把字串還原成完全相同的樹。 字串格式自己決定,只要兩邊對得上。
節點數 0 ~ 10⁴,值 −1000 ~ 1000(可以是負數、多位數)。
範例:[1,2,3,null,null,4,5] → 序列化 → 反序列化 → 同一棵樹。

只寫下節點的值,形狀就丟了:[1,2](2 在左)和 [1,null,2](2 在右)的值都是 1、2。 要把「這裡沒有節點」也寫下來,用一個記號(這裡是 n)代表 null, 字串才能唯一對應一棵樹。
2

為什麼用「BFS + null 記號 + 空白分隔」// KNOCKOUT

A 只寫值,不寫 null 形狀遺失
[1,2] 序列化成 "1 2 ",還原成 [1,2,2]。 實測 n ≤ 8 的 24,672 組裡錯 24,612 組,只有 n ≤ 1 會對。
× REJECT · 不唯一
B 前序 DFS + null 記號(遞迴) 正確,但會遞迴
格式同樣唯一,實測 0 失敗。但序列化、反序列化都要遞迴, 深度等於樹高:n = 10⁴ 斜鏈深度 10,001;10⁶ 個節點的斜鏈在 -O0 直接崩潰。
△ 對,但吃堆疊
ADOPT
C BFS 逐層寫出,null 寫成 n,每個 token 後面加空白 O(n) 時間 · O(n) 空間
兩邊都用 queue,完全不遞迴(10⁶ 個節點的斜鏈也正常)。 空白分隔讓 -1000 這種多字元的值能被 stringstream 整個讀出來。 實測往返 294,873 棵樹,不一致 0。
● ADOPT · 唯一且不遞迴
3

核心策略// STRATEGY

  1. 序列化:BFS。pop 出來是節點就寫它的值、把兩個小孩(包含 null)都放進 queue; pop 出來是 null 就寫 n。空樹寫空字串。
  2. 反序列化:第一個 token 是根,放進 queue。之後每 pop 一個節點, 就讀兩個 token,分別是它的左、右小孩;不是 n 就建節點並放進 queue。
  3. 兩邊用同一個順序:序列化時「節點出隊、放入兩個小孩」的順序,就是反序列化時「節點出隊、讀兩個 token」的順序。
[1,2,3,null,null,4,5] → "1 2 3 n n 4 5 n n n n "
5 個值 + 6 個 n = 2n + 1 個 token
4

動畫演示// VISUALIZER

00 / 08
▶ Deserialize · 每 pop 一個節點吃兩個 token(左、右)
00 / 08
把兩個動畫的 queue 對照著看:序列化時節點出隊的順序是 1、2、3、4、5,反序列化時也是 1、2、3、4、5。 序列化時每個節點放進兩個小孩,反序列化時每個節點就讀兩個 token —— 兩邊一步一步對得上。
5

為什麼 token 一定剛好配對// 2n + 1

// LEMMA: n 個值 + (n + 1) 個 n

n 個節點共有 2n 個子指標,其中 n − 1 個指向真的節點(除了根,每個節點都是某人的小孩), 剩下 n + 1 個是 null。序列化把每個 null 都寫成 n,所以總共 2n + 1 個 token。

扣掉開頭的根,剩下 2n 個,正好給 n 個節點各讀兩個。 所以反序列化迴圈裡第二次 ss >> word 沒有檢查也不會出事(實測 294,873 棵樹都成立)。

⚠ 前提是結尾的 n 一個都不能省。LeetCode 顯示樹時會把結尾的 null 去掉, 如果照那個格式輸出,[1,2] 會變成 "1 2 ",還原成 [1,2,2](實測錯 10,704 / 24,672)。

6

複雜度// COMPLEXITY

兩個方向都是每個節點進出 queue 一次、每個 token 寫或讀一次。額外空間是字串本身和 queue。

時間 O(n)(兩個方向)　·　空間 O(n)(字串 + queue)
項目值實測依據(n = 10⁴)
TimeO(n)serialize 391 ~ 519 µs,deserialize 1,049 ~ 1,373 µs
字串長度≤ 80,002 字元全部 −1000 時最長,約 8 bytes / 節點
queue 最大長度看樹寬平衡樹序列化時 10,001;斜鏈只有 3
堆疊不遞迴10⁶ 個節點的斜鏈在 -O0 也正常往返
7

一句洞察// INSIGHT

序列化的重點不是把值存下來,而是把「形狀」存下來 —— null 記號就是形狀。 BFS 版是 102 層序走訪多寫了 null, 反序列化則是同一個 queue 反著跑一次。 寫出來的 token 數恆為 2n + 1,這個性質讓讀的一方可以放心地「一次讀兩個」。

// ONE-LINE TAKEAWAY
BFS 逐層寫出每個節點的值,null 寫成 n,每個 token 後加空白;反序列化用同一個 queue,每 pop 一個節點讀兩個 token 當左右小孩。n 個節點恆產生 2n+1 個 token,所以一次讀兩個剛好配對 —— 前提是結尾的 n 不能省。全程不遞迴,O(n) 時間與空間。
