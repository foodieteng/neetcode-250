重點回顧// KEY POINTS

重點內容
null 記號把 null 寫成 n,形狀才不會丟
分隔符每個 token 後加空白;值可能是負數或多位數
序列化BFS,null 也進 queue,pop 到 null 就寫 n
反序列化同一個 queue 順序,每 pop 一個節點讀兩個 token
2n + 1n 個值 + n+1 個 n;根之後剩 2n 個,剛好配對
結尾的 n不能省;省了會讓沒檢查的第二次讀取沿用舊值
空樹寫成 "",讀的一方先檢查 empty()
複雜度時間、空間都 O(n);不遞迴

// 輸入 [1,2,3,null,null,4,5](官方範例 1) 1 / \ 2 3 / \ 4 5 先序列化,再把字串反序列化回來。 以下是對真實程式插樁後印出的過程。 // 5 個節點、6 個 null 位置
// STEP 1: serialize —— BFS 出隊順序 pop 1 → "1 " queue [2, 3] pop 2 → "2 " queue [3, ∅, ∅] pop 3 → "3 " queue [∅, ∅, 4, 5] pop ∅ → "n " pop ∅ → "n " queue [4, 5] pop 4 → "4 " queue [5, ∅, ∅] pop 5 → "5 " queue [∅, ∅, ∅, ∅] pop ∅ ×4 → "n " ×4 // 結果 "1 2 3 n n 4 5 n n n n ",11 個 token = 2 × 5 + 1
// STEP 2: deserialize —— 建根 ss >> word 讀到 "1" → root = 1,queue [1] 剩下的 token:2 3 n n 4 5 n n n n(10 個 = 2 × 5) // 接下來每一圈 pop 一個節點、讀兩個 token
// STEP 3: deserialize —— 五圈 第 1 圈 pop 1 讀 "2" "3" → 建 2、3 queue [2, 3] 第 2 圈 pop 2 讀 "n" "n" → 不建 queue [3] 第 3 圈 pop 3 讀 "4" "5" → 建 4、5 queue [4, 5] 第 4 圈 pop 4 讀 "n" "n" → 不建 queue [5] 第 5 圈 pop 5 讀 "n" "n" → 不建 queue [] // 節點出隊順序 1、2、3、4、5,和序列化時完全一樣
// OUTPUT 第 6 次 ss >> word 讀到結尾 → 離開迴圈 還原結果 = [1,2,3,null,null,4,5] ✓ 與原樹相同 迴圈跑了 5 次 = n // 往返對拍 294,873 棵樹,不一致 0
把 STEP 1 和 STEP 3 並排看:序列化時 pop 1 放進 2、3,反序列化時 pop 1 讀出 2、3。 兩邊用的是同一個 queue 順序,只是一個在「寫」、一個在「讀」。

// ANSWERS
Q1 為什麼要寫 null?

只寫值的話,很多形狀不同的樹會得到同一個字串。最小反例:[1,2](2 在左)和 [1,null,2](2 在右)都會寫成 "1 2 ",讀的一方沒辦法分辨。

實測只寫值的版本在 n ≤ 8 的 24,672 棵樹中錯 24,612 棵,只有 n ≤ 1 會對。[1,2] 會被還原成 [1,2,2]。

⚡ 寫出 null 等於把每個「位置」都記下來,有節點寫值、沒節點寫 n,形狀就唯一了。

Q2 為什麼要分隔符?

值的範圍是 −1000 ~ 1000,一個值可能佔 1 到 5 個字元。沒有分隔符就不知道一個值在哪裡結束:[1,2] 會寫成 "12nnn",讀回來變成 [12](實測錯 24,648 棵)。

如果改成一個字元一個字元讀(c − '0'),值只能是 0 ~ 9:[-1000] 會被讀成 [-3,1,0,0,0]。

⚡ 陷阱在於:如果測資的值都是 1 ~ 8,這個錯法全部會過(實測 2,056 棵只用 1..8 的樹 0 失敗)。所以測試一定要放負數和多位數。

Q3 為什麼一定讀得到兩個?

n 個節點有 2n 個子指標,其中 n − 1 個指向真的節點,n + 1 個是 null。序列化寫出 n 個值和 n + 1 個 n,共 2n + 1 個 token。

扣掉根之後剩 2n 個,而迴圈會 pop 出 n 個節點,每個讀兩個,剛好用完。實測所有序列化結果「根之後的 token 數」都是偶數,迴圈都恰好跑 n 次。

⚡ 所以右小孩那次 ss >> word 沒檢查成功與否,在這個格式下也不會出事。

Q4 省略結尾的 n 會怎樣?

token 數就不再是 2n + 1。當某個節點只剩左邊的 token 可讀時,右邊那次 ss >> word 會失敗,但 word 不會被清空,還是剛剛讀到的左小孩的值,於是右邊也建出一個同值的節點。

[1,2] → "1 2 " → [1,2,2]。實測錯 10,704 / 24,672,錯的剛好是「最後一個非 null 節點是左小孩」的那些樹;[1,null,2] 這種最後一個是右小孩的就沒事。

⚡ 不會崩潰,是安靜地多長出節點,所以更難發現。

Q5 BFS vs 前序 DFS

BFS(你的寫法):不遞迴,10⁶ 個節點的斜鏈在 -O0 也能往返。缺點是 queue 的大小看樹的寬度,平衡樹 n = 10⁴ 時序列化會放進 10,001 個元素。

前序 DFS:程式比較短,兩個函式是對稱的遞迴(見 App 1)。缺點是遞迴深度等於樹高,n = 10⁴ 斜鏈深度 10,001;10⁶ 的斜鏈在 -O0 會崩潰。

兩者序列化出來的 token 數一樣,都是 2n + 1。

⚡ 兩邊必須用同一種順序:用前序寫、用 BFS 讀,實測錯 24,480 棵;n ≤ 2 時兩種順序剛好一樣,所以小測資抓不到。

App 1 前序 DFS 版
void ser(TreeNode* root, string& s) {
    if (!root) { s += "n "; return; }
    s += to_string(root->val) + " ";
    ser(root->left, s);
    ser(root->right, s);
}
string serialize(TreeNode* root) { string s; ser(root, s); return s; }

TreeNode* des(stringstream& ss) {
    string w; ss >> w;
    if (w == "n") return nullptr;
    TreeNode* node = new TreeNode(stoi(w));
    node->left = des(ss);          // 前序:先建左子樹
    node->right = des(ss);
    return node;
}
TreeNode* deserialize(string data) { stringstream ss(data); return des(ss); }

空樹會寫成 "n ",讀的時候第一個 token 就是 n,直接回傳 nullptr,所以這個版本不需要特別處理空字串。

實測:往返 200,000 棵隨機樹(值含 −1000、1000),不一致 0。

App 2 省略結尾的 n

只要改一行:右小孩那次讀取失敗時就結束迴圈,而不是沿用舊的 word:

while (ss >> word) {
    TreeNode* node = q.front(); q.pop();
    if (word != "n") { /* 建左小孩 */ }
    if (!(ss >> word)) break;      // 右邊沒有 token 了 → 右小孩是 null
    if (word != "n") { /* 建右小孩 */ }
}

字串讀完的時候,還沒讀到的位置本來就是被省略的 null,不用處理。

實測:序列化時把結尾的 n 全部刪掉,再用這個版本讀回來,往返 200,000 棵隨機樹,不一致 0。

App 3 BST 不寫 null

可以。BST 的前序加上「值的上下界」就能唯一還原:第一個值是根,接下來比根小的屬於左子樹、比根大的屬於右子樹。遞迴時帶著區間 [lo, hi](和 98 同一個思路),下一個值不在區間內就代表這個位置是 null。

TreeNode* build(vector<int>& v, int& i, int lo, int hi) {
    if (i == (int)v.size() || v[i] < lo || v[i] > hi) return nullptr;
    TreeNode* node = new TreeNode(v[i++]);
    node->left  = build(v, i, lo, node->val - 1);
    node->right = build(v, i, node->val + 1, hi);
    return node;
}
// 序列化:前序只寫值;反序列化:讀成 vector,build(v, i = 0, INT_MIN, INT_MAX)

實測:往返 200,000 棵隨機 BST,不一致 0;字串長度平均只有你的 BFS 格式的 68.3%(省掉了所有 n)。

⚡ 一般二元樹不行,因為值和位置之間沒有關係,只能靠 null 記號記下形狀。
