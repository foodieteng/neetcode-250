// 輸入 [3,2,3,null,3,null,1](官方範例 1) A(3) / \ B(2) C(3) \ \ D(3) E(1) 以下是對真實程式插樁後印出的呼叫序列(19 次,含 12 次打在 nullptr) // 注意 D 和 E 各出現「兩次」—— 第二次是 cache hit
// STEP 1: rob(A) —— MISS,先算「搶 A」需要的四個孫子 memo[A] 不存在 → 展開 A->left = B 存在: ll = rob(B->left) = rob(null) = 0 lr = rob(B->right) = rob(D) ↓ 下一步 // 「搶 A」要跳過 B 和 C,直接問它們的小孩
// STEP 2: rob(D) —— MISS,葉子 D 沒有小孩,也沒有孫子 ⇒ ll=lr=rl=rr=0 搶 D = 3 + 0 + 0 + 0 + 0 = 3 不搶D = rob(null) + rob(null) = 0 memo[D] = max(3, 0) = 3 回傳 3 ⇒ lr = 3 // 葉子永遠是「搶」贏 —— 不搶它沒有任何補償
// STEP 3-4: 右邊同理 —— rob(E) MISS A->right = C 存在: rl = rob(C->left) = rob(null) = 0 rr = rob(C->right) = rob(E) rob(E):搶 E = 1,不搶 E = 0 memo[E] = max(1, 0) = 1 回傳 1 ⇒ rr = 1 // 到這裡 A 的四個孫子齊了:ll=0, lr=3, rl=0, rr=1
// STEP 5: A 的第一分支算完 搶 A = 3 + ll 0 + lr 3 + rl 0 + rr 1 = 7 接著算第二分支:rob(A->left) + rob(A->right) = rob(B) + rob(C) // 就是這個第二分支,會再次走到 D 和 E —— 重複計算的來源
// STEP 6-7: rob(B) —— 這裡出現第一次 CACHE HIT rob(B) MISS: B->left 是 null ⇒ ll = lr = 0 B->right = D 存在 ⇒ rl = rob(D->left) = 0, rr = rob(D->right) = 0 搶 B = 2 + 0 + 0 + 0 + 0 = 2 不搶B = rob(B->left) + rob(B->right) = rob(null) + rob(D) ↑ ⚡ rob(D):memo[D] = 3,非 0 ⇒ if (memo[root]) 成立 ⇒ 直接回傳 3 這是 D 的第二次走訪,但「沒有重新展開」 不搶B = 0 + 3 = 3 memo[B] = max(2, 3) = 3 回傳 3 // 不搶 B(2)而讓 D(3)去搶,比較划算 —— 所以 SKIP 這條贏
// STEP 8-9: rob(C) —— 第二次 CACHE HIT rob(C) MISS: C->left 是 null ⇒ ll = lr = 0 C->right = E ⇒ rl = rob(E->left) = 0, rr = rob(E->right) = 0 搶 C = 3 + 0 = 3 不搶C = rob(null) + rob(E) ↑ ⚡ rob(E):memo[E] = 1 ⇒ 直接回傳 1(E 的第二次走訪) 不搶C = 0 + 1 = 1 memo[C] = max(3, 1) = 3 回傳 3 // 這次反過來:搶 C(3)比讓 E(1)去搶好
// OUTPUT 回到 A: 搶 A = 7 (= A3 + D3 + E1) 不搶A = rob(B) 3 + rob(C) 3 = 6 memo[A] = max(7, 6) = 7 答案 = 7 ✓ 與官方一致 搶的是 A(3) + D(3) + E(1) —— A 與 D、E 是「祖孫」,不相連,可同時搶 呼叫統計:19 次 5 次 = 五個節點各展開一次 2 次 = D、E 的快取命中 12 次 = 打在 nullptr 上 memo.size() = 5 = 節點數 // 對拍獨立 pair-DFS 參考解:1072 萬組,不一致 0
整個 trace 裡最重要的是 STEP 7 和 STEP 9 那兩次命中。 如果 memo[D] 剛好是 0,那兩行就會變成「整棵子樹重新展開」 —— 而這棵樹裡它們湊巧是 3 和 1,所以看起來一切正常。 bug 就藏在這種「剛好沒事」裡。

// ANSWERS
Q1 為什麼跳到孫子?

限制是「不能搶直接相連的兩間」= 父與子不能同時搶。祖孫之間沒有邊,所以不受限制。

於是「搶這間」這條路上:兩個小孩被封鎖,但孫子完全自由 —— 所以要問的是四個孫子 ll, lr, rl, rr,而不是小孩。

不必跳到曾孫,因為孫子的答案 rob(孫) 本身已經遞迴處理了它底下的一切。只要跳過「被封鎖的那一層」就夠了。

⚡ 反過來說,「不搶這間」時兩個小孩完全自由,所以那條路就是 rob(left) + rob(right) —— 這也是為什麼兩條路問的層數不同。

Q2 沒有 memo 的複雜度?

Θ(φⁿ),φ ≈ 1.618 —— 就是費氏遞迴。

重複計算來自兩條路在同一批節點上重疊。第一分支算了 rob(A 的四個孫);第二分支算 rob(B),而 rob(B) 進去之後又會算 rob(B 的兩個小孩) —— 那正是 A 的孫子。同一個節點被兩條路各算一次。

在單邊鏈上這就化成 T(n) = T(n−1) + T(n−2),解是 φⁿ。

實測(完全拿掉 memo,單邊鏈):n=20 → 57,311;n=25 → 635,619;n=30 → 7,049,153;n=40 → 866,988,871(3.27 秒)。每多 5 個節點約 ×11.09,即每個節點 ×1.618。

答案仍然是對的(實測 104 萬組窮舉 0 失敗),純粹是慢。

Q3 if (memo[root]) 的問題?

它測的是值是不是非 0,不是這個 key 存不存在。一個真實答案就是 0 的節點,把 0 寫進 memo 之後,下次讀回來仍然是 falsy ——和「沒算過」完全無法區分,於是被無限重算。

觸發條件:值為 0 的節點。而題目寫的是 0 <= Node.val,全 0 的樹是合法輸入,不是刁鑽構造。

答案不會錯 —— 實測 10,728,178 組對拍(含 15 萬棵 {0,1} 值的隨機樹)不一致 0。這是純效能 bug,也正因如此才難發現。

嚴重程度取決於深度:

  • 全 0 單邊鏈 → Θ(φⁿ),n=40 要 3.27 秒,約 45 個節點就 TLE
  • 全 0 完美樹 → Θ(n^1.694),n=10⁴ 只要 35.3 ms,仍然會過(但白花約 50 倍時間)

⚡ 還有一個容易忽略的細節:memo[root] 在 miss 時會預設建構並插入一個 0(實測 size 0 → 讀一次 miss → size 1、值 0)。但 memo.size() 最後仍然剛好等於 n,記憶體不會爆 —— 少了一個明顯症狀,bug 更隱蔽。

修法一個字:if (memo.count(root)) return memo[root];。實測 1,065,947 組答案完全相同。

Q4 貪心「隔層搶」為什麼錯?

因為最佳解不必「整層同進退」。「父子互斥」是一個局部限制,它不蘊含「同一層要嘛全搶、要嘛全不搶」這種全域結構 —— 左子樹可以搶第 2 層,右子樹同時搶第 3 層,彼此互不干涉。

最小反例 [0,0,1,1]:貪心給 1,正解 2(實測程式輸出)。

失敗率 279,804 / 1,045,947 ≈ 26.8%。

⚡ 這個貪心在官方兩個範例上都會過([3,2,3,null,3,null,1] 給 7、[3,4,5,1,3,null,1] 給 9,我實測過)——這正是為什麼它很容易被當成正解交出去。只用範例測試抓不到它。

Q5 4n − 1 的 4 從哪來?

每個節點會被兩條不同的路徑問到:一次來自祖父的「搶」分支(當作孫子),一次來自父親的「不搶」分支(當作小孩)。第一次展開、第二次命中快取,兩次都算一次呼叫。

再加上打在 nullptr 上的呼叫 —— 每個節點的兩個孫子位置與兩個小孩位置都可能是空的。加總後恰好是 4n − 1。

實測(值非 0):

n=16 → 63、n=64 → 255、n=256 → 1023、n=1024 → 4095 —— 鏈與完美樹完全相同,與樹形無關。

對照範例那棵 n=5 的樹:4×5 − 1 = 19,而實測正是 19 次(5 次展開 + 2 次命中 + 12 次 nullptr)。

App 1 不用 hash map 的 O(n) 版本

讓遞迴一次回傳兩個值:{搶這個節點的最佳值, 不搶這個節點的最佳值}。

pair<int, int> dfs(TreeNode* root) {
    if (root == nullptr) return {0, 0};
    auto L = dfs(root->left);
    auto R = dfs(root->right);
    int rob  = root->val + L.second + R.second;   // 搶我 ⇒ 小孩都不搶
    int skip = max(L.first, L.second)             // 不搶我 ⇒ 小孩各自自由
             + max(R.first, R.second);
    return {rob, skip};
}
int rob(TreeNode* root) {
    auto p = dfs(root);
    return max(p.first, p.second);
}

為什麼沒有那個 bug:它根本不需要快取。每個節點只被走訪一次,因為「小孩的兩種狀態」都被一次帶上來了,不必再回頭問孫子。沒有重複計算 ⇒ 沒有 memo ⇒ 沒有「0 讀起來像 miss」的問題。

這正是本頁用來對拍的參考解,1072 萬組與主解完全一致。它也更省:O(h) 空間而不是 O(h) + O(n)。

⚡ 面試時值得講的一句:「需要 memo」往往代表狀態定義得不夠好 —— 把狀態從「一個值」擴成「一對值」,重複計算就消失了。

App 2 值可以是負數的話?

兩個地方會壞。

① 那個 memo 測試會更常失效。現在不只「答案為 0」會被當成 miss —— 負的答案雖然是 truthy(非 0),但只要某個子樹的最佳值恰好算成 0,一樣重算。而值域含負數時,答案為 0 的子樹會變多(正負相抵),bug 觸發得更頻繁。

② 邏輯本身也要改。現行的 max(搶, 不搶) 隱含「不搶的下界是 0」,但當所有值都是負的,最佳策略是一個都不搶。上面 App 1 的 pair 版其實已經正確處理了(skip 用 max(L.first, L.second),會自然選到「不搶」);而本頁這份「跳孫子」寫法也仍然正確,因為它的第二分支 rob(left)+rob(right) 在全負時會一路回傳 0。

真正需要動的是型別與溢位邊界:目前 int 之所以安全,是因為實測最大值只有 66,650,000(INT_MAX 的 3.10%)。值域放大時要重新量,不能沿用這個結論。

⚡ 保險的寫法:改用 memo.count 並把 pair 版當主解 —— 兩個問題一起消失。

App 3 回傳「搶了哪些節點」

標準做法是先算值,再回溯選擇,分兩趟:

第一趟:用 App 1 的 pair 版,把每個節點的 {rob, skip} 存進一個 unordered_map<TreeNode*, pair<int,int>>。

第二趟:從 root 帶一個「這個節點可不可以被搶」的旗標往下走:

void pick(TreeNode* root, bool allowed, vector<TreeNode*>& out) {
    if (root == nullptr) return;
    auto [rob, skip] = memo[root];
    if (allowed && rob >= skip) {      // 決定搶它
        out.push_back(root);
        pick(root->left,  false, out);  // 小孩就不能搶了
        pick(root->right, false, out);
    } else {                            // 決定不搶
        pick(root->left,  true, out);
        pick(root->right, true, out);
    }
}

⚡ 關鍵是第二趟的 allowed:「能不能搶」是父親的決定往下傳的,而「值是多少」是子樹往上回的 —— 兩個方向在同一題裡同時出現。

注意平手 rob == skip 時兩種選法都是最佳解,輸出不唯一;上面用 >= 固定偏好「搶」,只是為了讓結果可重現。

這裡的 memo 一定要用 count 或直接查 find —— 存的是 pair,而 {0,0} 在這個題型裡很常見(全 0 子樹),踩到的就是本題那個 bug 的同一個坑。

// ONE-LINE TAKEAWAY
搶(val + 四個孫子)vs 不搶(兩個小孩)取 max,記憶化把 Θ(φⁿ) 壓成 4n−1。但 if (memo[root]) 測的是值不是存在性 —— 答案為 0 的節點永遠 cache-miss,而 0 是合法值,全 0 深鏈約 45 個節點就 TLE。更好的解法是回傳 {搶, 不搶} 一對值:每個節點只走一次,連 memo 都不需要。
