題目簡介// THE QUESTION

QUESTION

二元樹的每個節點是一間房子,裡面有錢 val。 不能搶「直接相連」的兩間(父與子不能同時搶)。 回傳能搶到的最大總額。
節點數 1 ~ 10⁴,值 0 ~ 10⁴。 注意值可以是 0 —— 這件事等一下會變成整題的重點。

限制只管「父子」,不管「祖孫」。 所以搶了 root 之後,下一層整個跳過,但孫子那層可以全搶 —— 這就是為什麼遞迴會跳兩層去找孫子。
2

為什麼用「每個節點兩種選擇」// KNOCKOUT

× REJECT · WRONG
貪心:隔層搶

把偶數層加總、奇數層加總,取大的那個。「父子不能同時搶」聽起來就像「隔層拿」。

但最佳解不必整層一起動。實測失敗 279,804 / 1,045,947(26.8%), 最小反例 [0,0,1,1] → 給 1,正解 2。

△ REJECT · TLE
純遞迴,不記憶化

「搶 root + 四個孫子」對比「不搶 root + 兩個子」,直接遞迴下去。答案是對的。

但每個孫子會被算兩次(從 root 一次、從 child 一次),退化成費氏遞迴。 實測單邊鏈 n=30 要 7,049,153 次呼叫,n=40 要 8.67 億次、3.27 秒。

BOTH FAIL · ADOPT
● ADOPT · O(n)
遞迴 + 記憶化(每個節點只算一次)

同樣是「搶 / 不搶」兩條路,但把每個節點的答案存起來。 重複的孫子查表即可,呼叫次數從指數壓回線性。

實測(值非 0 時)呼叫次數恰好 4n − 1,與樹形無關。

⚠ 但這份程式的記憶化有一個真實的漏洞 —— 它在「答案是 0」的節點上完全失效, 而題目允許 val = 0。詳見第 5 節,那是這題最值得學的地方。
3

核心策略 · 三步驟// STRATEGY

  1. 搶這間:val + 四個孫子的答案(ll + lr + rl + rr)。 兩個小孩必須跳過,但孫子不受限。
  2. 不搶這間:rob(left) + rob(right)。 小孩搶不搶由它們自己決定。
  3. 取兩者的 max,存進 memo,回傳。
rob(X) = max( X.val + 四個孫子 , 兩個小孩 )
4

動畫演示// VISUALIZER

盯著 memo 那一列:D 和 E 各被走訪兩次 —— 第一次算完存起來,第二次直接命中回傳。 這兩次命中,就是把指數壓成線性的全部原因。

這份 memo 的漏洞// THE REAL BUG

// LEMMA: 測「值」不等於測「有沒有存過」

if (memo[root]) return memo[root]; 測的是值是不是非 0, 不是這個 key 存不存在。

於是一個真實答案就是 0 的節點,會把 0 存進 memo —— 而 0 讀回來是 falsy,和「沒存過」完全無法區分。 那個節點就會被無限重算。

題目寫的是 0 <= Node.val,全 0 的樹是合法輸入。

成長率實測是每多一個節點 ×1.618 —— 黃金比例 φ, 也就是沒有記憶化的費氏遞迴。 記憶化不是「變慢」,是整個失效。 一條 45 個節點的全 0 鏈就會 TLE,而 n 上限是 10⁴。
// 但「鏈」和「完全樹」的嚴重程度不同 —— 實測 全 0 單邊鏈 Θ(φⁿ) ≈ 1.618ⁿ n=40 → 3.27 秒 n=10⁴ 永遠跑不完 全 0 完美樹 Θ(n^1.694) n=10⁴ → 35.3 毫秒 仍然會過 完美樹的實測(每深一層 ×3.236,但 n 只翻倍 ⇒ 指數 log₂3.236 = 1.694): n = 1023 → 131,891 次呼叫 n = 4095 → 1,381,171 n = 16383 → 14,463,795 ⚡ 同一個 bug,嚴重程度由「深度」決定: 0 讓快取失效,而「深度」把失效放大成 φⁿ。 完美樹只有 log n 深,所以放大有限(約 50 倍),還能過。 // 所以不要以為「只有鏈會爆」—— 每種形狀都中招,只是鏈才致命
修法是一個字:if (memo.count(root))
實測 1,065,947 組,答案完全相同 —— 純粹是效能修正

一句洞察// INSIGHT

「搶或不搶」是每個節點各自的決定,所以狀態往上回傳,不往下傳 —— 這和 1448(約束往下傳)、 98(區間往下傳)方向相反。 而真正的教訓是:測 truthiness 的快取不是快取。 只要合法值裡包含 0,if (memo[x]) 就會在答案為 0 的地方靜靜失效 —— 答案仍然全對,只是慢到無法提交。
