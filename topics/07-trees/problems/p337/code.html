完整實作// MEMOIZED TREE DP

p337.cpp C++17 
class Solution {
private:
    unordered_map<TreeNode*, int> memo;

public:
    int rob(TreeNode* root) {
        if (root == nullptr) return 0;
        if (memo[root]) return memo[root];   // ⚠ 測「值」不是「存在」

        int ll = 0, lr = 0, rl = 0, rr = 0;
        if (root->left) {
            ll = rob(root->left->left);       // 孫子
            lr = rob(root->left->right);
        }
        if (root->right) {
            rl = rob(root->right->left);
            rr = rob(root->right->right);
        }

        return memo[root] = max(root->val + ll + lr + rl + rr,   // 搶這間
                               rob(root->left) + rob(root->right)); // 不搶
    }
};

邊界與陷阱// PITFALLS

陷阱症狀實測
if (memo[root]) 測值不測存在 答案對,但退化成無記憶化 全 0 鏈 n=40 → 8.67 億次、3.27 秒
root->val 加到兩個分支 答案偏大 失敗 948,656/1,045,947,最小 [1,1]
memo 用 root->val 當 key 重複值互相污染 失敗 412,928,最小 [0,0,0,1]
貪心「隔層搶」 最佳解不必整層一起動 失敗 279,804,最小 [0,0,1,1] → 1(正解 2)
第一分支漏掉一個孫子(如 rr) 少算一整棵子樹 失敗 343,430,最小 [1,null,0,null,1]
「不搶」誤算成「只取四個孫子」 等於「一定搶 root」 失敗 570,800,最小 [0,1]
// 第一列不是理論風險,是可提交的 TLE

memo[root] 讀到 0 時,無法分辨「算過,答案就是 0」和「還沒算過」。 題目寫 0 <= Node.val,全 0 的樹完全合法。

實測單邊鏈成長率是每多一個節點 ×1.618(黃金比例 φ)—— 這正是沒有記憶化的費氏遞迴。 約 45 個節點就會 TLE,而 n 上限是 10⁴。

修法是一個字:if (memo.count(root)) return memo[root];
實測 1,065,947 組答案完全相同 —— 純效能修正,不動邏輯。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼是「孫子」而不是「曾孫」 限制只說「不能搶直接相連的兩間」= 父與子不能同時搶。 搶了 root ⇒ 兩個「子」不能搶 ⇒ 但「孫」和 root 不相連,不受限,可以隨意搶 ⇒ 所以 rob(root) 的第一分支要跳兩層: root->val + rob(四個孫子) 不搶 root ⇒ 兩個子完全自由,各自決定 ⇒ 第二分支就是 rob(left) + rob(right) ⚠ 常見誤解:以為要「隔層搶」,於是寫成偶數層總和 vs 奇數層總和。 實測失敗 279804/1045947,最小反例 [0,0,1,1] → 給 1,正解 2。 最佳解「不必整層一起動」—— 它可以在左子樹搶第 2 層、右子樹搶第 3 層。 // 「父子互斥」是局部限制,不會蘊含「整層同進退」這種全域結構
// PHASE 2: 重複計算從哪來(為什麼非記憶化不可) 看第二分支 rob(root->left): 它進去之後,又會算 rob(root->left->left) 和 rob(root->left->right) 但第一分支已經算過這兩個了(它們就是 ll 和 lr)! rob(A) 需要 → rob(A 的四個孫) [第一分支] → rob(B), rob(C) [第二分支] 而 rob(B) 又需要 → rob(B 的兩個子) = A 的兩個孫 ⇒ 每個節點被「兩條路」同時需要 ⇒ 不記憶化就是 T(n) = T(n-1) + T(n-2) ⇒ 費氏遞迴,Θ(φⁿ) 實測(單邊鏈,完全拿掉 memo): n=20 → 57,311 n=25 → 635,619 n=30 → 7,049,153 n=40 → 866,988,871(3.27 秒) 每多 5 個節點約 ×11.09,即每個節點 ×1.618 // 記憶化把「兩條路各算一次」變成「第二條路查表」,φⁿ 降成 4n-1
// PHASE 3: if (memo[root]) 為什麼是 bug(逐步拆解) unordered_map 的 operator[] 有兩個副作用,這行同時踩到: ① 讀 miss 時「預設建構並插入」一個 0 實測:size=0 → 讀 m[a](miss)→ size=1, value=0 (所以它不只是讀,它在寫) ② if (值) 測的是 truthiness,而 0 是 falsy ⇒ 一個真實答案就是 0 的節點,存了 0 也等於沒存 合起來的後果: 答案為 0 的節點 → 每次被問到都重新展開整棵子樹 → 記憶化完全失效 ⚡ 但注意 memo.size() 最後仍然剛好 = n(實測 n=10^4 → 10000 筆) 因為 ① 插入的 key 就是稍後真的要寫的那個 key,不會多出幽靈項 ⇒ 「記憶體沒爆」這件事反而讓這個 bug 更難被發現 修法:if (memo.count(root)) —— 測 key 存不存在,和值是多少無關 // 同一個陷阱在任何「合法答案可能是 0 / false / 空字串」的 memo 都會出現
// PHASE 4: 嚴重程度由「深度」決定,不是由「有幾個 0」決定 全 0 的兩種形狀,同樣都讓 memo 失效,但後果差很多: 單邊鏈(深度 n) Θ(φⁿ) n=40 → 3.27 秒 n=10^4 跑不完 完美樹(深度 log n) Θ(n^1.694) n=10^4 → 35.3 ms 仍然會過 完美樹實測(每深一層呼叫數 ×3.236,而 n 只翻倍): n = 1023 → 131,891 n = 4095 → 1,381,171 n = 16383 → 14,463,795 指數 = log2(3.236) = 1.694 同形狀、同大小,只差值是 0 還是 1: 鏈 n=30, val=0 → 7,049,153 次 鏈 n=30, val=1 → 119 次 差 59,237 倍 ⇒ 0 讓快取失效;「深度」才把失效放大成指數。 ⇒ 所以「完美樹也會中招,只是還撐得住」比「只有鏈會爆」更準確。 // 提交會掛的是深鏈;但即使是完美樹,也白白多花了約 50 倍的時間
