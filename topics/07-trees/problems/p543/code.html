完整實作// ONE PASS

p543.cpp C++17 
class Solution {
public:
    int longestPath = 0;

    int diameterOfBinaryTree(TreeNode* root) {
        if (root == nullptr) return 0;

        path(root);
        return longestPath;
    }

    int path(TreeNode* root) {
        if (root == nullptr) return 0;

        int left = path(root->left), right = path(root->right);
        longestPath = max(longestPath, left + right);   // 穿過我:左右都要

        return 1 + max(left, right);                    // 往上延伸:只能挑一邊
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

最後兩行的對比就是整題的核心: left + right(穿過我 —— 左右各走一段) 對上 1 + max(left, right)(往上延伸 —— 只能挑一邊)。 把第 ② 行的 + 誤寫成 max,實測錯 280/626; 把第 ③ 行的 max 誤寫成 +,錯 369/626。
2

⚠ 成員變數沒有重置// STALE MEMBER

longestPath 是成員變數,只在建構時被初始化為 0。 如果同一個 Solution 物件被呼叫兩次, 第二次會沿用第一次留下的最大值 —— 而 max 只會讓它單調變大。

// 實測:同一個 Solution 物件連續呼叫兩次 Solution s; s.diameterOfBinaryTree([1,2,3,4,5]); → 3 ✓ 正確 s.diameterOfBinaryTree([1,2]); → 3 ✗ 正解是 1 另一組: s.diameterOfBinaryTree(大樹); → 4 ✓ s.diameterOfBinaryTree([1]); → 4 ✗ 正解是 0 最小反例對:T1 = [1,null,2]、T2 = [1] 第二次回傳 1,正解 0 原因:longestPath 從不重置,第二次的答案 = max(兩棵樹的直徑),永遠 ≥ 正解 // LeetCode 每個 test case 都會 new 一個新的 Solution,所以在平台上「隱形」
這個 bug 在 LeetCode 上不會被抓到,但在你自己寫的多測資 main()、 或面試官現場連跑兩棵樹時會當場現形。 修法很簡單:在 diameterOfBinaryTree 開頭加一行 longestPath = 0;, 或者改用區域變數 + 傳參考(見下方走讀 PHASE 3)。 主動說出這件事,是面試裡少見的加分點 —— 因為它顯示你在想「這段程式碼被怎麼用」。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼一行用 +、另一行用 max longestPath = max(longestPath, left + right); // ①「穿過我」 return 1 + max(left, right); // ②「從我往上」 ① 穿過我的路徑:可以「從左邊最深處,經過我,再到右邊最深處」 → 左右「兩段都要」 → 用 + ② 從我往上延伸的路徑:父節點只能接到「我底下的一條路」 → 如果左右都要,路徑就會在我這裡「分岔兩次」,那不是一條路徑 → 只能挑比較長的那一邊 → 用 max 實測把兩者互換的後果: ① 誤用 max → 錯 280/626(它變成在算樹高) ② 誤用 + → 錯 369/626(回傳值變成子樹節點數) // 「路徑不能在同一個節點分岔兩次」是這兩行差異的唯一理由
// PHASE 2: 為什麼「在每個節點試一次」不會漏也不會重複 關鍵觀察:任何一條路徑都有唯一的「最高點」 = 路徑上「離根最近」的那個節點 不會漏:每條路徑的最高點是某個節點,而我們「每個節點都試了一次」 在最高點 v 上,那條路徑恰好被算成 left + right(v 的左右各一段) 不會重:每條路徑只有「一個」最高點,所以只會在那一個節點被算到 因此「對所有節點取 max」= 「對所有路徑取 max」= 直徑 實測佐證:窮舉 n=0..7 共 626 種樹形,與 O(n^2) 暴力解逐棵比對,不一致 0 隨機 20 萬組亦零不一致 // 這個「每條路徑都有唯一最高點」的論證,也是 124 最大路徑和的正確性基礎
// PHASE 3: 不用成員變數的兩種寫法(避開 stale member 問題) 寫法 A —— 開頭重置(最小改動): int diameterOfBinaryTree(TreeNode* root) { longestPath = 0; // ← 加這一行就好 path(root); return longestPath; } 寫法 B —— 傳參考,完全不用成員變數(更乾淨): int diameterOfBinaryTree(TreeNode* root) { int best = 0; path(root, best); return best; } int path(TreeNode* root, int& best) { if (root == nullptr) return 0; int left = path(root->left, best), right = path(root->right, best); best = max(best, left + right); return 1 + max(left, right); } 實測:寫法 B 對「同一物件連呼兩次」完全免疫 —— 每次都用自己的 best // 寫法 B 和 94 那題「ans 傳參考」是同一個手法:把狀態放在呼叫端,不放在物件上
// PHASE 4: 外層那個 nullptr 檢查其實是冗餘的(但別亂拿掉內層的) int diameterOfBinaryTree(TreeNode* root) { if (root == nullptr) return 0; // ← 這一行冗餘 path(root); return longestPath; } 為什麼冗餘:path(nullptr) 本來就回 0,而 longestPath 初值也是 0 → 空樹的話什麼都不會發生,直接回 0 實測:只拿掉「外層」guard,窮舉 n=0..8 共 2056 棵樹比對,差異 0 ✓ 但「內層」path() 裡的 nullptr 檢查絕對不能拿掉: 實測拿掉 → 最小觸發輸入 [1] 就 SIGSEGV 有趣的是 [] 反而僥倖回 0 —— 因為外層 guard 先擋掉,path() 根本沒被呼叫 // 兩個 guard 一個冗餘、一個必要 —— 值得知道差別,但保留兩個也無妨

// ONE-LINE TAKEAWAY
「穿過我」用 + (左右都要)、「往上延伸」用 max(只能挑一邊),因為路徑不能在同一個節點分岔兩次。每條路徑都有唯一的最高點,所以在每個節點各試一次就不漏也不重。longestPath 是成員變數且從不重置 —— LeetCode 上隱形,但同一物件連呼兩次就會錯。
