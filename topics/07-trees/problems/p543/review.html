範例 Trace// [1,2,3,4,5] → 3

官方範例:根 1;1.left=2, 1.right=3;2.left=4, 2.right=5。 longestPath 起始 0。以下每一步都是實跑印出來的。

// 兩個葉節點:候選都是 0,不更新 1. ENTER path(node 1) 2. ENTER path(node 2) 3. ENTER path(node 4) 4. path(4.left) → nullptr, return 0 5. path(4.right) → nullptr, return 0 6. 節點 4: left=0 right=0 候選 = 0+0 = 0 longestPath 0 → 0(不變) return 1 + max(0,0) = 1 7. ENTER path(node 5) 8. path(5.left) / path(5.right) → return 0, 0 10. 節點 5: left=0 right=0 候選 = 0 longestPath 0 → 0(不變) return 1 // 葉節點的候選恆為 0 —— 「穿過一個葉節點」的路徑長度是 0 條邊
// 節點 2:第一次更新 11. 節點 2: left=1 right=1 候選 = 1+1 = 2 longestPath 0 → 2 ★ 更新 return 1 + max(1,1) = 2 這個 2 對應的路徑是 4 → 2 → 5,共 2 條邊 注意:它「穿過節點 2」,完全沒有碰到根節點 // 如果這棵樹的右子樹再深一點,這條路徑就會是最終答案 —— 而「只看根」會漏掉它
// 節點 3 與根:第二次更新 12. ENTER path(node 3) 13. path(3.left) / path(3.right) → return 0, 0 15. 節點 3: left=0 right=0 候選 = 0 longestPath 2 → 2(不變) return 1 16. 節點 1(根): left=2 right=1 候選 = 2+1 = 3 longestPath 2 → 3 ★ 更新 return 1 + max(2,1) = 3 這個 3 對應的路徑是 4 → 2 → 1 → 3,共 3 條邊 // 這一題根「剛好」贏了 —— 但那是這棵樹的性質,不是一般規律
// OUTPUT return longestPath = 3 統計:11 次 path() 呼叫(5 實節點 + 6 個 nullptr = 2n+1 = 2×5+1 ✓) 5 次「試算候選」(每個實節點一次) 2 次「真的更新」(節點 2 的 0→2、根的 2→3) 最大遞迴深度 3 // 5 次試算裡只有 2 次真的改變了答案 —— 但你必須「五次都試」才知道是哪兩次
這棵範例樹其實「不夠壞」 —— 它的直徑剛好通過根, 所以連「只看根」的錯誤寫法都會給出正確答案 3。 要真正測出這題的核心陷阱,你需要 程式碼頁裡那棵手工構造的樹: 一邊很淺、另一邊掛著一個內部的深分岔。

應用題// APPLICATION

App 1. 改成回傳直徑那條路徑本身(節點序列),而不只是長度。要怎麼做?
App 2. 用這題的骨架寫 LeetCode 124 二元樹最大路徑和(Hard)。要改哪裡?新增的唯一難題是什麼?
App 3. 如果樹的節點可以有任意多個小孩(N 元樹),直徑要怎麼算?left + right 要換成什麼?
// ANSWERS
A1. 因為最長路徑可能整條落在某棵子樹裡,完全不碰根 —— 而這種形狀最少需要 6 個節點。

實測:窮舉 n = 0..7 全部 626 種樹形,統計「直徑 > 根的左高+右高」:
· n = 0,1,2,3,4,5 → 各 0 種(全部 65 種樹形都通過根!)
· n = 6 → 8 / 132　　· n = 7 → 40 / 429
合計 48 / 626 = 7.67%。

「n ≤ 5 全部碰巧正確」就是這個 bug 難發現的原因。你在紙上畫的例子幾乎都是 3~5 個節點,那個範圍裡「只看根」永遠是對的。要露餡,你必須刻意造出「一邊很淺、另一邊掛著一條深的斜鏈」的不對稱形狀。

最小反例 [1,null,2,3,4,null,5,null,6]:「只看根」給 3,正解 4。

教訓有兩層:① 題目敘述裡「不一定要通過根節點」那句話是明示的提示,讀題時不能滑過去;② 「我手算了幾個例子都對」不是正確性的證據 —— 本頁所有陷阱表都是窮舉 626 種樹形跑出來的,正是因為手算會系統性地漏掉這一族。
A2. 因為「穿過我」和「從我往上」是兩件不同的事 —— 路徑不能在同一個節點分岔兩次。

更新用 left + right:「穿過我的最長路徑」可以從左子樹的最深處走上來、經過我、再走到右子樹的最深處。左右兩段都算數,所以是相加。

回傳用 1 + max(left, right):父節點接到的必須是一條路。如果我回報 left + right,父節點再往上接,那條「路徑」就會在我這裡分岔成兩支 —— 那不是一條路徑,是一棵子樹。所以往上回報時只能挑比較長的那一邊。

實測互換的後果:
· 更新誤用 max → 錯 280/626。它算的其實是樹高(邊數) —— 實測 626/626 與 height − 1 完全相符。
· 回傳誤用 + → 錯 369/626。回傳值變成子樹的節點數。

記法:「+ 是給答案用的,max 是給父親用的」。這個雙軌結構(一個值往上傳、另一個值進全域最大)在 124 最大路徑和裡一字不改地重現。
A3. 因為每條路徑都有唯一的「最高點」。

定義:一條路徑的「最高點」= 路徑上離根最近的那個節點。任何一條路徑都恰好有一個(路徑是連通的,不可能有兩個都最高)。

不會漏:設某條路徑的最高點是節點 v。那條路徑從 v 往左下走一段、往右下走一段(或只走一邊)。而我們在 v 上恰好算了 left + right —— 也就是「從 v 往左最遠 + 往右最遠」,它 ≥ 那條路徑的長度。既然我們對每個節點都算了,每條路徑的最高點都輪到過。

不會重:每條路徑只有一個最高點,所以它只會在那一個節點被算到一次。(就算重複算也不影響,因為取的是 max —— 但不重複讓論證更乾淨。)

所以:max 遍歷所有節點 = max 遍歷所有路徑 = 直徑。

實測佐證:窮舉 626 種樹形與 O(n²) 暴力解(對每個節點各算一次左右高度)逐棵比對,不一致 0;隨機 20 萬組亦零不一致。

這個論證是可以直接搬到 124 的 —— 那題只是把「路徑長度」換成「路徑上的值總和」,「每條路徑有唯一最高點」這件事完全不變。
A4. 不會錯 —— 而且 n = 1 正是最好的驗證。

path() 回傳「節點數高度」(葉節點回 1、空樹回 0)。但 left + right 出來的本來就是邊數,理由是:

left 是「左子樹裡最長的節點數」。從我走到左子樹最深處,要經過:我 → 左小孩(1 條邊),左小孩再往下(left − 1 條邊)—— 合計正好 left 條邊。那個「節點數 → 邊數」的 −1,剛好被「我到左小孩」的 +1 抵消掉了。右邊同理。

n = 1 的驗證:單節點樹,left = right = 0,候選 = 0 + 0 = 0。正確 —— 一個節點的樹沒有任何邊,直徑是 0。(如果單位搞錯了,這裡就會回 1 或 2。)

實測:窮舉 n = 1..8 全部 2055 棵樹,回傳值 == (最長路徑的節點數) − 1 命中 2055/2055。

但這件事值得在面試時主動說一句,因為它看起來很像 bug。實測「刻意把單位統一」的寫法(更新改成 1 + left + right)反而錯 625/626,而且是恆定 +1 —— 它算的是節點數,不是題目要的邊數。
A5. longestPath 是成員變數,而且從不重置 —— 同一個 Solution 物件呼叫第二次就會錯。

它只在建構時初始化為 0,而 max 只會讓它單調變大。所以第二次呼叫的答案 = max(兩棵樹的直徑),永遠 ≥ 正解。

實測:
Solution s;
s.diameterOfBinaryTree([1,2,3,4,5]); → 3 ✓
s.diameterOfBinaryTree([1,2]); → 3 ✗(正解 1)
最小反例對是 T1 = [1,null,2]、T2 = [1],第二次回 1 而正解是 0。

為什麼 LeetCode 抓不到:它每個 test case 都會 new 一個全新的 Solution,所以這個 bug 在平台上完全隱形。但只要你自己寫一個跑多筆測資的 main()、或面試官現場說「那再跑這棵樹看看」,它就會當場現形。

兩種修法:
① 最小改動 —— 在 diameterOfBinaryTree 開頭加 longestPath = 0;。
② 更乾淨 —— 不用成員變數,改成區域變數 + 傳參考:int best = 0; path(root, best); return best;,helper 簽名加一個 int& best。

寫法 ② 和 94 那題「ans 傳參考」是同一個手法:把狀態放在呼叫端,而不是掛在物件上 —— 這樣函式就沒有跨呼叫的殘留狀態,天生可重入。面試時主動指出這一點,是很少見的加分項,因為它顯示你在想「這段程式碼會被怎麼用」,而不只是「它能不能過測資」。
App 1. 多記「在哪個節點取到最大值」,以及每個節點「往下最深的那條路」。

作法分兩步:
① 記錄最佳節點:更新全域最大時,順便把當時的節點存下來 ——
if (left + right > longestPath) { longestPath = left + right; bestNode = root; }
注意這裡要用 > 而不是 max,因為我們需要知道「是哪一次更新贏的」。

② 從最佳節點往兩邊各走一次「最深路徑」:寫一個輔助函式,從 bestNode 出發,每一步挑高度較大的那個小孩走到底,分別得到左半段和右半段;把左半段反轉,接上 bestNode,再接右半段,就是完整路徑。

要注意的細節:第 ② 步需要知道每個節點的高度才能「挑比較深的那邊」。最省事的做法是在第一趟遞迴時就把高度存進一個 unordered_map<TreeNode*, int>,第二步直接查。這樣總複雜度仍是 O(n) 時間、O(n) 空間(多了那張表)。

一般原則:「求最佳值」和「求達成最佳值的方案」的差別,就是在更新最大值時順便記下決策。這在 DP 題裡是完全一樣的手法(記 parent / choice 陣列再回溯)。
App 2. 骨架一字不改,唯一的新難題是「負數要不要」。

int best = INT_MIN;                 // ← 不能初始化成 0!

int gain(TreeNode* root) {
    if (root == nullptr) return 0;

    int left  = max(gain(root->left),  0);   // ← 唯一的新東西
    int right = max(gain(root->right), 0);

    best = max(best, root->val + left + right);   // 穿過我:左右都要

    return root->val + max(left, right);          // 往上:只能挑一邊
}
對照 543,結構完全相同:中間一行更新全域最大(用 +),最後一行回報給父節點(用 max)。

新增的唯一難題:子樹的貢獻可能是負的。543 裡「多走一段路」永遠讓路徑更長,所以左右都拿;但 124 裡如果某邊的最大貢獻是負數,那就寧可不要 —— 直接在這裡截斷。這就是 max(gain(...), 0) 那個 0 的意思:「這一邊我可以選擇不走」。

兩個容易錯的地方:
① best 不能初始化成 0。如果所有節點都是負數(例如 [-3]),答案應該是 -3,初始化成 0 會回 0。要用 INT_MIN,或直接用 root->val。
② 截斷只用在「子樹的貢獻」上,不能用在「自己」上 —— 路徑至少要包含一個節點,所以 root->val 一定要算進去,不管它是不是負的。

把 543 學透之後,124 真的只剩這一個新觀念 —— 這也是為什麼 543 標 Easy 而 124 標 Hard,但兩題的骨架完全相同。
App 3. left + right 換成「所有小孩的高度裡最大的兩個相加」。

推廣的邏輯完全一樣:穿過節點 v 的最長路徑,是「從某個小孩的子樹最深處上來,經過 v,再下去另一個小孩的子樹最深處」。二元樹只有兩個小孩,所以就是 left + right;N 元樹要從所有小孩裡挑最深的兩個。

int path(Node* root) {
    if (root == nullptr) return 0;

    int best1 = 0, best2 = 0;              // 最大與次大的小孩高度
    for (Node* child : root->children) {
        int h = path(child);
        if (h > best1) {
            best2 = best1;
            best1 = h;
        } else if (h > best2) {
            best2 = h;
        }
    }

    longestPath = max(longestPath, best1 + best2);   // 穿過我:最深的兩條
    return 1 + best1;                                // 往上:只能挑最深那一條
}
注意 best1 和 best2 都初始化成 0 —— 這樣小孩少於兩個的情況會自動處理:只有一個小孩時 best2 = 0,候選就是 best1 + 0;葉節點兩個都是 0,候選 0。又是「用一個中性值取代特判」的手法,和二元樹版裡 nullptr 回傳 0 是同一招。

複雜度不變:每個節點的小孩只被掃一次,總共掃過所有邊 → 仍是 O(n) 時間、O(h) 空間。

這正是圖論裡「樹的直徑」的標準解法(另一個經典解法是「隨便找一點做 BFS 找最遠點 u,再從 u 做 BFS 找最遠點 v,dist(u,v) 就是直徑」—— 兩趟 BFS,不需要遞迴)。
