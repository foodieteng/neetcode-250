題目簡介// THE QUESTION

QUESTION

給兩棵二元樹 root 和 subRoot,判斷 subRoot 是不是 root 的子樹 —— 也就是 root 裡存在某個節點, 從它往下的整棵子樹和 subRoot 完全相同。 root 節點數 1 ~ 2000,subRoot 1 ~ 1000。

這題是 100 相同的樹的直接應用 —— 你的 isSame 和 100 那題一字不差。 新增的只有外面那一層:在 root 的每個位置都試一次。

兩層遞迴,各司其職: 外層 isSubtree 負責「找位置」, 內層 isSame 負責「在這個位置比到底」。 而且兩層用的是相反極性的短路 —— 外層 ||「找到一個就停」,內層 &&「差一個就停」。

B subRoot 走完就算成功 錯 1700/18556
這才是真正陰險的那一個。它接受「只對到一半」—— root 那邊多出來的子節點被忽略。 18556 個配對裡只有 1700 個抓得到它。
× REJECT · 部分匹配
ADOPT
C 完整的 isSame:兩邊必須同時走完 O(n×m) 最壞
isSame 的 base case if (!p || !q) return p == q; 會在「一邊空了、另一邊還有」時回 false —— 所以「頂端對上」不算數,必須逐位對齊到底。
● ADOPT · 比到底
A 和 B 這兩個錯誤有一個共同的特徵:它們只會多報 true,從不漏報。 實測正解為 true 的 1252 個配對,兩者全部答對 —— 因為真的是子樹時,「只比根」和「走完就算」都自動成立。 這正是它們在小測資上看起來沒問題的原因。
3

核心策略 · 兩層// THE SHAPE

外層 isSubtree · 找位置

  1. 兩個 guard:if (!subRoot) return true; 然後 if (!root) return false; —— 順序決定「兩個都空」時的答案。
  2. 以「這裡」為起點試一次:isSame(root, subRoot)。
  3. 或者答案在子樹裡: || isSubtree(root->left, ...) || isSubtree(root->right, ...) —— || 一找到就停。

內層 isSame · 比到底(和 100 完全相同)

  1. if (!p || !q) return p == q; —— 一邊空了另一邊還有,就是 false。
  2. p->val == q->val && 左配左 && 右配右 —— && 差一個就停。
那個 base case 就是「必須比到底」的執行者。 當 subRoot 走到 nullptr 而 root 那邊還有節點時, p == q 是 false —— 整個匹配當場失敗。 把它改成「q 空了就回 true」,就變成上面的錯誤 B。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 「部分匹配」為什麼是最陰險的 bug

把 isSame 的 base case 改成 if (!q) return true; if (!p) return false; —— 意思是「subRoot 走完就算成功」。 這會接受「root 的某棵子樹開頭長得像 subRoot, 但底下還多掛了東西」的情形。

實測:18556 個配對只有 1700 個抓得到它(9%), 而且失敗全部是 false-positive —— 正解為 true 的 1252 個配對它全部答對。
最小反例 root=[1,2]、subRoot=[1]: subRoot 走完了,但 root 的節點 1 底下還掛著 2。
官方範例 2 就是為此設計的:root=[3,4,5,1,2,null,null,null,null,0] 比範例 1 多了一個節點 0 掛在 2 底下, 答案就從 true 變成 false。

LEMMA 2 · 為什麼 O(n×m) 在實務上悲觀得離譜

理論上要對 root 的 n 個位置各跑一次 O(m) 的比較, 看起來是 O(n×m)。 但絕大多數位置在「比第一個值」就出局了。

實測 20 萬組隨機配對: isSame 呼叫中有 61% 在第一次值比較就返回, 平均每次 isSubtree 只觸發 0.62 次 isSame。
具體例子:root 是 n=127 的完美樹、subRoot 是一片葉子 —— 短路版只花 isSubtree 7 次 / isSame 15 次, 而拿掉短路要 255 次 / 381 次(省 96~97%)。

一句洞察// INSIGHT

兩層遞迴、兩種相反極性的短路: 外層 || 是「找到一個就夠」,內層 && 是「差一個就毀」。
而這題真正的陷阱不在遞迴,在「子樹」的定義 —— 必須從那個節點往下整棵都相同,不是「開頭對得上」就好。 兩個「部分匹配」的錯誤寫法都只會多報 true、從不漏報, 所以在正例上完全看不出問題 —— 要用「差一點點就不是」的反例才抓得到。
