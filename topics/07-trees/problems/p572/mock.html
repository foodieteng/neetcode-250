Here's the plan.

// outer layer — find a POSITION
isSubtree(root, subRoot):
  if subRoot is null -> true
  if root is null -> false
  return isSame(root, subRoot)
    || isSubtree(root.left, subRoot)
    || isSubtree(root.right, subRoot)

// inner layer — check a WHOLE TREE
isSame(p, q):
  if p is null or q is null -> return p == q
  return (p.val == q.val)
    && isSame(p.left, q.left)
    && isSame(p.right, q.right)

One: in the outer layer, an empty subRoot is true and an empty root is false.
Two: otherwise, try isSame right here, or search the left subtree, or the right subtree.
Three: isSame returns p == q when either side is null, else compares values and both child pairs.

The outer layer joins with || and stops at the first place that works; the inner one joins with && and stops at the first difference.

One thing worth flagging — that null line has to be p == q, not if (!q) return true; when subRoot runs out. Otherwise a tree that only starts like subRoot, with extra nodes below, passes: root = [1,2,3,4] against subRoot = [1,2,3]. The right answer is false. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. The outer function guards the two empty cases, then tries isSame here, or recurses left, or right. The inner function is the plain same-tree check.

class Solution {
public:
    // outer layer: try every position in root (|| stops once found)
    bool isSubtree(TreeNode* root, TreeNode* subRoot) {
        if (!subRoot) {
            return true;
        }
        if (!root) {
            return false;
        }

        return isSame(root, subRoot)
            || isSubtree(root->left,  subRoot)
            || isSubtree(root->right, subRoot);
    }

    // inner layer: compare the whole tree (&& stops at one difference)
    bool isSame(TreeNode* p, TreeNode* q) {
        if (!p || !q) {
            return p == q;       // one side empty, the other not → false
        }

        return (p->val == q->val)
            && isSame(p->left,  q->left)
            && isSame(p->right, q->right);
    }
};

One thing worth flagging — the single line return p == q; is carrying two cases at once. If both are null, it is true, which is how a leaf pair agrees. If exactly one is null, it is false, which is how the shapes are forced to match. One comparison, both jobs.

Let's also test with corner cases.

• The partial match, [1,2,3,4] against [1,2,3]: isSame hits isSame(4, null), so false.
• The official second example, [3,4,5,1,2,null,null,null,null,0], adds a 0 under the 2, and returns false.
• Single nodes: [1] against [1] is true, [1] against [2] is false.
• And a tree is always a subtree of itself.

Let me think about complexity here.

The time complexity is O(n · m): the outer walk visits the n nodes of root, and each can run a check costing up to m, subRoot's size. The space complexity is O(hroot), since a check never goes deeper than root itself.

In the worst-case scenario, long chains of equal values, the bound is real. But in practice it is pessimistic: on random pairs, about 60% of isSame calls return at the very first value comparison.

Oh, one more thing — the linear alternative is to serialize both trees with null markers and run a substring search, O(n + m). It needs a delimiter before every value: otherwise the tree [1,2] serializes to 12###, which contains 12##, the string for a single node 12 — a false positive.
