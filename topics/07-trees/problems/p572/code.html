完整實作// TWO LAYERS

p572.cpp C++17 
class Solution {
public:
    // 外層:在 root 的每個位置試一次(|| 找到就停)
    bool isSubtree(TreeNode* root, TreeNode* subRoot) {
        if (!subRoot) {
            return true;
        }
        if (!root) {
            return false;
        }

        return isSame(root, subRoot)
            || isSubtree(root->left,  subRoot)
            || isSubtree(root->right, subRoot);
    }

    // 內層:整棵比到底(&& 差一個就停)—— 和 LC100 一字不差
    bool isSame(TreeNode* p, TreeNode* q) {
        if (!p || !q) {
            return p == q;       // 一邊空、一邊還有 → false
        }

        return (p->val == q->val)
            && isSame(p->left,  q->left)
            && isSame(p->right, q->right);
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

兩層的短路方向剛好相反: 外層 || 是樂觀的(「找到一個就夠了」), 內層 && 是悲觀的(「差一個就毀了」)。 而 isSame 的那一行 base case,就是「必須比到底」的執行者 —— subRoot 走完但 root 還有節點時,它回 false。

// PHASE 1: 「必須比到底」是哪一行在執行的 是 isSame 的 base case: if (!p || !q) return p == q; 當 sub 走到 nullptr、而 root 那邊「還有節點」時: p = 某個真節點(非 null)、q = nullptr → !p||!q 成立 → return p == q → 「非 null == null」→ false ✓ 正確拒絕 把它改成「sub 走完就算成功」: if (!q) return true; ← 錯的 if (!p) return false; → 同樣情形變成 return true,root 多出來的子節點被「無視」 最小反例 root=[1,2] sub=[1]: isSame(節點1, 節點1):值相同 ✓ isSame(節點2, null) ← root 有左子 2,sub 沒有 正確版 → false(整個匹配失敗)✓ 錯誤版 → true (直接放行) ✗ 官方範例 2 就是同一件事的放大版: [3,4,5,1,2,null,null,null,null,0] 比範例 1 多了一個節點 0 掛在 2 底下 → 答案從 true 變成 false // 題目自己用範例 2 在考這件事 —— 兩個範例只差一個節點
// PHASE 2: 兩層短路,方向相反(官方範例 1 的實測呼叫樹) isSubtree#1(root=3) isSame#1(3,4) = false ← 根值 3 != 4,&& 立刻死 ★ 短路 A:節點 3 底下的 1、2 完全沒被 isSame 走訪 所以這次比對「只花 1 次呼叫」,不是 3 次 isSubtree#2(root=4) isSame#2(4,4) 4 == 4 ✓ isSame#3(1,1) 1 == 1 ✓ isSame#4(null,null) guard → true isSame#5(null,null) guard → true isSame#6(2,2) 2 == 2 ✓ isSame#7(null,null) guard → true isSame#8(null,null) guard → true = true = true ★ 短路 B:isSubtree(root->left) 回 true ⇒ isSubtree(root->right) 「一次都沒有被呼叫」 ⇒ 節點 5 從頭到尾沒被搜尋過 總計:isSubtree 2 次、isSame 8 次 // 外層 || 樂觀(找到就停)、內層 && 悲觀(差一個就停)—— 同一個機制的兩種極性
// PHASE 3: 兩個 guard 的順序決定什麼 if (!subRoot) return true; ← guard1 if (!root) return false; ← guard2 四種組合的實測結果: root 非空、sub 非空 → 兩個都不開火,正常往下比 root 非空、sub 空 → guard1 開火 → true (root 根本沒被看) root 空、 sub 非空 → guard2 開火 → false root 空、 sub 空 → guard1 先開火 → true ← 順序在這一格才有差別 把兩個 guard 對調,實測 18556 個配對只有「2 個」分歧 —— 就是 root 與 sub 皆空的情形 (對調後回 false)。其餘 18554 對完全相同,因為 root 非空時誰先誰後都一樣。 LeetCode 572 的約束是 root >= 1、subRoot >= 1 個節點 → 這一格「在評測機上永遠不會發生」 // 面試時值得主動說:「空的 subRoot 我當成 true,但題目保證非空,所以不影響」
// PHASE 4: 少哪個 guard 會怎樣(兩者差很多) 少了 guard2(!root): subRoot 非空時,遞迴會走進 root 的 nullptr 子樹 → isSame(nullptr, subRoot) 沒問題(它自己有 guard) → 但接著 isSubtree(root->left, ...) 就在解參考 nullptr->left 實測:18556 對中 17752 對 SIGSEGV —— 不是答錯,是崩潰 少了 guard1(!subRoot): 「不會」崩潰,而是安靜地答錯 isSame(root, nullptr) 走 guard 回 p==q 也就是 false 一路遞迴到 root 用完,guard2 回 false → subRoot 為空時回 false(正解 true) 實測:錯 472 對,全部是 subRoot 為空的情形,0 個 false-positive // 一個崩潰、一個安靜答錯 —— 安靜答錯的那種通常更難發現
