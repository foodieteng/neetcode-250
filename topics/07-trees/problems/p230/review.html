重點回顧// KEY POINTS

重點內容
核心性質BST 的中序走訪由小到大 ⇒ 第 k 個被處理的節點就是答案
計數器rank = k,放 member(或 int&),所有遞迴層共用
判斷--rank == 0(前置遞減);後置 rank-- 全錯
位置計數夾在左、右兩個遞迴中間;放前面或後面就不是由小到大
提早結束入口 rank <= 0 擋住新呼叫,但擋不住已在路上的祖先
多餘處理處理數 = k + L,呼叫數 = 2(k+L)+1;左子樹回來再檢查一次就恰好是 k
複雜度時間 O(h + k),最壞 O(n);空間 O(h)
Follow-up每個節點記子樹大小,一路往下走,每次查詢 O(h)

// STEP 4: 回到 5 —— 多餘的一次處理 5 早就進入函式了,正停在 inorder(5->left) 這一行 回來後沒有任何檢查,直接執行: 處理 5:--rank → −1 −1 ≠ 0,ans 不變 inorder(5->right = 6):入口 rank = −1 → return // 這一次處理和 6 那一次呼叫都是白做的

// ANSWERS
Q1 為什麼中序由小到大?

BST 的定義:左子樹所有值 < 根 < 右子樹所有值。

中序的順序是「整個左子樹 → 根 → 整個右子樹」。用歸納法:假設左、右子樹的中序各自由小到大,那麼先輸出的左子樹全都比根小,根再輸出,最後輸出的右子樹全都比根大 ⇒ 整體也由小到大。

⚡ 所以「第 k 小」完全不需要比大小,只需要數數。這也是為什麼計數一定要夾在兩個遞迴中間:放在前面(前序)實測錯 3151/4081。

Q2 rank 為什麼要放 member?

rank 記的是「整趟走訪已經處理了幾個」,而大部分的處理發生在別的遞迴層(左子樹裡)。所有層必須改到同一個變數,左子樹處理的數量回來才看得到。

改成傳值:每層拿到複本,左子樹減的是自己的複本,回來後父層的 rank 沒變。實測失敗 3600/4081。

最小反例 [2,1], k=1:1 把它的複本減成 0、設 ans = 1;回到 2,2 的 rank 還是 1,減成 0,ans 被改成 2(正解 1)。

⚡ 不想用 member 的話,改成 int& rank 傳參考也可以,實測 0 失敗。

Q3 改成 rank-- 會怎樣?

rank-- 是先比再減,要 rank 進來時已經是 0 才成立 —— 那時已經處理過 k 個節點了,輪到的是第 k+1 個,或是找到答案後回頭的祖先。

而 rank 一旦是 0,新的呼叫會被入口擋掉,所以常常根本沒有人設定 ans。

實測 4081/4081 全錯:1429 組 ans 從沒被設定(回傳未初始化的值,例如 [1], k=1),其餘 2652 組設成了錯的值。

⚡ 記法:rank 代表「還剩幾個」,處理自己就是「剩的少一個」,先扣再看剩多少。

Q4 範例 2 處理了幾個節點?

4 個:1、2、3、5;呼叫 9 次。

找到 3 之後,4 那次呼叫被入口擋下。但 5 早在一開始就進入函式了,當時正停在 inorder(5->left)。等左子樹回來,它不再檢查 rank,直接執行 --rank(0 → −1),再呼叫一次右子樹 6(這次被擋下)。

一般化:第 k 個節點的祖先中,往左走下來的那些(設 L 個),回來後都會各做一次多餘的處理和一次多餘的呼叫。實測公式 處理 = k + L、呼叫 = 2(k+L)+1,230,000 組全部吻合。這裡 L = 1:4 = 3 + 1、9 = 2×4 + 1。

⚡ 答案不會錯:rank 變成負數後,== 0 不會再成立,ans 只被設定一次。

Q5 ans 沒初始化為什麼安全?

題目保證 1 ≤ k ≤ n,中序會走到第 k 個節點,--rank == 0 一定剛好成立一次,ans 一定被寫入。實測用哨兵值(預設 −777)檢查,從沒被原封不動地回傳過。

重複呼叫也安全:rank 每次在 kthSmallest 開頭重設;ans 雖然留著上一次的值,但這一次一定會被覆寫。實測同一個物件連續呼叫 215,521 次,0 不一致。

值是 0 也沒問題:程式用 rank 判斷「找到沒」,不是用 ans。實測平衡樹 k = 1 回傳真實的 0。

⚡ 對照 337:那題用 if (memo[x]) 判斷「存過沒」,值是 0 就出事。用什麼當「找到沒」的旗標,決定了 0 安不安全。

App 1 頻繁增刪 + 頻繁查詢

讓每個節點多存一個欄位:以它為根的子樹有幾個節點(size)。查詢時從根往下走,每一步只看左子樹的大小 ls:

int kthSmallest(TreeNode* root, int k) {
    while (root) {
        int ls = size(root->left);
        if (k <= ls) root = root->left;             // 在左子樹裡
        else if (k == ls + 1) return root->val;     // 就是我
        else { k -= ls + 1; root = root->right; }   // 扣掉左邊和自己,去右邊找
    }
    return -1;
}

每一步往下一層,查詢 O(h),和 k 無關。插入、刪除時沿路把經過節點的 size 加一或減一,成本也是 O(h)。

實測(先算好每個節點的 size 再查):隨機 100,000 組,不一致 0。

⚡ 要保證 O(log n),樹本身還要保持平衡(例如紅黑樹、AVL),這種結構叫 order-statistic tree。

App 2 迭代版
int kthSmallest(TreeNode* root, int k) {
    stack<TreeNode*> st;
    TreeNode* cur = root;
    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }   // 一路往左
        cur = st.top(); st.pop();
        if (--k == 0) return cur->val;                   // 第 k 個,直接結束
        cur = cur->right;
    }
    return -1;
}

stack 裡放的就是遞迴版「正停在 inorder(root->left) 的祖先們」。差別在於找到答案時直接 return 整個函式,stack 裡剩下的祖先就被丟掉了,不會再被處理。

遞迴版做不到這件事,是因為「結束」只能一層一層 return 回去,每一層都要自己決定要不要繼續 —— 所以才需要在左子樹回來後再檢查一次。

實測:n ≤ 7 全部 4,081 組 0 失敗,隨機 100,000 組 0 不一致。

App 3 第 k 大

只要改一個地方:把左右兩個遞迴對調(先右、再自己、再左),就是「由大到小」的反向中序,數到第 k 個就是第 k 大。

實測:反向中序版當作「第 k 大」隨機 100,000 組 0 不一致;反過來,如果拿它回答「第 k 小」,n ≤ 7 全部組合錯 3604/4081 —— 這就是陷阱表裡那一列。

⚡ 另一個做法是不改程式,改參數:第 k 大 = 第 n − k + 1 小。但那要先知道 n,得多走一次整棵樹。

// ONE-LINE TAKEAWAY
BST 中序 = 由小到大,第 k 個被處理的節點就是答案。rank 要共用、要前置遞減、要夾在左右遞迴中間。入口的提早結束擋得住新呼叫、擋不住半路上的祖先(範例 2 多處理了 5)。頻繁增刪時,每個節點記子樹大小,查詢降到 O(h)。
