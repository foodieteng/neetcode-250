完整實作// INORDER + COUNTER

p230.cpp C++17 
class Solution {
public:
    int ans, rank;                                   // 所有遞迴層共用

    int kthSmallest(TreeNode* root, int k) {
        rank = k;
        inorder(root);
        return ans;
    }

    void inorder(TreeNode* root) {
        if (!root || rank <= 0) return;             // 只在入口檢查

        inorder(root->left);
        if (--rank == 0) ans = root->val;         // 第 k 個被處理的節點
        inorder(root->right);
    }
};

拿掉提早結束,並改成 if (rank <= 0) ans = … 一直覆寫,留下最後一個值 失敗 3456/4081,最小 [1,null,2], k=1 → 2
先右後左(反向中序) 變成第 k 大 失敗 3604/4081,最小 [1,null,2], k=1 → 2

// 修正「找到後還在走」:左子樹回來再檢查一次
void inorder(TreeNode* root) {
    if (!root || rank <= 0) return;
    inorder(root->left);
    if (rank <= 0) return;                         // 答案在左子樹裡找到了
    if (--rank == 0) { ans = root->val; return; }  // 就是我,右子樹不用走
    inorder(root->right);
}

實測 100,000 組隨機樹:答案全對,且處理的節點數恰好等於 k。

n = 10⁴ 左斜鏈、k = 1:呼叫 20001 → 10001,處理 10000 → 1。 平衡樹 k = 1:27 → 14 次呼叫。

剩下的 10001 次呼叫是「一路往左走到最底」本身的成本,遞迴版避不掉,那就是 O(h)。

// PHASE 1: 為什麼 rank 要放在 member 每一層遞迴都要知道「到目前為止已經處理了幾個節點」, 而這些節點大多在「別層」被處理(例如左子樹裡)。 member / 傳參考 → 所有層改的是同一個變數 → 左子樹處理了幾個,回來看得到 傳值 → 每層拿到的是複本 → 左子樹的遞減回不來 實測傳值版失敗 3600/4081,最小反例 [2,1], k=1: 根 2 先把 rank 的複本傳給左子樹 1,1 把它減成 0 並設 ans = 1 回到 2 時,2 手上的 rank 還是 1 → 減成 0 → ans 被改成 2 // 計數器是「全域的進度」,不是「每層自己的狀態」
// PHASE 2: --rank == 0 為什麼是前置遞減 rank 一開始是 k,代表「還要再處理幾個」。 處理一個節點 → 先減 1 → 剩 0 就代表這是第 k 個。 --rank == 0 : 先減再比,第 k 個節點時成立 ✓ rank-- == 0 : 先比再減,要等 rank 進來時已經是 0 才成立 → 那已經是第 k+1 個節點(或找到後回頭的祖先) → 常常被入口的 rank <= 0 擋掉,ans 根本沒被設定 實測 rank-- 版 4081/4081 全錯: 1429 組 ans 從沒被設定(例如 [1], k=1),其餘 2652 組設成了錯的值 // 這也是為什麼 ans 沒初始化卻不會出事:正確版保證一定會被設定一次
// PHASE 3: 找到之後發生什麼事(範例 2,k = 3) visit 3:rank 1 → 0,ans = 3 ← 找到了 inorder(3->right = 4):入口 rank = 0 → return(被擋下) 回到 5(5 早就進來了,正停在 inorder(5->left) 這行) --rank:0 → −1 ← 多餘的一次處理 −1 ≠ 0,ans 不變 inorder(5->right = 6):入口 rank = −1 → return(被擋下) 5 是「往左走到 3」的祖先 ⇒ L = 1 處理數 = k + L = 3 + 1 = 4,呼叫數 = 2 × 4 + 1 = 9 ✓ 與實測一致 // 3 的祖先只有 5,而且是從 5 往左走到 3 → L = 1
// PHASE 4: 值域包含 0 會不會出事 值域 0 ~ 10^4,答案可能就是 0。 這份程式用 rank 判斷「找到沒」,不是用 ans 判斷 ⇒ ans = 0 不會被誤認成「還沒找到」 實測:平衡樹 n=10^4, k=1 → 回傳 0(真實值),不是哨兵值 // 對照 337:那題用 if (memo[x]) 判斷「存過沒」,0 就出事了
