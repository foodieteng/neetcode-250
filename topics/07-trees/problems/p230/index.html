BST 中第 k 小的元素

// CONCEPT · 中序就是排序,數到第 k 個就停

題目簡介// THE QUESTION

QUESTION

給一棵二元搜尋樹(BST)的 root 和整數 k, 回傳樹中第 k 小的值(k 從 1 開始)。
節點數 n:1 ≤ k ≤ n ≤ 10⁴,值 0 ~ 10⁴。
範例:[5,3,6,2,4,null,null,1]、k = 3 → 3。
Follow-up:如果樹會被頻繁插入、刪除,又要頻繁查第 k 小,怎麼優化?

BST 的中序走訪會由小到大輸出所有值。 所以「第 k 小」= 「中序走訪時第 k 個被處理的節點」, 不需要排序,也不需要把整棵樹存下來。
2

為什麼用「中序 + 倒數計數器」// KNOCKOUT

A 走訪全部節點,收集後排序 O(n log n)
答案對,但完全沒用到 BST 的性質: BST 的中序本來就是排好的,再排一次是多餘的。 還要 O(n) 額外空間存所有值。
× REJECT · 浪費
B 中序走完整棵樹,存成陣列取 [k−1] O(n)
正確,本頁對拍就是用它當參考答案。 但 k 很小時還是會走完全部 n 個節點,並用 O(n) 空間存下整個序列。
△ 對但不必要
ADOPT
C 中序走訪 + rank 倒數,數到 0 就是答案 O(h + k) 時間 · O(h) 空間
每處理一個節點就 --rank,減到 0 的那個節點就是第 k 小。 不存陣列,找到之後就不再往下走。 實測:n ≤ 8 全部 BST 形狀 × 全部 k 共 15,521 組,加上隨機 200,000 組,不一致 0。
● ADOPT · 用到 BST 性質
3

核心策略 · 三步驟// STRATEGY

  1. 設計數器:rank = k,放在 member,讓所有遞迴層共用同一個。
  2. 中序走訪:左子樹 → 自己 → 右子樹。處理自己時 --rank, 減到 0 就記下 ans。
  3. 提早結束:rank <= 0 代表答案已經找到,新的呼叫一進來就直接 return。
中序順序 = 1, 2, 3, 4, 5, 6　⇒　第 k = 3 個被處理的節點 = 3

提早結束只擋住「新進來的呼叫」// THE HIDDEN COST

// LEMMA: 檢查只在函式入口

if (!root || rank <= 0) return; 只在進入函式時檢查一次。

找到答案時,第 k 個節點上面的祖先們早就進入函式了,正停在 inorder(root->left) 這一行等它回來。 回來之後它們不會再檢查 rank,而是照樣執行 --rank,再呼叫一次右子樹(那次呼叫才會被入口擋下)。

會這樣做的,是「往左走才到達第 k 個節點」的那些祖先。設它們有 L 個。

處理的節點數 = k + L　·　呼叫次數 = 2(k + L) + 1
實測 230,000 組(各種樹形、全部 k),公式全部吻合
n = 10⁴,k = 1L原版 呼叫 / 處理修正版 呼叫 / 處理
左斜鏈(最小值在最底)999920001 / 1000010001 / 1
平衡樹1227 / 1314 / 1
右斜鏈(最小值在根)03 / 12 / 1
左斜鏈、k = 1 最誇張:答案是最底下那個節點,找到後 9999 個祖先會一路把 rank 減到 −9999, 等於把整棵樹走完。答案仍然正確(== 0 只成立一次),只是做了白工。 修法是在左子樹回來後再檢查一次 —— 見程式碼頁第 4 節。

複雜度// COMPLEXITY

要先從根往下走到最小值(h 層),再依序處理 k 個節點,所以理想是 O(h + k)。 這份程式多了上一節的 L 次多餘處理,最壞會走完整棵樹。

時間 O(h + k + L),最壞 O(n)　·　空間 O(h) 堆疊
項目值實測依據
Time(原版)O(h + k + L)呼叫 = 2(k+L)+1,230,000 組吻合
Time(修正版)O(h + k)100,000 組隨機樹,處理的節點數恰好 = k
SpaceO(h),最壞 n左斜鏈 n = 10⁴ 深度 10001
Stack 餘裕≈ 26 倍-O0 約 32 B/層,崩潰深度 261,408

一句洞察// INSIGHT

BST 的中序就是一條已排序的串流,第 k 小就是串流的第 k 個 (中序走訪本身見 94)。 計數器一定要全部遞迴層共用,所以放 member 或傳參考。 「一進門就檢查」擋不住已經在路上的祖先 —— 想真的停下來,左子樹回來後要再檢查一次。

// ONE-LINE TAKEAWAY
BST 中序由小到大,每處理一個節點 --rank,減到 0 的就是第 k 小。答案永遠正確,但 rank <= 0 只在入口檢查:找到後,往左走過來的 L 個祖先仍會各做一次 --rank,處理數 = k + L(左斜鏈 k=1 等於走完整棵樹)。左子樹回來後再檢查一次,處理數就恰好是 k。
