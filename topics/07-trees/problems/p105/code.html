完整實作// DIVIDE & CONQUER

p105.cpp C++17 
class Solution {
public:
    TreeNode* buildTree(vector<int>& preorder, vector<int>& inorder) {
        unordered_map<int, int> rootToIdx;           // 值 → 中序索引
        int n = inorder.size();
        for (int i = 0; i < n; i++) {
            rootToIdx[inorder[i]] = i;
        }

        return build(preorder, inorder, 0, 0, n - 1, rootToIdx);
    }

    TreeNode* build(vector<int>& preorder, vector<int>& inorder, int preL, int inL, int inR, unordered_map<int, int>& rootToIdx) {
        if (inL > inR) return nullptr;                 // 空區間

        int rootV = preorder[preL];                      // 前序第一個 = 根
        int rootIdx = rootToIdx[rootV];                  // 根在中序的位置
        int leftSize = rootIdx - inL;                    // 左子樹大小

        TreeNode* node = new TreeNode(rootV);
        node->left = build(preorder, inorder, preL + 1, inL, rootIdx - 1, rootToIdx);
        node->right = build(preorder, inorder, preL + leftSize + 1, rootIdx + 1, inR, rootToIdx);

        return node;
    }
};

邊界與陷阱// PITFALLS

下表每一列都是把正解改掉一個地方後,在 n=1..7 全部 625 種樹形上實測的結果。

陷阱症狀實測
一組 L, R 同時當前序起點和中序區間 無限遞迴 失敗 618/625,最小 pre=[2,1] in=[1,2];官方範例 1 也 segfault
右子樹起點寫成 preL + leftSize(漏 +1) 越界讀取 失敗 618/625,最小 pre=[1,2] in=[1,2](正解 [1,null,2])
leftSize = rootIdx(忘了減 inL) 右子樹起點偏移,越界 失敗 498/625,最小 pre=[1,2,3] in=[1,2,3]
右子樹起點寫成 preL + rootIdx + 1 同上(inL ≠ 0 就錯) 失敗 498/625,最小 pre=[1,2,3] in=[1,2,3]
左子樹區間寫成 [inL, rootIdx](包含根) 越界 失敗 625/625,連 [1] 都錯
base case 寫成 inL >= inR 單一節點的區間被丟掉 失敗 625/625,[1] → []
全域 preIdx++ 寫法,但先建右子樹 前序順序被打亂 失敗 498/625,最小 pre=[2,1,3] in=[1,2,3]
// 大部分錯法不是「答案錯」,而是「崩潰」

上表 7 種錯法裡,只有 base case 那一種的最小反例是「安靜地回傳錯的樹」。其餘 6 種的最小反例都是越界或無限遞迴。

原因是索引一旦錯位,preL 會超出陣列,或區間永遠不縮小。 寫這題時如果 segfault,第一個要檢查的就是 preL 的算法。

第二常見的是 +1:右子樹的起點要跳過根本身(1 格)和整個左子樹(leftSize 格)。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼先建 map 每次遞迴都要知道「根在中序的哪一格」。 線性掃:每層 O(區間長度) → 斜鏈時 n + (n−1) + ... = O(n²) map 查:每層 O(1) → 全部 O(n) 實測 n=3000 左斜鏈:線性掃 2.75 ms,map 0.195 ms ⚠ map 能成立的前提是「值互不相同」—— 題目有保證。 值重複時,rootToIdx 只會記住最後一次出現的位置,而且樹本身也不唯一。 // 題目上限 n=3000,其實 O(n²) 也會過;但面試會期待你講出 map 這一步
// PHASE 2: 三個索引各自代表什麼 build(preL, inL, inR) 表示: 「這棵子樹在中序裡佔 [inL, inR],在前序裡從 preL 開始、長度一樣」 所以前序不需要右界:長度 = inR − inL + 1,由中序決定。 rootV = preorder[preL] 這棵子樹的根 rootIdx = rootToIdx[rootV] 根在中序的格子 leftSize = rootIdx − inL 根左邊有幾格 = 左子樹節點數 // 記得「inL 不一定是 0」—— 進到右子樹後 inL 就不是 0 了
// PHASE 3: 兩個子呼叫的參數怎麼來 前序區段:[ 根 | 左 × leftSize | 右 ] preL preL+1 preL+leftSize+1 中序區段:[ 左 × leftSize | 根 | 右 ] inL ... rootIdx−1 rootIdx rootIdx+1 ... inR 左子樹 → build(preL + 1, inL, rootIdx − 1) 右子樹 → build(preL + leftSize + 1, rootIdx + 1, inR) 右子樹的前序起點要「跳過根(+1)再跳過整個左子樹(+leftSize)」。 // 漏掉 +1 會少跳一格,把左子樹的最後一個節點(或根自己)當成右子樹的根;實測在 [1,2]/[1,2] 就越界
// PHASE 4: base case 為什麼是 inL > inR 區間 [inL, inR] 的長度是 inR − inL + 1: inL == inR → 1 個節點(葉子),必須建立 inL > inR → 0 個節點,回傳 nullptr base case 先檢查,才讀 preorder[preL]: 最後一個葉子的空子樹會帶著 preL = n 進來(例:範例 1 的 build(5, 4, 3)) 如果先讀陣列再判斷,這裡就越界了。 // 寫成 inL >= inR 會把所有葉子丟掉,實測 625/625 全錯
PREV概念與動畫 NEXT觀念題與走讀
// ONE-LINE TAKEAWAY
先建 值→中序索引 的 map,再遞迴 build(preL, inL, inR):根 = preorder[preL],leftSize = rootIdx − inL,右子樹前序起點 = preL + leftSize + 1。呼叫次數恆為 2n+1,n=3000 斜鏈深度 3001 仍安全。錯位的索引大多直接崩潰:漏 +1 越界,共用 L, R 無限遞迴。
