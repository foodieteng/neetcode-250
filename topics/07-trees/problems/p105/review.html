分工前序告訴你誰是根;中序告訴你左右怎麼切

// ANSWERS
Q1 為什麼能唯一決定?

用歸納法看:前序的第一個值一定是根。因為值互不相同,這個值在中序裡只出現一次,位置唯一確定。

中序裡根左邊的就是左子樹的全部節點,右邊的就是右子樹的全部節點,數量也因此確定。前序裡緊接在根後面的 leftSize 個就是左子樹的前序,剩下的是右子樹的前序。

兩棵子樹各自又是「前序 + 中序」的同一個問題,規模更小,所以一路切到空區間,每一步都沒有選擇的餘地 ⇒ 唯一。

⚡ 必要條件是值互不相同。值重複時,根在中序的位置就不唯一了(見 App 3)。

Q2 為什麼前序不需要右界?

同一棵子樹在前序和中序裡佔一樣多格。中序區間 [inL, inR] 已經決定了長度 inR − inL + 1,前序只要知道從哪裡開始,右界就自動是 preL + (inR − inL)。

程式也從來不需要前序的右界:它只讀 preorder[preL](根),其他位置都是透過 leftSize 算出來的。

⚡ 反過來說,如果你只帶前序的區間 [preL, preR],就得另外帶中序的起點 inL,不然算不出 leftSize。兩個陣列的起點至少要各有一個。

Q3 為什麼是 preL + leftSize + 1?

前序區段的排列是 [ 根 | 左子樹 leftSize 格 | 右子樹 ]。右子樹的第一格要跳過根(1 格)和整個左子樹(leftSize 格),所以是 preL + 1 + leftSize。

漏掉 +1 會少跳一格,把左子樹的最後一個節點(或 leftSize = 0 時的根自己)當成右子樹的根。

實測在 n=1..7 全部 625 種樹形上失敗 618 種,最小反例 preorder=[1,2]、inorder=[1,2](正解 [1,null,2])直接越界讀取。

Q4 共用一組 L, R 為什麼錯?

因為同一棵子樹在兩個陣列裡的起點一般不同:前序從根開始,中序從最左邊的節點開始。一個 L 不可能同時是兩者。

在官方範例 1 上:第一層 L=0 時兩個起點剛好都是 0,還沒事。進到左子樹 build(1, 1):根是 pre[1] = 9,idx[9] = 0,leftSize = 0 − 1 = −1。

右子樹的呼叫變成 build(1 + (−1) + 1, 1) = build(1, 1) —— 跟自己一模一樣,區間沒有縮小,於是無限遞迴直到 stack overflow。實測:範例 1 直接 segfault。

在 n=1..7 全部 625 種樹形上失敗 618 種;最小反例 preorder=[2,1]、inorder=[1,2]。

⚡ 看到 leftSize 是負數,就代表兩個陣列的座標已經混在一起了。

Q5 呼叫幾次?

恰好 2n + 1 次。

每個非空的呼叫建立一個節點,共 n 次。每個節點會發出兩個子呼叫,總共 2n 個子呼叫,其中 n − 1 個對應到真的子節點(除了根,每個節點都是某人的小孩),剩下 n + 1 個是空區間。再加上最外層那一次:(n − 1) + (n + 1) + 1 = 2n + 1。

這個算法只用到「n 個節點、每個有 2 個子指標」,完全不看形狀。實測 n=3000 的左斜鏈、右斜鏈、平衡樹、隨機樹都是 6001 次,其中 3001 次是 nullptr。範例 1 則是 2×5+1 = 11 次。

⚡ 形狀影響的是深度,不是次數:平衡樹深度 13,斜鏈深度 3001。

App 1 改成 inorder + postorder

後序的根在最後一格,排列是 [ 左子樹 | 右子樹 | 根 ]。所以改成從右邊找根,並用右子樹的大小往回推:

TreeNode* build(vector<int>& postorder, int postR, int inL, int inR,
                unordered_map<int, int>& rootToIdx) {
    if (inL > inR) return nullptr;
    int rootV = postorder[postR];            // 後序最後一個 = 根
    int rootIdx = rootToIdx[rootV];
    int rightSize = inR - rootIdx;           // 右子樹大小

    TreeNode* node = new TreeNode(rootV);
    node->left  = build(postorder, postR - rightSize - 1, inL, rootIdx - 1, rootToIdx);
    node->right = build(postorder, postR - 1,             rootIdx + 1, inR, rootToIdx);
    return node;
}
// 呼叫:build(postorder, n - 1, 0, n - 1, rootToIdx)

右子樹的後序終點就是根的前一格 postR − 1;左子樹要再往前跳過整個右子樹,是 postR − rightSize − 1。和 105 完全對稱。

實測:隨機 100,000 棵樹不一致 0;106 官方範例 inorder=[9,3,15,20,7]、postorder=[9,15,7,20,3] 建出 [3,9,20,null,null,15,7]。

App 2 全域 preIdx 寫法
int preIdx = 0;
TreeNode* build(vector<int>& preorder, int inL, int inR) {
    if (inL > inR) return nullptr;
    int rootV = preorder[preIdx++];
    TreeNode* node = new TreeNode(rootV);
    int rootIdx = rootToIdx[rootV];
    node->left  = build(preorder, inL, rootIdx - 1);   // 一定先左
    node->right = build(preorder, rootIdx + 1, inR);
    return node;
}

可行的原因:遞迴的建立順序本身就是前序(根 → 左 → 右)。所以「下一個要建的節點」一定是 preorder 的下一格,不需要自己算位移,leftSize 也省掉了。

條件是一定要先建左子樹、再建右子樹。反過來的話,建立順序變成「根 → 右 → 左」,跟前序對不上。實測先右後左:失敗 498/625,最小反例 preorder=[2,1,3]、inorder=[1,2,3] 越界;先左後右則是 0/625,隨機 100,000 棵也 0 不一致。

⚡ 在 LeetCode 上要注意:preIdx 如果是 member,同一個 Solution 物件被重複呼叫時要記得在 buildTree 開頭歸零。

App 3 前序 + 後序?值重複?

前序 + 後序:一般不能唯一決定。它們都沒有「切點」資訊。例如 preorder=[1,2]、postorder=[2,1]:2 可以是 1 的左小孩,也可以是右小孩,兩棵樹的前序和後序完全一樣。

LeetCode 889 就是這個題目,它只要求「回傳任一棵符合的樹」;如果題目保證是滿二元樹(每個節點 0 或 2 個小孩),才會唯一。

值重複:前序 + 中序也不唯一了。例如 preorder=[1,1]、inorder=[1,1]:第二個 1 可以是左小孩,也可以是右小孩,兩棵樹的兩種走訪都一樣。

而且這份程式的 map 會直接壞掉:rootToIdx[inorder[i]] = i 會讓重複的值只留下最後一次出現的位置。

⚡ 結論:中序提供切點,值互異保證切點唯一,兩者缺一就不唯一。
