A naive approach would be to just follow the right pointers from the root and collect what I pass. It's two lines, and it's wrong. Across all 6918 tree shapes up to 9 nodes, it fails on 6555 — 94.75%. It only works when the right spine is as long as the tree is tall.

CANDIDATE

Here's the plan.

// invariant: at the top of each outer turn,
// the queue holds one full level, left to right.

push root
while queue not empty:
  sz = q.size()  // freeze the level width
  for i in 0 .. sz-1:
    u = pop front; push u's children (left, then right)
    if i == sz - 1: record u->val

One: push the root.
Two: at the top of each round, freeze the level width, sz = q.size().
Three: pop that many nodes, push children left then right, and record the node where i == sz - 1 — the last one at this depth.

One thing worth flagging — sz must be frozen before the inner loop, because I push children into the same queue I pop from. Against the live q.size(), the last-of-level test fires on the wrong node and levels merge.

There's a trade-off here. A right-first DFS that records the first node at each new depth uses an O(h) stack instead of an O(w) queue. I prefer BFS because the rule, "last node at this depth," is stated directly in the code. Does this approach sound good, or would you rather I think of another way?

I — implement

CANDIDATE

Alright, let me code this up. A null root returns an empty list right away. Then it's standard BFS: freeze sz, pop that many nodes, push the left child before the right, and record the value when i == sz - 1.

class Solution {
public:
    vector<int> rightSideView(TreeNode* root) {
        if (root == nullptr) return {};

        queue<TreeNode*> q;
        q.push(root);
        vector<int> ans;

        while (!q.empty()) {
            int sz = q.size();          // ← freeze the level width

            for (int i = 0; i < sz; i++) {
                auto u = q.front(); q.pop();

                if (u->left) q.push(u->left);    // left first
                if (u->right) q.push(u->right);  // then right ⇒ each level left to right

                if (i == sz - 1) ans.push_back(u->val);  // last one at this level
            }
        }

        return ans;
    }
};

One thing worth flagging — the test i == sz - 1 looks at nothing but queue position. It never asks whether u is a left or a right child, which is exactly the property I wanted, and it's why the left-only chain needs no special case.

A nice sanity check: change the test to i == 0, and the same code gives the left side view — the opposite end of the level.

Let me think about complexity here.

Time is O(n) — each node is pushed once and popped once, with constant work. Space is O(w), where w is the widest level, and the output adds O(h).

The worst case is a perfect tree: the bottom level holds about half the nodes, so the queue peaks near n/2. The DFS version flips this — its O(h) stack is worse on a chain and better on a wide tree.

Oh, one more thing — this code never compares values; it only counts positions. So duplicates and negatives are fine, and a left view would be a one-line change.
