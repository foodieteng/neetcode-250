範例 Trace// [1,2,3,null,5,null,4] → [1,3,4]

官方範例 1,實跑印出來的。 重點:節點 5 和節點 4 都是右小孩,卻一個落選一個入選。

// Level 0 sz = 1 i=0/1 pop 1 push {2,3} i == sz-1 (0==0) → ★ 記錄 1 queue after = [2,3] ans = [1]
// Level 1 —— 這一層決定了下一層的順序 sz = 2 i=0/2 pop 2 push {5} i != sz-1 (0!=1) → 跳過 queue after = [3,5] i=1/2 pop 3 push {4} i == sz-1 (1==1) → ★ 記錄 3 queue after = [5,4] ans = [1,3] ⚡ 注意佇列此刻是 [5, 4]: 先 pop 的是 2,所以「2 的右孩 5」先進隊 後 pop 的是 3,所以「3 的右孩 4」後進隊 ⇒ 下一層 5 在前(i=0)、4 在後(i=1) // 5 和 4 都是右小孩,但 5 的父節點排在前面,所以 5 也排在前面
// Level 2 + OUTPUT sz = 2 i=0/2 pop 5 push {} i != sz-1 (0!=1) → 跳過 ← 5 落選 i=1/2 pop 4 push {} i == sz-1 (1==1) → ★ 記錄 4 ← 4 入選 queue after = [] while (!q.empty()) 不成立 → 結束 return [1,3,4] 統計:入隊 4、出隊 4(n=4 的節點都恰好進出一次) ans.size() = 3 == 樹高 3 ✓ // 5 被 4 擋住了 —— 不是因為 5 是左是右,而是因為 5 站在該層的左邊
把 Level 1 和 Level 2 連起來看,整題就清楚了: Level 1 的「彈出順序」決定了 Level 2 的「排隊順序」, 而 Level 2 的排隊順序決定了誰是「最右」。 所以「誰入選」是被兩層之前的推入順序決定的 —— 和節點自己是左是右無關。

// ANSWERS
A1. 因為「看得到」的條件是「該層最右」,而右脊一斷,下面幾層還是有節點看得到。

最小反例只要 2 個節點:[1,2](root 只有左小孩)。
· 右脊法:記下 1,發現 root->right 是 null,停 → [1]。
· 正解:第 1 層只有節點 2,它就是該層最右 → [1,2]。

最極端的教具是「左斜鏈」:[1,2,null,3,null,4,null,5] —— 整棵樹一個右小孩都沒有,右視圖卻是全部 5 個節點(實測)。站在右邊看一條往左斜的鏈,你當然每一節都看得到 —— 沒有東西擋在它前面。

實測錯誤規模:窮舉 n ≤ 9 的 6918 種樹形,右脊法錯 6555 種(94.75%),而且失敗率隨 n 上升(n=9 時 95.6%)。

一句話:「右視圖」問的是「每一層誰站最右」,不是「從根往右能走多遠」。
A2. 精確條件:右脊法正確 ⟺ 右脊的長度恰好等於樹高。

實測三個方向都驗過,零例外:
· 巧合對 且 右脊長 == 高 → 363
· 巧合對 但 右脊長 ≠ 高 → 0
· 右脊長 == 高 但 答錯 → 0

直覺:只要右脊本身就是一條最深的路徑,那麼每一層的最右剛好都落在右脊上,右脊法就沿路一個不漏地撿起來。只要有任何一層的最右不在右脊上(包含右脊提早斷掉),就錯。

⚡ 對測資選擇的意義,這才是重點:
「完美樹」和「右斜鏈」的右脊長度都等於樹高 —— 所以拿它們去測,這個 bug 一定會通過。
要抓它,測資必須有「某一層的最右不在右脊上」,最小的就是 [1,2]。

這和本章反覆出現的教訓是同一個(144 的斜鏈、102 的斜鏈):「我測過了」和「我測到能區分的形狀了」是兩回事,而有精確刻畫的 bug 特別好防 —— 你知道它會在哪裡騙過你。
A3. 不是那一行保證的 —— 是「先左後右」的推入順序保證的。

i == sz - 1 只做一件事:取出「該層的最後一個」。它憑什麼等於「最右」?靠的是佇列裡同一層本來就是由左到右排列。

而那個排列是這兩行的順序造成的:
if (u->left)  q.push(u->left);     // 先
if (u->right) q.push(u->right);    // 後
歸納法:假設第 k 層在佇列裡已經由左到右,那麼逐個彈出時,每個節點把「自己的左、再自己的右」接在隊尾 ⇒ 第 k+1 層也由左到右。基底是第 0 層只有 root,顯然成立。

所以如果把那兩行對調(先右後左),同層就變成「由右到左」,i == sz - 1 取到的就成了最左 —— 整個變成左視圖,而那一行完全沒改。

這是一個很好的提醒:一段程式碼的正確性,常常不在你盯著的那一行,而在別處建立的不變量上。
A4. i == 0 → 精確地變成「左視圖」;i == sz → 永遠回傳 []。

i == 0:取該層第一個 = 最左 ⇒ 左視圖。
實測:與一個獨立實作的「左視圖」參考解比對,6918/6918 完全相同 —— 它不是「壞掉」,而是精確地變成另一個合理的問題。官方範例會從 [1,3,4] 變成 [1,2,5]。
(它和正解「碰巧相同」的有 512 種 —— 就是那些每層只有一個節點的樹,左右視圖重合。)

i == sz:永遠不成立,因為迴圈條件就是 i < sz。
實測錯 6917/6918 —— 唯一「對」的是空樹(答案本來就是 [])。

兩者的症狀差很多:
· i == sz 回傳空陣列,一測就發現。
· i == 0 回傳一個「長度正確、看起來很合理」的答案 —— 如果你只檢查長度或只看小測資,很容易放過。
「安靜地變成另一個正確答案」永遠比「明顯壞掉」難抓。
A5. int sz 比較好;但在這題的約束下兩者都不會出錯。

實測的編譯警告(-Wall -Wextra):
· 102 的 auto sz 版 —— 吐出 -Wsign-compare:
warning: comparison of integers of different signs:
         'int' and 'size_type' (aka 'unsigned long')
   for (int _ = 0; _ < sz; _++) {
· 本題的 int sz 版 —— 0 warnings(要加 -Wconversion 才看得到窄化提醒)。

int sz 好在三點:
① 在多數 CI 的預設等級下乾淨。
② 一次轉換 vs 每圈一次隱式提升 —— 風險收斂到單一個可以審視的點。
③ ⚡ 這題特別重要:程式碼裡有 sz - 1。如果 sz 是 size_t 而某天 sz == 0,sz - 1 會回繞成天文數字。這裡因為佇列非空所以 sz >= 1,但那是「碰巧安全」,不是「設計上安全」。

約束內都不會出錯:n ≤ 100,實測最寬合法樹的佇列峰值只有 50,離 INT_MAX 差 4000 萬倍。要真的壞掉需要單層超過 21 億個節點。

一般習慣:看到 .size() - 1 就該停一秒想想無號回繞。
App 1. DFS「先走右子樹」,關鍵的一行是 if (ans.size() == depth)。

void dfs(TreeNode* root, int depth, vector<int>& ans) {
    if (root == nullptr) {
        return;
    }

    if ((int)ans.size() == depth) {     // ★ 第一次到達這個深度
        ans.push_back(root->val);
    }

    dfs(root->right, depth + 1, ans);   // ★ 先走右
    dfs(root->left,  depth + 1, ans);
}
為什麼對:因為先遞迴右子樹,每個深度「第一次」被走到的節點,必定是該深度最右的那個。ans.size() == depth 正好在偵測「這個深度是不是第一次被看到」。

本頁就是拿它當對拍參考解之一 —— 窮舉 6918 種樹形 + 隨機 20 萬組,與 BFS 版零不一致。

兩者取捨:DFS 空間 O(h)、BFS 空間 O(w) —— 又是那組相反的最壞情況。這題 n ≤ 100,兩邊都無所謂;但如果樹很寬,DFS 版反而更省(見 App 3)。
App 2. 把「只記最後一個」改成「整層取 max」——骨架一個字都不用動。

while (!q.empty()) {
    int sz = q.size();
    int best = INT_MIN;                 // ← 每層一個

    for (int i = 0; i < sz; i++) {
        auto u = q.front(); q.pop();
        best = max(best, u->val);       // ← 換掉 i == sz-1 那一行

        if (u->left)  q.push(u->left);
        if (u->right) q.push(u->right);
    }

    ans.push_back(best);
}
因為改成取 max,所以「推入順序」在這題就不重要了 —— 先左後右、先右後左,max 都一樣。這反過來凸顯了 199 的重點:那個順序之所以要緊,純粹是因為 199 用「位置」來選節點。

⚠ 一個小陷阱:best 必須每層重設。寫在 while 外面就會變成「前綴最大值」 —— 答案會變成單調不減,而那是另一個(錯的)問題。

同一個骨架還能生出好幾題:每層平均值(637)、每層節點數、之字形(103)…… 差別都只在「內層迴圈裡對那一層做什麼」。
App 3. BFS 的佇列會膨脹到 O(w) —— 這時候該換成 DFS。

一個有 10⁵ 個葉子的完全樹,最寬那一層就有約 5×10⁴ 個節點 ⇒ 佇列要裝 5 萬個指標(約 400 KB),而且那還只是佇列本身的內容。

實測對照(同一棵樹同時量兩者):
· 完美樹 n=1023 → BFS 佇列峰值 512 vs DFS 遞迴深度 10
· 左斜鏈 n=1000 → BFS 佇列峰值 1 vs DFS 遞迴深度 1000
完全對稱的兩個災難。

所以「樹很寬」的時候 DFS 版(App 1)明顯較好 —— 它的成本只跟樹高有關,而完全樹的高度只有 log n ≈ 17。

⚠ 但要注意反過來的風險:如果樹很深(退化成鏈),DFS 就會有 stack overflow 的問題 —— 本章 235、450 都量過那條線。

結論:沒有一個永遠較好的選擇,要看樹的形狀。這題 n ≤ 100,兩種都綽綽有餘;會需要真的選的是那些 n 到 10⁴~10⁵ 的題目。

右視圖是「每層最右」,而決定入選的是佇列位置、不是左右身分 —— 真正建立那個順序的是「先左後右」的推入,對調就變左視圖。走右脊錯 94.75%,且巧合對 ⟺ 右脊長度等於樹高,所以完美樹和右斜鏈永遠測不出它。
