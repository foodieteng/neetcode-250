完整實作// RECURSIVE

p226.cpp C++17 
class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        if (root == nullptr) return nullptr;

        root->left = invertTree(root->left);     // ① 左子樹先翻好
        root->right = invertTree(root->right);   // ② 右子樹也翻好
        swap(root->left, root->right);          // ③ 再換自己的兩根指標

        return root;
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

這份寫法是後序(先兩個遞迴、再處理自己),所以 swap 發生在回程 —— 實測順序 1 → 3 → 2 → 6 → 9 → 7 → 4,根的 swap 是最後一步。 但這題「先 swap 再遞迴」也完全正確(實測 0/197 失敗) —— 見下方走讀 PHASE 2。

兩個「其實可以省」的細節// REDUNDANCY

這份程式碼完全正確(20 萬組對拍零不一致),但有兩處是冗餘的。 知道它們冗餘、並說得出為什麼,是面試時的加分項。

// 冗餘 ①:回寫 root->left = invertTree(...) root->left = invertTree(root->left); invertTree() 回傳的「永遠就是傳進去的那個指標」——它不會換成別的節點。 實測:2000 棵隨機非空樹,invertTree(root) == root 命中 2000/2000。 所以這個回寫等於 root->left = root->left,寫成下面這樣完全等價: invertTree(root->left); invertTree(root->right); swap(root->left, root->right); // 保留它也無妨 —— 有些人喜歡這種「函式式」的寫法,而且改成會替換節點的題目時就需要了
// 冗餘 ②:base case 的 return nullptr if (root == nullptr) return nullptr; 回傳值是 nullptr,而呼叫端做的是 root->left = nullptr —— 本來就是 nullptr。 所以寫成 if (root == nullptr) return root; 或直接 return; (改成 void)都可以。 不過這一行「本身」絕對不能省: 實測拿掉整個 nullptr 檢查 → 197 種樹形「全部」SIGSEGV,連 [] 和 [1] 都當場崩 // 冗餘的是「回傳什麼」,不是「要不要檢查」—— 兩件事別搞混
面試時值得主動說出這兩點:「這個回寫在這題是冗餘的,因為節點本身不會被替換; 但如果題目改成會回傳新節點的操作(例如 BST 插入或刪除), 這個回寫模式就變成必要的。」—— 展示你知道它為什麼在那裡,不是照抄。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼「交換值」是錯的(兩種病) 病一:單邊子樹時,swap 根本不會發生 [1,null,2] 只有右小孩,left 是 nullptr 想交換值就得寫 swap(root->left->val, root->right->val) → 但 root->left 是 nullptr,不加保護會直接爆 → 加了保護(兩邊都非空才換)就變成「什麼都不做」 實測輸出 [1,null,2],正解 [1,2] ✗ 病二:就算兩邊都在,換值也只換了「一個節點的內容」 形狀完全沒動。任何「左右形狀不同」的樹都會壞掉 例:[1,2,3,4] (2 有左小孩 4,3 沒有小孩) 換值後 3 和 2 的值互換,但 4 還是掛在原本的位置 實測:194/197 錯。巧合對的只有 3 種:[]、[1]、[1,2,3] [1,2,3] 過關純屬巧合 —— 兩個孩子都是葉,換值和換子樹結果相同 // 換指標搬動整棵子樹,換值只搬動一個節點 —— 這是本題的核心區別
// PHASE 2: 為什麼「先 swap 再遞迴」也對(這不是陷阱) 版本 A(本頁的寫法,後序): 版本 B(先 swap): invertTree(root->left); swap(root->left, root->right); invertTree(root->right); invertTree(root->left); swap(root->left, root->right); invertTree(root->right); 實測:版本 B 窮舉 197 種樹形,失敗 0 種 —— 完全正確 為什麼:翻轉是「上下無關」的操作 「交換我的兩個孩子」動的是 root 的兩根指標 「把兩棵子樹各自翻好」動的是子樹「內部」的指標 兩者互不干擾 ⇒ 誰先誰後都一樣 版本 B 遞迴進去的雖然是「已經換位置」的孩子,但每個孩子 「要被翻成什麼樣子」和「它掛在哪一邊」無關 —— 所以結果同構 // 真正要緊的是「換指標不換值」,不是「順序」—— 別把這個寫進陷阱表
// PHASE 3: 手寫 swap 為什麼一定要暫存(實測病狀) 錯的寫法(經典的無暫存 bug): root->left = root->right; // ① left 現在指向原本的 right root->right = root->left; // ② 但 left 已經被改了!等於 right = right 實測兩種病狀,都是真的量出來的: [1,2](只有左孩子) distinct 節點數 before = 2 → after = 1 → 左子樹被 nullptr 覆蓋,那個節點「洩漏消失」 [1,null,2](只有右孩子) 輸出印成 [1,2,2],distinct 節點數仍是 2 → 同一個節點「同時掛在 left 和 right 兩個槽」= 別名共享 → 節點數「看起來」從 2 變成 3 正確寫法: TreeNode* tmp = root->left; root->left = root->right; root->right = tmp; 或者直接用 std::swap(root->left, root->right); // 「弄丟節點」和「製造別名」是指標題最典型的兩種死法,而且兩者都不會當場崩
// PHASE 4: 和 nullptr 交換是完全安全的(實測) 一個只有左小孩的節點,swap 前後的指標實測: before left = 0x140d8f360 right = 0x0 after left = 0x0 right = 0x140d8f360 子節點指標完好保存(childPtrPreserved = 1),left 正確變成 null。 所以程式碼裡「不需要」寫這種特判: if (root->left != nullptr && root->right != nullptr) swap(...); ← 多餘且有害 std::swap 對兩個指標一律良定義,不管它們是不是 nullptr。 加上這種特判反而會讓「單邊子樹」的節點不被翻轉 —— 那就變成上面的 M5 了。 // 少一個分支,少一個 bug —— 和「用 nullptr 當 base case」是同一個道理

// ONE-LINE TAKEAWAY
換的是子樹指標不是值(換值錯 194/197);手寫 swap 沒暫存會弄丟節點或製造別名,兩種病狀都實測到了。和 nullptr 交換完全安全,所以不要加「兩邊都非空才換」的特判。回寫 root->left = invertTree(...) 在本題是冗餘的,但改成會替換節點的操作時就必要。
