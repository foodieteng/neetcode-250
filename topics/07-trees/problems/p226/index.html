題目簡介// THE QUESTION

QUESTION

給二元樹的根節點 root,翻轉它,回傳根節點。 節點數 0 ~ 100,節點值 −100 ~ 100。

「翻轉」的意思是鏡射 —— 把整棵樹左右照鏡子。 做法是:每一個節點都把自己的左右子樹交換。

這題是後序骨架的第一個真正應用,而且它示範了一個新東西: 遞迴不只可以「收集」東西,也可以「修改」結構。 而修改結構時最重要的一件事是:交換的是子樹指標,不是節點的值。 實測把它寫成交換值,197 種樹形錯 194 種。
2

交換指標,不是交換值// WHY THIS

A 交換左右小孩的值 錯 194/197
swap(root->left->val, root->right->val) —— 值換了,形狀沒動。任何左右形狀不同的樹都會壞掉。 最小反例 [1,null,2]:只有一邊有小孩,swap 根本不會發生。
× REJECT · 只換了值
B 只交換根的左右,不遞迴 錯 192/197
只翻了最上面那一層。實測只在「高度 ≤ 2」的 5 種樹上碰巧正確 —— 因為那時只有一層需要翻。
× REJECT · 只翻一層
ADOPT
C 每個節點都 swap 自己的左右子樹指標 O(n) 時間 · O(h) 空間
交換的是兩根指標,等於把兩整棵子樹搬過去 —— 節點本身一個都不動、也不新增。 實測 2000 棵隨機樹,翻轉前後節點位址集合完全相同(2000/2000)。
● ADOPT · 原地鏡射
為什麼「交換指標」比「交換值」強: 交換一根指標,底下整棵子樹都跟著過去了 —— O(1) 的動作搬動 O(n) 的資料。 交換值只搬動一個節點的內容,而且當一邊是 nullptr 時,你根本沒有值可以交換。
3

核心策略 · 三步驟// THE SHAPE

  1. 終止:if (root == nullptr) return nullptr; —— 空子樹翻轉之後還是空的。
  2. 先把兩棵子樹各自翻好: invertTree(root->left) 和 invertTree(root->right)。
  3. 再交換自己的兩根指標:swap(root->left, root->right); 然後 return root;。
這份寫法是「先遞迴、後 swap」,所以交換發生在回程 —— 實測 swap 的發生順序是 1 → 3 → 2 → 6 → 9 → 7 → 4,根的 swap 是最後一步。 但這題有個好消息:順序其實無所謂(見下方 LEMMA 2)。

動畫演示// [4,2,7,1,3,6,9] → [4,7,2,9,6,3,1]

注意樹的節點位置會真的左右對調。 重點看根節點 4 是最後一個被 swap 的 —— 輪到它時,兩棵子樹內部早就翻好了,它只要把這兩整塊對調。

兩個值得知道的性質// TWO LEMMAS

LEMMA 1 · 翻轉 = 鏡射,而且可以用中序驗證

「翻轉」的正式說法是鏡射,而鏡射有一個可以直接測的定義: inorder(invert(T)) == reverse(inorder(T))。 翻轉之後的中序,恰好是原本中序的倒序。

實測:窮舉 n = 0..8 全部 2056 棵樹, 這條恆等式命中 2056/2056。
但同樣的說法換成前序就不成立: preorder(invert(T)) == reverse(preorder(T)) 只命中 2/2056 (只有 n ≤ 1 的平凡情形)。 原因是前序把根釘在第一個,而反轉會把根丟到最後 —— 只有中序的「根在中間、左右對稱」才撐得住反轉。

LEMMA 2 · 先 swap 再遞迴也是對的(這不是陷阱)

很多人會擔心:「先交換再遞迴的話,遞迴進去的不就是已經被換過的孩子了嗎?」 實測答案:完全沒問題。把 swap 移到兩個遞迴呼叫之前, 窮舉 197 種樹形失敗 0 種。

為什麼:翻轉是一個「上下無關」的操作 —— 「交換我的兩個孩子」和「把兩棵子樹各自翻好」互不干擾。 先換再各自翻,和先各自翻再換,結果同構。 所以這一題請不要把「順序」寫進陷阱表 —— 真正要緊的是「換指標而不是換值」。

一句洞察// INSIGHT

翻轉二元樹 = 每個節點交換自己的兩根子樹指標。 交換一根指標就搬動了整棵子樹,所以是 O(1) 的動作搬 O(n) 的資料 —— 這也是為什麼「交換值」是錯的:它只搬得動一個節點。 驗證方式記住這一條:inorder(invert(T)) == reverse(inorder(T)) —— 而換成前序就不成立,因為前序把根釘在最前面。
