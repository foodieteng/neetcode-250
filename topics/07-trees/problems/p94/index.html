題目簡介// THE QUESTION

QUESTION

給二元樹的根節點 root,回傳它的中序走訪結果。 節點數 0 ~ 100,節點值 −100 ~ 100。

這是整個 07 章的地基,而且是三連題的第一題(94 中序、 144 前序、145 後序)。 三題的程式碼只差一行的位置 —— 把 push_back 放在兩個遞迴呼叫的 前面 / 中間 / 後面,就分別是前序、中序、後序。

這題真正在教的不是「怎麼走訪」,而是遞迴的執行順序: 一個節點被走到和被收錄是兩個不同的時刻。 中序裡,一個節點走到之後要等整棵左子樹做完才輪到它 —— 看懂這個「等待」,後面 20 幾題的樹題都會變簡單。
2

為什麼是遞迴// WHY THIS

A 先把整棵樹壓平成陣列,再排序 O(n log n)
對 BST 碰巧會對(中序恰好遞增),但題目沒說是 BST。 一般二元樹的中序和值的大小完全無關 —— 它是位置決定的順序。 把它想成排序,是這題最根本的誤解。
× REJECT · 想錯方向
B 自己開一個 std::stack 模擬 O(n) 時間
完全正確,而且是本題最常見的追問(「不用遞迴怎麼寫」)。 但它要手動維護「這個節點的左邊做完了沒」,程式碼長度是遞迴版的三倍。 先把遞迴寫對,再談它。
△ 正確但先緩
ADOPT
C 遞迴:左 → 根 → 右,三行 O(n) 時間 · O(h) 空間
樹的定義本身就是遞迴的(一個根 + 兩棵子樹), 所以走訪的程式碼可以和定義長得一模一樣。 遞迴幫你維護的那個「左邊做完了沒」,就是呼叫堆疊 —— 你不用自己寫,編譯器已經寫好了。
● ADOPT · 三行搞定
遞迴不是「比較炫的寫法」,它是把「暫存狀態」外包給呼叫堆疊。 顯式 stack 版做的事一模一樣,只是那個 stack 由你自己開、自己 push、自己判斷 —— 代價從「編譯器幫你管」變成「你自己管」。
3

核心策略 · 三步驟// THE SHAPE

  1. 終止:if (root == nullptr) return; —— 空樹什麼都不做。 這是整段程式碼唯一的終止條件,葉節點不需要另外判斷。
  2. 先左:inorder(ans, root->left); —— 把整棵左子樹處理完。 這一行回來之前,自己什麼都不做。
  3. 再根、後右:ans.push_back(root->val); 然後 inorder(ans, root->right);。push 夾在中間,這就是「中」序。
三行的順序就是答案的順序。實測窮舉 n = 0..6 全部 197 種樹形: 把 push_back 移到最前面(變前序)錯 190 種, 移到最後面(變後序)也錯 190 種,把左右對調錯 195 種。 這一行放哪裡,不是風格問題。

兩個會被追問的「為什麼」// TWO LEMMAS

LEMMA 1 · 為什麼 nullptr 檢查不能省

很多人以為「反正葉節點的左右都是空的,少檢查一次應該只是多跑一層」。 不是 —— root->left 這個動作本身就要求 root 非空。 少了這行,遞迴會對 nullptr 解參考。

實測:拿掉 if (root == nullptr) return;,窮舉 n = 0..6 的 197 種樹形全部 SIGSEGV(exit 139) —— 連空樹 [] 和單節點 [1] 都當場崩。 它不是「少一層防禦」,它是唯一的地板。

LEMMA 2 · 為什麼 ans 一定要傳參考

void inorder(vector<int>& ans, ...) 那個 & 不是效能考量, 是正確性。少了它,每一層拿到的是自己的一份拷貝, push_back 寫進去就隨著那一層 return 一起消失。

實測:改成傳值,197 種樹形錯 196 種,最小反例 [1] 直接回 []。 唯一「對」的是空樹 —— 因為答案本來就是空的。 症狀非常好認:任何非空樹都回空陣列。

// 七種改法的實測結果(窮舉 n = 0..6,共 197 種樹形) push_back 移到最前面(變前序) → 錯 190/197,最小反例 [1,2] → [1,2](正解 [2,1]) push_back 移到最後面(變後序) → 錯 190/197,最小反例 [1,null,2] → [2,1](正解 [1,2]) 左右遞迴對調 → 錯 195/197,最小反例 [1,null,2] → [2,1](正解 [1,2]) 漏掉 nullptr 檢查 → 錯 197/197,連 [] 都 SIGSEGV ans 傳值而非傳參考 → 錯 196/197,最小反例 [1] → [] 忘了遞迴右子樹 → 錯 190/197,最小反例 [1,null,2] → [1] helper 開頭 ans.clear() → 錯 196/197,最小反例 [1] → [] // 「左右對調」錯 195/197 —— n ≥ 2 起零巧合,是最好抓的一種

複雜度// COMPLEXITY

每個節點恰好被進入一次,每次只做 O(1) 的事(一次 push_back)。 空間則是呼叫堆疊的深度 —— 也就是樹高 h,不是節點數。

時間 O(n)　·　空間 O(h),最壞(退化成鏈)O(n)、最好(平衡)O(log n)
維度值實測依據
時間O(n)inorder() 呼叫次數恆為 2n+1 —— 窮舉 n=0..8 全部 2056 種樹形皆成立,與形狀無關
空間O(h)實測每層 96 bytes(clean build,n=10000 量得 960000 bytes)
n=100 最壞堆疊約 9.7 KB退化成 100 節點的鏈,深度 101(多的一層是最底的 nullptr)
崩潰臨界87149 / 87150ulimit -s = 8176 KB;二分實測 87149 存活、87150 SIGSEGV
安全餘裕871 倍題目上限 n=100,離崩潰還有 871 倍 —— 這題遞迴絕對安全
常數項8 次 reallocans 容量成長 1→2→4→…→128(n=100 時)
注意空間是 O(h) 不是 O(n) —— 這是樹題和鏈結串列題最大的差別。平衡樹的 h ≈ log n,堆疊淺得多; 但退化成一條鏈時 h = n,兩者就一樣了,這也是「n 很大時遞迴會不會爆」的分界。

一句洞察// INSIGHT

中序的一切都在一句話裡:一個節點要等整棵左子樹做完,才輪到自己。 所以輸出的第一個元素是「一路往左走到底」的那個節點, 而根在輸出裡的下標,恰好等於左子樹的節點數 —— 後面「用前序 + 中序重建二元樹」(105)靠的就是這個性質。
