完整實作// RECURSIVE

p94.cpp C++17 
class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> ans;
        inorder(ans, root);
        return ans;
    }

    void inorder(vector<int>& ans, TreeNode* root) {
        if (root == nullptr) return;   // 唯一的終止條件

        inorder(ans, root->left);       // ① 左:整棵左子樹先做完
        ans.push_back(root->val);     // ② 根:夾在中間 = 「中」序
        inorder(ans, root->right);      // ③ 右
    }
};

整段程式碼只有三個決定:終止條件寫 root == nullptr(不是「是不是葉節點」)、 ans 用參考傳、push_back 放在兩個遞迴中間。 實測窮舉 197 種樹形,這三個決定各自改錯,分別會錯 197、196、190 種。

邊界與陷阱// PITFALLS

下表每一列都是窮舉 n = 0..6 全部 197 種樹形實跑出來的, 「失敗數」是真的錯掉的樹形數,「最小反例」是最小的那一棵。

陷阱失敗數最小反例怎麼修
漏掉 nullptr 檢查 197/197 [] → SIGSEGV 它不是防禦,是唯一的地板。連空樹都當場崩
ans 傳值而非傳參考 196/197 [1] → [] 簽名寫 vector<int>& ans。症狀:任何非空樹都回空陣列
helper 開頭 ans.clear() 196/197 [1] → [] ans 只能在最外層宣告一次,helper 裡永遠別碰它的長度
push_back 移到最前面(變前序) 190/197 [1,2] → [1,2](正解 [2,1]) 三行的順序就是答案的順序
push_back 移到最後面(變後序) 190/197 [1,null,2] → [2,1] 同上
左右遞迴對調 195/197 [1,null,2] → [2,1] 最好抓的一種 —— n ≥ 2 起零巧合
忘了遞迴右子樹 190/197 [1,null,2] → [1] 症狀:輸出長度比節點數少。先檢查 ans.size() == n
「巧合一致」是這張表最值得記的一欄。 把 push_back 移到最前面(前序),在純右鏈上會碰巧完全正確; 移到最後面(後序),在純左鏈上也碰巧正確。 所以只用一條斜鏈當測資,前序後序寫反你根本測不出來 —— 這也是為什麼上面對拍要涵蓋 197 種樹形,而不是幾筆手寫測資。

細節走讀// LINE BY LINE

// PHASE 1: 為什麼終止條件是 nullptr 而不是「葉節點」 寫成 if (root->left == nullptr && root->right == nullptr) return; 會有兩個病: ① root 本身是 nullptr 時,root->left 就直接爆炸 ② 葉節點被提早 return,它自己永遠不會被 push 實測:改成葉節點判斷,197 種樹形全錯 [] 與任何有「單邊子節點」的樹 → SIGSEGV [1](完美躲過 crash 的形狀) → 回 [](葉節點被吞掉) 寫成 root == nullptr 則兩件事一起解決: 空樹 → 第一次呼叫就 return,回 [] 葉節點 → 它的左右各進去一層、各自 return,葉節點本身照樣被 push // 「用 nullptr 當底」讓葉節點不需要任何特殊待遇 —— 這是遞迴寫得乾淨的關鍵
// PHASE 2: 那個 & 為什麼是正確性而不是效能 void inorder(vector<int> ans, ...) ← 少了 & 每一層拿到的是「自己的一份拷貝」 push_back 寫進拷貝 → 那一層 return 時拷貝一起消失 最外層的 ans 從頭到尾沒被寫過 實測:196/197 錯,最小反例 [1] → [] 唯一「對」的是空樹 [],因為答案本來就是空的 // 症狀極好認:任何非空樹都回空陣列。看到這個症狀,先去看簽名有沒有 &
// PHASE 3: 呼叫次數為什麼恆為 2n+1 一棵有 n 個節點的二元樹,有多少個「空指標」? 每個節點提供 2 個子指標 → 共 2n 個指標槽 其中 n-1 個被真實節點佔用(除了根,每個節點都被某個槽指到) 剩下 2n - (n-1) = n+1 個是 nullptr 所以 inorder() 的呼叫次數 = n(實節點) + (n+1)(nullptr) = 2n+1 實測:窮舉 n = 0..8 全部 2056 種樹形 每個 n 的呼叫次數 min == max == 2n+1 → 與樹的形狀完全無關 // n=100 → 201 次呼叫,不管樹長成什麼樣
// PHASE 4: 空間為什麼是 O(h) 而不是 O(n) 呼叫堆疊在任一瞬間,只裝著「從根到目前節點」那條路徑上的框 → 最深就是樹高 h(再加最底那層 nullptr) 實測 n = 100: 退化成鏈 → 最大深度 101,約 9.7 KB 完美平衡樹 → 樹高只有 7,深度 8 同樣 100 個節點,堆疊用量差了十幾倍 // 這就是為什麼樹題要問「會不會退化」——退化了,O(h) 就等於 O(n)
