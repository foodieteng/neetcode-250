完整實作// BFS

p102.cpp C++17 
class Solution {
public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        if (root == nullptr) {
            return {};
        }

        vector<vector<int>> ans;
        vector<int> level;
        queue<TreeNode*> q;
        q.push({root});

        while (!q.empty()) {
            auto sz = q.size();   // ← 凍結層寬,必須在推小孩之前
            level.clear();

            for (int _ = 0; _ < sz; _++) {
                auto u = q.front(); q.pop();
                level.push_back(u->val);

                if (u->left) {
                    q.push(u->left);
                }
                if (u->right) {
                    q.push(u->right);
                }
            }

            ans.push_back(level);
        }
        return ans;
    }
};

⚠ 那 512 種「碰巧對」的樹形基本上就是鏈 —— 因為每層只有一個節點,佇列從來不會在中途長大, i 永遠追得上那個「終點」。 所以拿斜鏈當回歸測試,這個 bug 完全隱形。 要抓它,測資必須有「某一層不只一個節點」的樹 —— 最小的就是 [1,2,3]。

看那兩欄的對比 —— BFS 和 DFS 的最壞情況完全相反。 完美樹上 DFS 只要 10 層而 BFS 佇列要裝 512 個(差 50 倍); 退化鏈上 BFS 佇列只要 1 個而 DFS 要 2000 層(差 2000 倍)。 所以「BFS 比較省記憶體」是錯的說法 —— 要看樹長什麼樣。
// 兩個實測細節 ① enqueued == dequeued == n,在「每一種形狀」上都成立 每個節點恰好進隊一次、出隊一次 ⇒ 時間 O(n),與樹形無關 ② 完全樹 n=2000:佇列峰值 1000,但「最大層寬」只有 977 峰值出現在「層的中途」—— 此時佇列裡同時裝著 「這一層還沒處理完的尾巴」+「已經推進去的下一層小孩」 ⇒ 所以空間界是 O(w),不是「剛好等於 w」 // 第 ② 點是實測才看得出來的細節,純推導很容易寫成「峰值 = 最大層寬」

// PHASE 1: 為什麼佇列裡會「混著兩層」 以官方範例走一遍(實測 trace): 外層第 1 輪: sz = 1 凍結 佇列 [3] 彈出 3,推入 9、20 佇列變成 [9,20] ← 已經是「下一層」了 但內層只跑 sz=1 次,結束 ans = [[3]] 外層第 2 輪: sz = 2 凍結 佇列 [9,20] i=0: 彈出 9(沒小孩) 佇列 [20] i=1: 彈出 20,推入 15、7 佇列 [15,7] ← 這一瞬間又是 2 個! 內層跑滿 sz=2 次,結束 ans = [[3],[9,20]] ★ 關鍵就在第 2 輪的 i=1: 推完之後 q.size() 又是 2,而 i 才剛到 1 ⇒ 如果條件寫成 i < q.size(),它會看到 1 < 2 而「繼續跑」 ⇒ 把 15 拖進 [9,20] 這一層 // 凍結的 sz 是唯一分隔「這一層的尾巴」和「下一層的頭」的東西
// PHASE 2: level 重用 —— 正確,而且省下不少配置 level 宣告在 while 外面、每輪 clear() —— 這樣對嗎? 正確性:clear() 在每次使用前都會執行,不可能殘留舊資料 實測:重用版 vs 每輪新宣告版,在 206918 組對拍語料上「逐位元相同」 效能(實測 heap 配置次數,只算 levelOrder 內部): 重用 + clear() 每輪新宣告 省下 完美樹 n=1023 29 74 45 退化鏈 n=1000 1016 2015 999 ← 幾乎每層省一次 原因:clear() 保留 capacity。重用的 level 容量成長 1→2→4→…→512 之後 「就再也不用重新配置了」;每輪新宣告則是每次都從 capacity 0 重來。 ⚠ 但注意 ans.push_back(level) 是「複製」,所以 ans 自己的 n 個元素照樣要配置 —— 重用只省下了「那個暫存 vector」的配置,上面的數字就是這個殘差。 想更快可以用 ans.push_back(std::move(level)),但那樣就必須把 level 移回迴圈內宣告(被 move 走的 vector 不該再 clear() 重用)。 // 高瘦的樹(層很多)獲益最大 —— 999 次 vs 45 次,差了 20 倍
// PHASE 3: auto sz(size_t)與 int _ 的有號/無號比較 auto sz = q.size(); → sz 的型別是 size_t(無號) for (int _ = 0; _ < sz; _++) → int 和 size_t 比較 -Wall -Wextra 實測「會」跳警告: warning: comparison of integers of different signs: 'int' and 'size_type' (aka 'unsigned long') [-Wsign-compare] 會不會真的出錯?約束內「不可能」: 比較時 int 會被提升成 unsigned long,只有 _ 是「負數」才會災難性 wrap 而 _ 從 0 開始遞增,要變負得先溢位過 INT_MAX ⇒ 需要「單一層超過 21 億個節點」,而題目上限是 2000 個 實測:n=2000 最寬的合法樹,佇列峰值 1000、最大層寬 977 —— 差了 200 萬倍 怎麼寫比較好: int sz = (int)q.size(); ← 一次轉換,之後都是 int 比 int 或 for (size_t _ = 0; _ < sz; _++) (對照 199 那題就是寫 int sz,-Wall -Wextra 下完全乾淨) // 「約束內安全」和「寫法乾淨」是兩件事 —— 面試時能講出前者才是重點
// PHASE 4: 這個骨架可以直接改成哪些題 四步驟骨架:推根 → while 不空 → 凍結 sz → 跑 sz 次(彈出、收錄、推小孩) 只要改「第 ④ 步收錄什麼」就變成另一題: 102 本題 收錄「整層」 ans.push_back(level) 199 右視圖 只收「最後一個」 if (i == sz-1) ans.push_back(u->val) 515 每層最大 收「這層的 max」 ans.push_back(*max_element(...)) 107 反向層序 收整層,最後整個 reverse 103 鋸齒層序 收整層,奇數層再 reverse 111 最小深度 第一個「葉節點」就 return 目前層數 ← 可以提早結束 ⇒ 骨架完全相同,差別只在那一行 // 學會這一題等於同時拿到後面一整排層序題的模板
