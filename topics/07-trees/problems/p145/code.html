完整實作// RECURSIVE

p145.cpp C++17 
class Solution {
public:
    vector<int> postorderTraversal(TreeNode* root) {
        vector<int> ans;
        postOrder(ans, root);
        return ans;
    }

    void postOrder(vector<int>& ans, TreeNode* root) {
        if (root == nullptr) return;   // 唯一的終止條件

        postOrder(ans, root->left);     // ① 整棵左子樹
        postOrder(ans, root->right);    // ② 整棵右子樹
        ans.push_back(root->val);     // ③ 兩邊都回來了,才輪到自己
    }
};

最值得記的一件事:「左右對調」和「reverse(preorder)」的巧合家族完全相同 —— 都是那 64 種「每個節點至多一個小孩」的鏈狀樹。 程式已逐棵驗證 reverse(preorder) == postorder ⟺ 該樹是鏈狀樹,零 mismatch。 換句話說,只要你的測資裡有一個節點同時有左右小孩,這兩個 bug 就會同時現形; 沒有的話,兩個都測不出來。

// PHASE 1: reverse(preorder) 到底錯在哪(用 [1,2,3] 拆給你看) 樹: 1 / \ 2 3 前序 (根→左→右) = [1, 2, 3] reverse(前序) = [3, 2, 1] ← 錯誤答案 真正的後序 (左→右→根) = [2, 3, 1] ← 正解 問題出在哪? reverse 會把「左在右前面」也一併反轉,變成「右在左前面」 但後序要的是「左仍然在右前面」,只有根被移到最後 正確的恆等式:先把走訪本身的左右對調,再 reverse —— 兩次反轉抵消 鏡像前序 (根→右→左) = [1, 3, 2] reverse(鏡像前序) = [2, 3, 1] ✓ 與真後序完全相同 實測:窮舉 n = 0..8 共 2056 棵樹,這條恆等式 2056/2056 成立,零反例 // [1,2,3] 是最小反例,也是「能區分三種走訪」的最小樹 —— 舉例時就用它
// PHASE 2: 顯式 stack 版怎麼寫(基於上面那條恆等式) vector<int> ans; if (root == nullptr) return ans; stack<TreeNode*> st; st.push(root); while (!st.empty()) { TreeNode* curr = st.top(); st.pop(); ans.push_back(curr->val); if (curr->left) st.push(curr->left); // 先放左 if (curr->right) st.push(curr->right); // 後放右 → 先被 pop } reverse(ans.begin(), ans.end()); // 最後整個反轉 注意 push 順序:前序版是「先右後左」,這裡是「先左後右」—— 剛好相反 因為我們要走的是「根→右→左」,所以右邊要先被 pop,就得後放 // 這是後序迭代版最好寫的一種;不用 reverse 的版本要額外記「上次訪問的節點」,麻煩得多
// PHASE 3: 為什麼後序是「釋放記憶體」的唯一正確順序 錯的寫法(前序): delete root; // 先把自己刪了 freeTree(root->left); // ← root 已經是懸空指標,存取 UB freeTree(root->right); 對的寫法(後序): freeTree(root->left); // 先把兩棵子樹整個釋放 freeTree(root->right); delete root; // 最後才刪自己 —— 此時沒有人還需要它 同樣的道理適用於: 算子樹大小 size(root) = 1 + size(左) + size(右) 算樹高 height(root) = 1 + max(height(左), height(右)) ← LC104 判斷是否平衡 需要先知道左右高度 ← LC110 算最大路徑和 需要先知道左右各能貢獻多少 ← LC124 // 共同點:自己的答案「依賴」子樹的答案 ⇒ 子樹必須先算完 ⇒ 後序
// PHASE 4: 「根在最後」的實測驗證 窮舉 n = 1..8 全部 2055 棵非空樹: 後序 ans.back() == root->val → 2055 / 2055 (100%) 後序 ans.front() == root->val → 1 / 2055 (只有單節點樹) 對照組(前序): 前序 ans.front() == root->val → 2055 / 2055 (100%) 前序 ans.back() == root->val → 1 / 2055 結論:根的位置是「順序專屬」的簽名,不是巧合 前序 → 根在最前 後序 → 根在最後 中序 → 根在「左子樹節點數」那一格 // 拿到一串輸出想判斷是哪種走訪?先看根在頭還是在尾
