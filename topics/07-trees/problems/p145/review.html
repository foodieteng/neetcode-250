// ANSWERS
A1. 不對。最小反例是 [1,2,3]。

對 [1,2,3](根 1,左 2,右 3):
· 前序 = [1,2,3] → reverse 得 [3,2,1]
· 真正的後序 = [2,3,1] ← 不一樣

錯在哪:reverse 會把「左在右前面」這個關係也一併反轉,變成「右在左前面」。但後序要的是 左 → 右 → 根 —— 只有根被移到最後,左右的相對順序不變。

正確的恆等式:
postorder = reverse(根 → 右 → 左 的走訪)
也就是先把走訪本身的左右對調,再整個反轉 —— 兩次反轉剛好抵消,左右就回到正確順序了。驗證:鏡像前序 [1,3,2] → reverse → [2,3,1] ✓。

實測:窮舉 n = 0..8 共 2056 棵樹,這條正確恆等式 2056/2056 成立,零反例;而錯誤的 reverse(preorder) 只在 64/197 種樹形上碰巧對(n ≤ 6)。

這條恆等式不只是冷知識 —— 它正是後序迭代版最好寫的那個實作的基礎。
A2. 第一個必是某個葉節點;最後一個必是根。

最後一個 = 根:push_back 是函式體的最後一個動作,最外層那次呼叫最晚結束,所以根必定最後被推進去。實測:窮舉 n = 1..8 全部 2055 棵樹,ans.back() == root->val 命中 2055/2055;而 ans.front() == root->val 只中 1/2055(單節點樹)。

第一個 = 某個葉節點:能被最先收錄的節點,必須不用等任何人 —— 也就是左右兩次遞迴都立刻 return,那正是葉節點的定義。(具體是哪一個葉節點?是「一路往左優先走到底」碰到的第一片葉子。)

三種走訪的根位置,一起記:
· 前序 → 根在最前(實測 2055/2055)
· 後序 → 根在最後(實測 2055/2055)
· 中序 → 根在「左子樹節點數」那一格

拿到一串輸出想判斷它是哪種走訪?先看根在頭還是在尾。
A3. 因為 delete 之後那個指標就懸空了,你再也不能透過它找到子節點。

錯的寫法(前序順序):
delete root;                 // ① 先把自己刪了
freeTree(root->left);        // ② root 已懸空,讀 root->left 是 UB
freeTree(root->right);
具體會發生什麼:第 ② 行在存取已釋放的記憶體(use-after-free)。它不一定當場崩潰 —— 那塊記憶體可能還沒被覆蓋,於是讀到看似正常的指標值,程式「好像」跑得過去。這比直接崩潰更糟:它是不可重現的隨機錯誤,而且在 ASan 之外很難抓。就算沒讀壞,兩棵子樹也永遠沒被釋放 = 記憶體洩漏。

對的寫法(後序順序):
freeTree(root->left);        // ① 先把左子樹整棵釋放
freeTree(root->right);       // ② 再把右子樹整棵釋放
delete root;                 // ③ 最後才刪自己 —— 此時沒有人還需要它
一般原則:「要用到某個資源的操作,必須排在釋放它之前」。子樹的位址只能透過 root 取得,所以 delete root 必須是最後一步 —— 這就是後序。

順帶一提,如果用 unique_ptr 或 shared_ptr 管理子節點,解構子會自動按後序釋放(先解構成員,再解構自己)—— C++ 的物件生命週期本身就是後序的。
A4. 難在「右子樹到底回來了沒」這個判斷。

比較三者在迭代版裡各要回答什麼問題:
· 前序 —— 什麼都不用問。pop 出來就直接輸出,四行搞定。
· 中序 —— 要問「左子樹做完了沒」。技巧:一路往左壓到底,pop 出來就代表左邊做完了。
· 後序 —— 要問「左右兩棵都做完了沒」。麻煩之處在於:一個節點會被「碰到」兩次 —— 第一次是要下去右子樹,第二次才是輪到自己。光靠「它在 stack 頂端」分不出這是第幾次。

所以後序需要額外狀態。兩種標準解法:
① 記一個 lastVisited 指標 —— peek 到某節點時,檢查「它的右子樹是空的,或者剛剛訪問完的就是它的右子樹」;成立才輪到它。
② 走「根→右→左」再整個 reverse(見 程式碼頁)—— 用一次反轉換掉那個狀態,程式碼短得多,代價是多一次 O(n) 的反轉和一個「先存起來再倒過來」的中介陣列。

面試時給法 ②,並主動說「還有一種不用 reverse 的寫法,要多記一個 lastVisited」 —— 這樣既簡潔又展示你知道取捨在哪。

一般規律:走訪的迭代版有多複雜,取決於那個順序需要「等」多久。前序不等、中序等一邊、後序等兩邊 —— 難度剛好照這個順序排。
A5. 是「每個節點至多一個小孩」的鏈狀樹;而且這兩個 bug 的巧合家族完全相同。

實測:窮舉 n = 0..6 共 197 種樹形 ——
· 左右對調 → 錯 133、對 64
· 誤用 reverse(preorder) → 錯 133、對 64
而且程式已逐棵驗證:兩者的「通過集合」是同一個集合,零 mismatch。

這 64 種是什麼?分佈是 1,1,2,4,8,16,32,即 n ≥ 1 時的 2ⁿ⁻¹。特徵是每個節點至多只有一個小孩 —— 也就是鏈狀樹(不只純左鏈、純右鏈,任何左右轉彎的單子鏈都算)。

為什麼兩個 bug 剛好同一族:兩者的病根其實是同一個 —— 都是把左右的相對順序搞反了。而「左右順序」這件事,只有在某個節點同時擁有左右小孩時才觀察得到。鏈狀樹上每個節點總有一邊是空的,先走空的還是先走非空的,結果一模一樣 —— 所以兩個 bug 同時隱形。

最小反例是 [1,2,3](根同時有左右小孩):正解 [2,3,1],兩個 bug 都給 [3,2,1]。

測資鐵則:一定要有「同時擁有左右小孩」的節點。[1,2,3] 就是最小的那個,而且它同時能區分前中後三種走訪([1,2,3] / [2,1,3] / [2,3,1])—— 這一題手上有一個 [1,2,3] 就夠了。
App 1. 差在第三行:把 push_back 換成 return 1 + max(左, 右)。

int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;          // 空樹深度 0

    return 1 + max(maxDepth(root->left),    // ① 左子樹的深度
                   maxDepth(root->right));  // ② 右子樹的深度
                                            // ③ 自己這一層 +1
}
骨架完全一樣:nullptr 當底 → 先做左 → 再做右 → 最後處理自己。差別只在「處理自己」那一步做什麼:本題是 push_back,104 是 1 + max(...)。

關鍵直覺:值是從葉子「往上傳」的。下潛的路上什麼都沒算,每個數字都誕生於某次 return 0(碰到 nullptr),然後每經過一層 +1。所以葉節點回傳 1、它的父節點回傳 2、依此類推。

常見錯誤(實測窮舉 n = 0..7 共 626 種樹形):
· 忘了 +1 → 錯 625/626,最小反例 [1] 回 0
· base case 回傳 1 而非 0 → 錯 626/626,而且是恆定 +1 的偏移(626 種樹形的誤差集合只有 {1} 這一個值)
· max 寫成 min → 錯 622/626;而且它算的也不是最小深度(LeetCode 111)—— 真正的 minDepth 必須走到葉節點,而 1+min 會被「不存在的空子樹」吃掉。最小反例 [1,null,2]:1+min 給 1,但真 minDepth 是 2。
· max 誤寫成加法 1 + 左 + 右 → 這其實是在數節點總數(實測 626/626 與節點數完全相符),也就是寫成了 LeetCode 222。
App 2. 讓遞迴同時回傳「高度」和「是否平衡」—— 一次走訪、O(n)。

成本較高的「由上往下」做法:對每個節點呼叫一次 height() 來比較左右。這樣每個節點會被重複走訪 —— 深度 d 的節點被走 d+1 次(每個祖先各走它一次)。

但它到底多慢,值得實測而不是套公式。實測(見 110 那一頁):真正的瓶頸不是退化鏈 —— 鏡在根節點就因為左右高度差過大而短路結束,實測呼叫次數只有 2n,是線性的。真正被完整走完的是平衡樹,而平衡樹的 h = O(log n),所以實際上限是 O(n log n),不是 O(n²)。實測完美樹 n=4095 的額外成本是 11 倍。

正確做法:借用後序「值往上傳」的特性,一趟解決。技巧是用回傳值兼作旗標 —— 回傳高度,但一旦發現不平衡就回傳 -1,並讓 -1 一路往上傳:
int check(TreeNode* root) {
    if (root == nullptr) return 0;

    int left = check(root->left);
    if (left == -1) return -1;              // 左邊已經壞了,直接往上傳

    int right = check(root->right);
    if (right == -1) return -1;

    if (abs(left - right) > 1) return -1;   // 這一層不平衡

    return 1 + max(left, right);            // 平衡,回傳高度
}
// isBalanced(root) 就是 check(root) != -1
為什麼是 O(n):每個節點只被進入一次,高度是「順便」在回程算出來的,沒有任何重複計算。而且 -1 的早退還讓它可以提早結束。

「用一個不可能的回傳值兼作失敗旗標」是這類題目很常見的手法(高度不可能是負的,所以 -1 安全)。更一般的做法是回傳一個 pair 或小 struct,可讀性更好、也不依賴「有個不可能的值」這個巧合 —— 面試時兩種都可以,但要能說出為什麼 -1 是安全的。
App 3. 要多記一個 lastVisited「上一個被輸出的節點」。

vector<int> ans;
stack<TreeNode*> st;
TreeNode* curr = root;
TreeNode* lastVisited = nullptr;

while (curr != nullptr || !st.empty()) {
    while (curr != nullptr) {          // ① 一路往左壓到底
        st.push(curr);
        curr = curr->left;
    }

    TreeNode* peek = st.top();         // ② 只看,先不 pop

    if (peek->right != nullptr && lastVisited != peek->right) {
        curr = peek->right;            // ③ 右邊還沒做 → 轉過去
    } else {
        ans.push_back(peek->val);      // ④ 兩邊都完成 → 輪到它
        lastVisited = peek;
        st.pop();
    }
}
核心是第 ② 步用 top() 而不是 pop() —— 因為一個節點會被碰到兩次:第一次要下去右子樹(不能 pop,等一下還要回來),第二次才輪到它自己。

lastVisited 就是用來分辨這兩次的。條件 lastVisited != peek->right 的意思是「我剛剛輸出的不是它的右小孩,代表右邊還沒做完」。如果剛輸出的正是它的右小孩,就表示右子樹整棵完成了 —— 這是因為右子樹的最後一個輸出必定是右子樹的根(又是「根在最後」這個性質)。

對照 reverse 版(見程式碼頁):那個版本只有 8 行,不需要 lastVisited,代價是最後多一次 O(n) 反轉。兩者複雜度相同(時間 O(n)、空間 O(h)),差別純粹是「多一個狀態變數」還是「多一次反轉」。

面試建議:先寫 reverse 版(不容易錯),再說明這個 lastVisited 版存在且不需要額外的輸出緩衝。
