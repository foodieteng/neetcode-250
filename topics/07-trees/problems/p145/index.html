題目簡介// THE QUESTION

QUESTION

給二元樹的根節點 root,回傳它的後序走訪結果。 節點數 0 ~ 100,節點值 −100 ~ 100。

三連題的最後一題。和 94 中序、144 前序 一樣的程式碼,push_back 這次放到兩個遞迴之後。

後序是三種裡等最久的:每個節點都要等左右兩棵子樹整個做完才輪到自己。 所以根一定排在最後 —— 而這正是它最有用的地方。 「先處理完所有子節點,再處理自己」正是釋放記憶體、計算子樹聚合值、 算檔案夾大小的唯一正確順序。

後序為什麼重要// WHY IT MATTERS

A 「後序 = 把前序反過來」 錯得很普遍
這是這題最常見的錯誤信念。實測窮舉 197 種樹形, reverse(preorder) 等於 postorder 的只有 64 種, 錯 133 種,最小反例 [1,2,3]。

B 用顯式 stack 硬寫後序 三者中最難
後序的迭代版是三種走訪裡最麻煩的 —— 因為要判斷「右子樹回來了沒」,得額外記一個「上次訪問的節點」。 面試時先寫遞迴,被追問再談它。

核心策略 · 三步驟// THE SHAPE

  1. 終止:if (root == nullptr) return; —— 和另外兩題完全一樣。
  2. 先左、再右:postOrder(ans, root->left); 然後 postOrder(ans, root->right); —— 兩棵子樹都要整個做完。
  3. 最後才是根:ans.push_back(root->val); —— 只有在兩個遞迴都回來之後,才輪到自己。
後序輸出的第一個元素一定是某個葉節點 —— 因為只有葉節點不必等任何人(它的左右都是 nullptr,兩層立刻 return)。 對稱地,最後一個一定是根。

兩個會被追問的「為什麼」// TWO LEMMAS

LEMMA 1 · 為什麼 postorder ≠ reverse(preorder)

前序是 根 → 左 → 右。把它整個反轉,得到的是 右' → 左' → 根 —— 注意左右的相對順序也被反轉了,變成「先右後左」。 但後序要的是 左 → 右 → 根,左仍然在右前面。

正確的恆等式是 postorder = reverse(根 → 右 → 左) —— 先把走訪本身的左右對調,再反轉,兩次反轉就抵消回來了。 實測:reverse(preorder) 只在 64/197 種樹形上碰巧正確, 最小反例 [1,2,3]:reverse(preorder) = [3,2,1], 但真正的後序是 [2,3,1]。

LEMMA 2 · 為什麼「根在最後」讓後序不可取代

實測:窮舉 n = 1..8 全部 2055 棵樹, ans.back() == root->val 命中 2055/2055; 而 ans.front() == root->val 只中 1/2055(單節點樹)。

這不只是個性質,它是一整類問題唯一正確的順序: 釋放樹的記憶體(先 delete 子節點再 delete 自己,順序反了就會存取已釋放的指標)、 算子樹大小 / 高度 / 總和(自己的答案依賴子樹的答案)、 算資料夾佔用空間。 凡是「自己的結果要靠子樹的結果算出來」的題目,骨架都是後序。 07 章後面的 104、110、124、543 全都是這個模式。

// 九種改法的實測結果(窮舉 n = 0..6,共 197 種樹形) push_back 移到最前面(變前序) → 錯 195/197,最小反例 [1,null,2] → [1,2](正解 [2,1]) push_back 移到中間(變中序) → 錯 190/197,最小反例 [1,null,2] → [1,2](正解 [2,1]) 左右對調(鏡像後序) → 錯 133/197,最小反例 [1,2,3] → [3,2,1](正解 [2,3,1]) 誤用 reverse(preorder) → 錯 133/197,最小反例 [1,2,3] → [3,2,1](正解 [2,3,1]) 漏掉 nullptr 檢查 → 錯 197/197,連 [] 都 SIGSEGV ans 傳值而非傳參考 → 錯 196/197,最小反例 [1] → [] 忘了遞迴右子樹 → 錯 190/197,最小反例 [1,null,2] → [1] helper 開頭 ans.clear() → 錯 190/197,最小反例 [1,2] → [1] base case 誤寫成葉節點判斷 → 錯 197/197,[] 就 SIGSEGV,[1] 回 [] // 「左右對調」與「reverse(preorder)」的巧合家族完全相同 —— 都是 64 種鏈狀樹

一句洞察// INSIGHT

後序 = 「先把兩棵子樹的事辦完,再辦自己的」。 所以它是釋放記憶體和由下往上聚合唯一正確的順序 —— 凡是「自己的答案要靠子樹的答案算出來」的題目(104 求深度、110 判平衡、543 求直徑、124 最大路徑和), 骨架全都是後序。學會這一題,等於拿到後面一整排題目的模板。
