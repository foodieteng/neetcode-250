完整實作// RECURSIVE

p144.cpp C++17 
class Solution {
public:
    vector<int> preorderTraversal(TreeNode* root) {
        vector<int> ans;
        preorder(ans, root);
        return ans;
    }

    void preorder(vector<int>& ans, TreeNode* root) {
        if (root == nullptr) return;   // 唯一的終止條件

        ans.push_back(root->val);     // ① 根:走到就收錄,不等任何人
        preorder(ans, root->left);      // ② 整棵左子樹
        preorder(ans, root->right);     // ③ 整棵右子樹
    }
};

// 對拍(遞迴版 vs 獨立寫的顯式 std::stack 版) 參考解:push root;迴圈 pop、輸出 val、先 push right 再 push left(先進後出 ⇒ 左邊先被處理) 測資:n = 0..12 隨機樹形(全隨機 / 純左鏈 / 純右鏈 / 偏深斜樹),值域 ±100,共 200000 組 輸出不一致 : 0 官方範例: [1,null,2,3] → [1,2,3] ✓ [] → [] ✓ 不必特判空樹 [1] → [1] ✓ [1,2,3,4,5,null,8,null,null,6,7,9] → [1,2,4,5,6,7,3,8,9] ✓ [1,2,null,3,null,4,null,5](左斜鏈) → [1,2,3,4,5] ✓ [1,null,2,null,3,null,4,null,5](右斜) → [1,2,3,4,5] ✓ // 注意最後兩列:左斜鏈和右斜鏈的前序輸出「完全相同」——前序看不出樹往哪邊斜
上面那個 std::stack 參考解值得記:先 push right 再 push left。 因為 stack 是後進先出,後 push 的 left 會先被 pop —— 要讓左邊先處理,就得把它後放。這個「順序反過來」的細節是迭代版最常寫錯的地方。

邊界與陷阱// PITFALLS

窮舉 n = 0..6 全部 197 種樹形實跑。 節點值以 level-order 指派 1..n,確保前序輸出是非平凡的排列(否則變體會被藏起來)。

陷阱失敗數最小反例怎麼修
漏掉 nullptr 檢查 197/197 [] → SIGSEGV 連空樹都當場崩,沒有任何輸入能活著跑完

helper 開頭 ans.clear() 196/197 [1] → [] 最後一次呼叫必定發生在某個 null 葉子上,結果永遠被清成空
push_back 移到中間(變中序) 190/197 [1,2] → [2,1] 但純右鏈上會碰巧全對 —— 見下方說明

「左右對調」為什麼巧合率高達 32.5%? 因為它在所有「鏈狀樹」上都碰巧正確 —— 不只純左鏈、純右鏈, 而是任何「每個節點至多一個小孩」的樹(包括左右轉彎的,例如 [1,null,2,3])。 實測這一族有 64 種(n ≥ 1 時是 2ⁿ⁻¹)。 只要沒有任何節點同時有左右小孩,交換遞迴順序就看不出差別。

// PHASE 1: 「三段連續」到底是什麼意思 以本頁的範例樹為例(root 1,左子樹掛 2,右子樹掛 3): 前序輸出 = [1, 2,4,5,6,7, 3,8,9] └┬┘ └───┬───┘ └──┬──┘ 根 整棵左子樹 整棵右子樹 三段「連續」的意思是:左子樹的 5 個節點是「一整塊」排在一起的, 中間不會插進任何右子樹的節點。中序就不是這樣 —— 根被夾在中間。 這正是 LC105「用前序+中序重建二元樹」的機制: 前序的第一個 = 根 → 1 去中序裡找 1 的位置 → 它左邊有 5 個,右邊有 3 個 → 前序的接下來 5 個就是左子樹、再接下來 3 個就是右子樹 → 遞迴 // 沒有「三段連續」這個性質,這個切法就不成立
// PHASE 2: 為什麼 base case 不能寫成葉節點判斷 寫成 if (root->left == nullptr && root->right == nullptr) return; 實測 197 種樹形「全錯」,而且是兩種病一起犯: 病一(崩潰):root->left 這個動作本身就要求 root 非空 [] 直接爆;任何「只有單邊子樹」的節點也爆 例如 [1,2] 和 [1,null,2] 都 SIGSEGV 病二(漏收):就算形狀剛好躲過崩潰(完美二元樹), 葉節點在 push_back 之前就 return 了 [1,2,3] → 只回 [1],兩個葉子被吞掉 寫成 root == nullptr 則兩件事一起解決: 葉節點的左右各進去一層、各自立刻 return,葉節點本身照樣被 push // 用 nullptr 當底,葉節點就完全不需要特殊待遇 —— 少一個分支,少一個 bug
// PHASE 3: 「巧合一致」的三個家族(實測,n ≤ 6 共 197 種) 把 push_back 移到中間(前序寫成中序): 巧合正確 7 種 —— 每個 n 恰好 1 種,全部是「純右鏈」 原因:左子樹恆空 ⇒ inorder 的「先 left」是 no-op ⇒ 退化成前序 把 push_back 移到最後(前序寫成後序): 巧合正確 2 種 —— 只有 [] 和 [1] 原因:後序的最後一個必是 root,前序的第一個必是 root 兩者只有在 ≤ 1 個節點時才相容 左右對調(鏡像前序): 巧合正確 64 種 —— 分佈 1,1,2,4,8,16,32,即 n ≥ 1 時為 2^(n-1) 家族:所有「每個節點至多一個小孩」的鏈狀樹(含左右轉彎的) 這是三者中巧合率最高的(32.5%),弱測資最容易放過 // 結論:測資一定要含有「同時擁有左右小孩」的節點,最小的是 [1,2,3]
// PHASE 4: 為什麼呼叫次數與樹形完全無關 一棵 n 個節點的二元樹,有多少個 nullptr? 每個節點提供 2 個子指標 → 2n 個槽 其中 n-1 個被真實節點佔用 → (除了根,每個節點都被某個槽指到) 剩下 2n - (n-1) = n+1 個是 nullptr 呼叫次數 = n(實節點) + (n+1)(nullptr) = 2n+1 實測:窮舉 n = 0..8 全部 2056 種樹形 每個 n 的呼叫次數 min == max,值恰為 2n+1 1 → 3、5 → 11、100 → 201 // 「空指標的數量恆為 n+1」是二元樹一個很好用的恆等式
