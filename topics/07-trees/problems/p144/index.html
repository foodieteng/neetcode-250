題目簡介// THE QUESTION

QUESTION

給二元樹的根節點 root,回傳它的前序走訪結果。 節點數 0 ~ 100,節點值 −100 ~ 100。

這是三連題的第二題。程式碼和 94 中序 只差 push_back 那一行的位置 —— 從兩個遞迴中間移到最前面,就從中序變成前序。

前序的特別之處:「走到」和「收錄」是同一個時刻。 節點一進來就被 push_back,不必等任何子樹 —— 中序要等左邊、後序要等兩邊,只有前序不用等。 所以前序輸出的第一個元素,永遠是樹根。

3

核心策略 · 三步驟// THE SHAPE

  1. 終止:if (root == nullptr) return; —— 空樹什麼都不做。 葉節點不需要另外判斷,它的左右各進去一層、各自 return 就好。
  2. 先根:ans.push_back(root->val); —— 一進來就收錄,不等任何人。
  3. 再左、後右:preorder(ans, root->left); 然後 preorder(ans, root->right);。整棵左子樹會完整地排在整棵右子樹前面。
和中序比,只有第 ② 和 ③ 的順序對調。 但這個小動作改變了整個輸出的結構:中序是「左、根、右」交錯, 前序是「根、左、右」三段連續。

兩個會被追問的「為什麼」// TWO LEMMAS

LEMMA 1 · 為什麼前序的第一個元素一定是根

push_back 是函式體的第一個動作(nullptr 檢查之後)。 最外層那次呼叫傳進來的就是 root,所以它一定第一個被推進去, 之後才輪到任何子樹的節點。

實測:窮舉 n = 1..8 全部 2055 棵樹, ans.front() == root->val 命中 2055/2055。 作為對照,ans.back() == root->val 只命中 1/2055(那唯一一棵是單節點樹)。 「根在最前面」是前序獨有的簽名,「根在最後面」則是後序的。

LEMMA 2 · 為什麼斜鏈測資抓不出「前序寫成中序」

純右鏈上每個節點的左子樹都是空的。 中序的第一行 inorder(root->left) 變成 no-op, 於是「左 → 根 → 右」退化成「根 → 右」 —— 那正是前序。

實測:窮舉 n ≤ 8 的 2056 種樹形, 前序輸出等於中序輸出的每個 n 恰好 1 種,而且100% 都是純右鏈,無一例外。 能區分三種走訪的最小樹是 [1,2,3]: 前序 [1,2,3]、中序 [2,1,3]、後序 [2,3,1] —— 三個都不同。

// 八種改法的實測結果(窮舉 n = 0..6,共 197 種樹形) push_back 移到中間(變中序) → 錯 190/197,最小反例 [1,2] → [2,1](正解 [1,2]) push_back 移到最後(變後序) → 錯 195/197,最小反例 [1,null,2] → [2,1](正解 [1,2]) 左右對調(鏡像前序) → 錯 133/197,最小反例 [1,2,3] → [1,3,2](正解 [1,2,3]) 漏掉 nullptr 檢查 → 錯 197/197,連 [] 都 SIGSEGV ans 傳值而非傳參考 → 錯 196/197,最小反例 [1] → [] 忘了遞迴右子樹 → 錯 190/197,最小反例 [1,null,2] → [1] helper 開頭 ans.clear() → 錯 196/197,最小反例 [1] → [] base case 誤寫成葉節點判斷 → 錯 197/197,[] 就 SIGSEGV,[1] 回 [] // 左右對調只錯 133/197 —— 巧合率 32.5%,是最容易矇混過關的一種

一句洞察// INSIGHT

前序是三種走訪裡唯一「不用等」的 —— 走到就收錄。 因此它的輸出永遠是 [根 | 左子樹 | 右子樹] 三段連續, 而第一個元素恆為根。 「第一個是根」+「三段連續」這兩件事合起來,就是重建二元樹(105)與序列化(297)的地基。
