A naive approach would be to DFS every path within k+1 edges. That's exponential — too slow.

My next thought is plain Dijkstra by price. But that's wrong here. Dijkstra locks in a node the first time it's settled, so it would grab the 300 path and ignore the stop limit. The cheapest path and the legal path are different things.

This problem reminds me of Bellman-Ford. Its whole idea is relaxing edges in rounds, and one round adds at most one edge to every path. So if I run exactly k+1 rounds, I cover all paths of at most k+1 edges — exactly the stop limit.

Here's the plan.

// state
dist[v] = cheapest price to v found so far  (∞ at start, 0 at src)

// each round (run k+1 of them)
temp = copy of dist          // freeze this round's source
for each edge (u, v, w):
    if temp[u] + w < dist[v]:
        dist[v] = temp[u] + w   // read temp, not dist

// invariant
after round r, dist[v] = cheapest price to v
using at most r edges

One: a dist array of the cheapest price so far — ∞, except 0 at src.
Two: run k+1 rounds; each round copies dist into a frozen temp, then relaxes every flight reading from temp.
Three: return dist[dst], or -1 if it's still ∞.

One thing worth flagging: the temp = dist copy is a correctness requirement, not a style choice. If I read the live dist, then 0→1 updates dist[1], and in the very same round, 1→2 reads that fresh value and chains a second edge. One round would sneak in two edges, and I'd overshoot the stop limit.

There's a trade-off here — the copy costs O(V) per round. That's fine; it's small next to the edge scan. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up, Bellman-Ford first: k+1 rounds, each freezing dist into temp, then relaxing every flight from temp only.

class Solution {
public:
    int findCheapestPrice(int n, vector<vector<int>>& flights,
                          int src, int dst, int k) {
        const int INF = INT_MAX;
        vector<int> dist(n, INF);
        dist[src] = 0;

        // run k+1 rounds: each round allows one more edge ⇒ at most k stops
        for (int round = 0; round < k + 1; round++) {
            vector<int> temp = dist;          // freeze this round's starting state
            for (auto& f : flights) {
                int u = f[0], v = f[1], w = f[2];
                if (temp[u] != INF && temp[u] + w < dist[v])
                    dist[v] = temp[u] + w;     // read temp only, never this round's fresh dist
            }
        }
        return dist[dst] == INF ? -1 : dist[dst];
    }
};

One thing worth flagging: the guard temp[u] != INF before adding. For a city that's still unreachable, temp[u] is INT_MAX, and INT_MAX + w overflows to a negative number — which would look cheaper and poison the answer.

The same idea works as a level-order BFS, where each layer is one stop:

int findCheapestPrice(int n, vector<vector<int>>& flights,
                      int src, int dst, int k) {
    vector<vector<pair<int,int>>> adj(n);
    for (auto& f : flights)
        adj[f[0]].push_back({f[1], f[2]});

    vector<int> dist(n, INT_MAX);
    dist[src] = 0;
    queue<pair<int,int>> q;        // {node, cost}
    q.push({src, 0});

    int stops = 0;
    while (!q.empty() && stops <= k) {   // run k+1 layers
        int sz = q.size();            // node count of this layer (snapshot)
        while (sz--) {
            auto [node, cost] = q.front(); q.pop();
            for (auto& [nei, price] : adj[node])
                if (cost + price < dist[nei]) {
                    dist[nei] = cost + price;
                    q.push({nei, dist[nei]});
                }
        }
        ++stops;
    }
    return dist[dst] == INT_MAX ? -1 : dist[dst];
}

Saving the queue size, int sz = q.size();, at the top of each layer is the same freeze trick as temp = dist: nodes I push now belong to the next layer. One layer, one edge.

CANDIDATE

The time complexity is O(k · E) — k+1 rounds, each scanning all E edges.

The space complexity is O(V) — the dist and temp arrays. The BFS version uses a queue, at most O(E).

In the worst-case scenario, E ≈ V² and k ≈ V, so about O(V³). With n ≤ 100 that's around 106 — instant.

Oh, one more thing — if the question changed to "exactly k stops" instead of "at most", I'd split dist into a 2D table indexed by edge count, and read the row for k+1 edges, dp[k+1][dst], without taking the min over fewer edges. This code is really that table rolled into one row.
