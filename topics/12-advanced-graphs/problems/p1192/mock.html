Hmm, let me think about this for a sec.

A naive approach would be to remove each edge, then run a BFS to see if the graph is still connected. That's O(E) removals times O(V + E) per check — far too slow at 105 edges.

This problem reminds me of Tarjan's bridge-finding. One DFS. I give each node a discovery time dfn, and a value low — the earliest dfn the node's subtree can climb back to using one back edge. A tree edge (u, v) is a bridge exactly when low[v] > dfn[u]: the subtree under v cannot reach u or anything above it, so that edge is its only way out.

Here's the plan.

// dfn = discovery time, low = earliest dfn reachable
dfs(p, u):
  dfn[u] = low[u] = timer++
  for v in graph[u], skip v == p:
    tree edge → dfs(u, v); low[u] = min(low[u], low[v])
      if low[v] > dfn[u]: (u, v) is a bridge
    back edge → low[u] = min(low[u], dfn[v])

One: on visiting u, set both dfn and low to the next timer value.
Two: for a tree edge, recurse, take the min with the child's low, and if low[v] > dfn[u], record a bridge.
Three: for a back edge, take the min with dfn[v].

One thing worth flagging — a back edge updates low with the neighbor's dfn, not its low, since it only proves I can reach that node. And the test is strict >: if low[v] == dfn[u], the subtree can still climb back to u, so it's not a bridge.

Also, I skip the parent by node, v == p. That's only safe because there are no parallel edges; otherwise I'd skip by edge id. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. I build the adjacency list, set dfn and low to -1 for unvisited, and start a DFS from every unvisited node.

class Solution {
public:
    vector<vector<int>> graph;
    vector<int> dfn, low;          // dfn = discovery time; low = earliest dfn reachable
    int timer = 0;

    vector<vector<int>> criticalConnections(int n, vector<vector<int>>& connections) {
        graph.assign(n, {});
        dfn.assign(n, -1);              // -1 = unvisited
        low.assign(n, -1);

        for (auto& e : connections) {
            graph[e[0]].push_back(e[1]);
            graph[e[1]].push_back(e[0]);
        }

        vector<vector<int>> ans;
        for (int i = 0; i < n; i++)
            if (dfn[i] == -1) dfs(-1, i, ans);  // start a DFS in every unvisited piece

        return ans;
    }

    void dfs(int p, int u, vector<vector<int>>& ans) {
        dfn[u] = low[u] = timer++;       // discover u: timestamp, low starts at itself
        for (int v : graph[u]) {
            if (v == p) continue;            // skip parent (safe: no parallel edges)
            if (dfn[v] == -1) {            // tree edge: v is new
                dfs(u, v, ans);
                low[u] = min(low[u], low[v]);  // inherit the subtree's earliest reach
                if (low[v] > dfn[u]) ans.push_back({u, v});  // can't escape → bridge!
            } else {                        // back edge: v is a visited ancestor
                low[u] = min(low[u], dfn[v]);  // use dfn[v], not low[v]
            }
        }
    }
};

Inside dfs, a tree edge recurses, pulls the child's low into mine, then tests low[v] > dfn[u]; a back edge only uses dfn[v]. That matches the plan.

One thing worth flagging — the root passes p = -1. Since node ids run 0..n-1, that never equals a real neighbor, so the root's skip is a harmless no-op.

Corner cases:

• A straight chain 0-1-2-3 → every edge is a bridge.
• A single cycle → no bridges.
• The outer loop over unvisited nodes covers the graph even if it came in as more than one piece.

The time complexity is O(V + E) — one DFS touches every node and every edge once. The space complexity is O(V + E), for the adjacency list, the two arrays, and the recursion stack. In the worst case a long chain makes the recursion depth O(V), so on a very deep graph I might switch to an explicit stack.

Oh, one more thing — if the problem later allowed repeated connections, I'd move from the parent-node skip to an edge-id skip, and everything else stays the same.
