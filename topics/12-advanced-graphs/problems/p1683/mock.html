Hmm, let me think about this for a sec.

A naive approach would be to test mutual reachability for every pair — a BFS from each planet is O(n·(n+m)). With n up to 105, that's far too slow.

This problem reminds me of Kosaraju's algorithm — strongly connected components in two linear DFS passes. The first pass on the original graph records a finish order. Then I process nodes in reverse finish order on the reversed graph; each DFS tree there is exactly one component.

CANDIDATE

Here's the plan.

// two passes, build reverse graph alongside
1. dfs1 on G: push a node to order after all its descendants finish
2. reverse(order) → latest-finished comes first
3. dfs2 on reverse graph, in that order → one label per SCC

One: DFS the original graph, pushing a node to order after all its descendants finish.
Two: reverse order, so the latest-finished node comes first.
Three: DFS the reversed graph in that order, one label per component.

One thing worth flagging — why the reversed graph is essential. The latest-finished node sits in a source component. On the original graph a source can reach several components downstream, so one DFS would merge them. Reversing every edge turns that source into a sink — from it you can only reach its own component, so one DFS traps exactly one.

Also, the order matters for correctness, not just speed. Reverse finish order guarantees I always start from the current graph's source; peel it off, and the next unlabeled node is the next source. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. dfs1 walks the original graph and pushes a planet onto order only after all its descendants finish. dfs2 walks the reversed graph and stamps every planet it reaches with kingdom k. main reads the teleporters, runs pass one from every unvisited planet, reverses order, then starts pass two from each unlabeled planet with a fresh k.

#include <bits/stdc++.h>
using namespace std;

void dfs1(int u, vector<vector<int>>& g, vector<int>& order, vector<int>& visit) {
    visit[u] = 1;
    for (int v : g[u])
        if (!visit[v]) dfs1(v, g, order, visit);   // DFS on the original graph
    order.push_back(u);                            // push after all descendants finish
}
void dfs2(int u, vector<vector<int>>& rg, vector<int>& comp, int k) {
    comp[u] = k;                                // label as SCC number k
    for (int v : rg[u])
        if (!comp[v]) dfs2(v, rg, comp, k);     // DFS on the reversed graph
}
int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int n, m; cin >> n >> m;
    vector<vector<int>> g(n + 1), rg(n + 1);   // g original · rg reversed
    for (int i = 0; i < m; i++) {
        int a, b; cin >> a >> b;
        g[a].push_back(b); rg[b].push_back(a);          // reverse of a→b is b→a
    }

    vector<int> order, visit(n + 1, 0);
    for (int i = 1; i <= n; i++)
        if (!visit[i]) dfs1(i, g, order, visit);   // pass 1: build finish order

    reverse(order.begin(), order.end());          // latest finish first

    vector<int> comp(n + 1, 0);
    int k = 0;
    for (int u : order)
        if (!comp[u]) dfs2(u, rg, comp, ++k);    // pass 2 (reversed): one SCC per call

    cout << k << "\n";
    for (int i = 1; i <= n; i++) cout << comp[i] << " \n"[i == n];  // kingdom id of each planet
    return 0;
}

That matches the plan. One thing worth flagging — I build rg in the same loop as g, so the reversed graph costs nothing extra. And comp[u] != 0 doubles as "visited" in the second pass, which is why kingdoms are numbered from 1.

The row that matters is the first: planet 1 is the latest to finish, so it's in a source component. On the reversed graph, its reachable set is trapped inside {1,2,3} — it can't leak into 4 or 5. Then 4 and 5 each find only labeled neighbors, so they become kingdoms 2 and 3. Output: 3, then 1 1 1 2 3.

Corner cases:

• A single planet with no teleporters → one kingdom.
• A graph that's already one big cycle → one kingdom.
• A DAG → every planet is its own kingdom, so k = n.

The time complexity is O(n + m) — two linear DFS passes. The space complexity is O(n + m), for the two adjacency lists plus the arrays. In the worst case a long chain gives recursion depth O(n), so at 105 I'd bump the stack or go iterative.

Oh, one more thing — Kosaraju needs the reverse graph and two passes; Tarjan's algorithm does it in one pass with dfn/low and a stack. I chose Kosaraju because it's easier to explain and hard to get wrong.
