Alright, let me code this up. Union-Find with union by size and path compression. Then one kruskal function: reset the parents, union the forced edge first if there is one, then scan the sorted indices, skipping the skip edge and stopping at n − 1 edges. The main function sorts indices with iota and a weight comparator, takes the baseline, and runs the two probes per edge.

class Solution {
private:
    vector<int> parent;

    int Find(int x) {
        return parent[x] < 0 ? x : parent[x] = Find(parent[x]);
    }

    bool Union(int x, int y) {
        int rx = Find(x);
        int ry = Find(y);
        if (rx == ry) {
            return false;
        }
        if (-parent[rx] < -parent[ry]) {
            swap(rx, ry);
        }
        parent[rx] += parent[ry];
        parent[ry] = rx;
        return true;
    }

    // build MST: skip one edge, or force one in first; returns weight or INT_MAX
    int kruskal(int n, vector<vector<int>>& edges, vector<int>& order,
                int skip, int force) {
        parent.assign(n, -1);
        int total = 0;
        int add = 0;

        if (force != -1) {                 // put the forced edge in first
            Union(edges[force][0], edges[force][1]);
            total += edges[force][2];
            add++;
        }

        for (int idx : order) {            // scan by ascending weight
            if (idx == skip) {
                continue;                  // skip the skipped edge
            }
            if (add >= n - 1) {
                break;                     // already have n-1 edges
            }
            if (Union(edges[idx][0], edges[idx][1])) {
                add++;
                total += edges[idx][2];
            }
        }
        return add == n - 1 ? total : INT_MAX;   // short = disconnected
    }

public:
    vector<vector<int>> findCriticalAndPseudoCriticalEdges(
            int n, vector<vector<int>>& edges) {
        int m = edges.size();

        vector<int> order(m);              // indirect sort: sort ids, not edges
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) {
            return edges[a][2] < edges[b][2];
        });

        int mst = kruskal(n, edges, order, -1, -1);   // baseline MST weight

        vector<int> critical;
        vector<int> pseudo;
        for (int i = 0; i < m; i++) {
            if (kruskal(n, edges, order, i, -1) > mst) {
                critical.push_back(i);                 // removing costs more → critical
            } else if (kruskal(n, edges, order, -1, i) == mst) {
                pseudo.push_back(i);                   // forcing still optimal → pseudo
            }
        }
        return {critical, pseudo};
    }
};

One thing worth flagging is kruskal's return line: add == n - 1 ? total : INT_MAX. If fewer than n − 1 unions happened, the graph fell apart, so I return INT_MAX. That's automatically greater than the baseline, so the same > mst test catches both "got more expensive" and "fell apart", in one line.

Corner cases:

• A single edge that's the only bridge is always critical.
• A cycle where every edge has the same weight makes them all pseudo-critical.
• If the whole graph is already a tree, every edge is critical.

Let me think about complexity here.

Time is O(m² · α), where m is the number of edges. I sort once in O(m log m), then for each edge I run up to two Kruskal builds, each O(m · α) with union-find. Space is O(n + m) — the parent array and the order array.

In the worst case every edge triggers both a skip and a force build, but α is basically constant, so it stays near m².

Oh, one more thing — for very large m this quadratic pass is slow. The faster route groups edges by weight and, within each group, contracts the components already joined by lighter edges and looks for bridges. Bridges are critical, and the other edges that still join two different components are pseudo-critical. That gets close to O(m log m).
