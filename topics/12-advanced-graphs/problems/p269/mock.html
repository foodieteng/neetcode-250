Two: for each neighboring pair, find the first differing index, add that one edge, and stop.
Three: topologically sort the graph, with DFS or Kahn — a cycle means return empty.

Alright, let me code this up. First the DFS version, with three colors for cycle detection.

class Solution {
private:
    unordered_map<char, unordered_set<char>> graph;
    unordered_map<char, int> color;   // 0=white(unseen) 1=gray(on stack) 2=black(done)
    string res;

    // returns false = cycle found
    bool dfs(char u) {
        color[u] = 1;                          // enter: gray
        for (char v : graph[u]) {
            if (color[v] == 1) {
                return false;                  // hit gray → cycle
            }
            if (color[v] == 0 && !dfs(v)) {
                return false;
            }
        }
        color[u] = 2;                          // done: black
        res += u;                              // post-order (reverse topo)
        return true;
    }

public:
    string alienOrder(vector<string>& words) {
        for (auto& w : words) {
            for (char c : w) {
                graph[c];                       // make sure the node exists
                color[c] = 0;
            }
        }

        for (int i = 0; i + 1 < (int)words.size(); i++) {
            string& w1 = words[i];
            string& w2 = words[i + 1];
            int minL = min(w1.size(), w2.size());
            int j = 0;
            for (; j < minL; j++) {
                if (w1[j] == w2[j]) {
                    continue;
                }
                graph[w1[j]].insert(w2[j]);    // set dedups for free
                break;
            }
            if (j == minL && w1.size() > w2.size()) {
                return "";                     // prefix conflict
            }
        }

        for (auto& [c, _] : color) {
            if (color[c] == 0 && !dfs(c)) {
                return "";                     // cycle
            }
        }

        reverse(res.begin(), res.end());       // reverse post-order → topo order
        return res;
    }
};

Both versions build the graph the same way: register every letter, add one edge per neighboring pair, and return "" on a prefix conflict.

One thing worth flagging in the DFS. I add a letter to res only after all its descendants have finished — that's post-order, which is the reverse of topological order, so I flip it at the end. Cycle detection is the gray color: if I reach a node that's still on the recursion stack, I've found a back edge.

Now the same thing with Kahn's BFS.

class Solution {
private:
    unordered_map<char, unordered_set<char>> graph;
    unordered_map<char, int> indegree;

public:
    string alienOrder(vector<string>& words) {
        int n = words.size();

        for (auto& w : words) {
            for (char c : w) {
                indegree[c] = 0;
                graph[c] = unordered_set<char>();
            }
        }

        for (int i = 0; i < n - 1; i++) {
            string& w1 = words[i];
            string& w2 = words[i + 1];
            int minL = min(w1.size(), w2.size());
            int j = 0;
            for (; j < minL; j++) {
                if (w1[j] == w2[j]) {
                    continue;
                }
                if (!graph[w1[j]].count(w2[j])) {   // only a NEW edge bumps indegree
                    graph[w1[j]].insert(w2[j]);
                    indegree[w2[j]]++;
                }
                break;
            }
            if (j == minL && w1.size() > w2.size()) {
                return "";                          // prefix conflict
            }
        }

        queue<char> q;
        for (auto& [c, deg] : indegree) {
            if (deg == 0) {
                q.push(c);
            }
        }

        string res;
        while (!q.empty()) {
            char u = q.front();
            q.pop();
            res += u;
            for (char v : graph[u]) {
                if (--indegree[v] == 0) {
                    q.push(v);
                }
            }
        }

        return res.size() == indegree.size() ? res : "";   // short = cycle
    }
};

Every letter with in-degree 0 starts in the queue; each pop appends the letter and lowers its neighbors' in-degrees. If res is shorter than the number of letters, something was stuck in a cycle.

One thing worth flagging in Kahn's — the count check before indegree[v]++. The same edge can be produced by more than one word pair. The set only stores it once, but if I bump the in-degree every time, the count is too high, that letter never drops to zero, and I'd falsely report a cycle. The DFS version uses a set with no counts, so it's immune.

Let me think about complexity here.

Time is O(C + V + E), where C is the total length of all words, V is the number of distinct letters, and E is the number of edges. Building the graph scans every character once; the topo sort touches each node and edge once. Both versions are the same.

Space is O(V + E), for the graph plus the color map or the in-degree map.

In the worst case V is capped at 26, so the letter part is basically constant.

Oh, one more thing — if I needed the smallest valid order instead of any, I'd take the Kahn version and swap the plain queue for a min-heap, always popping the smallest ready letter. The DFS version doesn't give that as cleanly.
