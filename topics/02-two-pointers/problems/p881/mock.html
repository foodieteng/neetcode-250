A naive approach would try every way of pairing people up, which is exponential — far too slow for 5 × 104 people.

This problem reminds me of a sorted two-pointer greedy: once the array is sorted, the lightest and heaviest sit at the two ends, so each step is one O(1) decision. Why is pairing the heaviest with the lightest optimal?

C
CANDIDATE

It's an exchange argument. The heaviest person, H, needs a boat. If H fits with the lightest, L, suppose an optimal answer doesn't pair them — L sits elsewhere, and H rides alone or with some X.

Move L into H's boat. Since L is the lightest, H+L <= H+X <= limit, so it's still valid, and L's old boat only got lighter. The boat count doesn't go up, so pairing H with L is at least as good.

And if H can't fit even L, H can't fit anyone, since everyone weighs ≥ L — so H going alone is forced.

class Solution {
public:
    int numRescueBoats(vector<int>& people, int limit) {
        int n = people.size();
        sort(people.begin(), people.end());       // sort → so lightest can pair with heaviest
        int l = 0, r = n - 1, boats = 0;

        while (l <= r) {
            boats++;                                // every step opens one boat

            int sum = people[l] + people[r];

            if (sum > limit) {
                r--;                              // doesn't fit → heaviest goes alone
            } else {
                l++; r--;                        // fits → lightest + heaviest share a boat
            }
        }

        return boats;
    }
};

Every iteration opens one boat for the heaviest person. I compute the sum of the two ends; if it's > limit, only r moves, otherwise both move.

One thing worth flagging — the loop condition is l <= r, not l < r. When l == r there's one person left, and they still need a boat; with a strict check, that last person would be dropped.

No. With 3+ per boat it becomes bin packing, which is NP-hard in general. The clean two-pointer only works because each boat has exactly one companion slot, which is what makes "lightest with heaviest" a safe choice.
