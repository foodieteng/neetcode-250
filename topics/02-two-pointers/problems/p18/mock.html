One: sort the array.
Two: loop i, then j from i+1, skipping repeated values at each level.
Three: put l right after j and r at the end, compute a long long sum, and move by comparing it to target — on a hit, record it, move both pointers inward, and skip duplicates.

Alright, let me code this up. Two nested loops over the sorted array, each with its own skip-duplicates check, and a two-pointer while loop inside.

class Solution {
public:
    vector<vector<int>> fourSum(vector<int>& nums, int target) {
        int n = nums.size();
        sort(nums.begin(), nums.end());
        vector<vector<int>> ans;

        for (int i = 0; i < n; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;       // dedup i

            for (int j = i + 1; j < n; j++) {
                if (j > i + 1 && nums[j] == nums[j - 1]) continue;  // dedup j

                int l = j + 1, r = n - 1;

                while (l < r) {
                    long long sum = (long long)nums[i] + nums[j] + nums[l] + nums[r];  // overflow guard

                    if (sum < target) {
                        l++;
                    } else if (sum > target) {
                        r--;
                    } else {
                        ans.push_back({nums[i], nums[j], nums[l], nums[r]});
                        l++; r--;
                        while (l < r && nums[l] == nums[l - 1]) l++;  // dedup l
                        while (l < r && nums[r] == nums[r + 1]) r--;  // dedup r
                    }
                }
            }
        }

        return ans;
    }
};

Too small, move l right; too big, move r left; equal, record the four values, step both pointers, and skip repeats.

One thing worth flagging — the cast. I cast the first term, nums[i], to long long, so the whole addition runs in 64 bits. Casting the finished sum would be too late; the int addition would already have overflowed. And the j check is j > i+1, not j > 0 — otherwise I'd skip a valid j whose value equals nums[i].

Let me think about complexity here.

Time is O(n3): the sort is absorbed, the two fixed loops give O(n2), times a linear inner scan. Space is O(1) extra beyond the output, not counting the sort.
