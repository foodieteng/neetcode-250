Let me name the alternatives.

A reversed copy is O(n) space — it fails the constraint. Recursion that swaps the ends is in place for the data, but it uses an O(n)-deep call stack.

This problem reminds me of the opposite-direction two-pointer pattern, because reversing just means the first and last characters trade places, then the next pair in, and so on. So: l at the start, r at the end, swap and move inward until they meet. O(n) time, O(1) space, no stack.

// converge from both ends

One: set l = 0 and r = n - 1.
Two: while l < r, swap s[l] and s[r].
Three: move l right and r left.

One thing worth flagging — the condition is l < r, which handles both parities: an even length ends with the pointers crossing, and an odd length stops at l == r, since the middle character is its own pair and needs no swap. Alright, let me write the explicit two-pointer version.

class Solution {
public:
    void reverseString(vector<char>& s) {
        int l = 0, r = s.size() - 1;
        while (l < r) {
            swap(s[l], s[r]);       // swap the two ends
            l++; r--;                 // move inward
        }
    }
};

Two indices start at the ends; each pass swaps them and steps both inward, until they meet.

One detail worth flagging — std::reverse(s.begin(), s.end()) would do exactly this in one line. I wrote it out to show the mechanism, because variants that reverse only some of the characters build on this same loop.
