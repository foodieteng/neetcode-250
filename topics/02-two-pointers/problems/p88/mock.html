A naive approach would concatenate and sort, which is O((m+n) log(m+n)), and wastes the fact that both inputs are sorted. Filling from the front needs a backup copy of nums1, so O(m) extra space.

This problem reminds me of the merge step of merge sort, just run backwards: one pointer per array, always placing the larger value at the back. That's O(m+n) time and O(1) space, because the tail slots make it work in place.

l = m-1, r = n-1, i = m+n-1

  nums1[i--] = larger of nums1[l], nums2[r] (step that one back)
while r >= 0: nums1[i--] = nums2[r--]
// invariant: i >= l, leftover nums1 stays put

One: start l = m-1, r = n-1, and the write index i = m+n-1.
Two: while both have values, write the larger one at i and step that pointer back.
Three: copy over any leftover nums2.

Two things worth flagging. The invariant i ≥ l always holds: i moves back every step, l only when I take from nums1, so a write never hits unread data. And I only copy leftover nums2; if nums1 has leftovers, they're already in place. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int l = m - 1, r = n - 1, i = m + n - 1;  // three pointers from the back

        while (l >= 0 && r >= 0) {            // both have values → larger to the tail
            if (nums1[l] > nums2[r])
                nums1[i--] = nums1[l--];
            else
                nums1[i--] = nums2[r--];
        }

        while (r >= 0) {                       // leftover nums2 → copy in
            nums1[i--] = nums2[r--];
        }
        // leftover nums1 needs nothing: already at the front, sorted
    }
};

Three indices start at the back. While both arrays have values, if nums1[l] is strictly larger it goes to slot i, otherwise nums2[r] does, and the used pointer and i step back. Then one loop copies any leftover nums2.

One detail worth flagging: there's no second loop for leftover nums1, because those elements are already sitting in their final sorted positions at the front. And on a tie the else branch takes nums2 first, which is fine, since equal values can go in either order.

Time is O(m+n), since each element is placed once. Space is O(1): three indices, in place, no backup.

One more thing: the trick is to "fill from the end that has free room," which generalizes to lots of in-place array work. And to merge k sorted arrays instead of two, I'd swap the two pointers for a min-heap of the k heads.
