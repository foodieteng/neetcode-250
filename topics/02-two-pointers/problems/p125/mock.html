One: start l at 0 and r at the last index.
Two: while l < r, if either end isn't alphanumeric, move just that pointer and loop again.
Three: compare the lowercased ends; a mismatch returns false, a match moves both inward.

Order matters — the two skips come before the compare, so I only ever compare two confirmed alphanumeric characters. Surviving until the pointers meet means it's a palindrome. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    bool isPalindrome(string s) {
        int l = 0, r = s.size() - 1;

        while (l < r) {
            if (!isalnum(s[l])) { l++; continue; }   // left not alnum → skip
            if (!isalnum(s[r])) { r--; continue; }   // right not alnum → skip

            if (tolower(s[l]) == tolower(s[r])) {
                l++; r--; continue;          // match → move inward
            }
            return false;                          // mismatch → not a palindrome
        }
        return true;
    }
};

Two skip checks, then one compare, inside a single while loop; falling out of the loop returns true.

One detail worth flagging — each continue moves just one pointer and re-enters the loop, which re-checks l < r, so both ends get aligned onto alphanumeric characters before any comparison, and the pointers never cross mid-skip. For non-ASCII input I'd cast to unsigned char before calling isalnum, but the input is printable ASCII here.
