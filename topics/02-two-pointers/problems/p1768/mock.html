class Solution {
public:
    string mergeAlternately(string word1, string word2) {
        int m = word1.size(), n = word2.size();
        int l = 0, r = 0;
        string res = "";

        while (l < m && r < n) {          // both have chars → alternate
            res = res + word1[l] + word2[r];
            l++; r++;
        }

        while (l < m) { res += word1.substr(l); break; }  // word1 tail
        while (r < n) { res += word2.substr(r); break; }  // word2 tail

        return res;
    }
};

The main loop takes word1[l], then word2[r], while both have characters. Then each leftover tail goes on in one piece with substr. Those two while loops end in a break, so they really act as ifs and run at most once.

One detail worth flagging: res = res + … builds a fresh string every step, copying the whole result, so the main loop is quadratic in the worst case. +=, or reserve + push_back, keeps it linear. With both lengths ≤ 100, it's harmless here.

The row that matters is when l reaches 3: word1 is used up, so the loop stops. word1 has no tail, but r = 3 < 4, so word2's tail "s" is appended. That matches.

Corner cases:

• equal length → pure alternation, no tail.
• "abcd" + "pq" → "apbqcd", from word1's tail.
• single characters "a" + "b" → "ab".

Time is O(m+n) once appends are in place, since each character is placed exactly once. As written, the res = res + … copy makes the main loop quadratic, which doesn't matter at 100 characters. Space is O(m+n) for the output, plus two indices.

One more thing: this is the parallel-cursor flavor of two pointers, distinct from the converging kind used for reversing or palindromes. Swap the fixed alternation for a comparison and it becomes merging two sorted arrays. Make one pointer advance only on a match and it's subsequence checking.
