題目簡介// THE QUESTION

QUESTION

addWord(word) 加入一個字;search(word) → 有沒有加過的字和它完全吻合?查詢字串裡的 '.' 可以配任意一個字母。
1 ≤ word.length ≤ 25,每個查詢最多 2 個 '.',兩種操作合計最多 104 次。

範例:加入 bad、dad、mad 之後,search("pad") → false、"bad" → true、".ad" → true、"b.." → true。

addWord 和 208 的 insert 一字不差;只有 search 要改。 一般字母照 208 走一條路;遇到 '.' 不知道走哪條,就 26 條都試 —— 迴圈變成遞迴 DFS。
2

為什麼用 Trie + DFS// WHY BRANCH ON THE TRIE

A vector<string>,查詢時逐字比對 O(N · L) / 次
每次 search 都要和已加入的 N 個字一個一個比('.' 跳過不比)。字越多越慢,共同前綴也被重複比。
× REJECT · TLE
B unordered_set,把 '.' 展開成 26 種字母去查 26k 次雜湊
2 個 '.' 就要組出 676 個字串,每個都算一次長度 L 的雜湊 —— 不管字典裡有沒有那些字母都得試。'.' 一多就爆炸,而且多數組合根本不存在。
△ REJECT · 白試很多不存在的字
BOTH FAIL · ADOPT
C Trie,'.' 只沿著「真的存在」的子節點分叉 字母 O(1),'.' 才分叉
字母照樣一步走完;遇到 '.',只有 Trie 上真的有的子節點才會往下長(nullptr 下一層立刻 false)。 一旦某條路回傳 true 就停,其他分支不用看。
● ADOPT · 只分叉存在的路,找到就停
3

核心策略 · 三步驟// THE SHAPE

  1. dfs(word, idx, node):「從 node 出發,能不能配完 word[idx..]」。開頭先擋 if (!node) return false。
  2. 配完了(idx == word.size())→ 回傳 node->isWord,和 208 的 search 一樣。
  3. 字母 → 只走 child[c - 'a'] 一條;'.' → 26 個子節點逐一 dfs,任一個 true 就 true,全部 false 才 false。
4

動畫演示// pad · .ad · b..

5

一行擋兩種 null、'.' 的位置決定成本// TWO LEMMAS

LEMMA 1 · if (!node) 放在開頭,一次處理兩種 nullptr

字母走到不存在的子節點(pad 的 p),和 '.' 迴圈把 26 格全部丟下去時遇到的空格,本質都是「這條路不存在」。 把檢查放在 dfs 第一行,兩個分支都不用再自己判斷。 拿掉這一行 → 下一層讀 node->isWord 或 node->child 就是對 nullptr 取值。實測拿掉後隨機 20,000 組有 17,244 組當掉,最小反例:空字典 search("a")。

LEMMA 2 · '.' 越前面越貴

'.' 在前面,分叉發生在樹最寬的上層,每條分支後面還要走完整段;'.' 在後面,前面的字母已經把範圍縮到一條路。 實測同一個 5,000 字的字典(115k 個節點):"..zzz…zb" 要 16,251 次 dfs,"zzz…z..b" 只要 76 次,差約 200 倍。 題目限制最多 2 個 '.',所以最壞也就是 26 × 26 條分支。

6

複雜度// COMPLEXITY

addWord 和 208 一樣 O(L)。search 沒有 '.' 是 O(L);每個 '.' 最多讓分支數乘上 26,k 個 '.' 最壞 26k 條路,每條走 L 步。

addWord O(L)　·　search O(26k · L)(k ≤ 2)　·　空間 O(Σ|word| · 26)
實測(64-bit, -O2)值
104 個隨機長度 25 的字228,199 個節點、峰值 53,132 KB
理論上界 25 × 104 + 1 個節點× 216 B ≈ 51.5 MiB
最壞查詢 "..zzz…zb" × 5,000 次約 8,100 萬次 dfs,189 ms
改成節點池(程式碼頁第 2 節)類 LeetCode 測資 167.2 → 33.2 ms
7

一句洞察// INSIGHT

208 的 search 是一條路;這題是「一條路 + 遇到 '.' 就分叉」的 DFS。 null 一律在 dfs 開頭擋掉;配完看 isWord;任一分支 true 就停。
