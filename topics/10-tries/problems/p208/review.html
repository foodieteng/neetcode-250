Q5. search(word, bool prefix = false) 用一個 bool 參數同時當 search 和 startsWith,有什麼好處和壞處?

範例 Trace// 共用前綴 + 開新分支

概念頁是一條直線;這組多一個 "bat",root 底下長出第二個分支。實跑插樁輸出,節點數含 root。

// 三次 insert Trie() root 節點數 = 1 insert("app") 新建 a ap app;app.isWord = true 節點數 = 4 insert("apple") 沿用 a ap app(共用前綴) 新建 appl apple;apple.isWord = true 節點數 = 6 insert("bat") root.child['b'] 是 nullptr → 開新分支 新建 b ba bat;bat.isWord = true 節點數 = 9
// 三次查詢 search("ba") 走 b → ba,走完;ba.isWord = false → false startsWith("ba") 走 b → ba,走完;prefix 模式 → true search("bat") 走 b → ba → bat;bat.isWord = true → true // OUTPUT: [null, null, null, null, false, true, true]
先插短的 "app" 再插 "apple",只多建 2 個節點;這就是共用前綴。 這組的 false 也是「走得完、但 isWord = false」;「半路斷掉」的 false 見概念頁動畫最後的 search("apx")。

應用題// APPLY IT

App 1. search 的字裡可以有 '.',代表任意一個字母(211 ↗)。search 要怎麼改?
App 2. 在一張字母格上一次找出很多個 word(212 ↗)。Trie 怎麼和 79 · Word Search 的回溯結合?
App 3. 要多一個 countWordsStartingWith(prefix):回傳有幾個插入過的字以 prefix 開頭,而且要 O(L)。節點要多存什麼?
// ANSWERS
A1. 存在。它是 apple 的必經之路,但沒有字在這裡結束,所以 isWord = false。

兩個函式走的路一模一樣(a → ap → app 都走得到),差別只在最後一行:search 回傳 cur->isWord(false),startsWith 在 if (prefix) return true; 就回傳了。「節點存在」回答的是前綴問題,「isWord」回答的是整字問題。
A2. 已經存在的節點被換成空的新節點,下面整串子樹和原本的 isWord 都斷掉(舊節點也洩漏)。

最小反例 insert("a") → insert("aa") → search("a"):第二次 insert 把 root 底下那個 isWord = true 的 "a" 換掉,回傳 false(正解 true)。隨機 20,000 組錯 147 組 —— 只有「先插入的字是後插入的字的前綴」(或共用前綴)才會觸發,所以範例常常測不到。
A3. 聚合初始化沒寫到的元素會補 0,所以 26 格全是 nullptr。完全不寫就是垃圾值,屬於未定義行為。

實測拿掉初始值(new TrieNode 不加括號):新程序單跑剛好全對,因為 OS 給的新記憶體剛好是 0;同一程序連跑就 segfault,堆疊被弄髒時 20,000 組錯 19,234 組。保留 = { nullptr } / = false 的話,有沒有括號都 0 錯。
A4. 每一步是 child[c - 'a'] 一次索引,走 L 步就結束,完全不需要和其他字比 —— 已存的字都「藏」在別的分支裡。

map 版 sizeof(TrieNode) 從 216 B 降到 64 B,但每個 map 項目和 bucket 另外配置。實測同一組資料(9,990,040 個節點),峰值記憶體幾乎一樣(2,198,116 KB vs 2,198,628 KB),還慢了約 1.6 倍。字母集只有 26 個時,陣列比較好。
A5. 好處:走路的迴圈只寫一次。壞處:search(s, true) 在呼叫端看不出 true 是什麼意思,而且 prefix 被暴露成公開介面。

另一種拆法是一個私有的 TrieNode* find(const string& s) 回傳走到的節點(斷掉就 nullptr),然後 search 回傳 node && node->isWord,startsWith 回傳 node != nullptr。兩種寫法做的事完全一樣。
A-App 1. 遇到 '.' 時,這一層要試 26 個非 nullptr 的子節點,任一個往下成功就 true —— 迴圈改成遞迴 DFS。

一般字母照舊走一步;'.' 才分叉。走到字尾一樣回傳 isWord。insert 完全不用改。
A-App 2. 把所有 word 建成一棵 Trie,每個格子當起點做一次 79 的回溯,但每走一格同時在 Trie 上往下走一層。

Trie 上沒有這個字母的子節點 → 立刻剪掉這條路(79 只能剪一個 word,這裡一次剪掉所有 word);走到 isWord 的節點就收答案。標 # / 還原的骨架和 79 一樣。
A-App 3. 每個節點多存 int pass:有幾個插入的字經過這個節點。

insert 時沿路每個節點 pass++(新建的也要);查詢時走完 prefix,回傳終點的 pass,斷掉回傳 0。一樣 O(L)。同一個字插兩次要不要算兩次,看題目定義。
