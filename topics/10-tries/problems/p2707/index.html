題目簡介// THE QUESTION

QUESTION

給字串 s 和一串互不相同的字典字 dictionary。把 s 切出若干段不重疊、而且每段都是字典字的子字串,沒被任何一段蓋到的字元就是「多餘字元」。回傳多餘字元的最少數量。
1 ≤ s.length ≤ 50,1 ≤ dictionary.length ≤ 50,1 ≤ dictionary[i].length ≤ 50,全部小寫。

範例:s = "leetscode",字典 ["leet","code","leetcode"] → 1(切成 leet + code,只剩 s); s = "sayhelloworld",字典 ["hello","world"] → 3(s、a、y 沒人蓋)。

這是 139 Word Break 的「允許失敗」版:139 問能不能全部蓋滿,這題問最少剩幾個沒蓋到。 所以轉移多了一條「這個字元放棄,算 1 個多的」—— 有了這條,dp 永遠有值,不會出現 false。
2

為什麼用 DP + 找字典字// WHY DP

A 暴力遞迴:每個位置試「跳過」或「接一個字」 指數級
同一個位置 i 會從很多種切法被走到,每次都把後綴重算一遍。實測 s 全 a、每種長度都在字典裡:n = 10 要 17,711 次呼叫,n = 20 就要 2.68 億次,每多 5 個字元約 ×120。n = 50 跑不完。
× REJECT · TLE
B 貪心:遇到字典字就先吃掉 O(n · m · L)
從左邊開始,接得上字就吃(最長或最短都一樣錯)。實測 s = "abcd"、字典 ["ab","bcd"]:貪心先吃 ab,剩 c、d 兩個 → 2;正解是放掉 a、吃 bcd → 1。
△ REJECT · 局部最佳 ≠ 整體最佳
BOTH FAIL · ADOPT
C 1-D DP:每個位置只算一次,所有切法都比過 n + 1 格
dp 存「某段後綴(或前綴)最少剩幾個」。每格先假設這個字元是多的(+1),再把所有能貼在這裡的字典字都試一遍取 min。 差別只在「怎麼找能貼的字」:A · Trie 從起點沿著樹往下走、路斷就停;B · set 每格把每個字拿出來比一次。
● ADOPT · 兩種寫法都對,找字的方式不同

核心策略 · 兩種寫法// THE SHAPE

A · Trie + 由右往左B · unordered_set + 由左往右
dp 的意思dp[start] = 後綴 s[start..] 最少剩幾個dp[i] = 前綴 s[0..i) 最少剩幾個
起點 / 答案dp[n] = 0,回傳 dp[0]dp[0] = 0,回傳 dp[n]
① 先 +1dp[start] = dp[start + 1] + 1dp[i] = dp[i − 1] + 1
② 找字從 root 沿 s[start], s[start+1] … 往下走,沒有子節點就 break每個字 w(長 L)都看 s[i−L..i) 是不是 w
③ 取 min走到 isWord(結尾在 end)→ dp[end + 1]對上了 → dp[i − L]

兩個關鍵// TWO LEMMAS

LEMMA 1 · 先 +1 再取 min:「這格是多的」永遠是一個合法選項

任何一種切法裡,位置 start 的字元只有兩種命運:沒被蓋到(多 1 個,剩下交給 dp[start+1]),或是某個字典字的開頭(那個字結束在 end,剩下交給 dp[end+1])。 先寫 +1 那條當預設值,再用每個字去挑戰它,兩種命運就都比到了。 這也是和 139 最大的差別:139 沒有「+1」這條路,所以 dp 是 bool;這題有,所以 dp 永遠是一個數字。

LEMMA 2 · 不能找到第一個字就停

同一個起點可能接得上好幾個字(leet、leetcode 都從 0 開始),接哪個最好要看後面剩多少,當下看不出來。 所以 Trie 版走到 isWord 只更新 min、繼續往下走;只有「沒有子節點」才 break —— 那代表從這個起點再也不可能有更長的字。 set 版同理,每個字都要比完。

6

複雜度// COMPLEXITY

n = s 長度、m = 字典字數、L = 最長字長。Trie 版每個起點最多往下走 L 步;set 版每個位置把 m 個字各比一次,每次比對(和 substr 複製)要 O(L)。

A · Trie:建樹 O(Σ|w|) + DP O(n · L)　·　B · set:O(n · m · L)　·　空間 A O(26 · Σ|w|)、B O(Σ|w|)
實測(-O2,s = 50 個 a,字典 a … a50,連跑 10,000 次)計數時間
A · Trie內層 1,275 次 · 51 個節點171.8 ms
B · set(原版)substr 1,275 次 + 複製字串共 85,850 個字元996.4 ms
B · set(改良:直接掃 dictionary、const string&、compare)不配置任何字串115.3 ms
答案最大值50s 全 z、字典 ["a"]:一個都蓋不到

原版 set 慢在複製字串,不是演算法:改良版甚至比 Trie 快,因為 Trie 還要 new 節點。n、m、L 都 ≤ 50 時,兩種都輕鬆過;字典很大、前綴大量共用時,Trie 的 O(n · L) 才會拉開差距。

7

一句洞察// INSIGHT

139 + 「這個字元可以放棄,代價 1」。 每格先 +1,再用每個能貼上的字典字挑戰它。Trie 讓「能貼上的字」從一個起點一路走出來、路斷就停;set 則是每格把每個字都比一次。
