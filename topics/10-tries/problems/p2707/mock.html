Hmm, let me think about this for a sec.

A naive approach would be to try every choice at every position: skip this character, or start any word that matches here. That branching recursion can blow up exponentially. But the answer for "the rest of the string from position i" doesn't depend on how I got to i, so the subproblems repeat — a 1-D DP over positions.

This problem reminds me of the word-segmentation DP: at each position, try every word that can start or end there. The difference is that a character may be skipped, at a cost of +1. For the matching, a prefix tree lets me walk forward one character at a time and find every word that starts at a position in one walk.

I'll show two versions: a trie with a backward DP, and a simpler hash set with a forward DP.

P — plan
C
CANDIDATE

Here's the plan. Same idea in both: first assume this character is extra (+1), then try to cover it with a word.

// A — trie, backward. dp[i] = min extras in s[i..n-1]
dp[n] = 0
for start = n-1 down to 0:
  dp[start] = dp[start+1] + 1   // s[start] is extra
  walk the trie from s[start]; stop at first missing child
    if s[start..end] is a word:
      dp[start] = min(dp[start], dp[end+1])
answer = dp[0]

// B — set, forward. dp[i] = min extras in s[0..i-1]
dp[0] = 0
for i = 1 to n:
  dp[i] = dp[i-1] + 1   // s[i-1] is extra
  for each word w of length L:
    if s[i-L..i-1] == w: dp[i] = min(dp[i], dp[i-L])
answer = dp[n]

One: in version A, dp[i] is the fewest extras in the suffix from i; dp[n] = 0.
Two: from each start, I walk the trie and stop at the first missing child; every word end I pass offers dp[end + 1].
Three: version B mirrors it, with dp over prefixes, checking every word that ends at i.

One thing worth flagging — I must take the min over every word that matches. A short word and a long word can both match at the same spot, so "first match wins" is wrong. In the trie walk, I only break when a child is missing.

Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. First, version A — the trie with a backward DP.

class TrieNode {
public:
    TrieNode *child[26] = { nullptr };
    bool isWord = false;
};

class Solution {
public:
    TrieNode *root;

    int minExtraChar(string s, vector<string>& dictionary) {
        root = new TrieNode();

        for (auto& w : dictionary) insert(w);

        int n = s.length();
        vector<int> dp(n + 1, 0);                      // dp[n] = 0: empty suffix

        for (int start = n - 1; start >= 0; start--) {
            dp[start] = dp[start + 1] + 1;             // ① first assume s[start] is extra
            TrieNode* node = root;                     // ② every start walks from root
            for (int end = start; end < n; end++) {
                int idx = s[end] - 'a';
                if (!node->child[idx]) break;          // ③ path broken: no longer word
                node = node->child[idx];
                if (node->isWord) dp[start] = min(dp[start], dp[end + 1]);  // ④ no break
            }
        }

        return dp[0];
    }

    void insert(string& w) {
        TrieNode *cur = root;

        for (char& c : w) {
            int i = c - 'a';
            if (!cur->child[i]) cur->child[i] = new TrieNode();
            cur = cur->child[i];
        }
        cur->isWord = true;
    }
};

Each start sets dp to the next cell + 1, then walks from the root. The inner loop breaks only when node->child[idx] is missing; when isWord is true, I update the min and keep walking, so a longer word can still match.

Now version B — the hash set with a forward DP.

class Solution {
public:
    int minExtraChar(string s, vector<string>& dictionary) {
        int n = s.size();
        vector<int> dp(n + 1, 0);                      // dp[0] = 0: empty prefix
        unordered_set<string> dict(dictionary.begin(), dictionary.end());

        for (int i = 1; i <= n; i++) {
            dp[i] = dp[i - 1] + 1;                     // ① first assume s[i-1] is extra
            for (string w : dict) {                    // ② compare every word once
                int L = w.size();
                if (i - L >= 0 && (s.substr(i - L, L) == w)) {  // ③ the piece ending at i
                    dp[i] = min(dp[i], dp[i - w.size()]);       // ④ no break
                }
            }
        }
        return dp[n];
    }
};

One thing worth flagging — two code-review notes on B. The unordered_set is only looped over; I never call find on it, so it gives no speed-up over looping on dictionary directly. And for (string w : dict) copies each word on every pass, while s.substr(i - L, L) allocates a new string; const string& w and s.compare(i - L, L, w) == 0 avoid both.

Let me think about complexity here.

For version A, building the trie is O(Σ|w|), plus O(n · Lmax) for the DP, since each walk stops at the first missing child. For version B, it's O(n · m · L), where m is the dictionary size, because each comparison costs up to O(L).

Space is O(26 · Σ|w|) for the trie in A, or just O(Σ|w|) for the set in B, plus O(n) for dp.

In the worst-case scenario, with many long words, B pays for every word at every position, while A only follows letters that exist in the trie. With every limit at 50, both pass easily.

Oh, one more thing — version A never frees its trie nodes. That's fine on LeetCode, but in real code I'd use unique_ptr or a node pool.
