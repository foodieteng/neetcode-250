PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼每一格都先寫 dp[start] = dp[start + 1] + 1,再去找字典字?
解答與說明 · ANSWER▾
位置 start 的字元只有兩種命運:沒被蓋到,或是某個字的開頭。先寫 +1,就是把「沒被蓋到」當成預設答案,再讓每個字去挑戰它。

這條路永遠存在,所以 dp 一定有值,不會像 139 那樣出現 false。實測拿掉 + 1(A、B 都一樣),窮舉 59,094 組錯 48,910 組:dp 永遠是 0,最小反例 "a"、["b"] → 0(正解 1)。
第 2 題10 分
Trie 版走到 isWord 的節點時,為什麼不能直接 break?那什麼時候可以 break?
解答與說明 · ANSWER▾
這個節點下面可能還有更長的字,而哪個字最好要看後面剩多少。只有「沒有子節點」才能 break —— 那代表從 start 出發,再也不可能有任何字。

實測 isWord 後加 break:窮舉錯 7,206 組,而且兩個官方範例都過。最小反例 "ab"、["a","ab"] → 1(正解 0):從 0 先吃到 "a" 就停,"ab" 沒機會。

反過來,把「沒有子節點就 break」改成 continue 也錯(25,724 組):配不上的字元被跳過,"ab" 會被當成 "b"。
第 3 題10 分
為什麼 Trie 版是由右往左填 dp,set 版卻是由左往右?能不能把 Trie 版改成由左往右?
解答與說明 · ANSWER▾
方向取決於「從哪一端去找字」。Trie 是從字的開頭往下走,所以站在 start、往右找到結尾 end,需要的是右邊的 dp[end+1] —— 右邊得先算好。set 版站在 i、往左看結尾在 i 的字,需要的是左邊的 dp[i−L]。

要讓 Trie 版由左往右,就把每個字反過來建 Trie:站在 i,沿 s[i−1], s[i−2], … 往下走,走到 isWord(長度 L)就看 dp[i−L]。同一套「路斷就停」照樣成立。
第 4 題10 分
set 版用了 unordered_set,為什麼說雜湊「完全沒用上」?
解答與說明 · ANSWER▾
程式只做了 for (string w : dict) —— 這是走訪,不是查找。雜湊表的價值在 O(1) 的 count / find,這裡一次都沒呼叫。

題目保證字不重複,直接掃 dictionary 結果一樣。真正拖慢的是每圈複製字和 substr:實測最壞情況共複製 85,850 個字元,10,000 次 996.4 ms;改成 const string& + compare 是 115.3 ms。

如果真的想用雜湊,寫法是反過來:對每個 i、每個可能的長度 L,查 dict.count(s.substr(i − L, L))。
第 5 題10 分
兩個 dp 陣列在 leetscode 上分別是 1 4 3 2 1 0 3 2 1 0 和 0 1 2 3 0 1 2 3 4 1,中間差這麼多,為什麼答案一樣?
解答與說明 · ANSWER▾
兩個 dp 的意思不同:A 的 dp[k] 是後綴 s[k..],B 的 dp[k] 是前綴 s[0..k)。只有 A 的 dp[0] 和 B 的 dp[9] 都代表「整個字串」。

例如 A 的 dp[5] = 0(後綴 code 全蓋到),B 的 dp[5] = 1(前綴 leets 剩 s)。中間值本來就不該相同,而且 A[k] + B[k] 也不一定等於答案 —— 最佳切法可能有一個字橫跨 k。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 官方範例 2 · sayhelloworld · [hello, world]:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

程式碼頁走過了範例 1;這裡看範例 2 的 Trie 版。s = s a y h e l l o w o r l d(索引 0–12),Trie 只有兩條鏈 h-e-l-l-o、w-o-r-l-d。實跑插樁輸出。

// start = 12 → 8:先遇到 world dp[13] = 0 start=12 'd' dp=1 root 沒有 d → break dp[12]=1 start=11 'l' dp=2 break dp[11]=2 start=10 'r' dp=3 break dp[10]=3 start=9 'o' dp=4 break dp[9]=4 start=8 'w' dp=5 走 w → o → r → l → d isWord "world":min(5, dp[13]=0) dp[8]=0
// start = 7 → 3:hello 接到 world 前面 start=7 'o' dp=1 break dp[7]=1 start=6 'l' dp=2 break dp[6]=2 start=5 'l' dp=3 break dp[5]=3 start=4 'e' dp=4 break dp[4]=4 start=3 'h' dp=5 走 h → e → l → l → o isWord "hello":min(5, dp[8]=0) = 0 end=8 'w':hello 節點沒有子節點 → break dp[3]=0
// start = 2 → 0:say 沒人蓋 start=2 'y' dp=1 break dp[2]=1 start=1 'a' dp=2 break dp[1]=2 start=0 's' dp=3 break dp[0]=3 // OUTPUT: dp[0..13] = 3 2 1 0 4 3 2 1 0 4 3 2 1 0 → 回傳 3(內層 22 次)
dp[3] 能是 0,是因為 dp[8] 已經先算好了 —— 由右往左填,才能讓「hello 接在 world 前面」一步取到。 set 版同一題則是 dp[8] = 3(前綴 sayhello 剩 say)、dp[13] = min(8, dp[8]) = 3,substr 比對 18 次。兩個方向在同一條鏈上相遇,答案一樣。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
同一個字典,要回答 104 個不同的 s。兩種寫法各要怎麼調整?哪一種比較划算?
解答與說明 · ANSWER▾
Trie 建一次、重複用;每個 s 只付 O(n · L)。set 版每個 s 都要 O(n · m · L)。

把 root 和 insert 移到建構子(或另一個函式)裡,minExtraChar 只跑 DP。這才是 Trie 版真正拉開差距的情境:單一個 s 時,改良版 set 實測還比 Trie 快,因為 Trie 的成本大半花在建樹和 new 節點。
第 8 題13 分
每個字母放棄的代價不同:給 cost[26],沒被蓋到的字元 c 要付 cost[c]。求最小總代價。要改哪一行?
解答與說明 · ANSWER▾
只改 ① 那一行:A 改成 dp[start] = dp[start + 1] + cost[s[start] − 'a'],B 改成 dp[i] = dp[i − 1] + cost[s[i − 1] − 'a']。

其餘完全不動 —— 「被字蓋到」的代價還是 0,只是「放棄」的代價從 1 變成看字母。原題就是 cost 全 1 的特例。
第 9 題14 分
除了最少剩幾個,還要回傳其中一種實際切法(哪些段用了哪個字)。dp 要多存什麼?
解答與說明 · ANSWER▾
多開一個 choice[start],記下 dp[start] 是由哪個選擇得到的:-1 表示「放棄這個字元」,否則記 end(用到 s[start..end] 這個字)。

算完後從 start = 0 開始照著 choice 走:-1 就前進 1 格,否則記下這一段、跳到 end + 1,直到 n。注意更新 min 時要用嚴格小於(或固定的平手規則),choice 才會和最後的 dp 值一致。
