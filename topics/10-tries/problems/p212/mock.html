Hmm, let me think about this for a sec.

A naive approach would be to run a single-word backtracking search once for each word, starting a DFS from every cell. The problem is that words that share a start, like "oa" and "oath", redo the same walk again and again. With 3·104 words, that's a lot of repeated work.

This problem reminds me of backtracking guided by a prefix tree. If I put all the words in a trie, words with the same start share one path. Then I do one DFS on the board and walk the trie at the same time, so one board walk checks every word that starts with those letters.

Here's the plan.

// 1. build: put every word in a trie
  the last node of a word stores that word

// 2. for each cell (i, j):
  if root has a child for board[i][j] → mark '#', search, restore

// 3. search(r, c, node): node = trie node for the path so far
  if node->word is set → add it, then clear it
  for each of 4 neighbors:
    skip if off the board, or '#', or node has no child
    mark '#', search(neighbor, child), restore

One: put every word in a trie, and let each word's last node store it.
Two: for each cell, start only if the root has a child for that letter — mark the cell '#', search, and restore it.
Three: the search carries the trie node for the path so far. If the node stores a word, add it and clear it; then try the four neighbors, skipping cells off the board, already marked, or with no trie child.

One thing worth flagging — when I find a word, I don't stop. If the list has "oa" and "oath", returning at "oa" would miss "oath". And clearing the word is how I dedupe, because the same word can be reached from two start cells.

Does this approach sound good, or would you rather I think of another way?

class TrieNode {
public:
    TrieNode *child[26] = { nullptr };
    string word = "";                     // the end node stores the whole word
};

class Solution {
public:
    TrieNode *root;

    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    vector<string> findWords(vector<vector<char>>& board, vector<string>& words) {
        root = new TrieNode();

        for (auto& w : words) insert(w);

        int m = board.size(), n = board[0].size();
        vector<string> ans;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                int idx = board[i][j] - 'a';
                if (root->child[idx]) {           // ① start only if the trie has this letter
                    char cache = board[i][j];
                    board[i][j] = '#';            // ② mark the start cell first
                    search(board, ans, i, j, root->child[idx]);
                    board[i][j] = cache;
                }
            }
        }

        return ans;
    }

    void insert(string& w) {
        TrieNode *cur = root;

        for (char& c : w) {
            int i = c - 'a';
            if (!cur->child[i]) cur->child[i] = new TrieNode();
            cur = cur->child[i];
        }
        cur->word = w;                    // store the word, not an isWord flag
    }

    void search(vector<vector<char>>& board, vector<string>& ans, int r, int c, TrieNode* node) {
        int m = board.size(), n = board[0].size();
        if (!node->word.empty()) {
            ans.push_back(node->word);        // ③ collect the answer
            node->word.clear();               // ④ clear it, so no duplicates
        }

        for (auto& [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            if (board[nr][nc] == '#' || !node->child[board[nr][nc] - 'a']) continue;  // ⑤ prune

            char cache = board[nr][nc];
            board[nr][nc] = '#';
            search(board, ans, nr, nc, node->child[cache - 'a']);
            board[nr][nc] = cache;            // ⑥ restore
        }
    }
};

insert stores the whole word at its last node, instead of an isWord flag. The main loop only starts a search if the root has a child for that letter. Inside search, the check !node->child[...] is the trie pruning — the same check, one level deeper.

One thing worth flagging — the order inside search. I mark the neighbor '#' before I recurse, and I pass node->child[cache - 'a']. I have to use cache there, not board[nr][nc], because that cell is already '#', and '#' - 'a' would be a bad index.

Let me think about complexity here.

Building the trie is O(Σ|word|). The search is O(m · n · 4 · 3L−1), where L ≤ 10 is the longest word. The first step has 4 ways to go; after that I came from one side, so only 3 are left.

In the worst-case scenario the board is all one letter and the words share a long start. On a 12×12 board of all 'a', with 25 words that are nine a's plus one other letter, nothing is found. Per-word search made about 47,091,600 calls; the trie made about 741,120, because the words share their first 9 letters.

Space is O(Σ|word|), plus O(L) for the recursion.

Follow-up: prune found words out of the trie. After I find a word, I clear it, but its nodes stay, so later searches still walk dead paths. The fix: each node keeps cnt, the number of its children. After a node's children are done, if it has no children and no word left, I delete it and lower the parent's cnt — that's why dfs takes the parent. When root->cnt hits 0, every word is found, so I return early.

class TrieNode {
public:
    TrieNode *child[26] = { nullptr };
    string word = "";
    int cnt = 0;
};

class Solution {
public:
    TrieNode *root;
    int m, n;
    vector<string> ans;
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    vector<string> findWords(vector<vector<char>>& board, vector<string>& words) {
        root = new TrieNode();
        for (auto& w : words) insert(w);

        m = board.size(), n = board[0].size();
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (root->cnt == 0) return ans;
                dfs(board, i, j, root);
            }
        }
        return ans;
    }

    void insert(string& w) {
        TrieNode *cur = root;
        for (char& c : w) {
            int i = c - 'a';
            if (!cur->child[i]) {
                cur->child[i] = new TrieNode();
                cur->cnt++;
            }
            cur = cur->child[i];
        }
        cur->word = w;
    }

    void dfs(vector<vector<char>>& board, int r, int c, TrieNode* parent) {
        if (r < 0 || r >= m || c < 0 || c >= n) return;
        char ch = board[r][c];
        if (ch == '#') return;

        TrieNode *node = parent->child[ch - 'a'];
        if (!node) return;

        if (!node->word.empty()) {
            ans.push_back(node->word);
            node->word.clear();
        }

        board[r][c] = '#';
        for (auto& [dr, dc] : dirs) dfs(board, r + dr, c + dc, node);
        board[r][c] = ch;

        if (node->cnt == 0 && node->word.empty()) {
            delete node;
            parent->child[ch - 'a'] = nullptr;
            parent->cnt--;
        }
    }
};

There's a trade-off here. Pruning only helps when words are actually found. On an all-a board where every word is found, visits drop from about 1.9 million to 10. But when a word is never found, its path stays, the visits are the same, and it's slower.

Oh, one more thing — the Big-O stays the same; pruning changes the real work, not the bound.
