範例 Trace// 官方範例 2 · ab / cd · ["abcb"]

程式碼頁走過了範例 1;這裡看範例 2 —— 為什麼「b 用兩次」會被擋下來。Trie 只有一條鏈 a → ab → abc → abcb。實跑插樁輸出。

// 起點 (0,0) 'a':root 有 a board[0][0] = '#' #1 search(0,0, "a") 上 出界、下 (1,0)='c' —— a 只有子節點 b → 剪 左 出界、右 (0,1)='b' → 標 #,進去
// 第二層 (0,1):要找 'c' #2 search(0,1, "ab") 上 出界、下 (1,1)='d' → ab 只有子節點 c → 剪 左 (0,0)='#' → 跳過、右 出界 → 還原 (0,1),再還原 (0,0)
// 其餘起點 (0,1) 'b'、(1,0) 'c'、(1,1) 'd' root 只有子節點 a → 3 格都跳過 // OUTPUT: [](2 次 search)
ab 之後要找 c,但 (0,1) 的鄰格只有 (0,0) 和 (1,1):一個是 '#'、一個是 d —— Trie 在第 3 個字母就剪掉了。 就算 c 接得上,"abcb" 最後的 b 只能是同一格 (0,1),它已經在路徑上、是 '#',一樣過不去。這就是 '#' 擋「一格用兩次」的工作。

應用題// APPLY IT

App 1. 改成可以走斜角(8 個方向)。程式要改哪裡?複雜度變多少?
App 2. words 只有 1 個字、board 是 12×12。還值得建 Trie 嗎?words 有 3 萬個、但全部都找不到呢?
App 3. 題目改成「回傳每個字能用幾條不同路徑拼出來」。Q2、Q3 的兩條規則(收完清空、找到不停)哪一條要改?
// ANSWERS
A1. 走到終點時要知道「是哪個字」才能放進 ans;存整個字就不用一路帶著 path 字串。

用 isWord 的話,search 得多一個參數 path,每往下一層就 path + c 複製一次字串。存在節點上,收答案只要 ans.push_back(node->word);非空字串也同時扮演 isWord 的角色(題目保證字長 ≥ 1,空字串不會是答案)。
A2. 同一個字可能被不同起點、不同路徑走到不只一次;不清空就會重複收。

實測拿掉 clear,隨機 5,000 組錯 2,585 組 —— 幾乎一半。最小反例:board ["aa"]、words ["a"] → ["a","a"],兩個起點各收一次。

清空之後,那個節點對之後的走訪來說就是普通的前綴節點,不影響更長的字。
A3. 不能:這個節點下面可能還有更長的字。

實測把 return; 加在 clear 後面,隨機 20,000 組錯 651 組。最小反例:board 兩列 b / a、words ["a","ab"] → 只回傳 ["a"](正解還有 "ab"):從 a 出發收到 "a" 就回去了,沒往上走到 b。79 能 return 是因為只有一個字;這裡一個節點同時是一個字的終點、另一個字的前綴。
A4. search 只會標「鄰格」;起點是 findWords 直接交給它的,沒人標它,它就可能在同一個字裡被走回來第二次。

實測拿掉起點的標記,隨機 5,000 組錯 829 組。最小反例:board ["aa"]、words ["aaa"] → 回傳 ["aaa"](正解 []):從 (0,0) 走到 (0,1),再走回沒被標過的 (0,0)。

規則和 79 一樣:「進到一格之前就把它標成 '#'」,起點也不例外。
A5. 剪葉子只能拔「字已經收走、而且下面沒東西」的節點;字從沒被找到,就沒有任何節點能拔。

全 a 那組,第一個起點就把 a … a10 全收走,整條鏈被拔光、root->cnt 歸零 → 10 次就結束。換成 a … a9 + aaaaaaaaab:board 沒有 b,那條鏈永遠留著,兩版都是 741,120 次;剪葉子版還多付「每個方向先呼叫、進去才判斷出界 / null」的成本,12.8 → 21.2 ms。
A-App 1. 只改 dirs,加上 4 個斜角 {-1,-1},{-1,1},{1,-1},{1,1};其他邏輯不動。

第一步最多 8 個方向,之後最多 7 個(來的那格是 '#'),複雜度變成 O(mn · 8 · 7L−1)。Trie 剪枝照樣有效,實際上只有字典裡存在的前綴才會展開。
A-App 2. 1 個字:直接跑 79 就好,Trie 只有一條鏈,沒有前綴可以共享。3 萬個字但都找不到:Trie 反而最划算 —— 每個字一走到 board 上接不下去的字母就被剪掉,共用的前綴也只走一次。

每字一次 79 的成本和字數成正比(程式碼頁實測 25 個找不到的字就要 4,709 萬次);Trie 不管字多少,搜尋次數只看 board 上「真的存在的前綴」。字很多、彼此共用前綴、又常常找不到,正是 Trie 的主場。
A-App 3. 「收完清空」要拿掉 —— 每條路徑都要算;「找到不停」保留。

把 ans 換成 unordered_map<string,int> cnt,走到存了字的節點就 cnt[node->word]++,不清空。剪葉子也不能用了(字收到還要再算)。注意:不同起點、不同方向走出的相同字母序列都算不同路徑,所以全 a 這種 board 次數會非常大。
