題目簡介// THE QUESTION

QUESTION

給一串會議時間 [start, end],一個人能不能全部參加?一場在 5 點結束、另一場 5 點開始,算來得及。
0 ≤ intervals.length ≤ 10⁴,0 ≤ start < end ≤ 10⁶。(LeetCode 上是會員題;NeetCode 上可以免費寫。)

範例:[[0,30],[5,10],[15,20]] → false([0,30] 和另外兩場都撞);[[7,10],[2,4]] → true。

能全部參加 ⇔ 任兩場都不重疊。 排好序之後,不用比 n² 對:每一場只要和「前面所有會議裡最晚的結束時間」比一次就知道。

核心策略 · 三步驟// THE LOOP

  1. 空的直接 true,然後排序 —— 你的寫法按終點 a[1] < b[1](按起點也對,第 5 節)。
  2. e = 目前為止最晚的結束時間,從第一場的結束開始。
  3. 往後掃 —— intervals[i][0] < e:這場在前面某場結束前就開始了,return false;否則更新 e。全部掃完 return true。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 碰到不算衝突:條件是嚴格的 <

前一場 4 點結束、下一場 4 點開始,來得及。所以衝突是 intervals[i][0] < e,不是 <=。 寫成 <=:[[0,1],[1,2]] 會回傳 false(正解 true)。兩個官方範例都會過(實跑),因為範例裡沒有剛好碰到的情況。

LEMMA 2 · 按終點排序時,max 其實是多餘的

按終點排好之後,後面那場的終點一定 ≥ 前面所有場,所以 max(intervals[i][1], e) 永遠等於 intervals[i][1]。寫 e = intervals[i][1] 一樣對(54,241 組 0 錯)。 留著 max 也沒錯。按起點排時,理論上 e 可能被一場短會議往回拉,但那一定是重疊、當場就 return 了 —— 所以實測按起點 + 不取 max 也 0 錯(複習頁第 3 題)。

正確性證明// PROOF OF CORRECTNESS

要證明什麼 · CLAIM

程式回傳 false ⇔ 存在兩場會議重疊。

PROOF · 手法:兩個方向各證一次
  1. 回傳 false ⇒ 真的有重疊。在第 i 場回傳 false 時,start_i < e,而 e 是前面某一場 k 的終點。按終點排,end_k ≤ end_i;又 start_k < end_k、start_i < end_k —— 兩場的較晚開始 < 較早結束,重疊。
  2. 有重疊 ⇒ 一定會回傳 false。設 j 排在 k 前面(end_j ≤ end_k)、兩者重疊,即 start_k < end_j。掃到 k 時(如果還沒提早 return),e ≥ end_j,所以 start_k < e,回傳 false。
  3. 做完。兩個方向都成立,所以回傳值正確。程式只在「已經確定有重疊」時提早結束,不會漏掉也不會誤判。
面試這樣說 · 30 秒

能全部參加,等於任兩場都不重疊。我先排序,記住目前為止最晚的結束時間 e。往後每一場,如果它在 e 之前就開始,代表和前面某一場撞了,直接回 false;否則更新 e。結束時間等於開始時間不算撞。排序 n log n,掃描是線性的。

複雜度// COMPLEXITY

T = O(n log n)　　S = O(1) 額外

排序 O(n log n),掃描 O(n)。只多用 n、e、i 三個 int;sort 原地排,本身要 O(log n) 遞迴空間。

一句洞察// INSIGHT

排好序,每一場只要和「前面最晚的結束時間」比一次。 起點 < e 就撞;碰到不算撞。只問有沒有衝突,按起點、按終點排都對。
