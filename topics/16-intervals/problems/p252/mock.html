A naive approach would compare every pair, which is O(n²), about 5 × 10⁷ pairs here.

This problem reminds me of a sort-then-sweep pattern. Once the meetings are sorted, each one only needs to be compared with the latest end time seen so far. If it starts before that, it clashes with some earlier meeting.

Here's the plan, in three steps.

// any overlap? compare with the latest end so far
if empty: return true
sort; e = first end
for each next meeting x:
  if x.start < e: return false
  e = max(e, x.end)
return true

If the list is empty, return true. Sort, and let e be the first meeting's end. Then for each next meeting, if it starts before e, return false; otherwise update e.

One thing worth flagging — the comparison is strictly <, because back-to-back meetings are allowed.

Alright. Empty check, sort by end with a lambda, then one loop.

class Solution {
public:
    bool canAttendMeetings(vector<vector<int>>& intervals) {
        if (intervals.empty()) return true;

        sort(intervals.begin(), intervals.end(), [&](auto& a, auto& b) {
            return a[1] < b[1];
        });

        int n = intervals.size(), e = intervals[0][1];

        for (int i = 1; i < n; i++) {
            if (intervals[i][0] < e) return false;
            e = max(intervals[i][1], e);
        }

        return true;
    }
};

If the current start is less than e, I return false right away. Otherwise e becomes the max of the current end and e. When sorted by end that max is always the current end, so it's just a safety net.

The easy line to forget is the empty check. Without it, reading the first meeting is undefined behavior: with the address sanitizer it crashes, and without it, it happened to print true, which is worse because it hides the bug.
