PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
拿掉 sort,只照輸入順序掃,哪個官方範例會錯?為什麼?
解答與說明 · ANSWER▾
範例 2 [[7,10],[2,4]] 會回傳 false(正解 true):e = 10,下一場 [2,4] 的起點 2 < 10,被誤判成衝突。

「起點 < e 就衝突」只有在排好序時才成立:排好序代表後面的會議不會整場跑到前面去。沒排序時,[2,4] 其實在 [7,10] 之前就結束了,根本沒撞。窮舉 54,241 組裡錯 382 組。
第 2 題10 分
衝突條件寫成 intervals[i][0] <= e,哪種輸入會錯?官方範例抓得到嗎?
解答與說明 · ANSWER▾
剛好接起來的會議會錯:[[0,1],[1,2]] → false,正解 true。兩個官方範例都抓不到(實跑都過)。

一場 1 點結束、下一場 1 點開始,人來得及。範例裡沒有這種剛好碰到的情況,所以要自己加測。窮舉錯 418 組。
第 3 題10 分
按終點排序時,e = max(intervals[i][1], e) 的 max 是必要的嗎?換成按起點排序呢?
解答與說明 · ANSWER▾
兩種都不是必要的,實測拿掉 max 都 0 錯。按終點排時,後面的終點本來就比較大;按起點排時,能讓 e 變小的只有「整場被前一場包住」的會議,而那一定是衝突,程式已經在前一行 return false 了。

留著 max 是無害的保險:它讓 e 的意思永遠是「前面最晚的結束時間」,不用再去想排序方式。這和 56 Merge Intervals 不同 —— 那裡遇到重疊不會 return,max 就不能省。
第 4 題10 分
這題按起點或按終點排序都對,但 435 按起點排會錯。差別在哪裡?
解答與說明 · ANSWER▾
435 要「挑」出最多個不重疊的,遇到重疊要決定留誰,留錯就少一個;這題只問「有沒有」重疊,一遇到就 return false,不用做選擇。

排序鍵決定的是貪心「先看到誰、先留誰」。不用選的時候,哪一端排都能把所有衝突找出來。實測:這題按起點 0 / 54,241 錯;435 按起點錯 11,592 / 111,110。
第 5 題10 分
第一行 if (intervals.empty()) return true; 拿掉會怎樣?
解答與說明 · ANSWER▾
空輸入時 intervals[0][1] 會讀不存在的元素,是未定義行為。實測開 ASan 直接 SEGV;不開 ASan 用 -O2 剛好印出 true。

「剛好跑對」最危險:本機看起來正常,換編譯器或測資就可能崩潰。這題 n 可以是 0,所以這行一定要有;如果題目保證 n ≥ 1(像 56),才可以省。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
手走官方範例 1 [[0,30],[5,10],[15,20]] 兩次:按終點排序(你的寫法)、按起點排序。兩次都回傳 false,但在不同的 i 停下來 —— 各在哪裡?
解答與說明 · ANSWER▾
// 按終點排序 sorted: [5,10] [15,20] [0,30] e = 10 i=1 [15,20] 15 < 10 ? no → e = 20 i=2 [0,30] 0 < 20 ? yes → return false // OUTPUT: false(在 i = 2 停)
// 按起點排序 sorted: [0,30] [5,10] [15,20] e = 30 i=1 [5,10] 5 < 30 ? yes → return false // OUTPUT: false(在 i = 1 停)
按起點排,長會議 [0,30] 排第一、e 一開始就是 30,馬上撞到;按終點排,它排最後,要掃到底才撞到。 停的位置不同,但「有沒有衝突」的答案一樣 —— 這就是第 4 題說的:只問有沒有,排序鍵不重要。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
如果不能全部參加,最少要取消幾場會議,剩下的才能全部參加?這題和本題是什麼關係?
解答與說明 · ANSWER▾
就是 435 Non-overlapping Intervals:按終點排序,能留就留,回傳 n − 留下的個數。本題回傳 true ⇔ 435 的答案是 0。

兩題的程式幾乎一樣,差別只在遇到衝突時:本題直接 return false;435 把這場丟掉、答案 +1、繼續掃。隨機 100,000 組對拍,「本題回傳 true」和「435 回傳 0」完全一致。
第 8 題14 分
改成問:如果每個會議室同時只能開一場會,最少需要幾間會議室?(Meeting Rooms II 的題目)
解答與說明 · ANSWER▾
答案是「同一時刻最多有幾場會在開」。把所有起點排序、所有終點排序,用兩個指標往前走:每遇到一個起點,先把終點 ≤ 這個起點的會議都結束掉(房間釋放),再開這一場,記錄同時進行的最大值。

碰到一樣不算重疊,所以是 end <= start 就先釋放。官方範例 1 → 2 間,範例 2 → 1 間。和「在時間軸上逐點數有幾場」的暴力解對拍 100,000 組 0 錯。本題就是「答案是不是 1 間」的特例。
第 9 題14 分
行程表已經排好、沒有衝突(按時間排序存著)。現在要新增一場 [s, e],怎麼最快判斷能不能排進去?
解答與說明 · ANSWER▾
不用重新排序、也不用整串掃:排好又不重疊 ⇒ 終點也是遞增的,二分搜尋第一場「終點 > s」的會議,它不存在或它的起點 ≥ e,就排得進去。O(log n)。

注意這題碰到不算衝突,所以是「終點 > s」、「起點 ≥ e」;57 Insert Interval 複習頁第 8 題是碰到也算衝突的版本(那裡的條件是 ≥ 和 >)。和「每一場都檢查」對拍 100,000 組(行程表裡也有剛好接起來的會議)0 錯。每次新增都重跑一次本題要 O(n log n),二分快得多。
