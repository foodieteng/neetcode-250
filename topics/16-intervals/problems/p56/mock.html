A naive approach would compare every pair and merge until nothing changes. That's at least O(n²), and one merge can create new overlaps, so it repeats. I could also mark every covered point on a number line, but then the speed depends on the coordinate range.

This problem reminds me of a sort-then-sweep pattern. Once the intervals are sorted by start, a single left-to-right pass is enough, because only the newest group can still grow.

// invariant: res = merge of everything seen, sorted
sort intervals by start
res = [intervals[0]]
for each next interval x:
  if res.back().end >= x.start:  res.back().end = max(…)
  else:  push x

Sort by start. Put the first interval in the result. Then for each next interval, if the last group's end reaches its start, extend that end to the larger of the two; otherwise push it as a new group.

One thing worth flagging — compare against the last group in the result, not the previous input interval, and always take the max for the end.

Alright. Sort, seed the result with the first interval, then one loop.

class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        int n = intervals.size();
        sort(intervals.begin(), intervals.end());

        vector<vector<int>> res;
        res.push_back(intervals[0]);

        for (int i = 1; i < n; i++) {
            if (res.back()[1] >= intervals[i][0]) {
                res.back()[1] = max(res.back()[1], intervals[i][1]);
            } else {
                res.push_back(intervals[i]);
            }
        }

        return res;
    }
};

If the result's last end is >= the current start, I set that end to the max of the two. Otherwise I push the current interval.

The easy line to get wrong is that max. Sorting only orders the starts; ends can go down. With [1,10] followed by [2,3], a plain assignment shrinks the group to [1,3]. And both official examples still pass with that bug, because neither has an interval inside another.

After sorting, [1,9] swallows [2,6] and [3,4], and the end stays at 9 thanks to the max. The moment that matters is [8,10]: 9 reaches 8, so the group grows to 10. Then 12 is past 10, so a new group.

Corner cases:

• A single interval comes back as is.
• All identical intervals become one.
• Nested intervals collapse into the outer one.
• Disjoint points stay separate.
