題目簡介// THE QUESTION

QUESTION

有 n 間會議室,編號 0 到 n − 1。會議 [start, end)(不含 end)照下面三條規則分配:
① 有空房就用編號最小的空房;② 沒有空房,會議延後到有房間空出來,長度不變;③ 有房間空出來時,原本開始時間較早的會議先拿。
回傳開最多場會議的房間編號,平手回傳編號最小的。
1 ≤ n ≤ 100,1 ≤ meetings.length ≤ 10⁵,0 ≤ start < end ≤ 5 × 10⁵,所有 start 都不同。

範例:n = 2, [[0,10],[1,5],[2,7],[3,4]] → 0;n = 3, [[1,20],[2,10],[3,5],[4,9],[6,8]] → 1。

照開始時間模擬,但「挑房間」有兩種完全不同的規則,所以要兩個 heap。 有空房時比的是編號(freeRoom:編號的 min-heap);沒空房時比的是誰先空出來(usedRoom:{結束時間, 編號} 的 min-heap)。
2

為什麼要兩個 heap// WHY TWO HEAPS

A 一個 heap 存 {可用時間, 編號} O(m log n)
每場拿 top 那間。但好幾間都已經空了的時候,top 是「最早空出來的」,不是「編號最小的」。n = 2, [[0,3],[1,2],[3,4]]:時間 3 兩間都空,它挑了房 1,正解是房 0 → 回傳 1(應為 0)。窮舉錯 297 組,兩個官方範例都過。
× REJECT · 規則 ① 錯
B 每場掃一遍 n 間房 O(m log m + m · n)
記每間房什麼時候空,每場從編號 0 掃到 n − 1:有空的就用,都沒空就挑最早空的。正確(驗證時拿它當參考解),而且 n ≤ 100 時也夠快 —— 但速度綁在 n 上。
△ 能用 · n 小才行
TWO HEAPS · ADOPT
C freeRoom(編號)+ usedRoom({結束, 編號}) O(m log m + m log n)
兩種規則各用一個 heap,每次挑房間都是 O(log n)。和 B 比對:n = 1–3、最多 5 場會議的所有組合共 10,098 組,加上隨機 50,000 組(n ≤ 6、最多 30 場),0 筆不一致。
● ADOPT · 兩條規則各一個 heap
3

核心策略 · 三步驟// THE LOOP

  1. 按起點排序,所有房間編號放進 freeRoom。
  2. 每場會議 [s, e) 開始前,先釋放 —— usedRoom 裡結束時間 ≤ s 的房間,編號放回 freeRoom。
  3. 分配 —— freeRoom 有房就拿 top(編號最小);沒有就從 usedRoom 拿 top(最早空、同時空取編號小),會議延後:e = end + (e − s)。房間的 freq +1,{e, 編號} 放回 usedRoom。最後回傳 freq 最大的編號。

和 253 Meeting Rooms II 同一個骨架:按起點掃、usedRoom 存結束時間、結束 ≤ 現在就釋放。253 的房間沒有編號、也不會不夠,所以一個 heap 就夠;這題房間數固定、要記編號,才多了 freeRoom 和「延後」。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 兩個平手規則,都不用額外寫程式

同時空出來的房間取編號小的:pair<long long, int> 先比 first(結束時間),一樣再比 second(編號),greater<> 讓小的在 top —— 自動做到。如果自己寫 comparator 只比結束時間,就會錯(窮舉 6 組,兩個官方範例都過)。
freq 平手取編號小的:max_element 回傳第一個最大值。 官方範例 1 兩個平手都會遇到:[3,4) 要在 {10, 0} 和 {10, 1} 之間選,最後 freq = [2, 2]。

LEMMA 2 · 延後會一直累加,結束時間要 long long

沒有空房時,會議從 end 開始、長度 e − s 不變,所以 e = end + (e − s)。被延後的會議又會讓後面的會議延更久。 n = 1、10⁵ 場 [k, 500000]:最後一場結束在 45,000,050,000,從第 4,313 場起就超過 int 上限(實測)。用 int 的版本在 n = 2 的同一組輸入回傳 1,正解 0。

正確性證明// PROOF OF CORRECTNESS

要證明什麼 · CLAIM

按起點一場一場處理,兩個 heap 的分配結果和題目的三條規則完全一樣。

PROOF · 手法:每一步對照規則
  1. 規則 ①。處理 [s, e) 時,先把結束 ≤ s 的房間全放回 freeRoom,所以 freeRoom 剛好是「時刻 s 沒人用的房間」;它的 top 是其中編號最小的。
  2. 規則 ②。freeRoom 空的時候,每間房都要等;usedRoom 的 top 是最早空出來的那間(同時空取編號小的),會議從它空的那一刻開始、長度不變。
  3. 規則 ③。會議是照原本的開始時間處理的,所以比較早的會議一定先拿到房間 —— 不需要另外一個「等待隊伍」。
面試這樣說 · 30 秒

我按開始時間模擬。用兩個 min-heap:一個放空房的編號,一個放使用中房間的結束時間和編號。每場會議開始前,先把已經結束的房間放回空房堆;有空房就用編號最小的,沒有就等最早空出來的那間,會議整段往後延,所以結束時間要用 long long。每間房記開了幾場,最後回傳最多的,平手取編號小的。

複雜度// COMPLEXITY

T = O(m log m + m log n)　　S = O(n)

m = 會議數、n = 房間數。排序 O(m log m);每場會議最多進出兩個 heap 各一次,heap 最多 n 個元素。

部分成本說明
排序O(m log m)瓶頸,m 到 10⁵
heap 操作O(m log n)兩個 heap 加起來永遠剛好 n 個元素
空間O(n)兩個 heap + freq
實測約 8–21 msm = 10⁵(含排序)

一句洞察// INSIGHT

有空房比編號、沒空房比誰先空 —— 兩條規則,兩個 heap。 延後的會議長度不變、結束時間會累加超過 int;兩個平手規則靠 pair 的比較和 max_element 自動處理。
