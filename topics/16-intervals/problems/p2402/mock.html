This problem reminds me of an event simulation with priority queues. Since there are two selection rules, I use two min-heaps: one of free room numbers, and one of busy rooms keyed by end time, then room number.

Here's the plan, in three steps.

// two rules, two min-heaps
sort by start; freeRoom = {0 … n−1}
for each meeting [s, e):
  move busy rooms with end <= s back to freeRoom
  if freeRoom empty: take earliest busy room, e = end + (e − s)
  take freeRoom.top() (lowest id), freq[id]++
return position of max freq

Sort by start. Before each meeting, move every busy room that ends at or before its start back to the free heap. Then, if a room is free, take the lowest number; otherwise take the busy room that frees first and delay the meeting to start there.

One thing worth flagging — rule three, earlier meetings first, comes for free, because I process meetings in start order.

Alright. Two priority queues and a count per room.

class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end());
        priority_queue<int, vector<int>, greater<int>> freeRoom;
        priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> usedRoom;  // {end, id}
        vector<int> freq(n, 0);

        for (int i = 0; i < n; i++) freeRoom.push(i);

        for (auto& v : meetings) {
            long long s = v[0], e = v[1];

            while (!usedRoom.empty() && usedRoom.top().first <= s) {
                auto [_, idx] = usedRoom.top(); usedRoom.pop();
                freeRoom.push(idx);
            }

            if (freeRoom.empty()) {
                auto [end, idx] = usedRoom.top(); usedRoom.pop();
                e = end + (e - s);
                freeRoom.push(idx);
            }

            int idx = freeRoom.top(); freeRoom.pop();
            freq[idx]++;
            usedRoom.push({e, idx});
        }

        return max_element(freq.begin(), freq.end()) - freq.begin();
    }
};

In the delay case, I pop the earliest busy room, set the new end to its end plus the meeting's length, and put the room back into the free heap, so both cases share the same assignment code. At the end I return the position of the max count, not the count itself.

The easy lines to get wrong are the three I actually got wrong at first: returning the count, using a max-heap for free rooms, and storing the end in an int. The last one only fails on large inputs.
