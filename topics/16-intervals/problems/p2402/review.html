PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼不能只用一個 heap 存所有房間的 {可用時間, 編號},每次拿 top 就好?
解答與說明 · ANSWER▾
因為有好幾間都已經空了的時候,題目要的是編號最小的,但這個 heap 的 top 是「最早空出來的」。n = 2, [[0,3],[1,2],[3,4]]:時間 3 時房 0(3 空)、房 1(2 空)都空,單一 heap 挑房 1,正解要房 0 → 回傳 1(應為 0)。

空了以後,先空還是後空已經不重要,只看編號;還沒空時才比誰先空。兩種比法不同,所以要兩個 heap。窮舉 10,098 組裡錯 297 組,兩個官方範例都會過。
第 2 題10 分
題目的時間最大只有 5 × 10⁵,為什麼結束時間還是要用 long long?
解答與說明 · ANSWER▾
因為延後會累加。n = 1、10⁵ 場 [k, 500000]:每場都要等前一場結束,最後一場結束在 45,000,050,000,從第 4,313 場起就超過 int 上限(約 2.1 × 10⁹)。

用 int 的版本在 n = 2 的同一組輸入回傳 1,正解 0。這個錯小測資完全抓不到(窮舉 0 錯),官方範例也過 —— 只能靠估最大值:最多 10⁵ 場 × 每場最長 5 × 10⁵。
第 3 題10 分
return *max_element(freq.begin(), freq.end()); 錯在哪?兩間房開的場數一樣時要回傳哪一間?
解答與說明 · ANSWER▾
它回傳「最多開了幾場」,題目要的是「哪一間」:要寫 max_element(…) - freq.begin()。平手時回傳編號小的,而 max_element 本來就回傳第一個最大值,剛好符合。

這個錯兩個官方範例都會抓到(回傳 2、2,正解 0、1),窮舉全錯。官方範例 1 的 freq 是 [2, 2],平手取 0。
第 4 題10 分
規則 ③ 說:有房間空出來時,原本開始時間較早的會議先拿。程式裡沒有「等待隊伍」,這條規則怎麼滿足的?
解答與說明 · ANSWER▾
會議是按原本的開始時間排序後一場一場處理的。被延後的會議在處理它的那一刻就直接拿走最早空出來的房間,比它晚開始的會議還沒被處理,不可能插隊。

所以「先處理」就等於「先拿」。如果拿掉 sort,這條規則就壞了:n = 2, [[2,3],[1,2],[0,1]] → 1,正解 0;窮舉錯 3,896 組。
第 5 題10 分
釋放的條件是 usedRoom.top().first <= s。寫成 < 會怎樣?
解答與說明 · ANSWER▾
會議是 [start, end),end 那一刻房間已經空了,下一場可以剛好在 end 開始。寫成 < 時,n = 2, [[3,4],[1,2],[0,3]] 回傳 1,正解 0。兩個官方範例都會過;窮舉錯 237 組。

[0,3) 在 3 結束,[3,4) 在 3 開始:≤ 會把房 0 放回去給它用;< 不會,只好用房 1,房 1 就多了一場。和 253 的「碰到可以接著用」是同一件事。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
手走官方範例 1:n = 2, [[0,10],[1,5],[2,7],[3,4]]。每一場分到哪一間、什麼時候開始?兩個平手規則各在哪一步用到?
解答與說明 · ANSWER▾
// n = 2 [0,10) free {0,1} → 房 0 used {10,0} [1,5) free {1} → 房 1 used {5,1} {10,0} [2,7) free 空 → 等 {5,1}:e = 5 + 5 = 10 → 房 1,5 點開始 used {10,0} {10,1} [3,4) free 空 → 等 {10,0}:e = 10 + 1 = 11 → 房 0,10 點開始 used {10,1} {11,0} // OUTPUT: 0(freq [2,2],平手取 0)
[3,4) 要在 {10,0} 和 {10,1} 之間選:兩間同時在 10 空,pair 比編號,選房 0。 最後 freq = [2, 2] 又平手,max_element 回傳第一個,答案 0。這組範例同時考了兩個平手規則。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
n ≤ 100。如果面試時一時想不到兩個 heap,有沒有更直接的寫法?複雜度多少?
解答與說明 · ANSWER▾
開一個陣列 busyUntil[n](long long)。每場會議從房 0 掃到房 n − 1:第一間 busyUntil ≤ s 的就用;一間都沒有,就用 busyUntil 最小的(同樣小取編號小),會議從那時開始。O(m log m + m · n)。

n ≤ 100 時是 10⁷ 等級,夠快,而且規則 ① ② 照字面寫,很難寫錯 —— 這份筆記驗證時就是拿它當參考解。面試可以先寫這版,再說明 n 大時用兩個 heap 降到 O(m log n)。
第 8 題14 分
除了答案,還想知道每場會議實際的開始時間。要改哪裡?
解答與說明 · ANSWER▾
開始時間只有兩種:有空房時就是 s;沒空房時是等到的那間的 end。在 if 裡記下 start = end,否則 start = s,和 e 一起存起來就好。

官方範例 2:[4,9) 實際 5 點開始(等房 2)、[6,8) 實際 10 點開始(等房 1),其他三場準時。延後量就是 start − s,概念頁動畫裡紅框的「延後 1」、「延後 3」就是這個數字。
第 9 題14 分
和 253 Meeting Rooms II(最少要幾間房)有什麼關係?n 要多大,這題才不會有任何會議被延後?
解答與說明 · ANSWER▾
沒有會議被延後 ⇔ n ≥ 253 的答案(同一時刻最多幾場在開)。隨機 100,000 組會議 × n = 1–8 共 800,000 組對拍,0 筆不一致。

兩題同一個骨架:按起點掃、usedRoom 存結束時間、結束 ≤ 現在就釋放。253 假設房間要多少有多少,只問最多同時用幾間;這題房間數固定,不夠時才需要「延後」,還要記每間的編號和次數。
