Minimum Interval to Include Each Query

// CONCEPT · 離線排序 + 依長度的 min-heap + 延遲刪除

1

題目簡介// THE QUESTION

QUESTION

給一堆區間 intervals[i] = [left, right](兩端都包含),長度是 right − left + 1。
對每個 queries[j],回傳包含它的區間裡最短的長度;沒有區間包含它就回傳 -1。答案要照 queries 原本的順序。
1 ≤ intervals.length, queries.length ≤ 10⁵,1 ≤ left ≤ right ≤ 10⁷,1 ≤ queries[j] ≤ 10⁷。

範例:intervals = [[1,4],[2,4],[3,6],[4,4]], queries = [2,3,4,5] → [3,3,1,4];intervals = [[2,3],[2,5],[1,8],[20,25]], queries = [2,19,5,22] → [2,-1,4,6]。

queries 可以自己決定處理順序(離線):由小到大掃,區間就能「進場一次、退場一次」。 按 start 讓區間進場,heap 用長度排,top 是候選裡最短的;top 的 right 已經在 q 左邊就丟掉 —— q 只會變大,丟掉的永遠不會再用到。

為什麼 heap 要用長度排// WHY A SIZE-KEYED HEAP

A 每個 query 掃一遍所有區間 O(n · q)
直接照定義:包含 q 的區間裡取最短。正確(驗證時拿它當參考解),但 n、q 都到 10⁵,是 10¹⁰ 次比較。
× REJECT · TLE
B heap 存 {right, size},用 right 排 O(n log n + q log q)
你的第一版。top 是「最早結束的」,不是「最短的」。intervals = [[1,3],[3,4]], queries = [3]:兩個都包含 3,top 是 [1,3](長度 3),正解是 [3,4] 的 2。窮舉 172,050 組錯 3,124 組,兩個官方範例都過。
△ REJECT · 排錯鍵
BOTH FAIL · ADOPT
C heap 存 {size, right},用 size 排 + 延遲刪除 O(n log n + q log q)
top 永遠是候選裡最短的;過期的只在浮到 top 時才 pop。和 A 對拍:窮舉 172,050 組 + 隨機 50,000 組,0 筆不一致;n = q = 10⁵ 的大測資也和另一種解法(並查集)完全一致。
● ADOPT · 最短的在 top

核心策略 · 三步驟// THE LOOP

  1. 離線排序 —— intervals 按 start 排;queries 不動,另外把下標按值排成 order,答案才能寫回原位置。
  2. 進場 —— 對每個 q(由小到大),把所有 start ≤ q 的區間推進 heap,存 {size, right}。
  3. 退場 + 作答 —— top 的 right < q 就 pop,直到 top 還包含 q 或 heap 空了。ans[qi] = top.size,空了就維持 -1。

區間按 start 排,是因為這題在「沿著數線往右掃」—— 和 253 Meeting Rooms II、2402 Meeting Rooms III 一樣是模擬時間線,所以看 start。不同的是,這裡 heap 裡比的不是結束時間,而是長度。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 延遲刪除:只要 top 有效就夠

heap 裡每個區間都滿足 start ≤ q(進場條件,而且 q 只會變大),所以它包含 q ⇔ right ≥ q。 right < q 的區間對之後更大的 q 也一定無效,丟掉不會後悔。埋在下面的過期區間不用管:它們比 top 長,只要 top 有效就輪不到它們;等它們浮上來時再 pop。 寫成 if 只 pop 一次就不夠:intervals = [[1,1],[1,1]], queries = [2] 回傳 1,正解 -1(窮舉錯 94,660 組)。

LEMMA 2 · 答案要寫回原位置

掃描必須照 q 由小到大,但輸出要照輸入順序。所以排序的是下標 order,不是 queries 本身,作答時寫 ans[qi]。 不排 queries、照輸入順序處理的話,官方範例 2 會變成 [2,-1,-1,6]:先處理了 19,把 heap 裡三個區間全 pop 掉,輪到 5 時已經沒東西了(窮舉錯 88,342 組)。

正確性證明// PROOF OF CORRECTNESS

要證明什麼 · CLAIM

處理到 q 時,pop 完之後的 top(如果有)就是包含 q 的區間裡最短的;heap 空了就代表沒有區間包含 q。

PROOF · 手法:不變量
  1. 進場完整。區間按 start 排、指標 i 只往右,處理 q 時所有 start ≤ q 的區間都已經推過一次;start > q 的一個都沒推。所以包含 q 的區間 = 推過的、而且 right ≥ q 的那些。
  2. 退場安全。被 pop 的區間 right 小於當時的 q,而之後的 q 只會更大,它不可能再包含任何 q。所以「推過且 right ≥ q」的區間全都還在 heap 裡。
  3. top 最短。pop 停下時 top 的 right ≥ q,它包含 q;heap 依 size 排,任何其他還在 heap 裡的區間(不論是否過期)都不比它短。所以它就是答案;heap 空了表示沒有任何區間包含 q。
面試這樣說 · 30 秒

我離線處理:queries 的下標按值排序,區間按左端點排序。由小到大掃每個 query,把左端點不超過它的區間推進一個 min-heap,用長度排,同時記右端點。接著只要 top 的右端點在 query 左邊就 pop,因為 query 只會變大,這些區間以後也用不到。剩下的 top 就是包含這個 query 的最短區間,沒有就是 -1,答案寫回原本的位置。

複雜度// COMPLEXITY

T = O(n log n + q log q)　　S = O(n + q)

n = 區間數、q = query 數。兩次排序;每個區間最多 push 一次、pop 一次,各 O(log n)。

部分成本說明
排序O(n log n + q log q)intervals 按 start、query 下標按值
heap 操作O(n log n)每個區間進出各一次,和 q 無關
空間O(n + q)heap 最多 n 個(實測峰值 10⁵);order、ans 各 q 個

一句洞察// INSIGHT

queries 由小到大掃:按 start 進場,按長度挑最短,right < q 才退場。 heap 的第一個鍵決定 top 是誰 —— 要最短就放 size;過期判斷只看 top,因為 q 只會變大。

// ONE-LINE TAKEAWAY
intervals 按 start 排、query 下標按值排;每個 q 推入 start ≤ q 的區間({size, right} min-heap),pop 掉 right < q 的 top,答案 = top.size 或 -1,寫回 ans[qi]。O(n log n + q log q) / O(n + q)。
