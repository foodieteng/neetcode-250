PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
heap 裡存 {right, size}(用右端點排),pop 掉 right < q 之後回傳 top 的 size,錯在哪?舉一個最小的反例。
解答與說明 · ANSWER▾
top 會是「最早結束的」區間,不是「最短的」。intervals = [[1,3],[3,4]], queries = [3]:兩個都包含 3,top 是 right 較小的 [1,3],回傳 3;正解是 [3,4] 的長度 2。

heap 的第一個鍵決定 top 是誰,題目要最短,第一個鍵就要放 size;right 只用來判斷過期。這是你第一版的寫法:窮舉 172,050 組錯 3,124 組,兩個官方範例都會過,所以光跑範例抓不到。
第 2 題10 分
退場只檢查 top,heap 底下可能還埋著已經過期的區間。為什麼這樣不會算錯?為什麼要用 while 不能用 if?
解答與說明 · ANSWER▾
埋在下面的區間都不比 top 短,只要 top 還包含 q,答案就是 top,底下的不會被用到。而 q 只會變大,過期的區間以後也不會再有效,等它浮上 top 時再丟就好。

但 top 過期時,新的 top 也可能過期,所以要一直 pop 到 top 有效或 heap 空。用 if 的版本:intervals = [[1,1],[1,1]], queries = [2] 回傳 [1],正解 [-1];窮舉錯 94,660 組,兩個官方範例都會錯。
第 3 題10 分
為什麼要排 query 的下標,不直接 sort(queries)?如果完全不排、照輸入順序處理,會怎樣?
解答與說明 · ANSWER▾
答案要照輸入順序回傳。直接排 queries 就不知道每個答案該放回哪裡,所以排下標 order,作答時寫 ans[qi]。

完全不排的話,大的 q 先處理會把區間 pop 掉,小的 q 再來時已經沒了。官方範例 2 會變成 [2,-1,-1,6](正解 [2,-1,4,6]);最小反例 [[1,1]], queries = [2,1] → [-1,-1],正解 [-1,1]。窮舉錯 88,342 組。
第 4 題10 分
進場條件是 left <= q,退場條件是 right < q。一個是 ≤、一個是 <,為什麼?各寫錯一邊會怎樣?
解答與說明 · ANSWER▾
區間兩端都包含 q。left 剛好等於 q 要進場,所以是 ≤;right 剛好等於 q 還有效,不能丟,所以只丟 right < q。

兩種寫錯都用同一個反例抓得到:[[1,1]], queries = [1] → [-1],正解 [1]。進場寫成 <,[1,1] 根本沒推進去;退場寫成 ≤,推進去又馬上被丟掉。兩種各錯 123,330 組,兩個官方範例都會錯。
第 5 題10 分
intervals 為什麼要按 left(start)排?改成按 right 排、或乾脆不排,會怎樣?
解答與說明 · ANSWER▾
指標 i 只往右走,遇到第一個 left > q 就停。只有按 left 排,停下來時才保證後面全都 left > q。沒照 left 排,指標會被一個 left 大的區間卡住,後面 left 小的永遠推不進去。

按 right 排:[[1,3],[2,2]], queries = [1] → [-1],正解 [3](窮舉錯 27,185 組)。不排:[[2,2],[1,1]], queries = [1] → [-1],正解 [1](窮舉錯 54,954 組)。兩種兩個官方範例都會過。
這題是沿著數線往右掃,和 2402 模擬時間線一樣看 start;435 按 end 是在挑最多不重疊的區間,目的不同。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
手走官方範例 1:intervals = [[1,4],[2,4],[3,6],[4,4]], queries = [2,3,4,5]。寫出每個 q 之後的 heap((size, right))和答案。如果退場用 if,哪一步會錯?
解答與說明 · ANSWER▾
// 照程式(while) q=2 push (4,4) (3,4) heap {(3,4), (4,4)} → 3 q=3 push (4,6) heap {(3,4), (4,4), (4,6)} → 3 q=4 push (1,4) heap {(1,4), (3,4), (4,4), (4,6)} → 1 q=5 pop (1,4) (3,4) (4,4) heap {(4,6)} → 4 // OUTPUT: [3,3,1,4]
// 錯誤走法:退場用 if q=2..4 和上面一樣 → 3, 3, 1 q=5 只 pop (1,4),top (3,4) 的 right 4 < 5 已經過期,還是拿來當答案 → 3 // OUTPUT: [3,3,1,3]
q = 5 時 right = 4 的三個區間一起過期,要連 pop 三次。 q = 4 時 (1,4)、(3,4)、(4,4) 都還有效(right = 4 = q),這是退場條件用 < 而不是 ≤ 的原因。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
題目改成:回傳那個最短區間在 intervals 裡的下標(有好幾個一樣短就回傳下標最小的)。要改哪裡?
解答與說明 · ANSWER▾
heap 多存一個原始下標:{size, index, right},一樣短時比 index,小的在 top。intervals 排序前要先記下原始下標(例如排 intervals 的下標,和 queries 同一招)。

退場判斷還是看 right;作答改成 ans[qi] = top 的 index。tuple 的比較順序就是平手規則:先比長度,再比下標 —— 和 2402 用 pair 自動處理「同時空出來取編號小」是同一招。
第 8 題14 分
換個角度:不用 heap,改成「區間由短到長處理,每個區間把它範圍內還沒有答案的 query 填上」。怎麼讓每個 query 只被填一次?複雜度多少?
解答與說明 · ANSWER▾
query 照值排好,用並查集記「從這格往右,下一個還沒填的 query 在哪」。區間 [left, right] 用二分找到第一個 ≥ left 的 query,沿著並查集跳,每填一個就把它併到右邊那格,直到值超過 right。

區間由短到長,所以第一個填到 query 的就是最短的。每個 query 只被填一次,總共 O(n log n + q log q + (n + q)·α)。這份筆記驗證大測資(n = q = 10⁵)時就是拿這個解法和主解對拍,結果完全一致。
第 9 題14 分
如果 intervals 事先全部給你,但 queries 是線上一個一個來、要馬上回答(不能先收齊再排序),主解還能用嗎?該怎麼做?
解答與說明 · ANSWER▾
主解不能用:延遲刪除靠的是「q 只會變大」,線上的 q 可大可小,丟掉的區間可能又需要。改成先把整條數線的答案都算好,每個 query 只做查表。

做法:把所有區間端點座標壓縮,數線切成 O(n) 段;區間由短到長,用第 8 題的並查集把每段塗上「第一個蓋到它的長度」。之後每個 query 用二分找到它所在的段,O(log n) 回答。前處理 O(n log n)。
