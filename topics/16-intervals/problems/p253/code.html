完整實作// SORT BY START · MIN-HEAP OF ENDS

你的版本只改一個字:cmp 的 a[1] < b[1] 改成 a[0] < b[0]。其他一行都沒動。

p253.cpp C++17 
class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(), [&](auto& a, auto& b) {
            return a[0] < b[0];   // 按起點(原版 a[1] < b[1] 會錯)
        });

        priority_queue<int, vector<int>, greater<>> pq;
        int room = 0;

        for (auto& v : intervals) {
            while (!pq.empty() && pq.top() <= v[0]) pq.pop();

            pq.push(v[1]);
            room = max((int)pq.size(), room);
        }

        return room;
    }
};

兩個官方範例 → 2、1,都正確。原版(按終點)也是 2、1 —— 範例抓不到它的錯。 修正版和「逐時刻數」的暴力解比對:座標 0–5 上長度 1–5 的所有會議序列共 813,615 組,加上隨機 30,000 組(n ≤ 40),0 筆不一致。原版在同樣 813,615 組裡錯 106,236 組,隨機錯 10,739 組。

每一行各自的意思:

  • priority_queue<int, vector<int>, greater<>>:C++ 的 priority_queue 預設是 max-heap,第三個參數 greater<> 把它變成 min-heap,top() 是最小的結束時間 —— 最早空出來的那間房。
  • while (… pq.top() <= v[0]) pq.pop();:現在是 v[0],結束時間不晚於現在的房間都空了。用 while 是因為可能一次空出好幾間。
  • pq.push(v[1]):這場佔一間,記下它什麼時候空。
  • room = max((int)pq.size(), room):heap 大小 = 此刻在開的場數。(int) 為什麼不能省,下一節。

為什麼要加 (int)// size_t VS int

不加不是答案錯,是根本編譯不過。把 (int) 拿掉,實際用 g++ 編譯:

// g++ -std=c++17,寫成 room = max(pq.size(), room); error: no matching function for call to 'max(std::priority_queue<…>::size_type, int&)' note: deduced conflicting types for parameter 'const _Tp' ('long unsigned int' and 'int')

原因有兩層:

  1. pq.size() 的型別是 size_t。在 64 位元的 Linux 上就是 unsigned long(錯誤訊息裡的 long unsigned int),而 room 是 int。一個無號、一個有號,長度也不同。
  2. std::max 是模板 max(const T& a, const T& b),兩個參數必須是同一個 T。編譯器從第一個參數推出 T = unsigned long,從第二個推出 T = int,兩個對不上,而模板推導不會自動幫你轉型 —— 所以報 conflicting types。

加上 (int) 之後兩邊都是 int,T 就確定了。下面三種寫法都能編譯、官方範例 1 都印出 2(實跑):

寫法說明
max((int)pq.size(), room)你的寫法:C 風格轉型,最短
max(static_cast<int>(pq.size()), room)C++ 風格轉型,意思一樣,比較好搜尋
max<int>(pq.size(), room)直接指定 T = int,不讓編譯器推;size_t 會自動轉成 int

轉成 int 安全嗎?安全:heap 最多 n = 10⁴ 個元素,遠小於 int 上限。反過來「把 int 轉成 size_t」才危險 —— 負數會變成超大的正數。實測:

// size_t s = 3; int r = -1; cout << (s > r); 輸出 0(false) -1 被轉成 size_t,變成 18446744073709551615,比 3 大 g++ -Wall 警告:comparison of integer expressions of different signedness
容器的 .size() 都是 size_t(無號)。和 int 一起丟進 max / min,或互相比大小,先把 size 轉成 int。 max / min 不轉會編譯錯誤(好事,馬上發現);用 < > 直接比卻只會警告,遇到負數就靜靜地算錯 —— 那個比較危險。

細節走讀// WALKTHROUGH · 原版 vs 修正版

同一組 [[0,3],[1,4],[2,7],[5,6]],每一行都是實際印出來的。

// 原版:按終點排序 sorted: [0,3] [1,4] [5,6] [2,7] [0,3] pop — → heap {3} size 1 room 1 [1,4] pop — → heap {3,4} size 2 room 2 [5,6] pop 3, 4 → heap {6} size 1 room 2 現在跳到 5 [2,7] pop — → heap {6,7} size 2 room 2 其實 2 就開始,3、4 那時還在開 // OUTPUT: 2(錯,正解 3)
// 修正版:按起點排序 sorted: [0,3] [1,4] [2,7] [5,6] [0,3] pop — → heap {3} size 1 room 1 [1,4] pop — → heap {3,4} size 2 room 2 [2,7] pop — → heap {3,4,7} size 3 room 3 三間同時在用 [5,6] pop 3, 4 → heap {6,7} size 2 room 3 現在是 5,3、4 真的結束了 // OUTPUT: 3
PREV概念、動畫與起點 vs 終點 NEXT複習考卷
// ONE-LINE TAKEAWAY
按起點排序 → min-heap 存結束時間 → top ≤ v[0] 就 pop → push v[1] → room = max((int)pq.size(), room)。(int) 是因為 size() 是 size_t,std::max 要兩個參數同型別,不轉就編譯錯誤。原版按終點排序兩個官方範例都過,卻錯 106,236 / 813,615 組。
