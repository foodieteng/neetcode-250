It matters a lot. Popping a room means it's already free right now, so now has to move forward, which means processing meetings by start time. If I sort by end, time can jump backward.

With [[0,3],[1,4],[2,7],[5,6]], [5,6] comes before [2,7], pops the first two rooms, and I end up with 2 instead of 3. Both official examples still pass with that bug, but I checked about 800,000 small cases and over 100,000 fail.

Here's the plan, in three steps.

// sweep by start time, heap = end times of rooms in use
sort by start
for each meeting v:
  while heap.top <= v.start: pop  (room is free)
  push v.end; room = max(room, heap.size)
return room

Sort by start. For each meeting, first pop every room whose end is at or before this start. Then push this meeting's end, and record the heap size as a candidate answer.

One thing worth flagging — the pop condition is <=, because back-to-back meetings can share a room.

Alright. Sort by start, a min-heap of ints, and a room counter.

class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(), [&](auto& a, auto& b) {
            return a[0] < b[0];   // by start
        });

        priority_queue<int, vector<int>, greater<>> pq;
        int room = 0;

        for (auto& v : intervals) {
            while (!pq.empty() && pq.top() <= v[0]) pq.pop();

            pq.push(v[1]);
            room = max((int)pq.size(), room);
        }

        return room;
    }
};

In the loop I pop while the top is at most the current start, push the current end, and take the max of the heap size and room.

One small but real detail: the heap's size is an unsigned size_t, and room is an int. std::max needs both arguments to be the same type, so without a cast to int, it doesn't even compile. The cast is safe here, since the heap never holds more than 10⁴ items.
