題目簡介// THE QUESTION

QUESTION

intervals 是一串已經按起點排好、互不重疊的區間 [start, end]。把 newInterval 插進去,有重疊的就合併,回傳的結果仍然要排好、互不重疊。
0 ≤ intervals.length ≤ 10⁴,0 ≤ start ≤ end ≤ 10⁵。

範例:[[1,3],[6,9]] + [2,5] → [[1,5],[6,9]];[[1,2],[3,5],[6,7],[8,10],[12,16]] + [4,8] → [[1,2],[3,10],[12,16]](new 一口氣吞掉 [3,5]、[6,7]、[8,10])。

因為 intervals 已經排好又互不重疊,和 new 重疊的區間一定是連續的一整塊。 所以整串只會被切成三段:完全在 new 左邊的、和 new 重疊的、完全在 new 右邊的。左右兩段原樣搬,中間那塊全部併進 new。
2

為什麼用三段掃描// WHY THREE PHASES

A 塞進去再排序、再合併 O(n log n)
把 new 加到最後、整串按起點排序、再從頭合併(就是 56 Merge Intervals 的寫法)。正確(驗證時拿它當參考解),但 intervals 本來就排好了,重排一次是白做。
× REJECT · 浪費已排序
B 二分搜尋找重疊範圍 O(log n) + O(n)
用二分找出第一個、最後一個和 new 重疊的區間。找得快,但回傳的是一個新的 vector,所有區間還是要搬一次,整體仍是 O(n),而且邊界更容易寫錯。
△ 能用 · 搬的成本省不掉
ONE LINEAR PASS · ADOPT
C 三個 while:左搬 · 吞 · 右搬 O(n) / O(n)
一個 i 從頭走到尾,每個區間只看一次。和 A 比對:座標 0–7 上所有「排好且不重疊」的 intervals × 所有 new,共 57,492 組;再加隨機 20,000 組(n < 200、座標到 10⁵),全部 0 筆不一致。
● ADOPT · 每個區間看一次

核心策略 · 三步驟// THE LOOP

  1. 左邊照搬 —— intervals[i][1] < new[0]:這段在 new 開始之前就結束了,碰不到,原樣 push。
  2. 碰到就吞 —— new[1] >= intervals[i][0]:這段在 new 結束之前(或剛好結束時)開始,有重疊。new 的起點取 min、終點取 max。條件一不成立,就把 new push 進去。
  3. 右邊照搬 —— 剩下的起點都比 new 的終點大,不用再比,全部原樣 push。

第 2 步的 new[1] = max(…) 和 763 Partition Labels 的 r = max(r, last[s[i]]) 是同一件事:目前這一塊「至少要延伸到哪」,只會往右推。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 兩個區間重疊,只需要比一邊

[a,b] 和 [c,d] 重疊 ⇔ b ≥ c 而且 d ≥ a。第一個 while 停下來的時候,已經知道 intervals[i][1] ≥ new[0](另一邊成立了),所以第二個 while 只要再比 new[1] ≥ intervals[i][0] 就夠。 吞完一個之後,下一個區間的終點比剛吞的更大,new 的終點又只會變大 —— 「另一邊」一直成立,所以整個第二個 while 都只比一邊。

LEMMA 2 · 剛好碰到也算重疊:< 和 ≥ 不能換

題目把 [1,3] 和 [3,5] 視為重疊,要合併成 [1,5]。所以 CASE 1 是嚴格的 <、CASE 2 是含等號的 >=。CASE 1 寫成 <=,[[1,3]] + [3,5] 會回傳 [[1,3],[3,5]]。 危險的是:這個錯法兩個官方範例都會過(實跑)。CASE 2 寫成 > 至少範例 2 抓得到([8,10] 和 new 在 8 碰到)。兩種錯法都在複習頁第 6 題逐步走一遍。

正確性證明// PROOF OF CORRECTNESS

要證明什麼 · CLAIM

res 涵蓋的點剛好等於「intervals 和 new 的聯集」,而且 res 按起點排好、兩兩不重疊。

PROOF · 手法:三段各自成立 + 交界處不重疊
  1. CASE 1 搬的都在 new 左邊。最後的 new 起點 = min(原本的 new 起點, 第一個被吞區間的起點)。這兩個數都比這些區間的終點大:前者是 CASE 1 的條件,後者因為 intervals 互不重疊。所以這些區間和最後的 new 不重疊。
  2. CASE 2 吞掉的,剛好是所有和 new 重疊的區間。由 LEMMA 1,每次比的那一邊成立就是重疊;intervals 按起點排好,一旦某個起點 > new 的終點,後面的起點更大,不可能再重疊。吞的時候取 min / max,new 就變成這些區間和原 new 的聯集。
  3. CASE 3 搬的都在 new 右邊。第一個的起點 > new 的終點,後面的起點更大。三段依序 push:左邊那段本來就排好、new 在中間、右邊那段本來就排好 —— res 整體排好、互不重疊,點也一個沒少。
面試這樣說 · 30 秒

因為輸入已經排好又不重疊,跟新區間重疊的一定是中間連續的一段。我用一個指標走三次:先把終點小於新區間起點的照搬,再把起點不超過新區間終點的全部併進來,起點取最小、終點取最大,最後把剩下的照搬。每個區間只看一次,所以是線性時間。

一句洞察// INSIGHT

排好又不重疊的區間,和一個新區間重疊的部分一定是連續的一塊。 左邊 end < new[0] 照搬、中間 new[1] ≥ start 就吞(min / max)、右邊照搬。剛好碰到也算重疊,所以是 < 和 ≥。
