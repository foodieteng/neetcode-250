PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼和 newInterval 重疊的區間,一定是 intervals 裡連續的一段?這個性質用到了題目給的哪兩個條件?
解答與說明 · ANSWER▾
用到「按起點排好」和「互不重疊」。兩者合起來,終點也是遞增的。所以「終點 < new 起點」的區間全部擠在前面,「起點 > new 終點」的全部擠在後面,中間剩下的就是重疊的那一段。

這就是為什麼一個 i 從頭走到尾、分三段就夠:不會出現「重疊、不重疊、又重疊」的情況。如果輸入沒排好,這個性質就不成立(見第 7 題)。
第 2 題10 分
兩個區間 [a,b]、[c,d] 重疊要同時滿足兩個不等式。為什麼程式第二個 while 只比 newInterval[1] >= intervals[i][0] 一邊?
解答與說明 · ANSWER▾
另一邊「intervals[i][1] ≥ new[0]」在第一個 while 停下來時就成立了,之後也一直成立:下一個區間的終點更大,而 new 的起點只會變小。

所以重疊 ⇔ 剩下那一邊成立。同樣的道理,第一個 while 只比終點:終點 < new 起點,起點更小,整段一定在左邊。
第 3 題10 分
把第一個 while 的 < 改成 <=。哪一種輸入會出錯?兩個官方範例抓得到嗎?
解答與說明 · ANSWER▾
new 的起點剛好等於某個區間的終點時會錯:[[1,3]] + [3,5] 回傳 [[1,3],[3,5]],正解 [[1,5]]。兩個官方範例都抓不到(實跑都過)。

題目把碰到也算重疊,而 <= 會把「碰到」的那段當成在左邊直接搬走。座標 0–7 全部 57,492 組裡錯 25,130 組。範例裡剛好沒有這種邊界,所以自己測試一定要加一組。
第 4 題10 分
第二個 while 每一輪都做 min 和 max。有沒有哪一個其實只需要做一次?為什麼?
解答與說明 · ANSWER▾
兩個都是。min 只有吞第一個區間時可能改到值(後面被吞的起點更大);max 只需要和最後一個被吞的區間取(被吞的終點遞增,最後一個最大)。

兩種精簡寫法都實際改出來跑過,57,492 組 0 錯。但每輪都做寫起來最短、也最不容易出錯,面試照原本寫就好;能說出為什麼可以省,代表真的懂這個迴圈。
第 5 題10 分
intervals 已經排好,能不能用二分搜尋把整題做到 O(log n)?空間複雜度是多少?
解答與說明 · ANSWER▾
不能。二分可以在 O(log n) 找到重疊的範圍,但題目要回傳一個新的 vector,裡面最多有 n + 1 個區間,光是搬就要 O(n)。

空間 O(n) 全是輸出:n = 10⁴、new 接在最後時實測回傳 10,001 個。除了 res 只用了 i、n。如果只問「能不能插入而不重疊」,不用輸出新陣列,二分就有用了(見第 8 題)。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩組「剛好碰到」的輸入:[[1,3]] + [3,5] 用正解和「CASE 1 寫成 <=」各走一次;[[3,5]] + [1,3] 用正解和「CASE 2 寫成 >」各走一次。四個版本各回傳什麼?錯的版本在哪一步走錯?
解答與說明 · ANSWER▾
// [[1,3]] + [3,5] · 正解 CASE 1 i=0 [1,3] end 3 < 3 ? no CASE 2 i=0 [1,3] new[1] 5 >= 1 ? yes → new = [1,5] i=1 = n → push new [1,5] // OUTPUT: [[1,5]]
// [[1,3]] + [3,5] · CASE 1 寫成 <= CASE 1 i=0 [1,3] end 3 <= 3 ? yes → push [1,3] 碰到的那段被當成在左邊 CASE 2 i=1 = n → push new [3,5] // OUTPUT: [[1,3],[3,5]](錯):在 3 碰到卻沒合併
// [[3,5]] + [1,3] · 正解 CASE 1 i=0 [3,5] end 5 < 1 ? no CASE 2 i=0 [3,5] new[1] 3 >= 3 ? yes → new = [1,5] i=1 = n → push new [1,5] // OUTPUT: [[1,5]]
// [[3,5]] + [1,3] · CASE 2 寫成 > CASE 1 i=0 [3,5] end 5 < 1 ? no CASE 2 i=0 [3,5] new[1] 3 > 3 ? no → push new [1,3] CASE 3 i=0 push [3,5] // OUTPUT: [[1,3],[3,5]](錯):碰到的那段被當成在右邊
兩個錯法是同一個錯誤的兩面:把「剛好碰到」當成不重疊。<= 把它推到左邊,> 把它推到右邊。 <= 那個連兩個官方範例都過(第 3 題);> 至少範例 2 會在 [8,10] 露餡,回傳 [[1,2],[3,8],[8,10],[12,16]]。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
如果 intervals 仍然互不重疊、但沒有排好,這段程式還對嗎?舉一個反例,再說怎麼改。
解答與說明 · ANSWER▾
不對。[[6,9],[1,3]] + [2,5] 回傳 [[2,5],[6,9],[1,3]](實跑),正解 [[1,5],[6,9]]:[6,9] 讓 CASE 2 提早停下來,[1,3] 被當成右邊照搬。

改法:先按起點排序,其他一行都不用動,O(n log n)。隨機打亂順序 50,000 組:不排序錯 32,657 組,先排序 0 錯。第 1 題的「重疊的一定連續」靠的就是排好這個條件。
第 8 題14 分
改成只問 yes / no:intervals 是已經訂出去的會議時段(排好、不重疊),newInterval 這個時段能不能直接訂(和任何一段都不重疊,碰到也不行)?能做到比 O(n) 快嗎?
解答與說明 · ANSWER▾
可以 O(log n)。排好又不重疊 ⇒ 終點也遞增,二分找第一個「終點 ≥ new[0]」的區間(就是 CASE 1 停下來的那個 i)。找不到,或它的起點 > new[1],就能訂;否則它就和 new 重疊。

這次不用輸出新陣列,所以二分真的省到時間(對照第 5 題)。範例 1 的 [[1,3],[6,9]]:[4,5] 能訂,[2,5]、[3,5] 不能(3 碰到)。和「每一段都檢查」對拍 50,000 組,0 錯。
第 9 題14 分
56 Merge Intervals:給一堆沒排好、可能互相重疊的區間,全部合併。這題的哪一個 while 可以直接搬過去用?
解答與說明 · ANSWER▾
CASE 2。先按起點排序,拿第一個區間當 cur(扮演 newInterval);往後看,cur[1] >= next[0] 就吞(終點取 max,起點已經是最小不用 min),否則 push cur、cur 換成 next。最後再 push 一次 cur。

官方範例 [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]、[[1,4],[4,5]] → [[1,5]](4 碰到也合併)。和「把每個點標在數線上再找連續段」的暴力解對拍 50,000 組,0 錯。這題的 CASE 1 / CASE 3 在 56 裡用不到,因為沒有一個固定的 new。
