完整實作// LEFT · MERGE · RIGHT

p57.cpp C++17 
class Solution {
public:
    vector<vector<int>> insert(vector<vector<int>>& intervals,
                               vector<int>& newInterval) {
        int n = intervals.size(), i = 0;
        vector<vector<int>> res;

        // Case 1: no overlapping case before the merge intervals
        // Compare ending point of intervals to starting point of newInterval
        while (i < n && intervals[i][1] < newInterval[0]) {
            res.push_back(intervals[i]);
            i++;
        }

        // Case 2: overlapping case and merging of intervals
        while (i < n && newInterval[1] >= intervals[i][0]) {
            newInterval[0] = min(newInterval[0], intervals[i][0]);
            newInterval[1] = max(newInterval[1], intervals[i][1]);
            i++;
        }
        res.push_back(newInterval);

        // Case 3: no overlapping of intervals after newinterval being merged
        while (i < n) {
            res.push_back(intervals[i]);
            i++;
        }
        return res;
    }
};

🎧 面試模擬 · UMPIRE mock · 逐句點播有聲版 ↗

兩個官方範例 → [[1,5],[6,9]]、[[1,2],[3,10],[12,16]],都正確。 和「塞進去、排序、再合併」比對:座標 0–7 上所有排好且不重疊的 intervals × 所有 new 共 57,492 組,加上隨機 20,000 組(n < 200、座標 ≤ 10⁵),0 筆不一致。ASan + UBSan 0 警告。

每一行各自的意思:

  • intervals[i][1] < newInterval[0]:這段在 new 開始前就結束了。只比終點就夠,因為 intervals 按起點排好,起點更小。
  • newInterval[1] >= intervals[i][0]:這段在 new 結束前(或剛好結束時)開始。「這段的終點 ≥ new 的起點」那一邊,第一個 while 停下來時已經保證了。
  • min / max:new 變成兩者的聯集。其實 min 只有吞第一個區間時會改到值(後面的起點更大),max 也只有吞最後一個時才真的需要 —— 這兩種精簡寫法實測都 0 錯,但照寫最不會出事。
  • res.push_back(newInterval) 在第二個 while 外面、無條件執行:就算沒有吞任何區間,new 自己也要放進去。
  • newInterval 是傳參考,函式會直接改掉呼叫端的值。LeetCode 不在意;自己寫測試時如果要重複用同一個 new,要先複製一份。
