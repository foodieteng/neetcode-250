完整實作// SORT BY END · KEEP IF FREE

p435.cpp C++17 
class Solution {
public:
    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(), [&](auto& a, auto& b) {
            return a[1] < b[1];
        });

        vector<vector<int>> res;

        for (auto& v : intervals) {
            if (res.empty() || res.back()[1] <= v[0]) {
                res.push_back(v);
            }
        }

        return intervals.size() - res.size();
    }
};

三個官方範例 → 1、2、0,都正確。 和「枚舉所有子集」比對:座標 0–4 上長度 1–5 的所有區間序列共 111,110 組,加上隨機 20,000 組(n ≤ 14、含負座標),0 筆不一致。ASan + UBSan 0 警告。

每一行各自的意思:

  • sort(…, cmp):按終點由小到大。cmp 的每個零件下一節拆開講。
  • res.empty() || …:第一個區間一定留。|| 會短路,res 空的時候不會去讀 res.back()。
  • res.back()[1] <= v[0]:最後留下的那個,結束在 v 開始之前(或剛好同一點)就不衝突。
  • intervals.size() - res.size():兩個 size_t 相減,回傳時轉成 int。res 不會比 intervals 大,所以不會變成負數繞回去;最大是 n = 10⁵ 個全相同時的 99,999(實跑)。

sort 的 cmp 怎麼寫// COMPARATOR ANATOMY

sort(first, last, cmp) 的 cmp 只回答一個問題:「a 要不要排在 b 前面?」回傳 true 就是要。把這題的 lambda 拆開:

// lambda 拆解 [&](auto& a, auto& b) { return a[1] < b[1]; } [&] 捕獲清單:lambda 能用外面哪些變數。這裡沒用到任何外部變數,寫 [] 也一樣 (auto& a, auto& b) 兩個要比的元素。auto = 讓編譯器推型別(這裡是 vector<int>),& = 傳參考不複製 { return a[1] < b[1]; } 回傳 bool:a 的終點比較小 → a 排前面 → 由小到大

常用的幾種寫法(都實際編譯跑過):

想要的順序寫法說明
起點小到大(起點一樣比終點)sort(v.begin(), v.end())不給 cmp:vector 預設按字典序比,先比 [0] 再比 [1]。56 / 57 用的就是這個
終點小到大(本題)[](const auto& a, const auto& b) { return a[1] < b[1]; }加 const 表示不會改到元素,習慣上更安全;和 auto& 速度一樣
終點大到小return a[1] > b[1];把 < 換成 > 就反過來。這題用它會錯(第 4 節)
終點一樣時再比起點return a[1] != b[1] ? a[1] < b[1] : a[0] < b[0];多鍵排序的標準寫法。這題不需要(概念頁 LEMMA 2,實測 0 差異)
寫成成員函式static bool cmp(…) + sort(…, cmp)在 class 裡一定要 static,不然編譯錯誤:invalid use of non-static member function

三個會出事的寫法(實測):

寫法實際結果為什麼
return a[1] <= b[1];16 個相同區間正常;17 個就 Segmentation fault(exit 139)。ASan 報 heap-buffer-overflow;-D_GLIBCXX_DEBUG 直接報「comparison doesn't meet irreflexive requirements」cmp(a, a) 必須是 false(strict weak ordering)。<= 讓「a 排在 a 前面」成立,sort 的內部迴圈會一路往外讀。16 個以下 libstdc++ 走插入排序,所以小測資看不出來
[](auto a, auto b)(傳值)n = 10⁵ 排序 95 ms,傳參考只要 10.8 ms(約 9 倍)每次比較都複製兩個 vector<int>,一次排序要比較上百萬次
成員函式沒加 static編譯錯誤非 static 成員函式需要 this,不能直接當成一般函式傳給 sort
cmp 永遠用嚴格的 < 或 >,參數用 const auto&。 題目裡「碰到算不算重疊」的 <= 寫在掃描的 if 裡,不是寫在 cmp 裡 —— 這兩個 <= 最容易搞混。

細節走讀// WALKTHROUGH · 長區間

走概念頁動畫的第二組 [[1,10],[2,3],[4,5],[3,6],[6,8]],每一行都是實際印出來的。

// sort by end [2,3] [4,5] [3,6] [6,8] [1,10] [1,10] 起點最早,終點最晚 → 排最後
// for v : intervals [2,3] res 空 → keep [4,5] back end 3 <= 4 ? yes → keep [3,6] back end 5 <= 3 ? no → drop [6,8] back end 5 <= 6 ? yes → keep [1,10] back end 8 <= 1 ? no → drop // OUTPUT: 5 − 3 = 2

同一組按起點排序會變成 [1,10]、[2,3]、[3,6]、[4,5]、[6,8]:[1,10] 第一個被留下,後面四個全撞到它,得到 4,錯。[3,6] 被刪是因為它在 [4,5] 之後才輪到 —— 它的終點 6 比 5 晚,留它只會更擋路。
