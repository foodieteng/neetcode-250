PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
題目問「最少刪幾個」,程式卻在算「留下幾個」。為什麼這樣可以?回傳值怎麼來?
解答與說明 · ANSWER▾
刪掉的和留下的加起來剛好是 n。留得越多、刪得越少,所以「最少刪幾個」= n − 「最多能留幾個兩兩不重疊的」。程式回傳 intervals.size() - res.size()。

「最多能留幾個」是經典的活動選擇問題,有現成的貪心解;直接想「刪哪個」反而難,因為刪一個會影響好幾對衝突。
第 2 題10 分
把 cmp 拿掉、改成預設的 sort(begin, end)(按起點),其他不動。三個官方範例會過嗎?舉一個會錯的輸入。
解答與說明 · ANSWER▾
三個範例都會過(實跑 1、2、0)。[[1,10],[2,3],[4,5]] 會回傳 2,正解 1:按起點排,[1,10] 第一個被留下,[2,3]、[4,5] 都撞到它。

貪心要留「讓出最多空間」的區間,看的是它什麼時候結束,不是什麼時候開始。窮舉 111,110 組裡錯 11,592 組。概念頁第 5 節的整理圖 ① 就是這一組。
第 3 題10 分
程式裡出現兩個「比大小」:cmp 的 a[1] < b[1],和 if 的 res.back()[1] <= v[0]。哪一個可以有等號?另一個加了等號會怎樣?
解答與說明 · ANSWER▾
if 要有等號(碰到不算重疊);cmp 絕對不能有等號。cmp 寫成 a[1] <= b[1],16 個相同區間還正常,17 個就 Segmentation fault(實跑 exit 139,ASan 報 heap-buffer-overflow)。

cmp 必須是嚴格的「排在前面」:cmp(a, a) 要回 false。<= 讓它回 true,sort 內部找分界的迴圈就停不下來,一路讀出陣列外。16 個以下 libstdc++ 用插入排序,不會出事,所以小測資很難發現。反過來,if 寫成 <,[[0,1],[1,2]] 會回傳 1(正解 0)。
第 4 題10 分
lambda 寫成 [](auto a, auto b)(沒有 &)答案還對嗎?[&] 換成 [] 呢?
解答與說明 · ANSWER▾
兩個答案都對。但傳值會慢很多:n = 10⁵ 排序實測 95 ms,傳參考 10.8 ms,約 9 倍。[&] 換 [] 沒有任何差別,因為 lambda 沒用到外面的變數。

傳值時每次比較都要複製兩個 vector<int>(各自一次 heap 配置),排序要比較上百萬次。習慣寫 const auto&:不複製,也保證不會不小心改到元素。[&] 是「用到的外部變數都傳參考」,這裡沒用到,所以寫不寫都一樣。
第 5 題10 分
另一個直覺:「短的區間佔的地方少,先留短的」。這樣對嗎?
解答與說明 · ANSWER▾
不對。[[0,4],[3,6],[5,9]]:最短的是 [3,6],先留它,另外兩個都撞到它,刪 2 個;正解是刪 [3,6] 一個,留 [0,4]、[5,9]。

短不代表不擋路 —— [3,6] 剛好卡在兩個長區間的交界。三個官方範例這個錯法也全過;窮舉 111,110 組裡錯 448 組,很少,所以更難被隨手測到。只有「最早結束」能用交換論證證明。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
手走 [[1,10],[2,3],[4,5]] 三次:按終點排(正解)、按起點排 + 同一個貪心、按起點排 + 重疊時留終點小的。各回傳什麼?
解答與說明 · ANSWER▾
// 按終點排序(正解) sorted: [2,3] [4,5] [1,10] [2,3] res 空 → keep [4,5] back end 3 <= 4 ? yes → keep [1,10] back end 5 <= 1 ? no → drop // OUTPUT: 3 − 2 = 1
// 按起點排序 + 同一個貪心 sorted: [1,10] [2,3] [4,5] [1,10] res 空 → keep 起點最早,先被留下 [2,3] back end 10 <= 2 ? no → drop [4,5] back end 10 <= 4 ? no → drop // OUTPUT: 3 − 1 = 2(錯)
// 按起點排序 + 重疊時留終點小的 sorted: [1,10] [2,3] [4,5] [1,10] 不重疊 → prevEnd = 10 [2,3] 重疊,刪一個 → prevEnd = min(10, 3) = 3 等於把 [1,10] 換成 [2,3] [4,5] 3 <= 4 不重疊 → prevEnd = 5 // OUTPUT: 1
第二種錯在一開始就把 [1,10] 定下來了;第三種先暫留,遇到更早結束的就換掉。 第一種和第三種本質相同:都是讓「終點小的」留下。按終點排序只是把這個決定提前做好。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
res 存了所有留下的區間,但程式其實只用到 res.back()[1]。把額外空間降到 O(1)(排序本身不算)。
解答與說明 · ANSWER▾
只留 prevEnd(初值 INT_MIN)和 removed:if (prevEnd <= v[0]) prevEnd = v[1]; else removed++;,最後回傳 removed。

INT_MIN 讓第一個區間一定被留下,取代 res.empty() 的判斷;座標最小只到 −5 × 10⁴,不會撞到它。和原本的寫法對拍 200,000 組隨機 0 差異。
第 8 題14 分
如果規定只能用預設的 sort(begin, end)(按起點),要怎麼改掃描,答案才會對?
解答與說明 · ANSWER▾
重疊時一樣刪一個,但要刪終點比較大的那個:removed++; prevEnd = min(prevEnd, v[1]);。不重疊時 prevEnd = v[1]。

按起點掃,兩個重疊的區間裡,留終點小的對後面最有利 —— 還是「最早結束」那個原則,只是要等看到兩個時才決定。窮舉 111,110 組 0 錯。官方範例 1:[1,2] 留下,[1,3] 和它重疊,prevEnd = min(2, 3) = 2,之後 [2,3]、[3,4] 都留,刪 1 個(實跑)。
第 9 題14 分
按起點由大到小排序(cmp 寫 a[0] > b[0]),能不能也用「能留就留」做出正解?條件要怎麼寫?
解答與說明 · ANSWER▾
可以。從右往左看,記住最後留下的起點 prevStart(初值 INT_MAX),v[1] <= prevStart 就留並更新 prevStart = v[0],否則刪。

把數線左右翻過來,「最晚開始」就是翻過來後的「最早結束」,交換論證一模一樣。窮舉 111,110 組 0 錯。這題的重點:排序鍵和掃描方向要配對 —— 由左往右看終點、由右往左看起點。
