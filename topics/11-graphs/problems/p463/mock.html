A naive approach would be to just scan every land cell and count its water or out-of-bounds sides directly. That already works in O(m·n) time.

This problem reminds me of a grid flood fill. Since it's a graph problem, I'll walk the island with DFS and count a perimeter edge every time I step off the island. Same complexity, and it's the reusable graph template.

Here's the plan.

// dfs(r, c): try to step onto cell (r,c)
if out of bounds OR cell is water → res += 1; return // stepped off → 1 edge
if cell is -1 (visited) → return
mark cell = -1
for each of 4 directions → dfs(neighbor)

One: the DFS tries to step onto a cell.
Two: if that cell is out of bounds or water, I add one edge and return.
Three: if it's already marked -1, I return; otherwise I mark it, so I never loop between neighbors, and try all four directions.

One thing worth flagging — where the boundary check lives really matters. My first instinct was to skip a water or off-grid neighbor before recursing. That's a bug: stepping off the island is the event I'm counting, so with a pre-call guard the edge never gets added. The check has to be the base case inside dfs.

There's a trade-off here. The -1 marker changes the input; if that's not allowed, I'd use a separate visited array, for O(m·n) extra space. Does this approach sound good, or would you rather I think of another way?

class Solution {
private:
    int m, n;
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

public:
    int islandPerimeter(vector<vector<int>>& grid) {
        m = grid.size(); n = grid[0].size();
        int res = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] != 1) continue;
                dfs(grid, i, j, res);       // connected: one call covers it
            }
        }
        return res;
    }

    void dfs(vector<vector<int>>& grid, int r, int c, int& res) {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] == 0) {
            res += 1; return;              // off grid / water = 1 edge
        }
        if (grid[r][c] == -1) return;       // visited land, don't count again

        grid[r][c] = -1;                   // mark visited

        for (auto [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            dfs(grid, nr, nc, res);          // walk in; check is the base case
        }
    }
};

The outer loops find land and launch the DFS, which adds to res by reference. Inside the DFS, out of bounds or water adds one and returns, a visited cell just returns, and otherwise I mark the cell and walk all four directions with no guard.

One thing worth flagging — the order in the base case matters. I check the bounds before I read grid[r][c]. Because || short-circuits, an out-of-bounds cell returns early and I never touch the array out of range.

The time complexity is O(m·n). Each land cell is marked once and its four sides are checked once. The space complexity is O(m·n) for the recursion stack. In the worst-case scenario, a snake-shaped island that fills the grid makes the stack that deep.

Oh, one more thing — this code already handles multiple islands for free. The outer loop starts a fresh DFS on any land cell not yet marked, and separate islands just add their perimeters into the same res. Nothing to change.
