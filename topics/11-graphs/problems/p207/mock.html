Each course is a node, each pair is a directed edge. "Can I finish all courses" is exactly "is this directed graph acyclic"?

This problem reminds me of cycle detection in a directed graph, and there are two standard ways to do it. DFS with three states — flag a node while it's on the current recursion path; if I ever step back onto one, that's a cycle. // build edge b → a
// visit[]: 0 = unvisited, 1 = on current path, 2 = done
hasCycle(u):
  if visit[u] == 1: return true  // stepped back onto the path
  if visit[u] == 2: return false
  visit[u] = 1
  for v in graph[u]: if hasCycle(v): return true
  visit[u] = 2; return false
for every i: if hasCycle(i): return false

One: build an edge b → a.
Two: keep a visit array — 0 unvisited, 1 on the current path, 2 done.
Three: run the cycle check from every course, and fail on the first cycle.

One thing worth flagging — the check needs three states, not two. In a DAG a node can be reached again through a different path; that's normal, not a cycle. Only re-entering a node that's still on the current recursion path (state 1) is a real cycle. A plain visited flag would falsely flag the diamond's shared node.

One more — I start the DFS from every course, not just course 0, because the graph may be disconnected and a cycle could hide where 0 never reaches.

class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<int> visit(numCourses, 0);       // 0 unvisited / 1 on path / 2 done
        vector<vector<int>> graph(numCourses);

        for (auto& p : prerequisites) {
            int a = p[0], b = p[1];
            graph[b].push_back(a);              // edge b→a
        }

        for (int i = 0; i < numCourses; i++)
            if (hasCycle(graph, visit, i)) return false;   // cycle → can't finish

        return true;
    }

    bool hasCycle(vector<vector<int>>& graph, vector<int>& visit, int u) {
        if (visit[u] == 1) return true;          // back onto the path → cycle
        if (visit[u] == 2) return false;         // already done, safe

        visit[u] = 1;                            // in progress (on path)
        for (int v : graph[u])
            if (hasCycle(graph, visit, v)) return true;
        visit[u] = 2;                            // done (off the path)

        return false;
    }
};

I build the graph with an edge b → a, then call hasCycle from every course and return false on the first cycle. Inside hasCycle, state 1 means I walked back onto my own path, so that's a cycle; state 2 means the node is already finished and safe. Otherwise I mark it 1, recurse into its neighbors, then mark it 2.

One thing worth flagging — setting visit[u] = 2 before returning is not just tidy, it's what keeps this O(V + E): a finished node is never explored again.

Sure. Instead of recursion I track each node's in-degree — how many prerequisites it still has. I queue every node at in-degree 0, and each time I pop one I "peel" it by decrementing its neighbors; any neighbor that hits 0 joins the queue. I count how many I peel.

class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<int> indeg(numCourses, 0);
        vector<vector<int>> graph(numCourses);

        for (auto& p : prerequisites) {
            int a = p[0], b = p[1];
            graph[b].push_back(a);
            indeg[a]++;                          // a gains one prerequisite
        }

        queue<int> q;
        for (int i = 0; i < numCourses; i++)
            if (indeg[i] == 0) q.push(i);          // no prerequisites → start

        int done = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            done++;                             // peel one course
            for (int v : graph[u])
                if (--indeg[v] == 0) q.push(v);
        }
        return done == numCourses;              // peeled all = no cycle
    }
};

One thing worth flagging — the cycle check falls out for free. Nodes inside a cycle keep a positive in-degree forever, so they never enter the queue and never get counted. If done ends up below numCourses, some courses are trapped in a cycle. Same O(V + E), and no recursion-depth risk.
