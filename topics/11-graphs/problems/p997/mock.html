One: two counter arrays, in and out, 1-indexed and starting at 0.
Two: for each pair [a, b], bump out[a] and in[b].
Three: scan 1 to n and return the first person with out == 0 and in == n-1.

One thing worth flagging — it's n-1, not n. The judge doesn't trust themselves, so at most n-1 people can trust the judge; writing in[i]==n would never match.

class Solution {
public:
    int findJudge(int n, vector<vector<int>>& trust) {
        vector<int> in(n + 1, 0), out(n + 1, 0);   // 1-indexed: 1..n

        for (auto t : trust) {
            int a = t[0], b = t[1];          // a trusts b
            out[a]++; in[b]++;                    // +1 to a's out-degree and b's in-degree
        }

        for (int i = 1; i <= n; i++) {
            if (out[i] == 0 && in[i] == n - 1) return i;  // trusts nobody + trusted by all others
        }

        return -1;                                // no judge
    }
};

One loop over the trust pairs bumps out[a] and in[b]. A second loop over 1 to n returns the first person with out == 0 and in == n-1, and if nobody matches I return -1.

One thing worth flagging — the arrays have size n + 1 because people are labeled 1..n. Index 0 goes unused, which keeps the labels and indices lined up and avoids off-by-one bugs.
