Hmm, let me think about this for a sec.

A naive approach is, for each edge, to run a DFS and see if its endpoints are already connected — that's O(n2).

This problem reminds me of cycle detection with Union-Find, because an edge closes a cycle exactly when its two endpoints are already in the same set. So I process edges in order and merge endpoints, and the first edge whose endpoints are already together is the one that closes the cycle — I return it.

Because I scan in input order, that first failing edge is automatically the last cycle edge in the list, which is exactly the tie-break the problem wants. It's O(n·α(n)), effectively linear.

class Solution {
    vector<int> parent;                        // <0: root, -value = size; >=0: parent

    int Find(int x) {
        return parent[x] < 0 ? x : parent[x] = Find(parent[x]);  // path compression
    }

    bool Union(int x, int y) {
        int rootX = Find(x), rootY = Find(y);
        if (rootX == rootY) return false;        // same group → this edge closes a cycle
        if (-parent[rootX] < -parent[rootY]) swap(rootX, rootY);
        parent[rootX] += parent[rootY];
        parent[rootY] = rootX;
        return true;
    }

public:
    vector<int> findRedundantConnection(vector<vector<int>>& edges) {
        int n = edges.size();
        parent.assign(n + 1, -1);              // nodes 1..n (0 unused)

        for (auto e : edges) {
            int u = e[0], v = e[1];
            if (!Union(u, v)) return {u, v};   // first same-root edge = answer
        }
        return {};
    }
};

Find uses path compression, and Union merges by size and returns a bool: false when both roots are the same. The number of nodes equals the number of edges, so I size parent to n + 1. Then I walk the edges and return the first one whose Union fails.

One thing worth flagging — one Union per edge is enough, and I check its result right there. A second, unchecked call on the same edge would be harmless — both ends already share a root, so it just returns false and changes nothing — but it's dead code.
