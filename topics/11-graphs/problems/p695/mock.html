Hmm, let me think about this for a sec.

A naive approach would be to count islands first and then re-scan to measure each. That's two passes for no reason.

This problem reminds me of flood fill, the sink-the-island pattern: each unseen land cell starts a DFS that sinks its whole island, so nothing is visited twice. The twist is that while the DFS sinks an island, I count the cells it visits. Each island's count is its area, and I keep the maximum. One pass.

P — plan
C
CANDIDATE

Here's the plan.

// area = cells sunk in one DFS
for each cell (i, j):
  if grid[i][j] == 1: curArea = 0; dfs(i, j, curArea)
  maxArea = max(maxArea, curArea)

dfs(r, c, curArea&): out of bounds or grid == 0 → return
  grid[r][c] = 0; curArea++ // sink + count, then recurse

One: scan every cell, skipping water.
Two: on land, reset curArea to 0 and run a DFS from there, then update the max.
Three: the DFS returns on out-of-bounds or water; otherwise it sinks the cell, adds one to the counter, and recurses into four neighbors.

One thing worth flagging — the counter is passed by reference. By value, each call would increment its own copy, and the top level would still see 0. An equivalent design is to have dfs return the area as 1 plus the sum of its four neighbors.

There's a trade-off here. Sinking mutates the grid, and a huge all-land grid could recurse deep enough to overflow — BFS would avoid that. For 50×50, in-place DFS is fine. Does this approach sound good, or would you rather I think of another way?

class Solution {
private:
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
    int m, n;

public:
    int maxAreaOfIsland(vector<vector<int>>& grid) {
        m = grid.size(); n = grid[0].size();
        int maxArea = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 0) continue;       // water or sunk: skip

                int curArea = 0;
                dfs(grid, i, j, curArea);          // sink + measure
                maxArea = max(maxArea, curArea);      // keep the largest
            }
        }
        return maxArea;
    }

    void dfs(vector<vector<int>>& grid, int r, int c, int& curArea) {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] == 0) return;
        grid[r][c] = 0;                        // sink now (mark visited)
        curArea++;                              // this cell: +1
        for (auto [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            dfs(grid, nr, nc, curArea);
        }
    }
};

The outer loops skip water with a continue; for each land cell I start a fresh curArea at 0, run the DFS, and take the max. The DFS checks bounds and water first, sinks the cell, bumps the counter, then visits the four directions.

One thing worth flagging — curArea is an int&, a reference, so the curArea++ inside every recursive call lands on the one counter the top level reads back. And since the grid is int, every check is against a plain 0 — no quotes this time.

The time complexity is O(m·n) — each cell is scanned once and sunk at most once, counting as it goes. The space complexity is O(m·n) for the recursion stack in the worst case. In the worst-case scenario, one island filling the whole grid makes the stack that deep.

Oh, one more thing — this is the plain flood-fill island count with two extra lines: a curArea counter and a max. If they later asked for every island's size, I'd just push each area into a list instead of maxing.
