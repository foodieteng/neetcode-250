A naive approach would be to BFS from every fresh orange to its nearest rotten one and take the max — that's O((mn)²).

This problem reminds me of multi-source BFS: every rotten orange is a starting point and they all spread in parallel, so seeding them together gives each cell its distance to the nearest rotten one in a single pass. Here's the plan.

// seed all rotten, count fresh
push every 2 into queue; count 1s as fresh
if fresh == 0 → return 0
while queue: sz = queue.size()  // this whole minute's cells
  repeat sz times: pop, rot fresh neighbors, fresh--, push
    fresh hits 0 → return this minute
  time++
return -1  // queue drained, fresh > 0

One: push every rotten orange into the queue and count the fresh ones; if there are none, return 0.
Two: while the queue isn't empty, snapshot its size and process exactly that many cells, rotting their fresh neighbors, then add one minute.
Three: if fresh hits zero, return the minute; if the queue drains first, return -1.

One thing worth flagging — that size snapshot is the whole trick. The queue holds this minute's oranges and the ones they just infected, so without it, two minutes blend together and the count comes out wrong.

There's a trade-off here. The fresh counter isn't optional — it's how I detect the walled-off case. And I write the rot back into the grid, so I don't need a visited array.

class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        queue<pair<int, int>> q;
        int fresh = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 0) continue;
                if (grid[i][j] == 1) fresh++;            // count fresh
                if (grid[i][j] == 2) q.push({i, j});  // seed EVERY rotten (multi-source)
            }
        }

        if (fresh == 0) return 0;                     // no fresh → 0 minutes

        const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        int time = 0;
        while (!q.empty()) {
            int sz = q.size();                       // this wave = this minute's cells
            for (int _ = 0; _ < sz; _++) {
                auto [r, c] = q.front(); q.pop();
                for (auto [dr, dc] : dirs) {
                    int nr = r + dr, nc = c + dc;
                    if (nr < 0 || nr >= m || nc < 0 || nc >= n || grid[nr][nc] != 1) continue;
                    if (--fresh == 0) return time + 1;       // last fresh rots → return this minute
                    grid[nr][nc] = 2;                    // only infect fresh (== 1)
                    q.push({nr, nc});
                }
            }
            time++;                                    // finished a wave = one minute
        }
        return -1;                                   // queue empty but fresh > 0 → unreachable
    }
};

One scan seeds every rotten orange and counts the fresh ones, with an early return of 0. Then the BFS loop: snapshot the size, pop exactly that many, and rot only neighbors that are in bounds and still fresh — writing a 2 into the grid so nothing rots twice. If the queue empties, I return -1.

One thing worth flagging — return time + 1, not time. time counts the minutes fully elapsed; the neighbor I'm rotting right now rots in the next minute, so when the last fresh one goes, the answer is time + 1.

• Fresh oranges but no rotten one → empty queue, so -1.
• A fresh orange boxed in by empties → fresh > 0 when the queue drains, so -1.

Let me think about complexity here.

The time complexity is O(m·n) — each cell enters and leaves the queue at most once. The space complexity is O(m·n) for the queue. In the worst-case scenario, a grid that's almost all rotten puts nearly every cell in the queue at the start.
