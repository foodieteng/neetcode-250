One: for every 'O' on the four borders, run a DFS that marks its region '#'.
Two: the DFS marks the cell, then recurses only into neighbors that are still 'O'.
Three: sweep the board — '#' goes back to 'O', everything else becomes 'X'.

Here, I'm using '#' as a third symbol for "confirmed safe," so the final sweep can tell a safe 'O' apart from a surrounded one.

One thing worth flagging — that still-'O' guard skips walls ('X'), already-marked safe cells ('#'), and out-of-bounds, so it's my visited check and my obstacle check in one.

There's a trade-off here. Mutating the board avoids a separate visited grid, and for a huge all-'O' board BFS avoids deep recursion, but I'll write DFS. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int m, n;
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    void solve(vector<vector<char>>& board) {
        m = board.size(); n = board[0].size();

        for (int r = 0; r < m; r++) {             // O on left / right edges
            if (board[r][0] == 'O') dfs(board, r, 0);
            if (board[r][n - 1] == 'O') dfs(board, r, n - 1);
        }
        for (int c = 0; c < n; c++) {             // O on top / bottom edges
            if (board[0][c] == 'O') dfs(board, 0, c);
            if (board[m - 1][c] == 'O') dfs(board, m - 1, c);
        }

        for (int r = 0; r < m; r++) {             // flip
            for (int c = 0; c < n; c++) {
                board[r][c] = (board[r][c] == '#') ? 'O' : 'X';  // # → O, else X
            }
        }
    }

    void dfs(vector<vector<char>>& board, int r, int c) {
        board[r][c] = '#';                      // mark safe on entry
        for (auto [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            if (nr < 0 || nr >= m || nc < 0 || nc >= n || board[nr][nc] != 'O') continue;  // still-O only
            dfs(board, nr, nc);
        }
    }
};

Two loops walk the left and right edges, then the top and bottom, launching the DFS on any 'O'. The DFS marks its cell '#' on entry, then only continues into in-bounds neighbors that are still 'O'. A final double loop flips: '#' back to 'O', anything else to 'X'.

One thing worth flagging — the board is char, so the quotes matter: 'O', 'X', '#' are all single-quoted characters, and it's the capital letter O, not the digit '0'. Compare against the digit and nothing is ever marked safe, so every 'O' gets captured.

The time complexity is O(m·n) — the border DFS visits each cell at most once, plus one flip sweep. The space complexity is O(m·n) for the recursion stack in the worst case, a board that's one big connected region of 'O'.

Oh, one more thing — this border-reverse trick is a general tool: when the target is hard to test per cell, flood from the edges and mark, then read off the answer. Here, "reached from an edge" means safe; the leftover 'O's are the surrounded ones.
