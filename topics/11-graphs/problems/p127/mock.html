I could build the whole graph by comparing every pair of words — O(N2·L), too slow for a big dictionary.

This problem reminds me of shortest path on an unweighted graph, which is exactly what breadth-first search solves — but here I'll use an implicit graph: I never store edges. For the current word, I generate neighbors on the fly by trying all 26 letters at each position and checking the dictionary hash set. Then a plain level-order BFS: the first time I reach endWord, the level count is the shortest length.

  step++

One: put wordList in a hash set, mark beginWord seen, and start step at 1.
Two: process the queue one layer at a time; for each word, try every letter at every position, and push each new dictionary word that isn't seen yet — if it's endWord, return step + 1.
Three: after each full layer, step goes up by one.

One thing worth flagging — I mutate the word in place to make neighbors, so after trying all 26 letters at position i I must restore it before moving to position i+1; otherwise I'd generate words that differ by two letters. And I mark a word seen the moment I push it, so it can't be enqueued twice.

class Solution {
public:
    int ladderLength(string beginWord, string endWord, vector<string>& wordList) {
        unordered_set<string> dict(wordList.begin(), wordList.end()), seen;
        int step = 1;
        queue<string> q;
        seen.insert(beginWord);
        q.push(beginWord);

        while (!q.empty()) {
            int sz = q.size();                // bind this layer
            for (int _ = 0; _ < sz; _++) {
                string w = q.front(); q.pop();

                for (int i = 0; i < w.size(); i++) {
                    string cache = w;                // remember the word, restore later
                    for (int j = 0; j < 26; j++) {
                        w[i] = j + 'a';            // position i becomes a..z
                        if (!dict.count(w) || seen.count(w)) continue;
                        if (w == endWord) return step + 1;  // hit → next layer's length

                        seen.insert(w);
                        q.push(w);
                    }
                    w = cache;                       // restore, move to next position
                }
            }
            step++;                             // layer done, step + 1
        }
        return 0;                             // unreachable
    }
};

A hash set for the dictionary, a seen set, and a queue seeded with beginWord. Each round, I bind the layer size, then for every word and every position I save a copy, try a..z, skip anything not in the dictionary or already seen, and return step + 1 on a hit.

That matches the plan. One thing worth flagging — step++ lives outside the per-word loop, so it only increments once per BFS layer. That's what makes step a true distance.

steplayer processednew words found

Each layer adds one more word to the ladder: hot, then dot and lot, then dog and log. The row that matters is step=4, processing dog and log: changing dog's d to c gives cog, which is the end word, so I return 4+1 = 5.

The +1 is the subtle part: at step=4 the queue holds the 4th-level words, and cog is generated as a 5th-level word, so it's the 5th word in the ladder. If cog weren't in the dictionary, BFS would drain the queue without a hit and return 0.

Time is O(N · L2 · 26), where N is the dictionary size and L the word length — each word spawns L·26 candidates, and each one costs O(L) to hash and look up in the set. Space is O(N · L) for the dictionary, seen set, and queue.

Oh, one more thing — for a large dictionary I'd switch to bidirectional BFS — expand from both ends and meet in the middle, cutting the explored frontier from roughly b^d to 2·b^(d/2). And if I needed the actual path, I'd store a parent pointer per word and backtrack.
