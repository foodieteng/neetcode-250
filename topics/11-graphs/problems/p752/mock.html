Here's the plan.

// level = one turn
if "0000" is a deadend → -1; if target == "0000" → 0
BFS from "0000", seen + queue
each level (sz = q.size()): pop u; if u == target return step
  for each of 4 wheels: try +1 and -1 (wrap), push if not dead/seen
step++ per level; queue empty → -1

One: if "0000" is a deadend, return -1; if target is "0000", return 0.
Two: BFS one level at a time — pop a code, return step if it's the target, and push each wheel turned up and down if not dead or seen.
Three: step goes up once per level; if the queue empties, return -1.

One thing worth flagging — character arithmetic is a classic trap. Turning '5' up as ASCII c + 1 gives '6'. But char(c - '0' + 1) gives the byte 6, a control character, not the digit '6'.

There's a trade-off here. DFS could explore the graph too, but only BFS gives shortest for free with unit weights.

class Solution {
public:
    int openLock(vector<string>& deadends, string target) {
        unordered_set<string> dead(deadends.begin(), deadends.end());
        if (dead.count("0000")) return -1;          // start is dead → can't open
        if (target == "0000") return 0;            // start is the target

        unordered_set<string> seen;
        queue<string> q;
        seen.insert("0000"); q.push("0000");
        int step = 0;

        while (!q.empty()) {
            int sz = q.size();                       // every state of this level (this turn)
            for (int _ = 0; _ < sz; _++) {
                auto u = q.front(); q.pop();
                if (u == target) return step;          // first time dequeued = shortest

                for (int i = 0; i < 4; i++) {
                    string cache = u;

                    u[i] = (cache[i] == '9') ? '0' : cache[i] + 1;  // turn up: plain ASCII + 1
                    if (!dead.count(u) && !seen.count(u)) { seen.insert(u); q.push(u); }

                    u[i] = (cache[i] == '0') ? '9' : cache[i] - 1;  // turn down: plain ASCII − 1
                    if (!dead.count(u) && !seen.count(u)) { seen.insert(u); q.push(u); }

                    u = cache;                          // ★ restore, then the next wheel
                }
            }
            step++;                                    // level cleared = one turn
        }
        return -1;                                   // target unreachable
    }
};

Two early returns, then a seen set and a queue seeded with "0000". Each level, I pop a code, return step if it's the target, and for each wheel I save a copy, turn it up, push if allowed, turn it down, push if allowed, then restore.

One thing worth flagging — both turns read the wrap from the saved copy cache[i], not from u. Turning up: '9' wraps to '0', else plain ASCII +1. Turning down: '0' wraps to '9', else -1. By the down turn, u has already been changed by the up turn, so reading from u would turn the wrong digit.

The deciding fact: every 4-move route is blocked — the direct paths hit deadends like 0102 and 0201. So BFS has to detour through the first wheel: 1000, build the 2 and the 2, then turn the first wheel back down to 0202. It first reaches the target at level 6, so the answer is 6.

Corner cases:

• If "0000" itself is a deadend, I return -1 up front.
• If target is "0000", it's 0.
• If deadends wall the target off entirely, the queue drains and I return -1.

The time complexity is O(104) — at most 10,000 states, each with a constant 8 neighbors. The space complexity is O(104) for the seen set and the queue. In the worst-case scenario, nearly all states are reachable and enqueued.

Oh, one more thing — the level loop is the standard batching trick: take the queue size, drain exactly that many, and that's one turn. And if the state space were huge, I'd reach for bidirectional BFS, searching from both "0000" and target to cut the explored states.
