The brute force is to root at every node and BFS its height — O(n2).

This problem reminds me of topological sort, run in reverse on an undirected tree: the center is the midpoint of the tree's longest path, and I can find it by peeling leaves inward. Repeatedly remove all current leaves (degree 1), one whole layer at a time, until ≤ 2 nodes remain — those are the centers. That's O(n).

Here's the plan.

// handle n==1 → [0], n==2 → [0,1]
build adjacency + degree; queue all leaves (deg==1)
while (remaining n > 2):
  sz = q.size(); n -= sz // peel one whole layer
  for each leaf u: for neighbor v: if --deg[v]==1: push v
return whatever is left in the queue // 1 or 2 centers

One: handle n of 1 and 2 up front, then build the adjacency list and degrees, and queue every leaf.
Two: while more than two nodes remain, peel one whole layer, and push any neighbor whose degree drops to 1.
Three: return whatever is left in the queue.

One thing worth flagging — the loop condition is remaining n > 2, not "queue non-empty." The centers' degrees also drop to 1 and they enter the queue, so if I peeled until empty I'd delete the centers too. Tracking the remaining count and stopping at ≤ 2 is what keeps them. And the sz = q.size() snapshot binds one layer together, so I don't mix the next layer into the current peel.

Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    vector<int> findMinHeightTrees(int n, vector<vector<int>>& edges) {
        if (n == 1) return {0};          // special cases
        if (n == 2) return {0, 1};

        vector<vector<int>> graph(n);
        vector<int> deg(n, 0);
        for (auto e : edges) {
            int a = e[0], b = e[1];
            graph[a].push_back(b); graph[b].push_back(a);
            deg[a]++; deg[b]++;
        }

        queue<int> q;
        for (int i = 0; i < n; i++)
            if (deg[i] == 1) q.push(i);       // initial leaves

        while (n > 2) {                    // keep peeling while > 2 remain
            int sz = q.size();              // bind "this layer"
            n -= sz;
            for (int _ = 0; _ < sz; _++) {
                int u = q.front(); q.pop();
                for (int v : graph[u])
                    if (--deg[v] == 1) q.push(v);   // drops to 1 = next layer's leaf
            }
        }

        vector<int> ans;
        while (!q.empty()) { ans.push_back(q.front()); q.pop(); }  // the 1 or 2 left = centers
        return ans;
    }
};

Two early returns, then adjacency plus degree, and every deg == 1 node goes in the queue. Each round I snapshot the layer size, subtract it from n, pop that many leaves, and decrement each neighbor's degree. When the loop stops, the queue holds the answer.

That matches the plan. One thing worth flagging — a neighbor joins the queue the moment its degree hits 1, not 0: degree 1 means it just became a leaf and is next to peel.

Time is O(V + E) = O(n) — a tree has n-1 edges and each node is peeled once. Space is O(n) for the adjacency list, degree array, and queue.

Oh, one more thing — if I also wanted the actual minimum height, I'd count the peel layers: that's the height when one center is left, plus one when two are left. And this leaf-peeling is the undirected-tree cousin of Kahn's topological sort, which peels indegree==0 nodes in a directed graph.
