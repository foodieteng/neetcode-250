A naive approach would be to run a BFS from every empty room to find its nearest gate — but that's O((mn)²) and times out.

This problem reminds me of multi-source BFS, the pattern for shortest distance to the nearest of many sources. Putting every gate in the first wave treats them as one super source, so a single pass of O(mn) gives every room its answer.

// seed every gate, then spread
push all cells with value 0 into the queue
while queue: pop (r,c)
  for each neighbor (nr,nc):
    if in bounds AND rooms[nr][nc] == INF:
      rooms[nr][nc] = rooms[r][c] + 1; push it

One: push every gate into the queue.
Two: pop a cell, and for each in-bounds neighbor that is still INF, write this cell's distance + 1 and push it.
Three: when the queue is empty, every reachable room is filled.

Here, I'm using the grid itself to keep track of distances and visited-ness at once.

One thing worth flagging — the guard rooms[nr][nc] == INF does triple duty. Walls are -1, gates are 0, and filled rooms are positive, so one check skips walls, gates, and revisits.

There's a trade-off here. Writing into the input mutates it, but that's expected here and saves a separate distance grid. And because BFS reaches each cell by its shortest path first, the first write is final.

class Solution {
public:
    void wallsAndGates(vector<vector<int>>& rooms) {
        int m = rooms.size(), n = rooms[0].size();
        const int INF = INT_MAX;

        queue<pair<int, int>> q;
        for (int i = 0; i < m; i++) {             // plant every source
            for (int j = 0; j < n; j++) {
                if (rooms[i][j] == 0) q.push({i, j}); // seed EVERY gate
            }
        }

        const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        while (!q.empty()) {
            int sz = q.size();
            for (int _ = 0; _ < sz; _++) {          // one wave at a time
                auto [r, c] = q.front(); q.pop();
                for (auto [dr, dc] : dirs) {
                    int nr = r + dr, nc = c + dc;
                    if (nr < 0 || nr >= m || nc < 0 || nc >= n || rooms[nr][nc] != INF) continue;
                    rooms[nr][nc] = rooms[r][c] + 1;   // only fills a still-INF room
                    q.push({nr, nc});
                }
            }
        }
    }
};

One scan pushes every gate. Then the BFS: pop a cell, look at its four neighbors, and skip anything out of bounds or != INF — the bounds check comes first, so I never read outside the grid. Otherwise the neighbor gets this cell's distance + 1 and joins the queue.

One thing worth flagging — I kept the sz snapshot loop to process one wave at a time, but here it's optional. The distance lives in the cell as rooms[r][c] + 1, so dropping that loop gives the same result. I'd only need it to return a number of waves.

Let me think about complexity here.

The time complexity is O(m·n) — each cell enters and leaves the queue at most once, when it's first filled. The space complexity is O(m·n) for the queue. In the worst-case scenario, a grid that's mostly gates puts nearly every cell in the queue at the start.

Oh, one more thing — this pattern fits any question about distance to the nearest of many sources. If I had to return how many waves it took instead, the sz snapshot would become essential, not optional.
