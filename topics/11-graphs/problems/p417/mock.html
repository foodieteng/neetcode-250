A naive approach would be to search from every cell and check if it reaches both oceans — that's O((mn)²).

This problem reminds me of a reverse flood fill: when many starting points share one target, search backward from the target instead. Two flood fills from the borders, going uphill, then intersect the two reachable sets. One linear pass each — O(mn).

Here's the plan.

// two reachable grids: p_set, a_set
dfs from Pacific edges (top row + left col) → mark p_set
dfs from Atlantic edges (bottom row + right col) → mark a_set
dfs(seen, r, c): mark; go to neighbor if heights[nei] >= heights[cur]
answer = cells where p_set AND a_set

One: flood from the Pacific edges, the top row and left column, into p_set.
Two: flood from the Atlantic edges, the bottom row and right column, into a_set — each step only goes to a neighbor at least as high.
Three: collect the cells marked in both.

Here, I'm using two separate visited grids to keep track of what each ocean can reach, so I can intersect them at the end.

One thing worth flagging — the flood condition is >=, not <=. Real flow is downhill, so the reversed walk goes uphill. And it includes equals, because equal-height cells share flow.

There's a trade-off here. Two m × n boolean grids cost extra memory, but they buy linear time over the quadratic per-cell search.

class Solution {
public:
    int m, n;
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    vector<vector<int>> pacificAtlantic(vector<vector<int>>& heights) {
        m = heights.size(); n = heights[0].size();
        vector<vector<bool>> p_set(m, vector<bool>(n, false)), a_set(m, vector<bool>(n, false));

        for (int i = 0; i < m; i++) {             // left edge → Pacific, right edge → Atlantic
            dfs(heights, p_set, i, 0);
            dfs(heights, a_set, i, n - 1);
        }
        for (int i = 0; i < n; i++) {             // top edge → Pacific, bottom edge → Atlantic
            dfs(heights, p_set, 0, i);
            dfs(heights, a_set, m - 1, i);
        }

        vector<vector<int>> ans;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (p_set[i][j] && a_set[i][j])       // reaches both oceans → answer
                    ans.push_back({i, j});
            }
        }
        return ans;
    }

    void dfs(vector<vector<int>>& heights, vector<vector<bool>>& seen, int r, int c) {
        seen[r][c] = true;                     // mark on entry
        for (auto [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            if (seen[nr][nc] || heights[nr][nc] < heights[r][c]) continue;  // only climb to neighbors >= current
            dfs(heights, seen, nr, nc);
        }
    }
};

The main function runs a DFS from every border cell: the left and top edges fill p_set, the right and bottom edges fill a_set. Then one scan collects every cell that's true in both. The DFS marks the cell on entry, skips out-of-bounds neighbors first, then skips anything already seen or lower than the current cell.

One thing worth flagging — heights[nr][nc] < heights[r][c] is the guard I continue on, which means I only recurse when the neighbor is >=. Flip that comparison and the whole thing floods the wrong direction.

Let me think about complexity here.

The time complexity is O(m·n) — two floods, each visiting every cell at most once, plus a linear intersection scan. The space complexity is O(m·n) for the two boolean grids and the recursion stack.

Oh, one more thing — the whole win is the reversal. Asking "can this cell reach the ocean" per cell is quadratic; asking "what can the ocean reach, going uphill" is one linear flood per ocean. That reverse-the-search trick shows up whenever many sources share one target.
