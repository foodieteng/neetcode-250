// map: original node → clone
dfs(node):
  if node in map → return map[node]  // reuse, breaks the cycle
  copy = new Node(node.val)
  map[node] = copy  // store BEFORE recursing
  for nei in node.neighbors: copy.neighbors.push(dfs(nei))
  return copy

One: if the node is already in the map, return its clone.
Two: otherwise create a copy and store it in the map right away.
Three: recurse into each neighbor, append the returned clones to the copy's neighbors, and return the copy.

Here, I'm using the map to keep track of which originals I've already cloned.

One thing worth flagging — I store the copy before recursing. If I recursed first, a cycle A→B→A would reach A before it's mapped, clone it again, and loop forever.

There's a trade-off here. Since values are unique and ≤ 100, I can swap the hashmap for a fixed array of 101 slots indexed by val — constant size, O(1). I'll show both.

// MAIN — DFS + HASHMAP
// Node: int val; vector<Node*> neighbors;
class Solution {
public:
    Node* cloneGraph(Node* node) {
        if (!node) return nullptr;                    // empty graph
        unordered_map<Node*, Node*> clone;          // original → clone
        return dfs(node, clone);
    }

    Node* dfs(Node* node, unordered_map<Node*, Node*>& clone) {
        if (clone.count(node)) return clone[node];       // already cloned → reuse it

        Node* copy = new Node(node->val);
        clone[node] = copy;                            // store BEFORE recursing (breaks the cycle)
        for (Node* nei : node->neighbors)
            copy->neighbors.push_back(dfs(nei, clone));
        return copy;
    }
};

The main version guards against an empty graph, then runs DFS with an unordered_map from original to clone.

One thing worth flagging — the clone[node] = copy line comes before the neighbor loop; that ordering is what makes cycles terminate.

// FOLLOW-UP — O(1) MAP VIA VAL-INDEXED ARRAY
class Solution {
public:
    Node* cloneGraph(Node* node) {
        if (!node) return nullptr;
        vector<Node*> clone(101, nullptr);            // fixed 101 slots, indexed by val → O(1)
        return dfs(node, clone);
    }

    Node* dfs(Node* node, vector<Node*>& clone) {
        if (clone[node->val]) return clone[node->val];   // val is unique → use it as the index

        Node* copy = new Node(node->val);
        clone[node->val] = copy;
        for (Node* nei : node->neighbors)
            copy->neighbors.push_back(dfs(nei, clone));
        return copy;
    }
};

For the follow-up, the only change is the map's type: a vector<Node*>(101), indexed by value. To be precise, that makes the map constant size, but the recursion stack is still O(V). For a general graph you can't reach true O(1) space — any traversal must remember what it visited. Unlike a linked list, a graph has no next pointer to enumerate its nodes for free.

Let me think about complexity here.

The time complexity is O(V + E) — each node is cloned once, and each edge is walked once from each end. The space complexity is O(V) for the map plus the recursion stack. In the worst-case scenario, a long chain makes the stack that deep.
