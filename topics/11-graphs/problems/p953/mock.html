Here's the plan.

// rank[c] = position of letter c in order
for each adjacent pair (w1, w2):
  compare column by column up to the shorter length
  · same letter → keep going
  · different → if rank[w1] > rank[w2] return false; else this pair is OK, stop
  all equal so far & w1 is longer → return false // prefix rule

One: build rank, each letter's place in the alien order, so a letter comparison is one array lookup.
Two: for each adjacent pair, compare column by column; the first different letter decides — bigger rank first means false.
Three: if all shared letters match and w1 is longer, return false.

One thing worth flagging — why checking adjacent pairs is enough. Sorted-ness is transitive: if w0 ≤ w1 and w1 ≤ w2, then w0 ≤ w2 for free. So I don't need all O(n2) pairs.

There's a trade-off here. The prefix case is easy to miss: ["apple","app"] must be false, because the shorter word should come first. I handle it after the inner loop.

Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    bool isAlienSorted(vector<string>& words, string order) {
        vector<int> rank(26, 0);
        for (int i = 0; i < 26; i++) {
            rank[order[i] - 'a'] = i;          // letter → its place in order
        }

        int n = words.size();

        for (int i = 0; i < n - 1; i++) {          // only adjacent pairs
            string w1 = words[i], w2 = words[i + 1];
            int minL = min(w1.size(), w2.size());
            int j = 0;

            for (; j < minL; j++) {
                if (w1[j] == w2[j]) continue;            // same → next column
                if (rank[w1[j] - 'a'] > rank[w2[j] - 'a']) return false;  // w1 bigger → out of order
                break;                                // different but OK → pair settled
            }

            if (j == minL && w1.size() > w2.size()) return false;  // prefix rule: longer first is wrong
        }

        return true;
    }
};

First I fill rank from order. Then for each adjacent pair I walk up to minL: same letter, keep going; a bigger rank in w1, return false. After the loop, if j == minL and w1 is longer, that's the prefix rule — return false.

One thing worth flagging — the break is doing real work. Once the first differing letter settles the pair, I must stop. If I kept comparing later columns, a reversed letter further down could wrongly fail a pair that's already in order — like ["ay","bx"], where a ranks before b but y ranks after x.

The time complexity is O(Σ|words|), linear in the total length — building rank is O(26), and every letter I compare is charged once against the total input length. The space complexity is O(1) — just the fixed 26-slot rank array.

In the worst-case scenario, all words nearly equal, I scan every character once.
