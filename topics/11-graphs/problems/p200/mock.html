Here's the plan.

// count = number of DFS launches
for each cell (i, j):
  if grid[i][j] == '1': count++; dfs(i, j)

dfs(r, c): if out of bounds or grid[r][c] == '0' → return
  grid[r][c] = '0' // sink NOW, before recursing
  dfs into 4 neighbors

One: scan every cell.
Two: when a cell is land, add one to the count and launch a DFS from it.
Three: the DFS returns on out-of-bounds or water; otherwise it sinks the cell to '0' and recurses into its four neighbors. So the grid itself is my visited marker.

One thing worth flagging — I sink the current cell before I recurse. If I recursed first, two adjacent cells would call each other forever, A into B and B back into A while A is still '1', and blow the stack.

There's a trade-off here. Sinking mutates the input, and on a huge all-land grid the recursion can get O(m·n) deep and overflow — so for very large inputs I'd switch to BFS with a queue. Does this approach sound good, or would you rather I think of another way?

class Solution {
private:
    int m, n;
    const vector<pair<int, int>> dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

public:
    int numIslands(vector<vector<char>>& grid) {
        m = grid.size(); n = grid[0].size();
        int cnt = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == '1') {       // unseen land = new island
                    cnt++;
                    dfs(grid, i, j);            // sink the whole island
                }
            }
        }
        return cnt;
    }

    void dfs(vector<vector<char>>& grid, int r, int c) {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] == '0') return;
        grid[r][c] = '0';                     // sink now, then recurse
        for (auto [dr, dc] : dirs) {
            int nr = r + dr, nc = c + dc;
            dfs(grid, nr, nc);
        }
    }
};

Two nested loops scan the grid; each unseen land cell bumps the count and starts a DFS. The DFS checks bounds and water first, sinks the cell, then visits four neighbors from a small dirs table.

One thing worth flagging — the comparisons use '1' and '0', with quotes. The grid is char, so a bare == 1 in the scan compares against character code one, never matches, and the function silently returns 0. The same slip in the DFS base case is worse: a sunk cell no longer stops the recursion, so neighbors bounce back and forth until the stack overflows.

The time complexity is O(m·n) — each cell is scanned once and sunk at most once. The space complexity is also O(m·n), for the recursion stack in the worst case. In the worst-case scenario, one snake-shaped island filling the grid makes the stack that deep.

Oh, one more thing — that deep-stack case is exactly when I'd reach for BFS instead. A queue keeps the frontier on the heap and won't overflow the call stack. Same O(m·n) time.
