題目簡介// THE QUESTION

QUESTION

手上有一疊牌 hand,問能不能把它們全部分成好幾組,每組剛好 groupSize 張,而且組內的點數是連續的(例如 3,4,5)。
1 ≤ n ≤ 104,0 ≤ hand[i] ≤ 109,1 ≤ groupSize ≤ n。

範例:[1,2,3,6,2,3,4,7,8], 3 → true(分成 [1,2,3]、[2,3,4]、[6,7,8]); [1,2,3,4,5], 4 → false(拿走 1,2,3,4 之後只剩一張 5)。

看最小的那張牌:它前面已經沒有更小的牌,所以它只能當某一組的「開頭」。 最小的 k 有 cnt 張,就一定要開 cnt 組 k, k+1, …, k+g−1 —— 不用選、不用試,一次扣完。
2

為什麼從最小的開始扣// WHY SMALLEST FIRST

A 回溯:每次試一種開頭 指數
每一步挑一個還有剩的點數當開頭、拿掉 g 張再遞迴。正確(驗證時拿它當參考解),但分支數爆炸;其實除了最小的那張,其他開頭都不用試。
× REJECT · TLE
B 一次只湊一組 O(n log n) · 常數大
每次從最小、還有剩的 key 湊一組,k..k+g−1 各減 1,直到它變 0。也正確(窮舉 20,592 組 0 錯),但 k 有 c 張就要重跑 c 次。10,000 張全是 7、g = 1:0.117 ms 對批次的 0.050 ms;各極端輸入實測慢 1.05–2.4 倍。
△ 能用 · 但一組一組扣
BATCH IT · ADOPT
C 有序 map + 一次扣 cnt O(n log n) / O(n)
最小的 k 還剩 cnt 張,就同時開 cnt 組:k..k+g−1 每一格都減 cnt。用到 0 的 key 之後輪到它時直接跳過。和回溯參考解對拍 270,592 組 0 錯;n = 104 實測約 3 ms。
● ADOPT · 每格成功只會發生一次

核心策略 · 三步驟// THE LOOP

  1. 數頻率 —— map<int,int> freq:key 會自動由小到大排好。
  2. 由小到大走每個 key —— 先複製 cnt = v;cnt == 0 代表這些牌已經被前面的組用光,跳過。
  3. 開 cnt 組 —— i = 0..g−1:k+i 不存在或剩不到 cnt 張 → false;否則減 cnt。全部走完 → true。

和 55、45 一樣是「由左往右掃、每一步的選擇是被逼出來的」:那裡是「最遠能到哪」,這裡是「最小的牌沒得選,只能當開頭」。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 最小的牌只能當開頭,而且全部一起開

設目前還剩下的最小點數是 k。任何一種合法分法裡,含有 k 的那一組如果不是從 k 開始,就需要一張 k−1 —— 但 k−1 已經沒有了。所以每一張 k 都是某一組的第一張,剩 cnt 張就恰好要開 cnt 組,每組都需要 k+1, …, k+g−1 各一張。 這一步完全沒有選擇:只要有任何一格不存在或不到 cnt 張,就不可能分得成,直接回傳 false;夠的話扣掉,剩下的牌又是同一個問題。

LEMMA 2 · cnt 一定要先複製,0 一定要跳過

迴圈寫的是 auto &[k, v],v 就是 freq[k] 本人。i = 0 時 freq[k] -= v 會把 freq[k] 變成 0,v 也跟著變成 0,後面的 k+1.. 就都在「減 0」。所以要先 int cnt = v; 存一份。 另外,被前面的組用光的 key 還留在 map 裡、值是 0;它不是任何一組的開頭,必須跳過,否則會去檢查它後面的 key 而誤判。這兩件事就是我第一版寫錯的地方(見程式碼頁)。

最佳解證明// PROOF OF OPTIMALITY

要證明什麼 · CLAIM

每一步扣牌都是「任何合法分法都必須做的事」—— 所以程式回 false 就真的分不成,回 true 就真的分得成。

PROOF · 手法:必然選擇
  1. 最小的牌沒有選擇。設剩下的最小點數是 k,有 cnt 張。含有 k 的那一組如果不從 k 開始,就需要一張 k − 1,但它不存在。所以每一張 k 都是開頭,恰好要開 cnt 組,需要 k + 1, …, k + g − 1 各 cnt 張。
  2. 不夠就一定失敗。第 1 步是每一種合法分法都得做的;只要哪一格不存在或不到 cnt 張,任何分法都做不到,回傳 false 正確。
  3. 扣完還是同一個問題。夠的話就扣掉這 cnt 組:原本分得成 ⇔ 剩下的牌分得成(把這 cnt 組拿掉 / 加回去)。所以由小到大一路扣完都沒出錯,就真的分得成。
面試這樣說 · 30 秒

剩下最小的那張牌前面沒有更小的,它只能當某一組的開頭,所以有幾張就得開幾組,後面 g − 1 個數都要扣這麼多張。這一步沒有選擇,任何分法都得這麼做,不夠就一定失敗;夠的話扣掉,剩下的又是同一個問題。

複雜度// COMPLEXITY

T = O(n log n)　　S = O(n)

內層看起來是 key 數 × g,但每一次成功的內層迭代至少扣掉 1 張牌,總共只有 n 張,所以成功的迭代 ≤ n 次,再加最多 1 次失敗。實測 n = 104 的所有極端輸入,內層最多 10,001 次。

部分次數說明
建 mapn 次插入O(n log n),主要成本
內層迭代≤ n + 1g = 104、0..9999 時 n·g = 108,實際只跑 10,000 次
空間O(n)最多 n 個不同 key;迴圈中 map 大小不變(count 先擋住,[] 不會插入)
數值範圍≤ 109 + 1k + i 一遇到缺的 key 就回傳,實測最大 1,000,000,001,int 夠用
