完整實作// COPY CNT · SKIP ZERO · SUBTRACT

p846.cpp C++17 
class Solution {
public:
    bool isNStraightHand(vector<int>& hand, int groupSize) {
        map<int, int> freq;
        for (int &x : hand) {
            freq[x]++;
        }

        for (auto &[k, v] : freq) {
            int cnt = v;
            if (cnt == 0) continue;
            for (int i = 0; i < groupSize; i++) {
                if (!freq.count(k + i) || freq[k + i] < cnt) return false;
                freq[k + i] -= cnt;
            }
        }

        return true;
    }
};

兩個官方範例 → true、false,都正確。 和窮舉回溯(每個點數都試當開頭,不是 greedy)對拍 270,592 組:窮舉值 0..5、長度 1–8 的全部多重集合 × 每個 groupSize 共 20,592 組 + 隨機 250,000 組(長度 ≤ 12),0 筆不一致。

每一行各自的意思:

  • map:key 由小到大,走訪順序就是「目前最小的牌」的順序。換成 unordered_map 順序就亂了(見第 4 節)。
  • int cnt = v:先把 k 剩幾張存成一個普通 int。下面 i = 0 那輪會把 freq[k](也就是 v)減成 0。
  • cnt == 0 → 跳過:這個 key 已經被前面開的組用光,它不是任何一組的開頭。
  • 內層:!freq.count(k + i) 放在 || 前面,短路保證 key 存在才會用 [],迴圈中 map 不會被插入新 key。

我寫錯的地方// MY MISTAKE

第一版的第二個迴圈(其他部分和上面一樣),直接拿 v 來比、來減,也沒有跳過 0:

p846_first_draft.cpp C++17 
        for (auto &[k, v] : freq) {
            for (int i = 0; i < groupSize; i++) {
                if (!freq.count(k + i) || freq[k + i] < v) return false;
                freq[k + i] -= v;   // ✗ v 就是 freq[k],i = 0 之後它就是 0
            }
        }
兩個錯,疊在一起變成「g ≥ 2 永遠回傳 false」

錯 1 · reference 改到自己:auto &[k, v] 的 v 是 freq[k] 本人。i = 0 執行 freq[k] -= v,freq[k] 變 0,v 也變 0;i ≥ 1 的檢查變成 freq[k+i] < 0(永遠不成立),每次只減 0 —— k+1.. 根本沒被扣到。

錯 2 · 沒跳過 0:因為 k+1.. 沒被扣,下一個 key 還留著原本的張數,又會被當成開頭再開一組,一路往右推。 最大的那個 key 一定會被走到,它會去找「最大值 + 1」—— 那張牌不可能存在。所以只要 groupSize ≥ 2,第一版一定回傳 false。實測窮舉 17,590 組 g ≥ 2 的輸入,第一版回傳 true 的次數是 0。

複雜度分析// COST BREAKDOWN

部分次數每次成本
建 freqnO(log n) 插入
外層走 key≤ n 個 keyO(1)(skip 或進內層)
內層成功的迭代≤ ncount + [] = O(log n)
內層失敗≤ 1直接 return
額外空間—≤ n 個 key 的 map
時間 O(n log n)　·　空間 O(n)　·　內層 ≤ n + 1 次

為什麼不是 O(n·g):每一次成功的內層迭代都減掉 cnt ≥ 1 張,而牌總共只有 n 張,所以成功的迭代加起來 ≤ n 次。
