範例 Trace// [1,1,2,2,3,3,3,4,5] · [5,5,5]

程式碼頁走過範例 1(每個開頭都只有 1 張)。這裡走兩個邊界:一個 key 有 2 張、要一次開兩組;和同一張牌太多、後面接不上。

// [1,1,2,2,3,3,3,4,5], g = 3:cnt = 2 一次扣 init freq: {1:2, 2:2, 3:3, 4:1, 5:1} k=1 cnt=2 freq[1] 2→0 freq[2] 2→0 freq[3] 3→1 兩組 [1,2,3] k=2 cnt=0 skip 被 k=1 用光 k=3 cnt=1 freq[3] 1→0 freq[4] 1→0 freq[5] 1→0 組 [3,4,5] k=4 cnt=0 skip k=5 cnt=0 skip // OUTPUT: return true([1,2,3] ×2、[3,4,5])
// [5,5,5], g = 3:張數夠,但沒有下一張 init freq: {5:3} k=5 cnt=3 freq[5] 3→0 key 6 不存在 → return false // OUTPUT: return false(內層 2 次)
第一段的 k=1 就是 Q2 的答案:cnt 要是 2,freq[2]、freq[3] 才會各減 2。用 reference 的話 i = 0 之後 v 是 0,freq[3] 會停在 3。 [5,5,5] 說明 3 張相同的牌不是一組「順子」:3 個 5 都只能當開頭,每一組都需要 6 和 7。

應用題// APPLY IT

App 1. 1296 Divide Array in Sets of K Consecutive Numbers:nums 能不能分成好幾組、每組 k 個連續數字?要改什麼?
App 2. 不只回答 true / false,還要把分好的每一組回傳出來。要多記什麼?範例 1 回傳什麼?
App 3. 659 Split Array into Consecutive Subsequences:每一段只要求長度 ≥ 3、不固定長度。這題的「最小的牌一定開新的一組」還成立嗎?
// ANSWERS
A1. 包含最小牌 k 的那一組,如果 k 不是第一張,就需要 k−1 排在它前面 —— 但比 k 小的牌已經全部分完了。所以 k 只能當開頭,而且每一張 k 都是。

「留給之後」沒有意義:之後的組開頭都 ≥ k,它們裡面放不進 k。所以 cnt 張 k 就要開 cnt 組,每組都要 k+1..k+g−1 各一張。這一步沒有任何選擇,做不到就一定分不成。
A2. 從 i = 1 開始錯:i = 0 的 freq[k] -= v 把 freq[k] 減成 0,v 是它的 reference,也變成 0。之後 freq[k+i] < 0 永遠不成立,每格都只減 0。

g = 1 時內層只有 i = 0 一輪,v 歸零之後就沒有下一輪了,所以不會錯。實測第一版在 g = 1 的 3,002 組全對,g ≥ 2 的 17,590 組一次 true 都沒回傳。
A3. 被前面的組扣到 0 的 key 還留在 map 裡(減到 0 不會刪掉),所以外層照樣會走到它。它不是任何一組的開頭,要跳過。

只補 skip 不夠:錯的不是「走到 0」,而是 v 在 i = 0 就變 0、k+1.. 根本沒被扣,下一個 key 還是原本的張數,skip 擋不到它。實測「用 v + skip」錯 151 組,和第一版錯的組合完全一樣;「cnt 複本但沒 skip」也錯 151 組。兩個都要。
A4. 每一次成功的內層迭代都會把某個 freq 減掉 cnt ≥ 1。所有 freq 加起來一開始是 n,不會變負,所以成功的迭代總共 ≤ n 次,失敗的最多 1 次(直接 return)。

被跳過的 key 只花 O(1)。實測 0..9999 各一張、g = 104:n·g = 108,內層實際只跑 10,000 次(第一個 key 一次扣完,其他 9,999 個都跳過)。所以瓶頸是建 map 的 O(n log n)。
A5. 第一版在 g ≥ 2 時只會回答 false。範例 2 的正解本來就是 false,所以剛好答對;範例 1 正解 true,才抓得到。

151 組錯的剛好是「正解 true 且 g ≥ 2」的全部輸入。自測要挑一個 g ≥ 2、答案是 true 的輸入,例如 [1,2,3], g = 3(第一版回 false)或最小反例 [0,1], g = 2。
A-App 1. 完全一樣的題目,只是參數名換成 nums 和 k。同一份程式碼直接交。

唯一的坑是變數名:1296 的組大小參數叫 k,如果照抄 auto &[k, v],迴圈裡的 k 會把參數蓋掉,i < k 變成拿 key 當組大小。實測照抄只改 groupSize → k:編譯不會報錯(只有 -Wshadow 警告),但 1296 的兩個 true 範例都回傳 false。key 改名成 [start, v] 就好。
A-App 2. 扣完一個 key 的 cnt 之後,把 [k, k+1, …, k+g−1] 這一組 push cnt 次就好,不用多記狀態;中途 return false 時回傳空的。

範例 1 → [1,2,3] [2,3,4] [6,7,8];[1,1,2,2,3,3,3,4,5], g=3 → [1,2,3] [1,2,3] [3,4,5]。實測窮舉 20,592 組,每一個回傳的分法都恰好用完所有牌、每組都是 g 個連續數字,0 錯。
A-App 3. 不成立。長度不固定時,x 可以「接在某一段的尾巴」而不是開新段;開新段反而可能讓別的段湊不到 3。所以 659 的貪心順序是:先接、接不上才開。

做法:freq 記剩幾張,endAt[x] 記有幾段結尾在 x。依序處理每張 x:有 endAt[x−1] > 0 就接上去;否則一定要開新段,而且馬上把 x+1、x+2 也拿走(湊滿 3);兩者都不行 → false。三個官方範例 [1,2,3,3,4,5] → true、[1,2,3,3,4,4,5,5] → true、[1,2,3,4,4,5] → false;和窮舉回溯對拍 2,001 組(值 0..4、長度 1–9)0 錯。第二個範例有 8 張牌,846 的「每組固定 3 張」根本分不了,659 卻可以分成 [1,2,3,4,5] 和 [3,4,5]。
