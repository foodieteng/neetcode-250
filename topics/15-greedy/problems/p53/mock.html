Hmm, let me think about this for a sec.

A naive approach would be to try every start index, then grow the end one step at a time and keep a running sum. That's O(n²). It's correct, but at n = 105 it took about 3,733 ms when I timed it. Too slow.

This problem reminds me of a one-pass DP, which is Kadane's algorithm. The idea: look at the best subarray that ends right here, at the current index. It has only two choices. Either it extends the best subarray that ended one step before, or it restarts with just the current number. Nothing else can be better. The real answer is just the best of these "ends here" values over all indexes.

C
CANDIDATE

Here's the plan.

// curL = best sum of a subarray that ends at num
// maxL = best sum seen anywhere so far
maxL = INT_MIN, curL = 0
for each num:
  curL = max(curL + num, num)  // extend vs restart
  maxL = max(maxL, curL)
return maxL

Here, I'm using curL to keep track of the best sum that ends at the current number, and maxL for the best sum I've seen so far.

One thing worth flagging — when do I restart? Let me walk through that. num beats curL + num exactly when curL is negative. So I drop the past only when the past sum is negative. It does not depend on whether the current number is negative. A common wrong idea is "reset when I see a negative number." Take [2,-1,2]. That rule gives 2, but the right answer is 3. The -1 is worth keeping, because 2 − 1 is still positive.

One thing worth flagging too — maxL starts at INT_MIN, not 0. This is a correctness rule, not style. If I start it at 0, then [-4] returns 0, but the answer is -4. Zero means "pick nothing," and that's not allowed. The scary part: starting at 0 still passes all three official examples. In my brute-force check, it failed on every all-negative array, and only those. And INT_MIN is safe because I only compare with maxL. I never add to it, so it can't overflow.

There's a trade-off here. The follow-up hints at divide and conquer. That's a nice idea, but it's O(n log n) and more code. Kadane is O(n) time and O(1) space. So I'll go with Kadane first.

Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int maxL = INT_MIN, curL = 0;

        for (int& num : nums) {
            curL = max(curL + num, num);
            maxL = max(maxL, curL);
        }

        return maxL;
    }
};

That matches the plan line by line.

One thing worth flagging — the order of the two lines in the loop. I update curL first, then maxL. So maxL always sees a subarray that includes the current number. That's what keeps "empty" out. If I swap the two lines, the very first compare uses curL = 0, which is the empty subarray, and [-4] would return 0 again. Also, curL = 0 at the start is fine. On the first number, extend and restart are both just nums[0].

Let me think about complexity here.

The time complexity is O(n). One pass, two max calls per number.

The space complexity is O(1). Just two integers.

In the worst-case scenario it's still exactly n steps. There's no early exit, but there's no extra work either. At n = 105 it ran in about 0.28 ms, versus about 3,733 ms for the O(n²) brute force.

Oh, one more thing — I'd test this against the brute force on lots of small arrays. That's how the maxL = 0 bug shows up. It hides from the official examples, but fails on every all-negative array.

Good. The follow-up asks for divide and conquer. How would that go?

C
CANDIDATE

I split the array in the middle. The best subarray is in one of three places: all in the left half, all in the right half, or crossing the middle. The left and right cases are recursive calls. For the crossing case, I take the best sum that ends at the middle going left, plus the best sum that starts right after the middle going right. That's one linear scan.

So the cost is T(n) = 2T(n/2) + O(n), which is O(n log n) time, plus O(log n) stack for the recursion. It's correct, but slower than Kadane. When I timed it at n = 105, it took about 1.6 ms, versus about 0.28 ms for Kadane. So in practice I'd ship Kadane, and keep divide and conquer as the follow-up answer.
