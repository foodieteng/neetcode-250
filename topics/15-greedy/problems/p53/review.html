重點回顧// RECAP

面向要記住的那一句
curL「結尾一定在這格」的最大和:max(curL + num, num)
重開的時機curL < 0:前面那段在拖後腿。和 num 自己是不是負的無關
maxL每格都拿 curL 比一次;從 INT_MIN 開始,因為至少要拿一個元素
順序先算 curL、再刷新 maxL;用「歸零」寫法時也是先刷新、再歸零
最常見的錯讓 0 混進答案:三種寫法都過範例,都錯全部 21,844 組全負陣列
速度n = 105:暴力 3,733 ms、分治 1.6 ms、Kadane 約 0.28 ms

觀念題// CONCEPT Q&A

Q1. curL 精確來說代表什麼?為什麼要強調「結尾一定在這格」?
Q2. 什麼時候會「重開」?有人寫成「遇到負數就重開」,錯在哪?
Q3. maxL 為什麼要從 INT_MIN 開始?改成 0 會錯哪些輸入?
Q4. 迴圈裡的兩行能不能交換順序(先 maxL = max(maxL, curL) 再算 curL)?
Q5. 這題放在 Greedy 章節,但 curL 看起來很像 DP。它到底是哪一種?

範例 Trace// [-3,-1,-2] · 全負 · 範例 3

程式碼頁走過範例 1;這裡走兩個極端:全部都是負的,和從頭到尾都不重開。

// [-3,-1,-2]:每一格都重開 i num extend restart curL maxL 0 -3 -3 -3 -3 -3 ↑ INT_MIN 被第一格取代 1 -1 -4 -1 -1 -1 ↑ 前面 −3 是負的 → 重開 2 -2 -3 -2 -2 -1 前面 −1 是負的 → 重開 // OUTPUT: return −1(最大的那個負數;maxL 若從 0 開始會回傳 0)
// 範例 3 [5,4,-1,7,8]:從不重開 i num extend restart curL maxL 0 5 5 5 5 5 ↑ 1 4 9 4 9 9 ↑ 2 -1 8 -1 8 9 −1 也接上:前面 9 是正的 3 7 15 7 15 15 ↑ 4 8 23 8 23 23 ↑ // OUTPUT: return 23(整段)
兩組剛好相反:全負時每格都重開,範例 3 一次都沒重開 —— 決定的是前面那段 curL 的正負,不是 num 本身。 範例 3 的 i = 2 是 num 為負卻照樣接上;全負陣列的 i = 1 是 num 為負卻選擇重開。

應用題// APPLY IT

App 1. 除了最大和,還要回傳那一段的起點和終點索引。要多記什麼?範例 1 會回傳什麼?
App 2. 陣列變成環狀(最後一格後面接回第一格,即 918)。怎麼用 Kadane 兩次解決?有什麼特例?
App 3. 改成求乘積最大的連續子陣列(152)。只把 + 換成 × 夠嗎?
// ANSWERS
A1. curL = 所有「最後一個元素是 nums[i]」的子陣列裡,和最大的那個。

強調結尾,是因為這樣才能遞推:結尾在 i 的段只有「nums[i] 自己」和「結尾在 i − 1 的段 + nums[i]」兩種,後者最好就是 curL(i−1) + nums[i]。如果 curL 只代表「到目前為止的最好」,下一格就不知道能不能接上去 —— 那一段可能早就斷了。
A2. 「重開」贏的條件是 num > curL + num,也就是 curL < 0。看的是前面那段,不是 num。

「遇到負數就歸零」實測窮舉錯 1,025,137 組,最小反例 [2,-1,2] → 2(正解 3):−1 雖然是負的,但前面有 2 撐著,帶著它走才能接到後面的 2。
A3. 題目要求至少拿一個元素。全負陣列的答案是最大的那個負數,從 0 開始的 maxL 永遠不會被刷新,等於回傳「一個都不拿」。

實測 maxL = 0 錯 21,844 組 —— 正好是窮舉裡全負陣列的總數,其他輸入全對,三個官方範例也都過。最小反例 [-4] → 0。另一個可行的初值是 nums[0],但迴圈就要從第二格開始,否則第一格會算兩次([1] → 2)。
A4. 不行。交換後 maxL 每次拿到的是「上一格」的 curL:第一次比的是初值 0,最後一格的 curL 永遠沒被比到。

實測錯 1,536,201 組,範例 1 都不過。最小反例 [-4] → 0。
A5. 兩種看法都對。DP 角度:curL 就是 dp[i],只是只需要前一格,所以壓成一個變數。貪心角度:每格只做一個局部決定 —— 前面那段是負的就丟掉,而且丟掉永遠不會吃虧。

和 860 的共同點:都能證明「這一步的選擇不會讓後面更糟」。860 靠交換論證,這題靠「負的前綴只會讓任何往後延伸的段更小」。
A-App 1. 多記兩組索引:start(curL 這段從哪開始,重開時設成 i)和 bestL / bestR(maxL 被刷新時,存下 start 和 i)。

範例 1:i = 3 重開,start = 3;maxL 最後一次刷新在 i = 6 → 回傳 [3, 6],也就是 [4,-1,2,1]。平手(curL + num == num,即 curL 剛好 0)時接上或重開都可以,和一樣,只是段的長短不同。
A-App 2. 環狀的最佳段只有兩種:不跨尾巴(就是普通 Kadane 的最大),或跨尾巴 —— 那等於「總和 − 中間某段最小的子陣列」。最小那段也用 Kadane 求(max 換成 min)。答案 = max(最大段, 總和 − 最小段)。

特例:全負時「最小段」就是整個陣列,總和 − 它 = 0,代表一個都不拿,不合法。所以最大段 < 0 時直接回傳最大段。例:[5,-3,5] → 10(跨尾巴的 5 + 5)。實測和暴力解窮舉 137,256 組 0 錯;拿掉全負判斷錯 1,092 組,最小反例 [-3] → 0。
A-App 3. 不夠。負數乘負數會變正,現在最小(最負)的那段,下一格乘上負數可能變最大。所以要同時記結尾在這格的最大乘積和最小乘積,每格從 {num, num × hi, num × lo} 三個裡挑。

例:[2,3,-2,4] → 6;[-2,3,-4] → 24(只記最大會得到 3)。實測只記最大的寫法窮舉 137,256 組錯 76,246 組,最小反例 [-3,1,-3] → 1(正解 9);同時記最大最小 0 錯。
