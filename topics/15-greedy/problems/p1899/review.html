PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼一個三元組只要有一位超過 target,就完全不能用?不能「先合進來,之後再想辦法」嗎?
解答與說明 · ANSWER▾
不管怎麼操作,最後的結果都是某幾個原本三元組的逐位 max。只要裡面有一個在第 k 位 > target[k],結果的第 k 位就 > target[k] —— max 只會變大,沒有任何操作能把它拉回來。

所以「先合進來再想辦法」不存在。能湊出 target 的組合只能用三位都 ≤ target 的三元組;丟掉其他的是必要條件,不是優化。
第 2 題10 分
安全的三元組裡,有些對答案根本沒貢獻(例如範例 3 的 [2,3,4])。為什麼全部合進來也沒關係?
解答與說明 · ANSWER▾
安全的三元組每一位都 ≤ target,合進來之後每一位也還是 ≤ target,不會讓任何一位超過。它最多是「沒幫上忙」,不會「幫倒忙」。

所以把安全的全部合起來,得到的是能做到的最大結果:任何安全的子集合起來,每一位都 ≤ 它。它等於 target 就做得到;它某一位小於 target,任何子集那一位只會更小,做不到。範例 3 的 [2,3,4] 合進來,ans 從 [2,5,3] 變 [2,5,4],沒有超過 [5,5,5]。
第 3 題10 分
ans(3, 1) 為什麼會錯?三個官方範例為什麼都抓不到?
解答與說明 · ANSWER▾
當所有三元組都被丟掉時,ans 停在起始值 [1,1,1]。如果 target 剛好也是 [1,1,1],就誤判成 true。最小反例 [[1,1,2]], target [1,1,1]。

官方範例抓不到,是因為三個範例裡 ans 都有被安全的三元組合到,起始值早就被 max 蓋掉了 —— 範例 1 兩種寫法每一步完全一樣。實測 751,853 組錯 21,220 組,全部是 target = [1,1,1],全部是「應該 false 卻回 true」。值都 ≥ 1,所以 0 永遠不會被誤認成已湊到。
第 4 題10 分
過濾條件用 < 而不是 <=,會在什麼輸入出錯?
解答與說明 · ANSWER▾
只要需要某一位「剛好等於 target」的三元組就會錯,最小反例 [[1,1,1]], target [1,1,1] → false(正解 true)。

用 < 會把剛好等於 target 的那一位也當成毒丟掉,但那正是我們要湊的值。實測錯 99,088 / 751,853 組,是所有改法裡錯第二多的。
第 5 題10 分
不過濾、只看「每一位有沒有某個三元組剛好等於 target」,為什麼會錯?加上什麼就對了?
解答與說明 · ANSWER▾
它只看「這一位等於」,沒看「另外兩位沒超過」。[[1,1,1],[1,2,2]], target [1,1,2]:[1,2,2] 的第 2 位等於 2 被算進來,但它第 1 位 2 > 1,其實不能用 → 回傳 true(正解 false)。

先套上同一個過濾就對了:安全的三元組 t[k] ≤ target[k],所以「合起來的 max == target[k]」和「有某個安全的 t[k] == target[k]」是同一件事。不過濾錯 143,595 組;過濾後 0 錯。第 8 題的 mask 就是把這個「哪幾位剛好等於」記成 bit。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩個最小反例,每一步寫下 ans:(a) [[1,1,2]], target [1,1,1],分別用正解 ans(3, 0) 和原本的 ans(3, 1) 走;(b) [[1,1,1],[1,1,2]], target [1,1,1],分別用正解(先過濾)和「不過濾,全部取 max」走。四個版本各回傳什麼?錯的兩個錯在哪一步?
解答與說明 · ANSWER▾
// [[1,1,2]], target [1,1,1] · 正解 ans(3, 0) ans = [0,0,0] [1,1,2] 第 2 位 2 > 1 → 丟掉 ans = [0,0,0] ans = [0,0,0] ≠ [1,1,1] // OUTPUT: false 沒有任何三元組能用,target 做不出來
// [[1,1,2]], target [1,1,1] · 原本的 ans(3, 1) ans = [1,1,1] [1,1,2] 第 2 位 2 > 1 → 丟掉 ans = [1,1,1] ans = [1,1,1] == [1,1,1] // OUTPUT: true(錯):沒合任何東西,起始值自己長得就像 target
// [[1,1,1],[1,1,2]], target [1,1,1] · 正解 [1,1,1] 安全 ans = [1,1,1] [1,1,2] 第 2 位 2 > 1 → 丟掉 ans = [1,1,1] // OUTPUT: true [1,1,1] 本身就是 target
// [[1,1,1],[1,1,2]], target [1,1,1] · 不過濾,全部取 max [1,1,1] ans = [1,1,1] [1,1,2] ans = [1,1,2] 毒被合進來,第 2 位變成 2 // OUTPUT: false(錯):第 2 位再也降不回 1
第一組是第 3 題的答案:所有三元組都被丟掉時,起始值會原封不動被拿去比,所以起始值不能是任何可能的真實值。 第二組是第 1 題的答案:max 只會變大,毒一旦合進來,那一位就永遠超過 target。過濾不是加速用的,少了它答案就錯。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
把操作從「逐位取 max」改成「逐位取 min」。過濾條件、起始值、合併各要怎麼改?[[4,6,5],[5,4,7]], target [4,4,5] 回傳什麼?
解答與說明 · ANSWER▾
整個方向反過來:min 只會變小,所以第 k 位小於 target 的才是毒,過濾改成三位都 t[k] >= target[k];起始值改成比任何真實值都大的數(值 ≤ 1000,用 1001);合併改成逐位 min。

[[4,6,5],[5,4,7]], target [4,4,5]:兩個都安全,ans 依序是 [4,6,5] → [4,4,5],回傳 true(實跑;和 min 版本的暴力閉包對拍 200,000 組,0 錯)。
第 8 題14 分
不只問做不做得到,還要回傳最少要用幾個原本的三元組(做不到回 −1)。三個官方範例各是多少?為什麼答案最多是 3?
解答與說明 · ANSWER▾
每個安全的三元組記一個 3 位元 mask:第 k 位 == target[k] 就把那個 bit 設起來。有 mask = 7 的 → 1 個;有兩個 mask OR 起來 = 7 → 2 個;全部 OR 起來 = 7 → 3 個;否則 −1。

最多 3 個,因為 target 只有三位,每一位挑一個「這一位剛好等於」的安全三元組就夠了,其他都是多餘的。mask 只有 8 種,檢查兩兩 OR 是常數時間,總共還是 O(n)。官方範例:範例 1 → 2([2,5,3] + [1,7,5])、範例 2 → −1、範例 3 → 3(三位各由不同的三元組湊到)。和「每個子集都試、找最少個數」對拍 200,000 組,0 錯。
第 9 題14 分
三元組變成長度 k 的向量(k 不固定)。程式要改哪裡?複雜度變成多少?
解答與說明 · ANSWER▾
把寫死的 3 換成 k = target.size():ans(k, 0),過濾改成一個迴圈檢查 k 位都 ≤,合併也改成迴圈。邏輯完全不變。

複雜度 O(n·k) 時間、O(k) 空間。k = 2..5 隨機 200,000 組和暴力閉包對拍,0 錯。三位寫死的版本只是 k = 3 的展開。
