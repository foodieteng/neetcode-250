題目簡介// THE QUESTION

QUESTION

給一堆三元組 triplets[i] = [a, b, c] 和一個目標 target = [x, y, z]。每次操作可以挑兩個不同的 i、j,把 triplets[j] 換成逐位取 max:[max(ai,aj), max(bi,bj), max(ci,cj)]。操作次數不限(也可以不做),問 target 能不能出現在 triplets 裡。
1 ≤ n ≤ 105,每個值都在 1..1000。

範例:[[2,5,3],[1,8,4],[1,7,5]], target [2,7,5] → true(合併第 0 和第 2 個:max([2,5,3],[1,7,5]) = [2,7,5]);[[3,4,5],[4,5,6]], target [3,2,5] → false(兩個的第二位都超過 2)。

max 只會讓數字變大、不會變小。所以只要某個三元組有任何一位超過 target,它一被合併進來,那一位就永遠超過了。 把這種三元組全部丟掉;剩下的「安全」三元組全部合併也不會超過 target。合出來的,就是能做到的最大結果 —— 它等於 target 就 true,否則 false。

為什麼先過濾再合併// WHY FILTER FIRST

A 把能合出來的全部列出來 O(2n)
從原本的集合開始,一直兩兩取 max 加進去,直到不再變多,再看 target 在不在裡面。正確(驗證時拿它當參考解),但能合出來的結果最多是 2n − 1 種子集,n = 105 完全不可能。
× REJECT · TLE
B 每一位各自找「剛好等於」 O(n)
三個位置各自問:有沒有哪個三元組的這一位 == target?三位都有就 true。快,但忘了「另外兩位不能超過」:[[1,1,1],[1,2,2]], target [1,1,2] 三位都找得到,卻回傳 true(正解 false,[1,2,2] 的第二位 2 > 1)。實測錯 143,595 / 751,853 組。
× REJECT · 少了過濾
FILTER FIRST · ADOPT
C 先丟掉超過的 · 安全的全部取 max O(n) / O(1)
三位都 ≤ target 的才留下,留下的逐位取 max,最後比 ans == target。和 A 的暴力閉包比對:n ≤ 3、值 1..3 窮舉 551,853 組 + 隨機 200,000 組(n ≤ 6、值 1..4),共 751,853 組,0 錯。B 只要先加上同一個過濾,也一樣 0 錯。
● ADOPT · 每個三元組看一次

核心策略 · 三步驟// THE LOOP

  1. 過濾 —— 三位都 t[k] ≤ target[k] 才算安全;任何一位超過就跳過,它一參與就毀了。
  2. 合併 —— 安全的全部逐位取 max:ans[k] = max(ans[k], t[k])。ans 從 [0,0,0] 開始。
  3. 比較 —— 掃完回傳 ans == target。安全的合起來不可能超過 target,所以只差在「每一位有沒有被湊到」。

和 763 Partition Labels 一樣,關鍵是 max 只會往一個方向走:那裡 r = max(r, …) 只往右推,所以要求只會變多;這裡 ans 只會變大,所以超過 target 就再也回不來。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 超過的那一位永遠救不回來

不管怎麼操作,最後出現在 triplets 裡的每個三元組,都是某幾個原本的三元組逐位取 max。如果其中一個原本的三元組在第 k 位超過 target[k],結果的第 k 位 ≥ 它 > target[k],不可能等於 target。 所以能湊出 target 的組合裡,只能有「三位都 ≤ target」的三元組。過濾不是加速,是正確性的必要條件:不過濾直接全部取 max,[[1,1,1],[1,1,2]], target [1,1,1] 會合成 [1,1,2],回傳 false(正解 true,只用 [1,1,1] 就好)。

LEMMA 2 · 安全的全部合併不吃虧 · 起始值必須是 0

安全的三元組每一位都 ≤ target,全部取 max 也還是 ≤ target;多合一個只會讓某一位更接近 target,不會害到別人。所以「安全的全部合併」是能做到的最大結果:它等於 target,target 就做得到;它不等於,任何安全的子集也只會更小,做不到。 起始值要用一個「真實值不可能是的數」:值都 ≥ 1,所以用 0。寫成 ans(3, 1) 時,如果所有三元組都被丟掉,ans 停在 [1,1,1],target 剛好是 [1,1,1] 就誤判成 true。最小反例 [[1,1,2]], target [1,1,1];實測 751,853 組裡錯 21,220 組,全部都是 target = [1,1,1]。三個官方範例都測不出來。
