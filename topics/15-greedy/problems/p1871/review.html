範例 Trace// "0000000" (1,3) · "0001000" (2,3)

程式碼頁走過兩個官方範例(窗口寬 2,從來沒有一進一出同時是 T)。這裡走兩個範例遮住的情況:窗口裡同時有好幾個 T,和同一步一進一出。

// "0000000",min 1,max 3:窗口寬 3,cnt 漲到 3 後一進一出 i s[i] 窗口 進(dp) 出(dp) cnt dp[i] 1 0 [0,0] 0 (T) +1 — 1 T 2 0 [0,1] 1 (T) +1 — 2 T 3 0 [0,2] 2 (T) +1 — 3 T 4 0 [1,3] 3 (T) +1 0 (T) −1 3 T 5 0 [2,4] 4 (T) +1 1 (T) −1 3 T 6 0 [3,5] 5 (T) +1 2 (T) −1 3 T // OUTPUT: return true
// "0001000",min 2,max 3:到得了的是 {0,2,4,5,6},中間有洞 i s[i] 窗口 進(dp) 出(dp) cnt dp[i] 2 0 [0,0] 0 (T) +1 — 1 T 3 1 [0,1] 1 (F) — 1 F s[3] = '1' 4 0 [1,2] 2 (T) +1 0 (T) −1 1 T 一進一出,cnt 不變 5 0 [2,3] 3 (F) 1 (F) 1 T s[1] 是 '0' 卻是 F:離 0 太近 6 0 [3,4] 4 (T) +1 2 (T) −1 1 T 又一次一進一出 // OUTPUT: return true
兩個例子的 i = 4 都是「一進一出、兩個都是 T」:cnt 是 +1 −1,不變。 換成旗標(Q3):先設 true 再設 false,dp[4] 變成 F。實跑兩個都回傳 false,正解都是 true —— 錯從 i = 4 開始。

應用題// APPLY IT

App 1. 不用一進一出,改用前綴和直接算「窗口裡有幾個 T」。要怎麼寫?
App 2. 如果 s 裡有一段連續 maxJump 個 '1',答案一定是 false 嗎?反過來,沒有這種段落、終點又是 '0',答案一定是 true 嗎?
App 3. 1696 Jump Game VI:每次往前跳 1..k 格,分數是踩過的 nums 總和,問最大分數。窗口還是「誰跳得到 i」,但 cnt 那招還能用嗎?
// ANSWERS
A1. cnt = 窗口裡已經確定到得了(dp = T)的格子數,也就是「一跳就能到 i 的起跳點」有幾個。

從 j 跳得到 i 的條件是 j + minJump ≤ i ≤ j + maxJump,把 j 移到一邊就是 i − maxJump ≤ j ≤ i − minJump。這段寬度固定(maxJump − minJump + 1),而且只在 i 左邊,所以算 dp[i] 時窗口裡每一格都已經算好了。
A2. 這一步窗口的左端是 i − maxJump,它還在窗口裡;離開的是上一步的左端 i − 1 − maxJump。

寫成 dp[i − maxJump] 實測錯 20,481 組,範例 1 就不過。最小反例 ("00", 1, 1) → false(正解 true):i = 1 時 dp[0] 剛進來,同一步就被當成離開踢掉了。
A3. 一個 T 離開時,旗標不知道窗口裡還剩不剩別的 T。同一步一進一出、兩個都是 T 的時候,旗標先設 true 再設 false,答案就錯了。

實測錯 33,483 組,兩個官方範例卻都過。最小反例 ("000", 1, 1) → false(正解 true)。上面兩個 trace 也一樣:旗標在 i = 4 出錯,兩個都回傳 false。
A4. 只在最後一行:dp[i] = cnt > 0 && s[i] == '0'。進、出兩行不管 s[i] 是什麼都要做,因為窗口是跟著 i 滑的,不是跟著能站的格子滑。

看到 '1' 就 continue 會漏掉那一步的進出:實測錯 42,347 組,最小反例 ("010", 1, 2) → false(正解 true)。完全忘了檢查 s[i] 更糟:錯 97,958 組,("01", 1, 1) → true。'1' 格不用特別從窗口排除 —— 它的 dp 是 F,本來就不會被數。
A5. 55 的 farthest 能用,是因為「到得了的格子是一段前綴」。這題有 minJump 下限,中間會有洞:"0001000"(2, 3)到得了 {0, 2, 4, 5, 6},index 1 是 '0' 卻到不了。所以要每一格自己算 dp。

只記「最後一個到得了的 index」也不行:它可能離 i 太近。實測錯 26,134 組,兩個範例都過;最小反例 ("0000", 2, 3) → false(正解 true):最後一個是 2,離 3 只有 1,可是 0 → 3 是合法的。反過來記「窗口裡最舊還沒過期的那一個」就對了(實測 0 錯):它離 i 最遠,如果連它都離 i 不夠遠,比它新的更不夠。
A-App 1. pre[k] = dp[0..k] 裡 T 的個數。算 dp[i] 時,窗口 [L, R] = [max(0, i − maxJump), i − minJump],裡面的 T 個數是 pre[R] − (L > 0 ? pre[L − 1] : 0),大於 0 而且 s[i] == '0' 就是 T,然後更新 pre[i]。

和直接模擬對拍窮舉 1,294,334 組 + 隨機 202,000 組,0 錯。本質一樣:cnt 就是「前綴和相減」的增量版,一進一出等於 R 和 L 各右移一格。
A-App 2. 第一句對:連續 maxJump 個 '1' 一定跨不過去(最遠只能跳 maxJump 格,一定會落在 '1' 上)。窮舉 n ≤ 12 的 229,374 組沒有反例;能到的情況裡,最長的 '1' 段剛好是 maxJump − 1。

第二句只在 minJump = 1 時成立(40,962 組全對)。minJump ≥ 2 時還有 34,037 組沒有擋路的 '1' 段、終點是 '0',答案卻是 false:"0000"(2, 2)只能踩偶數 index,到不了 3;"00000"(3, 3)只能踩 0 和 3。所以還是要跑 dp。
A-App 3. 窗口還是 [i − k, i − 1],但這次要的是窗口裡的最大 dp,不是個數。個數可以 +1 −1 維護,最大值不行 —— 最大的那一個離開時,不知道第二大是誰。改用單調遞減的 deque:隊頭是窗口最大,過期就從頭彈出,新值進來前把比它小的從尾巴彈掉。

dp[i] = nums[i] + dp[deque 頭]。三個官方範例 → 7、17、0;和 O(n·k) 暴力解對拍隨機 200,000 組,0 錯。同一個「誰跳得到 i」的窗口,問數量用 cnt,問最大用 deque。

誰跳得到 i = 窗口 [i − maxJump, i − minJump];cnt 數裡面的 T,出的是上一步的左端 i − maxJump − 1。一進一出同時是 T 時旗標會錯。要個數用 cnt / 前綴和,要最大值(1696)用單調 deque。
