題目簡介// THE QUESTION

QUESTION

二進位字串 s,從 index 0 出發(保證 s[0] == '0')。站在 i 時,可以跳到任何 j,只要 i + minJump ≤ j ≤ i + maxJump 而且 s[j] == '0'。問能不能到最後一格 n − 1。
2 ≤ n ≤ 105,1 ≤ minJump ≤ maxJump < n。

範例:s = "011010", minJump = 2, maxJump = 3 → true(0 → 3 → 5);s = "01101110",同樣 2、3 → false。

和 55 不一樣的地方:跳的距離有下限 minJump,而且只能落在 '0' 上。 所以「到得了的格子」不再是一段前綴:"0001000"(2, 3)到得了的是 {0, 2, 4, 5, 6},index 1 明明是 '0' 卻到不了(離 0 太近)。55 的 farthest 一路推的做法用不上。
2

反過來問:誰跳得到 i?// LOOK BACKWARD

「從 j 跳得到 i」等於 i − maxJump ≤ j ≤ i − minJump。所以 dp[i](到不到得了 i)只看 i 左邊固定寬度的一段:

// "011010",minJump = 2,maxJump = 3 index 0 1 2 3 4 5 s 0 1 1 0 1 0 誰跳得到 i — — [0,0] [0,1] [1,2] [2,3] dp T F F T F T // dp[i] = 窗口裡至少一個 T,而且 s[i] == '0';dp[5] = T → return true
  • 窗口 = [i − maxJump, i − minJump](左端小於 0 就從 0 開始);i 比 minJump 小時窗口是空的,dp[i] 一定是 F。
  • i 往右一格,窗口也往右一格:右邊進來 i − minJump,左邊掉出 i − maxJump − 1。
  • 所以不用每次重新看整段 —— 記一個 cnt = 窗口裡有幾個 T,一進一出各改一次。
3

為什麼用窗口計數// WHY A COUNTED WINDOW

A 直接模擬:每格往前標 O(n·(max−min))
每個到得了的 i,把 i+minJump..i+maxJump 裡的 '0' 全標成 T。正確(驗證時拿它當參考解),但窗口可以寬到 n。全 '0'、n = 105、(1, 99999)實測 1,792 ms。
× REJECT · TLE
B 只記一個旗標 / 最後一格 錯
想省掉計數:用 bool 記「窗口裡有沒有 T」,或只記最近一個到得了的 index。兩個官方範例都過,但窮舉 229,374 組分別錯 33,483 和 26,134 組。一個 T 離開時,不知道窗口裡還剩不剩。
△ REJECT · 範例騙人
ADOPT THE COUNT
C 滑動窗口 + cnt O(n) / O(n)
cnt = 窗口裡 T 的個數;每一步進一格、出一格,各 O(1)。同一個情況實測 104.9 µs(比 A 快約 17,000 倍)。和參考解對拍:窮舉 n = 2..14 共 1,294,334 組 + 隨機 202,000 組,0 錯。
● ADOPT · 一進一出
4

核心策略 · 三步驟// IN · OUT · DECIDE

  1. 初值 —— dp[0] = true,cnt = 0;i 從 minJump 開始(更小的 i 誰都跳不到)。
  2. 進 —— dp[i − minJump] 是 T 就 cnt++:它剛好變成「離 i 夠遠」。
  3. 出 —— i − maxJump − 1 ≥ 0 且 dp[i − maxJump − 1] 是 T 就 cnt−−:它剛好變成「離 i 太遠」。
  4. 判 —— dp[i] = cnt > 0 && s[i] == '0'。

和 45 的對照:45 往前看「從這一層最遠跳到哪」,因為到得了的格子是連續的;這題中間會有洞,所以改成往後看「誰跳得到我」,每一格都要自己的答案,dp 陣列省不掉。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 要「數幾個」,不能只記「有沒有」

同一步裡可能一進一出。"000"(1, 1):i = 2 時 dp[1] 進來、dp[0] 掉出去,窗口裡還是有一個 T。用 cnt 是 +1 −1 = 1,正確;用旗標是先設 true 再設 false,得到 false,錯。 旗標只知道「最後一次發生什麼」,不知道窗口裡還剩幾個。窮舉錯 33,483 組,兩個官方範例卻都過。

LEMMA 2 · '1' 格不用特別處理,但不能跳過窗口更新

s[i] == '1' 的格子 dp 一定是 F,所以它之後進窗口也不會讓 cnt 加 —— 自動被排除。範例 1 的 i = 2:cnt = 1,但 s[2] = '1',dp[2] = F。 可是如果看到 '1' 就 continue、連進出都不做,窗口就會跟 i 脫節:窮舉錯 42,347 組,最小反例 "010"(1, 2)→ false(正解 true)。窗口每一步都要滑,判斷只在最後一行。

複雜度// COMPLEXITY

T = O(n)　　S = O(n)

每一格一次「進」、一次「出」、一次判斷。dp 陣列要留著,因為之後要回頭讀 dp[i − minJump] 和 dp[i − maxJump − 1]。

做法時間空間
A · 直接模擬O(n·(max−min)),實測 1,792 msO(n)
B · 只記旗標 / 最後一格錯—
C · 窗口計數(vector<int>)O(n),實測 104.9 µs400,000 bytes
同上改 vector<bool>O(n),實測 307.9 µs12,504 bytes

一句洞察// INSIGHT

不問「從 i 能跳到哪」,改問「誰能跳到 i」—— 答案是 i 左邊一段固定寬度的窗口。 窗口跟著 i 一格一格滑,cnt 記裡面有幾個到得了:進一個加、出一個減,cnt > 0 而且自己是 '0' 就到得了。

// ONE-LINE TAKEAWAY
dp[i] = s[i] == '0' 且窗口 [i − maxJump, i − minJump] 裡有 T。窗口每步右移一格:dp[i − minJump] 進、dp[i − maxJump − 1] 出,cnt 數裡面的 T。要用計數,不能用旗標。O(n) / O(n)。
