完整實作// IN · OUT · DECIDE

p1871.cpp C++17 
class Solution {
public:
    bool canReach(string s, int minJump, int maxJump) {
        int n = s.size();
        vector<int> dp(n, false);
        dp[0] = true;
        int cnt = 0;

        for (int i = minJump; i < n; i++) {
            if (dp[i - minJump]) ++cnt;

            if (i - maxJump - 1 >= 0 && dp[i - maxJump - 1]) --cnt;

            dp[i] = (cnt > 0 && s[i] == '0');
        }
        return dp[n - 1];
    }
};

🎧 面試模擬 · UMPIRE mock · 逐句點播有聲版 ↗

兩個官方範例 → true、false,都正確。 和直接模擬(每個到得了的格子往前標)對拍:窮舉 n = 2..14、每個 s[0] = '0' 的字串、每組合法 (minJump, maxJump),共 1,294,334 組 + 隨機 200,000 組(n ≤ 40)+ 隨機 2,000 組(n ≤ 105),0 筆不一致。ASan / UBSan 0 警告。

每一行在做什麼(「窗口」= 跳得到 i 的那一段 [i − maxJump, i − minJump],見概念頁):

這一行白話
vector<int> dp(n, false)dp[i] = 到不到得了 i;false 存成 0。用 int 不用 vector<bool>:實測快約 3 倍(104.9 vs 307.9 µs),代價是記憶體 400,000 vs 12,504 bytes
dp[0] = true; cnt = 0起點到得了;窗口一開始是空的
for (i = minJump; …)i < minJump 誰都跳不到(離 0 太近),dp 維持 0,不用跑
if (dp[i − minJump]) ++cnt進:i − minJump 剛好變成「離 i 夠遠」,是窗口新的右端
if (i − maxJump − 1 ≥ 0 && dp[i − maxJump − 1]) −−cnt出:i − maxJump − 1 上一步還在窗口左端,這一步離 i 太遠了。≥ 0 擋負的 index
dp[i] = (cnt > 0 && s[i] == '0')判:窗口裡有人到得了,而且 i 自己能站
return dp[n − 1]終點那一格的答案
為什麼進的是 i − minJump、出的是 i − maxJump − 1?把窗口寫成 [L, R]:R = i − minJump,L = i − maxJump。i 加 1,R 多出一格 i − minJump,L 前面少掉一格 i − maxJump − 1。 出的那一格是「上一步的 L」,不是「這一步的 L」—— 寫成 i − maxJump 會把還在窗口裡的那一格提早踢掉(見下方陷阱 1)。

邊界與陷阱// WHAT IF I CHANGE ONE LINE

每一種都實際改出來跑:窮舉 n = 2..12、所有 s[0] = '0' 的字串、所有合法 (minJump, maxJump),共 229,374 組,和直接模擬比。

改法錯幾組最小反例(s, min, max)過官方範例?
1 · 出的寫成 dp[i − maxJump]20,481("00", 1, 1) → false(正解 true):dp[0] 進來的同一步就被踢掉範例 1 不過
2 · 邊界寫成 i − maxJump − 1 > 045,823("010", 1, 1) → true(正解 false):dp[0] 永遠不會被踢掉範例 2 不過
3 · 進的寫成 dp[i − minJump + 1]68,864("00", 1, 1) → false範例 1 不過
4 · 忘了 s[i] == '0'97,958("01", 1, 1) → true:站到 '1' 上範例 2 不過
5 · s[i] == '1' 就 continue(放在進出之前)42,347("010", 1, 2) → false(正解 true):窗口少滑一格範例 1 不過
6 · 只看一格:dp[i] = dp[i − minJump] && …63,932("010", 1, 2) → false範例 1 不過
7 · 用 bool 旗標代替 cnt33,483("000", 1, 1) → false(正解 true):一進一出,旗標被設回 false兩個都過
8 · 只記「最後一個到得了的 index」26,134("0000", 2, 3) → false(正解 true)兩個都過
9 · return cnt > 068,864("01", 1, 1) → true:忘了終點自己要是 '0'兩個都過
(不是錯)進、出兩行對調0進的 index ≥ 出的 index + 1,兩件事互不影響過
(不是錯)i 從 1 開始,進的那行加 i − minJump ≥ 00i < minJump 時 cnt = 0,dp 自然是 0過
(不是錯)vector<bool>0省記憶體,慢約 3 倍過
(不是錯)開頭 if (s[n−1] == '1') return false0提早結束過
最危險的三個 —— 旗標代替 cnt、只記最後一格、return cnt > 0 —— 兩個官方範例都過。 範例的窗口寬只有 2,而且沒有「同一步一進一出都是 T」的情況,剛好遮住旗標的問題。自己測的時候,加一個全 '0' 的輸入:("000", 1, 1) 就能抓到 7。
