Hmm, let me think about this for a sec.

A naive approach would be to try every start, and drive the loop from it until the tank goes negative. That's O(n2). With 105 stations, that's up to 1010 steps. Too slow.

Another quick idea is to start at the station with the biggest diff. That's wrong. gas = [0,1,2], cost = [3,0,0]: the biggest diff is at 2, but the answer is 1. From 1 I save up 1 + 2 = 3, which is just enough for the 3 I need at station 0.

This problem reminds me of a greedy with a running sum, like Kadane's: keep a sum, and when it goes negative, throw it away and start fresh. The question is why throwing it away is safe here.

The key fact is a skip lemma. Say I start at s and the tank first goes negative at i. Then no station in [s..i] can be the start. Let me walk through that. Pick any station k in between. When I drove from s, I reached k with some tank that was at least zero. If I start at k instead, I reach it with zero. So I'm never better off. I had at most the same gas all the way to i, and I already failed there. So I can jump the start straight to i + 1. Each station is looked at once.

That's the second fact: an answer exists exactly when the total of all diffs is at least zero. If the total is negative, the loop costs more than it gives, so nothing works. If the total is at least zero, the last candidate start works.

Here's why. From start to the end of the array, the running sum never went negative. That's how start survived. Then I wrap around to station 0 and drive the part before start. That part is made of pieces that each failed, so each has a negative sum. But inside a piece, the sum only dips below zero at its very end. So the lowest my tank can get is at the very end, and there it holds exactly total, which is at least zero. The part before start is paid for by total >= 0.

So there are two separate jobs. total answers "is there an answer?" cur and start answer "which station is it?"

Here's the plan.

// total: sum of all diffs → is there an answer?
// cur:   tank since start → which station?
total = 0, cur = 0, start = 0
for i in 0..n-1:
  diff = gas[i] - cost[i]
  total += diff, cur += diff
  if cur < 0:  // nothing in [start..i] works
    start = i + 1, cur = 0
return total < 0 ? -1 : start

Here, I'm using cur to keep track of the tank since the current candidate start. And I'm using total to keep track of the whole loop. total is never reset.

One thing worth flagging — the two comparisons are both strict, and both on purpose. cur < 0, not <= 0: an empty tank is still fine, I just can't go below zero. And total < 0, not <= 0: a total of exactly zero is a valid loop. I come back with an empty tank, like in example 1.

There's a trade-off here. I could do two passes: first sum everything to check total, then a second pass to find start. That's easier to read. But both jobs only need the same diffs, so one pass does both, with three ints.

class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = gas.size();
        int total = 0, cur = 0, start = 0;

        for (int i = 0; i < n; i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            cur += diff;

            if (cur < 0) {
                start = i + 1;
                cur = 0;
            }
        }

        return total < 0 ? -1 : start;
    }
};

That matches the plan line by line.

One thing worth flagging — start = i + 1 can be n, which is out of range. But that only happens if the very last station fails. Then every piece of the array went negative, so total < 0, and I return -1 instead. When total >= 0, start is never n. In my tests it happened 0 times.

I also checked what breaks if I get a small detail wrong. I tested every input with n from 1 to 5 and values 0 to 3, keeping the 612,240 inputs that meet the "unique answer" rule:

Let me think about complexity here. There's one loop over the stations. The start jumps forward, but it never moves back, and I never restart the loop. So each station is visited once.

The time complexity is O(n). The space complexity is O(1): just total, cur, and start.

In the worst-case scenario, the start resets at almost every station, like in example 1. That's still O(1) per station. The skip lemma is what lets me never look back.

Oh, one more thing — overflow. total sums up to 105 diffs, each between -104 and 104. So |total| <= 10^9, which is below INT_MAX. A plain int is safe here. If the limits were bigger, I'd switch to long long.
