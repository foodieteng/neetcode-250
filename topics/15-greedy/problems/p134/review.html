觀念題// CONCEPT Q&A

Q1. 從 start 開到 i 失敗了,為什麼可以說 start 和 i 之間的每一站也都不能當起點?
Q2. 失敗之後,新的候選為什麼是 i + 1,不是 i?
Q3. 迴圈結束時 cur ≥ 0 只保證 start 開得到 n−1。為什麼再加上 total ≥ 0,就保證繞回來的那一段也夠?
Q4. 重設時為什麼一定要 cur = 0?忘了寫會怎樣?
Q5. start 有可能變成 n(超出範圍)嗎?為什麼回傳的時候不用擔心?

範例 Trace// 兩個最小反例 · 正解 vs 改一行

概念頁動畫走了範例 1 和兩次重設的例子,程式碼頁走了範例 2。這裡走兩個最小反例,每組正解和錯的版本並排,都是實際印出來的。

// gas=[0,1], cost=[1,0] · 正解 i=0 diff = −1 total = −1 cur = −1 < 0 → start = 1,cur = 0 i=1 diff = 1 total = 0 cur = 1 // OUTPUT: total = 0 ≥ 0 → 1
// gas=[0,1], cost=[1,0] · start = i i=0 diff = −1 total = −1 cur = −1 < 0 → start = 0,cur = 0 剛失敗的 0 又被選回來 i=1 diff = 1 total = 0 cur = 1 // OUTPUT: 0(錯):從 0 出發,0 公升的油付不起 1 的路費
// gas=[0,1,1], cost=[2,0,0] · 正解 i=0 diff = −2 total = −2 cur = −2 < 0 → start = 1,cur = 0 i=1 diff = 1 total = −1 cur = 1 i=2 diff = 1 total = 0 cur = 2 // OUTPUT: total = 0 → 1
// gas=[0,1,1], cost=[2,0,0] · 重設時忘了 cur = 0 i=0 diff = −2 cur: 0 → −2 < 0 → start = 1 cur 還是 −2 i=1 diff = 1 cur: −2 → −1 < 0 → start = 2 背著 0 號站的債,1 號站被冤枉淘汰 i=2 diff = 1 cur: −1 → 0 // OUTPUT: 2(錯):從 2 出發,繞到 0 要付 2,只帶了 1
第一組就是 Q2 的答案:i 這一站自己的 diff 已經算進 cur 裡、而且就是它讓 cur 變負,所以 i 一定也被淘汰。 第二組就是 Q4 的答案:cur 是「從新候選出發的油箱」,新候選是空油箱出發,不能背著前一段的債。

應用題// APPLY IT

App 1. 題目只問「有沒有辦法繞一圈」(回傳 true / false),最少要算什麼?
App 2. 換成前綴和來看:P[i] = diff[0] + … + diff[i]。答案和 P 的哪一個位置有關?寫成公式。
App 3. 如果拿掉「答案唯一」的保證(例如每站 gas 都等於 cost,每一站都能出發),這份程式碼回傳的會是哪一個起點?
// ANSWERS
A1. 中間任一站 k 從 start 開過來時,油箱是 start..k−1 的總和,而這個值 ≥ 0(不然早就重設了)。改從 k 出發等於空油箱到 k,油只會更少;原本帶著 ≥ 0 的油都在 i 撐不住,空油箱更撐不住。

所以一次失敗可以淘汰一整段,每一站最多被淘汰一次,總共只要一趟。這也是和「每站都試一圈」(O(n²))的差別:暴力解失敗後只往前挪一站。
A2. 讓 cur 變負的就是 i 這一站的 diff 本身(它已經加進 cur 了),從 i 出發的那一段也包含在 start..i 裡,一樣被淘汰。下一個還沒被排除的就是 i+1。

寫成 start = i 實測錯 91,922 組,最小反例 gas=[0,1], cost=[1,0] → 0(見範例 Trace)。
A3. 把整圈切成兩部分:前面被淘汰的幾段(0..start−1)和最後一段(start..n−1)。total = 前面各段總和 + cur。total ≥ 0 代表 cur ≥ 前面各段的總虧損。

前面每一段都是「中途一直 ≥ 0、只在最後一站變負」,所以帶著 cur 繞回去時,每一段只會在段尾扣錢,而 cur 夠付所有段尾的虧損。窮舉 1,118,480 組驗證:「total ≥ 0」和「存在可行起點」每一組都一致。
A4. 新候選是空油箱出發,cur 必須從 0 開始;不歸零的話,新候選會背著前一段的債,被冤枉淘汰。

實測錯 24,699 組,最小反例 gas=[0,1,1], cost=[2,0,0]:正解 1,忘了歸零回傳 2(1 號站被 0 號站的債拖下水)。寫成 cur = diff 也一樣錯,23,984 組。
A5. 可能,但只會在 total < 0 的時候:start 要變成 n,代表最後一站也讓 cur 變負,那每一段都是虧的,total 一定 < 0,回傳的是 −1。

實測 total ≥ 0 時 start == n 出現 0 次;n = 1、gas=[4], cost=[5] 就是 start 變成 1 = n 但回傳 −1 的例子。所以寫 start % n 也不會錯(0 / 612,240),只是多餘。
A-App 1. 只要 total:return total >= 0;。cur 和 start 都是為了「是哪一站」才需要的。

這就是概念頁說的「兩個問題」。窮舉 n ≤ 5、值 0..3 的全部 1,118,480 組,「total ≥ 0」和「暴力解找得到起點」每一組都一致。
A-App 2. 答案 = 前綴和最小值「第一次」出現的位置 + 1(繞回 0 用 % n);total < 0 則 −1。

直覺:從前綴和最低點的下一站出發,之後每個前綴都比最低點高,油箱不會變負。和本題的 cur 寫法其實是同一件事 —— cur 每次重設的地方,就是前綴和創新低(比 0 和之前所有前綴都低)的地方。範例 1 → 3、範例 2 → −1、動畫裡的第二個例子 → 4;和暴力解比對 612,240 組合法輸入,0 錯。
A-App 3. 會回傳「最小的」可行起點。gas == cost 的例子 cur 從來不變負,start 停在 0。

實測:窮舉裡 506,240 組有多個可行起點的輸入,這份程式碼回傳的每一次都是最小的那個可行起點。直覺是:start 只在被證明不可行時才往右移,所以第一個沒被淘汰的可行起點會一直留著。
