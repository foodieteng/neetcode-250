A naive approach tries every start index and walks up to n steps with the index wrapping i % n. That's O(n²) — correct, and I'd keep it as a brute force to test against, but too slow at 3·104 elements.

This problem reminds me of Kadane's algorithm — the extend-or-restart scan for maximum subarray on a straight line — and it covers the non-wrapping case directly. For the wrap case, I flip the question: instead of searching for the best wrap, I find the worst normal block, the minimum subarray, and cut it out. Total minus the minimum block is the best wrap, and the minimum comes from the same Kadane with min instead of max, in the same loop.

Here's the plan.

// curMx / curMi = best / worst sum ending at x
// subMx / subMi = best / worst block seen so far
total = 0, curMx = 0, curMi = 0
subMx = INT_MIN, subMi = INT_MAX
for each x:
  total += x
  curMx = max(curMx + x, x)  // extend vs restart
  curMi = min(curMi + x, x)  // same, for min
  subMx = max(subMx, curMx)
  subMi = min(subMi, curMi)
if subMx < 0: return subMx  // all negative
return max(total − subMi, subMx)  // wrap vs normal

One: track the total, plus curMx and subMx for the best block, curMi and subMi for the worst.
Two: for each element, add it to the total, run extend-or-restart for both, and refresh the records.
Three: if subMx < 0, return subMx; otherwise return the larger of subMx and total − subMi.

One thing worth flagging — that guard. On [-3,-2,-3], the minimum block is the whole array, so total − subMi is 0 — the empty subarray, which isn't allowed. The answer is -2. And the guard must check subMx, not total: [1,-3,1] has a negative total, yet the wrap gives 2.

A doubled array with a monotonic deque also works, but needs O(n) space. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. One loop: each element goes into the total, curMx and curMi each extend or restart, then subMx and subMi take any new record. After the loop, the guard returns subMx if it's negative; otherwise I return the larger of total − subMi and subMx.

class Solution {
public:
    int maxSubarraySumCircular(vector<int>& nums) {
        int total = 0, curMx = 0, curMi = 0;
        int subMx = INT_MIN, subMi = INT_MAX;

        for (int &x : nums) {
            total += x;

            curMx = max(curMx + x, x);
            curMi = min(curMi + x, x);
            subMx = max(subMx, curMx);
            subMi = min(subMi, curMi);
        }

        if (subMx < 0) return subMx;
        return max(total - subMi, subMx);
    }
};

One thing worth flagging — the start values. subMx starts at INT_MIN and subMi at INT_MAX, not 0 — otherwise [-1] returns 0. Also, the last line still needs the max with subMx: [1] would otherwise give 0, because the min block is the whole array again.
