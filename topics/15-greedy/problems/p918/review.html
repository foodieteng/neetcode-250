PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼「跨尾巴的最大段」可以寫成 total − subMi?
解答與說明 · ANSWER▾
跨尾巴的段 = [j..n−1] + [0..i],沒拿到的正好是中間連續的一段。和 = total − 那一段,要和最大就讓那一段最小。

所以不用列舉跨尾巴的段,只要找「最小的連續段」—— 這就是把 53 的 Kadane 反過來用。
第 2 題10 分
如果 subMi 那段剛好貼著陣列的頭或尾(不是在中間),total − subMi 還是合法的答案嗎?
解答與說明 · ANSWER▾
合法。拿掉貼著頭(或尾)的一段,剩下的是一段普通的、不跨尾巴的子陣列,本來就是候選答案,只是 subMx 也會算到它,多算一次無妨。

唯一不合法的情況是最小段 = 整圈,剩下空段。窮舉 19,607 組裡這發生 2,955 次,其中 2,592 次 subMx ≥ 0、max 會選 subMx,不出事。
第 3 題10 分
為什麼全負判斷要看 subMx < 0,不能看 total < 0?
解答與說明 · ANSWER▾
要擋的是「最小段 = 整圈」且其他答案都 < 0 的情況,也就是全負。總和是負的,不代表每一格都負。

實測 if (total < 0) 錯 484 組,最小反例 [1,-3,1] → 1(正解 2):總和 −1,但跨尾巴的 1 + 1 = 2 才是答案,被判斷擋掉了。改成 total == subMi(直接問「最小段是不是整圈」)或 subMx <= 0 則都 0 錯。
第 4 題10 分
全負時改成 return total 可以嗎?
解答與說明 · ANSWER▾
不行。全負時答案是「最大的那個負數」(只拿一格),不是整圈的和。

實測錯 360 組,最小反例 [-1,-1] → −2(正解 −1)。只有一個元素時兩者剛好相等,所以 [-1] 測不出來。
第 5 題10 分
兩個 Kadane 能放在同一個迴圈,是因為它們互不依賴。那每個 Kadane 自己的兩行(cur 和 sub)能不能交換?
解答與說明 · ANSWER▾
不行,和 53 的 Q4 一樣:先更新 sub 再更新 cur,sub 拿到的是上一格的 cur,第一次比的是初值 0、最後一格沒被比到。

實測錯 363 組,最小反例 [-1] → 0(正解 −1)。兩個 Kadane 之間的順序則可以隨便排,total += x 放哪裡也無所謂。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
程式碼頁走過「跨尾巴贏」的 [2,-3,4,-6,1,5];拿一張紙手走另外兩種結局:範例 3 [-3,-2,-3] 和範例 1 [1,-2,3,-2],每一格更新 total、curMx、curMi、subMx、subMi,最後走收尾那兩行。兩個各回傳什麼?哪一個走進 subMx < 0 那一行?那一刻 total − subMi 是多少、代表什麼?
解答與說明 · ANSWER▾
// 範例 3 [-3,-2,-3]:全負,最小段 = 整圈 i x total curMx curMi subMx subMi 0 -3 -3 -3 -3 -3 -3 1 -2 -5 -2 -5 -2 -5 curMx 重開;curMi 接上 2 -3 -8 -3 -8 -2 -8 curMi 一路接上 → 整圈 −8 subMx = −2 < 0 → 直接回傳(total − subMi = −8 − (−8) = 0 是空段) // OUTPUT: return −2
// 範例 1 [1,-2,3,-2]:不跨尾巴贏 i x total curMx curMi subMx subMi 0 1 1 1 1 1 1 1 -2 -1 -1 -2 1 -2 最小段 [1] = −2 2 3 2 3 1 3 -2 curMx 重開:3 > −1+3 3 -2 0 1 -2 3 -2 [3] 也是 −2,平手不更新 subMx = 3 ≥ 0 → max(total − subMi = 0 − (−2) = 2, subMx = 3) // OUTPUT: return 3(只拿 [2];跨尾巴的 3,−2,1 只有 2)
三種結局各一組:[2,-3,4,-6,1,5] 跨尾巴贏(9 > 6),範例 1 不跨尾巴贏(3 > 2),範例 3 兩個都不比,判斷那行直接回傳。 範例 3 的 total − subMi 正好是 0 —— 這就是「最小段 = 整圈」的訊號,全負時一定發生。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
除了最大和,還要回傳那一段的起點和終點索引(跨尾巴時起點 > 終點)。要多記什麼?[2,-3,4,-6,1,5] 會回傳什麼?
解答與說明 · ANSWER▾
每個 Kadane 各記一個 start(重開時設成 i),紀錄被刷新時存下 [start, i]。最後:不跨尾巴贏就回傳最大段的區間;跨尾巴贏就回傳最小段區間 [L, R] 的「補集」[R+1, L−1](都取 % n)。

[2,-3,4,-6,1,5]:最小段 [3, 3] → 回傳 [4, 2],即 4 → 5 → 0 → 1 → 2,和 9。[5,-3,5] → [2, 0],和 10。實測窮舉 137,256 組(值 −3..3、長度 1–6),回報的區間和都等於正解,0 錯。
第 8 題14 分
改成求環狀陣列的最小子陣列和。公式和特例怎麼對稱過去?
解答與說明 · ANSWER▾
完全對稱:答案 = min(subMi, total − subMx);特例變成全正 —— subMi > 0 時直接回傳 subMi(否則 total − subMx 會是空段的 0)。

例:[1,-2,3,-2] → −3(跨尾巴的 −2,1,−2);[2,3,4] → 2。同一份程式碼(兩個 Kadane 一行不改)只換收尾,實測窮舉 137,256 組 0 錯。
第 9 題14 分
加一個限制:段的長度最多 k(k < n)。「total − 最小段」的技巧還能用嗎?
解答與說明 · ANSWER▾
不能直接用。「total − 最小段」拿掉的段長度不受控制,剩下的段可能超過 k。

這時要回到 ko 卡 B 的做法:把陣列接成兩倍、算前綴和 P,答案是 max(P[j] − P[i]),j − k ≤ i < j,用單調佇列維護視窗內最小的 P[i](和 239 同一套)。原題就是 k = n 的特例,所以 B 是更一般的解,C 是 k = n 時的捷徑。
