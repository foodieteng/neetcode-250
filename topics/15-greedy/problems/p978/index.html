題目簡介// THE QUESTION

QUESTION

給整數陣列 arr,找出最長的湍流子陣列:相鄰兩格的大小關係嚴格地一大一小交替(> < > < … 或 < > < > …),相等就斷掉。回傳長度;單一元素長度是 1。
1 ≤ n ≤ 4 × 104,0 ≤ arr[i] ≤ 109。

範例:[9,4,2,10,7,8,8,1,9] → 5(4 > 2 < 10 > 7 < 8); [4,8,12,16] → 2(一路往上,只能拿兩格);[100] → 1。

和 53、918 同一個骨架:每格只記「結尾在這格」的最好,再刷新全域最大。 不同的是「結尾在這格」要分兩種 —— 最後一步往上的、最後一步往下的 —— 而且兩種會互相接。

為什麼記兩個長度// WHY UP + DOWN

A 暴力:每個起點往右延伸到斷掉 O(n²)
每個起點都重新檢查一次交替。正確(驗證時拿它當參考解),但同一段會被不同起點重複走很多次,n = 4 × 104 時最壞要 8 × 108 次比較。
× REJECT · TLE
B 一個計數器:看方向有沒有翻轉 O(n) / O(1)
相等 → 1;和上一步方向相反 → +1;同方向 → 2。也對(窮舉 0 錯),但要另外記「上一步的方向」,還要處理第一步和相等。忘了相等的版本三個官方範例都過,卻錯 18 組。

核心策略 · 三步驟// THE LOOP

  1. 初值 —— curMx = curMi = maxL = 1:第 0 格自己就是長度 1。
  2. 每一格 i ≥ 1 —— 先存 prevMx、prevMi;arr[i] > arr[i−1] 則 curMx = prevMi + 1,否則 1;arr[i] < arr[i−1] 則 curMi = prevMx + 1,否則 1。
  3. 刷新答案 —— maxL = max(maxL, curMx, curMi)。

第 2 步的「先存」不能省:兩行交叉讀對方,第一行寫完,第二行就讀不到上一格了(程式碼頁的「我寫錯的地方」)。

兩個關鍵// TWO LEMMAS

LEMMA 1 · 往上結尾的最長段 = 往下結尾的最長段 + 1

結尾在 i、最後一步往上的湍流段,拿掉最後一格,剩下的是結尾在 i − 1 的湍流段,而且它的最後一步必須往下(才會交替)—— 或者它只剩一格。兩種情況的最長長度都是 prevMi(只有一格時 prevMi 正好是 1)。 所以 curMx = prevMi + 1;往下對稱,curMi = prevMx + 1。不是往上(往下或相等)時,「最後一步往上」的段只剩 i 自己,長度 1。

LEMMA 2 · 交叉引用 → 一定要先暫存上一格

918 的兩個 Kadane 各讀各的(curMx 只讀 curMx),順序無所謂;這題 curMx 讀 curMi、curMi 讀 curMx,不管先寫哪一行,第二行都會讀到這一格的新值。 實測沒存 prev 的版本錯 1,923 / 3,279 組:往下那一步的 curMi 永遠是 1 + 1 = 2,答案最多到 3;兩行對調也錯一樣多。
