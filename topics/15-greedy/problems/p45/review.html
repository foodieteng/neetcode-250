PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
用一句話說 curEnd 和 nextEnd 各代表什麼?
解答與說明 · ANSWER▾
curEnd:跳 step 次最遠能到哪,也就是「目前這一層」的右端。nextEnd:目前掃過的格子再多跳一次最遠能到哪,也就是「下一層」的右端(還在收集中)。

兩者之間 (curEnd, nextEnd] 就是下一層的格子。
第 2 題10 分
為什麼 step++ 要等到 i == curEnd,不能在 nextEnd 變大的時候就加?
解答與說明 · ANSWER▾
nextEnd 變大只代表「這一層某一格跳得比較遠」,不代表多跳了一次。同一層裡可能好幾格輪流把 nextEnd 推遠,但它們都是用同樣的跳數到的。

實測「變大就 +1」錯 23,580 組,而且兩個官方範例都過。最小反例 [2,2,0] → 2(正解 1:0 一跳直接到 2)。只有走到 curEnd,這一層所有格子都比過了,才確定「不多跳一次就到不了更遠」。
第 3 題10 分
為什麼迴圈只跑到 n − 2?跑到 n − 1 會怎樣?
解答與說明 · ANSWER▾
i 是「起跳點」,站在最後一格不需要再起跳。如果也看最後一格,剛好 curEnd == n − 1 時會觸發一次多餘的 step++。

實測跑到 n − 1 錯 21,376 組,每一組都剛好多 1;兩個官方範例都變成 3。最小反例 [0] → 1(正解 0:本來就站在終點)。
第 4 題10 分
「每次都跳最遠」為什麼錯?分層的做法為什麼不會犯同樣的錯?
解答與說明 · ANSWER▾
「跳最遠」在第一步就決定了落點,但跳最遠的那一格不一定是下一步最好的起跳點。分層把這一層每一格的 i + nums[i] 都比過才換層,等於所有起跳點都試過了。

[4,1,1,3,1,1,1]:跳最遠是 0 → 4 → 5 → 6,3 跳;分層看到第 1 層 [1..4] 裡的 index 3 能到 6,答案 2(0 → 3 → 6)。跳最遠還可能落在 0 上卡死:範例 2 [2,3,0,1,4] 就會。窮舉錯 11,884 組,其中 10,328 組是卡死。
第 5 題10 分
這題和 55 的程式差在哪?為什麼 55 不需要 curEnd?
解答與說明 · ANSWER▾
55 的 farthest 就是這裡的 nextEnd。55 只問「推得到終點嗎」,一路推就好;45 問「推了幾層」,所以要多一個 curEnd 標出每一層在哪裡結束。

55 的 i > farthest → false 在這題用不到,因為題目保證到得了;拿掉保證時,它會以「換層時推不動」的形式回來(第 8 題)。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩個形狀不同的輸入(程式碼頁已走過範例 1 和 [4,1,1,3,1,1,1]):先走 [1,1,1,1],再走 [1,2,1,1,1]。每一格記下 nextEnd、i == curEnd?、step、curEnd。兩個各回傳多少?哪些 i 沒有觸發 step++?為什麼?
解答與說明 · ANSWER▾
// [1,1,1,1]:每一格都是層的盡頭 i nums i+nums nextEnd i==curEnd? step curEnd 0 1 1 1 是 1 1 1 1 2 2 是 2 2 2 1 3 3 是 3 3 // OUTPUT: return 3(層 [0] · [1] · [2] · [3])
// [1,2,1,1,1]:層寬 1 · 1 · 2 · 1 i nums i+nums nextEnd i==curEnd? step curEnd 0 1 1 1 是 1 1 第 1 層 [1] 1 2 3 3 是 2 3 第 2 層 [2..3] 2 1 3 3 否 2 3 第 2 層裡,沒推更遠 3 1 4 4 是 3 4 第 3 層 [4],含終點 // OUTPUT: return 3(路線 0 → 1 → 3 → 4)
step 只在「走到這一層盡頭」時加:[1,1,1,1] 每格都是盡頭所以每格都加;[1,2,1,1,1] 的 i = 2 在第 2 層中間,不加。 第 2 題 的反例 [2,2,0]:i = 0 和 i = 1 都會把 nextEnd 推遠,「變大就 +1」會算成 2;但 i = 1 和終點 2 都在第 1 層,正解是 1。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
除了次數,還要回傳實際的路線(每一跳從哪一格起跳)。要多記什麼?
解答與說明 · ANSWER▾
多記一個 best:i + nums[i] 讓 nextEnd 變大時,記下這個 i。換層時,這一層的 best 就是下一跳的起跳點。最後補上終點。

[2,3,1,1,4] → 0 → 1 → 4;[4,1,1,3,1,1,1] → 0 → 3 → 6;[1,2,1,1,1] → 0 → 1 → 3 → 4。實測窮舉 41,600 組,每條路線的每一跳都合法、跳數等於 BFS 答案,0 錯。
第 8 題14 分
拿掉「保證到得了」:到不了時要回傳 −1。原本的程式會回傳什麼?要加哪一行?
解答與說明 · ANSWER▾
原本的程式不會回傳 −1,而是一個看起來像答案的數:[3,2,1,0,4] → 2、[0,1] → 1、[1,0,1] → 2。在換層時加一行 if (nextEnd == curEnd) return −1;:這一層看完了,下一層卻推不出去。

實測窮舉值 0..3、長度 1–8 的全部 87,380 組(包含到不了的 45,780 組),和 BFS(到不了算 −1)比,0 錯。這就是 55 的 i > farthest,換了個位置。
第 9 題14 分
1326 Minimum Number of Taps:花園 [0, n],第 i 個水龍頭澆 [i − r, i + r],問最少開幾個才能澆滿。怎麼變成這一題?
解答與說明 · ANSWER▾
先把每個水龍頭換成「從左端 l = max(0, i − r) 能延伸到 min(n, i + r)」,存成 reach[l] 取最大。這就變成 Jump Game II:站在 l 最遠能「跳」到 reach[l],問從 0 到 n 最少幾跳;推不動就 −1。

n = 5, ranges = [3,4,1,1,0,0] → 1(index 1 的水龍頭澆 [0, 5]);n = 3, ranges = [0,0,0,0] → −1。和枚舉所有水龍頭組合的暴力解比 21,840 組,0 錯。同一招也能解 1024 Video Stitching。
