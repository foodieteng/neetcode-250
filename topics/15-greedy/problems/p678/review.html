PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
'*' 有三種可能,程式碼卻只寫了 l--; r++;。「當空字串」那一種跑到哪裡去了?
解答與說明 · ANSWER▾
「當 ')'」讓 open 減 1(走到 l 這一端),「當 '('」讓 open 加 1(走到 r 這一端),「當空字串」open 不變,落在 l−1 和 r+1 之間。

因為範圍是連續的,中間的值不用另外記。我們只關心兩端:最少可能幾個(結尾能不能是 0)、最多可能幾個(中途會不會連最多都不夠)。
第 2 題10 分
為什麼「所有可能的 open」一定是連續的一段?如果中間有洞,兩個數就不夠了嗎?
解答與說明 · ANSWER▾
從 {0} 開始,'(' 和 ')' 只是整段平移;'*' 把每個值 v 變成 v−1、v、v+1,一段連續的 [l, r] 會變成 [l−1, r+1],相鄰的值互相補滿,不會有洞;剪掉負的部分也還是連續的。

如果真的會有洞,兩個數確實不夠(會把洞裡不可能的值誤認為可能)。這題剛好不會有洞,驗證時每一步都檢查 l ≤ r、並和記完整集合的 DP 比對 2,302,911 組,0 錯。(第 8 題就是會有洞的版本。)
第 3 題10 分
l 變負的時候,為什麼是把它夾回 0,而不是直接 return false?
解答與說明 · ANSWER▾
l 變負只代表「把太多 * 當成 ')'」的那些選法不合法;把 * 改當空字串或 '(' 的選法還是可以的。丟掉不合法的,範圍從 0 開始就好。

改成 return false 會把好的選法一起丟掉,錯 22,731 組,最小反例 "*"(見第 6 題)。完全不夾也錯,27,516 組,同一個反例。
第 4 題10 分
r < 0 為什麼要當下就回傳 false?等到結尾再檢查不行嗎?
解答與說明 · ANSWER▾
r 是「open 最多」的那條路;它變負代表連最樂觀的選法都已經有一個 ')' 配不到。括號是由左往右配的,之後再多的 '(' 或 * 都在它右邊,幫不了它。

延到結尾才檢查,r 可能被後面的 * 加回 ≥ 0,把失敗蓋掉:")*" 會回傳 true。實測錯 16,153 組,而且三個官方範例全都會過。
第 5 題10 分
結尾為什麼看 l == 0,不是 r == 0?
解答與說明 · ANSWER▾
要問的是「有沒有一種選法讓 open 剛好是 0」,也就是 0 在不在 [l, r] 裡。r ≥ 0 一路都檢查過了,所以只差 l 是不是 0。

r == 0 是在問「最多的那條路剛好是 0」,太嚴格了:"*" 的範圍是 [0, 1],答案是 true,但 r = 1。實測錯 22,731 組。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩個最小反例,每組先照正解走,再照「改一行」的版本走一次:"*" 正解 vs 拿掉夾;")*" 正解 vs r < 0 只在結尾檢查。每一步寫下 l、r,四個版本各回傳什麼?錯的版本錯在哪一步?
解答與說明 · ANSWER▾
// "*" · 正解 1 '*' l = −1 r = 1 → 夾回 [0, 1] // OUTPUT: l = 0 → true(* 當空字串)
// "*" · 拿掉夾 1 '*' l = −1 r = 1 沒有夾 // OUTPUT: l = −1 ≠ 0 → false(錯):最少的那條路是「* 當 ')'」,open = −1 根本不是合法狀態
// ")*" · 正解 1 ')' l = −1 r = −1 r < 0 → return false // OUTPUT: false
// ")*" · r < 0 只在結尾檢查 1 ')' l = −1 r = −1 (不檢查)夾回 l = 0 2 '*' l = −1 r = 0 夾回 l = 0 // OUTPUT: 結尾 r = 0 ≥ 0、l = 0 → true(錯):第一個 ')' 已經沒有東西可以配了,後面的 * 救不回來
"*" 就是第 3 題的答案:l 變負只是「最少的那條路」不合法,其他路(* 當空字串)還好好的。夾 = 丟掉壞的路,return false = 連好的路一起丟。 ")*" 就是第 4 題的答案:r 是「最多的那條路」,它變負代表所有路都已經失敗;之後的 * 只是把數字加回來,不會讓已經配不到的 ')' 回到過去。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
不用 l、r,改成左右各掃一次:能不能做?每一次掃要檢查什麼?
解答與說明 · ANSWER▾
可以。由左往右,把 '(' 和 '*' 都當 +1、')' 當 −1,中途變負就 false(')' 太多);再由右往左,把 ')' 和 '*' 都當 +1、'(' 當 −1,中途變負就 false('(' 太多)。兩次都過就是 true。

第一次掃其實就是 r < 0 的檢查;第二次掃負責 l 那一端「左括號太多」的問題。實測和暴力解比對 88,572 組,0 錯。缺點是要掃兩次;l、r 一次掃完。
第 8 題14 分
規則改成「* 只能當 '(' 或 ')',不能當空字串」。程式碼要改哪一行?"*"、"(*"、"**" 的答案是什麼?
解答與說明 · ANSWER▾
只改夾那一行:if (l < 0) l += 2;。* 不能當空字串,open 每一步一定變 1,可能的值只剩「同奇偶」的那些(有洞了),最小的非負值不是 0 就是 1。

實測:"*" → false(只有一個字,長度奇數不可能配完)、"(*" → true、"**" → true;和「* 只試兩種」的暴力解比對 88,572 組,0 錯。
第 9 題14 分
921 Minimum Add to Make Parentheses Valid:沒有 *,只問「最少要補幾個括號」。這題的兩種失敗,對應到 921 的什麼?
解答與說明 · ANSWER▾
沒有 * 時 l = r,就是一般的 open 計數。921 把兩種失敗都改成「補一個」:中途遇到 ')' 而 open = 0(本題的 r < 0)→ 補一個 '(',計數 +1;結尾還剩 open 個 '('(本題的 l > 0)→ 補 open 個 ')'。

答案 = 中途補的 + 結尾剩的。官方範例 "())" → 1、"(((" → 3;和 DP 對拍長度 ≤ 12 的全部 8,190 組 '(' / ')' 字串,0 錯。
