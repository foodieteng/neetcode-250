PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼只記一個 farthest 就夠了?不用記「哪些格子到得了」嗎?
解答與說明 · ANSWER▾
因為到得了的格子一定是一段從 0 開始的前綴:能落在 k,就能把最後一跳縮短,落在比 k 近的任何一格。一段前綴只要記右端點。

B 解(可達性 DP)的 reach[] 永遠長得像 T T T … T F F …,所以整個陣列可以壓成一個整數。
第 2 題10 分
為什麼 i > farthest 就能直接回傳 false,不用看後面的格子?
解答與說明 · ANSWER▾
檢查時的 farthest 是「0..i−1 能到的最遠」。i 超過它,代表沒有任何一格跳得到 i;而 i 之後的格子只能從 < i 或 ≥ i 的格子跳過去,≥ i 的本身都到不了,< i 的又跳不過 farthest。

所以第一次失敗就是最終答案。全 0 的陣列在 i = 1 就結束;最壞的 false 是全 1 只有倒數第二格是 0,要跑滿 10,000 圈。
第 3 題10 分
檢查和擴張兩行能不能交換?交換後錯在哪?
解答與說明 · ANSWER▾
不行。先擴張的話,farthest ≥ i + nums[i] ≥ i,i > farthest 永遠不成立,函式永遠回傳 true。

實測錯 45,780 組 —— 窮舉裡不可達的陣列總共就是 45,780 組,一組不差。最小反例 [0,0] → true,範例 2 也抓得到。如果真的想先擴張,檢查要改成 farthest <= i && i != n − 1(「到了這格卻推不出去」),實測 0 錯。
第 4 題10 分
為什麼要 max?farthest = i + nums[i] 不是也一直往右嗎?
解答與說明 · ANSWER▾
farthest 是「目前為止」的最遠,後面的格子可能跳得比較近。不取 max,近的那一格會把 farthest 拉回來,把本來到得了的格子當成到不了。

[2,0,0]:i = 0 推到 2,i = 1 的 1 + 0 = 1 會蓋掉 2,i = 2 就被擋下,回傳 false(正解 true)。實測錯 28,480 組,但兩個官方範例都過。
第 5 題10 分
這題為什麼算「貪心」?它貪的是什麼?
解答與說明 · ANSWER▾
貪的是「能到多遠就記多遠」:不決定實際怎麼跳,只維護所有跳法聯集的最遠點。

這不會漏解,因為 LEMMA 1 保證最遠點以內全都到得了 —— 記最遠就等於記住了全部。和 53 的「前面那段是負的就丟掉」一樣,都是能證明「只記這一個數不會吃虧」。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩個邊界輸入:[2,0,0](剛好跳到最後一格)和 [1,0,1,0](中間就卡住)。每一步記下 i、nums[i]、檢查前的 farthest、i > farthest 成不成立、更新後的 farthest。兩個輸入各回傳什麼?各在哪一格分出結果?
解答與說明 · ANSWER▾
// [2,0,0]:剛好到 i nums[i] before i > before? after 0 2 0 否 2 1 0 2 否 2 0 不會讓 farthest 變小(max) 2 0 2 否(2 > 2 不成立) 2 // OUTPUT: return true(farthest 剛好等於最後一格 2)
// [1,0,1,0]:中間就卡住 i nums[i] before i > before? after 0 1 0 否 1 1 0 1 否 1 2 1 1 是 → return false // OUTPUT: return false(在 i = 2;後面的 1 和 0 根本不用看)
[2,0,0] 是第 3、4 題的試金石:少了 max 會在 i = 1 把 farthest 從 2 拉回 1,i = 2 被擋下,回傳 false。 少 max 的版本兩個官方範例都過、窮舉卻錯 28,480 組 —— 自測一定要放一個「後面的格子跳得比前面近」的輸入。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
保證到得了,問最少跳幾次(下一題 45 Jump Game II)。farthest 還能怎麼用?
解答與說明 · ANSWER▾
按「跳幾次」分層,像 BFS:end = 目前這一跳最遠能到哪,farthest = 下一跳最遠能到哪。掃到 i == end 時,這一層用完了,跳一次,end = farthest。

迴圈只跑到 n − 2(站在最後一格不用再跳)。[2,3,1,1,4] → 2、[2,3,0,1,4] → 2、[1,1,1,1] → 3、[0] → 0。和 BFS 最短路比,窮舉 41,600 組可達的陣列 0 錯。
第 8 題14 分
改成從最後一格往回走:維護一個「目標」,能跳到目標的格子就變成新目標。怎麼寫?兩個範例怎麼走?
解答與說明 · ANSWER▾
goal = n − 1;i 從 n − 2 往回掃,i + nums[i] >= goal 就 goal = i;最後回傳 goal == 0。

範例 1:i = 3、2、1、0 每一格都跳得到目標,目標一路退到 0 → true。範例 2:i = 3..0 的 i + nums[i] 都是 3,跳不到 4,目標停在 4 → false。實測 0 錯;但把 >= 寫成 > 錯 35,948 組,連範例 1 都不過(最小反例 [1,0]:剛好跳到目標不算)。
第 9 題14 分
規則改成「每次必須剛好跳 nums[i] 格」。「到得了的是前綴」還成立嗎?怎麼解?
解答與說明 · ANSWER▾
不成立了:能到 k 不代表能到 k 之前的格子。但每格只有一種走法,所以根本不用搜尋 —— 從 0 開始照著跳,落在最後一格就 true;遇到 0、跳出界、或繞回走過的格子就 false。

[2,2,0,0]:0 → 2,停在 0 → false(原題可以 0 → 1 → 3,是 true)。這正好是程式碼頁陷阱表裡「每次都剛好跳 nums[i]」的寫法:拿來解原題會錯 10,328 組,拿來解這個版本卻是對的。
