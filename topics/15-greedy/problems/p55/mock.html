Hmm, let me think about this for a sec.

A naive approach treats it as a graph and runs a BFS, or a DP over reachable indices. That's correct, and I'd keep it as a checker, but it touches every edge, so it can be O(n²) — wasted work with jumps up to 105.

This problem reminds me of a greedy "frontier" scan — a running-maximum sweep over one growing covered interval, the same idea as merging overlapping intervals into a single covered prefix. Because the reachable set is a prefix, I only push its right edge forward: each index inside it offers i + nums[i], and I take the max. One pass, no set, no queue.

P — plan
C
CANDIDATE

Here's the plan.

// farthest = farthest index reachable using indices 0..i-1
// invariant: reachable set is exactly [0..farthest]
farthest = 0
for i = 0 .. n-1:
  if i > farthest: return false // i is outside the prefix
  farthest = max(farthest, i + nums[i]) // i can push the edge
return true  // every index, including n-1, was reachable

One: keep farthest, the right edge of the reachable prefix using only earlier indices, starting at 0.
Two: for each index, if i > farthest, nobody before i reaches it, and since the set is a prefix, nothing after it either — return false.
Three: otherwise push farthest to max(farthest, i + nums[i]); if the loop finishes, return true.

One thing worth flagging — the check must come before the update. Update first, and farthest is always at least i, so the check never fires and the function never returns false — even on example 2.

There's a trade-off here. A backward version moves a goal down from the last index; it's also O(n) and correct, but forward stops early at the first wall. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. One loop over the indices: first the check, if i > farthest, return false; then farthest becomes the max of itself and i + nums[i]. After the loop, return true.

class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size();
        int farthest = 0;

        for (int i = 0; i < n; i++) {
            if (i > farthest) return false;

            farthest = max(farthest, i + nums[i]);
        }

        return true;
    }
};

That matches the plan line by line.

One thing worth flagging — the compare is strictly >. When i == farthest, I'm standing on the last reachable index, which is fine; >= would return false at index 0 for every input, even [0].

And the max is needed: assigning farthest = i + nums[i] directly lets a small value pull the edge back. On [2,0,0], that returns false instead of true — yet it passes both official examples.
