PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼只從左往右掃一次不夠?一次掃描在走到某個人的時候,缺了什麼資訊?
解答與說明 · ANSWER▾
從左往右走到第 i 個人時,只知道他左邊的情況。他右邊如果接著一段很長的下坡,他其實需要很多顆,但現在還看不到。

例如 [1,0]:走到第 0 個人時沒有任何左邊資訊,給 1;但他比右邊高,至少要 2。只掃一次實測錯 69,820 / 121,844 組。下坡的資訊在右邊,所以要再從右邊掃回來把它帶過來。
第 2 題10 分
為什麼「左掃結果和右掃結果取 max」一定是最少的?會不會有更省的發法?
解答與說明 · ANSWER▾
左掃的 c[i] = 以 i 結尾的連續上升段長度。上升段 a1 < a2 < … < ak 每一步至少多 1 顆,所以 i 在任何合法發法裡都至少 k 顆。右掃同理是另一個下限。

每個人至少要兩個下限裡比較大的那個,所以總和不可能比「每人取 max」更少;而這組數字左右規則都滿足:右規則由右掃直接保證;左規則在右掃之後也還成立 —— 右掃只會把「比右邊高」的 c[i−1] 調大,而如果 i−1 比 i 高,i 就不比 i−1 高,左規則對這一對本來就沒有要求。所以它就是答案。和窮舉比對 121,844 組,0 錯。
第 3 題10 分
第二輪寫成 c[i] = c[i+1] + 1(不取 max),哪一種輸入會出錯?兩個官方範例抓得到嗎?
解答與說明 · ANSWER▾
只要有一段上坡、山頂右邊接一個比較低的人,左掃給山頂的數字就會比右掃要求的大,不取 max 就會被蓋小。最小反例 [0,1,2,0] → 6(正解 7)。

兩個官方範例都抓不到:範例 1 右掃到 i = 0 時,c[0] 本來就是 1,蓋成 2 剛好對;範例 2 右掃什麼都沒改。兩個範例實跑都還是 5、4。實測錯 11,599 / 121,844 組。
第 4 題10 分
第二輪為什麼一定要從右往左?
解答與說明 · ANSWER▾
右規則要求 c[i] > c[i+1],用到的是 i+1 的最終值。從右往左走,算 i 的時候 i+1 已經處理完了;從左往右走,i+1 之後還會被它自己的右鄰居推高,i 卻已經算完、不會再回頭。

最小反例 [2,1,0] → 5(正解 6),最後變成 2,2,1。實測錯 22,827 / 121,844 組。同理,左掃也必須從左往右。
第 5 題10 分
範例 2 的第三個人和第二個人同分,為什麼只拿 1 顆?[1,2,87,87,87,2,1] 中間的 87 拿幾顆?
解答與說明 · ANSWER▾
規則只說「分數比鄰居高的要比較多」,同分不算比較高,所以同分的兩人之間沒有任何要求。範例 2 的第三個人左邊同分、右邊沒人,只拿 1 顆就好。

[1,2,87,87,87,2,1] 發 1,2,3,1,3,2,1,共 13。中間的 87 兩邊都是 87,沒有任何要求,拿 1 顆;它左右兩個 87 各自從外側的坡爬上來拿 3 顆。用 >= 就會把同分當成比較高:[0,0] 會回 3(正解 2)。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙手走兩個最小反例,每個都先照正解跑、再照「改一行」的錯誤版本跑:
(a) [0,1,2,0]:正解 vs 右掃不取 max(c[i] = c[i+1] + 1);
(b) [2,1,0]:正解(右掃從右往左)vs 第二輪改成從左往右。
寫出左掃完的 c、第二輪每一步的 c,以及四個版本各回傳什麼。錯的版本錯在哪一步、哪兩個人違規?
解答與說明 · ANSWER▾
// [0,1,2,0] · 正解 左掃完 c = [1,2,3,1] i=2 2 > 0 → max(3, 1+1) = 3 c = [1,2,3,1] 左掃給的 3 比較大,留著 i=1 1 > 2 ? 否 i=0 0 > 1 ? 否 // OUTPUT: 7
// [0,1,2,0] · 右掃不取 max:c[i] = c[i+1] + 1 左掃完 c = [1,2,3,1] i=2 2 > 0 → c[3]+1 = 2 c = [1,2,2,1] 3 被蓋成 2 i=1 1 > 2 ? 否 i=0 0 > 1 ? 否 // OUTPUT: 6(錯):分數 2 比左邊的分數 1 高,兩人卻都是 2 顆
// [2,1,0] · 正解(右掃從右往左) 左掃完 c = [1,1,1] 一路下坡,左掃什麼都沒做 i=1 1 > 0 → max(1, 1+1) = 2 c = [1,2,1] i=0 2 > 1 → max(1, 2+1) = 3 c = [3,2,1] c[1] 已經是 2,所以給 3 // OUTPUT: 6
// [2,1,0] · 第二輪改成從左往右 左掃完 c = [1,1,1] i=0 2 > 1 → max(1, 1+1) = 2 c = [2,1,1] c[1] 還沒被推高,只看到 1 i=1 1 > 0 → max(1, 1+1) = 2 c = [2,2,1] c[1] 變 2 了,但 i=0 已經算完 // OUTPUT: 5(錯):分數 2 比右邊的分數 1 高,兩人卻都是 2 顆
[0,1,2,0] 就是第 3 題的答案:一段上坡的山頂右邊接一個低的人,右掃只要求 2,但左掃早就給了 3,不取 max 就把它蓋掉了。 [2,1,0] 就是第 4 題的答案:c[i+1] + 1 要用的是 i+1 的最終值;從左往右走,算 i 的時候 i+1 還沒被它自己的右鄰居推高。

PART C · 應用題// 3 題 × 12–14 分

第 7 題12 分
規則改成「比鄰居高的,至少要多 2 顆」。程式要改哪裡?[1,0,2] 和 [1,3,5,4,3,2,1] 各要幾顆?
解答與說明 · ANSWER▾
兩處 + 1 都改成 + 2:c[i] = c[i−1] + 2、max(c[i], c[i+1] + 2)。其他不變,證明一模一樣(上升段每一步至少多 2)。

[1,0,2] → 7(3,1,3);[1,3,5,4,3,2,1] → 29(山頂 1 + 2×4 = 9)。和窮舉(規則改成至少多 2)比對 35,460 組,0 錯。
第 8 題14 分
加一條規則:相鄰而且同分的人必須拿一樣多。[1,2,2] 和 [1,2,87,87,87,2,1] 各要幾顆?要怎麼改寫才能套用原本的兩次掃描?
解答與說明 · ANSWER▾
把連續同分的人併成一塊:每塊只有一個分數,塊和塊之間一定不同分,就變回原題。對塊的分數跑原本的兩次掃描得到每塊的糖果數,總和 = Σ(那塊的糖果數 × 那塊的人數)。

[1,2,2] → 塊 [1],[2,2] → 糖果 1,2 → 1 + 2×2 = 5;[1,2,87,87,87,2,1] → 塊分數 1,2,87,2,1 → 糖果 1,2,3,2,1 → 1+2+3×3+2+1 = 15(原題是 13,三個 87 現在都要 3 顆)。和窮舉(加上同分必須相等)比對 35,460 組,0 錯。
第 9 題14 分
不准開 c 陣列,只用 O(1) 額外空間。提示:從左往右一次,記「目前上坡幾步、下坡幾步、上一個山頂多高」。
解答與說明 · ANSWER▾
從左往右一次,用 up(目前連續上坡幾步)、down(目前連續下坡幾步)、peak(上一個山頂是上坡第幾步)三個數。上坡:這個人給 up + 1;同分:三個都歸零,給 1;下坡:新來的人給 1,等於把前面整段下坡每人 +1,所以總和加 down;當下坡長度超過 peak 時,山頂也要跟著 +1。

int n = ratings.size(), total = 1, up = 0, down = 0, peak = 0;
for (int i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) { up++; peak = up; down = 0; total += up + 1; }
    else if (ratings[i] == ratings[i - 1]) { up = down = peak = 0; total += 1; }
    else { up = 0; down++; total += down + (down > peak ? 1 : 0); }
}
return total;
兩個官方範例 → 5、4;[1,3,5,4,3,2,1] → 18、[1,2,87,87,87,2,1] → 13、[0,1,2,0] → 7。和兩次掃描的版本隨機對拍 200,000 組(n ≤ 60),0 錯。時間一樣 O(n),但不好想、不好講,面試先寫兩次掃描,被追問空間再提這個。

重點整理 · 七句話▾
面向要記住的那一句
換個說法「比鄰居高要比較多」= 左規則 + 右規則,分開滿足
左掃比左邊高就 c[i−1] + 1,否則 1 = 往左看的上升段長度
右掃從右往左,比右邊高就 max(c[i], c[i+1] + 1)
為什麼最少兩次結果都是下限;max 又合法 → 就是最少
地形谷底 1,上坡每步 +1,山頂取兩邊比較長的;同分回到 1
常見錯右掃不取 max、右掃方向反、同分用 >=、只掃一次
複雜度O(n) / O(n);最壞總和 n(n+1)/2,5·104 時仍在 int 內
