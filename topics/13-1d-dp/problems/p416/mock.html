Hmm, let me think about this for a second.

A naive approach would enumerate every subset, which is O(2n) — hopeless for 200 numbers.

This problem reminds me of 0/1 knapsack. Let dp[s] mean: can the numbers seen so far form the sum s. For each number, any reachable s-num makes s reachable. Each number is either taken once or skipped, which is exactly the knapsack choice. The table only goes up to the target, so this costs O(n·target).

Here's the plan.

// dp[s] = can we reach subset sum s
sum = total; if sum is odd return false
target = sum / 2; dp[0] = true
for each num:
  for s = target down to num:  // down = each num used once
    dp[s] = dp[s] || dp[s-num]
return dp[target]

One: sum everything; if the sum is odd, return false right away.
Two: set the target to sum/2, and mark dp[0] as reachable.
Three: for each number, sweep s from the target down to num, and set dp[s] if dp[s-num] is true. Then return dp[target].

One thing worth flagging — the inner loop goes high to low. That way dp[s-num] is still the value from before this number, so each number is used at most once. Going low to high would let a number repeat, which is the unbounded version. Does this approach sound good, or would you rather I think of another way?

Here's the boolean DP. It's the plan as written: the odd check, halve the target, dp[0] = true, then the downward sweep that sets dp[i] whenever dp[i - num] is set.

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int target = accumulate(nums.begin(), nums.end(), 0);
        if (target & 1) return false;       // odd total → can't split evenly

        target /= 2;                       // goal: reach half the total

        vector<bool> dp(target + 1, false);
        dp[0] = true;                     // empty set makes 0

        for (int num : nums) {
            for (int i = target; i >= num; i--) {  // high to low → each num once
                if (dp[i - num]) {
                    dp[i] = true;
                }
            }
        }

        return dp[target];
    }
};

And a bitset variant — same idea, but it packs 64 sums into each machine word. Both are O(n·target).

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = accumulate(nums.begin(), nums.end(), 0);
        if (sum & 1) return false;
        int target = sum / 2;

        bitset<10001> dp;              // bit s = is sum s reachable; target ≤ 10000
        dp[0] = 1;

        for (int num : nums)
            dp |= dp << num;            // every reachable s → s+num too

        return dp[target];
    }
};

One thing worth flagging — dp << num moves every reachable sum up by num at once, and |= adds them all in one step. Since each number is shifted exactly once, the bitset version needs no direction reasoning.
