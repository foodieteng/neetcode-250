Checking every substring is O(n2) substrings times O(n) to verify each — O(n3), too slow. The key structure: a palindrome with its two ends peeled off is still a palindrome.

This problem reminds me of interval DP, because that peel-the-ends rule is a recurrence over ranges: dp[i][j] means s[i..j] is a palindrome, and it depends only on the range one step inside. There's also expand-around-center with O(1) space — I'll mention it after.

Here's the plan.

// dp[i][j] = is s[i..j] a palindrome
base: dp[i][i] = true  // length 1
base: dp[i][i+1] = (s[i]==s[i+1])  // length 2
dp[i][j] = s[i]==s[j] && dp[i+1][j-1]  // length >= 3
fill by length L ascending; track longest (start, len)

One: every single character is a palindrome, and a pair is one when its two characters match.
Two: for length 3 and up, s[i..j] is a palindrome when the end characters match and the inside, s[i+1..j-1], is a palindrome.
Three: fill by length, ascending, and track the longest as a start and a length.

One thing worth flagging — the outer loop must run over length, not over i, j. The inner cell is 2 shorter, so all shorter lengths must be done first. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    string longestPalindrome(string s) {
        int n = s.size();
        vector<vector<bool>> dp(n, vector<bool>(n, false));
        pair<int, int> ans = {-1, -1};

        // base 1: length 1 is always a palindrome
        for (int i = 0; i < n; i++) {
            dp[i][i] = true;
            ans = {i, 1};
        }

        // base 2: length 2 is a palindrome when both chars match
        for (int i = 0; i < n - 1; i++) {
            if (s[i] == s[i + 1]) {
                dp[i][i + 1] = true;
                ans = {i, 2};
            }
        }

        // transition: lengths ascending, so inner dp[i+1][j-1] is ready
        for (int L = 3; L <= n; L++) {
            for (int i = 0; i + L - 1 < n; i++) {
                int j = i + L - 1;
                if (s[i] == s[j] && dp[i + 1][j - 1]) {
                    dp[i][j] = true;
                    ans = {i, L};
                }
            }
        }

        return s.substr(ans.first, ans.second);
    }
};

Base loops mark lengths 1 and 2; then the outer loop walks length L from 3 up, and the inner loop slides the window. Every time a cell turns true I set ans to its start and length; since lengths only grow, the last update is the longest.

Then expand-around-center — same O(n2) time, but O(1) space.

class Solution {
public:
    string longestPalindrome(string s) {
        int start = 0, best = 1;
        for (int center = 0; center < (int)s.size(); center++) {
            expand(s, center, center, start, best);       // odd-length center
            expand(s, center, center + 1, start, best);   // even-length center
        }
        return s.substr(start, best);
    }

    void expand(const string& s, int left, int right, int& start, int& best) {
        int n = s.size();
        while (left >= 0 && right < n && s[left] == s[right]) {
            left--; right++;
        }
        int len = right - left - 1;           // while overshoots one step each side, so -1
        if (len > best) { best = len; start = left + 1; }
    }
};

One thing worth flagging — expand needs two centers per index: (c, c) for odd lengths, (c, c+1) for even, or you miss palindromes like "bb". And when the loop stops, left and right have each overshot by one, so the length is right - left - 1.
