A naive approach would recurse straight on that formula, but it recomputes the same subproblems again and again — exponential time, O(2n).

First the straightforward table version: a vector of size n + 1, both bases set to 1, then one loop that adds the previous two.

class Solution {
public:
    int climbStairs(int n) {
        vector<int> dp(n + 1);
        dp[0] = dp[1] = 1;              // base: step 0 and step 1, 1 way each

        for (int i = 2; i <= n; i++)
            dp[i] = dp[i - 1] + dp[i - 2]; // last move: 1 step or 2 steps

        return dp[n];
    }
};

And the O(1)-space version — since only the last two values matter, I roll two variables, prev2 and prev1, forward.

class Solution {
public:
    int climbStairs(int n) {
        int prev2 = 1, prev1 = 1;          // dp[i-2], dp[i-1]
        for (int i = 2; i <= n; i++) {
            int cur = prev1 + prev2;          // dp[i]
            prev2 = prev1;                      // roll forward one step
            prev1 = cur;
        }
        return prev1;
    }
};

Both compute the same recurrence. One thing worth flagging — in the rolling version the order of the assignments matters. I compute cur first, then shift prev1 into prev2, then cur into prev1. Shift first, and I'd overwrite prev1 before using it.
