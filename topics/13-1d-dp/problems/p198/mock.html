Hmm, let me think about this for a second.

A naive approach would be greedy — "always grab the biggest house still available." That fails: on [2,3,2], greedy grabs the 3, both neighbors are blocked, and it ends with 3, but the best is the two ends, 2+2=4.

This problem reminds me of a 1-D DP with a take-or-skip choice: at each house I make one binary choice, rob it or skip it, and I keep the best running total. It's the same skeleton as counting ways up a staircase, with a max in place of the +.

// dp[i] = most money from the first i houses (house i = nums[i-1])
dp[0] = 0  // sentinel: zero houses
skip house i → dp[i-1]
rob  house i → dp[i-2] + nums[i-1]  // neighbor is now forbidden
dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])
answer = dp[n]  // then compress to two variables

One: dp[i] is the most money from the first i houses, with dp[0] = 0.
Two: skip house i and I keep dp[i-1]; rob it and I get dp[i-2] plus its cash.
Three: take the max, and the answer is dp[n].

One thing worth flagging — when I rob house i, its neighbor is off-limits, so I extend from dp[i-2], not dp[i-1]. That single index is the whole trick. Does this approach sound good, or would you rather I think of another way?

The table version first. I pad with a sentinel dp[0]=0 for "zero houses," so the loop is uniform — then house i is nums[i-1], and dp[1] is just the first house. The loop takes the max of rob and skip.

class Solution {
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n + 1, 0);
        dp[0] = 0;              // sentinel: rob 0 houses = 0
        dp[1] = nums[0];       // only house 1 → take it

        for (int i = 2; i <= n; i++) {
            // dp[i] covers the first i houses (house i = nums[i-1])
            dp[i] = max(dp[i - 2] + nums[i - 1],  // rob house i
                        dp[i - 1]);            // skip house i
        }

        return dp[n];
    }
};

Then the O(1)-space version — only the last two values matter, and it needs no base-case special-casing: prev2 and prev1 start at 0, and for each money I take max(prev1, prev2 + money).

class Solution {
public:
    int rob(vector<int>& nums) {
        int prev2 = 0, prev1 = 0;      // dp[i-2], dp[i-1]

        for (int money : nums) {
            int cur = max(prev1, prev2 + money); // skip vs rob
            prev2 = prev1;                     // roll forward one step
            prev1 = cur;
        }

        return prev1;
    }
};

One thing worth flagging — I compute cur first, then shift, so prev1 isn't overwritten before it feeds prev2.
