This problem reminds me of interval DP, because a palindrome with both ends peeled off is still a palindrome — a recurrence over ranges. So dp[i][j] means s[i..j] is a palindrome.

The trick is that every true cell is exactly one palindromic substring, so I just count true cells. There's also expand-around-center with O(1) space.

base: dp[i][i] = true → res++  // length 1
base: dp[i][i+1] = (s[i]==s[i+1]) → res++  // length 2
dp[i][j] = s[i]==s[j] && dp[i+1][j-1] → if true, res++
fill by length ascending; return res

One: every single character is a true cell, and so is every pair of matching neighbors — count each.
Two: for length 3 and up, a range is true when its ends match and its inside is true; count it.
Three: fill by length, ascending, and return the count.

One thing worth flagging — the count equals the number of true cells, because each palindrome maps to a unique (i, j) pair. No dedup needed. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. The interval DP is the longest-palindrome table, but counting: each base loop and each true transition does res++.

class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size();
        vector<vector<bool>> dp(n, vector<bool>(n, false));
        int res = 0;

        // base 1: length 1, each one is a palindrome
        for (int i = 0; i < n; i++) {
            dp[i][i] = true;
            res++;
        }

        // base 2: length 2, +1 when both chars match
        for (int i = 0; i < n - 1; i++) {
            if (s[i] == s[i + 1]) {
                dp[i][i + 1] = true;
                res++;
            }
        }

        // transition: lengths ascending, res++ on every true cell
        for (int L = 3; L <= n; L++) {
            for (int i = 0; i + L - 1 < n; i++) {
                int j = i + L - 1;
                if (s[i] == s[j] && dp[i + 1][j - 1]) {
                    dp[i][j] = true;
                    res++;
                }
            }
        }

        return res;
    }
};

Then expand-around-center — O(1) space, counting as you expand. Every index is an odd center and, with its right neighbor, an even center; count grows outward while the ends match.

class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size(), res = 0;
        for (int center = 0; center < n; center++) {
            res += count(s, center, center);       // odd-length center
            res += count(s, center, center + 1);   // even-length center
        }
        return res;
    }

    int count(const string& s, int left, int right) {
        int n = s.size(), c = 0;
        while (left >= 0 && right < n && s[left] == s[right]) {
            left--; right++; c++;       // each successful step = one new palindrome
        }
        return c;
    }
};

Both are O(n2) time. One thing worth flagging — each successful expansion step is one more palindrome, so count just tallies steps. And I need both odd and even centers, to catch "a"-type and "bb"-type palindromes.

Time is O(n2) for both. Space is O(n2) for the DP table, O(1) for expand-around-center.

Oh, one more thing — this is literally the longest-palindrome table with the finishing move swapped: track-longest becomes count. The same dp table also works as an O(1) "is this slice a palindrome" oracle when partitioning a string into palindromes. And for n up to 105, Manacher's algorithm counts in O(n) — the count is the sum of the palindrome radii.
