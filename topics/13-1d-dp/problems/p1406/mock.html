Hmm, let me think about this for a second.

A naive approach would simulate both players and branch three ways on every turn, which is exponential.

This problem reminds me of a minimax game DP, and the clean trick is to track a relative score. Let dp[i] be the best score difference the current player can achieve starting at stone i. Since what remains is always a suffix, one dimension suffices. After I take some stones for a sum take, my opponent plays from i+j+1 and achieves dp[i+j+1] — which is their lead over me, so I subtract it.

Here's the plan.

// dp[i] = best (me − opponent) starting at stone i
dp[n] = 0
for i from n-1 down to 0:
  take = 0
  for j in 0..2 while i+j < n:
    take += stone[i+j]
    dp[i] = max(dp[i], take − dp[i+j+1])  // minus = hand over to opponent
dp[0] > 0 → Alice, < 0 → Bob, else Tie

One: set dp[n] = 0 — no stones, no difference.
Two: go from the last stone back to the first, and try taking 1, 2, or 3 stones, keeping a running sum.
Three: dp[i] is the max of take − dp[next]; at the end, positive means Alice, negative means Bob, zero means Tie.

One thing worth flagging — the minus is the whole idea: I maximize "what I take minus how far the opponent can then pull ahead." And I fill back to front because dp[i] needs the next three entries, dp[i+1..i+3]. Does this approach sound good, or would you rather I think of another way?

The array DP starts every entry at INT_MIN, sets dp[n] = 0, and sweeps back to front; the inner loop grows take one stone at a time and keeps the best take − dp[i + j + 1].

class Solution {
public:
    string stoneGameIII(vector<int>& stoneValue) {
        int n = stoneValue.size();
        vector<int> dp(n + 1, INT_MIN);
        dp[n] = 0;                        // base: no stones → diff 0

        for (int i = n - 1; i >= 0; i--) {      // back to front
            int take = 0;
            for (int j = 0; j < 3 && i + j < n; j++) { // take 1/2/3 stones
                take += stoneValue[i + j];
                dp[i] = max(dp[i], take - dp[i + j + 1]); // minus opponent's best
            }
        }

        if (dp[0] > 0) return "Alice";
        if (dp[0] < 0) return "Bob";
        return "Tie";
    }
};

And the O(1)-space version: dp[i] only needs the next three, so I keep three variables and slide the window forward after each stone.

class Solution {
public:
    string stoneGameIII(vector<int>& s) {
        int n = s.size();
        int dp1 = 0, dp2 = 0, dp3 = 0;       // dp[i+1], dp[i+2], dp[i+3] (out of range = 0)

        for (int i = n - 1; i >= 0; i--) {
            int take = 0, best = INT_MIN;
            int nxt[3] = {dp1, dp2, dp3};
            for (int j = 0; j < 3 && i + j < n; j++) {
                take += s[i + j];
                best = max(best, take - nxt[j]);
            }
            dp3 = dp2; dp2 = dp1; dp1 = best;       // slide the window
        }

        int d = dp1;                            // dp[0]
        return d > 0 ? "Alice" : d < 0 ? "Bob" : "Tie";
    }
};

Both are O(n) time. One thing worth flagging — out of range (i ≥ n) counts as 0, matching dp[n]=0. That's why the three variables can start at 0.

Time is O(n), and space is O(n) or O(1).

Oh, one more thing — the reusable idea is: "track the relative score and subtract the opponent's optimum." The same trick powers the games where you take from both ends; there the remaining part is an interval [i,j], and the DP becomes 2-D. And because stones can be negative, taking more isn't always better — the max handles that automatically.
