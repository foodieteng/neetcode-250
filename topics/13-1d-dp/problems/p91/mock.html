Trying all splits recursively is O(2n). This problem reminds me of the Fibonacci-style one-or-two-step counting DP, but conditional. dp[i] is the number of ways to decode the first i characters.

The last code is either one digit, adding dp[i-1], or two digits, adding dp[i-2] — but each edge only counts if that code is valid. The DP shares subproblems, so it's O(n).

One: if the first character is '0', return 0; otherwise dp[0] and dp[1] are both 1.
Two: for each i, add dp[i-1] if the last digit is non-zero, and add dp[i-2] if the last two digits are 10–26.
Three: return dp[n].

One thing worth flagging — two gates: the one-digit code must be non-zero, and the two-digit code must land in 10–26. The lower bound 10 kills leading zeros. If both fail, dp[i] stays 0 and propagates to mean "no decoding." Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. The table version is one loop with two gated adds.

class Solution {
public:
    int numDecodings(string s) {
        int n = s.size();
        if (s[0] == '0') return 0;      // first char is 0 → can't decode

        vector<int> dp(n + 1, 0);
        dp[0] = 1; dp[1] = 1;          // empty string: 1 way; first char: 1 way

        for (int i = 2; i <= n; i++) {
            if (s[i - 1] != '0')            // one-digit code: last digit non-zero
                dp[i] += dp[i - 1];

            string w = s.substr(i - 2, 2);       // last 2 digits
            if (w >= "10" && w <= "26")    // two-digit code: 10–26
                dp[i] += dp[i - 2];
        }

        return dp[n];
    }
};

The two-digit check compares strings: two-digit strings sort the same way as their values, so "10" to "26" frames exactly the legal range, and "01" or "27" fall outside. The O(1)-space version keeps only the last two values, prev2 and prev1.

class Solution {
public:
    int numDecodings(string s) {
        if (s[0] == '0') return 0;
        int prev2 = 1, prev1 = 1;          // dp[i-2], dp[i-1]

        for (int i = 2; i <= (int)s.size(); i++) {
            int cur = 0;
            if (s[i - 1] != '0') cur += prev1;       // one-digit code
            string w = s.substr(i - 2, 2);
            if (w >= "10" && w <= "26") cur += prev2; // two-digit code
            prev2 = prev1;                      // roll forward one step
            prev1 = cur;
        }
        return prev1;
    }
};

One thing worth flagging — reset cur to 0 each round. If both gates fail it stays 0, and that correctly signals a dead end.

Time is O(n) for both. Space is O(n) for the table, O(1) for the rolling version.

Oh, one more thing — this is the one-or-two-step stair recurrence with a validity gate on each edge: an unconditional + becomes "add only if the code is legal." If wildcards '*' were allowed, each edge would carry a count multiplier instead of a 0/1 gate.
