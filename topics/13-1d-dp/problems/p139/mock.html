Hmm, let me think about this for a second.

This problem reminds me of sequence-segmentation DP: dp[i] means the first i characters can be segmented. dp[i] is true if some word ends at i and the prefix before it, dp[i-L], is already true.

The subtle part is loop order. The position must be the outer loop, ascending, so that when I compute dp[i], every smaller dp[j] is finalized. If I loop words on the outside instead, a word landing at i may need a dp[j] that only a later word turns true — and I've already passed i. That version's answer even changes with dictionary order.

One: dp[0] is true — the empty prefix.

Position outer, word inner.

class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        int n = s.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;                       // the empty prefix can be split

        for (int i = 0; i <= n; i++) {          // ← position outer, ascending
            for (string w : wordDict) {          // ← word inner, enumerate choices
                int L = w.size();
                if (i - L >= 0 && dp[i - L] &&
                    s.substr(i - L, L) == w) {
                    dp[i] = true;
                }
            }
        }

        return dp[n];
    }
};

For each end position i, I try every word that could end there: it has to fit, the prefix before it has to be true, and the substring has to match. The line that matters is the outer loop header — position outside, ascending, so every shorter prefix is final before I read it.

And a variant that scales better when the dictionary is large: put the words in a hash set and iterate cut points.

class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> dict(wordDict.begin(), wordDict.end());
        int n = s.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;

        for (int i = 1; i <= n; i++) {          // position outer
            for (int j = 0; j < i; j++) {       // inner: enumerate cut point j
                if (dp[j] && dict.count(s.substr(j, i - j))) {
                    dp[i] = true;
                    break;                          // one way is enough
                }
            }
        }

        return dp[n];
    }
};

Both keep the position on the outside. One thing worth flagging — the second one tries each cut point j and looks up the substring, so a position costs at most i lookups instead of 1000 word checks, and it breaks as soon as one split works.

Time is O(n·k·L) for the word scan — k words, each up to L long. For the cut-point version there are n² cut pairs, but each substring can be up to n characters to build and hash, so as written it's O(n³) in the worst case; capping the cut at the longest word brings it down to O(n·L²). Space is O(n).

Oh, one more thing — the rule I'd carry away: sequence-segmentation problems want the position outside, because the pieces sit at fixed, interleaving spots; knapsack problems want the item outside, because you pick an unordered multiset. Same 1-D array, opposite outer loop.
