Hmm, let me think about this for a second.

A naive approach would be greedy — always step to the cheaper of the next two steps. But a locally cheap step can trap you into a costlier path.

This problem reminds me of a 1-D DP on a staircase: dp[i] = min cost to reach position i. To get to i, I came from i-1, paying cost[i-1], or from i-2, paying cost[i-2] — so I take the min of those two. DP compares both routes at every position.

The table version first: a vector of size n + 1, filled with zeros, so both bases are already free. The loop takes the min of coming from two back plus its cost, and coming from one back plus its cost.

class Solution {
public:
    int minCostClimbingStairs(vector<int>& cost) {
        int n = cost.size();
        vector<int> dp(n + 1, 0);          // dp[0]=dp[1]=0: start free at 0 or 1

        for (int i = 2; i <= n; i++)
            dp[i] = min(dp[i - 2] + cost[i - 2],   // from i-2, pay cost[i-2]
                        dp[i - 1] + cost[i - 1]);  // from i-1, pay cost[i-1]

        return dp[n];                        // n = the top (one past the last step)
    }
};

Then the O(1)-space version — only the last two values matter, so I roll prev2 and prev1 forward.

class Solution {
public:
    int minCostClimbingStairs(vector<int>& cost) {
        int n = cost.size();
        int prev2 = 0, prev1 = 0;            // dp[i-2], dp[i-1]
        for (int i = 2; i <= n; i++) {
            int cur = min(prev2 + cost[i - 2], prev1 + cost[i - 1]);
            prev2 = prev1;                      // roll forward one step
            prev1 = cur;
        }
        return prev1;
    }
};

Both compute the same recurrence. One thing worth flagging — I capture cur before shifting, so prev1 isn't overwritten before it's used.
