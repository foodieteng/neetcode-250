Hmm, let me think about this for a second.

A naive approach would recursively try every square at every step, which repeats the same remainders over and over and blows up exponentially.

This problem reminds me of unbounded knapsack where we minimize the count: the items are the squares, and each can be used any number of times. So dp[i] is the fewest squares summing to i, and dp[i] = min over j of dp[i − j*j] + 1. I can also view it as a BFS shortest path from 0 to n, where each edge adds a square.

// dp[i] = fewest perfect squares summing to i
dp[0] = 0; rest = INF

  for j while j*j <= i:
    dp[i] = min(dp[i], dp[i − j*j] + 1)

One: set dp[0] = 0 and everything else to infinity.
Two: for each i from 1 to n, try every square j*j that fits in i.
Three: take the minimum of dp[i − j*j] + 1, then return dp[n].

One thing worth flagging — a type note. Because the aggregate is a min, not a sum, the values never grow: dp[i] is at most i, and by Lagrange's four-square theorem it's actually ≤ 4. So a plain int is fine here, with no overflow worry like a counting DP has. Does this approach sound good, or would you rather I think of another way?

The DP fills dp from 1 up to n, and for each i tries every square up to i.

class Solution {
public:
    int numSquares(int n) {
        vector<int> dp(n + 1, INT_MAX);   // min-DP won't overflow → int is fine
        dp[0] = 0;

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j * j <= i; j++) {   // squares are the "coins", reusable
                int k = j * j;
                if (dp[i - k] != INT_MAX)       // avoid INT_MAX + 1 overflow
                    dp[i] = min(dp[i], dp[i - k] + 1);
            }
        }

        return dp[n];
    }
};

The line that's easy to get wrong is the guard: the table starts at INT_MAX, and INT_MAX + 1 would overflow, so I only relax from entries that are already finite.

And the BFS is a shortest path from 0 to n, where each edge adds a square:

class Solution {
public:
    int numSquares(int n) {
        if (n == 0) return 0;
        vector<char> visited(n + 1, 0);
        queue<int> q; q.push(0); visited[0] = 1;
        int level = 0;

        while (!q.empty()) {
            level++;                                 // each level = one more square used
            for (int sz = q.size(); sz > 0; sz--) {
                int cur = q.front(); q.pop();
                for (int j = 1; j * j <= n; j++) {
                    int nx = cur + j * j;
                    if (nx == n) return level;          // first time we hit n = shortest
                    if (nx < n && !visited[nx]) {
                        visited[nx] = 1; q.push(nx);
                    }
                }
            }
        }
        return 0;
    }
};

Both are O(n√n). One thing worth flagging — BFS returns as soon as it first reaches n, and since all edges cost 1, that first hit is the minimum.
