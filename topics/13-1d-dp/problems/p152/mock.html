Hmm, let me think about this for a second.

This problem reminds me of Kadane's algorithm — the best subarray ending at i either extends the one ending at i-1, or starts fresh at i.

But products have a twist: a negative flips the largest into the smallest, and vice versa. So tracking only the max fails. On [-2,3,-4], the answer 24 comes from the running min, -6, times -4. So I'll track both the max and the min ending at i, swapping them when the current number is negative.

Here's the plan.

// maxP / minP = best & worst product ending at i
ans = maxP = minP = nums[0]
for i in 1..n-1:
  if nums[i] < 0: swap(maxP, minP)  // negative flips order
  maxP = max(maxP*nums[i], nums[i])
  minP = min(minP*nums[i], nums[i])
  ans = max(ans, maxP)

One: start ans, maxP and minP all at nums[0].
Two: for each next number, if it's negative, swap maxP and minP first.
Three: maxP becomes the larger of maxP × num and num alone; minP becomes the smaller; and ans takes the max.

One thing worth flagging — the swap goes before the multiply, and each update keeps a "start fresh here" option, the bare nums[i]. ans starts at nums[0], so all-negative inputs work. Does this approach sound good, or would you rather I think of another way?

The max/min tracking: one pass, three variables.

class Solution {
public:
    int maxProduct(vector<int>& nums) {
        int n = nums.size();
        int ans = nums[0], maxP = nums[0], minP = nums[0];

        for (int i = 1; i < n; i++) {
            if (nums[i] < 0) swap(maxP, minP);   // a negative flips big/small → swap first

            maxP = max(maxP * nums[i], nums[i]); // extend, or start fresh here
            minP = min(minP * nums[i], nums[i]);

            ans = max(ans, maxP);              // largest maxP seen overall
        }

        return ans;
    }
};

The line that's easy to get wrong is where the swap sits — it has to happen before the multiply, so the old minP becomes the base for the new maxP when the number is negative.

And a slick alternative — prefix and suffix products, resetting on zero:

class Solution {
public:
    int maxProduct(vector<int>& nums) {
        int n = nums.size(), ans = nums[0], prefix = 0, suffix = 0;

        for (int i = 0; i < n; i++) {
            prefix = (prefix == 0 ? 1 : prefix) * nums[i];          // left to right
            suffix = (suffix == 0 ? 1 : suffix) * nums[n - 1 - i];  // right to left
            ans = max(ans, max(prefix, suffix));
        }

        return ans;
    }
};

A running product that hits zero restarts at 1 on the next step. Both are O(n).

One thing worth flagging — the best product is always a prefix or a suffix of a zero-free segment, so scanning both directions and resetting at zeros covers every case.
