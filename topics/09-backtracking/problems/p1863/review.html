PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
寫法 A 為什麼 total += cur 要放在函式最前面,不能等到 s == n 才加?
解答與說明 · ANSWER▾
寫法 A 的每個節點都是一個不同的子集,只在 s == n 加,就只算到「最後挑的是最後一個數」的子集。

s == n 只發生在剛挑了 nums[n-1] 的節點。實測窮舉錯 9,324 / 9,330,[1,1] 回 1(正解 2):只算到 {第二個 1} 和 {1,1}。
第 2 題10 分
寫法 B 為什麼只能在葉子加,每個節點都加會怎樣?
解答與說明 · ANSWER▾
寫法 B 的內部節點是「還沒決定完」的狀態,不是子集;每個節點都加會把同一個部分結果算好幾次。

例如「選了 5、還沒決定 1 和 6」的節點,和它往下「1、6 都不選」的葉子是同一個 {5},會被算兩次。實測錯 9,324 組,[1,1] 回 3(正解 2)。
第 3 題10 分
寫法 A 遞迴時傳 i + 1,改成 s + 1 會怎樣?
解答與說明 · ANSWER▾
s + 1 讓同一層的每個小孩都從同一個位置往後挑,而不是從「剛挑的那個」之後。

挑了 nums[2] 的小孩,下一層卻還能挑 nums[1],index 不再遞增,同一個子集用不同順序出現好幾次。 實測錯 9,288 組,[1,1,1] 回 9(正解 4)。
第 4 題10 分
dfs(..., cur ^= nums[i]) 和 dfs(..., cur ^ nums[i]) 差在哪?怎樣寫 ^= 也能對?
解答與說明 · ANSWER▾
^= 會把這一層的 cur 改掉,下一圈的兄弟從錯的值出發;^ 只算出新值傳下去,自己不變。

[1,3] → 5 vs 6(上面的 Trace)。要用 ^= 就得成對:cur ^= nums[i]; dfs(...); cur ^= nums[i];, XOR 同一個數兩次會還原(隨機 2 萬組 0 錯)。這個「改 → 遞迴 → 改回來」就是之後 path 的 push_back / pop_back。
第 5 題10 分
同樣列出 2ⁿ 個子集,為什麼寫法 B 的呼叫次數幾乎是 A 的兩倍?
解答與說明 · ANSWER▾
寫法 B 是一棵完整的二元樹:2ⁿ 個葉子是子集,上面還有 2ⁿ − 1 個「做一半決定」的內部節點。

寫法 A 沒有這些中間狀態,每個節點本身就是答案。n = 12 時實測:A 呼叫 4,096 次,B 呼叫 8,191 次。兩者都是 O(2ⁿ),只差常數 2 倍。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 [1,3] · 對的 vs 我的第一版:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

官方範例 1 [1,3],答案 6。以寫法 A 實跑,上面是對的版本,下面是用 ^= 的版本。

// 對的:傳 cur ^ nums[i] dfs(s=0, cur=0) {} total = 0 i=0 → dfs(s=1, cur=1) {1} total = 1 i=1 → dfs(s=2, cur=1^3=2) {1,3} total = 3 i=1 → dfs(s=2, cur=0^3=3) {3} total = 6 ← cur 還是 0 // OUTPUT: 6
// 第一版:傳 cur ^= nums[i] dfs(s=0, cur=0) {} total = 0 i=0 → cur 變成 1,dfs(s=1, cur=1) {1} total = 1 i=1 → cur 變成 2,dfs(s=2, cur=2) {1,3} total = 3 i=1 → cur 已經是 1,1^3=2,dfs(s=2, cur=2) {3} 算成 2 total = 5 // OUTPUT: 5 ✗ (正解 6)
差別只在最後一個兄弟節點 {3}:它應該從父節點的 cur = 0 出發,卻從被第一個兄弟改過的 cur = 1 出發。 兄弟節點要共用「父節點的狀態」,所以父節點的狀態不能被任何一個小孩改掉。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
不用遞迴,怎麼用一個 for (mask = 0; mask < (1 << n); mask++) 列出所有子集?它對應到哪一種寫法?
解答與說明 · ANSWER▾
mask 的第 j 個 bit 是 1 就代表選 nums[j],裡面再跑一個 j 迴圈算 XOR。

它就是寫法 B 的葉子:每個葉子的「選 / 不選」路徑就是一個 mask(動畫裡的 111 … 000)。 我拿它當這題的對拍參考解。缺點是每個子集都要重算 O(n),總共 O(n · 2ⁿ)。
第 8 題13 分
有 O(n) 的做法嗎?(提示:看每一個 bit 會在幾個子集的 XOR 裡出現)
解答與說明 · ANSWER▾
有:答案 = (所有數 OR 起來) << (n − 1)。

某個 bit 只要有任何一個數有,它在剛好一半的子集(2ⁿ⁻¹ 個)的 XOR 裡會是 1 —— 把一個有這個 bit 的數拿出來,其他數任意選,它選或不選剛好決定這個 bit。 所以每個出現過的 bit 貢獻 bit × 2ⁿ⁻¹。實測三個範例都對,隨機 2 萬組和暴力一致。
第 9 題14 分
改成 78 Subsets:要回傳所有子集本身,兩種寫法要怎麼改?
解答與說明 · ANSWER▾
把 cur 換成 vector<int>& path,記錄答案時 ans.push_back(path)。

寫法 A:函式一進來就 ans.push_back(path),迴圈裡 path.push_back(nums[i]); dfs(i + 1); path.pop_back();。 寫法 B:i == n 時 push;否則 push → dfs → pop(選),再直接 dfs(不選)。 因為 path 是參考,一定要 pop 回來 —— 就是這題 第 4 題 的同一件事。
