面向要記住的那一句
骨架78 的 for 迴圈樹,遞迴 i + 1
收path.size() == k,收完 return
數字從 1 開始,到 n(含)

範例 Trace// 官方範例 n = 4, k = 2

以我的寫法實跑,11 次呼叫。

// 1、2 開頭 [] i = 1..4 [1] i = 2..4 → [1,2] 收 [1,3] 收 [1,4] 收 [2] i = 3..4 → [2,3] 收 [2,4] 收
// 3、4 開頭 [3] i = 4..4 → [3,4] 收 [4] i = 5..4 → 迴圈不跑,死路 // OUTPUT: [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]] (11 次呼叫,1 次死路)
k = 2 時只有 [4] 是死路;剪枝後根的迴圈上界是 4 − 2 + 1 = 3,[4] 不會被呼叫。 答案 6 個 = C(4, 2),順序剛好就是字典序。

應用題// APPLY IT

App 1. 用 1863 的二元寫法(每個數選 / 不選)寫這題,要怎麼剪枝?
App 2. 216 Combination Sum III:1~9 選 k 個加起來等於 n。和這題比要多加什麼?

// ANSWERS
A1. 78 每個節點都收;這題 size == k 才收。

收完 return,因為再往下 path 只會變長,不可能再是 k 個。不 return 也不會錯(實測 55 組 0 錯),只是白走:總呼叫 18,434 vs 11,253。
A2. 選了 i 之後,i..n 共 n − i + 1 個數要湊出 need 個:n − i + 1 ≥ need ⇔ i ≤ n − need + 1。

少了 +1 會把剛好夠的那個 i 也剪掉,n = 1, k = 1 一圈都不跑 → [],55 組全錯。
A3. 死路 = 已選的加上後面剩下的數,還湊不到 k 個的節點。

n = 4, k = 3 有 5 個:[1,4]、[2,4]、[3,4]、[3]、[4],所以我的寫法 15 次呼叫、剪枝版 10 次。
A4. 不剪枝的樹會長出所有大小 ≤ k 的子集。

k = 2 時那只是 1 + 20 + 190 = 211 個節點,幾乎都在答案路上(剪枝版 210 次)。 k = 18 時大小 ≤ 18 的子集有一百多萬個,其中能長到 18 的很少:答案 190 個,卻要 1,048,555 次呼叫;剪枝後 1,330 次。
A5. 傳 i 會讓同一個數被選很多次,這題要的是不同的數。

實測 n = 2, k = 2 → [[1,1],[1,2],[2,2]],45 / 55 組錯。k = 1 時剛好不會出事,所以要測 k ≥ 2。
A-App 1. size == k 收;i > n 或 size + (n − i + 1) < k(剩下全選也不夠)就 return;否則選 i、不選 i 各走一次。

不剪枝的二元版實測 n = 20、k = 18 要 2,097,109 次呼叫,比 for 迴圈版還多;加上「剩下全選也不夠就 return」後降到 2,659 次(55 組窮舉 0 錯)。
A-App 2. 多帶一個 sum,收的條件變成 size == k && sum == n;sum + i > n 就 break。

這題的 n 換成 9,剪枝兩個一起用:數字不夠就不往下、和超過就 break。39 複習頁 App 3 有實測過的版本。
A-App 3. 可以一位一位決定:第一個數選 1 的組合有 C(n − 1, k − 1) 個,m 比這個大就跳過 1、把 m 減掉,再試 2……

每一位最多試 n 次、算一次組合數,總共 O(n · k)。這是「排名 / 反排名」的技巧,60 Permutation Sequence 用的是同一個想法。實測 n = 1~10 所有 k、每一個 m(共 2,036 個)都和字典序列舉一致。

// ONE-LINE TAKEAWAY
78 的樹,size == k 才收;死路 = 剩下的數不夠湊滿。剪枝 i ≤ n − need + 1(+1 不能少),k 接近 n 時差上百倍。傳 i 會重複選、s + 1 會重複組合,都要 k ≥ 2 才看得出來。
