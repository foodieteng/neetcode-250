題目簡介// THE QUESTION

QUESTION

從 1 ~ n 裡選剛好 k 個不同的數,回傳所有組合(不分順序)。
1 ≤ n ≤ 20,1 ≤ k ≤ n。

範例:n = 4, k = 2 → [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]](C(4,2) = 6 個);n = 1, k = 1 → [[1]]。

就是 78 Subsets 裡「大小剛好是 k」的那些。 骨架一樣(for 迴圈、i + 1、push / pop),只把「每個節點都收」改成「選滿 k 個才收」。這次 path 是傳參考,沒有多餘的複製。

核心策略 · 三步驟// THE SHAPE

  1. 選滿就收:path.size() == k → ans.push_back(path),return。
  2. 從 s 挑下一個:path.push_back(i) → dfs(i + 1) → pop_back(),數字從 1 開始。
  3. (剪枝)還差 need = k - path.size() 個,i..n 至少要有 need 個 → 迴圈上界 n - need + 1。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 上界為什麼是 n − need + 1

選了 i 之後,還要從 i..n 這段湊出 need 個(i 自己算一個)。這段有 n − i + 1 個數, 所以要 n − i + 1 ≥ need,也就是 i ≤ n − need + 1。 少了 +1 會把最後一個合法的 i 也剪掉:n = 1, k = 1 迴圈一圈都不跑,回 [],55 組窮舉全錯。

LEMMA 2 · 剪枝什麼時候有用

不剪枝時,樹會長出所有大小 ≤ k 的子集,其中湊不滿 k 的都是死路。k 小時死路很少(n = 20、k = 2:211 vs 210 次); k 接近 n 時幾乎全是死路(k = 18:答案只有 190 個,卻要呼叫 1,048,555 次)。剪枝之後,呼叫次數只跟答案數成正比。
