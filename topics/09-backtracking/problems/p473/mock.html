There are two ways to see the search. The side view builds side 1 as a subset that sums to the target, then side 2, and so on. The bucket view walks the sticks one by one, and each stick picks one of 4 sides.

A naive approach would try all 4^n assignments and check the sums at the end. This problem reminds me of partitioning into k equal-sum buckets, with k = 4. I'll use the bucket view with backtracking, and prune early: never let a side go over the target.

Here's the plan.

// buckets[0..3] = current length of each side
if total % 4 != 0 → false   // quick exit
sort sticks descending; target = total / 4
exist(idx):
  if idx == n → true   // every stick placed, no side over target
  for i = 0..3:
    if buckets[i] + stick > target → continue
    if buckets[i] == buckets[i-1] → continue // same state, skip
    place, recurse, undo

One: if the total isn't divisible by 4, return false; else the target is a quarter, and I sort the sticks descending.
Two: for each stick, try the four sides — skip a side if the stick would push it over the target, or if it's the same length as the side to its left.
Three: place, recurse, and take it back if that fails.

Once every stick is placed, each side is exactly the target: they sum to 4 · target and none is over.

One thing worth flagging — the sort is descending: big sticks have the fewest places to go, so failures show up near the top of the tree. And two sides of the same length give the same state, just swapped, so I only try the first. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    bool makesquare(vector<int>& matchsticks) {
        sort(matchsticks.begin(), matchsticks.end(), greater<int>());   // big ones first
        int n = matchsticks.size();
        int total = accumulate(matchsticks.begin(), matchsticks.end(), 0);
        if (total % 4 != 0) return false;
        int target = total / 4;
        vector<int> buckets(4, 0);

        return exist(matchsticks, buckets, target, 0);
    }

    bool exist(vector<int>& nums, vector<int>& buckets, int target, int idx) {
        if (idx >= nums.size()) return true;                  // ① every stick placed

        for (int i = 0; i < 4; i++) {                         // ② try this stick on 4 sides
            if (buckets[i] + nums[idx] > target) continue;    // ③ doesn't fit
            if (i > 0 && buckets[i] == buckets[i - 1]) continue;   // ④ same length as left: symmetric

            buckets[i] += nums[idx];
            if (exist(nums, buckets, target, idx + 1)) return true;
            buckets[i] -= nums[idx];                          // ⑤ take it back
        }

        return false;
    }
};

The main function sorts descending, checks the total, and starts the search with four empty buckets.

One thing worth flagging — the over-target line must be continue, not break, because the buckets are not sorted; a full side can come before an empty one. Take [1,1,1,1]: the first 1 fills side 0, the next 1 overflows it, and a break would never try sides 1 to 3, so it returns false.

The same goes for the duplicate line: buckets[i] == buckets[i-1] says nothing about buckets[i+1], so a break wrongly fails on [2,2,2,2,2,2,3,3,3,7] — and small tests won't catch it.

Let me think about complexity here.

Time is O(4^n) in the worst case, since each stick has up to 4 choices. In practice the pruning is huge: the hardest random n = 15 input took 32,142 calls, about 0.34 ms. Space is O(n) for the recursion stack, plus the 4 buckets.

Overflow: the worst total is 15 × 10^8 = 1,500,000,000, below INT_MAX = 2,147,483,647. And a bucket never passes the target, so buckets[i] + nums[idx] ≤ target + 108, under half a billion. So int is safe.

The total % 4 check is just a shortcut: without it, target rounds down, the sticks can never all fit, and the search still returns false — only slower.

What if you want a guaranteed bound, not just good pruning?

C
CANDIDATE

Then I'd use a bitmask DP. The state is the set of used sticks, and I fill the sides one at a time, in order.

// dp[mask] = filled length of the current side, or -1 if unreachable
dp[0] = 0
for mask, if dp[mask] ≥ 0:
  for each unused stick j:
    if dp[mask] + a[j] ≤ side:
      dp[mask | 1<<j] = (dp[mask] + a[j]) % side
answer: dp[full] == 0

From a reachable mask, I add any unused stick that fits, and take the new length % side, so a full side resets to 0 and the next stick starts a new side. The answer is whether the full mask reaches 0. That's O(n · 2^n) time and O(2^n) space — at n = 15, 32,768 states.

And if the question asks for k sides instead of 4, both methods carry over: k buckets in the backtracking, or the same DP with side = total / k.
