題目簡介// THE QUESTION

QUESTION

給一串 2~9 的數字,照手機按鍵(2 = abc、3 = def … 7 = pqrs … 9 = wxyz),回傳所有可能的字母組合,順序不限。
1 ≤ digits.length ≤ 4(現在的限制;舊版允許空字串)。

範例:"23" → 9 個:ad ae af bd be bf cd ce cf;"2" → a b c。

09 分類裡最單純的一題:每一層 = 一位數字,選項 = 那個鍵上的字母,沒有任何剪枝或去重。 你的寫法 res 是傳值,所以和 46、131 不一樣:沒有 push / pop。
2

為什麼用 DFS// WHY DFS

A 寫 n 層巢狀迴圈 n 不固定
"23" 兩層 for 就好,但 digits 長度 1~4,迴圈層數寫死不了。遞迴就是「層數由輸入決定的巢狀迴圈」。
× REJECT · 寫不出來
B BFS:一位一位把舊組合接上新字母 也對
[""] → [a,b,c] → [ad,ae,…,cf]。對拍就是用它,4,680 組和你的答案連順序都一樣。缺點是每一層都要存一整排中間結果。
△ ALSO OK · 多存一整層
BOTH FAIL · ADOPT
C DFS:第 i 位選一個字母,往下一位 回溯的最小骨架
一條路徑一次只存一個 res,深度 = 位數。每個答案都得產生出來,這題沒有能剪的東西,所以重點只在「狀態怎麼傳」。 所有合法輸入 4,680 組全部對拍,0 錯。
● ADOPT · 層數跟著輸入走
3

核心策略 · 三步驟// THE SHAPE

  1. i 到底就收:i >= digits.size() → ans.push_back(res)。
  2. 第 i 位的每個字母:mp[digits[i] - '0'],前兩格是 "",讓 '2' 直接對到 index 2。
  3. 新字串往下傳:dfs(res + c, i + 1)。res + c 是新的字串,這一層的 res 沒變,下一個字母照樣從它開始。

傳值和傳參考// TWO LEMMAS

LEMMA 1 · res 傳值 = 每一層自己一份,所以不用 pop_back

dfs(ans, res + c, …):res + c 造出一個新字串交給小孩,這一層的 res 一個字都沒動。下一圈的 c 還是接在原本的 res 後面。 如果在迴圈裡寫 res += c(改到這層自己那份、又沒撤銷),"2" 會變成 [a, ab, abc] —— 4,680 組全錯。 改成 string& res + push_back / pop_back 也對(0 錯),而且省掉複製:"7979" 9.89 µs → 4.58 µs。

LEMMA 2 · mp 前面兩個 "" 是為了讓 digits[i] − '0' 直接當 index

'2' - '0' = 2,所以 mp[2] = "abc"。只存 8 格的話要寫 digits[i] - '2'(也對)。 8 格卻減 '0':"2" 變 [g,h,i],8 和 9 讀到陣列外面(ASan:heap-buffer-overflow)。 忘了 - '0':'2' 是 50,一樣讀到外面。

複雜度// COMPLEXITY

最多 4 個字母的鍵是 7 和 9。n 位全是 7 / 9 時有 4n 個答案,每個長 n。

時間 O(4n · n)　·　額外空間 O(n)(遞迴深度;傳值版每層多一份長度 ≤ n 的字串)
長度 4(實測)答案dfs 呼叫
"7979"(最多)256341 = 1+4+16+64+256
"2222"(最少)81121 = 1+3+9+27+81

一句洞察// INSIGHT

回溯的「撤銷」只有在大家共用同一份狀態時才需要。 res 傳值就是每層各一份:沒有共用,就沒有東西要還原。

// ONE-LINE TAKEAWAY
第 i 位數字的每個字母都試一次,dfs(res + c, i + 1);i 到底就收。res 傳值 → 每個小孩拿到新字串,父層的 res 沒被改,所以沒有 pop_back。最多 4^n 個答案、O(4^n · n)。
