核心策略 · 三步驟// THE SHAPE

  1. 長度到 2n 就收:res.size() == 2 * n → ans.push_back(res),return。
  2. 左括號還沒用完就放:open < n → dfs(res + '(', open + 1, close)。
  3. 右括號比左括號少才放:close < open → dfs(res + ')', open, close + 1)。兩個 if 是並列的,能走就都走。

res 是傳值,而且 res + '(' 本來就是做一個新字串,所以這層的 res 從來沒被改過 —— 不需要 pop。 這和 78 的 path 傳值不同:78 在迴圈裡 push_back 改了自己,所以還是要 pop。

兩個條件為什麼剛好夠// TWO LEMMAS

LEMMA 1 · 長出來的一定合法(不會多)

合法 = 任何前綴裡 ) 都不比 ( 多,最後兩個都剛好 n 個。 close < open 才放 ) → 前綴永遠 close ≤ open;open < n 才放 ( → open ≤ n。 長度 2n 時 open + close = 2n,兩個都 ≤ n,只能都是 n。所以 base case 不用再檢查。

LEMMA 2 · 合法的都長得出來(不會少),而且沒有死路

任何合法字串的每個前綴都滿足那兩個條件,所以沿著它一格一格走,每一步的 if 都會放行 —— 每個答案都會被走到。 反過來,任何 close ≤ open ≤ n 的前綴,只要先補滿 ( 再補滿 ) 就是合法的,所以每個節點都至少通往一個答案。 實測 n = 1~8 和暴力窮舉完全相同(1, 2, 5, 14, 42, 132, 429, 1430 個),沒有重複。

複雜度// COMPLEXITY

答案數是 Catalan 數 Cn = C(2n, n) / (n + 1) ≈ 4ⁿ / (n1.5√π)。 因為沒有死路,節點數只是答案數的常數倍左右;每個節點做一次 res + '('(複製 O(n) 個字元)。

約 Cn 個節點 × 每個 O(n) → 時間 O(4ⁿ / √n)　·　遞迴深度 2n → 額外空間 O(n)(不算輸出)
