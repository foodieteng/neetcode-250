題目簡介// THE QUESTION

QUESTION

能不能把 nums 分成 k 個非空子集,每個子集的和都一樣?
1 ≤ k ≤ n ≤ 16,1 ≤ nums[i] ≤ 104,每個值最多出現 4 次。

範例:[4,3,2,3,5,2,1], k = 4 → true(5、1+4、2+3、2+3);[1,2,3,4], k = 3 → false(總和 10 不能被 3 整除)。

這就是 473 火柴拼正方形把「4 個邊」換成「k 個桶」。你的兩份程式只差 4 ↔ k。 拿這支跑 k = 4 的 473 兩個範例:答案一樣,呼叫數也一樣(6、5)。這張卡只講 473 沒講到的:k 變大之後會怎樣、另一種寫法、什麼時候哪個快。
2

為什麼用桶回溯// WHY K BUCKETS

A 每個數試 k 個桶,不去重 kn
空桶有 k 個,第一個數放哪個空桶都一樣,卻要各走一次。k 越大越慘: 實測 k = 8 的難例 41,578,721 次呼叫、605 ms;你的版本 845 次。
× REJECT · 對稱 k! 倍
B 一次填滿一個桶(used[] + start) 另一種回溯
從沒用過的數挑一組湊滿 target,再填下一個桶。也對(0 錯), k = 3~5 的難例比你的少 17~270 倍呼叫;但 k = 8、數字小的例子反過來多 150 倍。兩種各有剋星。
△ ALSO OK · 看輸入
BOTH FAIL · ADOPT
C 降序 + k 個桶 + 兩個 continue(473 原封不動) 一套程式兩題
所有合法輸入對拍 56,776 組 0 錯;隨機搜尋到最難的 n = 16 輸入約 20 萬次呼叫、2 ms。 bitmask DP(O(n · 2n))是有保證的 follow-up,見複習頁。
● ADOPT · 和 473 共用

核心策略 · 三步驟// THE SHAPE

  1. 先篩、再排序:total % k != 0 → false;target = total / k;由大到小排。
  2. 第 idx 個數試 k 個桶:超過 target → continue;和左邊的桶一樣高 → continue。
  3. 放 → 遞迴 → 拿回;全部數字放完就是 true(桶總和 = total、每桶 ≤ target ⇒ 每桶剛好 = target)。

473 沒講到的兩件事// WHAT CHANGES WITH K

LEMMA 1 · k 越大,同高去重越關鍵

一開始 k 個桶都是 0,不去重的話第一個數要試 k 次,第二個數又是好幾次 …… 光是「空桶互換」就是 k! 種排列。 實測(都是 false 的難例):k = 3 去重前後 666,421 → 111,073 次;k = 4 4,960,005 → 206,649;k = 5 23,123,251 → 192,721; k = 8:41,578,721 → 845 次。降序排序是第二個槓桿:升序在 k = 8 要 353,613 次。

LEMMA 2 · 兩個 continue 一樣不能 break;break 版甚至更難測出來

桶沒有照高度排(理由和 473 一樣)。放不下寫 break:[1,1], k = 2 就錯 —— b0 滿了就 break,空的 b1 沒試。 同高寫 break:窮舉 16,776 組(n ≤ 8)一組都沒錯,隨機 40,000 組錯 23 組,最小反例要 9 個數:[10,12,9,2,6,2,5,13,13], k = 3 → false(正解 true)。

一句洞察// INSIGHT

473 和 698 是同一題:每個數放進哪個桶;k 越大,「同高只試一個」越值錢。 按數字放(你的)和按桶填(used[])各有剋星;要有保證就用 bitmask DP。
