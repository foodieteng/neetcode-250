A naive approach would be to try every way to put n queens on n² squares, then check each board. That's way too many.

The first big cut: two queens can't share a row, so each row has exactly one queen. This problem reminds me of generating permutations by backtracking: row r picks a column, and no column repeats. So it's one recursion level per row, try each column, and prune the moment a queen is attacked.

Here's the plan.

// level r of the recursion = row r → rows can never clash
dfs(r):
  if r == n → save a copy of the board
  for c = 0..n-1:
    if col[c] or diag1[r+c] or diag2[r-c+n-1] → continue
    place Q, set 3 flags, dfs(r+1), clear 3 flags, remove Q

One: level r places the queen for row r; when r reaches n, save a copy of the board.
Two: skip a column if its column, "/" diagonal, or "\" diagonal is taken.
Three: place, set the three flags, recurse, then clear the flags and remove the queen.

One thing worth flagging — since the row is the recursion level, I only need flags for columns and the two diagonals, each checked in O(1).

On a "/" diagonal, r + c is constant. On a "\" diagonal, r − c is constant, but it can be negative, so I shift it by n − 1. Both kinds have 2n − 1 diagonals.

diag1 = r + c         // "/" · index 3 = (0,3) (1,2) (2,1) (3,0)
diag2 = r − c + n − 1 // "\" · index 3 = (0,0) (1,1) (2,2) (3,3)
size of each = 2n − 1 = 7  // n = 4

Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. The main function builds an all-dot board, the flag arrays, and starts the search at row 0. The search saves the board when every row is filled; otherwise it tries each column, skips a blocked one, and does place, recurse, undo.

class Solution {
public:
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> ans;
        vector<string> board(n, string(n, '.'));
        vector<bool> row(n, false), col(n, false), diag1(2 * n - 1, false), diag2(2 * n - 1, false);
        dfs(ans, board, n, 0, row, col, diag1, diag2);
        return ans;
    }

    void dfs(vector<vector<string>>& ans, vector<string>& board, int n, int r, vector<bool>& row, vector<bool>& col, vector<bool>& diag1, vector<bool>& diag2) {
        if (r >= n) {                                        // ① every row is filled
            ans.push_back(board);
            return;
        }

        for (int c = 0; c < n; c++) {                        // ② row r tries each column
            if (col[c] || diag1[r + c] || diag2[r - c + n - 1]) continue;   // ③ column, /, \ taken

            board[r][c] = 'Q';                               // ④ place
            row[r] = col[c] = diag1[r + c] = diag2[r - c + n - 1] = true;
            dfs(ans, board, n, r + 1, row, col, diag1, diag2);
            row[r] = col[c] = diag1[r + c] = diag2[r - c + n - 1] = false;   // ⑤ remove
            board[r][c] = '.';
        }
    }
};

The undo is the exact mirror of the do: the same four flags go back to false, and the square goes back to '.'. ans.push_back(board) copies the board, so later changes don't touch saved answers.

Which bugs would be easy to make here?

C
CANDIDATE

One thing worth flagging — the scary ones here are the silent ones.

• Forget the + n − 1: diag2[r − c] can go negative. In a normal build the output is still correct, so tests pass; only the address sanitizer (ASan) catches it.
• Size the diagonal arrays n instead of 2n − 1: even quieter. vector<bool> packs bits, so the extra indices stay inside one 64-bit word, and even ASan says nothing. Still undefined behavior.
• Forget board[r][c] = '.': the flags are still reset, so the counts are all correct, but the boards have extra queens left over. A test that only checks the count misses it.
• Forget to reset the flags: that one is loud — n = 4 returns 0 boards.

C
CANDIDATE

Let me think about complexity here.

The time complexity is O(n!) placements as an upper bound: row 0 has n choices, row 1 at most n − 1 free columns, and so on. The diagonals cut far more: 2,056 placements at n = 8, and 8,393 at n = 9, around 0.56 ms. On top of that, each solution costs O(n²) to copy the board.

The space complexity is O(n) for the recursion depth and the flags, plus O(n²) for the working board. The output itself is O(S · n²) for S solutions.

What if I only want the number of solutions?

C
CANDIDATE

I'd drop the board completely; the flags alone decide everything, and the base case just does count++.

Then I'd make it faster with bitmasks: the three flag arrays become three ints.

// cols, d1, d2: bit c set = column c is attacked in this row
free = ~(cols | d1 | d2) & ((1 << n) − 1)
while free:
  bit = free & −free    // lowest free column
  free ^= bit
  dfs(r+1, cols | bit, (d1 | bit) << 1, (d2 | bit) >> 1)

The free columns for this row are one expression, I take the lowest free bit each time, and the diagonal masks shift by one each row, because a diagonal moves one column per row. I only visit free columns, so there's no skipping at all.

One more trick: symmetry. A board and its mirror are both solutions, so I only try row-0 columns in the left half, double the count, and handle the middle column on its own when n is odd. That's about half the work.
