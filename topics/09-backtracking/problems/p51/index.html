題目簡介// THE QUESTION

QUESTION

在 n × n 的棋盤放 n 個皇后,任兩個不能同列、同欄、同一條斜線。回傳所有擺法(每個擺法是 n 個字串,'Q' 和 '.')。
1 ≤ n ≤ 9。

範例:n = 4 → 2 種:.Q.. / ...Q / Q... / ..Q. 和 ..Q. / Q... / ...Q / .Q..;n = 1 → ["Q"]。 n = 1~9 的解數:1、0、0、2、10、4、40、92、352。

和 17 同一個形狀:第 r 層 = 第 r 列,選項 = 放在哪一欄。 多出來的是「衝突檢查」:用三個 bool 陣列記住哪些欄、哪些斜線已經被佔,檢查變 O(1);放和拿掉時一起改。
2

為什麼用旗標陣列// WHY FLAGS

A 每列任選一欄,全部擺好再檢查 nn
答案對(對拍就是用它),但 n = 8 要檢查 16,777,216 種擺法。 回溯只放了 2,056 次 —— 第二列就衝突的擺法,後面 6 列根本不用排。
× REJECT · 不剪枝
B 回溯,但每次掃棋盤檢查衝突 每格 O(n)
放之前往上看同一欄、左上、右上三個方向有沒有 Q。也對,但每試一格就要走 O(n) 步; 而且每一格都要試(n = 9 有 63,985 次 continue)。
△ OK · 檢查較慢
BOTH FAIL · ADOPT
C 回溯 + col / diag1 / diag2 三個旗標 O(1) 檢查
一條斜線上的格子 r + c(/)或 r - c(\)都一樣,所以一條斜線就是陣列裡的一格。 n = 1~8 和暴力法逐盤比對完全一致;n = 9 共 8,394 次 dfs、0.56 ms。
● ADOPT · 斜線變成陣列索引
3

核心策略 · 三步驟// THE SHAPE

  1. 一層一列:dfs(r) 在第 r 列放一個皇后;r == n 就把棋盤收進答案。
  2. 三個旗標 O(1) 檢查:col[c]、diag1[r + c](/)、diag2[r - c + n - 1](\),任一為 true 就 continue。
  3. 放 → 下一列 → 拿掉:放 Q、三個旗標設 true,dfs(r + 1),回來後旗標設回 false、Q 改回 '.'。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 斜線編號:r + c 和 r − c + n − 1,各 2n − 1 條

「/」方向往右上走,r 減 1、c 加 1,r + c 不變:n = 4 時 diag1[3] = (0,3)(1,2)(2,1)(3,0)。 「\」方向往右下走,r、c 一起加 1,r − c 不變:diag2[3] = (0,0)(1,1)(2,2)(3,3)。 r − c 的範圍是 −(n−1) ~ n−1,加 n - 1 讓它變成 0 ~ 2n−2,所以兩個陣列都開 2n - 1。 忘了 + n − 1:一般編譯答案竟然全對(vector<bool> 的負索引剛好讀到前一個 word 的位元),只有 ASan 抓得到。

LEMMA 2 · row[] 寫了,但從來沒有被讀過

row 只出現在設 true 和設 false 那兩行,if 裡只查 col、diag1、diag2。 因為第 r 層只在第 r 列放一個皇后,然後就去 r + 1 —— 兩個皇后不可能同列,不用檢查。 實測把 row 整個拿掉:n = 1~12 輸出逐位元組相同,速度沒有差別。 小心別把它當成 col 的替身:if 裡誤寫成 row[c],每個 n 都只剩 1 個(錯的)盤面。

複雜度// COMPLEXITY

第 r 列最多只有 n − r 欄沒被佔用(欄的限制),所以放置次數不超過 n!;斜線再剪掉一大半。每找到一個解,要把 n × n 的棋盤複製進答案。

一句洞察// INSIGHT

一層一列 → 列自動不衝突;欄和兩種斜線各用一個 bool 陣列,斜線靠 r + c / r − c 編號。 放的時候三個一起設、拿掉時三個一起清,棋盤的 Q 也要改回來。

// ONE-LINE TAKEAWAY
第 r 層在第 r 列放一個皇后:欄 col[c]、「/」diag1[r+c]、「\」diag2[r−c+n−1] 任一被佔就 continue;放、遞迴下一列、拿掉。一列一層所以列不用檢查 —— row[] 寫了但從來沒讀。n = 9:352 個解、8,393 次放置、0.56 ms。
