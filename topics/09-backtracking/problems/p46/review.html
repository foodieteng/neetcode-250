PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
77 Combinations 的迴圈從 s 開始,這題為什麼要從 0 開始?
解答與說明 · ANSWER▾
組合不在乎順序,所以只往後挑來避免重複;排列在乎順序,[2,1] 也是答案。

從 s 開始的話,第 1 格放了 2 之後就挑不到 1。實測 [1,2] 只剩 [[1,2]],246 組錯 238。
第 2 題10 分
從 0 開始,為什麼不會把同一個數放兩次?
解答與說明 · ANSWER▾
used[i] 記著「這條路上已經放了 nums[i]」,迴圈遇到就 continue。

拿掉這行,每一格都能挑任何數:[1,2] → [[1,1],[1,2],[2,1],[2,2]](2² 個,不是 2! 個)。
第 3 題10 分
忘了 used[i] = false 和忘了 pop_back(),[1,2] 都只得到 [[1,2]]。兩個錯的原因一樣嗎?
解答與說明 · ANSWER▾
不一樣,只是剛好輸出相同。

忘了 used = false:回來後 used 一直是滿的,後面每一格都挑不到東西(上面的 Trace)。 忘了 pop_back:path 回來時還帶著舊的數,長度一直超過 n,再也不會等於 n,所以不會再收。兩種都錯 238 / 246。
第 4 題10 分
[1,2,3] 為什麼是 16 次呼叫?
解答與說明 · ANSWER▾
樹每一層的節點數:根 1 個,第 1 格 3 個,第 2 格 3 × 2 = 6 個,第 3 格 6 個 → 1 + 3 + 6 + 6 = 16。

一般是 1 + n + n(n−1) + … + n!。n = 6 時是 1,957 次,答案 720 個。
第 5 題10 分
這題 path 和 used 都傳參考。如果兩個都改成傳值,還需要還原嗎?
解答與說明 · ANSWER▾
還是要。傳值只擋住「下一層改到我」,擋不住「我自己的迴圈下一圈看到上一圈的修改」。

實測兩個都傳值、迴圈裡不還原:[1,2] → [[1,2],[1,2]](第二圈的 path 還留著 1、used[0] 還是 T)。 和 78 的 LEMMA 1 同一件事。所以「在迴圈裡改、在迴圈裡還原」不管傳值傳參考都要寫。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 [0,1] · 對的 vs 忘了 used = false:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

官方範例 2 [0,1],正解 [[0,1],[1,0]],5 次呼叫。

// 對的 [] FF [0] TF → [0,1] TT 收 回來:pop、used[1] = F;回來:pop、used[0] = F [1] FT → [1,0] TT 收 // OUTPUT: [[0,1],[1,0]]
// 忘了 used[i] = false [] FF [0] TF → [0,1] TT 收 回來:pop,但 used 還是 TT i = 1:used[1] 是 T → 跳過 ← [1] 開頭的整棵樹都沒了 // OUTPUT: [[0,1]] ✗
第一個排列做完之後,所有數都被標成「用過」,後面每一格都挑不到東西。 used 記的是「現在這條路上有誰」,離開這條路就要擦掉。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
47 Permutations II:nums 可能有重複,答案不能有重複的排列。要加哪一行?
解答與說明 · ANSWER▾
先排序,迴圈裡加:if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;。

意思是:相同的數要照原本的順序用,前一個相同的數還沒用,就不能先用這一個。這樣同一格不會放兩次「同樣的值」。 實測隨機 2 萬組(大量重複值)和 next_permutation 的結果一致。
第 8 題13 分
不用 used[] 和 path,能不能直接在 nums 上交換做出所有排列?
解答與說明 · ANSWER▾
可以:dfs(s) 決定第 s 格,讓 i 從 s 到 n − 1,swap(nums[s], nums[i]) → dfs(s + 1) → 換回來。

nums[0..s-1] 是已經排好的部分,nums[s..] 是還沒用的數,所以不需要 used。s == n 時收 nums。 實測 246 組 0 錯,呼叫次數一樣(n = 6 是 1,957),時間 0.032 vs 0.050 ms。缺點是輸出不是字典序。
第 9 題14 分
只要長度為 k 的排列(從 n 個裡排 k 個),要改哪裡?共有幾個?
解答與說明 · ANSWER▾
只要把收的條件改成 path.size() == k。

共 n! / (n − k)! 個(第 1 格 n 種、第 2 格 n − 1 種……乘 k 次)。迴圈、used、還原都不用動。實測 n = 1~6 所有 k(21 組)個數都對、沒有重複。
