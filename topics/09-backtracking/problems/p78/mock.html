// state
path = the subset on this branch
s    = first index I may still pick
ans  = all subsets (passed by reference)

// dfs(path, s)
ans.push_back(path)    ← every node is a subset
for i in [s, n):
  path.push_back(nums[i])
  dfs(path, i + 1)     ← next pick is after i
  path.pop_back()      ← undo before the next sibling

One: record the path at the start of every call.
Two: loop i from s to the end; push nums[i] and recurse with i + 1, so the next pick comes after i.
Three: pop it back before the next sibling.

Here, I'm using s to keep track of where I may start picking. Every subset is built in increasing index order, so [2,1] can never appear. That's how I avoid duplicates.

One thing worth flagging — I record path at every node, not only at the bottom. The root is the empty set [], and each child adds one element with a bigger index. So the tree has exactly 2n nodes, one per subset.

class Solution {
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        vector<vector<int>> ans;
        vector<int> path;
        dfs(nums, ans, path, 0);
        return ans;
    }

    void dfs(vector<int>& nums, vector<vector<int>>& ans, vector<int> path, int s) {
        ans.push_back(path);                                // every node is a subset

        for (int i = s; i < nums.size(); i++) {
            path.push_back(nums[i]);                        // choose
            dfs(nums, ans, path, i + 1);                    // pass a copy down
            path.pop_back();                                // undo, try the next one
        }
    }
};

The main function makes an empty answer and an empty path, and calls dfs from index 0. dfs records the path, then loops: push, recurse with i + 1, pop.

There's no base case. When s == n, the loop doesn't run, and the call just returns. ans is a reference, so every call writes into the same list.

One thing worth flagging — here path is passed by value. So each call gets its own copy, and the callee can't break the caller's path.

    void dfs(vector<int>& nums, vector<vector<int>>& ans, vector<int>& path, int s) {
        ans.push_back(path);                                // store a copy

        for (int i = s; i < nums.size(); i++) {
            path.push_back(nums[i]);                        // change the shared path
            dfs(nums, ans, path, i + 1);
            path.pop_back();                                // must restore it
        }
    }

Let me walk through that. Now there is one shared path for the whole tree. Every push_back must be undone by the pop_back after the call returns. Then the path is back to what it was, and the next sibling starts clean.

There's a trade-off here. Copying path into ans happens in both versions. That copy is the output, so I can't skip it. By value just adds one more copy per call. At n = 10, that's 5,120 extra elements copied. At n = 20, it's about 10.5 million (10,485,760) extra, and I measured about 122 ms versus 104 ms. Same big-O, but by reference is cheaper.

One thing worth flagging — pop_back is needed even by value. The copy only protects the caller; inside one call, the loop keeps using its own copy. Without the pop, [1,2] gives [1,2] twice, instead of [2].

Corner cases:

• A single [0] → [[],[0]].
• By reference without the pop, [1,2] → [[],[1],[1,2],[1,2,2]].
• Recursing with s + 1 instead of i + 1 reuses the 2.
• Recording only when s == n loses the empty set on every input.

Let me think about complexity here.

The time complexity is O(n · 2n). There are 2n subsets, and copying each one into ans costs up to O(n). That's the output size, so no solution can do better.

The space complexity is O(n) extra by reference: the recursion stack and the path are at most n deep, not counting the output. By value it's O(n²), since each of the n levels holds its own copy.

In the worst-case scenario, n = 10: 1,024 subsets and 5,120 output elements. It ran in 0.07 ms by reference and 0.10 ms by value. I also checked both versions against the bitmask on 3,619 small arrays, with zero mismatches.
