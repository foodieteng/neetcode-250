重點回顧// RECAP

面向要記住的那一句
骨架和 1863 同一棵 for 迴圈樹,每個節點都是子集
三行push_back(nums[i]) → dfs(i + 1) → pop_back()
記錄一進來 ans.push_back(path),會自動複製
傳值 vs 參考都對;參考少一次複製,傳值每層一份
pop兩種寫法都不能省 —— 迴圈的兄弟要從同一個 path 出發
複雜度O(n · 2ⁿ),額外 O(n)(傳值是 O(n²))

觀念題// CONCEPT Q&A

Q1. 我的 path 是傳值,被呼叫的那層改不到我的 path。那迴圈裡的 pop_back() 還有必要嗎?
Q2. 傳參考時,ans.push_back(path) 存進去的子集,之後會不會被 push / pop 改掉?
Q3. 把 ans.push_back(path) 從函式開頭移到 for 迴圈後面,答案會錯嗎?
Q4. 為什麼時間是 O(n · 2ⁿ),不是 1863 的 O(2ⁿ)?
Q5. 傳參考忘了 pop,和傳值忘了 pop,錯的樣子為什麼不一樣?
3

範例 Trace// [1,2] · 有 pop vs 沒 pop

[1,2],正解 4 個子集 [] [1] [1,2] [2]。三種寫法並排(都實跑過)。

// 對的(傳值或傳參考都一樣) dfs(s=0) path [] 收 [] push 1 → dfs(s=1) path [1] 收 [1] push 2 → dfs(s=2) path [1,2] 收 [1,2] pop → [1] pop → [] push 2 → dfs(s=2) path [2] 收 [2] // OUTPUT: [[],[1],[1,2],[2]]
// 傳值、沒 pop dfs(s=0) path [] 收 [] push 1 → [1],dfs 拿到複本 [1] 收 [1] → 它自己 push 2 → 收 [1,2] (回到 s=0,這層的 path 還是 [1]) push 2 → [1,2],dfs 拿到複本 收 [1,2] ← 該是 [2] // OUTPUT: [[],[1],[1,2],[1,2]] ✗
// 傳參考、沒 pop dfs(s=0) path [] 收 [] push 1 → [1] dfs 收 [1] → push 2 → [1,2] 收 [1,2](共用的 path 停在 [1,2]) (回到 s=0,共用的 path 是 [1,2]) push 2 → [1,2,2] dfs 收 [1,2,2] ← 該是 [2] // OUTPUT: [[],[1],[1,2],[1,2,2]] ✗
兩種錯都錯在第 4 個([2] 那個兄弟)。 傳值時只有「這一層的 1」沒拿掉;傳參考時連下一層 push 的 2 也沒拿掉,所以多出一個 2。

應用題// APPLY IT

App 1. 用 1863 的二元寫法(選 / 不選)寫這題,path 要怎麼 push / pop?
App 2. 下一題 90 Subsets II:nums 可能有重複,答案不能有重複的子集。要改哪裡?
App 3. 只要大小剛好為 k 的子集(77 Combinations),要改哪裡?能不能提早剪枝?
// ANSWERS
A1. 有必要。傳值只擋住「下一層改我」,擋不住「我自己的迴圈」。

第一圈 push 了 nums[s],沒 pop 的話,第二圈會在它上面再 push。實測拿掉 pop:[1,2] → [[],[1],[1,2],[1,2]],窮舉錯 3,612 / 3,619。
A2. 不會。push_back(path) 存的是一份複本。

vector<vector<int>>::push_back 會呼叫 vector 的複製建構子,ans 裡的那份和 path 之後就沒有關係了。 (如果 ans 存的是指標或參考,才會跟著被改。)
A3. 不會錯,只是順序變了。

每個節點還是剛好收一次,只是從「先收自己再看小孩」變成「先看完小孩再收自己」(前序 → 後序)。實測 3,619 組 0 錯。 但不能放到迴圈裡面(實測 [1,2] → [[],[1],[]],空集合收兩次、少了 [1,2] 和 [2]),也不能只在 s == n 收(那樣只剩含最後一個數的子集,[1] 會少了空集合)。
A4. 1863 每個節點只做 O(1)(一個 XOR);這題每個節點要把 path 複製進 ans,平均 n/2 個元素。

輸出本身就有 n · 2ⁿ⁻¹ 個元素(n = 10 是 5,120 個,n = 20 是 10,485,760 個),所以不可能比 O(n · 2ⁿ) 更快。
A5. 傳參考時錯誤會「往上帶」:下一層 push 的東西也沒被拿掉,回到上一層時共用的 path 比該有的還長。

傳值時下一層改的是複本,回來時這層的 path 只多了「自己迴圈 push 的那一個」。 所以 [1,2]:傳參考錯成 [1,2,2],傳值錯成 [1,2]。
A-App 1. i == n 時 ans.push_back(path);否則 path.push_back(nums[i]); dfs(i + 1); path.pop_back(); dfs(i + 1);。

選的那支要 push / pop 成對,不選的那支直接往下。實測 3,619 組 0 錯。和 1863 一樣,只有葉子收,呼叫次數 2ⁿ⁺¹ − 1。
A-App 2. 先排序,迴圈裡加一行 if (i > s && nums[i] == nums[i-1]) continue;。

同一層(同一個 s)的兄弟裡,相同的數只讓第一個往下長;i > s 確保「同一層」才跳,往下一層時第一個還是可以選。 這就是 1863 說的「去重用 for 迴圈寫法比較順手」。實測隨機 2 萬組(值只有 0~2,大量重複)0 錯。
A-App 3. 改成 path.size() == k 才收、而且收完就 return。

剪枝:剩下的數不夠湊滿 k 個就不用往下(n - i < k - path.size() 時 break)。迴圈上界可以寫成 i <= n - (k - path.size())。實測 n = 1~10、所有 k 共 55 組,個數都等於 C(n, k)、沒有重複。

// ONE-LINE TAKEAWAY
push → dfs(i + 1) → pop,傳值或傳參考都要 pop;push_back(path) 會複製,不怕之後被改。沒 pop 時:傳值 [1,2] → 多一個 [1,2],傳參考 → [1,2,2]。下一步:90 排序 + 同層跳重複,77 收滿 k 個就停。
