題目簡介// THE QUESTION

QUESTION

在字串 s 裡加空格,讓每一段都是 wordDict 裡的字(字可以重複用)。回傳所有切法組成的句子,順序不限。
1 ≤ s.length ≤ 20、字典最多 1000 個字、每個字長 1~10;保證答案總長不超過 105。

範例:"catsanddog",字典 cat / cats / and / sand / dog → ["cat sand dog", "cats and dog"]; "catsandog" 同一本字典 → [](sand 和 and 後面都剩 "og")。

骨架和 131 · Palindrome Partitioning 一樣:一層 dfs 切下一段,檢查這段合不合法,切到底就收。 和 139 · Word Break 的關係:139 只問「切不切得完」;這題要列出所有切法,答案可能是指數多個,所以一定是搜尋 —— 但 139 的 DP 可以拿來剪枝,只是方向要反過來。
2

為什麼用「回溯 + 後綴剪枝」// WHY PRUNE

A 前綴 DP:dp[i] = s[0..i) 的所有句子 存死前綴
139 的 DP 直接改成存句子。它只知道「前面切得出來」,不知道後面接不接得下去。 "a"×19 + "b"、字典 a~aaaa:一句答案都沒有,dp 裡卻存了 306,128 個前綴句子。
× REJECT · 方向錯
B 純回溯:每個 end 都切切看 死路白跑
答案對、n ≤ 20 也能過。但死路要走到底才知道是死路:上面那組輸入要 306,128 次 dfs、約 9.7 ms,換字典 a~a10 約 17.5 ms,最後回傳 []。
△ OK · 無解時最慢
BOTH FAIL · ADOPT
C 先反向算 canBreak[i](s[i..n) 切不切得完),回溯只走 T 的位置 只走活路
預處理 O(n·L²),之後每一步都通往至少一個答案。同一組輸入:canBreak[0] = F,0 次 dfs 直接回 [];"catsanddog" 查字典從 29 次降到 7 次。 另一條也對的路是記憶化(第 2 支動畫):每個後綴的句子只算一次,一樣不會在死路上重算,代價是每個位置都要存一整份句子。
● ADOPT · OUTPUT-SENSITIVE
3

核心策略 · 三步驟// THE SHAPE

  1. 反向 Word Break I:canBreak[n] = true;i 從 n − 1 往回,只要有某個 end 讓 s[i, end) 是字而且 canBreak[end],就 canBreak[i] = true。canBreak[0] 是 F 就直接回 []。
  2. 切割回溯:dfs(start) 試 end = start + 1 … start + maxLen;canBreak[end] 是 F 就跳過(連字典都不查),是字就接到 path。
  3. 收與撤銷:start == n 收下 path;遞迴回來 path.resize(oldLen),字和前面的空格一起拿掉。

兩個要能講清楚的點// TWO LEMMAS

LEMMA 1 · 剪枝陣列一定要是「後綴」:139 的前綴 dp 剪不到任何東西

回溯是從左往右切,站在 start 時,左邊 s[0..start) 已經切好了 —— 「前面切不切得出來」早就是 true,沒有資訊。 要問的是「切到 end 之後,剩下的 s[end..n) 還切不切得完」,所以 DP 要從右往左做。 實測:把 139 方向的 dp 拿來剪枝,20,000 組隨機測資答案全對,但 "a"×19 + "b" 照樣 306,128 次 dfs —— 一刀都沒剪到。

LEMMA 2 · 剪枝後,每個 dfs 節點都在某個答案上

進 dfs(end) 的條件是 canBreak[end] = T,也就是從 end 一定有一種切法到底。 所以搜尋樹上每個節點往下至少有一條路走到 start == n,沒有任何一條死路。 搜尋的工作量因此被答案大小綁住(output-sensitive)—— 答案本來就要一句一句輸出,不可能更少。 反過來,當幾乎每條路都是活路(例如 20 個 a、字典 {a, aa},10,946 句),剪枝就沒東西可剪,三種寫法都由輸出主導:純回溯 1.39 ms、記憶化 3.17 ms、剪枝 0.83 ms。

複雜度// COMPLEXITY

n = 字串長、L = 最長的字、K = 答案總字元數。答案本身最壞是指數級,所以沒有寫法能做到多項式時間;差別在「沒有答案的部分」要不要付錢。

一句洞察// INSIGHT

列出所有切法 = 切割回溯;怕死路就先用「從右往左」的 Word Break I 標出哪些位置切得到底。 剪枝後每一步都在通往答案的路上;記憶化是另一個正確選擇,用記憶體換掉重算。
