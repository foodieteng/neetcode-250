A naive approach would be to try every set of cut positions — 2^(n−1) ways — and check each one. It's correct, but blind: it builds full cuts even when the first piece is already not a word.

This problem reminds me of partition backtracking: at index start, pick where the next word ends, check it, go deeper, then undo. It also reminds me of the yes-or-no version, "can it be split at all?", which is a simple DP. I think I can use that yes/no DP to prune this search.

So my plan is two steps: first, plain backtracking; then add a pruning table so I never walk into a dead end.

Here's the plan.

// step 1 — plain backtracking
dfs(start):
  if start == n → save path
  for end in start+1 .. n:
    word = s[start..end)
    if word in dict → add word, dfs(end), undo

// step 2 — prune with a suffix table
canBreak[i] = can s[i..n) be fully split into words?
canBreak[n] = true // empty suffix: done
for i = n-1 down to 0:
  canBreak[i] = some end with canBreak[end] and s[i..end) in dict
in dfs: skip any end where canBreak[end] is false

One: the search tries every end from start; if the piece is a word, it adds it, recurses, and undoes.
Two: canBreak[i] says whether the suffix from i can be fully split, filled from the right.
Three: in the search, skip any end where canBreak is false — that cut can never finish, so I don't even look up the word.

One thing worth flagging — the direction matters. The usual yes/no DP is a prefix table: "can I get here?" My search already got here; it needs: "can I get from here to the end?" A prefix table keeps the answers correct but prunes nothing.

Alright, let me code this up. First, the plain backtracking. The search saves the path when start reaches the end; otherwise it tries every end, skips pieces that aren't words, appends the word with a space if needed, recurses, and resizes the path back.

class Solution {
public:
    vector<string> wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> dict(wordDict.begin(), wordDict.end());
        vector<string> ans;
        string path;
        dfs(s, 0, dict, path, ans);
        return ans;
    }

    void dfs(const string& s, int start, unordered_set<string>& dict, string& path, vector<string>& ans) {
        if (start == (int)s.size()) {                               // ① whole string cut
            ans.push_back(path);
            return;
        }

        for (int end = start + 1; end <= (int)s.size(); end++) {    // ② where this word ends
            string word = s.substr(start, end - start);
            if (!dict.count(word)) continue;                        // ③ not a word

            int oldLen = path.size();                               // ④ append
            if (!path.empty()) path += ' ';
            path += word;
            dfs(s, end, dict, path, ans);
            path.resize(oldLen);                                    // ⑤ remove (with the space)
        }
    }
};

One thing worth flagging — the undo step. I save oldLen before I add the space and the word, so path.resize(oldLen) removes both. If I only cut off the word's length, the space would stay behind: on s = "aa", with {a, aa}, the second answer comes out as "a aa", instead of just "aa".

Two more small guards. The loop is end <= n, because the last word has to reach the end; with <, s = "a" returns []. And the path.empty() check stops a leading space.

Now the pruned version: same search, plus the canBreak table, and the loop only goes up to maxLen letters.

class Solution {
public:
    vector<string> wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> dict(wordDict.begin(), wordDict.end());
        int n = s.size();
        maxLen = 0;
        for (const string& word : wordDict) maxLen = max(maxLen, (int)word.size());

        // canBreak[i]: can s[i..n) be fully split into dictionary words
        canBreak.assign(n + 1, false);
        canBreak[n] = true;
        for (int i = n - 1; i >= 0; i--) {
            for (int end = i + 1; end <= min(n, i + maxLen); end++) {
                if (canBreak[end] && dict.count(s.substr(i, end - i))) {
                    canBreak[i] = true;
                    break;
                }
            }
        }

        vector<string> ans;
        if (!canBreak[0]) return ans;                               // whole string can't be split
        string path;
        dfs(s, 0, dict, path, ans);
        return ans;
    }

private:
    int maxLen = 0;
    vector<bool> canBreak;

    void dfs(const string& s, int start, unordered_set<string>& dict, string& path, vector<string>& ans) {
        int n = s.size();
        if (start == n) {
            ans.push_back(path);
            return;
        }

        for (int end = start + 1; end <= min(n, start + maxLen); end++) {
            if (!canBreak[end]) continue;                           // cutting here can never finish
            string word = s.substr(start, end - start);
            if (!dict.count(word)) continue;

            int oldLen = path.size();
            if (!path.empty()) path += ' ';
            path += word;
            dfs(s, end, dict, path, ans);
            path.resize(oldLen);
        }
    }
};

Let me think about complexity here.

The time complexity for the pruned version has two parts. Building canBreak is O(n · L²), where L is the longest word: n starts, L ends each, L per substr. The search is output-sensitive: every node I visit has canBreak true, so it leads to at least one sentence.

The space complexity is O(n) besides the answer: the table, the recursion depth, and one path.

The output itself can be exponential, so nothing beats that; plain backtracking is O(2^n · n), and pays it even with 0 answers.

Oh, one more thing — pruning isn't magic when almost every branch works. 20 'a' with {a, aa} gives 10,946 sentences; all three versions finish within a few milliseconds of each other (plain 1.39 ms, memo 3.17 ms, prune 0.83 ms), because writing the output is the real cost.
