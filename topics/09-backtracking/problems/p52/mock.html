A naive approach would be to try every permutation of columns, one column per row, and then check the diagonals at the end. That's n! full boards. It still works for n = 9, but it builds a lot of boards that were already broken in the second row.

This problem reminds me of the classic backtracking template: choose, recurse, un-choose. Here I go row by row, try each column, and skip a column the moment it's attacked. A bad prefix dies right away, so I never build its children.

Here's the plan.

// state: r = current row, ans passed by reference (int&)
// col[c], diag1[r+c], diag2[r-c+n-1] = "already attacked"
dfs(r):
  if r == n: ans += 1; return   // all n rows filled
  for c in 0..n-1:
    if (r,c) attacked: continue
    mark col, diag1, diag2
    dfs(r + 1)
    clear col, diag1, diag2   // undo

One: when the row index reaches n, all rows are filled, so add one.
Two: in this row, skip any column that's attacked.
Three: mark the column and both diagonals, recurse to the next row, then clear them.

Three boolean arrays track which lines are taken, so each check is O(1).

One thing worth flagging — the diagonal indexing. On a / diagonal, r + c stays the same. On a \ diagonal, r - c stays the same, but it can be negative, so I add n - 1. Both arrays need 2n - 1 slots.

class Solution {
public:
    int totalNQueens(int n) {
        int ans = 0;
        vector<bool> row(n, false), col(n, false), diag1(2 * n - 1, false), diag2(2 * n - 1, false);
        dfs(n, 0, ans, row, col, diag1, diag2);
        return ans;
    }

    void dfs(int n, int r, int& ans, vector<bool>& row,  vector<bool>& col, vector<bool>& diag1, vector<bool>& diag2) {
        if (r == n) {                                       // ① every row filled → count one
            ans += 1;
            return;
        }

        for (int c = 0; c < n; c++) {                       // ② row r tries each column
            if (row[r] || col[c] || diag1[r + c] || diag2[r - c + n - 1]) continue;   // ③ taken → skip

            row[r] = col[c] = diag1[r + c] = diag2[r - c + n - 1] = true;           // ④ place
            dfs(n, r + 1, ans, row, col, diag1, diag2);
            row[r] = col[c] = diag1[r + c] = diag2[r - c + n - 1] = false;          // ⑤ remove
        }
    }
};

One thing worth flagging — the row array. I added it for symmetry, but it never does any work. Each level places at most one queen in its own row, so row[r] is always false when I read it. Removing it gives the same answers for n = 1..9.

And ans is passed as int&, so every leaf adds into the same counter in totalNQueens.

Let me think about complexity here.

The time complexity is O(n!). Row r has at most n - r free columns, because each earlier queen takes one column. The diagonal checks cut it down a lot in practice: 8,394 calls for n = 9.

The space complexity is O(n) — the recursion depth plus the flag arrays. I keep no board at all.

Oh, one more thing — I'd clean up the code by dropping row. It's dead weight, since the recursion level already is the row.
