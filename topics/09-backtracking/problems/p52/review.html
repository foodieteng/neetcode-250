PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
從 51 改成這題,程式哪幾行要動?哪些完全不用動?
解答與說明 · ANSWER▾
只動三處:回傳型別 → int;拿掉 board 和 ans 陣列,改成一個 int 計數器;base case 從 push_back(board) 改成 ans += 1。

for 迴圈、三個旗標的檢查、設 true、遞迴、設回 false 一字不改。所以兩題的 dfs 呼叫數完全一樣(n = 9 都是 8,394)。51 裡的 board[r][c] = 'Q' / '.' 那兩行也一起消失。
第 2 題10 分
把 int& ans 寫成 int ans,會發生什麼事?為什麼 n = 2、3 看起來是對的?
解答與說明 · ANSWER▾
每一層拿到的是 ans 的副本,葉子加 1 只加在自己的副本上,return 後就丟了;最外層的 ans 永遠是 0。

實測 n = 1~9 全部回傳 0。n = 2、3 的正確答案本來就是 0,所以這兩個測資會「通過」—— 只測小 n 抓不到。至少用 n = 4(→ 2)測。
第 3 題10 分
怎麼確定 ans += 1 不會把同一個解數兩次?
解答與說明 · ANSWER▾
一個解 = 每一列各選一欄 = 搜尋樹上一條從根到 r == n 的路,而每條路只會被走一次。

每一層的 for 迴圈 c 從 0 到 n − 1,每欄只試一次;兩條不同的路一定在某一列選了不同的欄,所以對應不同的解。實測和排列暴力法 n = 1~9 一致。
第 4 題10 分
不用 int&,改成讓 dfs 回傳 int,要怎麼寫?
解答與說明 · ANSWER▾
if (r == n) return 1;,迴圈裡 count += dfs(r + 1, …),最後 return count;。

每個節點回傳「自己這棵子樹的解數」= 子節點回傳值的和 —— 概念頁動畫裡節點右邊的小格就是這個值。程式碼頁第 2 節的 bitmask 版就是這樣寫的,不需要成員變數或參考參數。
第 5 題10 分
為什麼第 0 列放 c 和放 n − 1 − c 的解數一定一樣?
解答與說明 · ANSWER▾
左右翻轉把每個合法盤面變成另一個合法盤面,而且第 0 列的欄 c 會變成 n − 1 − c。

翻轉後同欄還是同欄,「/」斜線變成「\」、「\」變成「/」,同一條斜線上的兩個皇后翻過去還在同一條斜線上 —— 所以不衝突的翻過去也不衝突。這是一一對應,兩邊個數相等。n = 4 的小計 0 / 1 / 1 / 0 就是例子。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 n = 4 · ans 什麼時候變:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

插樁實跑。ans 只在 dfs(4) 被改,其他 15 次 dfs 呼叫都沒碰它。

// 第一次 ans += 1 dfs(0) 放 (0,0) → … 兩條路都在 r2、r3 死掉 ans = 0 dfs(0) 放 (0,1) 佔 col[1]、diag1[1]、diag2[2] dfs(1) c0 ／、c1 欄、c2 ＼ → 放 (1,3) dfs(2) 放 (2,0) dfs(3) c0 欄、c1 欄 → 放 (3,2) dfs(4) r == n → ans += 1 ans = 1
// 第二次,然後收尾 dfs(0) 放 (0,2) → (1,0) → (2,3) → (3,1) dfs(4) r == n → ans += 1 ans = 2 dfs(0) 放 (0,3) → (1,0)→(2,2) 死、(1,1) 死 ans = 2 // OUTPUT: return ans → 2
兩次 +1 對應兩條走到 r == n 的路:[1,3,0,2] 和 [2,0,3,1],剛好互為左右鏡像。 (0,0) 和 (0,3) 的小計也一樣都是 0 —— 鏡像對稱在每一欄都成立,不只對有解的欄。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
題目改成「回傳第一個找到的解」或「判斷有沒有解」。回溯要怎麼提早停?
解答與說明 · ANSWER▾
讓 dfs 回傳 bool:base case 回 true;遞迴回來是 true 就直接往上 return true,不要再試下一欄。

要回傳盤面的話,在 return true 之前先不要撤銷(或在 base case 把目前的欄位記下來)。這是 79 · Word Search 那種「找到就停」的寫法;計數和列舉則必須把整棵樹走完。
第 8 題13 分
面試官說:n 最大 9,你直接打表就好。你怎麼回應?
解答與說明 · ANSWER▾
可以說打表在這個限制下是合法的 O(1),但表本身要靠一支正確的回溯產生,我會先寫那支程式。

然後把討論帶到可延伸的部分:n 變大時 bitmask 和鏡像能省多少(n = 12:73 ms → 4.2 ms)。面試官想看的是你能不能寫出搜尋、能不能講出剪枝。
第 9 題14 分
同樣「只數不存」的想法,還能用在這一章哪些題目?
解答與說明 · ANSWER▾
任何「回傳有幾種」而不是「列出全部」的題目:base case 改成 +1,省掉複製路徑。

例如把 78 · Subsets、46 · Permutations 改問個數,也是同一招。不過很多計數題的子問題會重複出現(例如只跟「剩多少」有關),那時應該改用 DP 加記憶化,而不是回溯一條一條數 —— N-Queens 的狀態包含整個旗標組合,幾乎不重複,所以回溯是對的工具。
