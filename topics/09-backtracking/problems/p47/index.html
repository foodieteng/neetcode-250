QUESTION

nums 可能有重複的值,回傳所有不重複的排列,順序不限。
1 ≤ n ≤ 8,-10 ≤ nums[i] ≤ 10。

範例:[1,1,2] → [[1,1,2],[1,2,1],[2,1,1]](3 個,不是 3! = 6 個);[1,2,3] → 6 個。

就是 46 加一行去重:排序後,if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;。 我的第一版這行寫成 break,[1,1,2] 少了 [2,1,1]。這張卡的重點就是 continue 和 break 差在哪。

核心策略 · 三步驟// THE SHAPE

  1. 排序:相同的值排在一起。
  2. 46 的骨架:每一格從 0 挑,used[i] 就 continue;填滿就收。
  3. 同層去重:nums[i] == nums[i-1] 且 !used[i-1] → continue(相同的值要照順序用,前一個還沒用就不能先用這一個)。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · !used[i-1] 為什麼代表「同一層」

排列的迴圈每層都從 0 開始,沒有 s 可以分辨同一層,只能看 used。 nums[i-1] 和 nums[i] 同值,而 used[i-1] 是 false:代表 1₁ 不在目前的路徑上 —— 它是這一層剛試完、已經還原的兄弟。 這時再用 1₂ 會長出和 1₁ 一樣的子樹,所以跳過。 相同的值等於被強迫「照 index 順序用」:1₁ 沒用之前,1₂ 不能先用。

LEMMA 2 · 我的 break 為什麼在沒有重複值時都對

沒有重複值時,去重那一行永遠不會成立,break 根本不會執行,就是 46。實測 n = 1~6 全部不同的陣列 6 / 6 都對,[1,2,3] 也對。 要有重複值、而且重複值後面還有別的值,才會出錯:[1,1]、[1,1,1] 也剛好對;[2,2,1,1] 只得到 3 個(正解 6),[1,1,2,2,3] 只有 8 個(正解 30)。 窮舉 1,092 組錯 946 組,最小反例 [2,1,1](排序後就是 [1,1,2])。

一句洞察// INSIGHT

continue 跳這一個,break 跳後面全部;只有「後面一定也不行」才能 break。 去重只說「這一個和前一個同值」,後面可能是別的值 → 一定用 continue。
