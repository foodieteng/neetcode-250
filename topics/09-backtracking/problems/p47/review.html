範例 Trace// 根節點的迴圈 · break vs continue

[1,1,2],只看根節點那一圈(i = 0、1、2),實跑結果。

// break(我的) i = 0 1₁:放 → 子樹收 [1,1,2]、[1,2,1] → 還原 i = 1 1₂:同值、1₁ 沒在路上 → break ← 迴圈結束 i = 2 2 :沒被試到 // OUTPUT: 2 個
// continue(修正) i = 0 1₁:放 → 子樹收 [1,1,2]、[1,2,1] → 還原 i = 1 1₂:同值、1₁ 沒在路上 → continue i = 2 2 :放 → 子樹收 [2,1,1] // OUTPUT: 3 個
break 和 continue 只在「被跳過的 i 後面還有東西」時才有差。 這裡 1₂ 後面還有一個不同的值 2,所以差了一整棵子樹。

// ANSWERS
A1. 39 的條件對後面的 i 一定也成立;這題的條件不會。

39 排序後 c[i] ≤ c[i+1],sum + c[i] 已經超過,後面只會更大 → 後面全部不行,break 安全。 這題 nums[i] == nums[i-1] 只描述「這一個」,後面的 nums[i+1] 可能是不同的值 → break 會把能放的數一起丟掉。
A2. used[i-1] 是 false 代表前一個同值的數不在目前的路徑上 —— 它是這一層剛試完、已經還原的兄弟。

排列每層迴圈都從 0 開始,沒有 s,只能用 used 分辨。如果 used[i-1] 是 true,代表 1₁ 是上一層放的(例如 [1₁] 底下要放 1₂),那是同一個排列裡的兩個 1,不能跳。
A3. 連「上一層放了 1₁、這一層要放 1₂」也被擋掉,兩個相同的值永遠不能同時出現。

實測 [1,1] → [],1,092 組錯 1,077。和 40 / 90 的 i > 0 是同一種錯:擋了兄弟,也擋了小孩。
A4. 沒有重複值的輸入(break 不會執行),和只有一種值的輸入(break 之後也沒有別的值可試)。

實測 n = 1~6 全部不同 6 / 6 對;[1,1]、[1,1,1] 也對。要「重複值後面還有不同的值」才會錯:[1,1,2]、[2,2,1,1](3 vs 6)、[1,1,2,2,3](8 vs 30)。
A5. used[i-1] 版本規定「相同的值要倒過來用」;走到 1₁ 已用、1₂ 還沒用的節點時,這個節點整個是死路,break 掉不會漏東西。

在那種節點,1₂ 之後每一層都會被跳過,永遠放不進去,路徑不可能填滿 —— 所以後面的 i 試了也沒用,break 剛好安全(實測 0 錯)。 代價是它會先走進死路才發現:[1,1,2] 要 12 次呼叫(其中 3 個死路節點),[1,1,2,2,3,3,4,4] 要 16,201 次,!used[i-1] 版只要 7,365 次。
A-App 1. 問:「這個 i 被跳過的理由,對 i + 1、i + 2 … 是不是一定也成立?」是 → break;不確定 → continue。

sum 超過(排序後)是;used[i] 不是(後面的數可能沒用);同值去重不是(後面可能是別的值)。拿不準的時候 continue 一定對,只是慢一點。
A-App 2. 可以:每一層開一個 unordered_set<int>,這一層放過的值就跳過。這樣連排序都不用。

排列每一格是「從所有沒用過的數挑一個」,同一格不放兩次同樣的值,就不會產生重複的排列(和 40 複習頁 App 3 不同:組合要靠排序固定順序,排列不用)。 實測不排序、隨機 2 萬組 0 錯;缺點是每一層多一個 set。
A-App 3. n! 除以每個值出現次數的階乘:n! / (c₁! · c₂! · …)。

[1,1,2]:3! / 2! = 3。[1,1,2,2,3,3,4,4]:8! / (2!)⁴ = 2,520,和實跑的答案數一致;隨機 2 萬組也全部一致。
