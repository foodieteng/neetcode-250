範例 Trace// [1,2,3,4,5], k = 2

// 往下遞迴 第 1 層 head = 1 → 數長度 n = 5 ≥ 2 （走了 5 步) 翻 [1,2] → 1 → ∅,2 → 1 prev = 2（新段頭) curr = 3（下一組) head = 1（新段尾) 呼叫 reverseKGroup(3, 2) … 第 2 層 head = 3 → 數長度 n = 3 ≥ 2 （又走了 3 步 —— 累計 8) 翻 [3,4] → 3 → ∅,4 → 3 prev = 4 curr = 5 head = 3 呼叫 reverseKGroup(5, 2) … 第 3 層 head = 5 → 數長度 n = 1 < 2 （又走了 1 步 —— 累計 9) return 5（原封不動)
// 回捲 回到第 2 層 head(3)->next = 5 → 4 → 3 → 5 return prev = 4 回到第 1 層 head(1)->next = 4 → 2 → 1 → 4 → 3 → 5 return prev = 2 ← 這就是最終的頭 結果 [2, 1, 4, 3, 5] ✓ // 兩層的接線形狀完全一樣 —— 那個「上一組的段尾」由呼叫堆疊自動保存

應用題// APPLICATION

App 1. 這題的 n 上限是 5000。如果上限是 10⁵ 呢?請把原碼的成長曲線量出來,並確認它真的是二次的。
App 2. 把遞迴改成迭代,需要多寫什麼?那個「多寫的東西」對應到遞迴版的哪一部分?
App 3. 如果題目改成「連不足 k 個的尾巴也要翻」,要怎麼改?
// ANSWERS
A1. 因為反轉會讓一段的頭尾對調 —— 進來時是頭的 head,翻完之後就是尾。

進入這一層時,head 是這一組的第一個節點。翻完之後,它排到最後。
而「這一組的最後一個」該接的,正是後面那一整段的處理結果 —— 也就是遞迴的回傳值。

同時 prev 停在原本的最後一個 = 新的段頭,所以 return prev;。

兩個端點都是反轉迴圈的副產品,一個都不用另外找 —— 和 92 的 A1 是同一件事。

實測拿掉那一行(只 return prev):窮舉 77 組錯 45 組,最小反例 n=2, k=1: [1,2] → [1] —— 後面整段全部掉了,因為沒人把它接回來。
A2. 因為 curr 是「下一組的開頭」,而 prev 是「這一組的新段頭」—— 傳 prev 等於叫遞迴再處理一次剛翻完的東西。

反轉迴圈跑完時:
· prev = 這一組翻好之後的頭(還在這一組裡);
· curr = 第 k+1 個節點,也就是下一組的開頭。

傳 prev 的話,遞迴會處理同一批節點,而它回傳的結果又被接回這一組 —— 串列被接成了環。

實測:窮舉 77 組錯 55 組,而且最小反例是 n=1, k=1 —— 回傳的串列走 200 步還走不完(測試裡加了守衛才沒有真的跑不停)。

這不是「答案錯」,是「程式不會停」 —— 而它在最簡單的輸入上就會發生。 四個變體裡這個最危險:另外三個會給你一個錯的答案,這個直接讓程式掛住。
A3. O(n² / k) —— 因為每一層都重新數一次整條剩餘串列的長度。

第 1 層走 n 步、第 2 層走 n−k 步、第 3 層走 n−2k 步…… 加起來:
n + (n-k) + (n-2k) + ... + k = k · (1 + 2 + ... + n/k) ≈ n² / 2k

實測「數長度」那個迴圈實際跑了幾次:
n=1000 k= 1: 500500 （n²/2k = 500000) n=5000 k= 1: 12502500 （n²/2k = 12500000) n=5000 k=500: 27500 （n²/2k = 25000) // 每一組都貼著理論值 —— 這不是估的,是數出來的

而它問的問題不需要總長度:「還夠不夠 k 個?」只要試著走 k 步 —— 走得到就夠。
把 while (tail) 換成 for (i < k),複雜度立刻變 O(n)。

但要說清楚:這在 LeetCode 上會過,n ≤ 5000 時最壞約 16 ms。 是題目上限剛好夠小救了它,不是演算法沒問題。
A4. 錯 17 / 77 組 —— 而且全部落在「剩下的節點剛好等於 k 個」這一類。

n == k 時,剛好還有一整組,應該要翻。但 n <= k 會把它當成 base case 原樣返回。

最小反例:
n = 2, k = 2 [1,2] → [1,2] // 正解 [2,1]

22% 的失敗率,而它需要的觸發條件很精確:某一層的剩餘長度恰好是 k 的倍數收尾。

四個變體裡它的失敗率最低,也最容易漏測 —— 拿 [1,2,3,4,5], k=2 這種官方範例測是測不出來的(剩 1 個,不足 k), 要剛好用 n 是 k 的倍數的輸入才會現形。
A5. 不會 —— 用掉 313 KB,只佔預設堆疊的 3.8%。但這同樣是題目上限救的。

遞迴深度是 ⌊n/k⌋ + 1,k=1 時就等於 n。題目上限 n=5000 ⇒ 最深 5001 層。

實測每層 frame 大小(比較深度 100 與 200 的堆疊指標):
深度 100 → 用掉 6416 bytes 深度 200 → 用掉 12816 bytes ⇒ 每層 64.0 bytes n=5000, k=1 → 堆疊最深用掉 320080 bytes = 313 KB 系統預設上限 = 8176 KB（3.8%)

崩潰門檻(把堆疊上限調成 1024 KB 之後二分搜):
實測活得下來的最大 n ≈ 16234 理論值 1048576 / 64 = 16384 ⇒ 誤差 0.9%

依同樣比例推算,預設 8176 KB 下的門檻約 13 萬層。

對照 206 的遞迴解:每層 48 bytes、門檻約 17 萬層。 兩題都是「n 上限五千,所以沒事」 —— 而迭代版根本沒有這個問題,它的空間是 O(1)。
App 1. 量出來確實是二次的:n 每加倍,耗時變 4 倍。而 n = 10⁵ 會直接超時。

實測(k = 1 最壞情形,每組取三次的中位數):
n 原碼 迭代版 比上一列 ────────────────────────────────────────────── 5000 16.10 ms 0.014 ms — 10000 48.34 ms 0.029 ms 3.00× 20000 195.43 ms 0.055 ms 4.04× 40000 782.29 ms 0.118 ms 4.00× // 4.04 與 4.00 —— 教科書等級的 O(n²) 驗證

(5000 → 10000 那格只有 3.00 倍,是因為小規模時快取效應還壓得住;規模拉大之後就完全貼合了。)

外推到 n = 10⁵:782 ms × (100000/40000)² ≈ 4.9 秒 —— 穩穩超時。
而迭代版在 n=40000 只要 0.118 ms,外推到 10⁵ 也不到 0.3 ms。

這就是為什麼「會過」和「正確」是兩件不同的事: 同一份程式碼,題目上限改一個數字就從 AC 變成 TLE,而演算法本身從頭到尾沒變過。
App 2. 要多寫兩樣東西:一個 dummy,和一個 tail 指標 —— 而 tail 就是「手動版的呼叫堆疊」。

遞迴版每一層都有自己的區域變數 head,那個「這一組的段尾」由呼叫堆疊自動保存,回捲時自然拿得回來。
迭代版沒有堆疊可以靠,所以必須自己拿一個變數記住它:
ListNode* newTail = tail->next; // 舊段頭 = 這一組的新段尾,先存住 tail->next->next = next; // 接尾 ← 和 92 完全同一行 tail->next = prev; // 接頭 ← 和 92 完全同一行 tail = newTail; // 下一組從這裡繼續

那個 newTail 就是 92 的 App 1 那一招 —— 一個欄位同時是「資料來源」和「寫入目標」時,先存進區域變數。

另外還要多一件事:dummy。因為第一組翻完之後,整條串列的頭會變 —— 遞迴版靠回傳值處理,迭代版就需要一個「頭的前驅」。和 19、92 同一個理由。

換來的是:O(1) 空間、沒有堆疊深度上限。實測 200104 組(窮舉 + 隨機)不一致 0。
App 3. 只要把「檢查夠不夠 k 個」換成「數出這一組實際有幾個」,然後翻那個數字。

原題的邏輯是「不足 k 個就不翻」,所以要先確認有 k 個。改版的邏輯是「有幾個翻幾個」:
while (tail->next) { // 不是「夠不夠 k 個」,而是「這一組實際有幾個」 int cnt = 0; for (ListNode* p = tail->next; p && cnt < k; p = p->next) cnt++; if (cnt == 0) break; // 翻 cnt 圈,而不是 k 圈 ListNode *prev = nullptr, *curr = tail->next, *next = nullptr; for (int i = 0; i < cnt; i++) { next = curr->next; curr->next = prev; prev = curr; curr = next; } // 接線完全不用改 ListNode* newTail = tail->next; tail->next->next = next; tail->next = prev; tail = newTail; }

實測:窮舉 n=0..12 × k=1..n+2 + 隨機 20 萬組共 200104 組,不一致 0。

兩者的差別:
[1,2,3,4,5] k=2: 原題 [2,1,4,3,5] 改版 [2,1,4,3,5] （尾巴只有 1 個,翻了一樣) [1,2,3,4,5] k=3: 原題 [3,2,1,4,5] 改版 [3,2,1,5,4] ← 這裡才看得出差別

值得注意的是:接線那三行一個字都沒改 —— 因為它們處理的是「一段翻完之後怎麼接回去」,而那和「這段有多長」無關。 這正是 92 那兩行值得練熟的理由:206 → 92 → 25,核心一直是同一組指標動作,變的只有邊界。
