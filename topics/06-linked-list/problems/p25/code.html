完整實作// THE CODE

原碼一字未改,只補上註解。答案完全正確 —— 窮舉 n = 0..12 × k = 1..n+2 共 104 組,加上隨機 20 萬組,不一致 0。 而且沒有任何 new,不會洩漏。

p25.cpp C++17 
class Solution {
public:
    ListNode* reverseKGroup(ListNode* head, int k) {
        // ① 數長度 —— 正確,但這裡走完了「整條」剩餘串列
        int n = 0;
        ListNode *tail = head;
        while (tail) {
            tail = tail->next;
            n++;
        }

        // base case:不足 k 個就原樣返回 —— 正好就是題目要的「尾巴不動」
        if (n < k) return head;

        // ② 翻 k 圈 —— 和 206 / 92 一字不差
        ListNode *prev = nullptr, *curr = head, *next = nullptr;
        for (int i = 0; i < k; i++) {
            next = curr->next;
            curr->next = prev;
            prev = curr;
            curr = next;
        }

        // ③ head 翻完之後是「這一組的段尾」,接上後面那一整段
        head->next = reverseKGroup(curr, k);

        return prev;   // prev 是這一組的新段頭
    }
};

中間那段 for 迴圈,剪下來貼到 206 或 92 都能跑。 新東西只有 ① 的判斷與 ③ 的一行接線 —— 而接線之所以只需要一行(92 要兩行),是因為另一條由遞迴的回傳值處理掉了。

第 ① 步藏了一個二次方// THE HIDDEN O(n²)

while (tail) { tail = tail->next; n++; } 走完整條剩餘串列。 而每一層遞迴都會再走一次:第 1 層走 n 步、第 2 層走 n−k 步、第 3 層走 n−2k 步…

// 總步數 = n + (n−k) + (n−2k) + … ≈ n² / 2k n + (n-k) + (n-2k) + ... + k = k · (1 + 2 + ... + n/k) ≈ n² / 2k // 實測「數長度」那個迴圈實際跑了幾次 n=1000 k= 1: 500500 次 （n²/2k = 500000) n=2000 k= 1: 2001000 次 （n²/2k = 2000000) n=5000 k= 1: 12502500 次 （n²/2k = 12500000) n=5000 k= 2: 6252500 次 （n²/2k = 6250000) n=5000 k=500: 27500 次 （n²/2k = 25000) // 每一組都貼著理論值 —— 這不是估計,是實際數出來的
而它問的問題,其實不需要知道總長度。 「還夠不夠 k 個?」只需要試著走 k 步 —— 走得到就夠,走不到就不夠。把 while 換成 for (i < k),複雜度立刻從 O(n²/k) 變成 O(n)。

四個變體,實測誰會壞// ADVERSARIAL VARIANTS

每一處改成「看起來也對」的寫法,拿窮舉 n = 0..10 × k = 1..n+2 共 77 組去跑 (最小反例即由此搜出):

最危險的那個:遞迴傳 prev

prev 是這一組的新段頭,curr 才是下一組的開頭。 傳錯的話,遞迴會再處理一次剛翻完的這一組 —— 而它接回來的結果又指向自己,把串列接成了環。

實測 n=1, k=1:回傳的串列走 200 步還走不完(測試裡加了守衛才沒有真的無限跑)。 這不是「答案錯」,是「程式不會停」 —— 而它在 k=1 這種最簡單的輸入上就會發生。

注意 n <= k 那個變體只錯 17 組(22%) —— 它只在「剩下的節點剛好等於 k 個」時出錯,而那正是隨手測最容易跳過的情形。 失敗率低的 bug,通常比全錯的 bug 更難發現。

遞迴深度會不會爆堆疊// STACK DEPTH

遞迴深度是 ⌊n/k⌋ + 1 —— k = 1 時就等於 n。 題目上限 n = 5000,所以最深 5001 層。

// 實測每層 frame 大小(比較深度 100 與 200 的堆疊指標) 深度 100 時用掉 6416 bytes 深度 200 時用掉 12816 bytes → 每層 64.0 bytes // 題目上限的實際用量 n = 5000, k = 1 → 堆疊最深用掉 320080 bytes = 313 KB 系統預設上限 = 8176 KB ⇒ 只用了 3.8%,安全 // 崩潰門檻(把堆疊上限調成 1024 KB,二分搜) 實測活得下來的最大 n ≈ 16234 理論值 1048576 / 64 = 16384 ⇒ 誤差 0.9%（差的那點是主程式與建串列本身佔掉的)
所以這題的遞迴是安全的 —— 但同樣是「題目上限救了它」。 對照 206 那題的遞迴解:每層 48 bytes、崩潰門檻約 17 萬層, 而這題每層 64 bytes —— 依同樣比例推算,預設 8176 KB 堆疊下門檻約 13 萬層。 兩題都是「n 上限五千,所以沒事」。 迭代版沒有這個顧慮 —— 它的空間是 O(1)。

兩種修法// THE FIXES

修法 A · 保留遞迴,只把「數長度」改成「數 k 步」 —— 只動一個迴圈,時間就從 O(n²/k) 變成 O(n)。

p25_fix_recursive.cpp O(n) 時間 · O(n/k) 堆疊 
ListNode* reverseKGroup(ListNode* head, int k) {
    // 只走 k 步:走得到就夠,走不到就不夠。不必知道總長度
    ListNode* t = head;
    for (int i = 0; i < k; i++) {
        if (!t) return head;       // 不足 k 個 → 原樣返回
        t = t->next;
    }

    // 以下完全沒變
    ListNode *prev = nullptr, *curr = head, *next = nullptr;
    for (int i = 0; i < k; i++) {
        next = curr->next; curr->next = prev; prev = curr; curr = next;
    }

    head->next = reverseKGroup(curr, k);
    return prev;
}

修法 B · 改成迭代 —— 用一個 tail 指標取代呼叫堆疊,順便把空間降到 O(1)。 那兩行接線和 92 一字不差。

p25_fix_iterative.cpp O(n) 時間 · O(1) 空間 
ListNode* reverseKGroup(ListNode* head, int k) {
    ListNode dummy(0, head);
    ListNode* tail = &dummy;       // 上一組的段尾 —— 手動版的「呼叫堆疊」

    while (true) {
        // 先確認還有 k 個
        ListNode* chk = tail;
        for (int i = 0; i < k && chk; i++) chk = chk->next;
        if (!chk) break;                // 不足 k 個 → 整組保持原樣,收工

        ListNode *prev = nullptr, *curr = tail->next, *next = nullptr;
        for (int i = 0; i < k; i++) {
            next = curr->next; curr->next = prev; prev = curr; curr = next;
        }

        ListNode* newTail = tail->next;   // 舊段頭 = 這一組的新段尾,先存住
        tail->next->next = next;          // ← 和 92 完全同一行(接尾)
        tail->next = prev;                // ← 和 92 完全同一行(接頭)
        tail = newTail;                    // 下一組從這裡繼續
    }

    return dummy.next;
}
// 兩種修法的實測(窮舉 n=0..12 × k=1..n+2 + 隨機 20 萬組,共 200104 組) 只數 k 步的遞迴版：不一致 0 迭代版： 不一致 0
newTail 那一行就是 92 的 App 1 那一招 —— 一個欄位同時是「資料來源」和「寫入目標」時,先存進區域變數。 而它也正是遞迴版不需要的東西: 遞迴的每一層都有自己的 head,那個「上一組的段尾」由呼叫堆疊自動保存,不必手動傳遞。
