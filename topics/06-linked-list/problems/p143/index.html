題目簡介// THE QUESTION

QUESTION

把 L₀ → L₁ → … → Lₙ₋₁ → Lₙ 重排成 L₀ → Lₙ → L₁ → Lₙ₋₁ → L₂ → Lₙ₋₂ → … —— 頭一個、尾一個、頭二個、尾二個…

不准改節點的值,只能改節點之間的連接。節點數 1 ~ 5×10⁴。

這題是 06 章前三題的組合技。困難點只有一個:目標順序需要從尾巴往回走, 而單向串列只能往後走,拿不到「尾巴的前一個」。

解法是把問題拆成三個已經會的小題: 141 的快慢指標找中點 → 206 的迭代翻轉把後半反過來 → 21 的 dummy + tail 交錯接起來。 三個骨架幾乎一字不改就能貼過來。
2

為什麼要翻轉後半// WHY THIS

A 每次都從頭走去找目前的尾巴 O(n²)
拿一次尾巴要走 O(n),要拿 n/2 次 ⇒ O(n²)。n = 5×10⁴ 時是 2.5×10⁹ 級,超時。
× REJECT · TLE
B 把所有節點指標倒進 vector,再雙指標接線 O(n) 時間 · O(n) 空間
完全正確,而且好寫:vector<ListNode*> 存指標(不是值,所以沒違反題目), 然後 i 從頭、j 從尾往中間接。代價是 O(n) 額外空間。
△ 可行 · 但吃空間
ADOPT
C 找中點 → 翻轉後半 → 交錯合併 O(n) 時間 · O(1) 空間
翻轉後半就等於「把倒著走變成正著走」 —— 之後只要兩條各往前推,交錯接起來即可。 三個階段各 O(n),加起來還是 O(n),而且只用幾個指標。
● ADOPT · O(1) 空間
「翻轉」在鏈結串列題裡的真正用途,就是把「往回走」變成「往前走」。 同樣的招式在 234 回文判斷 ↗、 445 正序相加 ↗ 都會再出現。

核心策略 · 三階段// STRATEGY

  1. 找中點(141 的骨架):while (fast && fast->next),slow 一步、fast 兩步。
  2. 翻轉後半 + 切斷(206 的骨架):l2 = reverseList(slow->next); 然後 slow->next = nullptr; —— 切斷那行少不得,見第 5 節。
  3. 交錯合併(21 的骨架):每圈先接 l1 一個、再接 l2 一個,直到兩條都空。
這種「把大題拆成三個已知小題」的解法,面試時要先把三步說出來再動手寫 —— 一次寫完三十行再解釋,面試官很難跟。

三件不明顯但成立的事// THREE LEMMAS

LEMMA 1 · 前半永遠比後半長

這個切法(兩者都從 head 起跑、while (fast && fast->next))得到 |l1| = ⌊n/2⌋ + 1、|l2| = n − |l1|,所以 |l1| − |l2| 是 1(n 奇數)或 2(n 偶數)。

實測:n = 1..8 分別是 (1,0) (2,0) (2,1) (3,1) (3,2) (4,2) (4,3) (5,3) —— |l1| > |l2| 恆成立。這一點是下一個 LEMMA 的前提。

LEMMA 2 · merge 迴圈裡不必寫 tail->next = nullptr

合併迴圈從頭到尾沒有把結果收尾成 nullptr。為什麼結果不會多出一截?

由 LEMMA 1,|l1| > |l2|,所以最後接上的一定是 l1 的尾巴。 而 l1 的尾巴就是 slow,它的 next 早在階段 2 就被 slow->next = nullptr 設好了。

所以那行「切斷」其實做了兩件事:防止成環,以及順便把結果收尾。 實測 n = 1..2000 全部長度,未終結 / 成環 0 次。

LEMMA 3 · 那個 dummy 在這題是多餘的

21 和 2 需要 dummy,是因為「結果的頭是誰」事先不知道。 但這題知道 —— 結果的第一個節點必定是 head(L₀),而且函式回傳 void、就地修改。

所以可以直接 tail = head; l1 = head->next; 開始合併,連 dummy 都不需要。 實測:無 dummy 版跑 n = 1..400 全部正確(錯 0)。而現在這個 new ListNode() 每次呼叫還會漏一個節點 —— 見程式碼頁。

三個階段各自來自哪一題// REUSE MAP

階段來自差別
① 找中點 141 Linked List Cycle 同樣的 while (fast && fast->next),只是不比 slow == fast,而是用 slow 最後停的位置
② 翻轉後半 206 Reverse Linked List 迭代版一字不改。這裡不能用遞迴版 —— n 到 5×10⁴,遞迴會吃 2.4 MB 堆疊
③ 交錯合併 21 Merge Two Sorted Lists 骨架相同,但不比大小 —— 固定「一邊一個」輪流接
階段 ② 用迭代版而非遞迴版是刻意的:206 那題量過, 遞迴每層 48 bytes,而這題 n 上限是 5×10⁴ ⇒ 約 2.4 MB 堆疊。 雖然還沒到 8 MB 的崩潰線,但沒有理由為此冒險。

一句洞察// INSIGHT

單向串列不能往回走,所以「需要倒著走」的題目,一律先想「能不能把那一段翻過來」。 翻轉的成本是 O(n) 一次,但它把後續的每一步都變成 O(1) —— 這比「每次都回頭找」的 O(n²) 划算太多。
