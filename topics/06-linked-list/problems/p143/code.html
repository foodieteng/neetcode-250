class Solution {
public:
    void reorderList(ListNode* head) {
        // ── 階段 1:快慢指標找中點(141 的骨架)──
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
        }

        // ── 階段 2:翻轉後半,然後切斷(206 的骨架)──
        ListNode* l2 = reverseList(slow->next);
        slow->next = nullptr;   // 少了這行 → 階段 3 會接成環

        // ── 階段 3:交錯合併(21 的骨架,但不比大小)──
        // 結果的頭必定是 head,所以不需要 dummy
        ListNode* l1 = head->next;
        ListNode* tail = head;

        while (l1 || l2) {
            if (l2) {
                tail->next = l2;
                l2 = l2->next;
                tail = tail->next;
            }

            if (l1) {
                tail->next = l1;
                l1 = l1->next;
                tail = tail->next;
            }
        }
    }

private:
    // 206 的迭代版,一字不改。不能用遞迴版:n 到 5×10^4
    ListNode* reverseList(ListNode* head) {
        ListNode *prev = nullptr, *curr = head, *next = nullptr;

        while (curr) {
            next = curr->next;
            curr->next = prev;
            prev = curr;
            curr = next;
        }

        return prev;
    }
};

slow->next = nullptr 做了兩件事// THE CUT

① 防止成環

翻轉後半之後,前半的尾巴(slow)還指著後半的舊頭 —— 而那個舊頭現在是 l2 的尾巴。 合併時把 l2 接進來,就形成了一個回路。

實測:拿掉這一行,n = 1..400 有 398 種長度會成環;最小反例 n = 3 走出 1,3,2,3,2,3,2… 永遠走不完。

② 順便把結果收尾

注意合併迴圈裡從頭到尾沒有寫過 tail->next = nullptr。結果為什麼不會多出一截?

因為 |l1| > |l2| 恆成立(下表),所以最後接上的一定是 l1 的尾巴 —— 而 l1 的尾巴就是 slow,它的 next 早在這一行被設成 nullptr 了。

一行擋掉兩種災難:成環,以及結果沒有終點。實測 n = 1..2000 全部長度,未終結 / 成環 0 次。

// 兩半的長度(實測)—— |l1| 永遠比 |l2| 多 1 或 2 n=1 slow 停在第 1 個 |l1|=1 |l2|=0 n=2 slow 停在第 2 個 |l1|=2 |l2|=0 n=3 slow 停在第 2 個 |l1|=2 |l2|=1 n=4 slow 停在第 3 個 |l1|=3 |l2|=1 n=5 slow 停在第 3 個 |l1|=3 |l2|=2 n=6 slow 停在第 4 個 |l1|=4 |l2|=2 n=7 slow 停在第 4 個 |l1|=4 |l2|=3 n=8 slow 停在第 5 個 |l1|=5 |l2|=3 |l1| = ⌊n/2⌋ + 1,差距 = 1(n 奇數)或 2(n 偶數) // 所以 merge 的最後一個節點必定來自 l1 —— 這是「不必收尾」的證明

原碼那個 dummy 是多餘的// AND IT LEAKS

原本寫的是:

// 原碼 ListNode *dummy = new ListNode(); ListNode *tail = dummy; while (l1 || l2) { ... } // 函式回傳 void,dummy 從此無人聞問 // 建出來、用完、沒有 delete,也沒有回傳

21 和 2 需要 dummy,是因為「結果的頭是誰」事先不知道。 但這題知道 —— L₀ 就是 head,而且函式回傳 void、就地修改, 根本沒有「要回傳哪個頭」的問題。

// 實測(覆寫 ListNode::operator new / delete 精確計數) [原碼:ListNode* dummy = new ListNode();] 建 5 個節點的串列 → 配置 5 個 reorderList 又配置 1 個 ← 就是 dummy 把整條串列 delete 之後:new = 6, delete = 5 ⇒ 洩漏 1 個節點 [累積] 呼叫 100000 次 → 洩漏 100000 個節點 = 1562 KB [拿掉 dummy 的版本] reorderList 配置 0 個 n = 1..400 全部長度,結果與參考解不一致 0 // 這是 06 章第三次遇到同一個 dummy 洩漏(21、2、143)

邊界與陷阱// PITFALLS

這題的結構只由長度決定(值不影響邏輯),所以窮舉 n = 1..400 就等於窮舉全部結構。 走訪都加了步數上限,否則第一個成環的變體就會把測試程式卡死。

陷阱後果實測
忘了 slow->next = nullptr 成環 —— 前半的尾還指著後半的舊頭 錯 398/400
n=3 → 1,3,2,3,2,3… 走不完
翻轉 slow 而非 slow->next 把中點也捲進去翻,前半被反向牽動 → 成環 錯 400/400(全錯)
n=1 → 1,1,1,1…
合併時先接 l2 再接 l1(有 dummy 的版本) 第一個變成 Lₙ 而不是 L₀,整體順序錯位 錯 398/400
n=3 → [1,2](正解 [1,3,2])
階段 2 用 206 的遞迴版 答案對,但 n = 5×10⁴ 時吃掉約 2.4 MB 堆疊(每層 48 bytes) 還沒到 8 MB 崩潰線
但沒有理由冒這個險
head == nullptr slow->next 解參考空指標(slow 也是 nullptr) SEGV(UBSan 實錘)
題目保證 n≥1,所以實務上不會發生
拿掉 dummy,直接 tail = head 這樣也對,而且更好 —— 結果的頭本來就確定是 head 錯 0/400
而且不再洩漏節點

// PHASE 1: 這個切法讓 slow 停在哪 slow = fast = head,while (fast && fast->next) n 奇數:fast 走到最後一個,slow 停在正中間 n 偶數:fast 走到 null,slow 停在「中間偏右」那一個 結果:|l1| = ⌊n/2⌋ + 1,|l2| = n − |l1| ⇒ |l1| − |l2| = 1(奇)或 2(偶)—— 前半永遠比較長 // 這個「永遠比較長」是後面兩件事的前提
// PHASE 2: 順序不能顛倒 —— 先翻轉,再切斷 l2 = reverseList(slow->next); ← 先翻,這時還需要 slow->next 找得到後半 slow->next = nullptr; ← 再切 若先切:slow->next 變成 null,reverseList(null) 回 null,後半整段失聯 // 這和 206 的「先存 next 再改指標」是同一種依賴關係
// PHASE 3: 為什麼不比大小(對比 21) 21 是「合併兩條有序串列」→ 每步要決定「該拿哪一條的」→ 比 val 143 是「交錯」→ 順序是固定的:l1、l2、l1、l2… → 不需要任何比較 所以兩個 if 是「輪流」而不是「二選一」—— 一圈裡兩個 if 都可能執行,這和 21 的 if/else 是不同的結構 // 骨架像,但語意不同:21 是二選一,143 是各來一個
// TERMINATION: 迴圈為什麼會停 每一圈至少消耗一個節點(l1 或 l2 前進) 兩條都是有限長且不成環(階段 2 已切斷) ⇒ 最多 max(|l1|, |l2|) 圈 // 前提是「已切斷」—— 少了那行,l2 走不完,迴圈就出不去
