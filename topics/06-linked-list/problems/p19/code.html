完整實作// THE CODE

演算法與原碼一字未改,只修了記憶體(dummy 放堆疊、被移除的節點 delete 掉)。

p19.cpp C++17 
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        // dummy 是「頭的前驅」—— n == sz 時要刪的就是頭
        ListNode dummy(0, head);
        ListNode *tail = &dummy, *curr = &dummy;

        // 拉開 n+1 格:多的那一格是為了讓 tail 停在「前一個」
        for (int i = 0; i < n + 1; ++i) {
            curr = curr->next;
        }

        // 同步前進,間距全程不變
        while (curr) {
            tail = tail->next;
            curr = curr->next;
        }

        // tail 正好停在要刪的節點的前一個
        ListNode* victim = tail->next;
        tail->next = victim->next;
        delete victim;            // 繞過去還不夠,它還佔著記憶體

        return dummy.next;
    }
};

整支只有三段:拉開間距、同步前進、繞過去。 而三段各對應一個容易寫錯的地方 —— n+1 的那個 +1、 while (curr) 而不是 while (curr->next)、以及 dummy。 下面的陷阱表把每一處的實測後果都列出來了。

正確性驗證// EXHAUSTIVE

這題的測資空間小到可以完全窮舉。sz ≤ 30、1 ≤ n ≤ sz, 而值不影響任何分支(只看位置)—— 所以合法輸入總共只有 1+2+…+30 = 465 種。跑完就是跑完了,不是抽樣。
// 窮舉全部 465 組合法輸入 sz = 1..30,n = 1..sz,值 = 1..sz 與參考解(直接算出「移除第 sz-n+1 個」後的序列)比對 不一致 0 官方範例: sz=5 n=2 → [1,2,3,5] ✓ sz=1 n=1 → [] ✓ ← 刪掉唯一的節點,回傳空串列 sz=2 n=1 → [1] ✓ sz=2 n=2 → [2] ✓ ← 刪頭 // sz=1 n=1 與 n=sz 是最容易漏測的兩個
