重點回顧// RECAP

面向要記住的那一句
核心技巧固定間距雙指標 —— 拉開之後鎖住,前面出界時後面自動到位
間距為什麼是 n+1要刪一個節點需要它的前驅;只要拿到它的話間距是 n(見 App 3)
dummy 為什麼必要n == sz 時要刪的是頭,而頭沒有前驅 —— dummy 補上那一格
迴圈條件while (curr),不是 while (curr->next)(差一步就刪錯一個)
不會越界n ≤ sz ⇒ curr 最遠剛好停在 nullptr,不會再取 ->next
兩處記憶體dummy 要放堆疊,被移除的節點要 delete —— 原碼各漏一個
「繞過去」≠「刪掉」改指標只是讓沒人指著它,記憶體還在
複雜度O(sz) 一趟、O(1) 空間;走兩趟也是 O(sz)
驗證測資空間可完全窮舉 —— 只有 465 種合法輸入,全跑,不一致 0

觀念題// CONCEPT Q&A

Q1. 為什麼間距是 n + 1 而不是 n?請說明「多的那一格」在買什麼。
Q2. dummy 在這題解決的是哪一種輸入?拿掉它會錯幾組、錯在哪裡?
Q3. curr 先走 n + 1 步 —— 會不會走出界?請用題目的約束證明。
Q4. 迴圈條件是 while (curr)。如果寫成 while (curr->next) 會怎樣?
Q5. tail->next = tail->next->next; 這一行把節點刪掉了嗎?

範例 Trace// sz=5, n=2 → 移除值 4

// SETUP 串列: dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null tail = curr = dummy 要移除的是「倒數第 2 個」= 值 4
// 拉開間距:curr 走 n+1 = 3 步 第 1 步 → 1 第 2 步 → 2 第 3 步 → 3 ⇒ tail 在 dummy、curr 在 3,間距 3 格
// 同步前進(間距全程不變) 第 1 次:tail = 1 curr = 4 第 2 次:tail = 2 curr = 5 第 3 次:tail = 3 curr = null ← while 條件不成立,跳出
// 移除 tail 停在 3,tail->next 正是要移除的 4 tail->next = tail->next->next ⇒ 3 直接接到 5 return dummy->next = [1, 2, 3, 5] // 一趟走完(這就是 follow-up 問的 one pass)

關鍵邊界的實測結果:

// 邊界(皆為實測) sz=1 n=1 → [] 刪掉唯一的節點;tail 就是 dummy,回傳 dummy.next = null sz=2 n=2 → [2] 刪頭 —— 這一組正是「沒有 dummy 就會壞」的那種 sz=2 n=1 → [1] 刪尾 sz=30 n=30 → 刪頭;curr 走 31 步剛好到 null(走最遠的情形) // sz=1 n=1 與 n=sz 是最容易漏測的兩個
這題可以「證明測完了」,不是抽樣。 sz ≤ 30、1 ≤ n ≤ sz,而值不影響任何分支(只看位置)—— 所以合法輸入總共只有 1+2+…+30 = 465 種。 全部跑過,不一致 0。

應用題// APPLICATION

App 1. 題目的 follow-up 問「能不能一趟」。那兩趟的版本長什麼樣、複雜度差多少?什麼時候該寫哪一個?
App 2. 如果拿掉「1 ≤ n ≤ sz」這個保證,n 可能大於串列長度。這份程式碼會怎樣?怎麼防護?
App 3. 改成「回傳倒數第 k 個節點」(不刪除)。間距要設多少?
// ANSWERS
A1. 多的那一格,買的是「前驅」。

推導:同步前進時間距完全不變,而迴圈在 curr == nullptr 時停 —— 可以把 nullptr 想成「尾巴後面那一格」。所以結束時 tail 距離那一格剛好等於間距。

間距 = n ⇒ tail 落在倒數第 n 個,也就是要刪的那個節點本身。但單向串列刪不掉自己 —— 要把一個節點從鏈上摘掉,你需要改它前面那個的 next。
間距 = n+1 ⇒ tail 落在倒數第 n+1 個 = 前驅 ✓

實測:少了那個 +1,全部 465 組合法輸入統統錯,最小反例 sz=1, n=1 回傳 [1](正解 [])。

反過來看更清楚:如果題目只是要「拿到」倒數第 n 個節點而不刪它,間距就該是 n。見 App 3 —— 那個對照最能說明這個 +1 到底在做什麼。
A2. 它解決的是「要刪的就是頭」,也就是 n == sz。

A1 說刪一個節點需要它的前驅。但當要刪的是第一個節點時,它沒有前驅 —— 整個推論就沒有落腳點了。

dummy 就是憑空補上那個不存在的前驅。有了它:
· 「刪頭」和「刪中間任何一個」變成完全同一段程式碼;
· 回傳 dummy->next 自動處理了「頭被換掉」——不必另外判斷。

實測:拿掉 dummy、兩個指標都從 head 出發,465 組錯 30 組 —— 而且剛好就是每個 sz 的 n == sz 那一組(sz = 1..30,一個 sz 一組)。

注意這個失敗率只有 6.5%,反而最危險 —— 它只在「刪頭」時出錯,而那正是隨手測幾筆最容易跳過的 case。三個陷阱裡,全錯的那個(+1)其實最安全,因為一測就發現。
A3. 不會 —— 而且是「剛好」不會,靠的正是題目那句 n ≤ sz。

數一下位置:dummy 加上 sz 個節點 = 共 sz + 1 個位置(索引 0 .. sz),再往後就是 nullptr(可以記成索引 sz + 1)。

curr 從索引 0 出發走 n + 1 步 → 停在索引 n + 1。
題目保證 1 ≤ n ≤ sz ⇒ n + 1 ≤ sz + 1。

所以最遠的情形(n == sz)剛好停在 nullptr 那一格 —— 迴圈到此為止,不會再對 nullptr 取 ->next。

實測:sz = 1..30 的 n = sz(走最遠)情形,curr 走完 sz+1 步之後正好是 nullptr —— 30 種全部如此。

但這個安全是「借來的」:它完全依賴 n ≤ sz。約束一旦拿掉就會 SEGV —— 見 App 2。
A4. 會少走一步,刪錯一個節點。

while (curr) 讓 curr 一路走到 nullptr,tail 停在倒數第 n+1 個 ✓
while (curr->next) 在 curr 是最後一個節點時就停了,少走一步 ⇒ tail 停在倒數第 n+2 個 ⇒ tail->next 是倒數第 n+1 個 ⇒ 刪錯一個(刪成了要刪的那個的前一個)。

實測:465 組錯 435 組(93.5%),最小反例 sz=2, n=1 回傳 [2](正解 [1])。

沒錯的那 30 組是哪些?正是 n == sz ——那時 tail 少走一步剛好還在 dummy 上,而 dummy->next 就是頭,答案碰巧對。又是「刪頭」那批,只是這次它們是唯一沒壞的。
A5. 沒有 —— 它只是「繞過去」,節點還在記憶體裡。

tail->next = tail->next->next; 做的事是:讓沒有人再指向那個節點。但那塊記憶體還是配置出去的狀態,只是變成了孤兒。

修法:先抓住它再刪。
ListNode* victim = tail->next;
tail->next = victim->next;
delete victim;

實測(覆寫 ListNode::operator new/delete 計數,sz=5、移除倒數第 2 個):原碼在函式內配置 1 個(dummy),把結果串列整條 delete 之後 new = 6、delete = 4 ⇒ 洩漏 2 個 = dummy(1) + 被移除的節點(1)。改成 ListNode dummy(0, head); 並 delete victim 之後,洩漏 0。累積:呼叫 10 萬次原碼漏 3125 KB。

LeetCode 上看不出來,因為判題框架擁有那些節點、函式結束後統一回收。但那是框架的責任邊界,不是程式碼正確 —— 而且這一項是刪除類題目獨有的:前面 21、2、143 只漏 dummy,這題漏兩個。
App 1. 兩趟版一樣是 O(sz) —— follow-up 買到的不是漸進上的改進。

int sz = 0; for (ListNode* p = head; p; p = p->next) ++sz;  // 第一趟:數長度
ListNode dummy(0, head); ListNode* t = &dummy;
for (int i = 0; i < sz - n; ++i) t = t->next;  // 第二趟:走到前驅
ListNode* v = t->next; t->next = v->next; delete v;
return dummy.next;

實測:窮舉全部 465 組,不一致 0,與一趟版結果完全相同。

複雜度:兩趟仍是 O(sz) —— 2n 和 n 是同一個量級。空間也一樣 O(1)。差別只在常數與「掃描次數」。

什麼時候寫哪個:如果資料在串流上(只能讀一次)、或走訪成本很高(每次讀取要 I/O),一趟才有實質意義。面試時最好的答法是先講兩趟版證明自己會做,再說「既然 follow-up 問了,可以用固定間距的雙指標做到一趟」——而不是直接跳到一趟版然後解釋半天。
App 2. 會 SEGV —— 因為那個「剛好不越界」的保證(A3)沒了。

n > sz 時,curr 要走 n + 1 > sz + 1 步。走到第 sz + 1 步時它已經是 nullptr,第 sz + 2 步就對空指標取 ->next。

防護版:在拉開間距的迴圈裡順便檢查。
for (int i = 0; i < n + 1; ++i) {
  if (!curr) return head;  // n 超過長度 —— 沒有這個節點
  curr = curr->next;
}

實測:
sz=3, n=3 → [2,3](合法,正常刪頭)
sz=3, n=4 / sz=3, n=10 / sz=1, n=2 → 偵測到越界,原樣回傳

要不要寫這段,取決於函式的契約。題目明文保證 1 ≤ n ≤ sz,所以在 LeetCode 上不必寫 —— 但如果這是一個對外的函式庫 API,呼叫端不見得守規矩,那就該擋。面試時值得說一句「題目保證了所以我不擋,但如果是產品程式碼我會加」。
App 3. 間距是 k,不是 k + 1 —— 而這個對照剛好解釋了本題那個 +1。

ListNode *lead = head, *trail = head;
for (int i = 0; i < k; ++i) lead = lead->next;  // 間距 k
while (lead) { lead = lead->next; trail = trail->next; }
return trail;  // 倒數第 k 個

實測:sz = 1..50、k = 1..sz 共 1275 組,不一致 0。

差在哪:
· 只要「拿到」那個節點 ⇒ 間距 k,trail 直接落在目標上。
· 要「刪掉」那個節點 ⇒ 間距 k+1,因為單向串列需要前驅才能摘掉它。

順帶一提這個版本連 dummy 都不需要 —— 因為它不修改串列,自然沒有「頭可能被換掉」的問題。

把兩者並排記:間距 = 「你需要停在目標前面幾格」。要讀就 0 格(間距 k),要刪就 1 格(間距 k+1)。這比死背「記得 +1」有用得多。
