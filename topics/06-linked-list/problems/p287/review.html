觀念題// CONCEPT Q&A

Q1. 為什麼「值域是 [1, n]」這個條件能保證走訪圖是 ρ 形而不是純圓?這件事為什麼重要?
Q2. 為什麼環的入口就是重複的那個值?請用「邊」的語言說一次。
Q3. 把 do { ... } while (slow != fast); 改成 while (slow != fast) { ... },程式會做什麼?錯幾組?
Q4. 階段 2 為什麼是「slow 回起點、fast 留原地、兩個都一次一步」?把 fast 也改成兩步會怎樣?
Q5. nums[nums[fast]] 連續兩層索引 —— 為什麼不需要任何邊界檢查?

範例 Trace// nums = [1,3,4,2,2]

// SETUP:先把陣列翻譯成圖 index : 0 1 2 3 4 nums : 1 3 4 2 2 邊: 0→1 1→3 2→4 3→2 4→2 從 index 0 出發走: 0 → 1 → 3 → 2 → 4 → 2 → 4 → … └───── 環 ─────┘ 尾長 μ = 3 環長 λ = 2 入口 = 2 // 注意 index 0 在環外 —— 沒有任何 nums[i] 等於 0
// 階段 1:slow 一步、fast 兩步,找相遇點 起始 slow = fast = nums[0] = 1 第 1 輪 slow = nums[1] = 3 fast = nums[nums[1]] = nums[3] = 2 第 2 輪 slow = nums[3] = 2 fast = nums[nums[2]] = nums[4] = 2 → 相遇於 2 // do-while:先各走一步才比,否則起始就相等,迴圈根本進不去
// 階段 2:slow 回 nums[0],兩個都一次一步 重置 slow = nums[0] = 1 fast = 2 (留在相遇點) 第 1 輪 slow = nums[1] = 3 fast = nums[2] = 4 第 2 輪 slow = nums[3] = 2 fast = nums[4] = 2 → 相遇 = 環的入口 return 2 // 全程沒有寫入 nums,也沒有任何額外容器
// 實測的迭代次數(不是估的) n = 10 階段 1 走 10 輪 階段 2 走 9 輪 n = 1000 階段 1 走 980 輪 階段 2 走 964 輪 n = 100000 階段 1 走 89160 輪 階段 2 走 49079 輪 // 兩階段合計約 1.4n —— 確實是線性
這個例子有個容易誤導的地方:相遇點剛好就是入口(都是 2)。 那是巧合,不是通則 —— 相遇點只保證「在環上」。所以就算看起來階段 1 已經給出答案, 階段 2 仍然不能省。

應用題// APPLICATION

App 1. 題目保證「只有一個值重複」。如果拿掉這個保證,允許好幾個不同的值都重複,這份程式碼還會回傳一個真的重複值嗎?
App 2. 如果值域從 [1, n] 改成 [0, n−1](長度仍是 n+1),這份程式碼會怎樣?
App 3. 順手把環長 λ 和尾長 μ 也算出來要加幾行?兩者的分布長什麼樣?
// ANSWERS
A1. 因為「值域 [1, n]」等價於「沒有任何一條邊指向 index 0」。

一條邊 i → nums[i] 的終點就是 nums[i] 這個值。而所有值都 ≥ 1 ⇒ 沒有邊的終點是 0 ⇒ index 0 沒有前驅。

一個節點若在環上,它必定有前驅(環上的前一個)。0 沒有前驅 ⇒ 0 不在環上。
又因為位置有限,從 0 走下去一定會撞進某個環(鴿籠 ↗:走 n+2 步以內必踩到重複位置)。

結論:一段非空的尾巴 + 一個環 = ρ 形。

為什麼重要?Floyd 的階段 2 需要「起點在環外」這個前提 —— 它算的是「起點到入口」與「相遇點到入口」的距離同餘。如果起點本身就在環上,μ = 0,入口的概念就崩了。

實測:30 萬組隨機測資,index 0 落在環內的有 0 組。而 App 2 示範了把這個條件拿掉會發生什麼事。
A2. 「入口有兩條以上的邊指進來」,而一條邊指進 v 就是「某個 nums[i] == v」。

ρ 形的圖裡,只有入口那一個節點同時被兩邊指到:
· 尾巴上最後一個節點指過來;
· 環繞一圈之後,環上最後一個節點也指過來。

把它翻回陣列的語言:存在兩個不同的索引 i ≠ j,使得 nums[i] == nums[j] == 入口 —— 這就是「入口這個值出現了兩次」的定義。

實測:30 萬組隨機測資,「環入口 ≠ 重複值」的有 0 組。

反過來也成立,而且是個好的自我檢查:如果一個值只出現一次,它就只有一條邊指進來,不可能是入口。
A3. 整支會退化成 return nums[0]; —— 兩個迴圈都一次都不跑。

slow 和 fast 初始都是 nums[0],所以 while (slow != fast) 的條件一開始就是 false,階段 1 整段被跳過。
接著階段 2 把 slow 設回 nums[0] —— 而 fast 從來沒動過,也還是 nums[0] ⇒ 第二個迴圈也不執行 ⇒ 直接 return nums[0]。

實測(n = 1..6 全部 61497 組):錯 34348 組,最小反例 [1,2,2] 回傳 1(正解 2)。
而且進一步驗證過:這個變體的回傳值在全部 61497 組中恰好等於 nums[0] —— 它答對的那 27149 組,純粹是因為 nums[0] 剛好就是答案,不是因為它算對了。

這正是 141 的同一課:只要兩個指標從同一點出發,「先比再動」就等於什麼都沒做。兩種寫法二選一 —— 要嘛 do-while,要嘛讓起點錯開一步。
A4. 因為階段 1 留下的等式是「距離同餘」,而同餘只在同速下才會保持。

設 μ = 起點到入口,λ = 環長,相遇時 slow 走了 d 步:
fast 走了 2d 步而兩者同點 ⇒ 2d − d = d 是環長的倍數 ⇒ d ≡ 0 (mod λ)。

於是:
· 從起點走 μ 步 → 到入口(定義);
· 從相遇點走 μ 步 → 等於從起點走 d + μ 步,而 d ≡ 0 ⇒ 在環上等價於走 μ 步 → 也到入口。

兩邊同時抵達,所以「第一次相等」就是入口。

實測兩種破壞方式(61497 組):
· fast 也走兩步(破壞同速)→ 錯 13458 組,最小反例 [1,2,3,2] 回傳 3(正解 2);
· slow 從 index 0 而非 nums[0](破壞起算基準)→ 錯 17082 組,最小反例也是 [1,2,3,2]。

但把「兩階段都從 index 0 起算」—— 也就是一起改 —— 實測 0 錯。錯的不是「從哪裡開始」,而是兩階段的基準沒對齊。
A5. 因為值域 [1, n] 同時就是「合法索引」的子集。

陣列長度 n + 1 ⇒ 合法索引是 0 .. n。
fast 的值永遠來自某個 nums[...] ⇒ fast ∈ [1, n] ⊂ 合法索引 ✓
nums[fast] 也是陣列裡的一個元素 ⇒ 一樣 ∈ [1, n] ✓
所以 nums[nums[fast]] 的兩層索引都在界內。

這是本題最省事的地方:比起 141 每一步都要防 nullptr(那題實測少一個守衛就 SEGV), 這裡連一個檢查都不用寫 —— 因為「走出界」在這個表示法裡根本不存在,它只會繞回陣列裡的某一格。
App 1. 會 —— 實測完全成立,但它只給你「其中一個」。

推理:A1 和 A2 的兩條論證都沒有用到「只有一個重複」。
· 「圖是 ρ 形」只用到值域 [1, n];
· 「入口有兩條邊指進來 ⇒ 入口是重複值」也只需要那一個入口本身重複。
多個值重複時,圖裡只是多了幾個分岔,但從 index 0 走出去的那條路徑還是唯一一條,它撞進的那個環還是只有一個入口。

實測:窮舉 n = 1..6 的全部長度 n+1、值域 [1,n] 的陣列共 296675 組 (其中 235178 組有兩個以上不同的值重複), 回傳值「不是一個真正的重複值」的:0 組。

但要說清楚它的極限:它回傳的是「從 0 走出去會撞到的那個」, 不是最小的、不是出現最多次的、也不是全部。題目那句「只有一個重複」買到的不是正確性,而是答案的唯一性。
App 2. 會壞,而且錯得很兇 —— 因為 index 0 可能落進環裡。

值域變成 [0, n−1] ⇒ nums[i] 可以等於 0 ⇒ 會有邊指向 index 0 ⇒ A1 的論證整條失效,0 可能在環上,圖可能是純圓而不是 ρ 形。

實測(n = 1..6、恰一個值重複,共 61497 組):
· index 0 落在環內:32133 組(超過一半);
· Floyd 答錯:21650 組,最小反例 [0,1,1] 回傳 0(正解 1)。

走一次最小反例:nums[0] = 0 ⇒ index 0 是自環。slow = fast = 0,第一輪兩個都還在 0 → 立刻相遇;階段 2 把 slow 設回 nums[0] = 0,又相等 → return 0。它找到的是「0 自己的環」,而不是 1 造成的那個環。

注意 21650 < 32133 —— 「0 在環內」不必然答錯,有時那個環的入口恰好還是重複值。但它已經不再是「保證」,而只是運氣。

修法:改成從一個確定在環外的位置出發(例如把值全部 +1 之後再跑),或直接退回值域二分 —— 那個做法完全不在意值域是從 0 還是 1 開始。
App 3. 各兩行,而且都在已經算出來的東西上再走一圈。

λ(環長):從入口出發一路走,數到回到入口為止。
μ(尾長):從 index 0 出發一路走,數到第一次等於入口為止。
兩者都是 O(n),不改變總複雜度。

範例 [1,3,4,2,2] 實測:μ = 3、λ = 2。

而分布本身很有意思(n = 1..6 全部 61497 組):
尾長 μ: μ=1:27149 μ=2:16666 μ=3:9618 μ=4:5064 μ=5:2280 μ=6:720 環長 λ: λ=1:27149 λ=2:16666 λ=3:9618 λ=4:5064 λ=5:2280 λ=6:720 // 兩列數字一模一樣

但「分布相同」不等於「每一組都相等」 —— 我原本以為會是後者,實測打臉:μ == λ 的只有 16597 組(27.0%),範例本身(μ=3, λ=2)就是個反例。

真正成立的是聯合分布對稱:實測 n=6 時 (μ=1, λ=2) 有 6270 組,而 (μ=2, λ=1) 也剛好是 6270 組 —— 每一對都對稱。邊際分布相同只是這個對稱性的推論。

順帶一提 μ = 1 的那 27149 組,正好就是 A3 裡「while 變體剛好答對」的那 27149 組 —— 因為 μ=1 的意思就是 nums[0] 本身即入口。兩個獨立測出來的數字對上了,這是個不錯的交叉驗證。

// ONE-LINE TAKEAWAY
值域 [1,n] 這一句同時買到三件事:索引安全、環必定存在、index 0 必在環外(ρ 形)。三者缺一,Floyd 就不成立 —— 實測把值域改成 [0,n-1],61497 組錯 21650 組。而「只有一個重複」買到的不是正確性,是唯一性:允許多重複時實測 296675 組仍全部回傳真的重複值。
