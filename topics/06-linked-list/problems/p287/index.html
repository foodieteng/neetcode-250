題目簡介// THE QUESTION

QUESTION

給一個長度 n + 1 的陣列 nums,每個元素都落在 [1, n]。 其中只有一個數字重複出現(可能出現不只兩次),把它找出來。

硬性限制:不能修改陣列,而且只能用常數額外空間。

Follow up:怎麼證明「至少有一個重複」一定成立?能不能做到線性時間?

這題如果沒有那兩條限制,它是入門題:開一個 unordered_set,或直接 sort,五行寫完。 整題的難度完全由「不能改陣列 + O(1) 空間」這兩句話製造出來 —— 它把所有「記下看過什麼」的做法一次全部封死。

關鍵的視角轉換:把 i → nums[i] 當成一條邊,整個陣列就變成一張圖。 因為值域是 [1, n],沒有任何邊會指向 index 0, 所以從 0 出發一路走下去,圖必定是 ρ 形(一條尾巴接一個環)。 而那個環的入口,就是重複的數字。問題於是變回第 141 題。

為什麼陣列會變成 ρ 形// THE TWO LEMMAS

LEMMA 1 · 一定有環,而且 index 0 一定在環外

從 index 0 出發,反覆做 i = nums[i]。因為只有 n+1 個位置, 走 n+2 步以內必定踩到重複的位置 —— 所以一定會進入某個環。

而值域是 [1, n],沒有任何 nums[i] 等於 0 ⇒ 沒有一條邊指向 index 0 ⇒ 0 不可能在環上,它只能在進環前的那條尾巴上。 於是整張走訪圖是「尾巴 + 環」= ρ 形,而不是一個純圓。 實測 30 萬組隨機測資,index 0 落在環內的有 0 組。

LEMMA 2 · 環的入口 == 重複的那個值

「入口」的定義是第一個有兩條以上的邊指進來的節點 —— 尾巴上那條邊,加上環繞回來那條邊。

而一條邊 i → nums[i] 指向節點 v,意思就是 nums[i] == v。 兩條邊指進 v,就是有兩個不同的 i 讓 nums[i] 都等於 v —— 那正是「v 重複出現」的定義。 實測 30 萬組,環入口 ≠ 重複值的有 0 組。

這兩條 lemma 講完之後,剩下的一行程式碼都不用自己想 —— 直接照抄 141 的兩階段 Floyd:階段 1 找相遇點,階段 2 找入口。

Follow up · 為什麼「一定存在重複」// PIGEONHOLE

題目自己問了這一題,而它不需要任何演算法 —— 是鴿籠原理一句話:

n + 1 個元素　放進　n 個可能的值 [1, n]

鴿子比籠子多一隻 ⇒ 至少有一個籠子裝了兩隻 ⇒ 至少有一個值出現兩次以上。 題目再額外保證「只有一個」值重複,才讓答案是唯一的。

這條鴿籠論證不只是嘴上功夫 —— 它就是解法 C 的正確性依據。 「小於等於 mid 的元素個數 > mid」代表 [1, mid] 這 mid 個籠子 裝了超過 mid 隻鴿子,重複值必定在左半。

一句洞察// INSIGHT

「i → nums[i]」把一個陣列題變成了一個鏈結串列題 —— 而值域 [1, n] 這個看似無害的條件,其實是在說「0 沒有前驅」, 也就是在保證圖是 ρ 形。 限制條件不是障礙,它常常就是提示:當題目同時封死「記憶體」和「修改」,它多半是在逼你換一種「看」資料的方式。
