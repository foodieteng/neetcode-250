完整實作// THE CODE

原碼一字未改。沒有配置、沒有容器、沒有修改陣列 —— 本章前面幾題都要處理的記憶體問題,這裡一個都沒有。

p287.cpp C++17 
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        // 兩個都從 nums[0] 出發 —— 等同於「已經各走了一步」
        int slow = nums[0], fast = nums[0];

        // 階段 1:slow 一步、fast 兩步,找「相遇點」(不是入口)
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // 階段 2:slow 回起點,fast 留在相遇點,兩個都改成一次一步
        slow = nums[0];

        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }

        // 相遇處 = 環的入口 = 有兩條邊指進來的節點 = 重複值
        return slow;
    }
};

nums[nums[fast]] 為什麼不會越界// INDEX SAFETY

這是本題唯一看起來危險的地方 —— 連續兩層索引。而它安全的理由只有一句:

// 陣列長度 n+1,合法索引 0 .. n 題目保證 1 ≤ nums[i] ≤ n 對每個 i 都成立 fast 的值永遠來自某個 nums[...] ⇒ fast ∈ [1, n] ← 合法索引 nums[fast] 也是某個元素 ⇒ ∈ [1, n] ← 一樣合法 nums[nums[fast]] 因此永遠在界內 // 順帶一提:因為值 ≥ 1,index 0 永遠不會被走到 —— 這正是圖是 ρ 形的原因
換句話說,「值域 [1, n]」這個條件同時做了兩件事: 保證索引安全,以及保證 index 0 在環外。 一個限制條件被用了兩次 —— 這通常代表題目是刻意這樣設計的。
本章其他題的隱憂287 有沒有為什麼
記憶體洩漏(new 沒配對)沒有整支沒有配置任何東西
nullptr 解參考沒有沒有指標,而且 LEMMA 1 保證環一定存在
整數溢位沒有全程只有索引賦值,沒有任何算術
修改輸入沒有實測 10 萬組,陣列被改 0 組

四個變體,實測誰會壞// ADVERSARIAL VARIANTS

把每一處都改成「看起來也對」的寫法,拿 n = 1..6 的全部 61497 組合法輸入去跑, 再回報最小的反例:

把哪裡改掉錯幾組 / 61497最小反例
do-while → while 34348 [1,2,2] → 回傳 1(應為 2)
階段 2 的 slow 改成從 index 0 出發 17082 [1,2,3,2] → 回傳 3(應為 2)
階段 2 的 fast 也走兩步 13458 [1,2,3,2] → 回傳 3(應為 2)
兩階段都從 index 0 出發(而不是 nums[0]) 0 這是合法的另一種寫法
最危險的那一個:do-while → while

slow 和 fast 一開始就相等(都是 nums[0])。 寫成 while (slow != fast) {...},條件一開始就是 false —— 迴圈一次都不會執行,階段 1 直接被跳過。

接著階段 2 把 slow 設回 nums[0],而 fast 也還是 nums[0] —— 兩個又相等,第二個迴圈也不執行,函式直接 return nums[0]。 換句話說,這個變體根本沒在跑演算法,它只是回傳第一個元素; 它答對的那 27149 組,純粹是因為剛好 nums[0] 就是答案。

這一點和 141 完全一樣 —— 只要「兩個指標從同一點出發」,就必須先動再比。 141 那題用的是while + 兩個指標錯開起點,本題用的是 do-while + 同起點, 兩者是同一件事的兩種寫法。

階段 2 的那個等式// WHY IT LANDS ON THE ENTRY

設 μ = 起點到入口的距離,λ = 環長,相遇時 slow 走了 d 步。

// 階段 1 結束時 fast 的步數 = 2d,slow 的步數 = d,而兩者停在同一點 ⇒ 2d − d = d 是環長的倍數 ⇒ d ≡ 0 (mod λ) // 於是 從「起點」走 μ 步 → 到入口 (定義) 從「相遇點」走 μ 步 → 相當於從起點走 d + μ 步 而 d ≡ 0 (mod λ) ⇒ 在環上等價於走 μ 步 → 也到入口 // 兩者同速前進,必定「同時」抵達入口 —— 這就是階段 2 的全部理由
這也解釋了為什麼另外兩個變體會壞: 「slow 從 index 0 而 fast 從相遇點」把兩邊的起算基準錯開了一步 (階段 1 是從 nums[0] 起算的); 而「fast 也走兩步」則直接破壞了「同速」這個前提,等式左右不再對齊。 這兩者的最小反例都是 [1,2,3,2] —— 一個 μ = 1 的例子,錯開一步就看得出來。

備案:對「值」二分// THE SAFE FALLBACK

如果面試當下想不起 Floyd,這個一定要寫得出來 —— 它同樣不改陣列、同樣 O(1) 空間, 只是慢一個 log。而且它跟本章無關,是第 05 章「答案二分」的直接應用。

p287_binary.cpp O(n log n) · O(1) 
int findDuplicateBinary(vector<int>& nums) {
    int lo = 1, hi = (int)nums.size() - 1;   // 二分的是「值」,不是索引

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int cnt = 0;

        for (int v : nums) {
            if (v <= mid) {
                ++cnt;
            }
        }

        // 鴿籠:[1,mid] 只有 mid 個籠子,裝了超過 mid 隻 ⇒ 重複值在左半
        if (cnt > mid) {
            hi = mid;
        } else {
            lo = mid + 1;
        }
    }

    return lo;
}
