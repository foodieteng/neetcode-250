題目簡介// THE QUESTION

QUESTION

設計一個固定容量 k 的環狀佇列,支援六個操作: enQueue、deQueue(回傳成功與否)、 Front、Rear(空的時候回 -1)、 isEmpty、isFull。

1 ≤ k ≤ 1000、0 ≤ value ≤ 1000、最多 3000 次呼叫。

這題的重點不在演算法,而在「你要拿哪幾個變數當狀態」。 一般的佇列用陣列實作時,deQueue 之後前面會空出一格 —— 要嘛整個往前搬(O(n)),要嘛就讓它空著(空間白白浪費)。

環狀佇列的想法是:那格空間留著,等寫到陣列尾端時繞回來用。 而所謂「繞回來」,實作上只是一個 % capacity —— 底層的陣列從頭到尾都是線性的,「環」只存在於索引的算術裡。
2

滿與空的歧義,和三種解法// WHY THIS

真正的難點是這個:如果用 front 和 rear 兩個索引來表示狀態, 那麼「空」和「滿」都會讓兩個索引重合 —— 光看索引分不出來。

// k = 3,用 (front, rear) 表示 空的時候： front = 0, rear = 0 ← 兩者相等 放三個之後： front = 0, rear = 0 ← 兩者又相等,而且是滿的 // 同一組數字,兩種完全相反的狀態 —— 這就是歧義
A (front, rear) 但不處理歧義 直接壞掉
這是最常見的錯法。常見的補救是把 isFull 寫成 (rear + 1) % capacity == front —— 但那等於偷偷把容量變成 k − 1。 實測 k = 1 時第一個 enQueue 就回 false,320 萬次呼叫錯 546467 次。
× REJECT · 少裝一個
B (front, rear) + 多配一格 正確 · 但浪費一格
教科書寫法:配置 k + 1 格,永遠留一格不用, 這樣「滿」就是 (rear+1) % (k+1) == front,和「空」不會撞。 實測完全正確,代價是 k = 1000 時多佔 4 bytes。
△ 正確 · 但多一格
C (front, rear) + 一個 bool full 旗標 正確 · 但多一個狀態
不浪費格子,改用一個布林值消除歧義。實測也完全正確, 但那個旗標要在 enQueue 和 deQueue 兩處各自維護 —— 多一個必須同步的狀態,就多一處會忘記更新。
△ 正確 · 但要同步
D (front, size) —— 換一組狀態 O(1) · 不浪費 · 無歧義
不去「解決」歧義,而是讓它根本不存在。 存 size 而不是 rear ⇒ 「空」是 size == 0、「滿」是 size == capacity,兩個永遠不可能同時成立。 而 rear 隨時可以從 (front + size − 1) % capacity 算出來。
● ADOPT · 這就是本題答案
B、C、D 三種寫法實測都正確 —— 各自窮舉 k = 1..4 的全部操作序列共 3202668 次呼叫,不一致 0。 所以這不是「對與錯」的選擇,而是「哪一種比較不容易寫錯」。 而 D 的優勢是它不需要任何補救措施:歧義沒有被修掉,是壓根沒發生。

三個索引算式// THE ARITHMETIC

要什麼算式怎麼想
第一個元素q[front]front 本身就是頭
下一個要寫的空位(front + size) % capacity從頭往後數 size 格 —— 前面 size 格都被佔了
最後一個元素(front + size − 1) % capacity空位再往回一格,−1 不能少
三個算式其實只有一個想法:「從 front 往後數幾格,超過陣列就折回來」。 而 enQueue 與 Rear 的差別只在那個 −1 —— 實測把它拿掉,320 萬次呼叫錯 134334 次,最小反例只要兩個操作: k=2: enQueue(1) → Rear() 回傳 0(正解 1)。

出隊為什麼不必清掉資料// THE KEY LEMMA

LEMMA · 「哪些格子算數」完全由 front 與 size 決定

索引 j 屬於佇列 ⟺ (j − front + k) % k < size。

陣列裡的值從來不參與這個判斷 —— 所以 deQueue 只要把 front 推一格、 size 減一,那格資料自動就「不算數」了,不需要清掉。

它會在下次繞回來時被自然覆蓋。 如果真的去清空(例如寫成 0),不但多做一次寫入,還會讓「0」這個合法的 value 變得曖昧。

這就是為什麼環狀佇列的每個操作都是嚴格的 O(1) —— 出隊是「移動邊界」,不是「刪除資料」;入隊是「覆蓋」,不是「插入」。 全程沒有任何元素被搬動過。

一句洞察// INSIGHT

當一個表示法產生歧義時,與其想辦法「補救」,不如換一組狀態讓歧義根本不存在。 rear 和 size 攜帶的資訊量完全一樣(彼此可互推),但 size 的 「空」與「滿」落在數線的兩端,而 rear 的落在同一點。 ——「存哪個變數」不是實作細節,它決定了你之後要不要處理特例。
