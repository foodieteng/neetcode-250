完整實作// THE CODE

原碼一字未改,只補上註解。這是本章唯一沒有任何 new、也沒有任何指標的一題 —— 沒有洩漏、沒有 null、沒有懸空。

p622.cpp C++17 
class MyCircularQueue {
private:
    // 狀態只有這兩個:頭在哪、有幾個。rear 不存,要用時再算
    int size, front, capacity;
    vector<int> q;

public:
    MyCircularQueue(int k) {
        q.resize(k, 0);          // 恰好 k 格,不多不少
        size = 0;
        front = 0;
        capacity = k;
    }

    bool enQueue(int value) {
        if (isFull()) return false;
        // 下一個空位 = 從頭往後數 size 格
        q[(front + size) % capacity] = value;
        size++;
        return true;
    }

    bool deQueue() {
        if (isEmpty()) return false;
        // 只移動邊界,不碰陣列內容 —— 舊值留著等下次繞回來覆蓋
        front = (front + 1) % capacity;
        size--;
        return true;
    }

    int Front() {
        if (isEmpty()) return -1;
        return q[front];
    }

    int Rear() {
        if (isEmpty()) return -1;   // 這個守衛是必要的,見第 3 節
        // 空位再往回一格 —— 那個 -1 不能少
        return q[(front + size - 1) % capacity];
    }

    // 兩個判斷落在數線的兩端,永遠不可能同時成立
    bool isEmpty() { return size == 0; }
    bool isFull()  { return size == capacity; }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

enQueue 與 deQueue 都是先呼叫自己的 isFull / isEmpty。 這不只是省事 —— 它保證了「守衛條件」與「對外回報的狀態」永遠是同一份邏輯, 不會出現「isFull() 說沒滿但 enQueue 卻拒絕」這種矛盾。

這題的測資空間可以真的窮舉// EXHAUSTIVE

六個操作、狀態只有 (front, size) 兩個小整數 —— 對小的 k,「所有可能的操作序列」是可以真的全部跑一遍的。

// 窮舉:k = 1..4,7 種操作,長度 1 到 7 的「全部」序列 序列數： 3843196 總呼叫： 26261872 回傳值不一致： 0 每次呼叫後比對佇列內容,不一致： 0 索引檢查 9711316 次,越界： 0 // 再補上窮舉搆不到的規模 k 隨機 1~1000,400 × 20000 次操作 = 800 萬次 → 不一致 0 k = 7,繞圈 200 萬輪（front 繞了約 142857 圈)→ 不一致 0
「比對回傳值」還不夠 —— 這裡是每一次呼叫之後都把整個佇列的內容跟參考解比一遍。 因為有些 bug(例如寫錯位置)不會立刻反映在回傳值上,要等好幾步之後才浮現。 逐步檢查不變量,才能讓 bug 在它發生的那一步被抓到,而不是在它被看見的那一步。

「回傳錯」與「內容錯」兩欄要分開看。 Rear() 那兩個變體「內容錯 0」——因為 Rear 是唯讀的,它只是回報錯了; 而 enQueue 寫錯位置的那個「回傳錯」只有 11880、「內容錯」卻高達 86840 —— 它默默把資料寫到不該寫的地方,而錯誤要好幾步之後才會被 Front/Rear 看見。 只比對回傳值的測試會嚴重低估這種 bug。
4

Rear 的守衛為什麼不能省// NEGATIVE MODULO

Rear() 算的是 (front + size − 1) % capacity。 如果 size == 0 而 front == 0,那就是 (−1) % capacity。 而 C++ 的 % 是往零截斷,不是數學上的模:

// 實測(C++11 起,負數取餘數的結果跟著被除數的正負號) (-1) % 1 = 0 ← k=1 時剛好落在界內,讀到 q[0] 的殘留值 (-1) % 3 = -1 ← k≥2 時就是 q[-1] (-1) % 5 = -1 // 拿掉守衛的實測後果(3202668 次呼叫) 回傳錯： 264364 索引越界： 176841 最小反例： k=1 Rear() → 0（正解 -1)
注意 k = 1 那個反例特別陰險:(−1) % 1 == 0,所以它沒有越界 —— 它安安靜靜地讀了 q[0],回傳一個殘留的舊值。 sanitizer 抓不到它,只有跟參考解比對才看得出來。 而 k ≥ 2 時才會真的變成 q[-1] —— 同一個 bug,兩種完全不同的表現。
