題目簡介// THE QUESTION

QUESTION

給兩條已排序的鏈結串列,合併成一條有序的。 題目特別寫明:結果要由拼接原本的節點組成(splicing together the nodes)。

兩條各 0 ~ 50 個節點,值域 ±100。

這是 merge sort 的那個 merge,換到鏈結串列上。因為兩條都有序, 每一步只需要比兩個頭 —— 小的那個接到結果尾巴後面,那條往前走一格。 直到有一條空了,把剩下那整條一次掛上去。

「splicing」那個字是題目給的提示:不要 new 新節點來複製值, 要把原本的節點搬過來接上。實測 5 萬組隨機測資,你的解法合併後的 節點位址集合正好等於兩條輸入的聯集 —— 除了那個 dummy 之外,零配置。

為什麼要一個 dummy 假頭// WHY THE DUMMY

A 把值倒出來排序,再建新串列 O(n log n) + n 個新節點
會過,但浪費了「兩條都已經有序」這個前提,而且違反題目要求的 splicing。舊的那些節點還得處理。
× REJECT · 沒用到有序
B 不用 dummy,直接維護 head O(m+n)
也對,但要為「第一個節點」寫一段特判:結果還是空的時候不能寫 tail->next, 得先決定 head。同一段邏輯要寫兩遍,而且那正是最容易漏掉的地方。
△ 可行 · 但多一個特判
ADOPT
C dummy 假頭 + tail 指標 O(m+n) 時間
先放一個不存資料的假頭,tail 指著它。 於是「接第一個節點」和「接第 k 個節點」變成完全同一行 tail->next = …, 特判整個消失。最後回傳 dummy->next。
● ADOPT · 消掉特判
dummy 是鏈結串列題的通用招式,不只這題:凡是「結果的頭可能還沒決定」或 「頭節點自己也可能被刪 / 被換」的題目(如 19 刪倒數第 N 個 ↗、 92 區間翻轉 ↗),掛個 dummy 都能把邊界情形抹平。
3

核心策略 · 三步驟// STRATEGY

  1. 建 dummy,tail = dummy。tail 永遠指著「目前結果的最後一個節點」。
  2. 兩條都還有東西時:比兩個頭,小的接到 tail->next,那條前進一格,然後 tail = tail->next。
  3. 收尾:迴圈結束時必有一條空了,tail->next = l1 ? l1 : l2; 把剩下那整條一次掛上,O(1)。回傳 dummy->next。
判斷式寫 l1->val <= l2->val 而不是 < —— 相等時取 l1,這叫穩定合併。 對這題來說兩種寫法的值序列一樣(所以都會 AC),但節點身分不同,見第 6 節。

那個 new 洩漏了// THE COMMENT IS WRONG

程式碼裡那句註解說反了

ListNode* dummy = new ListNode(); // stack-allocated: no leak

new 配置的東西在堆積(heap),不是堆疊。而函式回傳的是 dummy->next, dummy 這個節點本身沒有任何人再指得到它,也沒有人 delete 它 —— 它就是洩漏了。

實測(在 ListNode 上覆寫 operator new/delete 精確計數): 每呼叫一次 mergeTwoLists,new 多一次、delete 沒有 —— 呼叫 10 萬次洩漏 10 萬個節點 = 1562 KB。

修法就是那句註解本來想寫的東西:ListNode dummy;(不加 new、不加 *), 然後 tail = &dummy、return dummy.next。實測配置數 從 1 降到 0。

// 實測(覆寫 ListNode::operator new / delete 計數) [原碼 new ListNode()] 建輸入串列配置 6 個,merge 又配置了 1 個 釋放結果後:new = 7, delete = 6 ⇒ 洩漏 1 個節點 ← 就是 dummy [改成 ListNode dummy;] 建輸入串列配置 6 個,merge 又配置了 0 個 釋放結果後:new = 6, delete = 6 ⇒ 洩漏 0 個 [累積] 呼叫 100000 次 → 洩漏 100000 個節點 = 1562 KB (sizeof(ListNode) = 16 bytes) // LeetCode 不檢查洩漏,所以還是 AC —— 但面試官會看,而且這是真的 bug
這題在 LeetCode 上照樣 AC,因為判題不檢查記憶體。 但如果面試時寫了 new 又沒 delete,而註解還宣稱「no leak」—— 那比單純漏掉更糟,因為它顯示你以為自己處理過了。

兩個值得說出口的細節// TWO LEMMAS

LEMMA 1 · 收尾為什麼可以「整條一次掛上」

迴圈因 l1 && l2 不成立而結束,所以恰好有一條空了,另一條可能還有東西。

剩下那條本身就有序(輸入保證),而且它的每一個值都 ≥ 已接好的最後一個 —— 因為每一圈我們都挑當時兩個頭裡比較小的,剩下的都是被比下去過的。

所以不需要再逐個比較,一行 tail->next = l1 ? l1 : l2; 就結束,O(1)。 實測拿掉這行,4900 種組合錯 4899 種。

LEMMA 2 · <= 與 < 的差別:值一樣,節點不一樣

實測用 [1,1] + [1,1](把節點標記來源)跑兩種寫法:

<=(原碼):1(L1) 1(L1) 1(L2) 1(L2)
<(變體):1(L2) 1(L2) 1(L1) 1(L1)

值序列都是 1 1 1 1,所以兩種都會 AC(4900 種組合實測錯 0)。 但節點來源順序完全相反。若節點還帶有其他欄位(id、時間戳、原始順序), <= 才是穩定的那個。merge sort 的穩定性就是靠這個等號。

複雜度// COMPLEXITY

T = O(m + n)　　S = O(1)*

每一圈恰好消耗一個節點,所以最多跑 m + n 圈,每圈 O(1)。 *嚴格說是 O(1) 額外空間 —— 但那個 new 出來的 dummy 每次呼叫都漏掉一個節點,見第 5 節。

維度量級說明
TimeO(m + n)每圈消耗一個節點;收尾 O(1)
Space(演算法)O(1)只有 dummy / tail 兩個指標
Space(實際)每次呼叫 +16 bytesnew 的 dummy 沒被釋放

正確性0 錯20 萬組隨機 + 4900 種窮舉組合

一句洞察// INSIGHT

dummy 假頭的價值不是省程式碼,是把「第一次」和「其他次」變成同一件事 —— 鏈結串列題的 bug 幾乎都躲在「第一個節點」和「最後一個節點」那兩個特例裡, 而 dummy 一口氣消掉前者。但它是節點,是節點就要問一句:誰負責釋放它。
