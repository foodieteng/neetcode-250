PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
這段程式碼裡有一句註解是錯的:ListNode* dummy = new ListNode(); // stack-allocated: no leak。錯在哪?後果多嚴重?怎麼修?
解答與說明 · ANSWER▾
錯在兩件事,而且是相反方向的錯。

① new 配置在「堆積」不是「堆疊」 —— 註解說 stack-allocated,但 new 的語意正好是「我要這個東西活得比目前這個作用域久」。
② 它真的洩漏了 —— 函式回傳 dummy->next,dummy 本身從此沒有任何指標指得到,也沒有人 delete。

後果(實測,覆寫 ListNode::operator new/delete 精確計數):每呼叫一次多漏一個節點;呼叫 10 萬次 → 洩漏 10 萬個節點 = 1562 KB(sizeof(ListNode) = 16)。LeetCode 判題不檢查洩漏,所以照樣 AC —— 這正是它容易被放過的原因。

修法就是那句註解本來想寫的東西:ListNode dummy;(不加 new、不加 *),然後 tail = &dummy、return dummy.next。實測配置數從 1 降到 0。

而且這不只是「不會漏」的問題:dummy 的生命週期本來就只需要活到函式結束,用堆疊表達的正是這個意圖。用 new 等於在宣告「這東西要活得更久」,而那並不是真的。

最後一點:註解寫錯比忘記寫更貴。忘記釋放是「沒想到」,寫上「no leak」卻用 new 是「想過但結論相反」—— 後者會讓 reviewer 相信它處理過而跳過。
第 2 題10 分
dummy 假頭到底省掉了什麼?請把沒有 dummy 的版本寫出來對照,說明差在哪一段。
解答與說明 · ANSWER▾
dummy 省掉的不是行數,是「只會走一次的那個分支」。

沒有 dummy 的版本,迴圈裡必須長成:
if (!head) { head = pick; tail = pick; }
else       { tail->next = pick; tail = pick; }

同一件事寫兩遍,而且if 那條路整個函式只會走一次 —— 它是最難被測到、也最容易寫錯的分支(忘了同時設 tail、或忘了處理「兩條都空所以 head 始終是 nullptr」)。

有 dummy 之後,迴圈裡只剩:
tail->next = pick; tail = tail->next;
第一次寫的是 dummy.next、第 k 次寫的是真節點的 next —— 程式碼完全相同,分支消失。最後 dummy.next 自然就是真正的頭。

這是鏈結串列的通用招式,凡是「結果的頭還沒決定」或「頭自己可能被刪 / 被換」的題目都適用 —— 19 刪倒數第 N 個 ↗、92 區間翻轉 ↗ 都靠它把邊界抹平。
第 3 題10 分
收尾那行 tail->next = l1 ? l1 : l2; —— 為什麼可以「整條一次掛上」而不用逐個比較?請證明剩下那條的每個值都不小於已接好的最後一個。
解答與說明 · ANSWER▾
因為剩下那條的每一個值,都在某一圈被「比下去」過。

設迴圈結束時已接好的最後一個節點值是 x,剩下那條的頭是 y。

證明:x 是在某一圈被選中的,而那一圈的另一個候選頭正是 y(或 y 更前面的某個節點,但那些後來也被選走了 —— 總之最後一次比較時,對手那側的頭就是現在的 y 或它的祖先)。既然 x 被選中,表示 x ≤ y。
又因為剩下那條本身有序,它後面的每一個值都 ≥ y ≥ x。
⇒ 整條掛上去之後仍然有序,不需要再比任何一次。

所以這是 O(1),不是 O(剩餘長度) —— 鏈結串列的優勢正在這裡(換成陣列就得真的搬 O(k) 個元素)。

實測:拿掉這一行,4900 種組合錯 4899 種,最小反例 [] + [0] 回傳 []。順帶一提它還兼差做了另一件事:兩條都空時,這行把 dummy.next 明確設成 nullptr,讓 [] + [] 也不必特判。
第 4 題10 分
判斷式寫 l1->val <= l2->val。改成 < 會 WA 嗎?如果不會,那這個等號還有什麼用?
解答與說明 · ANSWER▾
不會 WA —— 但那個等號決定了合併是否「穩定」。

實測:改成 <,4900 種窮舉組合錯 0 種。因為兩者的值序列完全相同,而 LeetCode 只比值。

差別在「用到哪一條的節點」。把節點標上來源後跑 [1,1] + [1,1]:
<= → 1(L1) 1(L1) 1(L2) 1(L2)
<  → 1(L2) 1(L2) 1(L1) 1(L1)
來源順序完全相反。

什麼時候會出事:當節點不只有 val 的時候 —— 帶了 id、時間戳、或「原始輸入順序」。這時「值相等要保留誰」就有意義了,<= 保留左邊那條(先來的),那才叫穩定排序。

merge sort 之所以是穩定排序,靠的就是這個等號。把它改掉,整個 merge sort 就不穩定了 —— 而這件事在只比值的測資上永遠測不出來。
第 5 題10 分
迴圈條件是 while (l1 && l2)。為什麼不是 ||?如果改成 ||,迴圈裡要多做什麼?
解答與說明 · ANSWER▾
因為迴圈的職責是「比較」,而只有兩條都還在時才有東西可比。

while (l1 && l2) 一旦有一條空了就跳出,把「剩下那條怎麼辦」交給收尾那一行 —— 而收尾是 O(1) 的整條掛接,比在迴圈裡逐個搬更快也更短。

改成 || 的話,迴圈會在「只剩一條」時繼續跑,而迴圈第一行就是 l1->val <= l2->val —— 其中一個是 nullptr,直接對空指標解參考,SEGV。要救就得在迴圈裡加:
if (!l1) { tail->next = l2; l2 = l2->next; }
else if (!l2) { tail->next = l1; l1 = l1->next; }
else { …原本的比較… }

結果是:多兩個分支、把 O(1) 的收尾變成 O(剩餘長度) 的逐個搬,而且答案一樣。「用 && + 一行收尾」嚴格優於「用 || + 三個分支」。

第 6 題10 分
拿一張紙,照程式手走 [1,2,4] + [1,3,4]:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

節點標了來源(L1 / L2),才看得出穩定性與splice。

// SETUP list1 = 1(L1) -> 2(L1) -> 4(L1) -> null list2 = 1(L2) -> 3(L2) -> 4(L2) -> null dummy 建好,tail = &dummy
// 第 1 圈 比 l1->val = 1 vs l2->val = 1 ⇒ 1 <= 1,接 l1 的節點 已接好: 1(L1) l1 剩: 2(L1) -> 4(L1) l2 剩: 1(L2) -> 3(L2) -> 4(L2)
// 第 2 圈 比 2 vs 1 ⇒ 2 > 1,接 l2 的節點 已接好: 1(L1) -> 1(L2) l1 剩: 2(L1) -> 4(L1) l2 剩: 3(L2) -> 4(L2)
// 第 3 圈 比 2 vs 3 ⇒ 2 <= 3,接 l1 已接好: 1(L1) -> 1(L2) -> 2(L1) l1 剩: 4(L1) l2 剩: 3(L2) -> 4(L2)
// 第 4 圈 比 4 vs 3 ⇒ 4 > 3,接 l2 已接好: 1(L1) -> 1(L2) -> 2(L1) -> 3(L2) l1 剩: 4(L1) l2 剩: 4(L2)
// 第 5 圈 比 4 vs 4 ⇒ 4 <= 4,接 l1(平手取 l1) 已接好: 1(L1) -> 1(L2) -> 2(L1) -> 3(L2) -> 4(L1) l1 剩: null(空了) l2 剩: 4(L2) // l1 空了 → while (l1 && l2) 不成立 → 跳出
// 收尾 tail->next = l1 ? l1 : l2 ⇒ l1 是 null,所以掛上 l2 剩下的整條 已接好: 1(L1) -> 1(L2) -> 2(L1) -> 3(L2) -> 4(L1) -> 4(L2) -> null
// OUTPUT return dummy.next = 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> null 共 5 圈 + 1 次收尾 // 注意兩個 1 的順序是 L1 在前、兩個 4 也是 L1 在前 —— 這就是 <= 帶來的穩定性

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
你在筆記裡寫的那條路:「以 l1 為基準,l1->val 比較大就 swap(l1, l2)」。這條路走得通嗎?請把它寫完整並說明它的額外好處與代價。
解答與說明 · ANSWER▾
走得通,而且它有一個你可能沒注意到的好處:完全不需要 dummy,所以連 第 1 題 那個洩漏問題都不存在。

你筆記裡的想法是「以 l1 為基準,誰小就讓誰當 l1」。寫成遞迴最乾淨:

ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
  if (!l1 || !l2) return l1 ? l1 : l2;
  if (l1->val > l2->val) swap(l1, l2);  // 保證 l1 的頭比較小
  l1->next = mergeTwoLists(l1->next, l2);
  return l1;
}

實測:200000 組隨機測資(m, n = 0..6,值域 ±100)與參考解不一致 0;[1,2,4] + [1,3,4] → [1,1,2,3,4,4];[] + [] 也不必特判。

好處:① 沒有 dummy —— 因為「頭是誰」由 swap 直接決定了,不必用假頭迴避;② 短、對稱、容易講。
代價:遞迴深度 = m + n。本題上限 50 + 50 = 100 層,毫無問題(實測 m=n=50 正常);但如果串列長度放大,就會遇到 206 那題量過的堆疊上限。

穩定性也對:條件寫的是 >,所以相等時不 swap、保留 l1 —— 實測 [1,1] + [1,1] 得到 1(L1) 1(L1) 1(L2) 1(L2),和 <= 版一致。你的直覺是對的,而且那個 > 沒寫成 >= 剛好保住了穩定性。
第 8 題13 分
改成合併 k 條有序串列(LeetCode 23)。直接「一條一條 merge 進去」的複雜度是多少?有沒有更好的?
解答與說明 · ANSWER▾
一條一條 merge 是 O(k·N),分治或堆積可以壓到 O(N log k)(N = 所有節點總數)。

為什麼一條一條會慢:第 i 次合併時,累積結果已經有大約 i·N/k 個節點,而每次 merge 要走完兩條。加總是 N/k · (1 + 2 + … + k) ≈ N·k/2 ⇒ O(N·k)。前面的節點被反覆走過 k 次,這就是浪費的來源。

解法一 · 分治兩兩配對:第一輪把 k 條兩兩合併成 k/2 條,第二輪 k/4 條……共 log k 輪,每一輪的總工作量都是 O(N)(每個節點在該輪只被走一次)⇒ O(N log k)。

解法二 · 最小堆積:把 k 個頭丟進 priority_queue,每次取最小、接上、再把它的 next 推進去。每個節點進出堆積各一次,每次 O(log k) ⇒ 同樣 O(N log k),空間 O(k)。

兩者都直接複用本題的 merge —— 這也是為什麼 21 值得寫熟。分治版連程式碼都是「呼叫 mergeTwoLists」。
第 9 題14 分
如果兩條串列不保證有序,只保證各自沒有環。要合併成一條有序的,你會怎麼做?
解答與說明 · ANSWER▾
先問清楚再動手 —— 這題的答案取決於「合併後要不要保持節點身分」。

直接做法:把兩條接起來(O(1),走到 l1 尾巴接上 l2),再對整條做鏈結串列版的 merge sort —— 快慢指標找中點切兩半、遞迴排序、然後用本題的 merge 合併。時間 O(N log N),空間 O(log N)(遞迴)。本題的 merge 正好是它的組件。

如果允許重建:把所有值倒進 vector、std::sort、再串回去。同樣 O(N log N) 但常數小很多,程式碼也短 —— 代價是 O(N) 額外空間,而且節點身分沒了(等於重建,不是 splice)。

該選哪個,取決於一個必須問的問題:「節點上除了 val 還有別的資料嗎?」有的話就不能用倒值重建,只能走鏈結串列 merge sort。

另外注意「有序」這個前提一旦拿掉,O(m+n) 就不可能了 —— 比較排序的下界是 Ω(N log N)。本題之所以能線性,靠的完全是輸入已排序這件事。
