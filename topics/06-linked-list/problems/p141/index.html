題目簡介// THE QUESTION

QUESTION

給一條鏈結串列,判斷它有沒有環。 有環的定義是:某個節點的 next 指回了前面走過的節點,於是走下去永遠走不完。

進階要求:O(1) 額外空間。

有環的串列長得像一個 ρ(rho):前面一段直的,後面接一個圈。 這題就是問「後面那個圈存不存在」。

O(1) 空間那句話是全部的難度。 如果可以用 O(n) 空間,拿個 unordered_set 記走過的節點就結束了 —— 但那句要求把這條路封死,逼你想出不用記憶體也能偵測循環的辦法。
2

為什麼是快慢指標// WHY THIS

A 用 hash set 記走過的節點 O(n) 空間
最直覺、也一定對:走一遍,節點位址進 set,撞到重複就是有環。但題目點名要 O(1) 空間,這條路被封死了。
× REJECT · 空間不符
B 走 N 步還沒到終點就當有環 O(n) · 但要先知道 n
你不知道 n —— 唯一能量長度的方法就是走一遍,但有環的話那一遍永遠走不完。 用「走超過某個上限就當有環」是把題目的約束偷渡進演算法,換個題目就壞了。
△ REJECT · 依賴題目上限
BOTH FAIL · ADOPT
C Floyd:一個走一步、一個走兩步 O(n) 時間 · O(1) 空間
在圈上跑步,快的一定會套慢的一圈。所以 fast 追上 slow ⇒ 有環; 反過來,如果路有盡頭,fast 會先撞到 nullptr ⇒ 無環。 只用兩個指標,不需要任何額外容器。
● ADOPT · O(1) 空間
關鍵不是「快的比較快」,是兩者的距離每一輪剛好縮短 1 —— 所以只要 slow 進了環,fast 就會在不超過「環長」輪之內追上它,不可能跳過去。第 6 節有完整推導。
3

核心策略 · 三步驟// STRATEGY

  1. 擋掉太短的輸入:if (!head || !head->next) return false; —— 這份寫法用的是 do-while(先動再檢查),所以這一行不是防禦,是必要的,見第 5 節。
  2. 兩個指標一起跑:slow = slow->next; fast = fast->next->next;,每輪比一次 slow == fast。
  3. 迴圈條件:while (fast && fast->next) —— 兩個都要檢查。fast 為空是「剛好停在界外」,fast->next 為空是「再走兩步會出界」。

do-while 換來什麼、付出什麼// THE GUARD IS LOAD-BEARING

這份寫法用 do { … } while (fast && fast->next); —— 先移動,再檢查。 這麼寫有個好理由,也有個必須付的代價。

為什麼要 do-while(而不是先檢查 slow == fast)

slow 和 fast 一開始都在 head。如果把 if (slow == fast) return true; 放在移動之前,第一次檢查就成立 —— 任何輸入都會回 true。

do-while 保證先各走一步再比,把這個假相遇避開了。 實測把檢查提前,1891 種結構錯 59 種(所有 n ≥ 2 的無環串列全部誤判)。

代價:開頭那個 guard 變成「必要」而不是「保險」

do-while 的迴圈條件在迴圈體之後才檢查,所以第一次進入迴圈體是無條件的。 而迴圈體第一行就是 fast = fast->next->next; —— head 是 nullptr 或只有一個節點時,這行就爆了。

實測(g++ -fsanitize=address,undefined),拿掉 guard 之後:
head = nullptr → member access within null pointer + SEGV
head = 單節點 → 同樣 SEGV(fast->next 是空,再取 ->next)
所以 if (!head || !head->next) return false; 這一行是這個寫法的一部分,不能省。

// 對照:標準 while 版連 guard 都不需要 ListNode *slow = head, *fast = head; while (fast && fast->next) { // 條件在前 → 迴圈體永遠是安全的 slow = slow->next; fast = fast->next->next; if (slow == fast) return true; // 移動之後才比,也沒有假相遇問題 } return false; 實測:同樣 1891 種結構,錯 0 種,而且 head = nullptr 也不會爆 // 兩種都對;while 版把「安全」交給迴圈條件,do-while 版交給開頭的 guard
6

為什麼 fast 一定追得上、而且不會跳過// THE LEMMA

LEMMA · 兩者的距離每輪剛好縮短 1

先看有環的情形。slow 走進環之後,把「fast 在環上落後 slow 幾步」記成 d (在環上看,fast 其實是在後面追)。每一輪 fast 走 2 步、slow 走 1 步 ⇒ d 減少剛好 1。

d 每輪 −1,所以它必定會剛好踩到 0 —— 不可能跳過。 (如果 fast 一次走 3 步,d 每輪 −2,就有可能跨過去而永遠錯開。) 而 d < 環長,所以最多在「環長」輪之內相遇。

無環的情形更簡單:沒有回邊,fast 只能一路往右,和 slow 的距離只會越拉越開, 所以永遠不會相等,最後必定撞到 nullptr。

// 「每輪 −1」正是 2 這個步長的意義(實測輪數) 窮舉所有 n = 0..300、所有尾接位置 k = -1..n-1: 有環最壞 = 300 輪 (n=300, k=0,也就是整條成環) 無環最壞 = 150 輪 (= ceil(n/2)) 幾個具體例子(μ = 前段長 = k,λ = 環長 = n−k): n=10 k=0 λ=10 → 10 輪 n=10 k=5 λ=5 → 5 輪 n=100 k=50 λ=50 → 50 輪 n=100 k=99 λ=1 → 99 輪 // 輪數上界是 μ + λ ≤ n,所以整體是 O(n)

複雜度// COMPLEXITY

T = O(n)　　S = O(1)

實測:無環最壞 ⌈n/2⌉ 輪(fast 走完全程就結束),有環最壞 n 輪(整條成環時)。 空間只有兩個指標。

維度量級說明
Time · 無環⌈n/2⌉ 輪fast 每輪前進 2,走到底就停
Time · 有環≤ n 輪上界 μ + λ;實測最壞 n(k = 0)
SpaceO(1)兩個指標,符合進階要求
修改輸入否全程唯讀,不動任何 next
正確性0 錯窮舉 n=0..60 × 所有尾接位置,共 1891 種結構
對照 hash set 解法:時間同樣 O(n),但空間 O(n),而且常數大很多(每個節點都要 hash 一次)。 Floyd 唯一的成本是兩個指標。

一句洞察// INSIGHT

兩個速度不同的指標,把「有沒有循環」變成了「會不會相遇」 —— 而相遇這件事不需要記憶體去記,只需要比較兩個指標。 步長差 1 是關鍵:它保證距離每輪剛好減 1,所以只會踩中、不會跨過。
