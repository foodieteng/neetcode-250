面向要記住的那一句
核心比喻在圈上跑步,快的一定會套慢的一圈;路有盡頭則快的先撞牆
為什麼不會跳過步長差 1 ⇒ 兩者距離每輪剛好減 1 ⇒ 只會踩中 0,不會跨過
guarddo-while 無條件先跑一次 ⇒ if (!head || !head->next) 是必要的,拿掉 SEGV
比較的位置必須在移動之後 —— 兩者初始都在 head,先比會假相遇(錯 59/1891)
迴圈條件fast && fast->next 兩個都要:一個擋「已出界」,一個擋「即將出界」
比指標不比值值可以重複 ⇒ 比 val 誤判率實測 40.3%,而且會先 SEGV
複雜度O(n) 時間、O(1) 空間;實測無環 ⌈n/2⌉ 輪、有環最壞 n 輪
唯讀全程不改任何 next —— 所以能直接接上 142
相遇點不是環的入口。找入口要再走一段(見 App 1)

範例 Trace// 有環 / 無環各一

例 A · [3,2,0,-4],pos = 1(官方範例 1,動畫用的也是這個)。 尾巴 index 3 的 next 接回 index 1 ⇒ 前段長 μ = 1、環長 λ = 3。

// SETUP guard: head 非空、head->next 非空 → 通過 slow = index 0 fast = index 0
// 第 1 輪 slow 走 1 步 → index 1 fast 走 2 步 → index 2 (0 → 1 → 2) slow != fast;fast 與 fast->next 都還在 → 繼續
// 第 2 輪 slow 走 1 步 → index 2 fast 走 2 步 → index 1 (2 → 3 → 1,踩到回邊繞回來了) slow != fast → 繼續 // fast 已經在環裡打轉,再也出不去
// 第 3 輪 slow 走 1 步 → index 3 fast 走 2 步 → index 3 (1 → 2 → 3) slow == fast → return true
// OUTPUT true,共 3 輪 相遇在 index 3 —— 但環的入口是 index 1,兩者不同 // 這題不需要入口;要入口是 142(見 App 1)

例 B · [1,2,3,4,5] 無環 —— 看 fast 怎麼撞到邊界。

// 第 1 ~ 2 輪 第 1 輪 slow → index 1 fast → index 2 slow != fast,兩個條件都成立 → 繼續 第 2 輪 slow → index 2 fast → index 4 slow != fast fast->next 是 nullptr → while (fast && fast->next) 不成立 → 跳出 return false // 沒有回邊,兩者距離只會越拉越開,永遠不可能相等
// 其他退化輸入(皆已實測) head = nullptr → guard 命中 → false [1] 無環 → guard 命中(head->next 是空) → false [1] 自環 → 第 1 輪 slow = fast = 自己 → true [1,2] pos = 0 → 第 2 輪相遇 → true // 單節點自環是唯一「guard 沒擋、一輪就結束」的情形
正確性驗證範圍:這題的結構空間可以完全窮舉 —— 一條長 n 的串列,尾巴接回 index k(或 -1), 結構只由 (n, k) 決定。窮舉 n = 0..60、k = -1..n-1 共 1891 種, 全部在 ASan + UBSan 下跑,答案錯 0、記憶體報錯 0。

應用題// APPLICATION

App 1. 改成回傳環的入口節點(LeetCode 142)。相遇之後還要做什麼?為什麼那樣做會剛好停在入口?
App 2. 改成回傳環的長度(沒有環回 0)。要加幾行?
App 3. 如果把 fast 改成一次走 3 步,還偵測得到環嗎?先想再看答案 —— 這題我自己也猜錯了。
// ANSWERS
A1. 因為兩者的距離每一輪剛好減少 1 —— 只會踩中 0,不可能跨過。

slow 走進環之後,把「fast 在環上落後 slow 幾步」記成 d(在環上看,fast 是從後面追)。每輪 fast 走 2 步、slow 走 1 步 ⇒ d 減少剛好 1。

d 是非負整數且每輪 −1,所以必定剛好踩到 0,也就是相遇。而 d < λ(環長),所以最多在 λ 輪內追上。

無環的情形:沒有回邊,fast 只能一路往右,兩者距離只會越拉越開,永遠不相等,最後必定撞到 nullptr。

實測輪數(窮舉 n = 0..300、所有尾接位置):有環最壞 300 輪(n=300, k=0 整條成環),無環最壞 150 輪(= ⌈n/2⌉)。上界是 μ + λ ≤ n ⇒ O(n)。

注意這裡的關鍵是「差 1」而不是「比較快」。如果距離每輪減 2,就有可能從 1 跳到 −1 而錯過 —— 這個直覺是對的,但結論不是,見 App 3。
A2. 會變成「任何輸入都回 true」。

slow 和 fast 一開始都在 head。把比較放在移動之前,do 區塊的第一件事就是 if (slow == fast) return true; —— 而它們此刻確實相等,所以第一次檢查就成立。

實測:窮舉 1891 種結構,這個版本錯 59 種 —— 正好是所有 n ≥ 2 的無環串列(n = 2..60,共 59 個)。有環的那些「碰巧對」,因為答案本來就是 true。這是最陰險的一種錯:只在應該回 false 的時候錯。

do-while 的存在意義就是避開這個:它保證「先各走一步再比」,把「兩者都在起點」這個假相遇跳過去。

另一種等價的避法是讓兩者錯開起跑(slow = head; fast = head->next;),然後用一般 while。三種寫法都對,選一種寫熟就好 —— 但要知道自己選的那種在避什麼。
A3. 非有不可 —— 而且我是用 sanitizer 確認的,不是用推的。

理由:do-while 的迴圈條件在迴圈體之後才檢查,所以第一次進入迴圈體是無條件的。而迴圈體第一行就是 fast = fast->next->next;。
head == nullptr ⇒ fast->next 就爆。
head 只有一個節點 ⇒ fast->next 是 nullptr,再取 ->next 爆。

怎麼確認:拿掉 guard,用 g++ -O0 -fsanitize=address,undefined 跑那兩個輸入。結果:
runtime error: member access within null pointer of type 'ListNode'
AddressSanitizer: SEGV on unknown address 0x000000000008
兩個輸入都是同樣的報錯。「跑跑看沒錯」在這裡沒有用 —— 空串列這種輸入很容易被跳過,而 UB 不見得每次都顯現。

對照:改成標準的 while (fast && fast->next) { … },條件在前,連 guard 都可以省(head = nullptr 時迴圈直接不進),實測同樣 1891 種結構錯 0 種。

兩種寫法都對,差別是「安全由誰負責」:while 版交給迴圈條件,do-while 版交給開頭那一行。後者少寫一行就會 SEGV,前者不會 —— 要挑預設的話,失敗模式比較溫和的那個比較好。
A4. 兩個都要,而且擋的是不同的東西。

fast 為空 ⇒ 剛剛那兩步「剛好」走到界外了。下一輪的 fast->next 會直接解參考空指標。
fast->next 為空 ⇒ fast 還在,但它後面只剩盡頭。下一輪 fast->next->next 的第二個 ->next 會爆。

換句話說:第一個擋「已經出界」,第二個擋「再走兩步就會出界」。只留一個,另一種情形就會 SEGV。

順序也不能反。while (fast->next && fast) 會先解參考 fast 再檢查它是否為空 —— 完全失去保護。這裡靠的是 && 的短路求值:左邊為假就不會評估右邊。

小結:一次走兩步的代價,就是要檢查兩格。走 k 步就要檢查 k 格 —— 這也是為什麼實務上很少看到步長超過 2。
A5. 兩個層次的問題,而且第一個會直接讓程式死掉。

層次一 · 記憶體:直接 SEGV。fast 在 fast = fast->next->next 之後可能就是 nullptr(無環時很常見),而 if (s->val == f->val) 在 while 檢查之前執行 —— 於是對空指標取 val。
實測 [1,2] 無環,UBSan 報:member access within null pointer 與 load of null pointer of type 'int',接著 SEGV。
(原本的 slow == fast 沒這個問題 —— 比較兩個指標不需要解參考,nullptr 拿來比也完全合法。)

層次二 · 邏輯:值相同不代表是同一個節點。題目沒有保證值相異(-10⁵ ≤ val ≤ 10⁵)。就算加上 null 保護,拿 20 萬條無環的隨機串列(長度 2–9、值域 0–3)測,誤判成有環的佔 40.3%。最小反例是 [0,0,0] —— 第一輪 slow 到 index 1、fast 到 index 2,兩個值都是 0,直接回 true。

「有沒有環」問的是身分不是內容,所以只能比指標。而且比指標還更便宜 —— 不用解參考。
App 1. 相遇之後,把一個指標拉回 head,然後兩個都一次一步往前走,碰頭的地方就是入口。

// 接在 slow == fast 之後
ListNode* p = head;
while (p != slow) { p = p->next; slow = slow->next; }
return p; // 環的入口

為什麼會停在入口:設前段長 μ、環長 λ,相遇時 slow 走了 s 步、fast 走了 2s 步。兩者都在環上同一點 ⇒ 2s − s = s 是 λ 的倍數。
現在從 head 再走 μ 步會到入口;而從相遇點走 μ 步 = 總共走了 s + μ 步,由於 s 是 λ 的倍數,這等於「從入口再繞整數圈」⇒ 也在入口。所以兩者同時到達入口。

實測:窮舉 n = 1..120 的所有有環結構共 7260 種,找到的入口全部等於真正的 k(錯 0)。

這也是本題「全程唯讀」的價值 —— 因為沒有改過任何 next,141 的結果可以直接餵給這一段。
App 2. 加三行:相遇之後,讓其中一個指標原地繞一圈數回來。

// 接在 slow == fast 之後
int len = 1;
for (ListNode* p = slow->next; p != slow; p = p->next) ++len;
return len;

為什麼對:相遇點必定在環上,而從環上任一點出發、沿 next 走到回到自己,走過的步數就是環長。這一段是 O(λ),不影響整體 O(n)。

實測:窮舉 n = 1..200、k = -1..n-1 共 20300 種結構,不一致 0(無環回 0、有環回 n − k)。

順帶一提,拿到 λ 之後還能用另一種方式找入口:讓一個指標先走 λ 步,然後兩個一起一步一步走,碰頭處就是入口。和 App 1 等價,只是換個推導。
App 3. 會偵測得到 —— 我原本猜「可能會跳過去而漏掉」,實測打臉。

我的錯誤推理:步長 3 ⇒ 距離每輪減 2 ⇒ 如果距離是奇數而環長是偶數,就永遠踩不到 0。

實測:窮舉 n = 1..200 的所有有環結構共 20100 種,步長 3 的版本漏掉 0 種。

為什麼我錯了:slow 走進環的那一刻,fast 已經走了 3μ 步,所以它在環上領先 (3μ − μ) mod λ = 2μ mod λ。當 λ 是偶數時,2μ mod λ 必定是偶數 —— 那個「奇數距離配偶數環長」的壞情況根本構造不出來。λ 是奇數時,每次減 2 會走遍所有餘數,也一定踩到 0。

但有一件事真的壞了 —— 142 的入口性質。App 1 那個「從 head 和相遇點各走一步會在入口碰頭」的推導,用到了 2s − s = s,只對步長 2 成立。實測 7260 種有環結構:
步長 2 → 入口找錯 0 種
步長 3 → 入口找錯 2112 種
步長 4 → 入口找錯 1746 種

所以「一定要走 2 步」這個說法是對的,但常見的理由(「不然會跳過」)是錯的。真正的理由是:步長 2 讓「fast 走的距離剛好是 slow 的兩倍」,而 142 的整套推導都建立在那個「兩倍」上。 這題我沒推對,是量出來的 —— 也是為什麼這類「聽起來很有道理」的結論值得動手驗一次。
