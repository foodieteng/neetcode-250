完整實作// THE CODE

p141.cpp C++17 
class Solution {
public:
    bool hasCycle(ListNode *head) {
        // do-while 會無條件先跑一次迴圈體,而迴圈體會做
        // fast->next->next —— 所以這一行是必要的,不是防禦
        if (!head || !head->next) return false;

        ListNode *slow = head, *fast = head;

        do {
            slow = slow->next;          // 一次一步
            fast = fast->next->next;    // 一次兩步

            // 先移動再比 —— 兩者初始都在 head,先比會假相遇
            if (slow == fast) return true;

        } while (fast && fast->next);   // 兩個都要檢查

        return false;
    }
};

三個位置,三個不同的理由// THREE DECISIONS

寫法它在擋什麼拿掉的實測後果
if (!head || !head->next) do-while 無條件先跑一次,而迴圈體會做 fast->next->next SEGV(ASan/UBSan 實錘)
空串列與單節點都爆
slow == fast 放在移動之後 兩者初始都在 head,先比會假相遇 錯 59/1891
所有 n ≥ 2 的無環串列全誤判 true
while (fast && fast->next) fast 空 = 剛好停在界外;fast->next 空 = 再走兩步會出界 少檢查任一個 → 下一輪 fast->next->next 解參考空指標
// guard 拿掉之後(g++ -O0 -fsanitize=address,undefined) head = nullptr(空串列): runtime error: member access within null pointer of type 'ListNode' AddressSanitizer: SEGV on unknown address 0x000000000008 head = 單節點無環: runtime error: member access within null pointer of type 'ListNode' AddressSanitizer: SEGV on unknown address 0x000000000008 // 兩種都是「fast->next 是空,再取 ->next」—— do-while 沒有機會先攔下來
同一題的標準 while 版:把安全交給迴圈條件

ListNode *slow = head, *fast = head;
while (fast && fast->next) {
  slow = slow->next; fast = fast->next->next;
  if (slow == fast) return true;
}
return false;

條件在前面,所以進入迴圈體時 fast 和 fast->next 一定都在 —— 連開頭的 guard 都不需要(head = nullptr 時迴圈直接不進)。而比較仍在移動之後,也沒有假相遇問題。 實測同樣 1891 種結構錯 0 種。

兩種寫法都對,差別只在「安全由誰負責」:while 版交給迴圈條件,do-while 版交給開頭那一行。 後者少寫一行就會爆,所以如果要挑一個當預設,while 版的失敗模式比較溫和。

// 迴圈輪數實測(窮舉 n = 0..300、尾接位置 k = -1..n-1) 無環最壞 = 150 輪 (n = 300) = ceil(n/2) ← fast 每輪前進 2,走完全程就停 有環最壞 = 300 輪 (n = 300, k = 0) ← 整條成環,μ=0、λ=n 幾個具體點(μ = 前段長 = k,λ = 環長 = n − k): n=10 k=0 λ=10 → 10 輪 n=10 k=5 λ=5 → 5 輪 n=100 k=50 λ=50 → 50 輪 n=100 k=99 λ=1 → 99 輪 n=12 k=7 λ=5 → 10 輪 // 上界是 μ + λ ≤ n ⇒ O(n)
T = O(n)　　S = O(1)

兩個指標、零額外容器,而且不修改輸入。相較 hash set 版的 O(n) 空間,這是進階要求指名的解。

邊界與陷阱// PITFALLS

這題的結構空間可以完全窮舉:一條長度 n 的串列,尾巴接回 index k(或 -1 無環)—— 結構只由 (n, k) 決定,值無關。下表窮舉 n = 0..60、k = -1..n-1,共 1891 種。

陷阱為什麼錯實測
拿掉開頭的 guard do-while 無條件先跑一次,fast->next->next 解參考空指標 SEGV
空串列 & 單節點都爆
slow == fast 放在移動之前 初始兩者都在 head → 第一次檢查就成立 錯 59/1891
最小反例 n=2 無環 → true
fast 只走一步 兩者速度相同,永遠並排 ⇒ 每次都「相遇」 錯 59/1891
最小反例 n=2 無環 → true
比 slow->val == fast->val
而非比指標		 ① fast 可能是 nullptr,取 ->val 直接爆
② 就算加了保護,值相同不代表是同一個節點		 SEGV(UBSan 實錘)
加保護後仍誤判 40.3%
do-while 改成標準 while 這樣也對,而且連 guard 都可以省 —— 條件在前,迴圈體天然安全 錯 0/1891
「比 val」是這題最誘人的錯法

直覺上「兩個指標指到同一個東西」很容易寫成比值。但題目沒有保證值相異 (-10⁵ ≤ val ≤ 10⁵),所以值相同完全可能是兩個不同節點。

實測:先是直接 SEGV —— [1,2] 無環時,第一輪 fast = head->next->next 就是 nullptr,而 if (s->val == f->val) 在 while 檢查之前執行(UBSan: member access within null pointer + load of null pointer of type 'int')。

加上 null 保護之後,邏輯本身還是錯的:拿 20 萬條無環的隨機串列(長度 2–9、值域 0–3)測, 誤判成有環的佔 40.3%。最小反例是 [0,0,0]。 比指標是 O(1) 且精確,比值兩者皆非。
