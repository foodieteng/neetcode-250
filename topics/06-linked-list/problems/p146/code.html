寫法一 · 手刻雙向串列// THE CODE

原碼一字未改,只補上註解。在 LeetCode 的約束下完全正確 —— 實測與 O(n) 暴力解交叉比對 1200008 次 get,不一致 0, 而且每一步都比對完整的 LRU→MRU 順序,180 萬次檢查全數通過。

p146_handrolled.cpp C++17 
class Node {
public:
    int key, val;
    Node *prev, *next;
    // key 也要存 —— 淘汰時要拿它去 cache.erase()
    Node(int k = 0, int v = 0) : key(k), val(v), prev(nullptr), next(nullptr) {}
};

class LRUCache {
public:
    int sz;
    Node *left, *right;              // left 端 = 最舊,right 端 = 最新
    unordered_map<int, Node*> cache;  // key → 節點位址(這根指標就是橋)

    // 接到 right 之前 = 最新端。零個 if,因為 right 保證存在
    void insert(Node* node) {
        Node *back = right->prev;
        back->next = node;
        node->prev = back;
        node->next = right;
        right->prev = node;
    }

    // 就地拆下來。雙向串列才做得到 —— 前驅直接就在 node->prev
    void remove(Node* node) {
        Node *prev = node->prev, *next = node->next;
        prev->next = next;
        next->prev = prev;
    }

    LRUCache(int capacity) {
        sz = capacity;
        left = new Node();            // 兩個哨兵,先互相接起來
        right = new Node();
        left->next = right;
        right->prev = left;
    }

    int get(int key) {
        if (cache.find(key) == cache.end()) return -1;  // miss 不算使用

        Node *node = cache[key];
        remove(node);                    // 拆下來
        insert(node);                    // 接到最新端
        return node->val;
    }

    void put(int key, int value) {
        if (cache.find(key) != cache.end()) {
            Node *node = cache[key];
            node->key = key;              // 這行是多餘的:node->key 本來就等於 key
            node->val = value;
            remove(node);
            insert(node);                // put 也算一次使用
            return;
        }

        if (cache.size() == sz) {
            Node *lru = left->next;     // 受害者不用找,它就在 left 端
            remove(lru);                 // 兩張表都要清 ——
            cache.erase(lru->key);      // 這裡就是 node->key 的用途
        }

        Node *node = new Node(key, value);
        insert(node);
        cache[key] = node;
    }
};

Node 裡存 key 看起來重複(雜湊表的 key 不就是它嗎?),但它是必要的。 淘汰時你是從串列那一端拿到節點的,而你需要把它從雜湊表裡刪掉 —— 這時只有節點自己知道它的 key 是什麼。 缺了它,你就得反過來掃整張雜湊表找哪個 value 等於這個指標。

被淘汰的節點沒有人回收// THE LEAK

remove(lru) 只是把節點從串列上拆下來,cache.erase 只是把雜湊表項目刪掉 —— 那個節點本身還好端端地佔著記憶體,而且此刻已經沒有任何指標指向它了。

// 實測(覆寫 Node::operator new / delete,sizeof(Node) = 24 bytes) cap=2,put 三次(觸發 1 次淘汰),物件離開作用域後: new = 5, delete = 0 → 洩漏 5 個 = 2 個哨兵 + 2 個還在快取裡的 + 1 個被淘汰的 cap=10,put 10 萬個「不同」的 key(觸發 99990 次淘汰): new = 100002, delete = 0 → 洩漏 100002 個 = 2.3 MB 快取本身明明只該佔 10 個節點 cap=10,反覆 put 同樣那 10 個 key(從不淘汰): new = 12, delete = 0 → 洩漏 12 個(2 哨兵 + 10 個活的) // ⇒ 洩漏量正比於「淘汰次數」,不是操作次數
漏掉的東西為什麼修法
被淘汰的節點 remove 只改指標,節點還在 cache.erase(lru->key);
delete lru;
兩個哨兵 + 所有還活著的節點 沒有解構子 寫一個 ~LRUCache() 走一遍串列全部 delete
LeetCode 每個測資都是新開一個物件、跑完就結束,所以這不影響判題。 但「快取」這個東西的本質就是「記憶體有上限」 —— 一個會隨著淘汰次數無限長大的 LRU,已經違背了它存在的理由。 這也是面試裡最常被追問的一句。
4

補上 delete 之後,順序就變重要了// THE ORDER TRAP

上面的變體表裡,「先 cache.erase 再 remove」實測 0 錯 —— 因為 remove 只碰指標、erase 只碰雜湊表,兩者互不相干, 而且 lru->key 在兩種順序下都還讀得到。

但那個「還讀得到」,靠的正是「節點沒有被 delete」。 一旦補上 delete lru;,順序就從無所謂變成致命。
// 補上 delete 但寫成「先 delete 再 erase」 delete lru; cache.erase(lru->key); // ← 讀已經被釋放的記憶體 // ASan 的說法 ERROR: AddressSanitizer: heap-use-after-free READ of size 4 at 0x603000001c30 #4 in main uaf.cpp:15 // 讀 4 bytes —— 正是那個 int key
// 正確順序 remove(lru); // 從串列拆下 cache.erase(lru->key); // 趁節點還活著,讀它的 key delete lru; // 最後才釋放
這和 92 那兩行接線是同一類問題: 一個東西同時是「資料來源」和「銷毀目標」時,順序就不是風格問題了。 92 是「先讀再覆蓋」,這裡是「先讀再釋放」。

修好的版本// THE FIXED VERSION

三件事:淘汰時 delete、加解構子、 以及capacity == 0 的守衛(理由見複習頁 App 1)。

p146_fixed.cpp O(1) · 無洩漏 
class LRUCache {
public:
    LRUCache(int capacity) : sz(capacity) {
        left = new Node(); right = new Node();
        left->next = right; right->prev = left;
    }

    ~LRUCache() {                           // 哨兵與所有活著的節點
        Node* p = left;
        while (p) { Node* n = p->next; delete p; p = n; }
    }

    // 類別裡有裸指標 ⇒ 預設的複製建構會造成 double free,直接禁掉
    LRUCache(const LRUCache&) = delete;
    LRUCache& operator=(const LRUCache&) = delete;

    int get(int key) {
        auto it = cache.find(key);
        if (it == cache.end()) return -1;
        remove(it->second); insert(it->second);
        return it->second->val;
    }

    void put(int key, int value) {
        if (sz <= 0) return;                  // capacity 0 的守衛

        auto it = cache.find(key);
        if (it != cache.end()) {
            it->second->val = value;
            remove(it->second); insert(it->second);
            return;
        }

        if ((int)cache.size() >= sz) {     // >= 而非 ==,並顯式轉型
            Node* lru = left->next;
            remove(lru);
            cache.erase(lru->key);          // 必須在 delete 之前讀 key
            delete lru;
        }

        Node* node = new Node(key, value);
        insert(node); cache[key] = node;
    }

private:
    void insert(Node* n) {
        Node* b = right->prev;
        b->next = n; n->prev = b; n->next = right; right->prev = n;
    }
    void remove(Node* n) {
        Node *p = n->prev, *q = n->next;
        p->next = q; q->prev = p;
    }

    int sz;
    Node *left, *right;
    unordered_map<int, Node*> cache;
};
// 修好版的實測 與暴力解交叉比對 2500015 次 get（20 萬條序列,capacity 0 ~ 5)→ 不一致 0 cap=10,put 10 萬個不同 key：new = 100002, delete = 100002 → 洩漏 0（原碼 100002）

寫法二 · std::list + splice// THE STL VERSION

上面那五節談的全是「手刻雙向串列的代價」 —— 節點誰配置、誰釋放、順序不能顛倒。 把整條串列換成 std::list,這些問題一次全部消失:節點由容器自己配置與釋放, 解構時全部歸還,不必寫 delete、不必寫解構子。 而能這樣換的唯一理由是 list 的兩個保證 —— 給定 iterator 就能 O(1) 刪除/搬移,而且 iterator 幾乎不會失效, 所以才敢把 iterator 存進雜湊表。vector / deque 兩件都做不到。

p146_list.cpp C++17 
class LRUCache {
public:
    LRUCache(int capacity) {
        cap = capacity;
    }

    int get(int key) {
        auto it = m.find(key);                  // 一定要 find —— m[key] 會替不存在的 key 插一筆
        if (it == m.end()) return -1;           // miss 不算使用,l 一根鏈結都不動
        l.splice(l.begin(), l, it->second);     // 第二個參數是 l 自己 = 串列內部搬移
        return it->second->second;              // 搬完 it 仍有效,m 不用更新
    }                                             //   it->second 是 iterator,再 -> 取 pair

    void put(int key, int value) {
        auto it = m.find(key);
        if (it != m.end()) l.erase(it->second);   // 命中:先把舊節點拆掉,否則會留孤兒
        l.push_front(make_pair(key, value));     // 一律插到最新端(前端)
        m[key] = l.begin();

        if (m.size() > cap) {                     // 先插再檢查 → 所以是 > 而不是 >=
            int k = l.rbegin()->first;           // 必須先把 key 抄下來
            l.pop_back();                        //   pop_back 不回傳值,而且直接釋放節點
            m.erase(k);                          // 兩張表同步清理
        }
    }

private:
    int cap;
    list<pair<int, int>> l;                     // 順序:前端最新,後端最舊
    unordered_map<int, list<pair<int, int>>::iterator> m;   // 速度:key → 節點的 iterator
};
兩個寫法的資料結構是同一個 —— 雙向串列 + 雜湊表,雜湊表的值指向串列上的節點。 差別只在「節點誰管」:手刻版你要自己 new、自己 delete、自己接哨兵; list 版全部交給容器。方向也相反 —— 手刻版 right 端是最新,list 版前端是最新。

// 可以再快一點:put 命中時用 splice 取代 erase + push_front

原版 put 在命中時是「erase 舊節點 → push_front 新節點」—— 等於把一個節點釋放掉再配置一個新的。既然 get 已經證明「splice 之後 iterator 仍然有效」, put 命中也可以就地改值再搬移,完全不碰記憶體配置器:

p146_list_splice.cpp 同樣 O(1) · 少一次配置 
    void put(int key, int value) {
        auto it = m.find(key);
        if (it != m.end()) {
            it->second->second = value;            // 直接改值,節點不動
            l.splice(l.begin(), l, it->second);   // 搬到最前,iterator 仍有效
            return;                                 // m 一個字都不用改
        }
        l.push_front({key, value});
        m[key] = l.begin();
        if (l.size() > (size_t)cap) {
            m.erase(l.back().first);              // back() 比 rbegin()-> 好讀
            l.pop_back();                          //   一樣:先讀完再 pop
        }
    }

std::list 需要知道的用法// THE LIST TOOLKIT

std::list 是雙向鏈結串列。LRU 會選它,理由只有兩條 —— 給定 iterator 就能 O(1) 刪除/搬移,而且 iterator 極度穩定 (只有被 erase 掉的那一個會失效,其餘永遠有效)。 所以才敢把 iterator 存進雜湊表。

// 本題真正用到的七個

用法作用複雜度
l.push_front({k, v})前端插入O(1)
l.pop_back()刪最後一個 —— 不回傳值,而且直接釋放節點O(1)
l.erase(it)刪指定節點,回傳下一個 iteratorO(1)
l.begin()第一個元素的 iteratorO(1)
l.back() / l.rbegin()最後一個元素 —— back() 回參考,rbegin() 回 reverse_iteratorO(1)
l.splice(pos, l2, it)把 l2 的 it 節點搬到 pos 前面O(1)
l.size()元素個數 —— C++11 起保證 O(1)O(1)

三種形式,pos 一律是「插入到這個 iterator 的前面」:

// SPLICE: 三種形式 l.splice(pos, l2); // 把 l2 整串搬過來,l2 變成空的 l.splice(pos, l2, it); // 只搬 it 這一個節點 l.splice(pos, l2, first, last); // 搬 [first, last) 這個區間 // 關鍵:第二個參數可以是「自己」—— 這就變成串列內部搬移 l.splice(l.begin(), l, it); // 把 it 移到最前面,O(1) —— 本題 get 用的就是這行
