PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼不能「把兩條各轉成整數、加起來、再拆回串列」?請算出具體到哪一位會壞。
解答與說明 · ANSWER▾
因為 long long 在第 20 位就裝不下了,而題目每條可以有 100 位。

LLONG_MAX = 9223372036854775807 —— 19 位數。所以最多只能安全表示 19 位十進位。題目說每條串列最多 100 個節點,也就是 100 位數,差了 81 位。

實測:把 20 個 9 依權重塞進 long long,得到 7766279631452241919 —— 正確值應該是 20 個 9(99999999999999999999)。結果不是「稍微不準」,是完全不同的數字。

正解的關鍵:逐位相加時,每一格的運算永遠只有一位數的尺度(v ≤ 19),所以不管輸入有幾位都不會溢位。這正是所有大數(bignum)運算的作法 —— 不是「用更大的型別」,而是「永遠不用大的型別」。
第 2 題10 分
while (carry || l1 || l2) 這個條件的三項各在處理什麼?把 carry 拿掉會怎樣?
解答與說明 · ANSWER▾
三項各管一件事:

l1 —— l1 還有位數沒加。
l2 —— l2 還有位數沒加(這就是「兩條長度不等」的處理)。
carry —— 兩條都空了,但還剩一個進位要變成新的最高位。

拿掉 carry 的後果:像 [9] + [1] = 10 這種「和比兩個加數都長」的情形,最高位的 1 直接被丟掉。實測窮舉 100 萬組錯 504495 組 —— 剛好一半;最小反例 [1] + [9] 答 [0](正解 [0,1])。

而且它不會沒完沒了:因為 carry ≤ 1,兩條都空之後那一圈 v = 1,新的 carry = 1/10 = 0,下一次條件必定不成立 —— 最多只多跑一圈。

這一行是這題最漂亮的地方:三種邊界情形,一個條件全包。
第 3 題10 分
迴圈裡的 carry 有沒有可能越滾越大,導致迴圈跑不完或溢位?請給出 v 和 carry 的實測上界。
解答與說明 · ANSWER▾
不會 —— carry 是個布林量,實測最大就是 1。

推導:每圈 v = carry + l1位數 + l2位數 ≤ 1 + 9 + 9 = 19,所以 carry = v / 10 ≤ 1。這是個不變量 —— 進去是 ≤1,出來還是 ≤1,不會累積。

實測(在迴圈裡埋計數器,跑 30 萬組隨機測資):
v 的最大值 = 19 ← 恰好等於理論上界
carry 的最大值 = 1

兩個推論:
① 迴圈必定終止 —— 每圈至少消耗一個節點,而兩條都空之後最多再一圈就把 carry 清成 0。迴圈次數 ≤ max(m,n) + 1。
② int 綽綽有餘 —— 最大的中間值是 19。

「推理出上界,再量一次確認」比只推理可靠:這裡兩者剛好吻合,但如果量出來不是 19,那就代表推理漏了什麼。
第 4 題10 分
這段程式有兩處 new。哪一處是對的、哪一處是問題?判斷的準則是什麼?
解答與說明 · ANSWER▾
判準只有一句:它會不會被交出去?

new 的語意是「這東西要活得比目前這個作用域久」。

✓ new ListNode(v)(結果的每一位) —— 會被交出去,它們就是回傳值。所以 new 完全正確,釋放責任在呼叫端。
✗ new ListNode()(dummy 假頭) —— 不會被交出去(回傳的是 dummy->next)。它只是施工用的鷹架,只需要活到函式結束。用 new 配置它,就沒有人 delete 它。

實測(覆寫 ListNode::operator new/delete 精確計數,以 [2,4,3] + [5,6,4] 為例):addTwoNumbers 配置 4 個 = dummy 1 + 結果 3。把結果整條釋放後 new = 10、delete = 9 ⇒ 洩漏 1 個。改成 ListNode dummy; 後配置變成 3 個(全是結果節點),洩漏 0。

和 21 是完全同一個問題,但這題有個對照組:同一支函式裡,一個 new 對、一個不對。差別不在「用不用 new」,在「這東西該活多久」。
第 5 題10 分
題目把數字存成「相反順序」。這對解法是幫助還是阻礙?如果改成正序(高位在前)會難多少?
解答與說明 · ANSWER▾
是幫助,而且幫得很大。

直式加法必須從個位開始(因為進位是往高位跑的)。而題目把個位放在串列的頭 —— 所以從 head 往後走一遍,順序天生就對。不需要翻轉、不需要先量長度、不需要對齊。

如果改成正序(高位在前),同一題會多出一整層麻煩,因為單向串列只能往後走,而加法要往前(高位)進位。得先做下面其中一件事:
① 翻轉兩條,算完再翻回來 —— 但這會修改輸入;
② 用兩個 stack 把位數倒出來 —— 不動輸入,代價是 O(m+n) 空間;
③ 先量長度、補零對齊,再遞迴回來處理進位。

這正是 LeetCode 445 ↗,而且它被標成 Medium 也是因為這個。下次看到「reverse order」這種看起來很怪的輸入格式,先想想它是不是在幫你 —— 通常是。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 [9,9,9] + [9,9] = 1098:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

這個例子四圈剛好把三種情形都演一遍:進位串聯、一條先用完、最後只剩進位。

// SETUP l1 = 9 -> 9 -> 9 -> null (低位在前,代表 999) l2 = 9 -> 9 -> null (代表 99) 預期和 = 1098 dummy 建好,tail = &dummy,carry = 0
// 第 1 圈 while (carry=0 || l1=9 || l2=9) → 進入 v = carry(0) + l1(9) + l2(9) = 18 carry = 18 / 10 = 1 這一位 = 18 % 10 = 8 接上節點 8 目前結果: 8 -> null
// 第 2 圈 while (carry=1 || l1=9 || l2=9) → 進入 v = carry(1) + l1(9) + l2(9) = 19 carry = 1 這一位 = 9 接上節點 9 目前結果: 8 -> 9 -> null
// 第 3 圈 —— l2 用完了 while (carry=1 || l1=9 || l2=null) → 進入 v = carry(1) + l1(9) = 10 (if (l2) 不成立,跳過) carry = 1 這一位 = 0 接上節點 0 目前結果: 8 -> 9 -> 0 -> null // 長度不等就被這個 if 處理掉了 —— 沒有補零、沒有特判
// 第 4 圈 —— 兩條都空,只剩進位 while (carry=1 || l1=null || l2=null) → 進入(完全靠 carry 撐起來) v = carry(1) = 1 carry = 0 這一位 = 1 接上節點 1 目前結果: 8 -> 9 -> 0 -> 1 -> null
// OUTPUT while 條件不成立(carry = 0 且兩條都空)→ 跳出 return dummy.next = 8 -> 9 -> 0 -> 1 -> null 共 4 圈 驗證:低位在前,讀回來就是 1098 = 999 + 99 ✓ // [8,9,0,1]

其他關鍵輸入的實測結果:

// 邊界與極端(皆為實測) [2,4,3] + [5,6,4] → [7,0,8] 3 圈 (342 + 465 = 807) [0] + [0] → [0] 1 圈 不會多出前導零 [9,9,9,9,9,9,9] + [9,9,9,9] → [8,9,9,9,0,0,0,1] 進位串到底 100 個 9 + 100 個 9 → 101 位,最高位 = 1 最大合法輸入 // 結果長度 = max(m,n) 或 max(m,n)+1
正確性驗證範圍:隨機對拍 30 萬組(兩邊長度 1–8), 加上窮舉兩邊長度 1–3、無前導零的所有組合共 100 萬組 —— 與大數加法參考解不一致 0。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
數字改成正序存放(高位在前,LeetCode 445),而且不准修改輸入串列。怎麼做?
解答與說明 · ANSWER▾
用兩個 stack 把位數倒出來,然後「頭插」建結果 —— 全程不動輸入。

stack<int> s1, s2;
while (l1) { s1.push(l1->val); l1 = l1->next; }
while (l2) { s2.push(l2->val); l2 = l2->next; }

ListNode* head = nullptr; int carry = 0;
while (carry || !s1.empty() || !s2.empty()) {
  int v = carry;
  if (!s1.empty()) { v += s1.top(); s1.pop(); }
  if (!s2.empty()) { v += s2.top(); s2.pop(); }
  carry = v / 10;
  head = new ListNode(v % 10, head);  // 頭插 → 自然變成高位在前
}
return head;

兩個關鍵:① stack 把「只能往後走」變成「可以從個位開始」,而且不修改輸入;② 頭插取代了 dummy —— 每次新節點接在最前面,做完剛好就是正序,連 dummy 都不需要。

實測:200000 組隨機測資與參考解不一致 0;[7,2,4,3] + [5,6,4] = [7,8,0,7](7243 + 564 = 7807 ✓)。

時間 O(m+n),空間 O(m+n)(兩個 stack)。迴圈本體跟本題幾乎逐字相同 —— 換掉的只有「怎麼取到下一位」和「怎麼接結果」。
第 8 題13 分
改成任意進位(二進位、八進位、十六進位…)。要改幾個地方?carry 的上界會變嗎?
解答與說明 · ANSWER▾
只改兩個常數:v / 10 和 v %= 10 換成 base。其他一個字都不動。

carry = v / base;
v %= base;

carry 的上界不會變,仍然是 1。因為每位數的範圍是 0 .. base−1,所以
v ≤ 1 + (base−1) + (base−1) = 2·base − 1 < 2·base ⇒ carry = v / base ≤ 1。
這對任何進位都成立 —— 兩個一位數相加最多進 1,是進位制的普遍性質。

實測(每個 base 各 100000 組隨機):
base = 2 → 不一致 0(v 上界 3)
base = 8 → 不一致 0(v 上界 15)
base = 16 → 不一致 0(v 上界 31)

唯一要留意的是 v 的上界會隨 base 變大(2·base − 1)。base 大到 10⁹ 級(有些大數函式庫真的這樣做,用一個 int 存 9 位十進位)時,v 就會逼近 2×10⁹ ——那時 int 不夠,要換 long long。
第 9 題14 分
如果拿掉「保證無前導零」這個條件,這份程式碼還對嗎?
解答與說明 · ANSWER▾
算出來的值仍然完全正確,但輸出可能帶有「高位的零」。

演算法本身不在乎前導零 —— 它只是逐位加,多出來的零就當成 0 加進去。實測:20 萬組完全不限制前導零的隨機測資,與參考解算錯 0 組。

但輸出的形式會受影響。因為低位在前,「前導零」出現在串列尾端:
[1,0,0] + [1] = [2,0,0] —— 值是 2,正確,但尾端帶了兩個零
[0,0] + [0,0] = [0,0] —— 值是 0,正確,但寫成了兩位
[5,0] + [5,0] = [0,1] —— 這個反而沒有尾端零(進位剛好把它填掉了)

實測 20 萬組裡,結果尾端帶零的佔 6.9%。

所以要不要處理,取決於題目怎麼定義「合法輸出」。如果要求輸出也不能有前導零,就得在回傳前把尾端的零砍掉(但至少保留一個節點,否則 0 就變成空串列)。題目之所以保證輸入無前導零,正是為了讓你不必寫這一段 —— 那個保證是在替你省事,值得注意到它在保證什麼。
