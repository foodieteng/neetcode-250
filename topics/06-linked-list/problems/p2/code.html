完整實作// THE CODE

演算法與原碼一字未改,只有 dummy 的配置方式修好了(見第 3 節)。

p2.cpp C++17 
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        // dummy 只需要活到函式結束,而且不會被回傳 → 放堆疊
        ListNode dummy;
        ListNode* tail = &dummy;
        int carry = 0;

        // 一個條件管三件事:l1 還有、l2 還有、最後剩一個進位
        while (carry || l1 || l2) {
            int v = carry;          // 把上一位的進位帶進來

            if (l1) {
                v += l1->val;
                l1 = l1->next;
            }

            if (l2) {            // 空的那條直接不加 = 等效補零
                v += l2->val;
                l2 = l2->next;
            }

            carry = v / 10;       // v ≤ 9+9+1 = 19,所以 carry 只會是 0 或 1
            v %= 10;

            tail->next = new ListNode(v);   // 這個 new 是必要的:結果要回傳出去
            tail = tail->next;
        }

        return dummy.next;
    }
};

那個 while 條件// THREE JOBS, ONE LINE

條件的哪一項處理什麼拿掉會怎樣(實測)
carry 兩條都空了,但還有一個進位要變成新的最高位 錯 504495/1000000
[1] + [9] → [0](正解 [0,1])
l1 / l2 兩條長度不等時,長的那條還要繼續 結果會被截短成短的那條的長度
// carry 為什麼「最多多跑一圈」而不會沒完沒了 每圈的 v ≤ carry(1) + 9 + 9 = 19 ⇒ carry = v / 10 ≤ 1 兩條都空之後,那一圈的 v = carry = 1 ⇒ 新的 carry = 1 / 10 = 0 ⇒ 下一次 while 條件必定不成立 實測 30 萬組隨機測資,逐圈記錄: v 的最大值 = 19 ← 恰好等於理論上界 carry 的最大值 = 1 // carry 是布林量,不會累積 —— 所以迴圈必定終止,且 int 綽綽有餘
if (l1) / if (l2) 這兩個判斷就是「長度不等」的全部處理 —— 空的那條直接不加,效果等同補零,但不需要真的去補。 少了一整段「量長度 + 補零 + 再處理最高位進位」的前處理。

兩個 new,一個對一個錯// LIFETIME

原碼裡有兩處 new,它們的性質完全不同:

哪一處要活多久會被回傳嗎判定

(結果的每一位)		 比函式久 —— 呼叫端要用 會(就是回傳值本身) new 是對的
new ListNode()

// 實測(覆寫 ListNode::operator new / delete 精確計數) 輸入 [2,4,3] + [5,6,4](= 342 + 465 = 807) [原碼:ListNode* dummy = new ListNode();] 建輸入串列配置 6 個 addTwoNumbers 配置 4 個 = dummy 1 個 + 結果 3 個 把結果與兩條輸入全部 delete 之後:new = 10, delete = 9 ⇒ 洩漏 1 個節點 ← 正是 dummy [改成:ListNode dummy;] addTwoNumbers 配置 3 個 = 全部都是結果節點 全部釋放之後:new = 9, delete = 9 ⇒ 洩漏 0 個 // 和 21 完全同一個問題;差別是這題的「結果節點」本來就該 new
判斷 new 對不對的一個問題:它要活多久?

new 的語意是「這東西要活得比目前這個作用域久」。所以只要問一句: 它會不會被交出去?

結果節點會(它們就是回傳值)⇒ new 正確,而釋放責任在呼叫端 —— LeetCode 的判題框架會處理,真實系統則該用智慧指標或容器把它講清楚。
dummy 不會 ⇒ 它只是施工用的鷹架,應該放堆疊。

順帶一提,這題和 21 的 dummy 是完全同一個問題。 兩題都能 AC(判題不檢查洩漏),但兩題都值得在面試時主動說一句。

邊界與陷阱// PITFALLS

窮舉兩邊長度 1..3、每位 0..9、無前導零的所有組合,共 100 萬組。

陷阱為什麼錯實測
while 條件漏了 carry 兩條都走完之後,最高位的進位沒地方放,直接丟掉 錯 504495/1000000
[1] + [9] → [0]
忘了 v %= 10 節點裡存進 兩位數(例如 18),已經不是「一位數一節點」 錯 833625/1000000
[1] + [9] → [10,1]
int v = 0;(沒把 carry 帶進來) 進位算出來了卻沒用上,等於每一位都獨立相加 錯 833625/1000000
[1] + [9] → [0,0]
return dummy(而非 dummy->next) 把假頭也交出去,結果最前面多一個 0(而個位在前,等於整個數字乘 10) 錯 1000000/1000000(全錯)
[0] + [0] → [0,0]
忘了 tail = tail->next 每圈都覆蓋掉上一圈接的節點,只剩最後一位 錯 999945/1000000
[0] + [0,1] → [1]
先把兩條轉成 long long 再相加 LLONG_MAX 只裝得下 19 位,題目每條可到 100 位 20 個 9 → 7766279631452241919
(正確值是 20 個 9)
注意 return dummy 這一列在本題比在 21 更致命: 因為個位在前,最前面多一個 0 不是多一個無關的節點,而是把整個數字乘了 10。

細節走讀// LINE BY LINE

// ORDER: 為什麼「低位在前」讓這題變簡單 直式加法必須從「個位」開始 —— 因為進位是往高位跑的 而題目把個位放在串列的「頭」 ⇒ 從 head 往後走一遍,順序天生就對 若是正序(高位在前),就得先翻轉、或用堆疊、或先對齊長度 → 那是 445 (Add Two Numbers II) // 「reverse order」這句話是在幫你,不是在刁難
// CARRY: int v = carry; 這一行就是「進位」的全部實作 v 一開始不是 0,而是「上一位溢出來的量」 然後才把這一位的兩個數字加上去 carry = v / 10 取出溢出的部分,留給下一位 v %= 10 這一位只留個位數 // 三行合起來 = 小學直式加法的一格
// TERMINATION: 迴圈一定會停 每一圈至少消耗一個節點(l1 或 l2),或者處理掉最後那個 carry 而 carry ≤ 1,所以「兩條都空」之後最多再跑 1 圈: v = carry = 1 ⇒ 新 carry = 0 ⇒ 下一次條件不成立 // 迴圈次數 ≤ max(m, n) + 1
// TYPE: 為什麼 int 綽綽有餘 v 的最大值 = carry(1) + 9 + 9 = 19 實測最大 19 carry 的最大值 = 1 實測最大 1 節點值 v %= 10 之後 ∈ [0, 9] 無論輸入有幾位數,運算永遠只在「一位數」的尺度 // 這正是大數運算不溢位的原理 —— 對比「先轉整數」在第 20 位就死了
// EDGE: 退化輸入(皆已實測) [0] + [0] → [0] 兩個 0,一圈,不會多出前導零 [9] + [1] → [0,1] 靠 while 裡的 carry 多跑一圈 [1] + [9,9,9] → [0,0,0,1] 長度不等 + 進位一路串到底 100 個 9 + 100 個 9 → 101 位 最大合法輸入 // 題目保證每條至少 1 個節點,所以不必處理空串列
PREV概念與動畫 NEXT複習與練習
