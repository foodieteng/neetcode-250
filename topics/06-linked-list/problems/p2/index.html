題目簡介// THE QUESTION

QUESTION

兩條串列各代表一個非負整數,數字以相反順序存放 —— 也就是個位在最前面,每個節點放一位數。把兩數相加,結果也用同樣格式回傳。

每條 1 ~ 100 個節點,每位 0 ~ 9,保證無前導零。

「相反順序」聽起來很怪,但它其實是題目送的禮物: 直式加法本來就從個位開始算,而個位剛好就在串列的頭 —— 從頭往後走一遍就好,不必先翻轉、也不必先算長度。

如果數字是正序存放(高位在前),同樣一題會難很多 —— 得先翻轉、或用堆疊、或先對齊長度。 看到「reverse order」不要皺眉,那是在幫你。(正序的版本是 445 ↗。)

為什麼不能先轉成整數// WHY THIS

A 兩條各轉成 long long,加完再拆回去 O(n) · 但會溢位
直接爆掉。LLONG_MAX 只裝得下 19 位十進位,而題目每條可以有 100 位 —— 差了 81 位。 實測把 20 個 9 塞進 long long,得到 7766279631452241919(正確值是 20 個 9)。
× REJECT · 溢位
B 先補零對齊長度,再逐位加 O(n)
答案會對,但多了一趟「量長度 + 補零」,還要處理「補完之後最高位又進位」。 兩個 if 就能做到的事,不需要一整段前處理。
△ 可行 · 但多做工
ADOPT
C 一邊走一邊加,用 carry 串起來 O(max(m,n))
就是小學的直式加法:每一位算 carry + a + b,留下 % 10、把 / 10 帶到下一位。 永遠只有一位數在運算,所以不管數字多大都不會溢位 —— 這正是所有大數運算的作法。
● ADOPT · 不會溢位

核心策略 · 三步驟// STRATEGY

  1. dummy 假頭 + tail,和 21 一樣 —— 讓「接第一個節點」和「接第 k 個」變成同一行。
  2. 一個迴圈條件管三件事:while (carry || l1 || l2)。長度不等、其中一條先走完、最後還剩一個進位 —— 全部涵蓋。
  3. 每圈三行算術:v = carry + (l1?) + (l2?)、carry = v / 10、v %= 10,然後把 v 接成新節點。
if (l1) / if (l2) 這兩個判斷,就是「長度不等」的全部處理 —— 空的那條直接不加,效果等同補零,但不需要真的去補。

一個條件管三件事// carry || l1 || l2

LEMMA · 為什麼 carry 必須在迴圈條件裡

l1 和 l2 都走完之後,可能還有一個進位沒地方放 —— 例如 [9] + [1] = 10,兩條各一位,結果卻要兩位。

把 carry 寫進 while,就多跑一圈把那個 1 變成新的最高位。 而且因為 carry 最多是 1(見下),最多只會多跑一圈,不會沒完沒了。

實測:把 carry 從條件裡拿掉,窮舉 100 萬組錯 504495 組, 最小反例 [1] + [9] 答 [0](正解 [0,1])—— 剛好一半的測資會錯。

條件的哪一項它在處理什麼情形例子
l1l1 還有位數沒加[1,2,3] + [1]
l2l2 還有位數沒加(兩條長度不等)[1] + [1,2,3]
carry兩條都空了,但還有一個進位[9] + [1] → [0,1]
// carry 為什麼最多是 1(實測) 每一圈 v 的最大值 = carry(1) + l1 位數(9) + l2 位數(9) = 19 ⇒ carry = v / 10 ≤ 1 實測 30 萬組隨機測資,逐圈記錄: v 的最大值 = 19 ← 恰好等於理論上界 carry 的最大值 = 1 // 所以 carry 是個布林量,不會累積成大數 —— int 完全夠用

和 21 的對照:同一個 dummy,不同的 new// SPLICE vs BUILD

這題和 21 合併兩條有序串列 的骨架幾乎一樣(dummy + tail + 一個迴圈), 但對 new 的態度完全相反:

面向21 · 合併2 · 相加(本題)
結果的節點搬原本的節點(splice)必須 new 出來
為什麼題目明寫 "splicing together the nodes"和的每一位是算出來的新值,原本沒有這個節點
結果的節點數m + n(不多不少)max(m,n) 或 +1
額外配置0(除了 dummy)max(m,n) 或 +1 個(正當的)
dummy兩題一樣:寫成 new ListNode() 就每次呼叫漏一個節點
結果節點的 new 是對的;dummy 的 new 不是

結果節點必須 new,而且刻意要活得比函式久 —— 它們被回傳出去給呼叫端。這正是 new 的正確用途。

dummy 不一樣:它只需要活到函式結束,而且不會被回傳(回傳的是 dummy->next)。 用 new 配置它,就等於宣告「這東西要活得更久」—— 而那不是真的,結果就是沒有人 delete 它。

實測(覆寫 ListNode::operator new/delete 計數,以 [2,4,3] + [5,6,4] 為例): addTwoNumbers 配置 4 個節點 —— dummy 1 個 + 結果 3 個。 把結果整條釋放後,new = 10、delete = 9 ⇒ 洩漏 1 個,正是 dummy。 改成 ListNode dummy; 之後,配置變成 3 個(全是結果節點),洩漏 0。
