題目簡介// THE QUESTION

QUESTION

給一條單向串列的頭,以及兩個整數 left ≤ right。 把第 left 個到第 right 個節點就地反轉,回傳新的頭。

1 ≤ n ≤ 500、−500 ≤ Node.val ≤ 500、1 ≤ left ≤ right ≤ n。

Follow up:能不能只走一趟?

第 206 題已經把「整條反轉」練熟了。 這題把它縮成一個區間 —— 而反轉本身一行都不用改, 真正的新東西全在區間的兩個端點上。

把它想成三段:[前段] [要翻的段] [後段]。 翻完中間那段之後,它的頭尾對調了 —— 原本的段頭變成段尾、原本的段尾變成段頭。 於是前段要接上新段頭,新段尾要接上後段。 整題就是這兩條接線,而且順序不能顛倒。
2

為什麼是「定位 + 反轉 + 接線」// WHY THIS

A 把區間的值倒出來,再寫回去 O(n) 空間
正確也好寫,但花了 O(n) 空間,而且完全沒用到串列的性質 —— 換成 vector 是同一份程式碼。本章在練的是指標重接,這個做法把題目繞開了。
× REJECT · 繞開了題目
B 切三段 → 各自處理 → 再串回來 O(n) · 多趟
先把區間真的切斷成獨立一段,呼叫 206 的 reverse,再接回去。 邏輯最乾淨,但要多存四個端點指標,而且通常會走不只一趟。
△ 可行 · 但變數變多
ADOPT
C dummy + 走到區間前一個 + 就地翻 n 圈 + 兩行接回 O(n) 一趟 · O(1) 空間
不真的切斷,只是暫時斷開再接回。只需要一個 tail 指標記住區間的前一個, 反轉迴圈跑完之後,prev 是新段頭、next 是後段的頭 —— 兩個端點都已經在手上,兩行就接完了。
● ADOPT · 一趟走 right 步
C 的巧妙處在於它「不用額外去找」端點: 反轉迴圈天然就把 prev 停在新段頭、把 next 停在後段頭。 這兩個變數本來就是反轉的一部分,只是迴圈結束後被拿來當接線用。
3

核心策略 · 三步驟// STRATEGY

  1. 掛 dummy 並定位:dummy->next = head,從 dummy 走 left − 1 步,tail 停在區間的前一個。
  2. 就地翻 n = right − left + 1 圈: 和 206 迭代版一模一樣,只是迴圈條件從「走到 nullptr」換成「跑 n 圈」。
  3. 兩行接回去,順序不能換:
    tail->next->next = next; —— 舊段頭(現在是段尾)接上後段;
    tail->next = prev; —— 前段接上新段頭。
第 3 步的順序是整題最容易寫錯的地方。 第一行之所以能寫 tail->next->next,靠的就是 tail->next 此刻「還是」原本的段頭 —— 還沒被第二行改掉。 對調實測:窮舉 165 組錯 120 組。

兩行接線,各自在接什麼// TWO LEMMAS

LEMMA 1 · 迴圈結束時,兩個端點已經在手上了

反轉迴圈跑滿 n 圈之後:
· prev 停在原本的第 right 個節點 = 新的段頭;
· next 停在原本第 right 個的後面那個 = 後段的頭(可能是 nullptr);
· tail->next 還是原本的第 left 個 = 新的段尾。

三個端點,一個都不用另外找。 這就是為什麼這個寫法只需要一趟 —— 反轉的副產品剛好就是接線要用的東西。

LEMMA 2 · dummy 解決的是 left == 1

left == 1 時,「區間的前一個」不存在 —— 而 tail->next = prev 這一行 需要有個東西可以改。dummy 就是憑空補上那個前驅。

實測:改成從 head 起步而其他不動,窮舉 165 組錯 120 組。 就算把步數也一併調對(走 left − 2 步),只要忘了替 left == 1 寫特例, 仍然錯 36 組 —— 而且那 36 組全部落在 left == 1 裡 (left == 1 共 45 組,僥倖答對的 9 組全是 left == right == 1,翻一個節點等於沒翻)。

這是本章第五次用 dummy,判準還是同一句: 「結果的頭有沒有可能不是原本的 head?」 這題 left == 1 時會,所以需要。對照 143 的頭永遠是 L₀,就不需要。

一句洞察// INSIGHT

反轉一段,會讓那一段的頭尾對調 —— 所以前面要接新頭、後面要從新尾接出去。 而「新尾」正是那個還沒被動過的 tail->next,所以接線必須先接尾、再接頭: 一旦先改了 tail->next,通往新尾的唯一一條路就沒了。
