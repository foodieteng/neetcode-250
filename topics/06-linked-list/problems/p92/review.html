核心技巧定位 → 就地翻 n 圈 → 兩行接回,反轉本體與 206 一字不差

Q2. 為什麼 tail->next->next = next; 一定要寫在 tail->next = prev; 前面?對調會錯幾組?

Q5. 最後一行如果寫成 tail->next->next = curr;(而不是 next)會怎樣?

範例 Trace// [1,2,3,4,5], left=2, right=4

// SETUP dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null └── 要翻的段 ──┘ n = right - left + 1 = 4 - 2 + 1 = 3
// ① 定位:從 dummy 走 left-1 = 1 步 tail = 節點 1 （區間的前一個;之後全程不動）
// ② 反轉 3 圈(和 206 一字不差) 起始 prev = null curr = 節點 2 next = ? 第 1 圈 next = 3 2->next = null prev = 2 curr = 3 第 2 圈 next = 4 3->next = 2 prev = 3 curr = 4 第 3 圈 next = 5 4->next = 3 prev = 4 curr = 5 // 迴圈結束。此刻整段從鏈上斷開:1 還指著 2,而 2 指著 null
// ③ 接回去(順序不能換) tail->next 此刻 = 節點 2 （舊段頭 = 新段尾) prev 此刻 = 節點 4 （舊段尾 = 新段頭) next 此刻 = 節點 5 （right 後面那個) ① tail->next->next = next; → 2 -> 5 ② tail->next = prev; → 1 -> 4 return dummy.next → 1 -> 4 -> 3 -> 2 -> 5 // 共走 right = 4 步(定位 1 + 反轉 3),沒有節點被走第二次
// 邊界(皆為實測) n=1, left=1, right=1 → [1] 段長 1,翻了等於沒翻 left == right → 原樣不變 共 45 組(n=1..9),接線順序在這裡無所謂 left == 1 → 頭會換掉 dummy 就是為了這 45 組 right == n → next = nullptr,接線照舊成立 // left == 1 與 left == right 是最容易漏測的兩類

應用題// APPLICATION

App 1. 那兩行的順序限制,能不能用「先把段尾存成一個變數」繞掉?如果可以,原本的限制到底是什麼性質的問題?
App 2. 題目保證 1 ≤ left ≤ right ≤ n。如果拿掉這個保證,right 可能超過串列長度,這份程式碼會怎樣?
App 3. 改成「每 k 個一組反轉」(LC 25 ↗),這兩行接線還能用嗎?要加什麼?
// ANSWERS
A1. 三個端點全部是反轉迴圈的副產品,一個都不用另外找。

· prev = 原本的第 right 個節點 = 新的段頭(反轉之後它排最前面);
· next = 原本第 right 個的下一個 = 後段的頭(可能是 nullptr);
· tail->next = 原本的第 left 個 = 新的段尾(反轉之後它排最後面,而 tail 全程沒動,所以它還指著原來那個)。

這就是為什麼這個寫法只需要一趟:如果要「切三段再接回」,你得額外走一趟去找 right 和 right + 1。而這裡反轉本身已經把它們掃過一次了,順手留在變數裡。

記法:反轉讓一段的頭尾對調 —— 所以前面接新頭(prev)、後面從新尾(tail->next)接出去。
A2. 因為第一行讀的 tail->next 就是第二行要寫的那個欄位。

tail->next->next = next; 的意思是「找到新段尾,把它接上後段」—— 而「新段尾」這個資訊只存在 tail->next 裡。
一旦先執行 tail->next = prev;,tail->next 就變成節點 4 了,通往節點 2 的唯一一條路被覆蓋掉。

對調後實際發生的事(以 [1,2,3,4,5], left=2, right=4):
tail->next = prev → 1 → 4;接著 tail->next->next = next 改的是 4->next,把 4 → 3 打成 4 → 5。
結果 [1,4,5] —— 節點 3 和 2 整段掉了。

實測:窮舉 n = 1..9 的全部 165 組,錯 120 組,最小反例 n=2, left=1, right=2 回傳 [2](正解 [2,1])。

答對的 45 組全部是 left == right —— 段長 1 時新段頭與新段尾是同一個節點,誰先誰後都一樣。所以「翻一個節點」這種測資永遠測不出這個 bug。
A3. 因為區間是閉區間,兩端都要算進去。

從第 left 個到第 right 個,含頭含尾,共 right − left + 1 個節點。left = 2, right = 4 是節點 2、3、4 —— 3 個,不是 2 個。

實測:寫成 right − left,窮舉 165 組全部 165 組都錯。
最小反例是 n=1, left=1, right=1:n 算成 0,反轉迴圈一圈都不跑,prev 保持 nullptr,於是 tail->next = prev 把整條串列砍成空的,回傳 [](正解 [1])。

這是三個陷阱裡最安全的一個:165/165 全錯代表隨便一筆測資都會炸,不可能矇混過關。真正危險的是 A4 那個只錯 36 組的。
A4. 它解決的是 left == 1 —— 而且就算把步數改對,忘了特判照樣會錯。

left == 1 時,要翻的段就從頭開始,而「頭的前一個」不存在。但 tail->next = prev 需要有個東西可以寫。dummy 就是憑空補上那一格,而 return dummy.next 順便處理了「頭被換掉」。

實測兩種拿掉 dummy 的方式(165 組):
· 直接把 tail = &dummy 換成 tail = head,步數不變 → 錯 120 組。整段定位偏一格,連 left > 1 都跟著壞。
· 步數也改對(走 left − 2 步),但忘了替 left == 1 寫特例 → 錯 36 組,而且那 36 組全部落在 left == 1 裡(該類共 45 組,僥倖答對的 9 組全是 left == right == 1,翻一個節點等於沒翻)。
· 步數改對 + 手動特判 left == 1 → 0 錯。合法,但要多一個 if 分支。

所以 dummy 買的不是正確性,是「少寫一個分支」 —— 它讓「翻頭」和「翻中間」變成完全同一段程式碼。而 36/165 這個低失敗率,正是它最危險的地方:隨手測幾筆很容易全部通過。
A5. 完全等價 —— 實測 0 錯。

反轉迴圈的最後一行是 curr = next;,所以每一圈結束時 curr 和 next 必定同值,迴圈跳出時當然也是。

實測:窮舉 n = 1..60 的全部 37820 組 (left, right),迴圈結束時 curr != next 的有 0 組;把接線那一行改成 curr,165 組錯 0 組。

但可讀性不等價:next 這個名字說的是「right 後面那個」,正是這一行的意圖;curr 只是碰巧同值的迴圈變數。面試時寫 next,順便講一句「這裡 curr 也一樣,因為迴圈末行剛把它同步了」—— 那句話本身就是在展示你知道迴圈的不變量。
App 1. 可以繞掉 —— 而這證明了那個限制是 aliasing 問題,不是語意問題。

在反轉之前(或之後,只要在改動 tail->next 之前)加一行:
ListNode* segTail = tail->next; // 舊段頭 = 未來的段尾,先抓住 ...反轉... segTail->next = next; tail->next = prev; // 這兩行現在誰先誰後都可以

實測:加了 segTail 之後,照原順序 165 組錯 0,兩行對調也是 165 組錯 0。

所以原本的順序限制,本質是「tail->next 這個欄位同時被當成資料來源和寫入目標」 —— 和 206 那個 next = curr->next; 必須先存的道理是同一個: 指標重接題裡,只要一個欄位既要讀又要寫,就先把它存進區域變數。

兩種寫法怎麼選?原碼少一個變數、更精簡,但順序成了隱性依賴;segTail 版多一行,但把依賴變成顯性的名字。面試我會寫 segTail 版,因為它自己解釋了自己。
App 2. 會 SEGV —— 而且是在反轉迴圈裡,不是在定位迴圈裡。

反轉迴圈的條件是 i < n,它完全不檢查 curr 是不是 nullptr —— 因為題目保證了 right ≤ n,節點一定夠。保證一旦拿掉,curr 會走出串列尾,然後 next = curr->next 就是對 nullptr 取成員。

實測(串列長度 3,呼叫 reverseBetween(head, 1, 5),ASan 編譯):
AddressSanitizer: SEGV on unknown address 0x000000000008 The signal is caused by a READ memory access. #0 in reverseBetween(ListNode*, int, int) oob.cpp:7 // 0x8 正是 ListNode::next 在物件裡的位移(val 4 bytes + padding)

崩在 next = curr->next; 那一行,和推理一致。

防護:把迴圈條件加上守衛 —— for (int i = 0; i < n && curr; i++),並在接線前檢查 tail->next 非空。

但更值得說的是:題目給的約束不是裝飾。1 ≤ left ≤ right ≤ n 這一行,買到的就是「反轉迴圈可以不寫任何 null 檢查」—— 和 19 靠 n ≤ sz 保證指標剛好停在 nullptr 是同一種「借來的安全」。
App 3. 兩行接線一字不改就能用 —— 只要加「檢查夠不夠 k 個」和「把 tail 往前推」。

LC 25 ↗ 就是「把 92 重複做很多次」,每一組的區間是 [1..k], [k+1..2k], …。多出來的只有兩件事:
① 開工前先數夠不夠 k 個(不足就整組保持原樣、直接結束);
② 這一組接完後,tail 要移到「這一組的新段尾」,也就是反轉前的段頭 —— 得在覆蓋 tail->next 之前先存下來。

ListNode* newTail = tail->next; // 舊段頭 = 這一組的新段尾 tail->next->next = next; // ← 和 92 完全同一行 tail->next = prev; // ← 和 92 完全同一行 tail = newTail; // 下一組從這裡繼續

注意 newTail 又是 App 1 那一招 —— 一個欄位既要讀又要寫,就先存起來。

實測:窮舉 n = 1..10 × k = 1..n 共 55 組,錯 0。
[1..9], k=3 → [3,2,1,6,5,4,9,8,7];[1..5], k=3 → [3,2,1,4,5](尾巴不足 3 個,保持原樣)。

這就是 92 值得寫熟的理由:它不是一道獨立的題,而是 LC 25(hard) 的內層迴圈。把這兩行接線練到手熟,25 就只剩「數夠不夠 k 個」這一件新事。
