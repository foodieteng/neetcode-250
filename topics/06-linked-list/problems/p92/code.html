完整實作// THE CODE

演算法與原碼一字未改,只修了記憶體(dummy 改放堆疊)。

p92.cpp C++17 
class Solution {
public:
    ListNode* reverseBetween(ListNode* head, int left, int right) {
        int n = right - left + 1;          // 段長,不是 right - left

        // dummy 是「頭的前驅」—— left == 1 時要改的就是它
        ListNode dummy(0, head);
        ListNode* tail = &dummy;

        // ── ① 定位:從 dummy 走 left-1 步,停在區間的前一個
        for (int i = 0; i < left - 1; i++) {
            tail = tail->next;
        }

        // ── ② 就地反轉 n 圈(這段和 206 迭代版一字不差)
        ListNode *prev = nullptr, *curr = tail->next, *next = nullptr;
        for (int i = 0; i < n; i++) {
            next = curr->next;
            curr->next = prev;
            prev = curr;
            curr = next;
        }

        // ── ③ 接回去,順序不能換
        tail->next->next = next;   // 舊段頭(= 新段尾)→ right 後面那個
        tail->next = prev;         // 前段 → 新段頭

        return dummy.next;
    }
};

為什麼 curr 和 next 在這裡可以互換

反轉迴圈的最後一行是 curr = next; —— 所以每一圈結束時 curr 和 next 必定相等, 迴圈跳出時當然也相等。

實測:窮舉 n = 1..60 的全部 37820 組 (left, right), 迴圈結束時 curr != next 的有 0 組。 兩種寫法都對 —— 但 next 讀起來更貼近意圖(「right 後面那個」),而 curr 只是碰巧同值。

注意最後兩個「拿掉 dummy」的失敗率:120 和 36。 36 那個更危險 —— 它只在 left == 1 時錯,而且 left == right == 1 還會僥倖答對, 隨手測幾筆很容易全部通過。而 165/165 全錯的 n 算錯,反而一測就發現。

原碼漏了 dummy// THE LEAK

原本寫的是 ListNode* dummy = new ListNode(); —— 而函式回傳的是 dummy->next, dummy 本身沒人指得到,也沒人 delete。

另解:頭插法// HEAD INSERTION

不先反轉再接,而是一邊把後面的節點一個一個「搬」到 tail 後面。 搬 n − 1 次就翻好了,而且完全不需要事後接線。

p92_headinsert.cpp 一樣 O(n) · O(1) 
ListNode* reverseBetweenHI(ListNode* head, int left, int right) {
    ListNode dummy(0, head);
    ListNode* tail = &dummy;

    for (int i = 0; i < left - 1; i++) {
        tail = tail->next;
    }

    // curr 固定不動 —— 它會一路被擠到區間尾巴
    ListNode* curr = tail->next;

    for (int i = 0; i < right - left; i++) {
        ListNode* mv = curr->next;   // 要搬走的那個
        curr->next = mv->next;      // 把它從原位摘掉
        mv->next   = tail->next;    // 插到 tail 後面
        tail->next = mv;
    }

    return dummy.next;
}
// 實測:窮舉 n=1..9 的全部 165 組 不一致：0 // 兩種寫法都對,而且都是一趟

頭插法每搬一個節點要改 3 根指標,三段式每翻一個只改 1 根 —— 所以段越長,三段式的常數優勢越明顯(翻整條時寫入約 3 倍差距)。 但兩者都是 O(n)、都是一趟、都是 O(1) 空間,面試寫哪個都行。 頭插法的賣點是「不需要事後接線」,少了本頁第 2 節那個順序陷阱。
