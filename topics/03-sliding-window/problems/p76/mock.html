Hmm, let me think about this for a second.

A naive approach would check every substring, which is at least O(n2) — too slow for 105.

This problem reminds me of a variable-length sliding window that shrinks while valid, the shortest-window pattern. I grow the right end r; once the window covers t, I shrink from the left, recording the shortest, until it stops covering.

The hard part is testing coverage in O(1). So I keep a counter, formed, for the number of distinct characters whose required count is met, and required, the number of distinct characters in t. The window covers t exactly when formed == required. Total time is O(m+n).

How do you update formed cheaply?

C
CANDIDATE

I initialize freq to what t needs, as positive counts.

On expand, --freq[s[r]]. Hitting exactly 0 means that character just got fully satisfied, so formed++. A surplus copy goes negative and doesn't trigger again.

On shrink, ++freq[s[l]]. Crossing above 0 means it's now short, so formed--.

Only the zero crossings move formed, so it's O(1) per step.

class Solution {
public:
    string minWindow(string s, string t) {
        unordered_map<char, int> freq;
        for (char c : t) freq[c]++;              // t's needs (positive)

        int required = freq.size();              // distinct chars in t
        int formed = 0, l = 0;
        int bestLen = INT_MAX, bestStart = 0;

        for (int r = 0; r < (int)s.size(); r++) {
            if (--freq[s[r]] == 0) formed++;     // exactly met → formed++

            while (formed == required) {         // covers t → shrink left
                if (r - l + 1 < bestLen) {
                    bestLen = r - l + 1;
                    bestStart = l;
                }
                if (++freq[s[l]] > 0) formed--;  // now short → formed--
                l++;
            }
        }

        return bestLen == INT_MAX ? "" : s.substr(bestStart, bestLen);
    }
};

freq starts as t's counts, required is the map's size, and one loop moves r, with an inner while that records the best window and then shrinks from the left. If bestLen is still INT_MAX at the end, nothing ever covered, so I return "".

One thing worth flagging — both comparisons are exact on purpose. formed goes up only when the count lands on == 0, not <= 0, or every surplus copy would count again. And formed goes down only when the count goes > 0, so dropping a surplus copy doesn't break coverage.
