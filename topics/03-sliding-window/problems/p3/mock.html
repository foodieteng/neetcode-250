A naive approach would enumerate every substring and check it — O(n2) or worse.

This problem reminds me of a variable-length sliding window. I expand r, and whenever the window contains a duplicate, I shrink from the left until it's valid again, tracking the max window length. Both pointers only move forward, so it's O(n).

The contrast with a fixed-size window: there you shrink by size; here I shrink by validity.

A count map over the window. After adding s[r], only that character can have just become a duplicate — everything else was already unique. So I check freq[s[r]] > 1, and shrink until it drops back to 1.

// window = s[l..r], freq = counts inside it
l = 0, freq = {}
for r = 0 .. n-1:
  freq[s[r]]++
  while freq[s[r]] > 1: freq[s[l++]]--
  maxL = max(maxL, r - l + 1)
// invariant: no duplicates after the while

One: l = 0, empty freq.
Two: for each r, add s[r] to the map.
Three: while freq[s[r]] > 1, drop the left end and move l forward; then update the max with r - l + 1.

One thing worth flagging — it's a while, not an if. The shrink isn't a fixed amount; it keeps going until the window is valid again. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. One loop over r: count the new character in, shrink from the left while it's duplicated, then record the window length.

class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int n = s.size();
        int maxL = 0, l = 0;
        unordered_map<char, int> freq;          // count of each char in the window

        for (int r = 0; r < n; r++) {
            freq[s[r]]++;                       // expand: take in s[r]

            while (freq[s[r]] > 1) {            // duplicate → shrink until valid
                freq[s[l++]]--;                  // drop the left end
            }

            maxL = max(maxL, r - l + 1);       // record the longest valid window
        }

        return maxL;
    }
};

The line that's easy to get wrong is the shrink — it has to be a while, because the old copy may sit several characters in.

A faster variant stores each character's last index, so l jumps instead of stepping — same O(n), smaller constant.

int lengthOfLongestSubstring(string s) {
    vector<int> last(128, -1);        // ASCII → index where it was last seen
    int maxL = 0, l = 0;
    for (int r = 0; r < (int)s.size(); r++) {
        if (last[s[r]] >= l)          // last copy still inside the window → skip it
            l = last[s[r]] + 1;       // l jumps right past the duplicate
        last[s[r]] = r;
        maxL = max(maxL, r - l + 1);
    }
    return maxL;
}

The key line there is the guard: only jump if last[s[r]] >= l — that last index is still inside the window.
