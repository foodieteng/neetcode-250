Hmm, let me think about this for a second.

A naive approach would rescan each window, which is O(n·k). A heap gets that down to O(n log k).

This problem reminds me of a monotonic deque — a decreasing deque of indices. Values from front to back are decreasing, so the front is always the window max.

Before pushing i, I pop from the back everything <= nums[i]. They're dominated by a later, larger element and can never be the max again. Then I pop the front if it slid out of the window. Each index is pushed once and popped at most once, so it's amortized O(n).

class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq;  // indices, values decreasing
        int n = nums.size();
        vector<int> ans;

        for (int i = 0; i < n; i++) {
            while (!dq.empty() && nums[i] >= nums[dq.back()]) dq.pop_back();
            while (!dq.empty() && i - k >= dq.front()) dq.pop_front();
            dq.push_back(i);

            if (i >= k - 1) ans.push_back(nums[dq.front()]);  // front = window max
        }

        return ans;
    }
};

One loop over i: two while loops clean the deque, one from the back by value and one from the front by index, then I push i, and once the first full window is formed I record the front's value.

One thing worth flagging — the expiry test is i - k >= dq.front(). The window covers [i-k+1, i], so index i-k is the first one out. Also, popping on >=, not just >, drops equal values early — an older equal value would expire first anyway.
