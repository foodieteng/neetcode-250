Hmm, let me think about this for a second.

A naive approach would take every window of s2 with the same length as s1, sort it, and compare it with sorted s1. That's roughly O(n · m log m) work, which turns quadratic when both strings are long.

This problem reminds me of a fixed-length sliding window. The target length is fixed at m = |s1|, so I slide a window of exactly m letters across s2, keep a 26-letter count, and compare it with s1's count. Neighboring windows differ by one letter in and one letter out, so each update is O(1), and the whole scan is O(n).

I
INTERVIEWER

How is this window different from a variable-size window that grows and shrinks?

C
CANDIDATE

A variable window grows and shrinks depending on whether it's valid. Here the size is exactly fixed — l and r move in lockstep, one letter in and one letter out each step, so there's no while loop to shrink it.

I think of three flavors: exactly fixed, like this one; bounded, where the window is only capped at a maximum size; and fully variable.

One: if |s1| > |s2|, return false right away.
Two: build s1Map and the first window's cmp, and compare once.
Three: for r from m to the end, add the letter at r, remove the letter at l and move l forward, then compare.

One thing worth flagging — the first-window compare is easy to forget, and without it an answer that starts at index 0 is missed. This is O(n) time and O(1) space. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. Two arrays of 26 counts: s1Map for the target, and cmp for the current window.

class Solution {
public:
    bool checkInclusion(string s1, string s2) {
        if (s1.size() > s2.size()) return false;

        vector<int> s1Map(26, 0), cmp(26, 0);

        for (int i = 0; i < s1.size(); i++) {
            s1Map[s1[i] - 'a']++; cmp[s2[i] - 'a']++;   // target + first-window counts
        }

        if (s1Map == cmp) return true;                       // first window is a permutation

        int l = 0;
        for (int r = s1.size(); r < s2.size(); r++) {
            cmp[s2[r] - 'a']++; cmp[s2[l++] - 'a']--;   // add right + remove left (lockstep)

            if (cmp == s1Map) return true;                   // counts equal → permutation
        }

        return false;
    }
};

The first loop fills both over the first m letters, then I compare once. The main loop adds the right letter and removes the left letter on one line, so the window shifts by exactly one and its size never changes.

One thing worth flagging — the l++ inside the remove reads the old left letter first, then moves l, which keeps l and r exactly m apart.

To make each step strictly O(1) instead of a 26-element compare, I could track how many letters currently match, and answer when that count reaches 26:

// win[in]++; if (win[in] == need[in]) matches++;
// else if (win[in] == need[in] + 1) matches--;   (symmetric on removal)
// answer when matches == 26
