Hmm, let me think about this for a second.

A naive approach would try every buy/sell pair. That's O(n2) — about 1010 steps, way too slow.

The key insight is to fix the sell day. To maximize prices[s] - prices[b], I just want the smallest price to the left of today.

This problem reminds me of a running-minimum scan — really a sliding window whose left edge is pinned to the cheapest day so far. One left-to-right pass, keep minPrice, and at each day compute the "sell today" profit against it. That's O(n) time and O(1) space.

// state: minPrice = cheapest day so far
minPrice = prices[0], maxProfit = 0
for i = 1 .. n-1:
  maxProfit = max(maxProfit, prices[i] - minPrice) // old min
  minPrice  = min(minPrice, prices[i])
return maxProfit

One: start with minPrice = prices[0] and maxProfit = 0.
Two: for each later day, first update maxProfit with prices[i] - minPrice, using the old minimum.
Three: then lower minPrice with today's price.

One thing worth flagging — the order. Profit first means the buy is always on an earlier day. Swapping the two lines would only add a same-day trade worth 0, so the answer survives, but this order states the rule directly. Does this approach sound good, or would you rather I think of another way?

Alright, here's the running-minimum version. One loop from day 1: update the best profit, then lower the minimum.

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int maxProfit = 0, minPrice = prices[0], n = prices.size();

        for (int i = 1; i < n; i++) {
            maxProfit = max(maxProfit, prices[i] - minPrice);  // sell today, buy at the lowest so far
            minPrice = min(minPrice, prices[i]);            // then update the lowest buy price
        }

        return maxProfit;
    }
};

The easy line to get wrong is the start value — maxProfit must start at 0, not INT_MIN, so a falling market returns 0 instead of a loss.

There's also an equivalent Kadane view. On the day-to-day difference array, the profit of holding a stretch telescopes to the sum of its daily changes. So max profit is the maximum subarray sum: extend the held stretch, or restart.

int maxProfit(vector<int>& prices) {
    int cur = 0, best = 0;
    for (int i = 1; i < (int)prices.size(); i++) {
        int diff = prices[i] - prices[i - 1];   // today's change vs yesterday
        cur = max(diff, cur + diff);             // Kadane: extend the stretch or restart
        best = max(best, cur);
    }
    return best;
}

Let me think about complexity here.

Time is O(n) — a single pass with two constant-time operations per day. Space is O(1) — two scalars, no prefix array needed.

Oh, one more thing — the natural follow-ups.
• Unlimited transactions: the answer is the sum of every positive daily change.
• At most two: a small state machine — buy1, sell1, buy2, sell2 — updated each day, still O(1) space.
• At most k: the same idea with k pairs of states.

All the same backbone: one pass, tracking running extremes.
