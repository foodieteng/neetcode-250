A naive approach would compare each index with the next k, which is O(n·k) — up to 1010 here, too slow.

This problem reminds me of a sliding window with a hash set: abs(i - j) <= k is a proximity constraint, and "a duplicate within distance k" is exactly "a duplicate inside some window of length k+1". So I keep the last k+1 values in a hash set; if the incoming value is already there, its earlier copy is within k. That's O(n).

One: for each r, first shrink — while r - l > k, evict nums[l] and advance l.
Two: then insert/check nums[r] — if it was already present, return true.
Three: reach the end with no hit → false.

One thing worth flagging — order matters: shrink before checking, so stale far-away values are gone first.

Alright, let me code this up. I'll use a count map with an explicit left pointer; a value hitting count 2 means two copies coexist in the window.

class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        int n = nums.size(), l = 0;
        unordered_map<int, int> freq;          // count of each value in the window

        for (int r = 0; r < n; r++) {
            while (r - l > k) {                   // window longer than k+1 → shrink
                freq[nums[l++]]--;              // evict leftmost value, advance l
            }

            if (++freq[nums[r]] == 2) return true;  // a value reaches 2 after adding → hit
        }

        return false;
    }
};

The while loop evicts from the left until r - l <= k, then I increment the count for nums[r] and return true if it becomes 2.

One thing worth flagging — the shrink sits before the increment, so when I check, the window only holds indices within k of r. An equally clean variant uses a set: if (r > k) window.erase(nums[r - k - 1]); and a failed window.insert(nums[r]) means a hit.
