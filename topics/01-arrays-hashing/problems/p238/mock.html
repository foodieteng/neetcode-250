The brute force multiplies everything else for every index, which is O(n²).

This problem reminds me of prefix and suffix products: answer[i] = prefix(left of i) × suffix(right of i). Two linear sweeps compute both. And if I write the prefixes into the output array first, then fold the suffixes in on a reverse pass, I only need two scalar variables — O(1) extra space.

One: start the answer array as all ones.
Two: sweep left to right with a running prefix, multiplying it into each cell.
Three: sweep right to left with a running suffix, the same way.

One thing worth flagging — in each pass I write to the answer before updating the running product. That way the stored value excludes nums[i] itself, and the update folds it in for the next index.

And it's naturally zero-safe: with no division, a zero only wipes out the positions whose left or right span crosses it, so no special casing. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n, 1);

        int prefix = 1;                    // Pass 1: left→right, left product
        for (int i = 0; i < n; i++) {
            ans[i] *= prefix;          // write the left product (excl. self) first
            prefix *= nums[i];         // then fold self into the running product
        }

        int suffix = 1;                    // Pass 2: right→left, right product
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= suffix;          // multiply in the right product (excl. self)
            suffix *= nums[i];         // then fold self into the running product
        }
        return ans;
    }
};

Two loops: the forward one multiplies each cell by the running prefix, then folds nums[i] into the prefix; the backward one does the same with the suffix.

One thing worth flagging — ans starts as all 1s, so the very first *= works. If it started at 0, everything would stay zero. And the whole thing reuses ans as scratch, so the extra space is just two ints.
