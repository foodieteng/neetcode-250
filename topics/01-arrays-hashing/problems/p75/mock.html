This problem reminds me of three-way partitioning, the same step quicksort uses to group keys equal to the pivot.

Three pointers: l = boundary of the 0-region, i = scanner, r = boundary of the 2-region. I maintain four zones: [0,l) all 0s, [l,i) all 1s, [i,r] unexamined, (r,n) all 2s. As i scans, I route each value to its zone.

CANDIDATE

Here's the plan.

// l=0, i=0, r=n-1; while i <= r
nums[i]==0: swap(i,l); l++; i++
nums[i]==2: swap(i,r); r--  // i stays!
nums[i]==1: i++

One: start l and i at 0, r at the last index, and loop while i <= r.
Two: on a 0, swap it to l, and move both l and i forward.
Three: on a 2, swap it to r and pull r back, but leave i where it is; on a 1, just move i.

The crux is the asymmetry. On a 0, I advance i after the swap, because l sits in the already-scanned 1-zone, so whatever comes back is a 1, already handled. On a 2, I do not advance i — the element swapped in from r comes from the unexamined zone, so I must re-check it next iteration.

Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    void sortColors(vector<int>& nums) {
        int i = 0, l = 0, r = nums.size() - 1;   // l = 0-boundary, i = cursor, r = 2-boundary

        while (i <= r) {
            if (nums[i] == 0) {
                swap(nums[i], nums[l]);          // move the 0 to the left boundary
                l++; i++;                        // what comes back must be a 1 → advance i
            } else if (nums[i] == 2) {
                swap(nums[i], nums[r]);          // move the 2 to the right boundary
                r--;                             // i stays! the swapped-in value is unchecked
            } else {
                i++;                             // a 1 stays in the middle, just advance
            }
        }
    }
};

It's one while loop with three branches: a 0 swaps left and advances both l and i; a 2 swaps right and only pulls r back; a 1 just advances i.

The line that's easy to get wrong is the 2 branch — writing i++ there out of habit would skip the swapped-in value, and if that's a 0 it stays stuck in the middle.

One detail worth flagging — l ≤ i always holds, so the 0-swap is safe even when i == l; it just swaps the element with itself.

Time is O(n) — each step advances i or pulls back r, so r - i shrinks every iteration: at most n steps, one pass. Space is O(1) — three pointers, in place.

One more thing — this is exactly a three-way quicksort partition with pivot = 1, which is the standard trick for arrays with many duplicate keys. For k distinct values instead of 3, I'd switch to a two-pass counting sort.
