This problem reminds me of the hold/free state machine, the dynamic program behind the whole stock family — always correct, O(n). But here, with unlimited transactions and no fee or cooldown, it collapses into a one-line greedy: sum every positive day-over-day difference.

Why that's optimal — any buy-at-day-a, sell-at-day-b profit p[b] − p[a] telescopes into the sum of the daily differences in between. So the best I can ever get is the sum of all the positive differences, and the greedy hits exactly that.

Three: return the total.

One thing worth flagging — the "hold at most one share" rule doesn't bind. Each positive difference is a buy-yesterday, sell-today, so I never hold more than one share at once. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        int mx = 0, start = prices[0];       // start = previous day's price

        for (int i = 1; i < n; i++) {
            if (start < prices[i])            // today higher than yesterday
                mx += prices[i] - start;     // harvest this rise
            start = prices[i];               // advance the previous day
        }
        return mx;
    }
};

For each day from the second one on, if start is lower than today's price, I add the rise to mx. Then start moves to today's price.

One thing worth flagging — start advances on every iteration, whether or not I profited, so I'm always comparing consecutive days. If it only moved after a gain, then on [7,1,5] it would stay stuck at 7 and miss the +4.
