A naive approach would try every start/end pair with a running sum — O(n²). With n up to 2×104, n² is 4×108, too slow.

This problem reminds me of prefix sums paired with a hash map of counts. The sum of a subarray is the prefix at its end minus the prefix just before its start. Setting that equal to k means the earlier prefix must equal prefix − k. So at each position, I just need how many earlier prefixes equal prefix − k — and a hash map of prefix-sum frequencies answers that in O(1).

CANDIDATE

Here's the plan.

// freq: prefix sum → count of occurrences
freq[0] = 1 // seed: empty prefix
prefix = 0, cnt = 0
for num in nums:
  prefix += num
  cnt += freq[prefix - k] // COUNT first
  freq[prefix] += 1 // then RECORD

One: seed the map with the empty prefix — freq[0] = 1.
Two: for each number, add it to the running prefix, then add freq[prefix − k] to the answer.
Three: only after that, record the current prefix in the map.

Two subtleties worth flagging. First, the seed is what counts subarrays starting at index 0 — without it, [1,2], k = 3 would be missed. Second, count before recording — if I inserted the current prefix first, then with k = 0 I'd match myself and count an empty subarray at every step. And I add the frequency, not 1, because a prefix sum can recur when there are negatives or zeros. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. One map from prefix sum to how many times it's been seen, seeded with zero once.

class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> freq;       // prefix sum → times seen
        int prefix = 0, cnt = 0;
        freq[0] = 1;                        // seed: empty prefix

        for (int num : nums) {
            prefix += num;                     // prefix sum up to here
            if (freq.count(prefix - k))        // look up first: earlier prefixes = prefix−k
                cnt += freq[prefix - k];     // add the count, not 1
            freq[prefix] += 1;              // then record: register self
        }
        return cnt;
    }
};

In the loop, I extend the prefix, look up prefix - k and add its count, then record the prefix.

One thing worth flagging — the line cnt += freq[prefix - k] must use the stored frequency, not +1; that's what handles repeated prefixes. On overflow: prefix is at most 2×104 values of at most 1000 each, so 2×107 in size — comfortably inside an int.
