Let me think about the constraints for a second.

The naive route is a hash set of all values, then probe 1, 2, … until one is missing — O(n) time, but O(n) space, which breaks the space rule. Sorting is O(n log n), which breaks the time rule.

This problem reminds me of cyclic sort. Since the answer lives in [1, n+1], the array indices themselves can act as the hash table: put value v at index v-1, and the first index whose value doesn't match is the gap.

P — plan
C
CANDIDATE

Here's the plan.

// invariant: value v belongs at index v-1
for each element, carry its value x:
  while 1 ≤ x ≤ n AND x != nums[x-1]:
    swap(x, nums[x-1]) // place x home, pick up displaced
then scan: first i with nums[i] != i+1 → return i+1
else return n+1

One: walk the array, carrying each value x in hand.
Two: while x is in [1, n], and its home, index x-1, doesn't already hold x, swap x into its home and pick up whatever was there.
Three: scan for the first index i where nums[i] != i+1, and return i+1; if there is none, return n+1.

One thing worth flagging — the guard x != nums[x-1] is load-bearing. Without it, a duplicate like [1,1] swaps 1 with an already-correct 1 forever — an infinite loop.

And the nested while looks like O(n²), but each swap fixes one value into its final home for good, so there are ≤ n swaps — amortized O(n). Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();

        for (int x : nums) {                       // x = the value in hand
            while (1 <= x && x <= n && x != nums[x - 1]) {
                swap(x, nums[x - 1]);    // put x home; x picks up the old value
            }
        }

        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) return i + 1;  // first mismatch → answer
        }
        return n + 1;                          // 1..n all present
    }
};

The outer loop picks up each element; the while swaps x into its home and carries the old value onward, until x is out of range or already home. Then one scan finds the first mismatch.

One detail worth flagging — the range check 1 <= x && x <= n must come before touching nums[x-1]; otherwise a negative or oversized x indexes out of bounds. The short-circuit && makes that order safe.
