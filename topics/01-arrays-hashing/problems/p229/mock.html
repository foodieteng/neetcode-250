A naive approach would count everything in a hash map — O(n) time, but O(n) space too, so it fails the follow-up. Sorting costs O(n log n).

This problem reminds me of Boyer-Moore majority voting, extended to two candidates. The classic vote finds a value that fills more than half the array with one candidate slot. Since at most two elements can clear a third, I keep two (candidate, count) slots instead of one.

Here's the plan, in two phases.

// phase 1: vote → 2 candidates
for num:
  if num == c1: cnt1++
  elif num == c2: cnt2++
  elif cnt1 == 0: c1 = num, cnt1 = 1
  elif cnt2 == 0: c2 = num, cnt2 = 1
  else: cnt1--, cnt2-- // 3rd distinct value
// phase 2: verify by real count > n/3

One: keep two candidate slots, each with a count.
Two: for each number, if it matches a candidate, bump that count; else if a slot is empty, adopt the number there; otherwise it's a third distinct value, so decrement both counts.
Three: in a second pass, count the two candidates for real, and keep each one that appears more than n/3 times.

One thing worth flagging — and this is the big difference from the more-than-half version — voting alone isn't enough. A candidate can survive the vote without truly qualifying, so I must verify with a real count. In the more-than-half version a majority is guaranteed to exist; here it isn't. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    vector<int> majorityElement(vector<int>& nums) {
        int c1 = 0, cnt1 = 0, c2 = 0, cnt2 = 0;

        // ── pass 1: vote, narrow down to 2 candidates ──
        for (int num : nums) {
            if (num == c1) cnt1++;              // matches c1
            else if (num == c2) cnt2++;         // matches c2 (compare values first)
            else if (cnt1 == 0) { c1 = num; cnt1++; }  // c1 empty → adopt
            else if (cnt2 == 0) { c2 = num; cnt2++; }  // c2 empty → adopt
            else { cnt1--; cnt2--; }          // third value → decrement both
        }

        // ── pass 2: verify the real counts ──
        cnt1 = 0, cnt2 = 0;
        for (int num : nums) {
            if (num == c1) cnt1++;
            else if (num == c2) cnt2++;
        }

        vector<int> ans;
        if (cnt1 > nums.size() / 3) ans.push_back(c1);
        if (cnt2 > nums.size() / 3) ans.push_back(c2);
        return ans;
    }
};

The first loop is the vote, with four integers: two candidates and their counts. The second loop resets the counts and recounts the two candidates, and I push each one whose count beats nums.size() / 3.

One thing worth flagging — the two == match checks must come before the two empty-slot checks. If an empty slot were checked first, a number already held in the other slot could be adopted again, and the same value would sit in both slots, wasting one.
