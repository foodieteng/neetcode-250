// prefix sized (m+1)x(n+1), padded row/col of 0
build: prefix[i][j] = up + left − upLeft + matrix[i-1][j-1]
query: prefix[r2+1][c2+1] − prefix[r1][c2+1]
       − prefix[r2+1][c1] + prefix[r1][c1]

One: allocate prefix with one extra row and column of zeros.
Two: build each cell as up + left − up-left + the matrix cell.
Three: answer a query with the four-corner formula.

Two things worth flagging. First, I pad with a zero row and column and shift indices by +1 — that way queries touching the top or left edge read zeros from prefix[0][…] or prefix[…][0], with no special-casing. Second, both formulas are the same inclusion-exclusion: the build subtracts the double-counted top-left, the query adds back the double-subtracted corner.

Let me write it. The constructor sizes prefix to (m+1) × (n+1), all zeros, then fills it with the up + left − up-left recurrence. sumRegion is a single return with four corners.

class NumMatrix {
public:
    int m, n;
    vector<vector<int>> prefix;

    NumMatrix(vector<vector<int>>& matrix) {
        m = matrix.size(), n = matrix[0].size();
        prefix.assign(m + 1, vector<int>(n + 1, 0));  // pad one ring of 0

        for (int i = 1; i <= m; i++)
            for (int j = 1; j <= n; j++)            // build: up + left − upLeft + self
                prefix[i][j] = prefix[i-1][j] + prefix[i][j-1]
                             - prefix[i-1][j-1] + matrix[i-1][j-1];
    }

    int sumRegion(int r1, int c1, int r2, int c2) {      // query: four corners
        return prefix[r2+1][c2+1] - prefix[r1][c2+1]
             - prefix[r2+1][c1] + prefix[r1][c1];
    }
};

That matches the plan. One detail worth flagging — the shift: prefix[i][j] covers the matrix up to (i-1, j-1), so the query reads r2+1 and c2+1 for the bottom-right, but plain r1 and c1 for the cut lines. The build happens once in the constructor; sumRegion is just four lookups and three additions.
