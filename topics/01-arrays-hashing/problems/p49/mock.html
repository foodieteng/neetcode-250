Let me think about how to group efficiently.

Comparing every pair for anagram-ness is O(N²·L) — too slow at N=10⁴.

This problem reminds me of hash grouping by a canonical key: compute each string's sorted form as a key and bucket into a hash map. Anagrams collide into the same bucket automatically.

Here's the plan.

// map: sorted(w) → list of original words
for w in strs:
  key = sorted(w)
  map[key].push_back(w)
return map.values()

One: make a map from sorted key to the list of original words.
Two: for each word, sort a copy to get its key, and push the word into that bucket.
Three: return all the buckets.

One thing worth flagging — I sort a copy for the key and push the original word into the bucket, so the output keeps the input strings intact.

A trade-off worth mentioning — sorting the key is O(L log L). I could instead use a 26-letter count as the key for O(L) per word, giving O(N·L) overall. For L ≤ 100 the sorted key is simpler and plenty fast, but I'd switch to counts if strings were long.

Does this approach sound good, or would you rather I think of another way?

Let me write the sorted-key version.

class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> group;

        for (auto w : strs) {
            string key = w;
            sort(key.begin(), key.end());   // canonical fingerprint = sorted string
            group[key].push_back(w);        // drop into its bucket
        }

        vector<vector<string>> ans;
        for (auto [k, v] : group)           // collect every bucket
            ans.push_back(v);
        return ans;
    }
};

One pass builds the buckets: copy the word, sort the copy, and append the original under that key. A second loop collects every bucket into the answer.

The line that's easy to get wrong is string key = w; — sorting w itself would put scrambled letters into the output instead of the real words. Both loops take the word and the bucket by value, so they copy; that's fine at this size.
