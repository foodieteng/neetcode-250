Two: put each value into the bucket for its frequency.
Three: scan the buckets from n down and collect values until I have k.

Two things worth flagging. First, the bucket array is size n+1, because the max frequency is n when all elements are equal. Second, I scan high to low and stop the moment I have k — the index encodes the ordering, so no sort or heap is needed.

Let me write it. Three blocks: count into a hash map, push each value into the bucket at its frequency, then walk the buckets from n downward, collecting into result.

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        int n = nums.size();
        unordered_map<int, int> counts;
        for (int x : nums) counts[x]++;              // ① count

        // ② buckets[f] = values seen f times (size n+1: max freq is n)
        vector<vector<int>> buckets(n + 1);
        for (auto const& [val, freq] : counts)
            buckets[freq].push_back(val);

        vector<int> result;
        // ③ collect from the highest-frequency bucket downward
        for (int i = n; i >= 0 && result.size() < k; --i) {
            for (int num : buckets[i]) {
                result.push_back(num);
                if (result.size() == k) break;
            }
        }
        return result;
    }
};

That matches the plan. One detail worth flagging — the outer condition result.size() < k plus the inner break both stop as soon as I have k. The break only leaves the current bucket; the outer check is what stops the next one from opening. So I never touch the low-frequency buckets.
