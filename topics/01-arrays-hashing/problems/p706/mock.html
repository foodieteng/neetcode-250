Let me think about the sentinel.

This problem reminds me of direct addressing: when keys are small, dense integers, the key itself can be the array index, so there's no hashing and no collisions.

A set marks "present" with a bit; a map has to store the value and still tell "absent" apart. Since values are ≥ 0, filling the array with -1 gives a clean "absent" marker that no real value can collide with. If get reads -1, the key was never put.

One thing worth flagging — it all rides on values being ≥ 0. If values could be -1, I'd need a separate presence array.

Alright, let me code this up.

class MyHashMap {
public:
    vector<int> mp;

    MyHashMap() {
        mp.assign(1000001, -1);      // all -1 = no mapping
    }

    void put(int key, int value) {
        mp[key] = value;            // store / overwrite
    }

    int get(int key) {
        return mp[key];            // -1 means absent
    }

    void remove(int key) {
        mp[key] = -1;              // reset to sentinel
    }
};

The constructor fills 1000001 slots with -1, and each method is a single array access.

The size is the line that's easy to get wrong: keys go up to 106 inclusive, so the array needs 1000001 slots, or the largest key goes out of bounds.

Every operation is O(1), and put handles insert and update identically — it just overwrites the slot.

What if the value could be any integer, including -1?

C
CANDIDATE

Then a single sentinel breaks — put(k, -1) would be indistinguishable from "absent." I'd split existence from value with a parallel presence array:

vector<int>  val;       // any value
vector<bool> present;   // does this key map?
void put(int k, int v) { val[k] = v; present[k] = true; }
int  get(int k) { return present[k] ? val[k] : -1; }
void remove(int k) { present[k] = false; }

Now the value can be anything — the boolean carries existence separately. And for unbounded keys, I'd use buckets of list<pair<int,int>>, indexed by key % prime, where put scans the bucket to update or insert — that's unordered_map in miniature.

put(1,1), then get(1) returns 1, and get(3) returns -1, since it was never put. The row that matters is the last one: put key 2, overwrite it, then remove(2) — get(2) returns -1.

"Never put" and "put then removed" both return -1. For a map both are "absent," so the shared sentinel is correct.

C
CANDIDATE

Direct addressing is O(1) per operation. Space is O(range) — a vector<int> of 106 is about 4 MB, 32× a bit-packed hash set's 125 KB, because each slot holds a 32-bit int instead of one bit.

Oh, one more thing — a set is just a map whose value is one bit. And whenever the key range is small and dense, a plain array beats a hash map — no hashing, no collisions, cache-friendly, worst-case O(1). That's exactly why anagram-style problems use int cnt[26]. The array is the map when keys are indices.
