Let me think about how to get linear time.

This problem reminds me of hash-set membership — put everything in a hash set, and every lookup is O(1). A naive idea is, for each number, walk right counting x+1, x+2, …. That's O(n²) on [1..n], because every number re-walks the whole run.

The fix: only start counting from a run's left end — a number x where x-1 is not in the set. Then each run is walked exactly once.

// seen = set(nums)

One: put all the numbers in a set called seen.
Two: for each value in the set, skip it if its left neighbor is also in the set.
Three: otherwise walk right while the next value exists, and keep the longest length.

One thing worth flagging — the key line is the skip, if (s-1) in seen: continue. Without it, the answer is still correct, but it degrades to O(n²). With it, the amortized cost is O(n): each number is examined once by the outer loop, and walked once by its run's start, so the inner while steps total n.

One more thing — I iterate the set, not the array, so duplicates don't cause repeated examinations. Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        unordered_set<int> seen(nums.begin(), nums.end());  // dedupe + O(1) lookup
        int maxL = 0;

        for (int s : seen) {
            if (seen.count(s - 1)) continue;   // s-1 present → not a start, skip

            int curL = 0;
            while (seen.count(s)) {       // count right from the start
                s++; curL++;
            }
            maxL = max(maxL, curL);
        }
        return maxL;
    }
};

I build the set straight from the array, which dedupes it. Then for each value, if s - 1 is in the set, I continue; otherwise I count right from s and update the max.

One thing worth flagging — s is a by-value copy in the range-for, so incrementing it inside the while doesn't disturb the outer iteration over the set.
