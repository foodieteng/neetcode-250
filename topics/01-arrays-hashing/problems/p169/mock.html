Let me think about the space constraint.

A naive approach would count with a hash map — O(n) time, but O(n) space too. Sorting and taking nums[n/2] is O(n log n). To hit O(n) time and O(1) space, I need something smarter than counting everything.

This problem reminds me of the Boyer-Moore voting algorithm, a cancellation pattern, and it fits because the majority outnumbers everyone else combined. The intuition: pair up two different elements and cancel them. Since the majority can't be fully cancelled, whatever survives is the answer.

I
INTERVIEWER

How do you simulate that cancelling with O(1) space?

C
CANDIDATE

Keep a candidate and a count. For each element: if the count is 0, adopt this element as the candidate with count 1; if it equals the candidate, increment — that's reinforcing; otherwise decrement — an opposing vote cancels one.

The key point is that count isn't the candidate's true frequency. It's how far ahead the current candidate is. When it hits zero, the lead is wiped out, and the next element starts fresh.

One: start with cnt = 0.
Two: for each number, adopt it when cnt == 0, add one when it matches the candidate, subtract one when it doesn't.
Three: return the candidate.

Since existence is guaranteed, one pass is enough — no verification needed. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. Two scalars, cnt and candidate, and one loop with three exclusive branches: adopt, reinforce, or cancel. Then I return the candidate.

class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int cnt = 0, candidate = 0;

        for (int num : nums) {
            if (cnt == 0) {                 // no candidate → adopt
                cnt++; candidate = num;
            } else if (candidate == num) {  // same vote → reinforce
                cnt++;
            } else {                        // opposing vote → cancel
                cnt--;
            }
        }
        return candidate;                   // majority can't be cancelled, it wins
    }
};

One thing worth flagging — the cnt == 0 check has to come first, and the branches are an if / else if chain. A freshly adopted element starts at 1; it must not fall through and get compared again in the same step. Also, the starting candidate = 0 is just a placeholder — the first element always replaces it.

That's O(n) time and O(1) space, with two scalars and one pass.

Then this candidate is only "the one that survived" — not necessarily a true majority. Boyer-Moore guarantees that if a majority exists, it must be this candidate, but it can't prove that one exists.

So I'd add a second pass, counting the candidate's actual occurrences, and return it only if that count is > n/2; otherwise, report none. That's still O(n) time and O(1) space. Here existence is promised, so I skip it.

Time is O(n), space is O(1) — exactly the follow-up. There's no early exit, so every case reads each element exactly once.

Oh, one more thing — it generalizes nicely. For elements that appear more than n/3 times, there can be at most two, so you run Boyer-Moore with two candidates and two counters, decrementing both on an unmatched vote. There, the verification pass becomes mandatory.

And because it keeps only O(1) state and never looks back, it's a genuine single-pass streaming algorithm — you could run it over a data stream too large to store.
