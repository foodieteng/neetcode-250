Find Median from Data Stream

題目簡介// THE QUESTION

QUESTION

設計 MedianFinder:addNum(num) 把一個整數加進資料流,findMedian() 回傳目前所有數字的中位數(個數是偶數時取中間兩個的平均)。
-10⁵ ≤ num ≤ 10⁵,呼叫 findMedian 時至少有一個數,兩種操作合計最多 5 × 10⁴ 次。

範例:addNum(1), addNum(2) → findMedian() = 1.5;再 addNum(3) → findMedian() = 2.0。 難的不是算中位數,而是「每加一個數都要能馬上回答」,不能每次重新排序。

中位數只和「中間那一兩個數」有關。 把資料切成「較小的一半」和「較大的一半」,只要隨時拿得到小半的最大值、大半的最小值就夠了。
2

為什麼是「兩個堆」// WHY THIS

A 每次 findMedian 都複製一份再排序 O(n log n) / 次
最直覺,但每問一次就重排一次。 5 萬次 add + find 實測約 65.6 秒。
× REJECT · TLE
B 維持一個排好序的 vector,二分插入 O(n) / add
找位置 O(log n),但插入要把後面整段往後搬。記憶體搬移很快,5 萬次實測 43 ms 其實會過; 只是本質是 O(n²),n = 2 × 10⁵ 就變 763 ms。
△ REJECT · 能過但面試要說得出更好的
BOTH FAIL · ADOPT
C 較小的一半放最大堆、較大的一半放最小堆 O(log n) · O(1)
兩個堆的 top 剛好是「小半的最大」和「大半的最小」—— 中位數就是其中一個,或兩個的平均。 add 只動幾次 push / pop,find 只看兩個 top。5 萬次實測 0.2~6 ms,和排序答案對拍 410 萬次查詢 0 錯。
● ADOPT · 每個堆內部不用排序,只要 top 對
和 703 資料流第 k 大 是同一種想法:堆不用整個排好,只要堆頂剛好是答案需要的那個數。 703 用一個堆夾住「第 k 大」,這題用兩個堆從兩邊夾住「中間」。
3

核心策略 · 兩條不變量// THE SHAPE

  1. 順序:左堆(最大堆)的每個數 ≤ 右堆(最小堆)的每個數 —— 只要檢查 左.top ≤ 右.top。
  2. 數量:左.size() == 右.size() 或多 1 —— 奇數個時中位數就是 左.top。
  3. findMedian:左邊多一個就回 左.top,一樣多就回 (左.top + 右.top) / 2。

兩種 add 寫法維護的是同一組不變量,差別只在「先顧哪一條」:

寫法先做什麼再做什麼
我的版本依 size 決定放哪邊(先顧數量)兩個 top 亂序就交換一次(修順序)
精簡版一律進左邊,再把左邊最大的送到右邊(先顧順序)右邊比較多就送回一個(修數量)

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 我的版本:交換一次就夠

加之前兩條不變量都成立。新數 x 放進某一邊後,只有 x 可能站錯邊,其他數彼此之間還是左 ≤ 右。 如果 x 進了左邊又比右 top 大,它一定是左邊新的 top(左邊其他數都 ≤ 右 top < x)。對調之後: 右 top 是右邊最小的,搬到左邊仍然 ≤ 右邊剩下的每個數;x 比左邊每個數都大,搬到右邊也不會破壞「左 ≤ 右」。 x 進右邊、比左 top 小的情況完全對稱。交換是各 pop 一個、push 一個,size 不變,所以數量那條也沒被破壞。 窮舉長度 1~8、值 -2~2 的所有資料流(488,280 條)0 錯。

LEMMA 2 · 先轉 double 再相加

我寫的 double(mxH.top() + miH.top()) 是先用 int 相加、再轉 double。 這題 |num| ≤ 10⁵,和最多 200,000,完全安全;但如果值可以到 INT_MAX,實跑會得到 -1.0(UBSan 報 signed overflow)。 寫成 (a + (double)b) / 2.0 就是 2147483647.0,好習慣。

一句洞察// INSIGHT

中位數被兩個 top 夾住:小半用最大堆、大半用最小堆,維持「左 ≤ 右」和「左比右多 0 或 1 個」。 先顧數量再交換(我的版本),或先顧順序再補平衡(精簡版),都是 O(log n)。
