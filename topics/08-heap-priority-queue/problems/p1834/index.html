題目簡介// THE QUESTION

QUESTION

tasks[i] = [enqueueTime, processingTime]:任務 i 在 enqueueTime 才能開始處理,要花 processingTime。 CPU 一次只做一個、開始了就做完;閒下來時,從已經到達的任務中挑處理時間最短的,一樣短就挑 index 小的;沒有任務可做就閒著等。 回傳處理的順序。
1 ≤ n ≤ 10⁵,1 ≤ enqueueTime, processingTime ≤ 10⁹。

這是一個模擬題:要追蹤「現在幾點」,把到了的任務收進候選,每次挑最短的做。 兩件事要做好:時間怎麼前進,以及候選怎麼快速挑出最短的。

時間 t 只能往前走:做完一個任務 t += processingTime;沒有任務可做時,跳到下一個任務的到達時間 —— 但只能往前跳,不能往回拉。 候選任務放進以 (processingTime, index) 排序的最小堆,堆頂就是下一個要做的。

為什麼是「排序 + 最小堆」// WHY THIS

A 每次掃過所有任務挑最短的 O(n²)
最直接,驗證時就拿它當對拍的參考解。 但 n = 10⁵ 時要掃 10¹⁰ 次,一定超時。
× REJECT · TLE
B 閒著時 t++ 一格一格走 跟著時間值走
答案是對的(窮舉 0 錯),但時間值可以到 10⁹: [[1,1],[1e9,1]] 只有 2 個任務,卻要跑 1,000,000,001 圈、約 552 ms;直接跳只要 2 圈。
△ REJECT · 大間隔會 TLE
BOTH FAIL · ADOPT
C 依到達時間排序 + 最小堆 (處理時間, index) O(n log n)
排好序的到達順序用一個指標 i 走一遍;到了的就推進堆,堆頂就是該做的;堆空時直接跳到下一個到達時間。 實測 n = 10⁵ 隨機約 60 ms,和 O(n²) 暴力解對拍 0 錯。
● ADOPT · 每個任務進出堆一次
這題的骨架和 621 很像:都是「模擬時間 + 用堆挑下一個」。 差別是 621 的任務一開始就全部可用,這題的任務要等到達時間才能進堆 —— 所以多了排序和指標 i。
3

核心策略 · 三步驟// THE SHAPE

  1. 排序 index:arr 依到達時間排好(排 index,不動原陣列,index 才保得住)。
  2. 收進堆:堆空時 t = max(t, 下一個到達時間);然後把所有 到達時間 ≤ t 的推進堆。
  3. 做一個:pop 堆頂(處理時間最短、同長 index 最小),t += 處理時間,記進答案。
三個細節,正好是這題最容易寫錯的三個地方: ① max,時間不能倒退;② 比較子要比 index,同長時才能選對;③ t 要用 long long,總時間最多約 10¹⁴。 程式碼頁有這三個錯的完整紀錄。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 堆空不代表 CPU 閒著 —— 所以跳時間要取 max

迴圈每一圈結尾都 pop 一個、t 加上它的處理時間。下一圈開頭如果堆是空的,有兩種可能:

· 下一個任務還沒到(到達時間 > t):CPU 真的閒著,要跳到它的到達時間。
· 下一個任務早就到了(到達時間 ≤ t):只是剛才的任務做完、堆剛好被清空。這時 t 應該不動。
t = max(t, 下一個到達時間) 同時處理兩種情況;直接 t = 到達時間 在第二種情況會把時間拉回過去。
實測:只拿掉 max,窮舉 66,429 組錯 6,372 組,官方範例 1 就會錯(回 [0,1,2,3])。

LEMMA 2 · int 的 t 會溢位,但答案不會錯 —— 仍然要用 long long

t 最大約 10⁹ + 10⁵ × 10⁹ ≈ 10¹⁴,int 一定溢位;-fsanitize=undefined 直接報 signed integer overflow: 2000000001 + 1000000000。
但實測輸出從來沒被影響(窮舉、隨機大資料、刻意構造的 10⁵ × [1, 10⁹] 都一樣): 要溢位,t 得先超過 INT_MAX − 10⁹ ≈ 1.147×10⁹,這已經大於任何到達時間(≤ 10⁹), 所以溢位那一刻所有任務都已經在堆裡(300 組隨機測資 300/300 如此),之後 t 不再被拿來比較。
這是「剛好沒事」,不是「沒有 bug」:有號整數溢位是未定義行為,題目的上限稍微一改就會出事。

複雜度// COMPLEXITY

排序 O(n log n) + 每個任務 push / pop 各一次 O(n log n)　·　空間 O(n)
情境(-O2)時間說明

n = 10⁵,全部在 t=1 到達≈ 43 ms堆一次長到 10⁵

同一組直接跳2 圈跳躍次數 ≤ n
外層迴圈每一圈恰好 pop 一個任務,所以正好跑 n 圈 —— 和時間值有多大無關。 這就是「直接跳」比「一格一格走」好的原因。
