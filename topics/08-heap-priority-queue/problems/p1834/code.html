完整實作(修正版)// SORT + MIN-HEAP

p1834.cpp C++17 
class Solution {
public:
    vector<int> getOrder(vector<vector<int>>& tasks) {
        int n = tasks.size();
        vector<int> arr(n);
        iota(arr.begin(), arr.end(), 0);
        sort(arr.begin(), arr.end(), [&](int a, int b) {
            return tasks[a][0] < tasks[b][0];          // 依到達時間排 index
        });

        auto cmp = [&](int a, int b) {                           // ① 參數是 int,不是指標
            if (tasks[a][1] != tasks[b][1]) return tasks[a][1] > tasks[b][1];
            return a > b;                                       // ③ 一樣長:index 小的先
        };
        priority_queue<int, vector<int>, decltype(cmp)> pq(cmp);

        long long t = 0;                                          // ④ 總時間可到 ~10¹⁴
        int i = 0;
        vector<int> ans;

        while (i < n || !pq.empty()) {
            if (pq.empty()) {
                t = max(t, (long long)tasks[arr[i]][0]);          // ② 只往前跳
            }
            while (i < n && t >= tasks[arr[i]][0]) {
                pq.push(arr[i]); i++;                           // 到了的都進堆
            }
            int idx = pq.top(); pq.pop();                         // 這裡堆一定非空
            t += tasks[idx][1];
            ans.push_back(idx);
        }
        return ans;
    }
};

#錯在哪後果(實測)修正
①比較子參數寫成 const auto*編譯失敗:mismatched types 'const auto:28*' and 'int'堆裡放的是 int:[&](int a, int b)
②堆空時 t = 到達時間錯 6,372 / 66,429;官方範例 1 回 [0,1,2,3]t = max(t, 到達時間)
③處理時間一樣時沒比 index錯 32,005 / 66,429相等時 return a > b;
④int tUBSan 報溢位;輸出實測從未改變long long t
② 時間倒退 —— 最嚴重的一個

我以為「堆空 = CPU 閒著,要等下一個任務」。但堆也可能是「剛做完一個任務、候選剛好用完」,這時下一個任務早就到了, 把 t 設成它的到達時間,就等於把時間撥回過去。

官方範例 1:#0 在 t=3 做完 → 堆空 → t 被設成 #1 的到達時間 2 → 在 t=2 只有 #1 進堆(#2 在 t=3 才到)→ 先做了長的 #1 → 回 [0,1,2,3],正解 [0,2,3,1]。
最小反例:[[1,2],[2,2],[3,1]] → 回 [0,1,2],正解 [0,2,1]。 (我先前看到的 [[4,1],[2,2],[1,3]] → 2 1 0 vs 2 0 1 也是同一個錯。)

③ 沒有 index tie-break —— 範例 2 抓不到

題目明講「處理時間一樣,選 index 小的」,但我只比了處理時間。priority_queue 不是穩定的,相等元素誰先出來沒有保證。
最小反例:[[1,1],[2,1],[1,1]] → 回 [0,2,1],正解 [0,1,2](t=2 時 #1、#2 處理時間都是 1,要選 #1)。
官方範例 2 五個任務處理時間都不同,所以抓不到;全部相同的輸入有時也會「剛好對」,因為堆碰巧照順序吐出來 —— 那不是保證。

④ int t —— 剛好沒事,但仍是 bug

-fsanitize=undefined:runtime error: signed integer overflow: 2000000001 + 1000000000 cannot be represented in type 'int'。
輸出沒被影響,是因為溢位時所有任務都已在堆裡(概念頁 LEMMA 2)。但「測不出來」不等於「對」:有號溢位是未定義行為,編譯器可以假設它不會發生而做任何最佳化。

三個會影響答案的錯同時存在時(只修掉編譯錯誤):窮舉錯 33,853 / 66,429,範例 1 錯、範例 2 剛好對。 教訓:範例 2 過了不代表對 —— ② 要看「剛做完就堆空」,③ 要看「一樣長」,兩種情況都要自己造測資。
