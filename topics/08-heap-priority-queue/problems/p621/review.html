PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼一輪是 n + 1 格,不是 n 格?寫成 n 會怎樣?
解答與說明 · ANSWER▾
一輪要容納「一個任務 + 它後面的 n 格冷卻」,所以是 n + 1 格。

一種任務在一輪裡只出現一次,下一次最早在下一輪。一輪 n+1 格,兩次之間才會隔滿 n 格。
寫成 cycle = n:窮舉錯 484 / 620;而且 n = 0 時 cycle = 0,內層一次都不跑、堆永遠不會空 → 無限迴圈。
第 2 題10 分
if (pq.empty() && buff.empty()) break; 為什麼兩個條件都要?各舉一個少了會錯的例子。
解答與說明 · ANSWER▾
「堆空」只代表這輪沒有可做的任務;還有任務在 buff 冷卻時,這格是 idle,時間要算。只有兩者都空,才是真的做完了。

· 只寫 if (pq.empty()) break;:CC, n=1 —— 第一輪做完一個 C,堆空了就 break,那格 idle 沒算 → 回 2(正解 C idle C = 3)。窮舉錯 360。
· 完全不 break:C, n=1 —— 做完 C 還把這輪剩下的格子補成 idle → 回 2(正解 1)。窮舉錯 451。
第 3 題10 分
為什麼每格要拿「剩最多」的?改成最小堆,三個官方範例都會過,那它錯在哪?
解答與說明 · ANSWER▾
剩最多的任務最難安排:它需要最多輪,拖到後面就只能和 idle 交替。

最小堆的反例 ABCC, n=1(cycle = 2):先做次數少的 A、B,C 的兩個被留到最後,只能 C idle C → 共 5 格。 正解先排 C:C A C B = 4 格。窮舉錯 54 / 620。
三個官方範例剛好都是「各種任務次數相同」或「沒有 idle」的情況,先排誰都一樣,所以抓不到這個錯。 和精確搜尋比對 620 組 0 不一致,說明「先排剩最多的」在這些輸入上都是最佳的。
第 4 題10 分
不模擬,直接算答案的公式是什麼?用範例 1 說明它從哪裡來。
解答與說明 · ANSWER▾
max(len, (maxF − 1)(n + 1) + countMax)

範例 1 AAABBB, n=2:次數最多的是 A、B,maxF = 3,countMax = 2。 把次數最多的任務當骨架,先畫 maxF − 1 = 2 個寬 n + 1 = 3 的框: [A B _] [A B _],最後一行只放次數等於 maxF 的那 2 種:[A B]。 2·3 + 2 = 8。其他任務塞進框裡的空格;塞不下(任務太多)時就完全不需要 idle,答案是 len。
實測和你的模擬對拍 200,000 組,0 不一致。
第 5 題10 分
freq 有 26 格,大部分是 0。為什麼一定要跳過 0?能不能用 priority_queue 的比較子把 0 濾掉?
解答與說明 · ANSWER▾
每 pop 出一個數,程式就認為「這格做了一個任務」;0 代表根本沒有這種任務,pop 到它就會多算一格。

實測把 0 也推進堆:620 組全部錯,範例 1 回 30(正解 8)。
比較子不能用來過濾:priority_queue 的比較子只決定「誰排前面」,不能決定「誰要進來」。 要在進堆前濾掉:迴圈加 if (f)(你的寫法);或先 freq.erase(remove(freq.begin(), freq.end(), 0), freq.end()); 再用區間建構; 或 C++20 的 freq | views::filter(...)。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 範例 2 · ACABDB · n = 1:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾

次數 第 2 題、B2、C1、D1,cycle = 2。這組完全沒有 idle,而且堆裡的任務比一輪的格數多 —— 看沒輪到的任務留在堆裡等下一輪。實跑印出。

// STEP 1: 第 1 輪 pq=[2,2,1,1] 格 1:B 2→1 進 buff 格 2:A 2→1 進 buff (C、D 還在 pq 裡,這輪沒輪到) buff=[1,1] 推回 → pq=[1,1,1,1] time = 2
// STEP 2: 第 2、3 輪 pq=[1,1,1,1] 格 3:D 1→0 格 4:C 1→0 buff=[] time = 4 pq=[1,1] 格 5:B 1→0 格 6:A 1→0 buff=[] time = 6 pq 空 → while 結束
// STEP 3: 結果 排程:B A | D C | B A 外層 3 輪(maxF = 2) 公式:(2−1)·2 + 2 = 4,max(len = 6, 4) = 6 // OUTPUT: 6
任務夠多、能把每輪塞滿時,答案就是 len,一格 idle 都不用。 這時外層輪數(3)會比 maxF(2)多 —— 有 idle 時兩者才相等。公式裡 max(len, …) 的 len 就是在處理這種情況。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
題目改成「回傳實際的排程(例如 "A B idle A B idle A B")」,程式要怎麼改?
解答與說明 · ANSWER▾
堆裡改存 pair<int, char>(次數, 字母),每格把字母(或 "idle")接到結果字串。

pair 先比次數,次數相同時比字母,所以範例 1 會先做 B:B A idle | B A idle | B A —— 格數一樣是 8。 本頁的字母排程就是用這個版本印出來的,和只存次數的版本 time 完全相同。
第 8 題13 分
Reorganize String(LeetCode 767):重排字串讓相鄰字元都不同,做不到就回傳 ""。這和 621 是什麼關係?
解答與說明 · ANSWER▾
767 就是 621 在 n = 1、而且「不准有 idle」的版本。

相鄰不同 = 同一字元之間至少隔 1 格。用同一個最大堆,每輪拿兩個不同的字元; 如果某一輪堆裡只剩一種字元、但它還沒用完,就需要 idle —— 在 767 裡這代表做不到,回傳 ""。 用公式看:maxF − 1 ≤ len − maxF(其他字元夠把最多的那種隔開)才有解,也就是 maxF ≤ (len + 1) / 2。
第 9 題14 分
用公式寫一個 O(len) 的版本。什麼時候 len 會比 (maxF−1)(n+1) + countMax 大?
解答與說明 · ANSWER▾
數次數、找 maxF 和 countMax,回傳 max(len, (maxF − 1)(n + 1) + countMax)。

len 比較大,代表任務多到能把所有框的空格塞滿還有剩 —— 完全不需要 idle,每格都在做事。 例如範例 2:(2−1)·2 + 2 = 4 < len = 6,答案 6。 反之 'A'×10⁴、n=100:9999·101 + 1 = 1,009,900 遠大於 10⁴,幾乎全是 idle。 公式永遠 O(len);模擬的成本則跟著答案走,這個例子要跑 1,009,900 次內層。
