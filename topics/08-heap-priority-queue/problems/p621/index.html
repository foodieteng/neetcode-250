題目簡介// THE QUESTION

QUESTION

CPU 要做一堆任務,每個任務是 'A'~'Z' 其中一個大寫字母。每一格時間做一個任務或閒置(idle)。 同一種任務之間至少要隔 n 格。求做完全部任務的最少格數。
1 ≤ tasks.length ≤ 10⁴,0 ≤ n ≤ 100。

任務的名字其實不重要,重要的只有每種任務還剩幾個。 要讓 idle 最少,就要讓剩最多的任務盡早、盡量均勻地排開 —— 它是最難塞的,拖到最後就只能一個一個夾著 idle 做。

把時間切成每輪 n + 1 格:一輪之內,同一種任務最多出現一次(下一次出現至少隔 n 格,剛好落在下一輪)。 每輪從最大堆依序拿「剩最多的」不同任務填進去;填不滿就 idle。 這輪做過的任務先放 buff 冷卻,輪結束才放回堆。

核心策略 · 三步驟// THE SHAPE

  1. 數次數:freq[c - 'A']++(大寫!),只把 非 0 的次數推進最大堆。
  2. 一輪 n + 1 格:每格從堆拿一個(次數減 1,還有剩就進 buff);堆空了但 buff 還有 → 這格是 idle。
  3. 輪結束把 buff 推回堆;堆和 buff 都空 → 立刻停,最後一輪不補 idle。
那行 if (pq.empty() && buff.empty()) break; 是整份程式最關鍵的一行。 兩個條件缺一不可:只看 pq.empty() 會漏算還在冷卻的 idle;完全不 break 會在最後一輪多補 idle。 兩種寫法實測各錯 360 和 451 / 620。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 一輪 n+1 格,同一種任務不會違反冷卻

一輪之內每種任務最多被 pop 一次(做完的先進 buff,這輪不會再被拿到)。 如果一個任務在第 k 輪排第 i 格、第 k+1 輪也排第 i 格或更後面,兩次之間至少隔 (n + 1) − 1 = n 格。
它會不會在下一輪「往前跑」?這輪一起做的任務次數都各減 1,彼此的大小順序不變; 這輪沒做到的任務只可能插到它前面(讓它更晚)。唯一能讓它往前的是次數相同的任務換了先後 —— 但堆裡只存次數,次數相同的任務可以互換名字,換個標籤就又滿足冷卻。 所以只要每輪走滿 n+1 格(不夠就補 idle),一定存在一個合法的排法,格數就是程式算出的 time。
唯一的例外是最後一輪:後面已經沒有任務,補 idle 只是浪費,所以兩者都空就 break。 (實測:和精確的最短排程搜尋比對 620 組,0 不一致。)

LEMMA 2 · 「先排剩最多的」是最佳的 —— 以及公式從哪來

剩最多的任務(次數 maxF)決定了骨架:它至少需要 maxF − 1 個完整的「它 + n 格」框, 最後一框只放和它一樣多的那幾種(countMax 種)。這給出下界 (maxF − 1)(n + 1) + countMax。 另一個下界是任務總數 len(每格最多做一個)。答案 = 兩者取大。

實測:你的程式和公式對拍 200,000 組隨機,0 不一致; 和精確的 BFS 最短排程搜尋比對 620 組(3 種任務、各 0~4 個、n 0~4),0 不一致。 範例 1:(3 − 1)·3 + 2 = 8,max(6, 8) = 8。

複雜度// COMPLEXITY

內層迴圈每跑一次就是一格時間,所以內層總次數 = 答案;堆最多 26 個數,每次 push/pop 是 O(log 26)。

一句洞察// INSIGHT

每輪 n+1 格、每種任務一輪最多一次,冷卻就自動成立;每輪先排剩最多的,idle 就最少。 做過的先進 buff,輪結束才回堆;堆空但 buff 有 → idle,兩者都空 → 停。 答案也可以直接算:max(len, (maxF−1)(n+1) + countMax)。
