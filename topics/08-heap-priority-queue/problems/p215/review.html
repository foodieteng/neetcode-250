Q4. 實測 n = 10⁵ 時,k = 50000 比 k = 10⁵ 慢。k 越大不是應該越慢嗎?
Q5. 題目問「能不能不排序」。除了堆,還有哪些做法?各自的前提是什麼?

範例 Trace// 範例 1 · k = 2

[3,2,1,5,6,4],k = 2,沒有重複值 —— 看純粹的「篩子」動作。arr 是實跑印出的底層陣列。

// STEP 1: 前 2 個直接進 push 3 → arr=[3] push 2 → arr=[2,3]
// STEP 2: 之後每個都 push + pop push 1 → arr=[1,3,2] pop 1 → arr=[2,3] (1 自己出局) push 5 → arr=[2,3,5] pop 2 → arr=[3,5] push 6 → arr=[3,5,6] pop 3 → arr=[5,6] push 4 → arr=[4,6,5] pop 4 → arr=[5,6] (4 自己出局)
// STEP 3: 回傳 堆裡 {5,6} = 最大的 2 個 → top = 5 // OUTPUT: 5(pop 了 4 次 = n − k = 6 − 2)
1 和 4 都是「一進來就被自己踢出去」 —— 它們比當時的堆頂還小,連前 2 名的邊都摸不到。 堆頂就是入場門檻:2 → 3 → 5,只升不降。

// ANSWERS
A1. 不會去重,所以答案是 4。

priority_queue 是「可以有重複」的容器:實測把範例 2 的 9 個數全部 push 進去,size() 是 9,倒出來是 6 5 5 4 3 3 2 2 1。
你的迴圈最後留下 {4,5,5,6} —— 兩個 5 各佔一格。由大到小:6 是第 1 名、5 第 2 名、另一個 5 第 3 名、4 第 4 名。 堆頂是這 4 個裡最小的,就是 4。兩個 3 是第 5、6 名,在最後兩次 pop 被踢掉了。

什麼時候才會是 3?只有把兩個 5 算成一名(去重:6 5 4 3),或者 k = 5 的時候。 題目明講「不是第 k 個不同值」,所以 4 才對。
A2. 第 k 大 = 最大的 k 個裡最小的那一個;最小堆能隨時拿到並踢掉這 k 個裡最小的。

每次 push 後超過 k 個,被 pop 的是 k+1 個裡最小的 —— 至少有 k 個數比它大或一樣大,它不可能是前 k 名。 用最大堆(忘了 greater)同樣邏輯會留下最小的 k 個:窮舉錯 24,824 / 30,948,[1,2], k=1 回 1。
A3. 一定剛好 k 個,不會空。

題目保證 1 ≤ k ≤ n。前 k 次 push 堆長到 k;之後每次都是 push 到 k+1、pop 回 k。所以結束時恰好 k 個(k ≥ 1),top() 有值。
反例寫法:pop 條件寫成 >= k,堆只剩 k−1 個 —— [1], k=1 時堆空了還呼叫 top(),是未定義行為(窮舉錯 17,472 組)。
A4. 因為成本是「堆的大小」和「pop 的次數」兩者一起決定的。

pop 次數是 n − k,每次操作是 O(log k):
· k = 1:堆很小、pop 99,999 次 → 0.463 ms
· k = 50000:堆最大到 5 萬、還要 pop 5 萬次 → 約 4.4 ~ 5.1 ms(最慢)
· k = 10⁵:堆從來沒超過 k,一次都不 pop → 1.566 ms
(n − k) · log k 在 k 約為 n/2 時最大,所以「O(n log k)」只是上界,實際成本在中間最高。
A5. 四條路,前提各不同:

· 大小 k 的最小堆(你的):O(n log k)、O(k) 記憶體,不需要任何前提,也能處理串流(703)。
· quickselect / nth_element:平均 O(n),實測 0.27 ~ 0.57 ms;前提是能一次拿到全部資料、可以重排陣列。
· 計數:O(n + 值域),實測約 0.07 ms,最快;前提是值域小(這題 ±10⁴ 只要 20,001 格)。
· 最大堆裝全部 + pop k−1 次:O(n + k log n)、O(n) 記憶體,k 小時不錯(0.9 ms),k = n 時最慢(9.1 ms)。
面試時寫堆,再主動講另外兩個更快的選項和前提,是最完整的回答。
A-App 1. 把「重複的值只算一次」做出來:最簡單是先丟進 set 去重,再對不同值做同樣的事。

例如 set<int> s(nums.begin(), nums.end());,然後從 s.rbegin() 往前走 k−1 步; 或者維護一個大小為 k 的 set,超過 k 就 erase(s.begin())(set 自動去重)。 還要處理「不同值不到 k 個」的情況 —— 實測隨機資料裡這種情形很常見(200,000 組中有 64,596 組)。
這正是本題程式碼頁「去重陷阱」那一列:同一段 set 程式碼,在 215 是錯的,在這個變體才是對的。
A-App 2. 開 20001 格的計數陣列,從最大值往下扣。

int cnt[20001] = {};
for (int x : nums) cnt[x + 10000]++;
for (int v = 20000; v >= 0; v--) { k -= cnt[v]; if (k <= 0) return v - 10000; }

重複值自然各佔一名:cnt 記的是次數,一次扣掉整批。範例 2 從 6 往下扣:6(k 4→3)、5 兩個(3→1)、4(1→0)→ 回傳 4。 實測 n = 10⁵ 約 0.07 ms,和排序對拍 200,000 組 0 不一致。
A-App 3. nth_element(nums.begin(), nums.begin() + k - 1, nums.end(), greater<int>()); return nums[k - 1];

greater 讓它以「由大到小」為準,第 k−1 個位置放的就是第 k 大;前面的都 ≥ 它、後面的都 ≤ 它,其他順序不保證。 窮舉 30,948 組 0 錯。它會改動 nums 的順序 —— 這題參數是 vector<int>&,可以接受。
