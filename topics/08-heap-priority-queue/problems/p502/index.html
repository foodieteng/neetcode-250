題目簡介// THE QUESTION

QUESTION

起始資金 w,最多做 k 個不同的專案。專案 i 要目前資金 ≥ capital[i] 才能做,做完資金增加 profits[i]。 回傳最後最多有多少資金。
1 ≤ k, n ≤ 10⁵,0 ≤ w ≤ 10⁹,0 ≤ profits[i] ≤ 10⁴,0 ≤ capital[i] ≤ 10⁹。

最容易讀錯的一點:capital[i] 是門檻,不是成本 —— 做專案不會扣錢,profits[i] 已經是淨利。 所以 w 只會變大,做得起的專案只會越來越多。

capital 是「入場資格」,profit 是「淨賺多少」。 我第一次寫就把 w += capital 寫進去了 —— 程式碼頁有完整紀錄。
2

為什麼是「排序 + 最大堆」// WHY THIS

A 每輪掃過全部專案,挑做得起的最大利潤 O(k·n)
貪心本身是對的,只是每輪重掃一次。 n = k = 10⁵ 實測超過 20 秒還沒跑完。
× REJECT · TLE
B 依利潤排序,從大的開始試 O(n log n)
利潤大的可能門檻太高、現在做不了;做不了的要「等一下再回來看」, 光靠排序沒辦法記住這些等候中的專案。
△ REJECT · 會漏掉之後解鎖的
BOTH FAIL · ADOPT
C 依門檻排序 + 利潤最大堆 O(n log n)
指標 i 沿著門檻由小到大走:門檻 ≤ w 的就推進堆,堆頂就是現在最賺的。 因為 w 只增不減,進了堆的專案永遠做得起,指標也不用回頭。 實測 n = k = 10⁵ 約 15~20 ms,和暴力解對拍 8,000 萬組 0 錯。
● ADOPT · 每個專案最多進出堆一次
骨架和 1834 單執行緒 CPU 一模一樣:依「什麼時候能用」排序、指標把能用的推進堆、堆頂挑下一個。 1834 的「時間」只往前走,這題的「資金」只往上走 —— 都是單調的,所以指標不用回頭。
3

核心策略 · 三步驟// THE SHAPE

  1. 排序 index:idx 依 capital 由小到大(排 index,profit 和 capital 才對得上)。
  2. 每輪先補堆:把所有 capital ≤ w 的專案利潤推進最大堆(while,不是 if)。
  3. 再挑一個:堆空就 break(沒得做);否則 w += 堆頂、pop。跑 k 輪,回傳 w。
「補堆」和「挑一個」要分開、而且每輪都要補:挑完之後 w 變大,可能解鎖新的專案,下一輪開頭就會補進來。 我的第一版把兩件事混在同一個迴圈裡,結果挑完一次就提早 return 了。

兩個一定會被問到的「為什麼」// TWO LEMMAS

LEMMA 1 · 每輪拿「現在做得起的最大利潤」一定不會錯

假設最佳解這一輪拿的是利潤較小的 p,而我們拿最大的 P ≥ p。 拿 P 之後資金不會比拿 p 少,最佳解之後能做的每個專案,我們也都做得起(門檻只看資金夠不夠); 而 p 還在堆裡,之後要做也可以。把最佳解裡的 p 和 P 對調,總和不變、每一步仍然合法。 所以「每輪拿最大的」不會比最佳解差。

LEMMA 2 · 這題 int 不會溢位

最壞情況:w = 10⁹,10⁵ 個專案、每個利潤 10⁴、門檻都是 0 → 最後 w = 2,000,000,000, 離 INT_MAX = 2,147,483,647 還有 147,483,647。UBSan 實跑零報錯,題目也保證答案在 32 位元內。 和 1834 不一樣,這題不用 long long。

複雜度// COMPLEXITY

排序 O(n log n) + 每個專案最多 push 一次、最多 pop k 次 O((n + k) log n)　·　空間 O(n)
情境(-O2,n = k = 10⁵)時間說明
門檻全是 0≈ 15 ms堆一次長到 10⁵
門檻 c[i] = i,利潤 1(樓梯)≈ 2 ms每輪剛好解鎖一個

一句洞察// INSIGHT

capital 是門檻不是成本,所以 w 只增不減;依門檻排序,做得起的推進最大堆,每輪拿堆頂。 每輪先補堆再挑,堆空才停 —— 回傳的是 w,不是利潤總和。
