完整實作(修正版)// SORT + MAX-HEAP

p502.cpp C++17 
class Solution {
public:
    int findMaximizedCapital(int k, int w, vector<int>& profits, vector<int>& capital) {
        int n = profits.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return capital[a] < capital[b];              // 依門檻排 index
        });

        priority_queue<int> pq;                          // 只需存 profit
        int i = 0;
        while (k--) {                                   // ④ 跑 k 輪,不看 i
            while (i < n && capital[idx[i]] <= w)
                pq.push(profits[idx[i++]]);             // ③ 每輪先補堆
            if (pq.empty()) break;                     // 沒有做得起的專案
            w += pq.top();                              // ① 加的是 profit
            pq.pop();
        }
        return w;                                       // ② 回傳資金
    }
};

#錯在哪只剩這個錯時(實測)修正
①w += capital[...]:把門檻當成收入範例 1 的 w 一直是 0w += 利潤
②回傳 maxProfit(利潤總和)起始 w > 0 時就少算了 wreturn w;
③pop 完堆空就 return錯 131,067 / 1,034,592每輪先補堆,補完還空才 break
④迴圈條件 i < n && k錯 605,881 / 1,034,592外層跑 k 輪:while (k--)
① 把 capital 當成收入 —— 根本原因是讀錯題

capital 是「要有這麼多錢才能做」,做的時候不扣、也不會加。做完增加的是 profit。 範例 1:做完 #0 後 w = 0 + capital[0] = 0,w 永遠長不大,門檻 1 的 #1、#2 一直解鎖不了。
只修 ① 反而錯得更多(808,410 → 813,628 / 1,034,592):因為還在回傳 maxProfit,w 變大只是讓迴圈走到別的地方提早結束。四個錯是綁在一起的。

③ 堆空就 return —— 忘了 w 剛剛變大了

pop 完堆變空,不代表沒專案可做:剛拿到的利潤可能讓 idx[i] 剛好解鎖。要先回頭補堆,補完還是空才停。
最小反例(① ② ④ 都修好,只剩 ③):k=2, w=0, profits=[1,1], capital=[0,1] → 回 1,正解 2(做完 #0 後 w=1,#1 剛好做得起)。
也不能直接刪掉這行:實測刪掉後 225,192 組變成無窮迴圈 —— 堆空、capital[idx[i]] > w 時,i 和 k 都不會動。這行在原稿裡同時扛著「停止條件」的責任。

④ i 走完就停 —— 堆裡剩的沒人拿

原稿只有在「遇到做不起的專案」時才會 pop。所有專案都推進堆之後(i == n),迴圈直接結束,堆裡的利潤和剩下的 k 都浪費了。
最小反例(只剩 ④):k=1, w=0, profits=[1], capital=[0] → 回 0,正解 1。只有一個專案、而且做得起,卻一個都沒做。

原稿整體:窮舉錯 808,410 / 1,034,592,兩個官方範例都回 1(正解 4、6)。 教訓:① 是讀題錯,③④ 是結構錯 —— 「補堆」和「挑一個」該是兩個步驟,外層照 k 輪跑。拆開後四個錯一起消失。
