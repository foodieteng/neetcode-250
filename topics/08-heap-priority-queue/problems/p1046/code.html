最後一塊石頭的重量

完整實作// MAX-HEAP

p1046.cpp C++17 
class Solution {
public:
    int lastStoneWeight(vector<int>& stones) {
        // 預設 priority_queue 就是最大堆;範圍建構子 O(n) 建堆
        priority_queue<int> pq(stones.begin(), stones.end());

        while (pq.size() > 1) {          // ① 至少兩顆才能撞
            int x = pq.top(); pq.pop();    // 最重
            int y = pq.top(); pq.pop();    // 第二重(x ≥ y)

            if (x != y) pq.push(x - y);     // 一樣重就都消失
        }

        return pq.size() ? pq.top() : 0;      // ② 可能一顆都不剩
    }
};

兩個 size 檢查各守一個邊界: ① > 1 保證第二次 top() 有東西(改成 !empty(),[1] 就崩潰); ② 最後的 size() 處理「全部撞光」(拿掉它,[1,1] 就對空堆 top())。 -Wall -Wextra 編譯零警告 —— 和 703 不同,這裡是拿 size() 和字面常數 1 比,不會有號/無號混比。

邊界與陷阱// PITFALLS

陷阱實測(窮舉 5460 個陣列)修正
用成最小堆錯 4860 · [1,2] → -1拿到的是最輕的兩顆;要用預設的最大堆
照題目字母寫 y − x錯 3384 · [1,2] → -1程式裡 x 先 pop,是較重的;差值是 x − y
回傳前不檢查 size崩潰 2471 · [1,1]全部撞光時堆是空的,要回 0
while (!pq.empty())崩潰 2989 · [1]只剩一顆時沒有第二顆可以 pop;要用 size() > 1
排序一次、差值接尾端錯 636 · [1,1,3] → -1新石頭的排名不確定,必須每次維護順序
相等時也 push 0錯 0不是 bug,只是多跑幾輪(0 撞任何石頭都會把那顆原封不動推回)
寫完拿三組最小測資走一遍就夠:[1]、[1,1]、[1,2]。 它們分別抓到迴圈條件、收尾檢查、以及堆的方向/差值方向 —— 表上前四個錯全部現形。
