題目簡介// THE QUESTION

QUESTION

對方從 1 … n 挑了一個數 pick(過程中不變)。你看不到它,只能呼叫 API guess(num): 回 -1 表示你猜太大、回 1 表示你猜太小、回 0 表示猜中。請回傳 pick。 1 ≤ n ≤ 2³¹ − 1。

這題和 704、35 的差別:那兩題「值」擺在陣列裡可以直接讀,這題的值藏起來了, 只能透過一個單調的 API 間接探測。但骨架完全一樣 —— 因為二分要的從來不是陣列,而是一個單調的是非回應。

為什麼把三分支併成兩分支// WHY THIS

A 從 1 猜到 n O(n)
n 可到 2³¹−1,線性猜要 20 億次 API 呼叫,直接出局。
× REJECT · TLE
B 三分支 l<=r,==0 提早 return O(log n)
複雜度已經對,但要維護 l<=r、r=m−1、l=m+1 三處對齊,而且末尾那句 return -1 是永遠執行不到的死碼。
△ REJECT · 分支多、有死碼
BOTH FAIL · ADOPT
C 把 0 併進「太大」那側,收斂到單格 O(log n)
只問一件事:「猜小了嗎?」是 → left = mid + 1;不是(太大或剛好)→ right = mid。 因為 right = mid 保留了 mid,猜中的那個數不會被丟掉,最後一定是唯一活下來的那格。 兩分支、無死碼、和 704/35 同一副骨架。
● ADOPT · STABLE
3

核心策略 · 三步驟// STRATEGY

  1. 定義區間:left = 1、right = n,答案保證落在閉區間 [left, right] 內。
  2. 收縮:mid = left + (right − left) / 2。guess(mid) == 1(猜小了)→ left = mid + 1;否則 → right = mid。
  3. 收斂即答案:left == right 時區間只剩一格,而答案保證存在 → return left;。

把「猜中」併進「太大」為什麼安全// LEMMA

INVARIANT · pick 永遠留在 [left, right] 之內

不變量:每一輪開始時,pick ∈ [left, right]。初始 [1, n] 依題目保證成立。

維持:若 guess(mid) == 1(mid 比 pick 小),則 pick ≥ mid + 1,取 left = mid + 1 後 pick 仍在區間內。 若 guess(mid) == -1(mid 比 pick 大),則 pick ≤ mid − 1 ≤ mid;若 guess(mid) == 0,則 pick = mid。 兩種情況都滿足 pick ≤ mid,所以同一行 right = mid 對兩者都保住了不變量 —— 這正是能合併的理由。

終止與正確:因為 left ≤ mid < right,兩個分支都讓區間嚴格變短,必定收斂到 left == right。 此時區間只剩一格而 pick 仍在其中 ⇒ 那一格就是 pick。所以 return left 不需要任何驗證。

注意合併的代價:-1 明明可以縮到 mid − 1,合併後只縮到 mid,多留一格。 但那一格最多讓迴圈多跑一輪,換來的是少一個分支、少一段死碼、和其他二分題共用同一副骨架 —— 這筆交易很划算。

這題的 mid 一定要防溢位// OVERFLOW

704 和 35 的 n ≤ 10⁴,(left + right) / 2 寫了也不會出事。但這題 n 可以到 2³¹ − 1 = INT_MAX, 兩數相加必定溢位 —— 這是本題唯一真正危險的地方。

// 實測(int,模擬溢位環繞) left = 1073741825, right = 2147483647 // 二分後期很容易出現的一組值 (left + right) / 2 → -536870912 ← 負數!接著 guess(負數) 完全失效 left + (right - left)/2 → 1610612736 ← 正確 // 差別不是「風格」,是會不會壞掉
寫法n ≤ 10⁴(704/35)n ≤ 2³¹−1(本題)
(left + right) / 2安全溢位 → 錯誤答案
left + (right − left) / 2安全安全
這就是為什麼建議一律寫防溢位版:同樣一行程式,在小題目上是好習慣,在這題上是正確性。 (Java 標準函式庫的 binarySearch 就曾因為這個 bug 存在近十年。)

一句洞察// INSIGHT

三種回應不一定要三個分支 —— 只要問「是不是猜小了」這一個是非題: 是 就 left = mid + 1,不是(太大或剛好)就 right = mid。 因為 right = mid 把 mid 留著,猜中的那格自然會是最後的倖存者。
