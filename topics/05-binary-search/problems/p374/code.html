/**
 * Forward declaration of guess API.
 * @param  num   your guess
 * @return       -1 if num is higher than the picked number
 *                1 if num is lower than the picked number
 *                otherwise return 0
 * int guess(int num);
 */

class Solution {
public:
    int guessNumber(int n) {
        int left = 1, right = n;          // 答案保證落在閉區間 [left, right]

        while (left < right) {            // 剩一格就停,不必等到區間空
            int mid = left + (right - left) / 2;  // n 可達 2^31-1,必須防溢位

            if (guess(mid) == 1) {
                left = mid + 1;          // 猜太小 → 答案在 (mid, right]
            } else {
                right = mid;              // 太大或剛好 → 答案在 [left, mid]
            }
        }

        return left;                     // 收斂到唯一一格,答案保證存在 → 就是它
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

三件事撐起這份程式碼:只問「是不是猜小了」(三分支變兩分支)、right = mid 保留 mid(猜中的數不會被丟掉)、 答案保證存在(所以單格即答案,不用驗證、也不需要 return -1)。

太大 -1right = mid − 1right = mid
太小 1left = mid + 1相同

guess 次數運氣好時較少最多多 1 輪
// 為什麼三分支版的 return -1 是死碼 題目保證 pick ∈ [1, n],而不變量保證 pick 永遠在 [left, right] 內。 只要區間非空就一定還有機會猜中;而每輪區間至少縮 1, 所以在區間變空之前,mid 必然某一輪剛好等於 pick → 從 return mid 離開。 // 迴圈正常結束(區間空)的路徑永遠走不到 → return -1 只是編譯器要求的擺設
面試時這是個好加分點:主動指出「那句 return -1 永遠不會執行」,並說明怎麼改寫可以讓它消失, 比單純寫出能過的程式碼更能顯示你理解了不變量。

步驟成本說明
每輪一次 guess()O(1)API 呼叫是這題真正的成本
區間長度n → n/2 → n/4 …至少對半
總輪數⌈log₂n⌉n=2³¹−1 → 實測 31 次
收尾O(1)單純 return left
T = O(log n)　　S = O(1)

窮舉 n ≤ 300 的所有 pick 實測:全數正確,最多 9 次 guess(⌈log₂300⌉ = 9)。

邊界與陷阱// PITFALLS

陷阱後果正解
mid = (left + right) / 2 n 接近 2³¹−1 時溢位成負數,guess 全亂 left + (right − left) / 2
合併時寫成 right = mid − 1 猜中的那格被丟掉 → 答案消失 合併版必須 right = mid
用 left <= right 配 right = mid 剩一格時原地打轉 → 無窮迴圈 配 left < right
把回傳值方向記反 往錯的半邊縮,永遠找不到 1 = 你猜太小、-1 = 你猜太大
一輪內呼叫 guess() 多次 答案仍對 但 API 成本翻倍,存成變數再判斷
left = 0 起始 本題仍會收斂到正確值 但 0 不在題目範圍內,起點該是 1
第四列最容易在面試現場出錯:guess 的回傳值是站在「你的猜測」的角度說的 —— 1 是「你猜的數比較小」。寫之前先把這句話唸出來一次,可以省掉一次 debug。
