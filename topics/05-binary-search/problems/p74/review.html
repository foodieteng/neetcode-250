重點回顧// RECAP

面向要點
兩個性質合起來攤平就是一條遞增序列
第一段對「首元素欄」二分,pred = matrix[m][0] > target
取哪個rowIdx = l − 1(最後一個不滿足)
必要檢查l == 0 → false(l−1 = −1 的坑)
為何用嚴格 >把「等於首元素」留在 l−1 那側
第二段列內二分收斂到單格,再驗 == target
複雜度O(log m + log n) = O(log(m·n))
另解攤平成一維,mid/n 與 mid%n 還原座標

觀念題// QUIZ

Q1. 題目給的兩個性質(每列遞增、下一列首元素 > 上一列末元素)合在一起,等價於一句更簡單的話。那句話是什麼?為什麼它讓這題變成一維問題?
Q2. 第一段收斂後為什麼要取 l − 1 而不是 l?用 TF 帶說明 l 那一列為什麼不可能含 target。
Q3. if (l - 1 < 0) return false; 少寫會怎樣?什麼樣的 target 會觸發它?為什麼 l 收斂到 m 時不需要對稱地擋一次?
Q4. 第一段的 pred 用嚴格 >。若改成 >=,哪一種 target 會出錯?請說出一組具體的矩陣與 target。
Q5. 為什麼 O(log m + log n) 就等於題目要求的 O(log(m·n))?兩段二分和「攤平後一次二分」在效率上有差嗎?

範例 Trace// [[1,3,5,7],[10,11,16,20],[23,30,34,60]]

// 矩陣與首元素欄 欄0 欄1 欄2 欄3 列0 [ 1, 3, 5, 7] 首元素 1 列1 [ 10, 11, 16, 20] 首元素 10 列2 [ 23, 30, 34, 60] 首元素 23 首元素欄 [1, 10, 23] 遞增 → 可以二分
// CASE A: target = 3(存在) 第一段 pred = 首元素 > 3 → TF 帶 [F, T, T] [0,3) m=1 10 > 3 是 → r = 1 [0,1) m=0 1 > 3 否 → l = 1 收斂 l = 1 → rowIdx = l − 1 = 0 第二段 列0 = [1,3,5,7],pred = >= 3 [0,3] m=1 3 >= 3 是 → r = 1 [0,1] m=0 1 >= 3 否 → l = 1 收斂 l = 1,matrix[0][1] = 3 // return true
// CASE B: target = 13(列選對了,但值不在) 第一段 首元素 > 13 → [F, F, T] → l = 2 → rowIdx = 1 第二段 列1 = [10,11,16,20] 收斂到 matrix[1][2] = 16 16 != 13 // return false —— 被第二段的值檢查擋下
// CASE C: target = 0(比全部都小) 第一段 首元素 > 0 → [T, T, T] → l = 0 l − 1 = −1 < 0 // return false —— 被 l−1 的左邊界檢查擋下(沒擋就會讀 matrix[-1])
// CASE D: target = 100(比全部都大) 第一段 首元素 > 100 → [F, F, F] → l = 3 = m l − 1 = 2,仍是合法列 → rowIdx = 2 第二段 列2 = [23,30,34,60] 收斂到 matrix[2][3] = 60,60 != 100 // return false —— l 跑到尾後沒關係,l−1 照樣合法
四個 case 走了三條不同的失敗路徑:值檢查、左邊界檢查、以及「l 到尾後但無妨」。 特別記 CASE D —— 很多人會對稱地加一個 if (l == m) return false;,那是錯的,會漏掉最後一列的所有答案。

應用題// APPLY

App 1. 把矩陣當成一維陣列直接跑一次通用模板:索引 i 對應到哪一格?請寫出完整的 O(log(m·n)) 解,並說明它為什麼可以完全套用模板頁的骨架。
App 2. 240. Search a 2D Matrix II:改成「每列由左到右遞增、每欄由上到下遞增」,但不保證下一列首元素 > 上一列末元素。本題的做法為什麼失效?那題的 O(m + n) 走法是什麼?
App 3. 若題目改成「回傳 target 的座標 (i, j),不存在回 (-1,-1)」,本題的程式碼要改哪裡?若改成「回傳不小於 target 的最小元素座標」呢?
// ANSWERS
A1. 等價於:把每一列首尾相接串起來,得到的就是一條完整的遞增序列。因為「列內遞增」保證每段內部有序,「下一列首元素 > 上一列末元素」保證段與段之間也接得上,沒有任何地方會下降。既然攤平後是一條長度 m·n 的遞增序列,這題就不是二維問題 —— 它只是把一維陣列摺成了矩形。這也是為什麼答案可以是「攤平後一次二分」(App 1)或「先選列再列內」兩種等價寫法。
A2. 第一段的 pred 是「matrix[m][0] > target」,TF 帶(以 target=3、首元素欄 [1,10,23] 為例)是 [F, T, T],模板收斂到第一個 T 也就是 l = 1。但 l 那一列的首元素已經 > target,而列內遞增 ⇒ 該列每一個元素都比 target 大,不可能含 target。真正可能含 target 的,是最後一個「首元素 ≤ target」的列 —— 也就是最後一個 F,即 l − 1。這正是模板頁的規則:第一個滿足拿 l,最後一個不滿足拿 l − 1。
A3. 少寫會讀到 matrix[-1],是陣列越界的未定義行為。觸發條件是「target 比所有列的首元素都小」(例如 CASE C 的 target = 0),此時整條 TF 帶全是 T,l 收斂到 0,l − 1 = −1。至於 l == m 為什麼不用對稱地擋:因為那代表「所有列的首元素都 ≤ target」,l − 1 = m − 1 是最後一列的合法索引,而 target 完全可能就落在最後一列裡(例如 target=60)。l − 1 家族只怕左邊界 −1,不怕右邊界。
A4. 出錯的是「target 剛好等於某一列的首元素」。用 >= 時,那一列自己就是第一個 T,l 指向它,l − 1 反而退到前一列,於是在錯的列裡找,回傳 false。具體反例:matrix = [[1,3],[10,11]]、target = 10 —— 用 > 時 TF 帶 [F,F] → l = 2 → rowIdx = 1 → 在 [10,11] 找到,true;用 >= 時帶子變 [F,T] → l = 1 → rowIdx = 0 → 在 [1,3] 找,false(錯)。窮舉 m,n=1..4 共有 40 筆不一致。口訣:要取 l−1,pred 就得用嚴格不等式,把「等於」留在 F 那側。
A5. 因為對數的基本性質 log m + log n = log(m·n) —— 兩段二分的成本是相加,而相加在對數世界裡就等於底下的規模相乘。所以兩段二分和攤平後一次二分是同一個量級,沒有優劣之分。實務上的小差別:攤平版只有一個迴圈、程式碼較短,但每次要做 mid / n 與 mid % n 兩個除法;兩段版多一個迴圈,但都是純比較。實測兩者在 m,n=1..4 的所有矩陣與 target(280 組)上結果完全一致。
App 1. 一維索引 i 對應 matrix[i / n][i % n](n = 每列長度)—— 因為攤平是「一列一列接」,除法給列號、餘數給欄號。完整解就是把模板原封不動抄過來,只把「讀元素」那一行換掉:
int l = 0, r = m * n;
while (l < r) { int mid = l + (r - l) / 2; int v = matrix[mid / n][mid % n]; if (v >= target) r = mid; else l = mid + 1; }
return l != m * n && matrix[l / n][l % n] == target;
之所以能完全套用,是因為攤平後判斷式 v >= target 沿著 i 單調(A1 已證明攤平是遞增序列),TF 帶完整不斷。這裡取的是 l(第一個滿足)並擋 l == m*n —— 和 704 一模一樣的收尾。已與兩段版對拍 280 組,結果一致。
App 2. 240 少掉的正是「跨列銜接」那個性質:第 1 列的末元素可能大於第 2 列的首元素,所以攤平後不再遞增,首元素欄雖然仍遞增,卻無法憑首元素排除整列(某列首元素 ≤ target 不代表 target 只可能在那列,它也可能在更後面的列)。A1 的一維化前提整個垮掉。240 的標準走法是從右上角開始:設 i=0, j=n−1,若 matrix[i][j] > target 就 j--(整欄都太大),若 < target 就 i++(整列都太小),相等即找到。每一步砍掉一整列或一整欄,最多走 m + n 步 → O(m + n)。
App 3. 回傳座標:把最後一行改成 return matrix[rowIdx][left] == target ? make_pair(rowIdx, left) : make_pair(-1, -1);,其餘完全不動 —— 因為 rowIdx 與 left 本來就是座標,原版只是把它們丟掉了。至於「不小於 target 的最小元素」(二維 lower_bound):第二段要改成右開 right = n 並取 l(而非收斂到單格),因為答案可能落在該列尾端之外 —— 此時 l == n,代表該列全都比 target 小,答案是下一列的第一個元素 (rowIdx+1, 0)(若 rowIdx+1 == m 則不存在)。這是典型的「l 收斂到 n 要接著往下一段找」的情形。
