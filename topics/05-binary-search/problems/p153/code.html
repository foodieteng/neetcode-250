完整實作// THE CODE

p153.cpp C++17 
class Solution {
public:
    int findMin(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            // 參考點永遠是「右端」—— 不是 nums[left],也不是 nums[0]
            if (nums[mid] > nums[right]) {
                left = mid + 1;   // 斷崖在 mid 右邊,mid 不可能是最小
            } else {
                right = mid;       // mid 與 right 同段,mid 自己還是候選
            }
        }

        return nums[left];       // 收斂成單點,那一格就是答案
    }
};

2

最容易犯的那個錯// nums[l] vs nums[r]

「比左端大就往右走」聽起來很順,但它把「一定有旋轉」當成了前提。 題目說旋轉 1 到 n 次,而旋轉 n 次就等於沒動 —— 這個 case 題目還特地寫在敘述裡。

// 錯法:跟 nums[l] 比 · nums = [11,13,15,17](完全沒旋轉) 第 1 輪: l=0 r=3 m=1 nums[m]=13 nums[l]=11 13 > 11 遞增 → l = m+1 = 2 第 2 輪: l=2 r=3 m=2 nums[m]=15 nums[l]=15 不大於 → r = m = 2 l == r == 2 // 得到 nums[2] = 15,正解是 11
// 正解:跟 nums[r] 比 · 同一筆輸入 第 1 輪: l=0 r=3 m=1 nums[m]=13 nums[r]=17 13 < 17 → r = m = 1 第 2 輪: l=0 r=1 m=0 nums[m]=11 nums[r]=13 11 < 13 → r = m = 0 l == r == 0 // 得到 nums[0] = 11 ✓ —— 沒有斷崖時每輪都往左收,自然停在 index 0

根本原因是兩個關係的成立條件不一樣:

關係有旋轉時沒旋轉時
最小值在 nums[r] 的左側或就是它成立成立
最小值在 nums[l] 的右側成立不成立(最小值就是 nums[l])
參考點要挑那個「對所有合法輸入都成立」的。右端就是這樣的錨:不論旋轉幾次, 最小值永遠不會跑到 nums[r] 的右邊 —— 因為它右邊沒有東西。 實測窮舉全部 55 種結構,跟左端比錯 36 組;跟右端比 0 組。

實測(每個 n 窮舉所有旋轉量取最大輪數):n=100 → 7、n=1000 → 10、n=5000 → 13 —— 恰好等於 ceil(log₂ n),一次都沒多。

和 81 對照:那題允許重複值,nums[m] == nums[r] 時分不出方向,只能縮一格,最壞 O(n)。 這題「所有整數相異」那句約束,就是它保持 O(log n) 的全部理由。

邊界與陷阱// PITFALLS

這題的測資空間可以完全窮舉:值相異且是「排序後旋轉」,所以結構只由 (n, 旋轉量 k) 決定, 具體數值無關。長度 1–10 的全部組合共 55 種,下表就是拿改壞的版本跑完這 55 種的結果。

陷阱為什麼錯實測(55 種結構)

// ASYMMETRY: 為什麼一邊 +1、一邊不 +1 nums[mid] > nums[right] : mid 在「高的那段」裡 ⇒ 它右邊某處有斷崖 ⇒ mid 自己絕不是最小 ⇒ 可以跨過 ⇒ left = mid + 1 nums[mid] < nums[right] : mid 與 right 同段遞增 ⇒ 最小值在 [left, mid] ⇒ 但 mid 自己還可能是最小 ⇒ right = mid // 不對稱來自「能不能證明 mid 出局」,和 1095 找峰是同一個道理
// TERMINATION: 為什麼一定收斂 迴圈條件 left < right ⇒ left ≤ mid < right left = mid + 1 ⇒ left 嚴格變大(mid ≥ left) right = mid ⇒ right 嚴格變小(mid < right) // 兩條路都讓區間嚴格縮短 ⇒ 必達 left == right
// EQUALITY: 判斷式不必處理相等 left < right ⇒ mid = left + (right-left)/2 < right ⇒ mid 與 right 是不同索引 題目保證所有整數相異 ⇒ nums[mid] != nums[right] 實測:窮舉所有 n ≤ 200 的旋轉量,140495 次比較中 mid >= right 0 次 nums[mid] == nums[right] 0 次 // 這是 > 與 >= 等價的原因,也是本題不會退化成 O(n) 的原因
// EDGE: 退化輸入(皆已實測) n = 1 [5] → 5,迴圈 0 輪(left == right,直接回傳) 沒旋轉 [11,13,15,17] → 11,2 輪(每輪都往左收) 旋轉 1 [17,11,13,15] → 11 n=5000 未旋轉、值域 -5000..-1 → -5000,13 輪 n=5000 旋轉 4999 次 → -2500,13 輪 // 含負數不影響 —— 程式只做比較,不做算術
