題目簡介// THE QUESTION

QUESTION

一個相異值的遞增陣列被旋轉了 1 到 n 次,回傳它的最小值。 要求 O(log n)。

旋轉後的陣列長成兩段各自遞增的樣子,中間掉一次。最小值就是那個斷崖的底。 整條不是有序的,所以不能直接二分找值 —— 但「我現在站在斷崖的哪一側」這件事, 只要跟一個固定的參考點比就能知道。

這題的全部難度濃縮在一個選擇上:參考點要選右端 nums[r],不能選左端 nums[l]。 選錯的話,程式在「旋轉 n 次 = 完全沒動」那個 case 上會壞掉 —— 而那正是題目特地在敘述裡點出來的例子。
2

參考點為什麼是右端// WHY nums[r]

A 線性掃描取 min O(n)
一定對,n ≤ 5000 也跑得動。但題目明文要求 O(log n),而且這題存在的意義就是練旋轉陣列的二分。
× REJECT · 不符要求
B 跟左端 nums[l] 比 O(log n)
直覺上很順:「比左端大就是還在前半段,往右走」。但完全沒旋轉時整條都遞增, nums[m] > nums[l] 恆成立,指標一路往右跑過頭。 實測窮舉 55 種結構錯 36 組,最小反例 [1,0] 答 1。
× REJECT · 未旋轉就壞
BOTH FAIL · ADOPT
C 跟右端 nums[r] 比 O(log n)
nums[m] > nums[r] ⇒ 斷崖夾在 m 和 r 之間 ⇒ 最小值在 m 右邊,m 可排除 ⇒ l = m + 1。
nums[m] < nums[r] ⇒ m 和 r 同段遞增 ⇒ 最小值在 m 或更左,m 不能排除 ⇒ r = m。
沒旋轉時第二條恆成立,每輪都往左收,自然停在 index 0 —— 不用特判。
● ADOPT · 0/55 錯
為什麼右端行、左端不行?因為最小值永遠在「右端的左側或就是它」,這個關係旋不旋轉都成立; 而「最小值在左端的右側」只有真的旋轉過才對。參考點要挑那個對所有輸入都成立的。
3

核心策略 · 三步驟// STRATEGY

  1. 區間 [l, r] = [0, n-1],迴圈條件 while (l < r)(收斂型,答案必存在)。
  2. 比較 nums[m] 與 nums[r] —— 永遠是右端,不是左端、不是 nums[0]。
  3. 收縮:大於 → l = m + 1(m 已被證明不是最小);小於 → r = m(不減 1,m 還是候選)。收斂後 return nums[l]。

不變量與兩個不對稱的分支// THE INVARIANT

LEMMA · 最小值永遠留在 [l, r] 裡

初始:[0, n-1] 是整條陣列,顯然含最小值。

nums[m] > nums[r](往右收) —— 若 m 和 r 在同一段遞增裡, 必有 nums[m] ≤ nums[r]。既然反了,斷崖一定夾在 (m, r] 之間。 於是最小值落在 [m+1, r],而且 m 本身在高的那一段、絕不可能是最小值 ⇒ l = m + 1 安全。

nums[m] < nums[r](往左收) —— m 和 r 同段, 所以 (m, r] 這一段全都比 nums[m] 大,最小值只可能在 [l, m]。 但 m 自己還可能就是最小值(例如 [0,1] 的 m = 0)⇒ 只能寫 r = m,不能減 1。

兩條路都保住不變量,而且都讓區間嚴格縮短 ⇒ 必定收斂到 l == r,那一格就是答案。 把 r = m 寫成 r = m - 1 會把答案丟出區間 —— 實測 55 組錯 17 組,最小反例 [2,0,1] 答 2。

// 為什麼判斷式不必處理「相等」 迴圈條件 l < r ⇒ m = l + (r-l)/2 < r ⇒ m 與 r 必定是不同的索引 題目保證所有值相異 ⇒ nums[m] != nums[r] 實測:窮舉所有 n ≤ 200 的旋轉量,共 140495 次比較 m >= r 出現 0 次 nums[m] == nums[r] 出現 0 次 // 所以 > 寫成 >= 完全等價,兩種都對(實測皆 0/55 錯)
這也正是 81 為什麼難那麼多:一旦允許重複值,nums[m] == nums[r] 就會發生, 而那時分不出在斷崖哪一側,只能保守縮一格,最壞退化成 O(n)。

複雜度// COMPLEXITY

T = O(log n)　　S = O(1)

每輪區間至少砍半,沒有 81 那種退化情形 —— 因為值相異,永遠分得出方向。

// 實測迴圈輪數(每個 n 窮舉所有旋轉量取最大) n = 1 → 0 輪 ceil(log2 n) = 0 n = 2 → 1 輪 1 n = 5 → 3 輪 3 n = 10 → 4 輪 4 n = 100 → 7 輪 7 n = 1000 → 10 輪 10 n = 5000 → 13 輪 13 ← 題目上限 // 恰好等於 ceil(log2 n),一次都沒多

一句洞察// INSIGHT

二分要的不是「有序」,是一個能用 O(1) 回答「答案在左還是在右」的判準。 這題的陣列整體並不有序,但只要挑對參考點(右端),那個判準就成立了 —— 選錯參考點不是效率問題,是正確性問題。
