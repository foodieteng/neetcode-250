完整實作// THE CODE

// MountainArray 由 judge 提供,只有 get(index) 與 length()

class Solution {
    // 在 [lo, hi] 這段「已知單調」的區間裡二分
    // ascending 說明它是遞增段還是遞減段
    int binarySearch(MountainArray& arr, int target, int lo, int hi, bool ascending) {
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int value = arr.get(mid);

            if (value == target) {
                return mid;
            }

            // 遞增段:值太小要往右;遞減段:值太小要往左
            if ((value < target) == ascending) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }

        return -1;
    }

public:
    int findInMountainArray(int target, MountainArray& mountainArr) {
        int n = mountainArr.length();

        // PHASE 1 · 二分坡向找峰(每輪讀相鄰兩格)
        int left = 0, right = n - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;

            if (mountainArr.get(mid) < mountainArr.get(mid + 1)) {
                left = mid + 1;   // 上坡 → mid 不可能是峰,跨過
            } else {
                right = mid;       // 下坡 → mid 可能就是峰,保留
            }
        }
        int peak = left;

        // PHASE 2 · 左半遞增,含 peak;先搜這半才拿得到最小索引
        int index = binarySearch(mountainArr, target, 0, peak, true);
        if (index != -1) {
            return index;
        }

        // PHASE 3 · 右半遞減
        return binarySearch(mountainArr, target, peak + 1, n - 1, false);
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

三個階段用了兩種不同的二分模板,這不是隨便挑的:找峰用 while (left < right) + right = mid (收斂到一個位置,答案必存在);搜值用 while (lo <= hi) + hi = mid - 1 (可能找不到,要能回 −1)。用途不同,模板就不同。
2

(value < target) == ascending 在做什麼// ONE XNOR

這一行把「升序搜」和「降序搜」合併成同一段程式碼。拆開看就是四種組合:

ascendingvalue < target該往哪條件式的值
true(遞增)true(值太小)往右找更大的true → lo = mid+1
true(遞增)false(值太大)往左false → hi = mid−1
false(遞減)true(值太小)往左找更大的false → hi = mid−1
false(遞減)false(值太大)往右true → lo = mid+1

也就是 XNOR(同號為真):兩個布林值一致就往右,不一致就往左。 直觀的講法是「遞減段等於把比較反過來」。

// 忘了 asc(兩半都當升序)會壞在哪 if (v < target) lo = mid + 1; else hi = mid - 1; // 少了 == asc 實測最小反例:arr=[0,3,2,1], target=1 peak = 1,左半 [0,1] 找不到 1 → 進右半 [2,3] = 值 [2,1] mid=2, v=2 > 1 → (錯)往左 hi=1 → lo>hi 結束 但 1 其實在 index 3,在 mid 的右邊 變體全掃:6360 組裡錯 728 組 // 回傳 -1,正解 3

下表的反例都是實測出來的:窮舉所有長度 3–7、值域 0–5 的山形陣列(共 6360 組 陣列×target), 拿改壞的版本跟線性掃描參考解對拍,取最短的失敗輸入。

錯 1100/6360
binarySearch 忘了 ascending 降序半的比較方向沒反過來,整半段失效 [0,3,2,1] t=1 → −1(正解 3)
錯 728/6360
左 [0, peak-1] 且右 [peak+1, n-1] 峰本身被兩邊都漏掉了 [0,1,0] t=1 → −1(正解 1)
錯 1060/6360
左 [0, peak-1]、右 [peak, n-1] 這樣是對的 —— peak 只要被恰好一邊蓋到就行,而且它在山上只出現一次,不影響最小索引 錯 0/6360
左 [0, peak]、右 [peak, n-1] 也對,只是 peak 被驗兩次。實測 n=10⁴ 最壞仍是 53 次 —— 因為左半命中就 return 了,重複那次幾乎不會發生 錯 0/6360
注意最後兩列:不是每個看起來可疑的邊界都真的有 bug。峰的歸屬有三種寫法都對,只有「兩邊都不含」那種會錯。 判準很單純 —— 每個索引至少被蓋到一次,且左半優先。

// PHASE 1: 兩個分支為什麼不對稱(一個 +1、一個不 +1) 上坡 get(m) < get(m+1): 遞增段的每一格都比右鄰小 ⇒ m 自己「絕不是峰」⇒ 可以跨過 ⇒ left = m + 1 下坡 get(m) > get(m+1): m 要嘛「就是峰」,要嘛在遞減段 ⇒ 不能排除 m ⇒ right = m // 不對稱來自資訊量不同:上坡能否證 m,下坡不能
// PHASE 1: get(mid + 1) 為什麼不會越界 迴圈條件 left < right ⇒ mid = left + (right-left)/2 滿足 left ≤ mid < right 又 right ≤ n - 1 ⇒ mid < n - 1 ⇒ mid + 1 ≤ n - 1 // 恆在範圍內。實測 4363 座山、每次 get 都加越界偵測,零次觸發
// PHASE 1: 為什麼一定收斂(不會死迴圈) 上坡 left = mid + 1 ⇒ left 嚴格變大(mid ≥ left) 下坡 right = mid ⇒ right 嚴格變小(mid < right) // 兩條路都讓區間嚴格縮短 ⇒ 必達 left == right
// PHASE 2/3: 為什麼「最小索引」靠順序就解決了 山形是嚴格遞增再嚴格遞減 ⇒ 同一段內不會有重複值 ⇒ 任何 target 在整座山上最多出現 2 次(左半一次、右半一次) ⇒ 左半的索引必定小於右半 ⇒ 先搜左半、找到就 return,拿到的就是最小索引 // 不需要「找到後再往左壓」那套(對比 704 的 lower_bound 寫法)
// EDGE: 退化輸入(皆已實測) n = 3 是最小合法輸入(題目保證 length ≥ 3 且峰不在兩端) [1,5,2] t=5 → 1(峰本身),get 6 次 [1,5,2] t=2 → 2(右半), get 7 次 [1,5,2] t=9 → -1, get 7 次 峰在最左 p=1:找 arr[0] → 0,get 29 次(n=10⁴) 峰在最右 p=n-2:找 arr[0] → 0,get 39 次(n=10⁴) // 題目保證 0 < peak < n-1,所以左右兩半都非空,不必特判
