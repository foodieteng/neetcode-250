p704.cpp C++17 
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int n = nums.size();
        int left = 0, right = n;          // 候選區間 [left, right) —— 右開,所以初值是 n

        while (left < right) {            // 區間非空才繼續
            int mid = left + (right - left) / 2;   // 防溢位寫法,等價 (left+right)/2

            if (nums[mid] >= target) {
                right = mid;              // mid 本身還可能是答案 → 保留(不減 1)
            } else {
                left = mid + 1;          // mid 太小,已出局 → 丟掉(一定加 1)
            }
        }
        // 離開迴圈時 left == right == 第一個 >= target 的位置

        if (left == n) return -1;       // 全部都比 target 小
        return nums[left] == target ? left : -1;  // 位置對了,值不一定等
    }
};

四個對子要成套:right = n、left < right、right = mid、left = mid + 1。 迴圈不做等於判斷,只壓邊界;命中與否交給最後兩行。

為什麼一邊 +1、一邊不減 1// ASYMMETRY

判斷mid 還可能是答案?怎麼寫區間變化
nums[mid] >= target 可能(它本身就 ≥) right = mid 右界收到 mid,因右開而仍含 mid−1 以左,mid 保留在候選
nums[mid] < target 不可能(太小) left = mid + 1 mid 連同左半一起排除
// 為什麼不會無窮迴圈 mid = left + (right-left)/2 → 整數除法向下取整 ⇒ left <= mid < right (mid 必定落在區間內,且 mid 不會等於 right) 分支一 right = mid : 因 mid < right,right 嚴格變小 分支二 left = mid+1 : 因 mid >= left,left 嚴格變大 // 兩邊都保證區間嚴格變短 → 必定收斂到 left == right
// 反例:右開區間卻誤寫 right = mid - 1(把閉區間的寫法混進來) nums = [0,1], target = 1 // 最小的反例 left=0, right=2 mid = 1, nums[1] = 1 >= 1 → right = mid - 1 = 0 ← 唯一的答案位置被刪掉了 left(0) < right(0) 不成立 → 離開迴圈,left = 0 nums[0] = 0 != 1 // 回傳 -1(正解應為 1)。右開區間就寫 right = mid,別憑感覺減 1

步驟成本說明

迴圈外驗證O(1)兩個判斷

迭代版沒有遞迴堆疊;遞迴版雖同為 O(log n) 時間,但空間變 O(log n)。

邊界與陷阱// PITFALLS

陷阱後果正解
right = n 卻寫 left <= right 會取到 mid = n,讀 nums[n] 越界 右開就配 left < right
右分支寫成 right = mid − 1 把可能的答案位置一起刪掉 右開區間 → right = mid
左分支寫成 left = mid 區間沒縮短 → 無窮迴圈 必須 left = mid + 1
忘記迴圈外那兩道檢查 target 不存在時回傳錯誤索引 left == n 先擋,再比 nums[left] == target
left == nums.size() 直接比 int 與 size_t 比較,編譯器警告 / 隱式轉型 先取 int n = nums.size(); 再比
mid = (left + right) / 2 本題 n ≤ 10⁴ 不會溢位 仍建議寫 left + (right − left) / 2 養成習慣
