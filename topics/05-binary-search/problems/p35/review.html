重點回顧// RECAP

面向要點
核心「找到回索引」和「沒找到回插入點」是同一個值
那個值第一個 nums[i] ≥ target 的位置 = lower_bound
區間左閉右開 [0, n),right 初值 = n
兩個分支≥ → right = mid;< → left = mid + 1
收尾return left; —— 不特判、不比較
為何不用擋 n插入位置合法範圍是 [0, n],含 n
與 704 的差704 回傳「格」要驗證,35 回傳「縫」不用
複雜度時間 O(log n),空間 O(1)

觀念題// QUIZ

Q1. 為什麼「找到回索引」與「找不到回插入點」可以用同一個 return 處理?請用「第一個 ≥ target 的位置」把兩件事說成一件事。
Q2. 704 需要 if (left == n) return -1;,本題卻不能加。為什麼同一個 left = n 在兩題的地位完全相反?
Q3. 把判斷式從 nums[mid] >= target 改成 >,回傳值會變成什麼?在命中與沒命中兩種情形分別差多少?
Q4. 若 right 初值誤寫成 n − 1,哪一個測資會第一個爆?寫出一組最小反例並說明結果。
Q5. 題目保證元素相異。如果允許重複,這份程式碼回傳的會是哪一個位置?語意還成立嗎?

範例 Trace// [1,3,5,6]

// 縫的編號 = 插入後的索引 | 1 | 3 | 5 | 6 | 0 1 2 3 4 n = 4,答案的合法範圍是 0…4
// CASE A: target = 5(命中) [0,4) mid=2 nums[2]=5 >= 5 → right = 2 [0,2) mid=1 nums[1]=3 < 5 → left = 2 [2,2) 空 → 離開 // return 2
// CASE B: target = 2(沒命中,插中間) [0,4) mid=2 nums[2]=5 >= 2 → right = 2 [0,2) mid=1 nums[1]=3 >= 2 → right = 1 [0,1) mid=0 nums[0]=1 < 2 → left = 1 [1,1) 空 → 離開 // return 1 → [1,2,3,5,6]
// CASE C: target = 7(比全部大,插最後) [0,4) mid=2 nums[2]=5 < 7 → left = 3 [3,4) mid=3 nums[3]=6 < 7 → left = 4 [4,4) 空 → 離開 // return 4 = n → [1,3,5,6,7]
// CASE D: target = 0(比全部小,插最前) [0,4) mid=2 nums[2]=5 >= 0 → right = 2 [0,2) mid=1 nums[1]=3 >= 0 → right = 1 [0,1) mid=0 nums[0]=1 >= 0 → right = 0 [0,0) 空 → 離開 // return 0 → [0,1,3,5,6]
四個 case、四種語意,程式碼一行都沒有分岔。 特別看 CASE C:left 停在 4 = n,這在 704 是要攔下來的越界值,在這裡卻是正確答案。

應用題// APPLY

App 1. 用本題的 lower_bound 再寫一個 upper_bound(第一個 > target 的位置),然後說明如何用兩者算出 target 在陣列中的出現次數,以及這如何解 34. Find First and Last Position。
App 2. 300. Longest Increasing Subsequence 的 O(n log n) 解法,核心就是對一個遞增的 tails 陣列反覆做本題的動作。請說明:每個新元素找到插入位置後,是覆蓋該格還是 append?為什麼這兩種情況剛好對應 left < len 與 left == len?
App 3. 若陣列不是升冪而是降冪排序,要找插入位置,程式碼要改哪裡?(提示:只需要動一個符號,想清楚「單調的方向」是什麼。)
// ANSWERS
A1. 兩件事都在問「target 該待在哪個位置」。定義 p = 第一個滿足 nums[i] ≥ target 的索引。若 target 存在,因為排序,它的位置就是第一個 ≥ 它的地方,所以 p 正是它的索引。若 target 不存在,則 nums[p−1] < target < nums[p],把 target 插在 p 這格,前面全比它小、後面全比它大,陣列仍遞增,所以 p 就是插入點。同一個 p,兩種讀法。因此一個 return left; 就夠。
A2. 差別在回傳的東西是「格」還是「縫」。704 要回傳元素的索引,合法值只有 0 … n−1;left = n 代表「沒有任何元素 ≥ target」,那是越界,必須轉成 -1(而且要在讀 nums[left] 之前擋)。35 要回傳插入位置,而長度 n 的陣列有 n + 1 道縫,合法值是 0 … n,left = n 剛好表示「插在最尾端」—— 是正確答案。若照抄 704 的特判,nums=[1,3,5,6], target=7 就會從 4 變成 -1,直接錯。
A3. 改成 > 得到的是 upper_bound:第一個嚴格大於 target 的位置。沒命中時兩者完全相同(沒有等於 target 的元素,「≥」與「>」的第一個位置是同一格),所以插入點答案不變。命中時就差 1:元素相異的前提下,lower_bound 指向 target 那格,upper_bound 指向它後面那格。所以本題若誤用 >,target=5 會回傳 3 而不是 2 —— 只有命中的測資會爆,這種 bug 特別難抓。
A4. 最小反例:nums = [1], target = 2。正解是 1(插在最後)。若寫 right = n − 1 = 0,迴圈條件 left(0) < right(0) 一開始就不成立,一輪都沒跑就回傳 left = 0 → 錯。更一般地說:right 初值決定了 left 能到達的最大值,寫 n − 1 就永遠回傳不了 n,於是所有「比全部元素都大」的測資全錯。這也是為什麼右開區間的 right = n 不是隨便選的。
A5. 會回傳第一個等於 target 的位置(這正是 lower_bound 的定義),因為 ≥ 讓等號歸在左側,指標會一路往左壓過整段相等區。語意仍然成立:把 target 插在「第一個等於它的位置」之前,陣列依舊非遞減,是合法的插入點。想插在相等區之後的話,把判斷式改成 > 即可(upper_bound)—— 兩者都是合法插入點,差別只在你要它排在同值元素的前面還是後面。
App 1. upper_bound 只要把判斷式從 nums[mid] >= target 改成 nums[mid] > target,其餘一字不改。出現次數 = upper_bound(target) − lower_bound(target),因為相等的元素在排序陣列中必然連成一段,兩個邊界正好夾住它。34 題要「第一個與最後一個位置」:第一個 = lo = lower_bound(target)(若 lo == n 或 nums[lo] != target 則回 [-1,-1]),最後一個 = upper_bound(target) − 1。兩次二分,總計仍是 O(log n)。
App 2. tails[i] 存「長度 i+1 的遞增子序列的最小結尾」,它必為遞增,所以可以二分。對新元素 x 求 p = lower_bound(tails, x):若 p == len,代表 x 比目前所有結尾都大,能把最長長度延長一格 → append,len++;若 p < len,代表存在某個長度的結尾 ≥ x,用 x 取代它會讓同長度的結尾更小、更好接 → 覆蓋 tails[p] = x。兩種情況對應的正是本題 left 落在 [0, len) 還是等於 len —— 又一次「n 是合法答案」的用途。整體 O(n log n)。
App 3. 只要把判斷式的比較方向反過來:nums[mid] <= target → right = mid,否則 left = mid + 1。原理不變 —— 骨架真正要求的是「判斷式沿著索引單調由 F 變 T」。升冪時「≥ target」是 F…FT…T;降冪時改成「≤ target」才有同樣的形狀(前面都比 target 大 → F,之後都 ≤ target → T)。收斂後 left 一樣是第一個 T,也就是降冪陣列中該插入的位置。記住形狀,而不是記住那個 ≥ 符號。
