完整實作 · 骨架本身// return left

p35.cpp C++17 
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int left = 0, right = nums.size();   // 候選區間 [left, right),right = n

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] >= target) {
                right = mid;              // mid 可能就是插入點 → 保留
            } else {
                left = mid + 1;          // mid 太小,插入點在它右邊 → 丟掉
            }
        }

        return left;                     // 命中時是索引,沒命中時是插入點 —— 同一個值
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

這份程式碼就是 std::lower_bound(回傳的是索引而非迭代器)。實測與 lower_bound 在所有小規模遞增陣列上逐一比對零差異。 面試時可以直接說「這是手寫的 lower_bound」,對方立刻懂。

和 704 的唯一差別// DIFF

部位35 本題704
區間初值[0, n)[0, n) 相同
迴圈條件left < right相同
兩個分支right = mid / left = mid + 1相同
收尾return left;left == n ? -1 : (nums[left]==target ? left : -1)
回傳語意縫(0 … n)格(0 … n−1,否則 -1)
// 一句話記法 迴圈的產物永遠是「第一個 >= target 的位置」。 問「它該插哪」→ 直接回傳 (35) 問「它在不在」→ 再驗一次那一格 (704) 問「它出現幾次」→ 配 upper_bound 相減 (34) // 同一個迴圈,不同的問題只差在收尾

複雜度分析// COMPLEXITY

步驟成本說明
每輪一次比較O(1)只讀 nums[mid]
總輪數⌈log₂n⌉區間至少對半
收尾O(1)單純 return
T = O(log n)　　S = O(1)

n = 10⁴ → 約 14 輪。若題目改成要真的插入元素,搬移是 O(n),那時瓶頸就不在搜尋。

邊界與陷阱// PITFALLS

陷阱後果正解
擔心 left == n 而加特判 把「插在最後」誤判成錯誤 → target=7 回傳錯 n 是合法答案,不要擋
right = n − 1 起始 插入點永遠碰不到 n,比全部大時答錯 右開區間 → right = n
判斷式用 > 而非 ≥ 命中時回傳的是它後面那格(upper_bound) 要 lower_bound → 用 ≥
左分支寫成 left = mid 區間不縮 → 無窮迴圈 left = mid + 1
迴圈裡加 if (nums[mid] == target) return mid; 答案仍對(值相異) 但多一個分支、失去 lower_bound 語意,不建議
最值得注意的是第一列:「多加一個看似安全的特判」反而寫錯。 如果從 704 帶著 left == n → -1 的肌肉記憶過來,這題就會在 target=7 掛掉。
