題目簡介// THE QUESTION

QUESTION

給升冪排序、元素相異的陣列 nums 與 target:找到就回傳索引,找不到就回傳它應該被插入的位置(插入後陣列仍遞增)。要求 O(log n)。 例 [1,3,5,6]:target=5 → 2;target=2 → 1;target=7 → 4。

這題和 704 是同一副骨架,而且更純粹:704 的迴圈本來就在找「第一個 ≥ target 的位置」, 只是 704 還要多問一句「那格真的等於 target 嗎」。35 連那句都不用問 —— 迴圈的結果直接就是答案。 換句話說,35 才是骨架本身,704 是骨架 + 一次驗證。

為什麼答案一定是 left// WHY THIS

A 線性掃到第一個 ≥ target O(n)
邏輯最直觀,但沒用上排序,不符 O(log n) 的要求。
× REJECT · 不符要求
B 先二分找命中,沒中再另外算插入點 O(log n)
要分「找到」與「沒找到」兩套收尾,還得判斷 left/right 誰才是插入點 —— 正是最容易寫錯 ±1 的地方。
△ REJECT · 多餘的分岔
BOTH FAIL · ADOPT
C 左閉右開邊界二分,直接 return left O(log n)
「命中」與「沒命中」本來就是同一個答案:第一個 ≥ target 的位置。命中時那格就是 target 的索引;沒命中時把 target 塞進那格,前面全都比它小、後面全都比它大 —— 剛好維持遞增。不需要任何特判,連 left == n 都不用。
● ADOPT · STABLE
3

核心策略 · 三步驟// STRATEGY

  1. 定義區間:left = 0、right = n。答案的可能範圍是 0 … n(含 n —— 比全部都大時插在最後),這正好是右開區間端點的取值範圍。
  2. 收縮:nums[mid] ≥ target → right = mid;否則 left = mid + 1。
  3. 回傳:return left; —— 沒有 if、沒有特判、沒有第二次比較。

為什麼連 left == n 都不用擋// LEMMA

LEMMA · 插入位置的合法範圍恰好是 0 … n

長度 n 的陣列有 n + 1 道縫:最前面一道、每兩格之間 n−1 道、最後面一道。把它們編號成 0, 1, …, n,「插在第 k 道縫」就等於「插入後 target 的索引是 k」。 所以答案的合法範圍本來就是 [0, n],包含 n。

而迴圈收斂後 left 的取值範圍恰好也是 [0, n]:全部都 ≥ target 時 left = 0,全部都 < target 時 left = n。兩個範圍完全對上,一個都不多、一個都不少。

對照 704:704 要回傳的是索引,合法範圍只有 [0, n−1],所以 left == n 對它是非法值,必須擋下來變成 -1。 同樣一個 left = n,在 35 是好答案,在 704 是要攔的錯誤 —— 差別只在「回傳的是縫還是格」。

這就是為什麼建議先熟 35、再記 704:35 是乾淨的骨架,704 是骨架加一層驗證。 反過來從 704 學,容易誤以為「二分一定要有一個等於判斷」。
