完整實作 · 值域二分// template + check()

p875.cpp C++17 
class Solution {
public:
    int minEatingSpeed(vector<int>& piles, int h) {
        // 值域區間 [1, max+1) —— 右開,所以 max 要 +1 才取得到
        int left = 1;
        int right = *max_element(piles.begin(), piles.end()) + 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (getTime(piles, mid) <= h) {
                right = mid;              // 來得及 → 也許還能更慢,保留 mid
            } else {
                left = mid + 1;          // 來不及 → 太慢了,跨過 mid
            }
        }

        return left;                     // 第一個可行速度;答案保證存在,不必驗證
    }

    int getTime(vector<int>& piles, int k) {
        int t = 0;

        for (int p : piles) {
            t += ceil((double)(p) / k);   // 每堆各自向上取整(吃不滿也佔一小時)
        }

        return t;
    }
};

向上取整的三種寫法// CEILING DIVISION

寫法安全性說明
ceil((double)p / k) 本題安全 本頁採用。double 有 53 位尾數,p ≤ 10⁹ 可精確表示;實測 1500 萬組(含所有整除邊界)與整數版零誤差
(p + k − 1) / k 最推薦 純整數,沒有浮點疑慮。注意 p + k − 1 在 p, k 都接近 2³¹ 時會溢位,要用 long long
p / k + (p % k != 0) 絕對安全 不會有任何溢位,但多一次取餘
// 為什麼這題的浮點 ceil 不會出錯 危險情境是「真正的商剛好是整數,浮點卻算成 2.0000000001 → ceil 多加 1」。 本題不會發生,因為: ① p ≤ 1e9 < 2^53,(double)p 完全精確 ② IEEE 除法是「正確捨入」:若真商剛好是整數,結果就是那個整數,無誤差 ③ 若真商不是整數,它與最近整數至少差 1/k ≥ 1e-9, 而 double 在此範圍的相對誤差約 1e-16 —— 差了七個數量級,不可能跨過去 // 實測 1500 萬組(整除點 ±1 密集掃 + 大值隨機)零不一致

getTime 回傳 int 會不會爆?// THE OVERFLOW QUESTION

這是本題最值得想清楚的一點。getTime 用 int 累加,而理論上總時數可以很大: k = 1 且 10⁴ 堆各 10⁹ 根時,總時數是 10¹³ —— 遠超 INT_MAX(約 2.15×10⁹)。 那為什麼這份程式碼還是對的?

ANALYSIS · 二分永遠不會探到那麼小的 k

關鍵是:getTime 只會被二分呼叫,而二分是從上往下折半逼近答案 A 的。 當 mid 小於 A 時判斷立刻失敗、left 跳上去,所以造訪過的最小 k 不會低於 A/2。

而 ⌈p/(A/2)⌉ ≤ 2⌈p/A⌉,對每堆都成立,相加得 getTime(A/2) ≤ 2 · getTime(A) ≤ 2h。 題目保證 h ≤ 10⁹,所以造訪過的時數最多約 2×10⁹ < INT_MAX。

實測佐證:20 萬組隨機輸入中,「A ÷ 造訪過的最小 k」的上限恰好是 2,與推導一致。 用 10⁴ 堆 × 10⁹ 根、h = 10⁹ 的極端輸入實跑,過程中出現的最大時數是 1,310,620,000,仍在 int 範圍內,答案 10000 正確。

結論:在本題的約束下 int 安全,但這份安全是「借來的」 —— 它依賴 h ≤ 10⁹ 這條約束,以及「getTime 只被二分以那種順序呼叫」。 只要 h 的上限放寬、或有人把 getTime 單獨拿去用(例如 getTime(piles, 1)),立刻溢位。 所以實務上仍建議把回傳型別寫成 long long —— 成本是零,換掉一個需要三行推導才能說服自己的隱患。

複雜度分析// COMPLEXITY

步驟成本說明
max_elementO(n)只做一次
單次 getTimeO(n)掃過所有堆
二分輪數O(log C)C = max(piles) ≤ 10⁹ → 約 30
合計O(n log C)10⁴ × 30 = 3×10⁵
T = O(n log C)　　S = O(1)

答案二分的通則:總複雜度 = 二分輪數 × 單次 check 的成本。

邊界與陷阱// PITFALLS

陷阱後果正解
left = 0 起始 p / 0 → 除以零 速度至少 1 → left = 1
right = max(piles)(沒 +1) 右開區間取不到 max。若答案正好是 max 就會錯 max + 1;或改用閉區間寫法
判斷式寫 < h 「剛好用滿 h 小時」被誤判為不可行 → 答案偏大 必須 <= h
整堆一起除:ceil(總數 / k) 每小時只能吃一堆,不能跨堆 逐堆取整再相加
getTime 回傳 int 本題約束下安全(見上節推導) 但建議寫 long long,不必靠推導保平安
用公式 ⌈總數 / h⌉ 直接算 忽略「吃不滿也佔一小時」的浪費 [1,1,1,99], h=5:公式 21,正解 50
