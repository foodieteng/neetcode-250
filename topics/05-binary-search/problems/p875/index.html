題目簡介// THE QUESTION

QUESTION

n 堆香蕉,第 i 堆有 piles[i] 根。警衛 h 小時後回來。 科科挑一個固定速度 k(根/小時):每小時挑一堆吃 k 根,不夠 k 根就吃完該堆並休息到下一小時。 求能在 h 小時內吃完的最小 k。

注意題目沒有給你要搜尋的陣列 —— piles 甚至不必排序。要二分的是答案 k 本身。 這就是模板頁提到的答案二分(值域二分),而 875 是它的原型題: 骨架一字不改,只把「nums[m] 比大小」換成「check(m)」。

2

為什麼能二分「答案」// WHY THIS

A 從 k=1 一路試上去 O(n · maxPile)
答案正確,但 maxPile 可到 10⁹、n 可到 10⁴ → 10¹³ 次運算,完全不可能。
× REJECT · TLE
B 用公式直接算出 k O(n)
想用 k = ⌈總數 / h⌉ 一步解出來。但每小時只能吃一堆,吃不滿的那小時會浪費 —— piles=[1,1,1,99], h=5 公式得 ⌈102/5⌉ = 21,實際答案卻是 50(三小堆各佔掉一整個小時,只剩 2 小時吃 99 根)。官方範例 [30,11,23,4,20], h=5 也一樣:公式 18、正解 30。
△ REJECT · 公式不成立
BOTH FAIL · ADOPT
C 對答案的值域二分,用 check(k) 當判斷式 O(n log maxPile)
正著算 k 很難,但反過來驗證一個 k 行不行很容易:check(k) = (Σ⌈pile/k⌉ ≤ h),一趟 O(n)。 而 k 越大越容易吃完 ⇒ check 單調 ⇒ 候選帶仍是 F F F T T T ⇒ 通用模板直接套,找第一個 T。
● ADOPT · O(n log C)
答案二分的判斷標準只有一句:「求解很難,但驗證很容易,而且驗證結果隨答案單調」。 符合這三點,就把答案本身當成搜尋空間。
3

核心策略 · 三步驟// STRATEGY

  1. 定值域:left = 1(速度不能是 0,否則除以零)、right = max(piles) + 1(寫 max 也對,見第 6 節)。
  2. 寫 check:getTime(k) = Σ ⌈piles[i] / k⌉,判斷式 getTime(mid) ≤ h。
  3. 套模板:成立 → right = mid(可行,但也許還能更慢);否則 → left = mid + 1。收斂後 return left,不需額外驗證(答案保證存在)。

單調性:整個做法的地基// THE MONOTONICITY

LEMMA · k 變大,所需時數不會變多

對每一堆而言,⌈pile / k⌉ 隨著 k 變大而單調不增(除數變大,商不會變大)。 總時數是各堆相加,所以 getTime(k) 整體也單調不增。

於是 check(k) = (getTime(k) ≤ h) 一旦成立,所有更大的 k 也都成立 —— 這正是 F F F T T T: 左邊一段太慢(F),右邊一段來得及(T),中間有唯一的分界。我們要的就是第一個 T。

答案一定存在:取 k = max(piles) 時每堆都只花 1 小時,總共 n 小時,而題目保證 h ≥ n ⇒ 這個 k 必定可行。 所以整條帶子至少最後一格是 T,l 不會跑出界,也不需要像 704 那樣再驗一次。

6

值域的三個邊界為什麼那樣取// THE BOUNDS

位置取值理由
左界 left = 1 速度至少 1。取 0 會讓 pile / k 除以零,而且 0 永遠不可行,沒有意義
右界 right = max(piles) + 1 速度超過 max(piles) 完全沒有幫助(每小時最多吃掉一整堆),所以 max 就是答案上限。這裡寫成 max 或 max + 1 都對 —— 見下方說明
判斷式 getTime(mid) ≤ h 剛好用滿 h 小時也算來得及。寫成嚴格 < 會把「正好 h 小時」的合法解排除掉
NOTE · 這題的 +1 可加可不加(和 704 不同)

[1, max+1) 與 [1, max] 兩種寫法答案完全相同 —— 實測 20 萬組隨機輸入零不一致,連「答案正好等於 max」的 [30,11,23,4,20], h=5 兩者都回 30。

原因是本題答案保證存在:不變量「答案 ∈ [left, right]」在初始就成立,迴圈只會收斂到它。 +1 真正的用途是留出「全部都不可行」的哨兵位置(像 704 的 l == n 代表沒找到)—— 這題不需要那個哨兵。兩種都寫得出來,重點是知道自己在用哪一套語意。

// 動畫那組正好踩到「等號」 piles=[3,6,7,11], h=8 k=4 → ⌈3/4⌉+⌈6/4⌉+⌈7/4⌉+⌈11/4⌉ = 1+2+2+3 = 8 ← 剛好等於 h 若判斷式寫成 getTime(mid) < h,k=4 會被判為不可行 → 答案變成 6 // 正解 4。「來得及」包含「剛好趕上」

複雜度// COMPLEXITY

T = O(n · log maxPile)　　S = O(1)

和一般二分的差別:每次判斷不再是 O(1),而是 O(n) 的模擬。 n = 10⁴、maxPile = 10⁹ → 約 10⁴ × 30 = 3×10⁵ 次運算,非常寬裕。

維度量級說明

SpaceO(1)只有幾個變數
二分輪數≈ 30log₂(10⁹)
單次 checkO(n)掃過所有堆

一句洞察// INSIGHT

正著求答案很難,反過來驗證一個答案很容易 —— 那就二分答案。 骨架完全不用改,只把「讀 nums[mid] 比大小」換成「跑一次 check(mid)」, 把「索引區間」換成「值域區間 [1, max+1)」。
