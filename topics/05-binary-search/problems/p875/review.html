重點回顧// RECAP

面向要點
套用時機求解難、驗證易、驗證隨答案單調
搜尋空間答案的值域 [1, max(piles)+1)
判斷式check(k) = (Σ⌈pile/k⌉ ≤ h)
單調理由⌈p/k⌉ 隨 k 單調不增(非嚴格)
收縮可行 → right = mid;不可行 → left = mid + 1
收尾return left —— 答案保證存在,免驗證
等號≤ h:剛好用滿也算來得及
複雜度O(n log C) = 輪數 × 單次 check

應用題// APPLY

App 1. 1011. Capacity To Ship Packages Within D Days:給包裹重量陣列與天數 D,求最小船運載量。請寫出它的 check、值域左右界,並說明為什麼左界不能取 1。
App 2. 410. Split Array Largest Sum:把陣列切成 k 段,最小化「各段和的最大值」。它為什麼也是答案二分?check 該怎麼寫?
App 3. 若題目改成求「最大可行答案」(例如:分巧克力,最大化最小甜度),模板要怎麼調整?收斂後該回傳 l 還是 l − 1?
// ANSWERS
A1. 二分的是答案本身的值域 —— 這裡是速度 k ∈ [1, max(piles)]。要成立必須檢查三件事:① 答案落在一個可列舉的區間內(這裡是 1 到 max);② 給定一個候選答案,能有效驗證它可不可行(check(k) 只要 O(n));③ 驗證結果隨候選答案單調(k 越大越可行,一旦 T 就永遠 T)。三者齊備,候選帶就是 F…FT…T,通用模板直接套用,找第一個 T。口訣:求解難、驗證易、且單調。
A2. 因為對每一堆而言,⌈p/k⌉ 隨 k 變大而不會變大(除數變大,商不增),總和自然也不增。所以 getTime 單調不增,check 一旦為真就永遠為真。但它不是嚴格遞減 —— 動畫那組就有現成的反例:k=4 和 k=5 都是 8 小時(因為 ⌈7/4⌉ = ⌈7/5⌉ = 2、⌈11/4⌉ = ⌈11/5⌉ = 3)。函數是階梯狀的。好消息是二分只需要單調,不需要嚴格 —— 平台期不影響「第一個 T」的唯一性。
A3. 左界 1:速度 0 代表不吃,不但永遠不可行,還會讓 p / k 除以零直接當掉。右界 max(piles):速度再快也不能跨堆吃,超過最大堆之後每堆一樣是一小時,時數不會再降 —— 所以 max 就是「最壞情況下的答案」,是有效上界。取 Σpiles 當右界也正確,只是白白多幾輪(log 級,影響很小);取 max(piles) 更緊。至於 +1,純粹因為區間是右開的:寫 [1, max) 會讓 max 本身永遠取不到,而 h 恰等於堆數時答案正好就是 max(見 CASE h=5)—— 那時就會答錯。
A4. 會把「剛好用滿 h 小時」的合法解排除掉,答案偏大。以 piles=[3,6,7,11], h=8 為例:k=4 需要正好 8 小時,是合法的最小速度。若判斷式寫 < h,k=4 與 k=5(也是 8 小時)都會被判為不可行,left 一路被推到 k=6(6 小時),回傳 6 而非 4。題意是「在 h 小時內吃完」,而「內」包含「剛好」。
A5. 因為 getTime 只會被二分呼叫,而二分是從上往下折半逼近答案 A:一旦 mid 小於 A,判斷立刻失敗、left 就跳上去,所以造訪過的最小 k 不會低於 A/2。又因為 ⌈p/(A/2)⌉ ≤ 2⌈p/A⌉,相加得 getTime(A/2) ≤ 2·getTime(A) ≤ 2h ≤ 2×10⁹ < INT_MAX。實測 20 萬組隨機輸入,「A ÷ 造訪過的最小 k」的上限恰好是 2,與推導吻合;10⁴ 堆 × 10⁹ 根、h=10⁹ 的極端輸入實跑,過程中最大時數為 1,310,620,000,確實沒溢位。但這個保證依賴兩個前提:h ≤ 10⁹ 這條約束,以及 getTime 只被二分以那種順序呼叫。放寬 h 的上限、或單獨呼叫 getTime(piles, 1),立刻爆掉 —— 所以實務上仍該寫 long long。
App 1. check(cap) = 「以載量 cap 貪心裝箱,需要的天數 ≤ D 嗎」:掃過包裹,累加當天重量,超過 cap 就換一天並重設。值域左界是 max(weights) 而非 1 —— 因為包裹不能拆開,載量小於最重的那件就永遠裝不下(check 對更小的值沒有定義上的意義,會無窮多天)。右界是 Σweights(一天全部載走),右開就 +1。這是它與 875 唯一的結構差異:875 的「一堆」可以分很多小時吃完,所以左界是 1;1011 的「一件包裹」不可分割,左界被抬高到 max。
App 2. 因為它同樣符合三條件:答案(各段和的最大值)落在 [max(nums), Σnums]、給定候選值容易驗證、且驗證單調。check(limit) = 「若每段和都不能超過 limit,貪心切下去所需的段數 ≤ k 嗎」:掃過陣列累加,超過 limit 就切一刀。limit 越大需要的段數越少 → 單調。收斂後的 l 就是最小可行的 limit。它和 1011 其實是同一題換皮(包裹→數字、天數→段數、載量→段和上限),連左界要取 max 的理由都一樣:元素不可分割。
App 3. 求最大可行答案時,可行性是反過來的:小的可行、大的不可行,帶子變成 T T T F F F。有兩種寫法。① 保持模板不動,把 pred 改成「!check(mid)」(即「不可行嗎」),帶子就轉回 F…FT…T,收斂後 l = 第一個不可行 → 答案取 l − 1(記得擋 l == 0,代表無解)。② 換一種收縮方向:if (check(mid)) l = mid; else r = mid - 1; 並把 mid 改成上取整 l + (r - l + 1) / 2,收斂後直接回 l —— 上取整是必要的,否則兩格時 mid == l 會原地打轉而無窮迴圈。建議用寫法 ①:骨架不必動,只要記住「最後一個不滿足 → 拿 l − 1」這條老規則。
