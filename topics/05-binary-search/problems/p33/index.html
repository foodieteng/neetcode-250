題目簡介// THE QUESTION

QUESTION

一個元素相異的升冪陣列,被在未知位置左旋過一次(例 [0,1,2,4,5,6,7] 旋轉成 [4,5,6,7,0,1,2])。 給旋轉後的 nums 與 target,回傳索引;不存在回 -1。要求 O(log n)。

這題是本章的轉折點。前面 704 / 35 / 374 都能寫成 通用模板的「找第一個 T」,是因為判斷式單調。 但旋轉之後,那個單調性被打斷了 —— 所以不能直接套 lower_bound。得先找回一段「還能信任」的區域。

2

為什麼 lower_bound 在這裡失效// THE BROKEN STRIP

TF 帶被斷成兩段 · 二分的前提沒了

通用模板要求判斷式沿索引單調(一旦為 T 就不再變回 F)。把 nums[i] ≥ 0 畫在旋轉陣列上:

index   0  1  2  3  4  5  6
nums    4  5  6  7  0  1  2
≥ 5 ?   F  T  T  T  F  F  F　← T 之後又變回 F

不是 F…FT…T,而是 F T T T F F F。模板收斂後的 l 不再有「第一個 ≥ target」的意義,結果會錯。 所以這題要換一個切入點 —— 不去問「這格夠不夠大」,改問「哪半邊還是有序的」。

3

關鍵性質:至少有一半是有序的// THE LEMMA

LEMMA · 一個斷點,兩半,最多只能弄壞一半

旋轉只會製造一個斷點(值突然變小的那一格)。用 mid 把區間切成 [l, mid] 與 [mid, r] 兩半 —— 一個斷點最多只能落在其中一半裡,所以另一半必定是完整遞增的。

怎麼判斷?比較兩端:nums[l] ≤ nums[mid] 成立 ⇒ 左半沒有跨過斷點 ⇒ 左半有序;否則 ⇒ 斷點在左半 ⇒ 右半有序。

有序半能做什麼?在一段遞增區間裡,「target 在不在裡面」只要比兩個端點就能確定:nums[l] ≤ target ≤ nums[mid]。 在裡面 → 往有序半收;不在裡面 → 它只可能在另一半 → 往另一半收。不論哪種,都砍掉一半。

這就是本題的全部:把「無序」轉化成「一半有序 + 一次範圍判斷」。 注意判斷式 nums[l] ≤ nums[mid] 的等號不能省 —— 區間剩兩格時 mid 會等於 l,單格當然算有序。
4

核心策略 · 三步驟// STRATEGY

  1. 定義區間:left = 0、right = n − 1,用 while (left < right) 收斂到單格(不是找第一個 T)。
  2. 每輪兩問:① nums[left] ≤ nums[mid] ? → 哪半有序;② target 在有序那半的範圍內嗎 → 決定往哪收。收縮一律 right = mid 或 left = mid + 1。
  3. 最後驗一次:收斂只保證「唯一候選」,target 可能根本不存在 → return nums[left] == target ? left : -1;

哪半有序target 在有序半?怎麼收理由
左半
nums[l] ≤ nums[m]		 在 [nums[l], nums[m]] 內 right = mid 往有序半收(保留 mid)

右半

// 為什麼右半的範圍是「開左閉右」(m, r] 左半有序時,判斷寫 nums[l] <= target <= nums[m] —— 含 mid,對應 right = mid(保留 mid) 右半有序時,判斷寫 nums[m] < target <= nums[r] —— 不含 mid,對應 left = mid + 1(跨過 mid) // 範圍的開閉,要和「收縮時 mid 留不留」對齊 —— 這是本題最容易寫反的地方

複雜度// COMPLEXITY

T = O(log n)　　S = O(1)

每輪不論走哪個分支都砍掉一半,和普通二分同級。判斷多了一層,但只是常數。n = 5000 約 13 輪。

SpaceO(1)三個 int

一句洞察// INSIGHT

旋轉破壞了整體單調,但一個斷點最多只能弄壞一半。 所以每輪先問「哪半是有序的」,再對那半用兩端比大小判斷 target 在不在 —— 在就往那收、不在就往另一半收,兩種都砍一半。
