重點回顧// RECAP

面向要點
為何不能套模板旋轉後「≥ target」不再單調,TF 帶斷成兩段
關鍵引理一個斷點最多弄壞一半 ⇒ 至少一半有序
判哪半有序nums[l] ≤ nums[m] → 左半;否則右半
那個等號剩兩格時 m == l,單格必須算有序
怎麼收在有序半內 → 往那收;不在 → 往另一半收
開閉對齊左半含 mid 配 r = m;右半不含 mid 配 l = m + 1
收尾收斂到單格,仍要驗 nums[l] == target
複雜度時間 O(log n),空間 O(1)

Q3. 判斷左半有序寫的是 nums[l] <= nums[m]。那個等號什麼時候會被用到?把它改成嚴格 < 會怎樣?

範例 Trace// [4,5,6,7,0,1,2]

// CASE A: target = 0(存在) index 0 1 2 3 4 5 6 nums 4 5 6 7 0 1 2 斷點:index 3 → 4 [0,6] m=3 nums[0]=4 <= nums[3]=7 → 左半有序 [4..7] 0 在 [4,7]? 否 → l = 4 → [4,6] [4,6] m=5 nums[4]=0 <= nums[5]=1 → 左半有序 [0..1] 0 在 [0,1]? 是 → r = 5 → [4,5] [4,5] m=4 nums[4]=0 <= nums[4]=0 → 左半有序 [0..0] ← 靠等號 0 在 [0,0]? 是 → r = 4 → [4,4] 驗證:nums[4] = 0 == target // return 4
// CASE B: target = 3(不存在) [0,6] m=3 左半有序 [4..7],3 在 [4,7]? 否 → l = 4 → [4,6] [4,6] m=5 左半有序 [0..1],3 在 [0,1]? 否 → l = 6 → [6,6] 驗證:nums[6] = 2 != 3 // return -1
// CASE C: 走到「右半有序」的例子 nums=[5,6,7,0,1,2,4], target=6 index 0 1 2 3 4 5 6 nums 5 6 7 0 1 2 4 [0,6] m=3 nums[0]=5 > nums[3]=0 → 斷點在左半 → 右半有序 [0..4] 6 在 (0, 4]? 否 → r = 3 → [0,3] [0,3] m=1 nums[0]=5 <= nums[1]=6 → 左半有序 [5..6] 6 在 [5,6]? 是 → r = 1 → [0,1] [0,1] m=0 nums[0]=5 <= nums[0]=5 → 左半有序 [5..5] 6 在 [5,5]? 否 → l = 1 → [1,1] 驗證:nums[1] = 6 == target // return 1
// CASE D: 兩個邊界 未旋轉 nums=[0,2,4,6] t=4 → 每輪都判「左半有序」,退化成普通二分 → 2 單元素 nums=[1] t=0 → 迴圈一輪都不跑,驗證 nums[0]=1 != 0 → -1 窮舉驗證:長度 1..9 × 所有旋轉 × 所有 target 共 660 組,失敗 0 筆 // 「未旋轉」也是合法輸入 —— 它只是斷點在最前面的特例
CASE C 才會走到 else 那半。注意它第一輪判的是「右半有序 [0,1,2,4]」, 而 6 不在 (0, 4] 內 → 往左收。對有序半做的永遠是「排除法」,不是直接找。

應用題// APPLY

App 1. 153. Find Minimum in Rotated Sorted Array:求旋轉陣列的最小值。它可以用通用模板寫成一行 pred —— 請寫出那個 pred,並說明為什麼「找最小值」是單調的、而「找 target」不是。
App 2. 另一種解法:先用 153 找出斷點位置 k,再決定 target 落在哪一段、對那段做普通二分。請比較它與本題「一次到底」寫法的優缺點。
App 3. 81. Search in Rotated Sorted Array II:如果允許重複值,本題的判斷會在哪裡失靈?最壞複雜度會變成多少?該怎麼補救?
// ANSWERS
A1. 因為模板要求判斷式沿索引單調。把 nums[i] ≥ 5 畫在 [4,5,6,7,0,1,2] 上得到 F T T T F F F —— T 之後又變回 F,不是 F…FT…T。二分的正確性建立在「看到 T 就知道答案在左邊、看到 F 就知道在右邊」,一旦帶子斷成兩段,這個推論就不成立:你在中間看到 F,無法判斷該往左還往右。所以必須換一個仍然可靠的判斷 —— 也就是「哪半有序」。
A2. 因為旋轉一個原本嚴格遞增的陣列,只會製造一個「值突然變小」的斷點(7 → 0 那裡)。用 mid 把區間切成 [l, mid] 和 [mid, r] 兩段,這唯一的斷點最多只能落在其中一段裡(它是一個位置,不能同時在兩段的內部)。沒有斷點的那一段,自然就保持原本的遞增 —— 所以至少一半有序。這也解釋了為什麼「未旋轉」的輸入沒問題:那只是斷點在最前面(等於沒有),兩半都有序,判斷會走左半那支,程式退化成普通二分。
A3. 等號會在區間只剩兩格時被用到:mid = l + (r − l)/2 向下取整,兩格時 mid == l,於是 nums[l] == nums[mid]。此時「左半」只有一格,單格當然是有序的,必須判為 true。改成嚴格 < 就會把它誤判成「右半有序」,拿錯誤的區間去做範圍判斷而收錯邊。實測窮舉(長度 1..9 × 所有旋轉 × 所有 target)嚴格版失敗 19 筆,最小反例 nums=[2,0]、target=0:正解是 1,嚴格版回傳 -1。
A4. 因為範圍的開閉必須和收縮動作對齊。左半判斷成立時走 right = mid —— mid 留在候選區間裡,所以範圍要含 mid(t ≤ nums[m]);右半判斷成立時走 left = mid + 1 —— mid 被跨過了,所以範圍必須不含 mid(nums[m] < t),否則當 target == nums[mid] 時,程式會判定「在右半」而執行 left = mid + 1,把正確答案那一格直接跳掉。實測 <= 版失敗 27 筆,最小反例 nums=[4,0,2]、target=0:正解 1,錯誤版回 -1。口訣:收完 mid 還在 → 用 ≤;收完 mid 不在 → 用 <。
A5. 因為迴圈做的是「排除」而不是「確認」。每輪只保證「答案如果存在,一定不在被丟掉的那半」,它從來沒有檢查過任何一格是否等於 target。所以收斂到單格的意思是「唯一還沒被排除的候選」,而不是「找到了」。當 target 根本不在陣列裡(例如 CASE B 的 3),迴圈照樣會收斂到某一格,只是那格的值不對。這和 704 是同一個道理(收斂只給位置,命中要另驗);差別在 374 因為題目保證答案存在,才可以省掉這道驗證。
App 1. pred 寫 nums[m] <= nums[n−1](和最後一個元素比),收斂後的 l 就是最小值的位置。它單調的理由:以最後一個元素 nums[n−1] 當基準,斷點之前的元素全都比它大(F)、斷點之後全都 ≤ 它(T),剛好是乾淨的 F…FT…T —— 最小值就是第一個 T。反觀「找 target」,target 是任意值,它可能同時小於左段又大於右段的某些元素,產生 F T T F F 這種斷掉的帶子,所以不單調。關鍵差別:153 的基準點固定在陣列端點、和旋轉結構綁在一起;33 的基準是外來的 target。(這條 pred 已窮舉 36 種旋轉驗證,零失敗。)
App 2. 兩段式:先用 App1 的方法 O(log n) 找出斷點 k(最小值位置),陣列就被切成兩段各自遞增的區間 [0, k) 與 [k, n);比較 target 與端點決定它落在哪段,再對那段做普通 lower_bound。優點:每一步都是你已經熟的模板,四個分支的開閉問題完全不用想,除錯容易,而且找到 k 之後可以重複回答多次查詢。缺點:要跑兩次二分(常數約兩倍),而且多了「判斷落在哪段」的邊界討論。兩者都是 O(log n);面試時如果緊張,兩段式其實更不容易寫錯。
App 3. 失靈的點是判有序那一行:當 nums[l] == nums[m] 時,你無法判斷左半到底是「全等的一段(真有序)」還是「跨過斷點」。實測窮舉出的最小反例是 nums = [0,1,0,0,0]、target = 1(正解 1,原版回 -1):第一輪 l=0, m=2,nums[0] == nums[2] == 0 被判成「左半有序、範圍 [0,0]」,於是 1 被判定「不在左半」而執行 l = m + 1 —— 但左半 [0,1,0] 根本不是有序的,答案就藏在裡面,一步被丟掉。補救方式是加一個 else if (nums[l] == nums[m]) l++; —— 無法判斷時就保守地縮掉一格(因為 nums[l] 與 nums[m] 相等,丟掉 l 不會丟掉答案的存在性)。代價是最壞情況(整條幾乎全相等,如 [1,1,1,1,1])每輪只縮一格 → 退化成 O(n)。這正是 81 題,也是為什麼本題特地保證「元素相異」。
