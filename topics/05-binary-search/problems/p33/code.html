完整實作 · 收斂到單格// find the sorted half

p33.cpp C++17 
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;   // 閉區間 [left, right],收斂到單格

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[left] <= nums[mid]) {          // ① 左半 [left, mid] 有序(等號:mid 可能 == left)
                if (nums[left] <= target && target <= nums[mid]) {
                    right = mid;                // 在有序半內 → 收過去(含 mid)
                } else {
                    left = mid + 1;            // 不在 → 只可能在另一半
                }
            } else {                            // ② 否則右半 [mid, right] 有序
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;            // 在有序半內 → 收過去(不含 mid)
                } else {
                    right = mid;                // 不在 → 只可能在另一半
                }
            }
        }

        return nums[left] == target ? left : -1;  // 唯一候選,仍要驗一次
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

四個分支,但只有兩個動作:right = mid(保留 mid)或 left = mid + 1(跨過 mid)。 決定用哪個,就看「target 落在的那一側,含不含 mid」—— 範圍判斷的開閉,必須跟收縮動作對齊。

三個符號為什麼是那樣// THE SIGNS

位置寫法為什麼
判有序 nums[left] <= nums[mid] 區間剩兩格時 mid 向下取整會等於 left,此時 nums[left] == nums[mid],單格必須算「有序」;寫成嚴格 < 會誤判成右半有序而收錯邊
左半範圍 nums[left] <= t <= nums[mid] 右端含 mid,因為對應的動作是 right = mid(mid 留在候選裡)
右半範圍 nums[mid] < t <= nums[right] 左端不含 mid,因為對應的動作是 left = mid + 1(mid 被跨過);若寫 ≤,當 target == nums[mid] 時會把答案跳掉
// 一句話對齊法 問自己:「這個分支收完之後,mid 還在候選裡嗎?」 還在 (right = mid) → 範圍判斷就要「含 mid」→ 用 <= 不在 (left = mid + 1) → 範圍判斷就要「不含 mid」→ 用 < // 開閉與收縮動作一致,四個分支就不會寫反
3

複雜度分析// COMPLEXITY

步驟成本說明
判斷哪半有序O(1)一次比較
範圍判斷O(1)最多兩次比較
每輪區間砍一半四個分支皆然
總輪數⌈log₂n⌉n=5000 → 13 輪
T = O(log n)　　S = O(1)

多出來的那層判斷只是常數;真正會讓它退化成 O(n) 的是重複元素(見 81 題,本題保證相異)。

邊界與陷阱// PITFALLS

陷阱後果正解
判有序寫成 nums[left] < nums[mid] 兩格時 mid==left 被誤判成右半有序 → 收錯邊。實測窮舉 19 筆失敗,最小反例 nums=[2,0], t=0 → 回 -1(正解 1) 必須用 <=
右半範圍寫成 nums[mid] <= target target == nums[mid] 時走 left = mid + 1,直接跳過答案。實測窮舉 27 筆失敗,最小反例 nums=[4,0,2], t=0 → 回 -1(正解 1) 右半用嚴格 <
忘了最後的命中驗證 target 不存在時回傳一個無關索引 nums[left] == target ? left : -1
用 left <= right 配 right = mid 剩一格時原地打轉 → 無窮迴圈 配 left < right(收斂到單格)
直接套 lower_bound 模板 旋轉後判斷式不單調,答案錯 先判有序半(見 概念頁)
nums.size() - 1 的型別 本題 n ≥ 1,不會出事 但 size() 是無號數,空陣列會環繞成巨大值 —— 習慣先取 int n = nums.size();
