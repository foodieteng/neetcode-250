PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
題目要求「切成 恰好 k 段」,程式卻寫 check(mid) <= k。這不是放寬了條件嗎?為什麼答案還是對的?請證明,並說明改成 == k 會壞在哪裡。
解答與說明 · ANSWER▾
放寬了,但不影響答案。設 check(v) = c ≤ k,即上限 v 之下最少切 c 段。因為 k ≤ n(題目保證)且每段非空,我們可以在任一段內再補 k − c 刀,湊到恰好 k 段 —— 而多切刀只會讓每段變短,各段和只會更小,所以最大段和不會超過 v。因此「存在 ≤ k 段的合法切法」與「存在恰好 k 段的合法切法」等價。

改成 == k 會壞兩件事:①漏解 —— 最優的 v 底下貪心可能只切出 c < k 段,判斷式回 false,答案被推大;②破壞單調性 —— check(v) == k 這個述詞隨 v 增大是 F…F T…T F…F(v 大到一定程度段數會掉到 k 以下),不是 F…F T…T,二分的前提直接消失。實測最小反例 nums=[8,2,1], k=3 → 答 11(正解 8);對拍 56000 組錯 22533 組。
第 2 題10 分
為什麼左界是 max(nums) 而不是 0?請說明取 0 時 countSegments 會算出什麼樣的「假段數」,並給一個具體反例。
解答與說明 · ANSWER▾
因為 countSegments 只在 cur + x > limit 時切刀,切完之後無條件執行 cur += x —— 它沒有檢查「x 自己塞不塞得下」。當 limit < max(nums) 時,那個超大元素會被硬塞進一個新段裡,函數回報的段數是一個不對應任何合法切法的假數字。

具體反例:nums=[6,7], k=2,正解 7。若 left = 0,二分會試到 v=6:cur=6,接著 6+7=13 > 6 → 切刀、cur=7。回報 2 段 ≤ 2,判定「可行」—— 但那一段的和是 7 > 6,根本不合法。於是答案被壓成 6。對拍 56000 組錯 15708 組。

把左界設成 max(nums) 之後,limit ≥ 每個 x 恆成立,「切刀後 cur = x ≤ limit」永遠為真,假段數就不可能出現。左界不只是效率優化,它是 check 正確性的前提。
第 3 題10 分
countSegments 用的是貪心。為什麼貪心給出的段數一定是最少的?請寫出交換論證。
解答與說明 · ANSWER▾
交換論證。因為順序固定,任一種切法就是把序列切成連續幾段。設有一個最少段數的切法 OPT,和貪心切法 G。取第一個兩者不同的切點:貪心在該處「還塞得下就繼續塞」,所以貪心的第一段結束位置不早於 OPT 的第一段。

現在把 OPT 的第一刀往後推到貪心的位置:第一段仍不超過 v(因為貪心驗證過它塞得下),而第二段的起點往後移,裝的東西只會更少或一樣,所以第二段仍不超過 v。以此類推,後續每一段都只會變輕,段數不會變多。反覆對每個切點做這個調整,OPT 就變成了 G 而段數沒增加 ⇒ |G| ≤ |OPT|。又因 OPT 最少,故 |G| = |OPT|。所以貪心算出的就是該上限下的最少段數,check 是正確的。

實測佐證:對所有非負的短陣列(n ≤ 6)與其值域內的每一個 v,把貪心段數和「最少段數」的 DP 逐一比對,1072680 組全部相同。(這條性質依賴非負 —— 見下方 第 9 題 的反例 [4,4,-4]。)
第 4 題10 分
二分的前提是單調性。check(v) 對 v 是嚴格遞減嗎?如果不是,為什麼二分仍然成立?用 nums=[7,2,5,10,8] 舉例。
解答與說明 · ANSWER▾
不是嚴格遞減,是「單調不增」——有平台。以 nums=[7,2,5,10,8] 實測:v=10..13 → 4 段、v=14..17 → 3 段、v≥18 → 2 段。v 從 14 加到 17 段數完全不動,因為多出來的容量擠不進下一個元素(要再多裝一個必須跨過 10 這個門檻)。

二分仍然成立,因為二分要的不是 check 本身嚴格遞減,而是述詞 P(v) = [check(v) ≤ k] 單調:v 增大時 check 不增 ⇒ P 一旦為真就永遠為真 ⇒ 序列是 F…F T…T。平台只是讓某些相鄰的 v 有相同真值,不會讓 T 之後又出現 F。這也正是 == k 不能用的理由 —— 它在平台上會由 T 翻回 F。
第 5 題10 分
收斂後直接 return left,不再驗證一次。憑什麼確定它可行?請指出程式碼中維持的不變量。
解答與說明 · ANSWER▾
不變量:right 全程指向一個已知可行的上限。①初始:right = Σnums,此時 check = 1 ≤ k(k ≥ 1),可行。②維持:right 只在 check(mid) ≤ k 成立的分支被賦值成 mid —— 也就是只會被換成另一個剛驗證過可行的值。left = mid + 1 那條路完全不動 right。

迴圈結束時 left == right,而 right 可行 ⇒ left 可行。同時 left 這一側的不變量是「left - 1 及以下全部不可行」,所以 left 是第一個可行值,即最小值。兩個不變量合起來就是答案,不需要收斂後再 check 一次。對照:81 因為沒有這種「right 恆可行」的結構,收尾就必須寫 return nums[left] == target; 再驗一次。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
題目把限制放寬成 n ≤ 10⁵、nums[i] ≤ 10⁷。現在這份程式碼還對嗎?請算出實際的 Σ 上限並說明要改哪幾行。
解答與說明 · ANSWER▾
會溢位,必須改型別。Σ ≤ 10⁵ × 10⁷ = 10¹²,而 INT_MAX = 2147483647 ≈ 2.1×10⁹ —— 超出約 465 倍。原本的限制下 Σ ≤ 1000 × 10⁶ = 10⁹ 剛好安全(餘裕 1147483647,實測過),放寬一級就爆。

要改的地方:① accumulate(nums.begin(), nums.end(), 0) → accumulate(nums.begin(), nums.end(), 0LL)(初始值的型別決定累加器的型別,這是最常漏的一行);② left / right / mid 與 countSegments 的 cur、參數 limit 全部改成 long long;③ 回傳型別視題目而定。

複雜度不變:O(n log Σ),只是 log Σ 從 30 變成 40,n 從 10³ 變成 10⁵ → 約 4×10⁶ 次運算,仍然輕鬆。注意 mid = left + (right - left) / 2 這個寫法本來就避開了 left + right 的溢位,不需要再改。
第 8 題13 分
除了回傳最小的最大段和,還要回傳一組達成它的切點。怎麼改?會增加複雜度嗎?
解答與說明 · ANSWER▾
改一行、複雜度不變。答案 v = left 求出後,再跑一次 countSegments(nums, left),這次把切刀的位置記下來即可:切刀發生在 cur + x > limit 那個 x 的索引處。以 [7,2,5,10,8], v=18 為例,唯一一刀落在索引 3(元素 10)之前 → 切法 [7,2,5] | [10,8]。

若貪心只切出 c < k 段而題目要求恰好 k 段,就任意再補 k − c 刀(例如把最長的段對半再切,或直接在最後幾個元素之間逐一補刀)—— 由 第 1 題,補刀不會讓最大段和變大,所以仍然達成 v。

成本:多一次 O(n) 掃描 + O(k) 儲存切點 ⇒ 總複雜度仍是 O(n log Σ),空間從 O(1) 升到 O(k)。這是答案二分的常見收尾:先二分出「值」,再用同一個 check 重建「解」。
第 9 題14 分
如果 nums 可以含負數,這套解法還能用嗎?請指出哪一個前提先崩掉。
解答與說明 · ANSWER▾
不能用。三個前提依序崩掉,最先垮的是「值域」。

① 值域倒掛(最致命):答案不再夾在 [max(nums), Σnums] 之間 —— 有負數時 Σnums 可以小於 max(nums)。此時 left > right,while (left < right) 一次都不進,直接回傳 left = max(nums),而那通常不是答案。實測最小反例 nums=[-4,6], k=1:left=6, right=2 → 回傳 6,正解是整條一段的和 2。隨機生成含負數的短陣列,70494/100000 組滿足 Σ < max。

② 貪心不再最少:交換論證的關鍵是「把切點往後推,後面每段只會更輕」。有負數時往後推可能把一個負數留給後面,方向不再確定,論證斷掉。實測最小反例 nums=[4,4,-4], v=4(注意 v = max,值域是合法的):貪心切成 [4] [4,-4] 共 2 段,但整條和是 4 ≤ 4,1 段就夠。在 v ≥ max 的 520 萬組實測中,貪心有 89587 組不是最少段數。

③ 單調性也會破(但很少):check 對 v 大多仍不增,實測 12 萬個含負數陣列中只有 5 個在 v ≥ max 區間出現「v 變大段數反而變多」。這是 ② 的副作用 —— 貪心本身不最優,它算出的數字不保證有單調性。

正確做法:退回區間 DP —— dp[j][i] = min over t of max(dp[j-1][t], pre[i] - pre[t]),O(k·n²),不依賴任何單調性或貪心,負數照樣正確(本題的對拍參考解就是它)。但 dp[0][0] 要設成 −∞ 而不是 0 —— max 的單位元是 −∞,寫成 0 會把所有負的段和「墊高」到 0,答案全錯。這個坑我在寫本頁的對拍時實際踩過:第一版參考解對 [-3,-4], k=2 答 0(正解 −3),差點把正確的主解誤判成有 bug。
