題目簡介// THE QUESTION

QUESTION

把 nums 切成 k 個非空的連續子陣列,使得各段總和中最大的那一個盡可能小。 回傳這個最小化後的最大段和。

這題掛 HARD,但如果你已經寫過 1011 送包裹, 它其實是同一題換了說法:「切成 k 段、最小化最大段和」和「k 天內送完、最小化載量」是字面上等價的 —— 一段 = 一天,段和 = 當天總重,最大段和 = 載量。

HARD 的標籤是給直覺解法(區間 DP)的:那條路要 O(k·n²) 又難寫。 答案二分把它壓成 十幾行,難度真正的落差在「想不想得到要二分答案」,而不在實作。
2

為什麼是答案二分// WHY THIS

關鍵的視角轉換:不要去問「該怎麼切」,去問「這個上限行不行」。 前者是最佳化問題(難),後者是是非題(容易到只要一次貪心掃描)。

A 枚舉所有切法 C(n−1, k−1)
在 n−1 個縫隙裡挑 k−1 刀。n=1000, k=50 時是天文數字,連寫出來都沒意義。
× REJECT · 指數
B 區間 DP 直接求切法 O(k · n²)
dp[j][i] = 前 i 個元素切成 j 段的最小最大和,轉移枚舉上一刀的位置。 答案是對的(本頁的對拍就是用它當參考解),但 50 × 1000² = 5×10⁷ 已經吃緊, 而且要處理前綴和、初始 INF、j−1 ≤ t < i 的邊界,寫錯機率高。
△ REJECT · 又慢又難寫
BOTH FAIL · ADOPT
C 二分「最大段和」+ 貪心驗證 O(n log Σ)
「最小的最大段和是多少」很難直接算,但給定一個上限 v,算「最少要切幾段」很容易: 照順序累加,超過 v 就切一刀,O(n)。 而上限越大段數越少 ⇒ check 單調 ⇒ 候選帶是 F F F T T T ⇒ 套模板找第一個 T。
● ADOPT · O(n log Σ)
3

核心策略 · 三步驟// STRATEGY

  1. 定值域:left = max(nums)(最大的元素自己單獨一段也要這麼多)、right = Σnums(不切,整條就是一段)。
  2. 寫 check:check(v) —— 照原順序累加,cur + x > v 就切一刀開新段,回傳段數。判斷式 check(mid) ≤ k。
  3. 套模板:段數夠少 → right = mid(保留);段數太多 → left = mid + 1(跨過)。收斂後 return left。
注意判斷式是 ≤ k 而不是 == k。切得比 k 段少也算可行 —— 因為 k ≤ n,任何少於 k 段的切法都能再多切幾刀湊到剛好 k 段,而多切刀只會讓各段更小, 最大段和不會變大。實測把 ≤ 改成 ==,[8,2,1] k=3 就答 11(正解 8)。

兩個必須成立的前提// TWO LEMMAS

LEMMA 1 · 「能塞就塞」得到的段數一定是最少的

順序固定,所以每一種切法就是把序列切成連續幾段。貪心的做法是:當前段塞得下就塞,塞不下才切刀。

交換論證:假設有一種更省的切法,它在某處「明明還塞得下卻提早切刀」。把那個元素挪回前一段, 前一段仍不超過 v(因為本來就塞得下),而後面每一段的起點都只會往後移或不變 —— 於是後續每段裝的東西只會更少或一樣,總段數不會變多。 反覆做這個調整,任何切法都能變成貪心的切法而不變差。

所以貪心給出的段數就是上限 v 之下的最少段數,用它判斷「這個 v 行不行」是正確的,而且只要 O(n)。

LEMMA 2 · check 對 v 單調不增

若 v₁ < v₂,則 check(v₁) ≥ check(v₂):上限放寬之後,原本 v₁ 的那組切法依然合法 (每段和都 ≤ v₁ < v₂),所以 v₂ 的最少段數不會比它多。

於是「check(v) ≤ k」這個述詞沿 v 遞增方向一旦為真就永遠為真 ⇒ F F F T T T ⇒ 可以用「找第一個 T」的模板。 實測 [7,2,5,10,8] 的段數序列:v=10..13 → 4 段、v=14..17 → 3 段、v≥18 → 2 段 —— 遞減但有平台。

一句洞察// INSIGHT

看到「最小化最大值」或「最大化最小值」這種極值的極值句型, 幾乎都是答案二分的訊號:把最佳化問題翻成「給定一個門檻,做得到嗎」的是非題, 困難的部分被二分吸收,check 只需要簡單且可證明正確。
