題目簡介// THE QUESTION

QUESTION

設計一個帶時間戳的鍵值結構:set(key, value, timestamp) 存入; get(key, timestamp) 回傳時間戳 ≤ 查詢值中最大的那一筆的 value,沒有就回 ""。 關鍵約束:set 的 timestamp 嚴格遞增,最多 2×10⁵ 次呼叫。

這題是本章 l − 1 家族的第三個實戰(74 用它選列,這裡用它找前驅)。 模板頁那條規則直接套上來:要「最後一個滿足 ≤ target 的」,就先找「第一個 > target 的」,再退一格 —— 也就是 upper_bound − 1。

「set 的 timestamp 嚴格遞增」這句話是整題的地基。它保證每個 key 的 vector 天生就是排序好的 —— push_back 就夠,不必排序、不必插入到中間。少了這句,set 就得付 O(n) 或改用 map。
2

為什麼 vector + 二分// WHY THIS

A 每次 get 從尾巴往前掃 O(n) / 次
最多 2×10⁵ 次呼叫,若全集中在同一個 key,總成本可到 10¹⁰ 級,超時。而且完全沒用上「已排序」。
× REJECT · TLE
B 改用 map<int, string> 存每個 key O(log n) / 次
複雜度同級,upper_bound 現成可用。但紅黑樹每個節點一次配置、快取不友善,常數明顯較大 —— 而本題根本不需要「中間插入」的能力(timestamp 遞增),那份彈性是白付的。
△ REJECT · 白付常數
BOTH FAIL · ADOPT
C unordered_map<string, vector<pair<int,string>>> + 手寫 upper_bound set O(1) · get O(log n)
key 用雜湊 O(1) 定位,value 用連續記憶體的 vector。因為 timestamp 遞增,set 只是 push_back(攤還 O(1)); get 對那條 vector 二分找第一個 > timestamp,再退一格。
● ADOPT · 最省常數
3

核心策略 · 三步驟// STRATEGY

  1. 存:dict[key].push_back({timestamp, value}) —— timestamp 遞增,所以 vector 自然有序。
  2. 找第一個 > timestamp:左閉右開 [0, n),pred 是 v[mid].first > timestamp(嚴格 >),收斂後 l = upper_bound。
  3. 退一格:答案是 v[l − 1]。若 l == 0 代表「所有時間戳都比查詢值大」→ 回 ""。

嚴格 > 配 l − 1 · 兩者必須成套// THE PAIRING

RULE · 第一個滿足拿 l,最後一個不滿足拿 l − 1

題目要的是「最後一個 timestamp ≤ 查詢值」。這是模板頁的 l − 1 家族 —— 把條件寫成它的反面「timestamp > 查詢值」,TF 帶就是 F…F T…T, l 停在第一個 T,而l − 1 就是最後一個 F,正是要的答案。

為什麼 pred 必須用嚴格 >:如果寫 ≥,那 l 會變成 lower_bound(第一個 ≥ 查詢值)。 當查詢值剛好等於某個 timestamp 時,那一筆會被算進 T 側,l − 1 就退到它前面那筆 —— 精確命中反而拿到舊值。

為什麼 l == 0 必須擋:l − 1 家族永遠附帶這個坑。當查詢值比所有 timestamp 都小,整條帶子全是 T, l = 0 → l − 1 = −1,直接讀 v[-1] 就是越界。這也正是題目要求「沒有就回 ""」的那個情形。

n 是該 key 的筆數,不是總筆數。2×10⁵ 次呼叫全塞同一個 key 也只是 2×10⁵ × 18 ≈ 3.6×10⁶。

一句洞察// INSIGHT

「找最後一個 ≤ x」不要自己想收縮條件 —— 把它翻成「找第一個 > x」,套模板,再退一格。 配套只有兩件事:pred 用嚴格 >(否則精確命中會拿到舊值),以及擋 l == 0(否則讀到 v[-1])。
