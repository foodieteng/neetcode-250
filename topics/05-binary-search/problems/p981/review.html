範例 Trace// foo: (1,bar) (4,bar2) (7,bar3)

// 三種查詢,對應 TF 帶的三種形狀 index [0] [1] [2] ts / val 1/bar 4/bar2 7/bar3
// CASE A: query = 5(落在中間) > 5 ? 的 TF 帶 = F F T [0,3) m=1 v[1].first=4 > 5 ? 否 → l=2 [2,3) m=2 v[2].first=7 > 5 ? 是 → r=2 收斂 l=2,l > 0 成立 → 取 v[1] // return "bar2"
// CASE B: query = 0(比全部都小 → 守門生效) > 0 ? 的 TF 帶 = T T T [0,3) m=1 v[1].first=4 > 0 ? 是 → r=1 [0,1) m=0 v[0].first=1 > 0 ? 是 → r=0 收斂 l=0,l > 0 不成立 → 連一個 F 都沒有 // return ""(少了守門就會讀 v[-1])
// CASE C: query = 7(精確命中最後一筆) > 7 ? 的 TF 帶 = F F F [0,3) m=1 v[1].first=4 > 7 ? 否 → l=2 [2,3) m=2 v[2].first=7 > 7 ? 否 → l=3 收斂 l=3 = n,l − 1 = 2 仍是合法索引 // return "bar3" —— 右邊界不必特判
// 正確性驗證規模 官方範例 4/4 相符:get(foo,1)="bar" get(foo,3)="bar" get(foo,4)="bar2" get(foo,5)="bar2" 隨機對拍(參考解為 map<string, map<int,string>> + upper_bound + prev,不共用二分程式碼): 35322 條操作序列,比對 300004 個操作(其中 164433 個 get)→ 不一致 0 邊界 15 項全數符合:未 set 的 key、低於最小、精確命中、介於兩筆之間、 高於最大、單筆的上/中/下、兩個 key 互不干擾 // 30 萬個操作零不一致
三個 case 剛好對應 TF 帶的三種形狀:中間有分界(F F T)、全 T(l=0,守門擋下)、全 F(l=n,不必擋)。 能默寫這三條,l − 1 家族的邊界就完整了。

應用題// APPLY

App 1. 直接用 STL 取代手寫二分。請寫出 get 的 upper_bound 版本(pair 的比較要怎麼處理?),並說明它和手寫版的對應關係。
App 2. 若改用 map<int,string> 存每個 key 的資料,程式會怎麼寫?複雜度一樣是 O(log n),那為什麼本題仍偏好 vector?反過來,什麼情況下 map 才是對的選擇?
App 3. 若題目改成 get 要回傳「timestamp ≥ query 中最小的那一筆」(找後繼而非前驅),程式要改哪裡?守門要擋哪一邊?
// ANSWERS
A1. 它保證每個 key 的 vector 天生就是排序好的,所以 set 只需要 push_back(攤還 O(1)),而 get 可以直接二分。省掉的是「維持有序」的成本。

拿掉這個保證後:set 要嘛每次 upper_bound 找位置再 insert(vector 中間插入是 O(n) 搬移),要嘛改用 map<int,string> 讓它自己維持有序(O(log n) 插入,但每筆一次節點配置)。get 的邏輯不變 —— 它只要求「有序」,不在乎有序是怎麼來的。這是設計題常見的暗示:約束裡的一句話,往往就是叫你別用更重的結構。
A2. 因為通用模板只會找「第一個滿足 pred 的位置」。而「最後一個 ≤ query」不是「第一個」形狀,沒辦法直接寫成 pred。解法是翻成反面:條件寫 ts > query,TF 帶就成了 F…F T…T —— 所有 ≤ query 的落在 F 側、所有 > query 的落在 T 側。模板收斂到第一個 T(l),而我要的「最後一個 ≤ query」正是最後一個 F = l − 1。模板頁的規則原話:第一個滿足拿 l,最後一個不滿足拿 l−1。
A3. 出錯的形狀是「query 剛好等於某一筆的 timestamp」—— 也就是精確命中。用 ≥ 時,那一筆自己就滿足 pred、被算進 T 側,於是 l 指向它,l − 1 就退到它前面那筆 → 回傳上一個時間點的舊值。非精確命中的查詢則完全不受影響(沒有元素等於 query 時,「≥」與「>」的第一個位置是同一格)。

實測窮舉 217 組(長度 1..6 的遞增子集 × query 0..6),≥ 版失敗 80 組,而 80 恰好等於「query 精確命中某個 timestamp」的組數(5 × 16)—— 失敗集合與理論預測完全吻合。最小反例只要一筆:v=[(1,"v1")]、query=1 → 回 ""(正解 "v1")。
A4. 觸發條件是「query 比所有 timestamp 都小」,此時整條帶子全是 T,l 收斂到 0。少了守門,v[l - 1] 就是 v[-1] —— 不只是答案錯,而是陣列越界的未定義行為。實測 217 組中有 57 組會走到這條路徑;用 -fsanitize=address 編譯,最小輸入 v=[(1,"v1")]、query=0 立刻報 heap-buffer-overflow / READ,位址是「32-byte region 之前 1 byte」。

右邊界為什麼不用擋:l 收斂到 n 代表「所有 timestamp 都 ≤ query」,那 l − 1 = n − 1 是最後一筆的合法索引,而且正是該回的答案(query 比全部都大 → 回最新一筆)。l − 1 家族只怕左邊界 −1,不怕右邊界 —— 和 74 同一條規則。
A5. 答案仍然正確 —— 複製出來的 vector 內容一模一樣,二分結果不變。代價是效能:auto 推導時會剝掉 reference 與 top-level const,得到一個乾淨的值型別,所以 auto v = it->second; 會把整條 vector 連同裡面每個 string 深拷貝一份,而 get 其實只讀其中一格。

成本和「vector 多長」成正比,和「呼叫幾次」只是線性倍數關係 —— 換句話說,每一次 get 都付一次 O(n),把原本 O(log n) 的查詢直接打回 O(n)。程式碼頁有實測的毫秒數與 copy constructor 呼叫次數。口訣:auto 給你「一份新的」,const auto& 給你「原來那個」。
App 1. 因為 vector 裝的是 pair<int,string>,要和一個純 int 比較,得指定比較方式。最乾淨的兩種寫法:
① 造一個哨兵 pair 並利用 pair 的字典序:upper_bound(v.begin(), v.end(), make_pair(timestamp, string(1, char(127)))) —— 醜且脆弱,不建議。
② 用異質比較的 comparator(C++14 起 upper_bound 允許 value 與 element 不同型):
auto it2 = upper_bound(v.begin(), v.end(), timestamp,
  [](int t, const pair<int,string>& e){ return t < e.first; });
注意 upper_bound 的 comparator 參數順序是 (value, element)(lower_bound 才是 (element, value))—— 這是最常寫反的地方。

對應關係:it2 - v.begin() 就是手寫版的 l,而 it2 == v.begin() 就是 l == 0 那道守門,答案取 prev(it2)->second。手寫版的好處正是不必記 comparator 的參數順序。
App 2. 用 map<string, map<int,string>> 的話:set 是 dict[key][timestamp] = value;,get 是 auto it = m.upper_bound(timestamp); if (it == m.begin()) return ""; return prev(it)->second; —— 更短,而且 upper_bound 與 prev 把「找第一個 > 再退一格」直接寫在臉上。

本題仍偏好 vector 的理由是常數:紅黑樹每個節點一次動態配置、節點散落各處、走訪要跳指標,而 vector 是連續記憶體,二分時的快取行為好得多;而 map 提供的「任意位置插入仍維持有序」這項能力,本題因為 timestamp 遞增而完全用不到 —— 那是白付的。

什麼時候該用 map:timestamp 不保證遞增(需要中間插入)、需要刪除、或需要對 key 做有序走訪時。原則:別為用不到的能力付常數。
App 3. 找後繼就不需要退格了 —— 這是 l 家族而非 l − 1 家族。把 pred 從 v[m].first > query 改成 v[m].first >= query(即 lower_bound),收斂後的 l 直接就是「第一個 ts ≥ query」的位置,答案是 v[l].second。

守門要換一邊:改成 if (l == v.size()) return ""; —— 代表所有 timestamp 都比 query 小、沒有後繼。兩種家族的邊界是鏡像的:取 l 就怕 l == n,取 l − 1 就怕 l == 0。(這也正是 704 與本題的差別:704 取 l 所以擋右邊,這裡取 l−1 所以擋左邊。)
