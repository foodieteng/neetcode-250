題目簡介// THE QUESTION

QUESTION

輸送帶上有一排包裹,第 i 件重 weights[i]。每天依照輸送帶上的原順序裝船,裝載總重不得超過船的載量。 求能在 days 天內全部送完的最小載量。

這題是 875 科科吃香蕉 的雙胞胎 —— 同一副答案二分骨架,只有兩處不同: ① 左界從 1 抬到 max(weights)(包裹不可分割),② check 從「逐堆取整」換成「貪心裝箱」。 把這兩題並排記,答案二分的模式就穩了。

最容易被忽略的一句話是「依照原順序」。這代表不能排序、不能重排 —— 所以它不是背包問題,而是「把一個序列切成連續幾段」的問題。這也讓 check 可以用貪心。
2

為什麼又是答案二分// WHY THIS

A 從 max 一路試上去 O(n · Σw)
總重可達 5×10⁴ × 500 = 2.5×10⁷,每次驗證又要 O(n) → 10¹² 級,超時。
× REJECT · TLE
B DP 求「切 D 段的最小最大段和」 O(n²·D)
直接對「怎麼切」做 DP 也能得到正解,但狀態轉移要枚舉切點,n = 5×10⁴ 完全跑不動。方向錯了:不該去求切法,該去驗證載量。
△ REJECT · 太慢
BOTH FAIL · ADOPT
C 二分載量 + 貪心驗證 O(n log Σw)
「最小載量是多少」很難直接算,但給定一個載量,算它需要幾天很容易:照順序累加,裝不下就換一天,O(n)。 而載量越大天數越少 ⇒ check 單調 ⇒ 候選帶是 F F F T T T ⇒ 套模板找第一個 T。
● ADOPT · O(n log Σw)
3

核心策略 · 三步驟// STRATEGY

  1. 定值域:left = max(weights)(最重那件一定要裝得下)、right = Σweights(一天全部載走,必定可行)。
  2. 寫 check:getDay(cap) —— 照原順序累加,curW + w > cap 就開新的一天。判斷式 getDay(mid) ≤ days。
  3. 套模板:天數夠 → right = mid;不夠 → left = mid + 1。收斂後 return left,答案保證存在。

check 為什麼可以用貪心// THE EXCHANGE ARGUMENT

LEMMA · 「能裝就裝」得到的天數一定是最少的

因為順序固定,每一種送法就是把序列切成連續幾段。貪心的做法是:當天能塞就塞,塞不下才換天。

交換論證:假設有一種更好的切法,它在某處「明明還裝得下卻提早換天」。把那件包裹挪回前一天,前一天仍不超重(因為本來就裝得下),後面每一段的起點都只會往後移或不變 —— 於是後續每一天裝的東西只會更少或一樣,總天數不會變多。反覆做這個調整,任何切法都能變成貪心的切法而不變差。

所以貪心給出的天數就是該載量下的最少天數,用它來判斷「這個載量行不行」是正確的。這一步是 O(n),不需要 DP。

答案二分的威力就在這:把一個看起來要 DP 的最佳化問題,換成一個「只要貪心就能回答」的是非題。 困難的部分被二分吸收了,check 只需要簡單且正確。

一句洞察// INSIGHT

和 875 同一副骨架,只有兩處要重想:左界要問「這個候選在物理上可能嗎」(包裹不可分割 → max), check 要問「怎麼驗證最省事」(順序固定 → 貪心分段,O(n) 且可證明最優)。
