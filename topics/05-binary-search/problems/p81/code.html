class Solution {
public:
    bool search(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            // ── (D) 兩端同值 → 分不出哪半有序,只能保守縮一格 ──
            if (nums[left] == nums[mid]) {
                if (nums[left] == target) {
                    return true;          // 丟掉它之前先驗過 —— 這行是正確性的關鍵
                }

                left++;
                continue;
            }

            if (nums[left] < nums[mid]) {      // 左半 [left, mid] 有序
                if (nums[left] <= target && target <= nums[mid]) {
                    right = mid;              // 在有序半內 → 收過去(含 mid)
                } else {
                    left = mid + 1;
                }
            } else {                            // 否則右半 [mid, right] 有序
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;            // 在有序半內 → 收過去(不含 mid)
                } else {
                    right = mid;
                }
            }
        }

        return nums[left] == target;      // 收斂到單格,仍要驗一次
    }
};

把 33 的程式碼並排看,只多了最前面那個 (D) 分支,其餘一字不動。 而那個分支只做兩件事:先驗這一格,再放棄這一格。

為什麼判有序可以從 ≤ 收成 <// A DEAD EQUALS

在 33 裡,判有序必須寫 nums[left] <= nums[mid] —— 那個等號用在「區間剩兩格、mid == left」的情形,少了它會誤判。但在 81 裡,那個等號是死的:

// 等號永遠不會被觸發 (D) 分支的條件就是 nums[left] == nums[mid],而它一旦成立就 continue。 ⇒ 能走到判有序那一行時,必然 nums[left] != nums[mid] ⇒ 此處 <= 與 < 在邏輯上完全等價,寫 <= 只是留了一個永遠為假的可能 實測:把 <= 換成嚴格 <,窮舉 4530 組 + 隨機 400000 組 → 失敗 0 筆 // 這是恆等改寫,不是 bug。寫 < 更誠實:讀者不必猜那個等號在防什麼
這是個小但真實的差別:同一行程式碼在 33 是必要的,在 81 是死的。 因為 81 把「相等」這個情況提前攔掉了,後面就再也遇不到它。

複雜度分析// COMPLEXITY

情形每輪做的事區間縮多少
判斷得出方向一次比較 + 範圍判斷砍一半
(D) 兩端同值一次比較 + 一次命中檢查只縮一格
平均 O(log n)　　最壞 O(n)　　S = O(1)

實測迭代次數:n=1000 → 999、n=5000 → 4999,恆等於 n−1; 同尺寸無重複只要 13 次。兩個資料點隨 n 成 5 倍 ⇒ 線性。

// 實測表(每進一次 while 計 1) 輸入(n = 5000) 迭代次數 全部相等 [1]*5000,target 不存在 4999 ← 最壞 全相等只有 v[4998] 不同,target=2 4999 [1,...,1,2],target=3 4999 只有正中間一格不同 2500 全部相等,target 存在 1 ← 第一輪就命中 無重複的旋轉陣列(掃過所有 target 取最大) 13 // 最壞 4999 = n−1;無重複 13 ≈ log₂5000

邊界與陷阱// PITFALLS

下表每一列的失敗筆數與反例都是窮舉實測的結果(全部長度 1..8、字母表 {0,1} 與 {0,1,2} 的非遞減陣列 × 所有旋轉 × 所有 target = 4530 組),不是推論。

陷阱實測後果最小反例
整段刪掉 (D) 分支(= 照抄 33) 失敗 60/4530 [0,1,0,0,0] t=1 → false(正解 true)
(D) 裡沒先驗 nums[left] == target 失敗 725/4530 [0,1] t=0 → false(正解 true)
(D) 裡改成 right-- 失敗 1234/4530 [0,1] t=1 → false(正解 true)
右半範圍用 nums[mid] <= target 失敗 166/4530 [1,0,1] t=0 → false(正解 true)
迴圈條件寫 left <= right 行為上測不出錯,但越界讀取 [1,1,1] t=2 → 讀到 nums[3](ASan 抓到 heap-buffer-overflow)
判有序寫 <= 而非 < 失敗 0/4530 —— 恆等改寫 那個等號是死的(見第 2 節)
(D) 條件用 nums[left] == nums[right] 失敗 0/4530 —— 也正確 觸發次數較少,最壞仍是 O(n)
⚠ 第五列特別值得記:測不出錯 ≠ 沒有錯

把迴圈條件改成 left <= right 之後,窮舉 4530 組一筆都沒失敗,也沒有無窮迴圈 —— 因為 left == right 時 mid == left,必定進入 (D) 分支,要嘛 return、要嘛 left++ 跳出。

但跳出時 left 已經是 right + 1,最後那行 nums[left] 就讀到陣列外面。 用 -fsanitize=address 跑 [1,1,1]、target=2,立刻報 heap-buffer-overflow。 這是未定義行為 —— 它「碰巧沒錯」而不是「沒錯」。行為測試看不到的東西,要靠 sanitizer。
