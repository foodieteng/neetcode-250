重點回顧// RECAP

面向要記住的那一句
視角轉換不找中位數那個數,找那條切線
為什麼能二分左半格數 leftCount 固定 ⇒ j = leftCount − i ⇒ 只剩 i 一個自由度
合法條件兩排各自有序 ⇒ O(mn) 個條件塌成 L1 ≤ R2 與 L2 ≤ R1
兩個失敗方向L1 > R2 切太多 → hi = i−1;L2 > R1 切太少 → lo = i+1
對調 m ≤ n不是優化,是正確性 —— j 的上下界都恰好靠它成立
+1奇數時多的那格分給左半 ⇒ 中位數 = max(L1, L2),奇偶共用一段程式
哨兵±∞ 在 max/min 裡永遠輸;已證明並實測不會進到加法
回傳方式找到就當場回傳,沒有「收斂後 return lo」;末尾 -1.0 不可達
複雜度O(log min(m,n)),比題目要求的 O(log(m+n)) 更嚴格;實測 ≤ 10 輪

觀念題// CONCEPT Q&A

Q1. leftCount = (m + n + 1) / 2 —— 那個 +1 在做什麼?請分奇偶說明,並解釋它為什麼讓兩種情形共用同一段程式。
Q2. 「左半每個數都 ≤ 右半每個數」看起來要比 O(mn) 次,程式卻只比了兩次。為什麼夠?另外,L1 > R2 和 L2 > R1 有沒有可能同時成立?
Q3. if (m > n) return findMedianSortedArrays(nums2, nums1); —— 有人說這只是為了「在短的那排二分比較快」。這個說法不完整,請說出真正的理由。
Q4. (max(L1,L2) + min(R1,R2)) 是 int 加法,而 L1 可能是 INT_MIN、R1 可能是 INT_MAX。這行會不會溢位?請證明,再說你要怎麼驗證你的證明。
Q5. 本章其他二分都是「收斂後 return left」,這題卻是找到就當場回傳,末尾還掛一句 return -1.0。為什麼結構不一樣?那句 -1.0 會被執行到嗎?

範例 Trace// 主例 + 哨兵例

例 A · nums1=[1,3,5,13,25]、nums2=[6,12,15,18,21](動畫用的就是這個)。 m = n = 5,leftCount = (5+5+1)/2 = 5,i ∈ [0, 5]。

// 第 1 輪:lo=0 hi=5 → i=2, j = 5 − 2 = 3 nums1 切在 i=2 : 1 3 | 5 13 25 L1 = 3 | R1 = 5 nums2 切在 j=3 : 6 12 15 | 18 21 L2 = 15 | R2 = 18 交叉檢查:L1(3) ≤ R2(18) ✓ 但 L2(15) > R1(5) ✗ → nums1 切太少 → lo = i + 1 = 3
// 第 2 輪:lo=3 hi=5 → i=4, j = 5 − 4 = 1 nums1 切在 i=4 : 1 3 5 13 | 25 L1 = 13 | R1 = 25 nums2 切在 j=1 : 6 | 12 15 18 21 L2 = 6 | R2 = 12 交叉檢查:L1(13) > R2(12) ✗ → nums1 切太多 → hi = i − 1 = 3
// 第 3 輪:lo=3 hi=3 → i=3, j = 5 − 3 = 2 nums1 切在 i=3 : 1 3 5 | 13 25 L1 = 5 | R1 = 13 nums2 切在 j=2 : 6 12 | 15 18 21 L2 = 12 | R2 = 15 交叉檢查:L1(5) ≤ R2(15) ✓ 且 L2(12) ≤ R1(13) ✓ → 合法! 左半 = {1,3,5,6,12} 右半 = {13,25,15,18,21}
// OUTPUT m + n = 10 是偶數 左半最大 = max(L1, L2) = max(5, 12) = 12 右半最小 = min(R1, R2) = min(13, 15) = 13 → (12 + 13) / 2.0 = 12.5 驗證:合併後 = [1,3,5,6,12,13,15,18,21,25],第 5、6 個正是 12 和 13 共 3 輪 // 12.5

例 B · 官方範例 2:nums1=[1,2]、nums2=[3,4] —— 這個會用到 兩個哨兵。 leftCount = (2+2+1)/2 = 2。

// 第 1 輪:lo=0 hi=2 → i=1, j = 1 L1 = 1 | R1 = 2 L2 = 3 | R2 = 4 L2(3) > R1(2) → 切太少 → lo = 2
// 第 2 輪:lo=2 hi=2 → i=2 (== m), j = 0 nums1 整排進左半 → 右半沒有東西 → R1 = INT_MAX (+∞) nums2 一格都不出 → 左半沒有它 → L2 = INT_MIN (−∞) L1 = 2 | R1 = +∞ L2 = −∞ | R2 = 3 交叉檢查:L1(2) ≤ R2(3) ✓ 且 L2(−∞) ≤ R1(+∞) ✓ → 合法
// OUTPUT max(L1, L2) = max(2, −∞) = 2 ← 哨兵被淘汰 min(R1, R2) = min(+∞, 3) = 3 ← 哨兵被淘汰 → (2 + 3) / 2.0 = 2.5 // 2.5 —— 兩個哨兵都沒有真的進到加法
例 B 就是 Q4 的答案在跑:哨兵出現了,但被 max / min 擋在加法之外。 實測 18 萬組(全部 m+n ≤ 8 的窮舉 + ±10⁶ 的極端值),偶數分支一次都沒有真的加到 ±∞。

應用題// APPLICATION

App 1. 把題目改成「回傳兩個有序陣列合併後的第 k 小」(1-based)。這套切點法要改哪幾行?複雜度變嗎?
App 2. 改成三個有序陣列的中位數。切點法推廣得過去嗎?如果不行,你會怎麼做,複雜度多少?
App 3. 值域從 ±10⁶ 放寬到整個 int(元素可以是 INT_MIN / INT_MAX)。這份程式碼還對嗎?
// ANSWERS
A1. 那個 +1 把奇數時「多出來的那一格」分給左半。

偶數(設 m+n = 2t):leftCount = (2t+1)/2 = t(整數除法),左右各 t 格。中位數是中間兩數的平均 = 左半最大與右半最小的平均 = (max(L1,L2) + min(R1,R2)) / 2.0。

奇數(設 m+n = 2t+1):leftCount = (2t+2)/2 = t+1,左半 t+1 格、右半 t 格。中位數是第 t+1 小 = 左半最大 = max(L1, L2),完全不必碰右半。

為什麼能共用一段程式:因為 +1 固定把餘數放左邊,「中位數」在兩種情形下都只跟切口旁的四個值有關,差別僅在最後那一行怎麼組合。若寫成 (m+n)/2,奇數時餘數跑到右半,max(L1,L2) 就變成第 t 小而不是第 t+1 小 —— 實測最小反例 [0] + [1,1] 答 0(正解 1),119965 組錯 17176 組。
A2. 因為兩排各自有序,大部分條件是免費的。nums1 左半的最大值就是 L1、右半最小就是 R1;nums2 同理。同一排內部的 L1 ≤ R1、L2 ≤ R2 由排序天然保證,不用檢查。所以只剩跨排的兩組:L1 ≤ R2、L2 ≤ R1。而只要這四個極值兩兩就位,左半任一元素 ≤ max(L1,L2) ≤ min(R1,R2) ≤ 右半任一元素。O(mn) 塌成 2。

不可能同時成立。反證:若 L1 > R2 且 L2 > R1,由同排有序有 R2 ≥ L2 與 R1 ≥ L1,於是
L1 > R2 ≥ L2 > R1 ≥ L1 ⇒ L1 > L1,矛盾。

這件事很重要:它保證 if / else if / else 三個分支互斥且窮盡 —— 不會有「兩個條件都成立、不知道往哪縮」的情形,也不會漏掉任何狀態。
A3. 真正的理由是「保證 j = leftCount − i 不越界」,效率只是附帶好處。

i 在 [0, m] 掃,j 必須落在 [0, n],否則 nums2[j-1] 或 nums2[j] 會讀到陣列外面:
上界 j ≤ leftCount = (m+n+1)/2 ≤ n ⟺ m + n + 1 ≤ 2n + 1 ⟺ m ≤ n
下界 j ≥ leftCount − m ≥ 0 ⟺ m + n + 1 ≥ 2m ⟺ m ≤ n + 1
兩個界都恰好卡在 m ≤ n。

實測:拿掉對調、在每次存取加上界檢查,119965 組裡有 10284 組讀到陣列外面,最小反例 [0,1,1,1] + [0,0](m=4 > n=2)。

另外兩個細節:它寫成遞迴而不是 std::swap,所以不會改動呼叫端的資料;而且對調後必定 m ≤ n,遞迴最多一層。
A4. 不會溢位。證明分兩半:

max(L1, L2) == INT_MIN 需要 i == 0 且 j == 0,即 leftCount = i + j = 0。但 leftCount = (m+n+1)/2 且題目保證 m + n ≥ 1 ⇒ leftCount ≥ 1。矛盾。

min(R1, R2) == INT_MAX 需要 i == m 且 j == n,即 leftCount = m + n。而偶數分支裡 leftCount = (m+n)/2,要等於 m+n 只有 m+n = 0。矛盾。

所以相加的兩個都是真實元素,值域 ±10⁶ ⇒ 和 ≤ 2×10⁶。(奇數分支只回 max(L1,L2),靠上面第一半的論證同樣安全。)

怎麼驗證證明 —— 這才是重點。「我推理過所以安全」不夠。做法是在偶數分支埋計數器,記錄 max(L1,L2) 是否等於 INT_MIN、min(R1,R2) 是否等於 INT_MAX、以及 int 加法結果與 long long 版本是否一致,然後跑:全部 m+n ≤ 8 的窮舉(125969 組)+ ±10⁶ 值域的隨機(60400 組)+ 極端輸入(2000 個 10⁶、m = 0 等)。

結果:三個計數器全部為 0,實測和的絕對值上限 2000000 —— 只有 INT_MAX 的 0.093%。證明與量測對上了才算數。
A5. 因為這題找的不是「邊界」,是一個確定的位置。

410、1011 那類答案二分,找的是「第一個可行的值」——可行性是 F...F T...T,答案在 T 的邊界上,所以要一路收斂到 lo == hi 再回傳。

這題不同:i 掃過去時狀態是「切太少 → 剛好 → 切太多」三段,而我們要的就是中間那段本身。一踩到就已經拿到全部需要的資訊(切口旁四個值),沒有必要再縮。所以是 while (lo <= hi) + 命中即 return,而不是收斂型模板。

那句 return -1.0 不可達。左半格數固定為 leftCount,而 i 從 0 掃到 m 一定會經過那個合法切點(由 A2 的三分結構保證),所以迴圈必定在 else 分支返回。實測 125969 組窮舉 + 60400 組隨機,觸發次數 0。它純粹是給編譯器看的;要更誠實可以換成 __builtin_unreachable() 或直接 throw。

順帶一提:迴圈條件寫成 while (lo < hi) 會提早跳出,而答案常常正好在最後那一格 —— 實測 [0] + [1] 就回 −1(正解 0.5),119965 組錯 35520 組。
App 1. 改兩行,複雜度不變。

① leftCount 從 (m+n+1)/2 直接改成 k —— 因為「第 k 小」就是「左半剛好放 k 格時,左半的最大值」。
② i 的範圍要重新夾:lo = max(0, k − n)、hi = min(m, k)。原版靠 m ≤ n 就能保證 j ∈ [0, n],但 leftCount 換成任意 k 之後那個保證沒了,得明確夾住。
③ 回傳一律是 max(L1, L2),沒有偶數分支 —— 第 k 小是一個確定的元素,不是平均。

實測:300000 組隨機(m, n ≤ 6,值域 ±10,k 隨機),與「合併後取第 k−1 個」對拍不一致 0。

複雜度仍是 O(log min(m, n))。反過來看,原題就是這個廣義版在 k = (m+n+1)/2 的特例,偶數時再多取一次右半最小。
App 2. 切點法推不過去。三排要決定 i₁, i₂, i₃,而約束只有一條 i₁ + i₂ + i₃ = leftCount —— 剩下兩個自由度。二分需要「一維 + 單調」,兩個自由度就沒有「往左還是往右」可言了。而且合法性條件從 2 個變成 3 × 2 = 6 個跨排比較,失敗時指不出唯一的修正方向。

改用「二分值」:不猜切點,猜答案本身的數值 v,再問「有幾個元素 ≤ v」。這個計數對每排都是一次 upper_bound,O(log);計數對 v 單調不減 ⇒ 可二分。找第 k 小就是找第一個使計數 ≥ k 的 v。

實測:三排、各長 0–5、值域 ±15,200000 組隨機與合併排序對拍不一致 0。

複雜度 O(t · log V · log L)(t 排數、V 值域寬度、L 最長排長)。比切點法多一個 log V,但排數任意、而且完全不依賴「只有兩排」這個結構。這是一個常見的取捨:切點法更快但只吃兩排,二分值慢一點卻能推廣。
App 3. 會壞 —— 哨兵撞上真實資料。整套哨兵的前提是「INT_MIN / INT_MAX 不是合法元素值」,所以它們在 max / min 裡永遠輸。值域一旦涵蓋整個 int,這個前提就沒了,A4 的證明第一步就垮(它證的是「哨兵不會被選中」,不是「哨兵被選中也沒關係」)。

實測(g++ -fsanitize=undefined):
[INT_MAX] + [INT_MAX] → UBSan 報 signed integer overflow: 2147483647 + 2147483647。int 相加繞回 −2,除以 2.0 得 −1.0(正解 2147483647)。
[INT_MIN] + [INT_MIN] → 相加繞回 0,答 0(正解 −2147483648)。
對照題目真正的值域:[10⁶] + [10⁶] → 1000000,正確。

怎麼修(兩處都要改):① 哨兵換成 long long 的 LLONG_MIN / LLONG_MAX,四個 L/R 變數也一併改型別;② 最後那行改成 (max(L1,L2) + min(R1,R2)) / 2.0 在 long long 下算,或直接寫成 max(L1,L2) / 2.0 + min(R1,R2) / 2.0 避開中間值。

教訓:用哨兵等於借走值域裡的兩個數。借之前要先確認題目沒在用它們 —— 這題的 ±10⁶ 剛好讓這筆借貸是安全的,但那是約束給的,不是寫法本身安全。
