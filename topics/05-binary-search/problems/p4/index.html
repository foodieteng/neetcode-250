題目簡介// THE QUESTION

QUESTION

給兩個各自有序的陣列 nums1(長 m)、nums2(長 n), 回傳兩者合起來的中位數。

而且題目明文要求 O(log(m+n)) —— 這句話才是這題的全部難度。

如果沒有那句複雜度要求,這題是 easy:合併兩個有序陣列取中間,五行寫完。 那句話把「合併」整條路封死了 —— 你不能碰過每一個元素,連 O(m+n) 都不行。

關鍵的視角轉換:中位數的定義是「把資料切成一樣大的兩半」。 所以不要去找那個數,去找那條切線 —— 而切線的位置只有一個自由度,可以二分。

△ 可行 · 但邊界更雜
ADOPT
C 二分「nums1 出幾格到左半」 O(log min(m,n))
左半總格數 left 是固定的,所以只要決定 i(nums1 出幾格), j = left − i 自動決定 —— 兩個自由度塌成一個。 再用交叉比較 L1 ≤ R2 且 L2 ≤ R1 判斷「切多了還是切少了」,單調 ⇒ 可二分。 而且只在短的那個陣列上二分,比要求的 log(m+n) 還快。

核心策略 · 三步驟// STRATEGY

  1. 對調成 m ≤ n:if (m > n) return findMedianSortedArrays(nums2, nums1);。這不只是為了快 —— 見第 6 節,它是 j 不越界的唯一保證。
  2. 二分 i ∈ [0, m]:j = left − i,其中 left = (m+n+1)/2。取出切口旁的四個值 L1 | R1 與 L2 | R2,邊界用 ±∞ 哨兵。
  3. 交叉比較:L1 > R2 → nums1 切太多 → r = i − 1;L2 > R1 → 切太少 → l = i + 1;兩者皆否 → 合法,直接算答案。
注意第 3 步沒有「收斂後再算」這一段。合法切點一被找到就當場回傳 —— 這也是為什麼迴圈末尾那句 return -1.0; 在實測中一次都沒被執行過(12 萬組窮舉)。

為什麼只比四個數就夠// THE CROSS CHECK

LEMMA 1 · 兩個交叉比較 ⇔ 左半每個數 ≤ 右半每個數

我們要的條件是「左半的每一個 ≤ 右半的每一個」,看起來要比 O(mn) 次。但因為兩排各自有序:

nums1 左半的最大值就是 L1、右半的最小值就是 R1;nums2 同理是 L2 和 R2。 同一排內部已經天然滿足(L1 ≤ R1、L2 ≤ R2,因為排序過了),完全不用檢查。 剩下的只有跨排那兩組:L1 ≤ R2 和 L2 ≤ R1。

所以 O(mn) 個條件塌成 2 個。這就是為什麼程式只碰四個數。

LEMMA 2 · 兩個失敗方向剛好指向相反的縮法

L1 > R2 —— nums1 左半的最大值比 nums2 右半的最小值還大。 要修好它必須把 L1 變小,也就是 nums1 少出一點 ⇒ i 要變小 ⇒ r = i − 1。

L2 > R1 —— 對稱的另一邊。要修好它必須把 R1 變大,也就是 nums1 多出一點 ⇒ i 要變大 ⇒ l = i + 1。

兩者不可能同時成立(否則 L1 > R2 ≥ L2 > R1 ≥ L1,矛盾),所以三個分支恰好互斥且窮盡。 i 增大時 L1 單調不減、R1 單調不減、L2 單調不增、R2 單調不增 ⇒ 「切太多 / 剛好 / 切太少」沿著 i 是一段一段連著的 ⇒ 可以二分。

left = (m+n+1)/2 總數奇數時,把多出來的那一格分給左半 ⇒ 中位數就是 max(L1, L2),奇偶兩種情形共用同一段程式 改成 (m+n)/2:
