完整實作// THE CODE

p4.cpp C++17 
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        int m = nums1.size(), n = nums2.size();

        // 保證在短的那排上二分 —— 也是 j 不越界的唯一保證
        if (m > n) {
            return findMedianSortedArrays(nums2, nums1);
        }

        // 左半要放的總格數。+1 讓奇數時多的那格落在左半
        int leftCount = (m + n + 1) / 2;

        int lo = 0, hi = m;
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;   // nums1 出 i 格到左半
            int j = leftCount - i;       // nums2 出的格數就跟著定了

            // 切口旁的四個值;邊界用 ±∞ 哨兵,免特判
            int L1 = (i == 0) ? INT_MIN : nums1[i - 1];
            int R1 = (i == m) ? INT_MAX : nums1[i];
            int L2 = (j == 0) ? INT_MIN : nums2[j - 1];
            int R2 = (j == n) ? INT_MAX : nums2[j];

            if (L1 > R2) {
                hi = i - 1;            // nums1 切太多
            } else if (L2 > R1) {
                lo = i + 1;            // nums1 切太少
            } else {
                if ((m + n) % 2) {
                    return (double)max(L1, L2);
                }

                return (max(L1, L2) + min(R1, R2)) / 2.0;
            }
        }

        return -1.0;   // 不可達:合法切點必存在(實測 12 萬組從未走到)
    }
};

這是全章唯一一題「找到就當場回傳」的二分 —— 沒有收斂、沒有 return lo。 因為合法切點不是一段區間的端點,而是一個確定的位置,踩到就結束。 410、1011 那種「回傳 left」的模板在這裡用不上。
2

±∞ 哨兵:為什麼安全// THE SENTINELS

四個三元運算子把「切在最邊上」的情形吸收掉了:i == 0 表示 nums1 一格都不出,左半沒有它的元素, L1 就取 INT_MIN —— 在 max() 裡永遠輸。i == m 同理,R1 = INT_MAX 在 min() 裡永遠輸。

但這帶出一個必須回答的問題:(max(L1,L2) + min(R1,R2)) 這行 int 加法,會不會加到 INT_MIN + INT_MAX?

PROOF · 偶數分支不可能拿到哨兵

max(L1, L2) == INT_MIN 需要 i == 0 且 j == 0,即 leftCount = i + j = 0。 但 leftCount = (m+n+1)/2 而題目保證 m + n ≥ 1 ⇒ leftCount ≥ 1。不可能。

min(R1, R2) == INT_MAX 需要 i == m 且 j == n,即 leftCount = m + n。 偶數分支裡 leftCount = (m+n)/2,要等於 m+n 只有 m+n = 0。也不可能。

所以偶數分支相加的兩個都是真實元素,值域 ±10⁶ ⇒ 和的絕對值 ≤ 2×10⁶。

// 但推理可能出錯 —— 直接量 在偶數分支埋計數器,跑: · 全部 m+n ≤ 8、值域 0..5 的窮舉 125969 組 · 值域 ±10^6、m,n ≤ 1000 的隨機 60400 組 · 極端:2000 個 +10^6 / 2000 個 -10^6 / m=0,n=2000 max(L1,L2) 拿到 INT_MIN 的次數 : 0 min(R1,R2) 拿到 INT_MAX 的次數 : 0 int 加法與 64-bit 結果不符的次數: 0 實測 |max(L1,L2) + min(R1,R2)| 上限 = 2000000 (INT_MAX 的 0.093%) // 證明與量測一致 —— int 安全,而且餘裕超過 1000 倍
注意奇數分支不受這個保護,它直接回 max(L1, L2)。 但同樣的論證擋住了它:max(L1,L2) == INT_MIN 一樣要求 leftCount = 0,一樣不可能。 兩個分支都安全,但理由要各自講一次。

邊界與陷阱// PITFALLS

反例全是實測的:窮舉所有 m + n ≤ 8、值域 0–5 的非遞減陣列組合,拿改壞的版本跟合併參考解對拍。 下表用兩邊都非空的那 119965 組(空陣列的反例更短,但沒那麼有代表性)。

陷阱為什麼錯實測最小反例
leftCount 忘了 +1 奇數時多的那格跑到右半,max(L1,L2) 就不再是中位數 [0] + [1,1] → 0(正解 1)
錯 17176/119965
拿掉 if (m > n) 對調 j = leftCount − i 可能為負或大於 n → 讀到陣列外面 [0,1,1,1] + [0,0] → 越界
錯 10284/119965
hi 初值 m 寫成 m − 1 i = m(nums1 整排進左半)是合法候選,砍掉就可能無解 [0] + [1] → −1(正解 0.5)
錯 22550/119965
while (lo <= hi) 寫成 < 區間剩一格時就跳出,但答案常常正好在那一格 [0] + [1] → −1(正解 0.5)
錯 35520/119965
奇數分支回 min(R1,R2) +1 把多的那格放在左半,中位數是左半最大,不是右半最小 [0] + [0,1] → 1(正解 0)
錯 17176/119965
/ 2.0 寫成 / 2 整數除法,小數部分被截掉 [0] + [1] → 0(正解 0.5)
錯 30375/119965
L1 > R2 寫成 L1 >= R2 這樣也對。L1 == R2 時切點其實合法,被誤判丟掉,但二分會收到另一個等價的合法切點,值相同 錯 0/119965
另測 363000 組重複值密集(值域只有 1–3 種)也 0
最後一列是刻意留的:> 和 >= 在這裡看起來像經典 off-by-one,實際上兩者都對。 我特地用「值域只有 1–3 種值」的測資去逼出大量 L1 == R2,36 萬組仍然零錯、也從沒掉進 return -1.0。 不是每個可疑的符號都是 bug —— 但要靠測不是靠猜。
