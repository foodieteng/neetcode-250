Hmm, let me think about this for a second.

A naive approach expands from each bar to find its shorter boundaries — that's O(n2), too slow for 105 bars. This problem reminds me of a monotonic stack, because it finds every nearest-smaller boundary in O(n).

Increasing or decreasing? The rule I use: the stack holds elements still waiting for a boundary, and an element is popped exactly when the incoming one is its boundary. I want the nearest smaller, so I pop whenever the incoming bar is <= the top — which keeps the stack increasing. If I were looking for the nearest greater instead, it would be a decreasing stack.

// increasing stack of indices; append a -1 sentinel
for i: while stack and h[top] >= h[i]:
  bar = pop; right = i; left = new top (or none)
  width = stack.empty() ? i : i - top - 1
  maxArea = max(maxArea, h[bar] * width)

One: keep an increasing stack of indices, and append a -1 sentinel to the heights.
Two: for each index, while the top bar is at least as tall as the current one, pop it and settle its rectangle.
Three: push the current index.

One thing worth flagging — when I pop a bar, its right boundary is the current i, and its left boundary is whatever sits below it now, so the width is the open interval, i - top - 1. And the trailing -1 sentinel is shorter than every bar, so it flushes any bars still left on the stack at the end.

class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        heights.push_back(-1);              // sentinel: shorter than all
        int n = heights.size();
        int maxArea = 0;
        stack<int> st;                      // indices, heights increasing

        for (int i = 0; i < n; i++) {
            while (!st.empty() && heights[st.top()] >= heights[i]) {  // settle
                int h = heights[st.top()]; st.pop();       // settled height
                int w = st.empty() ? i : i - st.top() - 1;  // right=i, left=top
                maxArea = max(maxArea, h * w);
            }
            st.push(i);                        // waits for a right bound
        }
        return maxArea;
    }
};

I append the sentinel, then walk every index. While the top of the stack is at least as tall as the current bar, I pop it, compute its width, and update the max area with h * w. Then I push the current index.

One thing worth flagging — if the stack is empty after popping, there's no shorter bar to the left, so the width runs all the way to the start: w = i. Otherwise it's i - st.top() - 1. And h * w peaks at 104 × 105 = 109 — still within int.

Corner cases:

• A strictly increasing histogram → flushed entirely by the sentinel.
• A single bar → returns its own height.
• Equal heights → the rightmost equal bar gets the full width.
