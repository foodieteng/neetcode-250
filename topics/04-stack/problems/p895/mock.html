push(v): f = ++freq[v]; group[f].push(v)
pop(): take the top of the highest level; freq[v]--
  (highest level = max key, or track an int maxFreq)

One: keep a count per value, and a stack per frequency level.
Two: push bumps the count to f and pushes the value onto level f.
Three: pop takes the top of the highest level and decrements that value's count.

One thing worth flagging — a value with frequency 3 sits in levels 1, 2, and 3 simultaneously. So after I pop it off the top level and decrement its frequency, its copies in lower levels keep it in play. And the level being a stack is exactly what breaks ties by recency — no timestamps needed.

Alright, let me code this up. A hash map holds each value's count, and an ordered map goes from frequency to a stack of values. push increments the count and pushes onto that level. pop reads the largest key with rbegin(), takes that stack's top, and decrements the count.

class FreqStack {
public:
    unordered_map<int, int> freq;            // value → current count
    map<int, stack<int>> st;            // freq f → stack of values that reached f

    FreqStack() {}

    void push(int val) {
        freq[val]++;                          // bump the count first
        st[freq[val]].push(val);              // drop into its current level
    }

    int pop() {
        int k = st.rbegin()->first;            // highest level (max key)
        int v = st[k].top(); st[k].pop();       // most recent to reach k
        if (st[k].empty()) st.erase(k);        // drop empty level
        freq[v]--;                            // falls back one level
        return v;
    }
};

One thing worth flagging — I erase a level once it's empty, so rbegin() keeps pointing at a real highest level. Replacing the ordered map with an unordered_map plus an int maxFreq, decremented when the top level empties, makes it O(1).
