重點回顧// RECAP

面向要點
規則先比頻率,同頻率再取最近
結構freq[val] + bucket[f](每頻率一個堆疊)
pushfreq[v]++,疊進 bucket[freq[v]]
pop取最高層 bucket[maxF].top(),freq[v]--
為何對高度=最頻繁;堆疊頂=最近 → 一次滿足兩規則
複雜度map 版 O(log D);maxFreq 變體 O(1)

觀念題// QUIZ

Q1. 為什麼一個出現 3 次的值,會同時存在於 bucket[1]、bucket[2]、bucket[3]?這對 pop 有什麼幫助?
Q2. 「取最高層 bucket 的頂端」為什麼同時滿足「最頻繁」與「同頻率取最近」兩條規則?
Q3. push 時為什麼要先 freq[v]++ 再疊進 bucket[freq[v]]?順序反了會怎樣?
Q4. pop 後為什麼一定要 freq[v]--?不做會壞在哪?
Q5. O(1) 變體用一個整數 maxFreq。為什麼 pop 到某層空掉時,maxFreq-- 一定正確、不會跳過某層?

範例 Trace// push 5,7,5,7,4,5 · pop×4

// 官方例:pop 依序應得 5,7,5,4(bucket 右=top) push 5,7,5,7,4,5 後: freq = {5:3, 7:2, 4:1} bucket = {1:[5,7,4], 2:[5,7], 3:[5]} pop(): 最高層3 top=5 → 5; freq{5:2}; bucket{1:[5,7,4],2:[5,7]} pop(): 最高層2 top=7 → 7; freq{7:1}; bucket{1:[5,7,4],2:[5]} pop(): 最高層2 top=5 → 5; freq{5:1}; bucket{1:[5,7,4]} pop(): 最高層1 top=4 → 4; freq{4:0}; bucket{1:[5,7]} // 依序 5, 7, 5, 4 ✓
第 2、3 個 pop 都在 freq 2 這層:先取頂端 7(較晚),再取 5。第 4 個 pop 降到 freq 1 層取頂端 4。 「頻率相同看新近」全靠堆疊頂端自動排序,程式完全沒記時間戳。

應用題// APPLY

App 1. 改成 unordered_map + maxFreq 的 O(1) 版:把 push/pop 寫出來,並說明為何不需要有序 map。
App 2. 若同頻率要改成取最早(最不近)而非最近,結構要怎麼改?(提示:每層改用佇列)
App 3. 若還要支援 peek()(看但不移除最頻繁),以及查詢「某值目前頻率」,分別怎麼做、複雜度多少?
// ANSWERS
A1. 因為每 push 一次,頻率就 +1,並把該值疊進「新達到的那一層」bucket。所以第一次 push 進 bucket[1]、第二次進 bucket[2]、第三次進 bucket[3] —— 一份份留在各層。好處:當它被 pop 一次(從最高層移除),它在較低層的分身還在,freq-- 後它自然「退回」較低頻率繼續參與,不需要重建任何東西。
A2. 最頻繁:最高層 bucket[maxF] 裡的值,其頻率就是目前最大,取它必定最頻繁。同頻率取最近:bucket[maxF] 是堆疊,值按「達到 maxF 的先後」由底往頂疊,頂端就是最後(最近)達到 maxF 的值。並列最高頻率的值都在這層,頂端正是其中最近 push 的。所以一個 top() 同時滿足兩條。
A3. 因為要疊進的是它更新後的頻率層。先 freq[v]++ 讓 freq[v] 變成新次數 f,再 bucket[f].push(v) 才是把它放到「第 f 層」。若先疊再 ++,會放到舊的 f−1 層,層次全錯位,pop 時取到的頻率就不對。
A4. 因為 pop 把該值的一個分身從最高層移除了,它的「目前頻率」實際上少了一。若不 freq[v]--,freq 會虛高,之後再 push 這個值時會用錯的頻率層(跳層),導致 bucket 結構與真實頻率不一致,pop 順序全亂。freq[v]-- 讓帳目與 bucket 同步。
A5. 因為頻率是逐一累加的:任何值要到達 maxFreq,一定先經過 maxFreq−1,並在 bucket[maxFreq−1] 留下一份。所以當 bucket[maxFreq] 被取空時,bucket[maxFreq−1] 必定非空,新的最高層剛好是 maxFreq−1,maxFreq-- 不會跳空。這也是為什麼不必用有序 map 去「找」最高層。
App 1. push(v){ int f=++freq[v]; maxFreq=max(maxFreq,f); group[f].push(v); };pop(){ int v=group[maxFreq].top(); group[maxFreq].pop(); if(group[maxFreq].empty()) maxFreq--; freq[v]--; return v; }。不需要有序 map,因為最高層只會 +1(push)或 −1(pop 空),用一個整數維護即可,省掉 map 的 O(log D),達到攤還 O(1)。
App 2. 把每層的堆疊改成佇列(queue)。堆疊頂端是最近、佇列前端是最早;要「同頻率取最早」就從佇列前端取。其餘邏輯(freq、分層、取最高層)完全不變。這說明「同頻率的順序策略」被封裝在每層的容器型別裡,換容器即換策略。
App 3. peek():和 pop 相同但不 pop、不 freq--,回傳 bucket[maxF].top(),O(1)(或 map 版 O(log D))。查「某值目前頻率」:直接讀 freq[v],O(1)。兩者都只是讀取,不動結構;注意 peek 不可改動 maxFreq 或層內容。
