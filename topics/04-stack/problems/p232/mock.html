Two: peek drains in into out if out is empty, then returns out's top.

Alright, let me code this up. st1 is in and st2 is out.

class MyQueue {
    stack<int> st1, st2;                 // st1 = in (takes push) · st2 = out (serves pop)
public:
    MyQueue() {}

    void push(int x) { st1.push(x); }    // only into in, O(1)

    int pop() {
        int v = peek();                  // make sure out holds the front (pour if needed)
        st2.pop();
        return v;
    }

    int peek() {
        if (st2.empty()) {               // pour only when out is empty (lazy transfer)
            while (!st1.empty()) {
                st2.push(st1.top());     // in → out, order reversed
                st1.pop();
            }
        }
        return st2.top();                // out's top = queue front
    }

    bool empty() {
        return st1.empty() && st2.empty();  // empty only if both are empty
    }
};

push only touches in. peek holds the transfer: if out is empty, it moves everything from in to out, which reverses the order, then returns out's top. pop calls peek() first, so out is guaranteed to have the front, then pops it.

The line to get right is the guard on the transfer, if (st2.empty()): pour only when out is empty. Pouring while out still holds elements would bury the older ones under newer ones and break the order. And empty must check both stacks, since elements can sit in either one.

Each element takes a fixed tour: a push onto in, one transfer to out, and one pop from out. That's a constant number of stack operations, done once.

Over n operations, that's O(n) total work, so O(1) amortized. The occasional expensive pop just settles up for the cheap pushes that came before it.

push is O(1). pop and peek are amortized O(1), with a worst case of O(n) for a single call. Space is O(n) for the two stacks.

The mirror problem, a stack built from queues, doesn't get this with the rotate approach: rotating the queue redoes work on every push, because the old elements keep cycling around. Here the reversal happens once and flows one way, which is what makes lazy transfer amortize cleanly.
