題目簡介// THE QUESTION

QUESTION

n 台車在 position[i]、以 speed[i] 開往終點 target。不能超車:追上前車就跟著它同速。 一個車隊是併在一起的一群車(速度取隊內最慢)。求最後抵達終點的車隊數量。

幫每台車算「若暢行無阻,幾小時到終點」:t = (target − position) / speed。關鍵事實:後車會併入前車 ⟺ 後車的 t ≤ 前車的 t (後車在後面、卻不比前車晚到 → 必定追上、卡在後面)。把車依位置排序,用堆疊數出「彼此併不到一起」的獨立車隊數。

2

會不會併,要看抵達時間而非單看速度 —— 起點不同,快車未必先到。
△ REJECT · 判準錯
ADOPT
C 依位置排序,用堆疊比抵達時間 t 數車隊 O(n log n)
依位置由小到大處理(最後才輪到最前車)。新前車 i 來時,把堆疊頂端 t ≤ t_i 的後車 pop(它們追得上、併入 i 這隊);再 push t_i。 最後堆疊大小 = 車隊數。
● ADOPT · O(n log n)
3

核心策略// STRATEGY

  1. 依位置排序:對索引依 position 由小到大排(用 idx 陣列,不動原資料)。
  2. 算抵達時間:t = (double)(target − position[i]) / speed[i] —— 一定用浮點。
  3. 堆疊比時間:當 st.top().t ≤ t_i 就 pop(後車併入前車);再 push。回傳 st.size()。

為什麼「t 較小的後車會被吃掉」// THE INVARIANT

KEY · 後車 A 併入前車 B ⟺ t_A ≤ t_B

t 是「暢行到終點的時間」,t 越大越慢到。後車 A(位置較小)若 t_A ≤ t_B,代表它不比前車 B 晚到 —— 但它起點在後,要不晚到就得追上 B;不能超車,於是卡在 B 後同速、併成一隊,整隊以 B 的時間 t_B 抵達。反之 t_A > t_B:A 太慢、永遠追不上,自成一隊。

本解依位置由小到大處理,堆疊頂端是「目前最靠後的車隊時間」。新來的前車 i 把所有 t ≤ t_i 的頂端 pop(那些後車都會被 i 這隊吸收),i 自己 push。停在 t > t_i 的頂端表示那隊追不上,獨立存在。用 ≤(含等於)是因為「同時在終點相遇也算同隊」。最後堆疊裡每個 t 就是一個獨立車隊。

等價的經典寫法:依位置由大到小(最前車先),維護目前車隊時間 cur;每台車 t > cur 才是新車隊(cur = t),否則併入。數 t 嚴格變大的次數即車隊數。本題的堆疊版與它結果一致。

一句洞察// INSIGHT

把「會不會併隊」化約成一條不等式:後車 t ≤ 前車 t 就併入。排好位置後,獨立車隊數 = 抵達時間「擋不住」的車數 = 堆疊倖存者。 判準是抵達時間不是速度,而且一定要用浮點算。
