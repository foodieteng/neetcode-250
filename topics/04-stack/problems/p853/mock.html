A naive approach would be to simulate positions over time and watch cars merge — messy and slow.

This problem reminds me of a monotonic stack over sorted data, and it fits because each car only cares about which rear fleets it absorbs. So, sort by position and compare arrival times. I process cars from the back and keep a stack of fleet arrival times; a new front car absorbs any rear fleet whose time is ≤ its own.

One: sort the car indices by position, and compute each arrival time as a double.
Two: for each car, from back to front, pop every stacked time that is ≤ its time — those rear cars catch up and merge.
Three: push its time, and return the stack size.

One thing worth flagging — two correctness details. t must be a double; integer division would collapse distinct arrival times and overcount merges. And I compare with <=, so cars that meet exactly at the target count as one fleet.

class Solution {
public:
    int carFleet(int target, vector<int>& position, vector<int>& speed) {
        int n = position.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](const auto& a, const auto& b) {
            return position[a] < position[b];       // by position, ascending
        });

        stack<pair<int, double>> st;       // (car index, arrival time t)

        for (auto i : idx) {
            double t = (double)(target - position[i]) / speed[i];  // floating point!
            while (!st.empty() && st.top().second <= t) {  // rear t ≤ front t → merge
                st.pop();
            }
            st.push({i, t});
        }

        return st.size();                     // surviving entries = fleets
    }
};

I sort an index array by position, ascending. Then for each car I compute its time as a double, pop every stacked fleet whose time is ≤ it, and push the car's index with its time. The stack size is the answer. That matches the plan.

One thing worth flagging — I sort indices, not the arrays, so position and speed stay aligned. The cast to double happens before the division; casting after would already be too late. The survivors on the stack are exactly the independent fleets.

The time complexity is O(n log n), dominated by the sort; the stack pass is O(n). The space complexity is O(n), for the index array and the stack.

Oh, one more thing — I could drop the stack: sweep from the front to the back and keep one running "current fleet time," counting each car whose time exceeds it. That's the same logic in O(1) extra space beyond the sort. And to avoid floating point entirely, I'd cross-multiply the time comparison.
