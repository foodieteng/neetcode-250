題目簡介// THE QUESTION

QUESTION

給一串逆波蘭式(後綴)token,每個是整數或運算子 + - * /。運算子作用在它前面剛出現的兩個運算元上。 求整個式子的值(除法向零截斷)。例 ["2","1","+","3","*"] = (2+1)*3 = 9。

後綴表示式天生為堆疊而生:數字就 push;遇運算子就 pop 兩個、算完把結果 push 回去。一趟掃完,堆疊剩下的唯一元素就是答案。 不需要括號、也不需要處理運算子優先序 —— 順序已經編碼在 token 排列裡。

2

為什麼用堆疊// WHY THIS

A 轉回中綴、處理括號與優先序 繞遠路
後綴本來就是為了避開括號/優先序而存在,再轉回中綴是自找麻煩。
× REJECT · 多此一舉
B 建表達式樹再求值 O(n) 但重
可行,但要建樹、遞迴,程式與空間都更重 —— 而堆疊一個容器就夠。
△ REJECT · 過度
ADOPT
C 一個整數堆疊,一趟掃:數字 push、運算子 pop 兩個算完 push O(n)
運算子出現時,它要的兩個運算元剛好是堆疊頂端那兩個(已算好的子結果)。pop y、pop x,push x op y。 後綴的排列保證「用到時運算元一定已就緒」。
● ADOPT · O(n)

核心策略// STRATEGY

  1. 逐一掃 token:是數字(不是 + - * /)→ stoi 後 push。
  2. 是運算子:先 pop y(右運算元)、再 pop x(左運算元),計算 x op y,push 回去。
  3. 掃完:堆疊剩唯一元素 = 答案。

為什麼一趟就對// WHY IT WORKS

KEY · 運算子的兩個運算元,恆在堆疊頂端就緒

後綴表示式的定義:每個運算子都緊跟在它兩個運算元(可能是子式)的後面。所以掃到運算子時,那兩個運算元早已被算成數字、且正好躺在堆疊最上面兩格。pop 兩個、算完、把子結果 push 回去,子結果又能當下一個運算子的運算元 —— 一路收斂到單一答案。

順序是鐵律:先 pop 的是右運算元 y,後 pop 的是左運算元 x,算 x op y。對 +、* 交換律下順序無所謂,但 - 和 / 顛倒就會算錯(x - y ≠ y - x)。

複雜度// COMPLEXITY

T = O(n)　　S = O(n)

每個 token 只被處理一次(push 或一次運算);堆疊最多裝 n/2+1 個數 → O(n) 空間。
