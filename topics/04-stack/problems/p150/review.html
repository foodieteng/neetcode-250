PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼後綴表示式可以「一趟掃、用堆疊」就求值,而中綴不行?後綴消掉了什麼麻煩?
解答與說明 · ANSWER▾
後綴把「先算哪個」直接編碼進 token 的排列順序,消掉了括號與運算子優先序兩個麻煩。中綴要靠括號/優先序決定計算順序,單趟掃無法定序,需要兩個堆疊(運算元 + 運算子)或轉後綴。後綴則保證「掃到運算子時運算元一定就緒」,一個堆疊、一趟搞定。
第 2 題10 分
掃到運算子時,為什麼它要的兩個運算元保證就在堆疊頂端?
解答與說明 · ANSWER▾
因為後綴的定義:每個運算子緊跟在它兩個運算元(或其子式的結果)之後。掃描過程中,任何已完成的子式都被壓成一個數字留在堆疊上;輪到某運算子時,它的兩個運算元正是最近兩個尚未被消費的結果 —— 也就是堆疊最上面兩格。所以 pop 兩次必得正確運算元。
第 3 題10 分
為什麼「先 pop 的是 y、後 pop 的是 x」?哪些運算子顛倒會出錯、哪些不會?
解答與說明 · ANSWER▾
堆疊是後進先出:左運算元 x 比右運算元 y 先被 push,所以 y 在上、先被 pop。要還原成原式 x op y,就得「先 pop 的當 y、後 pop 的當 x」。+、* 有交換律,顛倒也對;但 -、/ 沒有,顛倒會把 x-y 算成 y-x、x/y 算成 y/x,結果錯。
第 4 題10 分
op.find(token) == npos 為什麼能正確區分「數字」與「運算子」,連 "-11" 這種負數也不誤判?
解答與說明 · ANSWER▾
op = "+-*/",op.find(token) 是把整個 token 當子字串去 op 裡找。運算子都是單字元,能在 op 找到;而任何數字字串("3"、"-11"、"42")都不是 "+-*/" 的子字串 → 回 npos。所以 == npos 精準等於「這是數字」。"-11" 雖含 '-',但整串 "-11" 不在 op 裡,不會誤判。
第 5 題10 分
用 token[0](首字元)判斷是不是運算子,會在什麼輸入上出錯?
解答與說明 · ANSWER▾
會在負數 token 上出錯。"-11"、"-3" 的首字元是 '-',用 token[0] 判斷就會被當成減法運算子,於是去 pop 兩個運算元 —— 但它其實是個運算元。正確做法是比對整個字串(如 op.find(token)==npos),或先判 token.size()==1 && 是 +-*/。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 大例:[10,6,9,3,+,-11,*,/,*,17,+,5,+]:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾
// LeetCode 官方大例,答案 22(堆疊右=top) 10 6 9 3 → [10, 6, 9, 3] "+": y=3 x=9 → push 12 [10, 6, 12] "-11" → 數字 → push -11 [10, 6, 12, -11] "*": y=-11 x=12→ push -132 [10, 6, -132] "/": y=-132 x=6→ 6/-132 = 0 [10, 0] (向零截斷) "*": y=0 x=10 → push 0 [0] 17 → push 17 [0, 17] "+": y=17 x=0 → push 17 [17] 5 → push 5 [17, 5] "+": y=5 x=17 → push 22 [22] // return 22
看 6 / -132 = 0:C++ 整數除法向零截斷,剛好符合題目要求。全程只是「數字進、運算子把頂端兩個收成一個」,一路收斂到 22。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
若輸入是中綴(含括號與優先序),要怎麼先轉成後綴?(提示:Shunting-yard,一樣用堆疊)
解答與說明 · ANSWER▾
用 Shunting-yard(調度場)演算法:掃中綴,數字直接輸出;運算子則和「運算子堆疊」頂端比優先序,較低/相等就先把頂端彈出輸出,再把自己 push;遇 ( push、遇 ) 一路彈到 (。掃完把運算子堆疊全彈出。輸出即後綴,再套本題的堆疊求值即可。整體 O(n)。
第 8 題13 分
若要防禦性處理「除以 0」或「token 不合法」,程式該在哪裡加檢查?回傳什麼?
解答與說明 · ANSWER▾
在取運算元之前檢查 st.size() >= 2(否則 token 不合法);在做 / 前檢查 y != 0。不合法時可回傳錯誤碼、丟例外,或依題目約定回傳。本題保證輸入合法、除數非 0,所以正式解可省略,但面試講出這些防禦點會加分。
第 9 題14 分
若數值可能溢位 int,該怎麼調整?哪個運算最容易溢位?
解答與說明 · ANSWER▾
把堆疊與運算改用 long long(累乘/累加最容易溢位,尤其 *)。若題目允許超出 64-bit,則需大數(BigInteger)。本題 LeetCode 保證中間與最終結果落在 32-bit,故 int 足夠;但養成「帶權/乘積一律 long long」的習慣可避免隱性溢位。
