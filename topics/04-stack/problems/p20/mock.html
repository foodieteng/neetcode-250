Hmm, let me think about this for a second.

This problem reminds me of a stack, because last-in-first-out is exactly what a stack gives me. Push openers; on a closer, the stack top must be its matching opener — pop if so, else fail. At the end, the stack must be empty.

Three checks cover the three ways to fail: a top mismatch, for wrong type or order; an empty stack on a closer, for an extra closer; and a non-empty stack at the end, for an extra opener. That's O(n).

class Solution {
public:
    bool isValid(string s) {
        stack<int> st;

        for (char c : s) {
            if (c == ')') {
                if (st.empty() || st.top() != '(') return false;
                st.pop();
            } else if (c == '}') {
                if (st.empty() || st.top() != '{') return false;
                st.pop();
            } else if (c == ']') {
                if (st.empty() || st.top() != '[') return false;
                st.pop();
            } else {
                st.push(c);                // opener → push
            }
        }

        return st.empty();                 // leftover openers → invalid
    }
};

One loop with three closer branches — ), }, ] — each checking that the stack is non-empty and the top is the matching opener, then popping. Anything else is an opener, so it gets pushed. After the loop, I return st.empty().

One thing worth flagging — the order inside each check, empty() first, then top(). The || short-circuits, so top() is never called on an empty stack.
