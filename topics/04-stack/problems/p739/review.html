重點回顧// RECAP

面向要點
問題本質下一個更大元素(next greater)的距離版
結構單調遞減堆疊,存索引
結算temp[i] > temp[top] → ans[top]=i−top,pop(連環)
比較嚴格 >(要更暖);相等不結算
預設ans(n,0):沒更暖的天天然為 0
複雜度時間 O(n) 攤還,空間 O(n)

觀念題// QUIZ

Q1. 為什麼堆疊要存索引而不是溫度?若存溫度會少了什麼、算不出什麼?
Q2. 為什麼堆疊裡的溫度一定由底到頂遞減?這個不變式是怎麼被維持的?
Q3. 為什麼「把 j pop 掉的那個 i」恰好是 j 之後第一個更暖的日子?(而不只是某個更暖的日子)
Q4. 比較用 > 還是 >= 有差嗎?什麼情況會導致答案不同?
Q5. while 是巢狀的,為什麼總時間仍是 O(n) 而非 O(n²)?

範例 Trace// [73,74,75,71,69,72,76,73]

// LeetCode 官方例,答案 [1,1,4,2,1,1,0,0](堆疊存索引) i0(73): push0 st=[0] i1(74): 74>73 ans[0]=1 pop0; push1 st=[1] i2(75): 75>74 ans[1]=1 pop1; push2 st=[2] i3(71): 71<75 push3 st=[2,3] i4(69): 69<71 push4 st=[2,3,4] i5(72): 72>69 ans[4]=1 pop4; 72>71 ans[3]=2 pop3; 72<75 push5 st=[2,5] i6(76): 76>72 ans[5]=1 pop5; 76>75 ans[2]=4 pop2; push6 st=[6] i7(73): 73<76 push7 st=[6,7] 剩 idx 6,7 → ans[6]=ans[7]=0 // ans = [1,1,4,2,1,1,0,0]
看 i6(76):它先結算 72(idx5,距離1),再結算 75(idx2,距離4)—— 75 從第 2 天等到第 6 天。 這正是單調堆疊「延後、連環結算」的威力。

應用題// APPLY

App 1. 若改問「下一個更暖是哪一天的索引」而非等幾天,程式要怎麼微調?
App 2. 若改成「之後第一個更冷的日子」,單調堆疊的方向(遞增/遞減)與比較符號要怎麼改?
App 3. 用「從右往左掃」也能解嗎?那版的堆疊語意與這版有何不同?
// ANSWERS
A1. 因為答案是等待天數 = 索引差 i − j。存索引才拿得到位置 j;要比較溫度時再用 temperatures[j] 去查即可。若只存溫度,結算時就不知道那天是第幾天,算不出距離。存索引是「一份資料兩用」:位置拿來算距離、值拿來比大小。
A2. 因為壓入 i 之前,已把所有 temp ≤ temp[i] 的頂端都 pop 掉(while 條件 temp[i] > temp[top])。所以壓入時,新頂端下方的那個一定 > temp[i],壓入後堆疊仍是「由底到頂遞減」。這個不變式每一步都被 while + push 共同維持。
A3. 反證:假設在 i 之前存在一天 k(j < k < i)比 j 暖。那 k 出現時,while 就會因為 temp[k] > temp[j] 把 j 結算並 pop 掉了 —— j 根本活不到 i。既然 j 一直留到 i 才被 pop,代表 j 與 i 之間沒有任何更暖的日子,i 就是第一個。
A4. 有差,取決於「相同溫度算不算更暖」。題目要更暖(strictly warmer),所以用 >:相等時不結算、把 i 直接壓入(它會排在相等者上面繼續等)。若誤用 >=,遇到相同溫度會把前一天當成「已遇更暖」而結算,距離就錯。凡是「嚴格 vs 非嚴格」的 next-greater 變體,比較符號都要對準題意。
A5. 攤還:每個索引一生最多被 push 一次、pop 一次。while 每轉一圈必定 pop 掉一個索引,而被 pop 的索引永久離場、不再進 while。因此跨整個外層迴圈,while 的總轉數 ≤ 總 pop 次數 ≤ n。外層 O(n) + while 合計 O(n) = O(n)。
App 1. 幾乎不用改:把 ans[st.top()] = i - st.top() 改成 ans[st.top()] = i(直接存那天的索引);「沒有更暖」的預設值改成 -1(或依約定)。堆疊與流程完全一樣,只是結算時記的內容從「距離」換成「索引」。
App 2. 求「之後第一個更冷」= next smaller。把堆疊維持遞增,while 條件改成 temp[i] < temp[st.top()](更冷才結算)。方向與符號同時反轉:「找更大→維持遞減、用 >」;「找更小→維持遞增、用 <」。距離一樣是 i − top。
App 3. 可以。從右往左掃時,堆疊存「右邊已看過、可能成為某天答案」的索引,維持遞減;對每個 i,先把 ≤ temp[i] 的 pop 掉(它們被 i 擋住,不會是左邊某天的下一個更暖),堆疊頂端若存在就是 i 的答案、距離 top − i,再把 i 壓入。語意不同:左掃版是「舊日等未來」,右掃版是「當下直接查右邊最近更暖」。兩者都 O(n)。
