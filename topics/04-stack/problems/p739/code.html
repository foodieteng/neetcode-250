class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n, 0);          // 預設 0:之後沒更暖就留 0
        stack<int> st;                    // 存「還在等更暖」的索引(溫度遞減)

        for (int i = 0; i < n; i++) {
            while (!st.empty() && temperatures[i] > temperatures[st.top()]) {
                ans[st.top()] = i - st.top();   // 距離 = 下標差
                st.pop();                          // 結算後移除,可連環
            }
            st.push(i);                          // i 進場等待
        }

        return ans;
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

三個關鍵:堆疊存 索引(才能算 i − top)、用 嚴格 >(要「更暖」)、ans 預設 0(留在堆疊沒被結算的天,答案天生是 0,不必特別處理)。
2

複雜度分析// COMPLEXITY

觀察成本說明
每索引 push ≤ 1O(n)外層一趟
每索引 pop ≤ 1O(n)結算一次即離場
ans / stackO(n)各一個長度 n
T = O(n)　　S = O(n)

while 看似巢狀,但總 pop ≤ n(每天只被結算一次),整體線性。

3

邊界與陷阱// PITFALLS

陷阱後果正解
堆疊存溫度而非索引 算不出等待天數(要下標差) 存 索引,距離 = i − st.top()
用 >= 比較 相同溫度被當「更暖」 要嚴格 >(更暖才算)
忘了 ans 預設 0 / 收尾清堆疊 沒更暖的日子答案未定 ans(n, 0),留在堆疊的天天然為 0
while 忘了 !st.empty() 空堆疊 top() → UB 守門先判非空
先 pop 再讀 st.top() 用錯索引算距離 先 ans[st.top()]=i-st.top() 再 pop

細節走讀// WALKTHROUGH

// [73,74,71,72,76](堆疊存索引,右=top) i=0 (73): 空 → push 0 st=[0] i=1 (74): 74>73 → ans[0]=1-0=1, pop 0 → push 1 st=[1] i=2 (71): 71>74? 否 → push 2 st=[1,2] 溫度 [74,71] 遞減 i=3 (72): 72>71 → ans[2]=3-2=1, pop 2;72>74? 否 → push 3 st=[1,3] i=4 (76): 76>72 → ans[3]=4-3=1, pop 3;76>74 → ans[1]=4-1=3, pop 1 → push 4 st=[4] 剩 idx 4 在堆疊 → ans[4]=0 // ans = [1,3,1,1,0]
看 i=4 (76) 這步:它一口氣結算了 72(距離1)和 74(距離3)兩天 —— 這就是「連環結算」。 74 從 i=1 一路等到 i=4 才遇到更暖,等待 4−1=3 天。
