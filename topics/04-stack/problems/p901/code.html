class StockSpanner {
public:
    stack<pair<int, int>> st;       // (price, span)· 價格由底到頂遞減

    StockSpanner() {}

    int next(int price) {
        int span = 1;                        // 至少含今天
        while (!st.empty() && st.top().first <= price) {  // 頂端 ≤ 今天 → 吃掉
            span += st.top().second;          // 整段 span 累加(不必重數)
            st.pop();
        }
        st.push({price, span});              // 今天成為新區塊
        return st.top().second;             // = span
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

核心是 span += st.top().second:被吃掉那格的 span 已經算好它代表幾天,直接累加就好。 用 <=(含等於)才會把等價的日子也吃進來;return st.top().second 等同 return span(剛 push 的就是它)。
2

複雜度分析// COMPLEXITY

觀察成本說明
每價 push ≤ 1O(1) 攤還每次 next 只 push 一格
每價 pop ≤ 1攤還被吃掉即永久離場
n 次呼叫O(n)總 pop ≤ n
next() = O(1) 攤還　　S = O(n)

while 看似巢狀,但一個價格被 pop 後不會再回來,總 pop 次數上限是呼叫數 n。

3

邊界與陷阱// PITFALLS

陷阱後果正解
只存 price 不存 span pop 後還得重數那段天數 → O(n)/次 存 (price, span),pop 時累加
比較用 < 等價的日子沒被算進 span 要 <=(≤ 今天都算)
先 pop 再累加 拿不到被 pop 那格的 span 先 span += top.second 再 pop
span 初值設 0 漏算今天自己 span = 1(含今天)
while 忘了 !st.empty() 空堆疊 top() → UB 守門先判非空

細節走讀// WALKTHROUGH

// next 100,80,70,75,85(堆疊右=top,格式 price:span) next(100): span=1 → push 100:1 st = [100:1] 回傳 1 next(80): 100 > 80 停 → push 80:1 st = [100:1, 80:1] 回傳 1 next(70): 80 > 70 停 → push 70:1 st = [100:1, 80:1, 70:1]回傳 1 next(75): 70<=75 吃1(span=2)pop;80>75 停 → push 75:2 st = [100:1, 80:1, 75:2] 回傳 2 next(85): 75<=85 吃2(span=3);80<=85 吃1(span=4);100>85 停 → push 85:4 st = [100:1, 85:4] 回傳 4 // span 序列 = [1,1,1,2,4]
next(85) 一次吃掉 75:2 和 80:1 —— 這兩格的 span 早已把「它們各自代表幾天」壓縮好,累加成 1+2+1=4。 這就是不必重數的關鍵:答案存在被吃掉的元素身上。
