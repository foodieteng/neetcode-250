重點回顧// RECAP

面向要點
問題本質往回找上一個嚴格更大價;span = 距離
結構單調遞減堆疊,存 (price, span)
結算top.price ≤ price → span += top.span,pop(連環)
比較<=:等價的日子也吃進來
初值span = 1(含今天)
複雜度攤還 O(1)/次,n 次 O(n),空間 O(n)

範例 Trace// next 100,80,60,70,60,75,85

// LeetCode 官方例,span=[1,1,1,2,1,4,6](格式 price:span,右=top) next(100): span1 → [100:1] → 1 next(80): 100>80 → [100:1, 80:1] → 1 next(60): 80>60 → [100:1, 80:1, 60:1] → 1 next(70): 60<=70 吃1(2);80>70 → [100:1,80:1,70:2] → 2 next(60): 70>60 → [100:1,80:1,70:2,60:1] → 1 next(75): 60<=75 吃1(2);70<=75 吃2(4);80>75 → [100:1,80:1,75:4] → 4 next(85): 75<=85 吃4(5);80<=85 吃1(6);100>85 → [100:1,85:6] → 6 // span = [1,1,1,2,1,4,6]
next(85) 回傳 6:它吞併了 75:4 和 80:1,加上今天 = 4+1+1=6。 注意 75:4 本身就已把它先前吃掉的 60、70 那幾天壓縮進去了 —— 一層層累積,永遠 O(1) 攤還。

應用題// APPLY

App 1. 這題與 739 每日溫度都是單調堆疊,兩者的堆疊「存什麼、比較方向」有何異同?為什麼 901 存 span、739 存索引?
App 2. 若改用「存索引 + 保留全部歷史價」也能算 span:怎麼寫?和「存 (price,span)」比,空間與思路差在哪?
App 3. 若把規則改成「嚴格小於今天」才算(<),對連續相同價的輸入,答案會怎麼變?程式改哪裡?
// ANSWERS
A1. 堆疊裡每格 (p, s) 代表「一段已壓縮好、往回 s 天都 ≤ p」的區塊,s 就是那段的天數。今天若 ≥ p,表示今天也 ≥ 那整段(p 是段內最大),於是可以整批把 s 天算進今天,不必逐天回頭數。答案早就存在被吃掉的元素身上,累加即可。
A2. 因為 push 今天之前,已把所有 price ≤ 今天 的頂端都 pop 掉,剩下的頂端一定 > 今天;push 後仍是「由底到頂遞減」。這個不變式由 while(吃掉 ≤ 的)+ push 共同維持,保證堆疊只留「一段段遞減的區塊代表」。
A3. 要 <=。題目定義 span 是「≤ 今天」的連續天數,等價的日子也算。若寫成 <,遇到和今天相同的價就不吃、停下,那些相等的日子被排除在 span 外 —— 少算。用 <= 才把等價日一併吞入,停在嚴格更大處。
A4. 因為要用的是被 pop 那格的 span。span += st.top().second 必須在 pop 之前讀取 top;若先 pop,top 就換成下一格,拿到的 span 是別格的、累加就錯。正確順序:讀 top.second 累加 → 再 pop。
A5. 攤還:每個價格一生最多被 push 一次、pop 一次。某次 next 的 while 即使 pop 了很多格,那些格永久離場、不會再被處理。把總成本分攤到 n 次呼叫:總 push ≤ n、總 pop ≤ n,合計 O(n),故平均每次 O(1)。單一次可能慢,但總量線性。
App 1. 相同:都是單調堆疊、都靠「今天 vs 頂端」決定 pop、複雜度都攤還 O(n)。不同在「答案形式」:739 要的是到未來第一個更暖的距離,結算發生在「未來那天」,所以存索引、用未來 i 減過去 index;901 要的是到過去第一個更大的距離,而且是 online(不能看未來),所以把「往回的天數」壓成 span 直接存,新價來就累加。方向相反(739 找更大在未來、901 找更大在過去),但同一套堆疊思想。
App 2. 存全部歷史價 prices 與一個索引單調堆疊 idx(價遞減)。next(price):把 prices[idx.top()] ≤ price 的 pop,若堆疊空 span = 目前天數(全部 ≤),否則 span = 今天index − idx.top();再 push 今天 index。空間同樣 O(n),但要多存整條 prices、且算距離要用 index 相減。相比之下「存 (price,span)」更直接:span 不必靠 index 推、也不需保留完整歷史值,常數更小。
App 3. 改 <= 為 < 後,「相同價」不再互相吞併。對連續相同價輸入(如 5,5,5),每個 5 的 span 都會是 1(只含自己),而非累加成 1,2,3。因為停在「≥ 今天」而不再吃相等者。改動只在 while 的比較符號一處;要不要含等於,完全看題目對「相等」的定義。
