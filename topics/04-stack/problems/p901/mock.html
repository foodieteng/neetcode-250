Hmm, let me think about this for a second.

A naive approach would be to store every price and walk backward on each call. That's O(n) per call, O(n²) overall.

This problem reminds me of a monotonic stack, and it fits because once a higher price arrives, the cheaper days before it can never stop a later span on their own. I keep a stack of (price, span) pairs, with prices decreasing. When today's price is ≥ the top price, I absorb that block's span instead of recounting its days. That makes each call amortized O(1).

class StockSpanner {
public:
    stack<pair<int, int>> st;       // (price, span), prices decreasing

    StockSpanner() {}

    int next(int price) {
        int span = 1;                        // includes today
        while (!st.empty() && st.top().first <= price) {  // top ≤ today → absorb
            span += st.top().second;          // add the whole block
            st.pop();
        }
        st.push({price, span});              // today becomes a new block
        return st.top().second;             // = span
    }
};

The class holds one stack of (price, span) pairs. In next, span starts at 1; a while loop folds in every block whose price is ≤ today's, then I push today's pair and return the top's span, which is exactly the span I just pushed. That matches the plan.

One thing worth flagging — I must read the top's span before popping, or I'd lose the count I'm folding in.
