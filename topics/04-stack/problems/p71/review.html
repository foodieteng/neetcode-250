重點回顧// RECAP

面向要點
做法以 / 切段 + 目錄堆疊
切段工具getline(ss, seg, '/'),空段自然出現
四種段空/. 跳過;.. 非空才 pop;其餘 push
關鍵坑...、.... 是名稱,不是上層
收尾由底到頂用 / 串;空堆疊回 /
複雜度時間 O(n),空間 O(n)

觀念題// QUIZ

Q1. 為什麼「先用 / 切段」能一次解決「多重斜線 //」和「首尾斜線」兩個邊界?切段後這些會變成什麼?
Q2. getline(ss, tok, '/') 遇到連續分隔符 // 會產生什麼?若不傳第三個參數 '/' 會怎樣?
Q3. 為什麼 ...、.... 要當普通目錄名 push,而不是往上?判斷條件該怎麼寫才不誤傷?
Q4. .. 在空堆疊(已在根目錄)時該怎麼處理?若無腦 pop 會怎樣?
Q5. 最後為什麼要特判「堆疊空 → 回 /」?什麼輸入會走到這條?

範例 Trace// /a/./b/../../c/

// getline 依 '/' 切段後逐段處理(st 底→頂) path = "/a/./b/../../c/" 段序: "" "a" "." "b" ".." ".." "c" "" "": 空 → 跳過 st = [] "a": push st = [a] ".": 跳過 st = [a] "b": push st = [a, b] "..": 非空 → pop st = [a] "..": 非空 → pop st = [] "c": push st = [c] "": 空 → 跳過 st = [c] 串接: '/' + c // return "/c"
兩個 .. 把 b、a 依序 pop 回根,再 push c。. 與首尾空段全被跳過。 切段 + 四類判斷,邊界一次收乾淨。

應用題// APPLY

App 1. 用 vector<string> 當堆疊取代 stack,收尾串接會更簡單嗎?寫出串接那段。
App 2. 不用 stringstream,改用 string::find / 手動掃 '/' 切段,要注意哪個容易漏的地方?(提示:最後一段)
App 3. 若是 Windows 風格用 \\ 當分隔、且要支援磁碟機代號(如 C:),你會怎麼調整切段與規則?
// ANSWERS
A1. 因為用 / 切段後,斜線本身就消失了,只剩「段」。連續 // 之間、以及開頭/結尾的斜線,都會切出空字串段;而我們對空段一律跳過。於是「多重斜線壓成一個」「首尾不留斜線」都自動達成,不必寫任何數斜線的特例。切段把格式問題轉成「處理四種段」的乾淨問題。
A2. 連續 // 會讓 getline 在兩個 / 之間讀到空字串 —— 也就是產生一個空段(我們跳過)。若不傳第三參數 '/',getline 預設用換行 '\n' 當分隔,整條路徑沒有換行 → 只會讀出一整段(= 原字串),切段失效。所以第三個參數 '/' 不可省。
A3. 規則裡只有剛好兩個點 .. 代表上層;. 是當前目錄;其餘任何序列(...、....、.a、a.…)都是合法名稱。所以判斷要用精確字串比對 seg == ".." 與 seg == ".",而不是「開頭是不是點」或「是不是全是點」。用精確比對,... 自然落到 else 分支被 push,不會誤刪。
A4. 根目錄的上一層還是根,所以空堆疊遇 .. 應直接忽略,不做事。程式用 if (!st.empty()) st.pop(); 保護。若無腦 st.pop(),對空 stack 呼叫 pop() 是未定義行為(可能崩潰),而且語意也錯(根不能再上去)。
A5. 因為若所有段都被跳過或 pop 光(如 "/"、"/../"、"/a/.."),堆疊會是空的。這時正確答案是根目錄 "/";但一般串接邏輯(用 / 接每個目錄)對空堆疊會產出空字串。所以要特判「空 → return "/"」,保證結果至少是根、且以 / 開頭。
App 1. 會更簡單。用 vector<string> st;,收尾:if (st.empty()) return "/"; string ans; for (auto& d : st) ans += "/" + d; return ans; —— 由前往後接、天然是正確順序,不必像 stack 那樣反向 '/'+top+ans。vector 也能直接 back()/pop_back(),功能與 stack 等價但更方便走訪。
App 2. 最容易漏的是最後一段:手動掃時只有遇到 '/' 才把 cur 收進結果,所以迴圈結束後要再 push 一次 cur(它是最後一個 / 之後、到字串結尾的段)。忘了補,末端目錄會遺失。其餘與 getline 版相同:空段/./.. /名稱四類。也要注意空段同樣會出現,一樣跳過。
App 3. 把分隔符換成 \\(或同時支援 /);切段邏輯不變。磁碟機代號 C: 視為路徑的固定前綴單獨保留(不參與 .. 回退超過它),可在切段前先剝離、最後再接回。此外 Windows 的 ../. 規則相同,但要決定大小寫、以及 .. 不可越過磁碟根。核心「切段 + 堆疊 + 四類」不變,只是前綴與分隔符要特別處理。
