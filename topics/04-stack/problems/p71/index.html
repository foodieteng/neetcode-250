題目簡介// THE QUESTION

QUESTION

給一個 Unix 絕對路徑,化簡成標準路徑:.=當前目錄、..=上層、多個 // 視為一個 /; 像 ...、.... 這種是合法目錄名。結果須以 / 開頭、目錄間單一 /、結尾不留 /(根目錄除外)。

把路徑用 / 切成一段段,只會出現四種段:空段(來自 // 或首尾)、.、..、一般名稱。 用堆疊模擬目錄:名稱 push、.. pop、空段與 . 跳過。最後串起來就是答案。

2

為什麼用堆疊// WHY THIS

A 在字串上直接刪改 易錯
用字串取代/回溯處理 ..,邊界(連續斜線、結尾)一堆特例,很容易漏。
× REJECT · 難維護
B 把 ... 也當上層 判斷錯
只有剛好 .. 才是上層;...、.... 是普通名稱,誤判會刪錯目錄。
△ REJECT · 規則錯
ADOPT
C 以 / 切段,目錄堆疊:名稱 push、.. pop、空/. 跳過 O(n)
切段後每段只需 == 比對四種情況。堆疊天然表示「目前所在目錄鏈」:.. 就是 pop(且空堆疊時忽略)。 最後由底到頂用 / 串起,空堆疊回 /。
● ADOPT · O(n)
3

核心策略 · 四種段// STRATEGY

  1. 切段:用 / 把 path 切成一段段(空段自然出現)。
  2. 空段 或 .:跳過(//、首尾、當前目錄都無作用)。
  3. ..:堆疊非空才 pop(回上層;已在根就忽略)。
  4. 其餘名稱(含 ...、....):push。最後用 / 串起,空則回 /。

四種段 · 為什麼這樣分// THE CASES

CASES · 切段後只剩四類,各自對應一個動作

用 / 切段後,斜線本身消失了,連續 // 會切出空段、首尾斜線也各造出一個空段 —— 全部跳過即可,不必特別處理「多重斜線」。.(當前目錄)同樣跳過。這兩類讓「規範化斜線」自動完成。

.. 是唯一會「往回」的:堆疊非空才 pop——若已在根目錄(空堆疊),.. 無效、直接忽略。最關鍵的陷阱:只有剛好兩個點 .. 才是上層;...、....、.foo 都是合法檔名,要 push。所以判斷要用 segment == ".." 的精確比對,而不是「開頭是點」。
