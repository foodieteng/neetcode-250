最小堆疊

重點回顧// RECAP

面向要點
目標push/pop/top/getMin 全 O(1)
核心每格存 (val, minSoFar),min 隨元素進出
push空 → (val,val);否則 (val, min(val, top.min))
getMin讀 top().second,O(1)
不變式每格 min = 「這格與底下所有格」的最小
為何 pop 後正確新 top 早已握著它那時的 min,不必還原

觀念題// QUIZ

Q1. 為什麼「用一個變數 minVal 記全域最小」這個直覺做法會壞?壞在哪個操作?
Q2. 每格的 min 到底代表什麼範圍的最小?為什麼「讀 top 的 min」就等於整個堆疊的最小?
Q3. 為什麼 pop 之後不需要任何「重算 / 還原最小值」的動作?
Q4. 若不想每格都存 min(嫌浪費空間),還有什麼等價做法?各有什麼取捨?
Q5. push 對空堆疊沒特判會發生什麼事?為什麼?

範例 Trace// push 5,2,7,1 · getMin · pop · getMin

// 操作序列(堆疊由左到右,右=top) push(5): (5,5) push(2): (5,5) (2,2) min(2,5)=2 push(7): (5,5) (2,2) (7,2) min(7,2)=2 ← 7 大,沿用 2 push(1): (5,5) (2,2) (7,2) (1,1) min(1,2)=1 getMin(): top=(1,1) → 1 pop(): (5,5) (2,2) (7,2) 移除 (1,1) getMin(): top=(7,2) → 2 ← 自動退回 top(): top=(7,2) → 7 // OUTPUT: getMin 依序回 1、2
看 push(1) 讓 min 降到 1,pop 之後 getMin 立刻回到 2 —— 因為 (7,2) 這格從一開始就記著 2。 整個過程沒有任何「掃描」或「還原」,全是讀 top。

應用題// APPLY

App 1. 改成同時支援 getMax:要怎麼改?每格要存幾個欄位?
App 2. 用兩個堆疊(一個存值、一個存目前最小)實作,pop 時要注意什麼?何時「min 堆疊」才需要一起 pop?
App 3. 若要「省空間」:當新值嚴格大於目前最小時,min 堆疊可以不 push。這樣 pop 的判斷要怎麼寫才正確?(提示:相等時的處理)
// ANSWERS
A1. 壞在 pop。單一 minVal 只記得「當前最小是多少」,卻沒記「移除它之後,次小是多少」。當 pop 掉的正好是最小值,minVal 就失去依據、無法還原成上一個最小。要嘛把 min 存進每一格(隨結構回溯),要嘛另開一個 min 堆疊同步 pop。
A2. 第 i 格的 min = 堆疊底到第 i 格(含)的最小值。因為 push 時取 min(val, 舊 top.min),這條遞迴把「底下累積的最小」一路傳上來。於是 top 那格的 min = 底到 top = 整個堆疊的最小,讀 top 即答案。
A3. 因為每格的 min 是入堆疊當下就算好、且只描述「它與底下」的最小,與上面的元素無關。pop 掉 top 後,新 top 的 min 仍然如實描述「底到它」——本來就是剩餘堆疊的正確最小,不需要任何重算或還原。
A4. 用兩個堆疊:一個存值 s,一個存目前最小 mins。push 時 mins.push(min(val, mins.top()));pop 時兩個一起 pop;getMin 讀 mins.top()。取捨:和「每格存 pair」空間相同(都 O(n) 額外),但可進一步優化成「只在 val ≤ mins.top() 時才 push min 堆疊」以省空間(見 App3)。pair 版程式更短、無需同步兩個容器。
A5. 空堆疊時 getMin() 會呼叫 st.top(),但 st 是空的 → top() 是未定義行為(UB),可能崩潰或讀到垃圾。所以第一個元素要特判:空時直接 min = val、建出第一格 (val, val),之後才有 top 可讀。
App 1. 每格改存 (val, minSoFar, maxSoFar)(或用 struct / 三個平行堆疊)。push 時 minSoFar = min(val, top.min)、maxSoFar = max(val, top.max)。getMin/getMax 各讀 top 的對應欄位,仍全 O(1)。
App 2. 值堆疊與 min 堆疊同步 pop:每次 push 都往 min 堆疊放 min(val, mins.top()),pop 時兩個一起彈。這樣兩堆疊高度一致、min 堆疊頂端恆為當前最小。若採「省空間版」(只在需要時 push min),就不能無腦同步 pop —— 見 App3。
App 3. 省空間版:只在 val ≤ mins.top()(注意含等號)時才 mins.push(val)。pop 時,若被彈出的值 == mins.top(),才一起 mins.pop()。等號是關鍵:若有重複的最小值卻只 push 一次,pop 第一個時就會把 min 提前彈掉,導致還有一個相同最小值還在、min 卻錯。用 ≤ push、相等時一起 pop,才對重複最小值安全。
