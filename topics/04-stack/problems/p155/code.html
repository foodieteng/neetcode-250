完整實作 · pair 堆疊// (val, min)

p155.cpp C++17 
class MinStack {
public:
    stack<pair<int, int>> st;       // 每格 = (值, 到此為止的最小)

    MinStack() {}

    void push(int val) {
        if (st.empty()) {                // 空堆疊:min 就是 val 自己
            st.push(make_pair(val, val));
            return;
        }

        int curMin = this->getMin();       // 舊 top 的 min
        if (curMin > val) curMin = val;    // min(val, 舊 min)

        st.push(make_pair(val, curMin));
    }

    void pop() {
        st.pop();
    }

    int top() {
        return st.top().first;          // 值
    }

    int getMin() {
        return st.top().second;         // 最小 —— O(1),不用掃
    }
};

🎤 面試模擬 · UMPIRE mock interview transcript ↗

push 是唯一有邏輯的地方:空堆疊時 min = val;否則 min(val, 舊 top.min)。其餘三個操作都只是讀/彈 top。 getMin 直接回 top().second —— 答案早就存好了。

複雜度分析// COMPLEXITY

操作成本說明
pushO(1)一次比較 + 一次 push
pop / top / getMinO(1)只碰 top
SpaceO(n)每格多一個 int(min)
四個操作 = O(1)　　空間 = O(n)

用「每格存 min」把 getMin 從 O(n) 降到 O(1),代價是每格多一個 int。

3

邊界與陷阱// PITFALLS

陷阱後果正解
用單一變數 minVal 記最小 pop 掉最小後無法還原次小 把 min 存進每一格(或用第二個 min 堆疊)
push 空堆疊沒特判 getMin() 對空 top() → UB 空時 min = val 先建第一格
getMin 掃整個堆疊 O(n)/次,違反要求 讀 top().second,O(1)
只存 val,min 另外算 pop 後 min 失去記憶 min 與 val 綁在同一格一起進出

細節走讀// WALKTHROUGH

// push 5,2,7,1 → 每格的 (val, min) push(5): 空 → (5, 5) 堆疊: (5,5) push(2): min(2, 5)=2 → (2, 2) 堆疊: (5,5)(2,2) push(7): min(7, 2)=2 → (7, 2) 堆疊: (5,5)(2,2)(7,2) push(1): min(1, 2)=1 → (1, 1) 堆疊: (5,5)(2,2)(7,2)(1,1) getMin() = top.second = 1 每格的 min = 「它與底下所有格」的最小
// pop 之後 min 自動退回 pop(): 移除 (1,1) → top = (7, 2) getMin() = top.second = 2 ← 自動正確,不必重算 理由: (7,2) 這格在 push 當下就記著「底到它」的最小 = 2
注意 push(7):7 比舊 min 2 大,所以這格存 (7, 2) —— 沿用舊 min。 正因為每格都自帶 min,pop 後不論彈掉的是不是最小值,新的 top 都已握著正確答案。
