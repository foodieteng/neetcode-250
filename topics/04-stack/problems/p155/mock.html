Here's the plan.

// each cell = (value, min of this cell and everything below)
push(v): if empty → (v, v); else → (v, min(v, top.min))
getMin(): top.min    top(): top.value    pop(): pop

One: each cell holds the value and the minimum of this cell and everything below it.
Two: on push, if the stack is empty store the value twice, otherwise store the value with min(v, top.min).
Three: top reads the value, getMin reads the min, and pop just pops.

One thing worth flagging — the invariant. Each cell's stored min is the minimum of itself and everything below it. So the top's min is the whole stack's min. And after a pop, the new top already holds the right answer, with no recompute.

Alright, let me code this up. The stack holds pairs of value and min so far.

class MinStack {
public:
    stack<pair<int, int>> st;       // each cell = (value, min so far)

    MinStack() {}

    void push(int val) {
        if (st.empty()) {                // empty stack: min is val itself
            st.push(make_pair(val, val));
            return;
        }

        int curMin = this->getMin();       // old top's min
        if (curMin > val) curMin = val;    // min(val, old min)

        st.push(make_pair(val, curMin));
    }

    void pop() {
        st.pop();
    }

    int top() {
        return st.top().first;          // value
    }

    int getMin() {
        return st.top().second;         // min — O(1), no scan
    }
};

push is the only method with logic: on an empty stack the value is its own min; otherwise I read the old top's min through getMin(), take the smaller of that and val, and push the pair. pop, top and getMin each touch only the top.

One thing worth flagging — the empty-stack guard in push is essential. Without it, the very first push would call getMin(), which reads top() on an empty stack. That's undefined behavior.

The row that matters is the pop. Popping (1,1) exposes (7,2), whose stored min is 2 — set back when 7 was pushed, because 7 is bigger, so it carried the old min forward. So getMin instantly returns 2, with no recompute.

Let's also test corner cases.

• Push, pop to empty, and push again works: the guard rebuilds the first cell.
• Repeated minimums like 2,2 also work, since each cell carries its own min.
