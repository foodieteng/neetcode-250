重點回顧// RECAP

面向要點
模型正數向右、負數向左;絕對值 = 大小
唯一相遇左邊正 + 右邊負 ⟺ 堆疊 top > 0 && ast < 0

存活survived 為真才 push

觀念題// QUIZ

Q1. 為什麼 while 的守門是 top > 0 && ast < 0?其他方向組合(兩正、兩負、負左正右)為什麼一定不撞?
Q2. 三個分支裡,哪一個不 break?為什麼「top 較小」時要讓 ast 繼續?
Q3. survived 這個旗標在做什麼?若把最後的 if (survived) push 改成無條件 push 會怎樣?
Q4. 為什麼「相等」那個分支要 pop 掉 top?若忘了 pop 只設 survived=false 會錯在哪?
Q5. while 看起來像巢狀迴圈,為什麼整體仍是 O(n)?用攤還說明。

範例 Trace// [8, -4, 6, -6, -10]

// 逐顆處理(堆疊右=top) ast=8: 空 → push st = [8] ast=-4: top=8>0 & ast<0 撞;8 > 4 → ast 炸,break;survived=false → 不 push st = [8] ast=6: top=8>0 但 ast=6>0 → while 不進;survived=true → push → st = [8, 6] ast=-6: top=6>0 撞;6 == 6 → pop 6、兩爆,break;survived=false → st = [8] ast=-10: top=8>0 撞;8 < 10 → pop 8(不 break);堆疊空 → while 停 survived=true → push → st = [-10] 倒出 + reverse // OUTPUT: [-10]
-10 那步展示了「連環撞後存活」:先炸掉 8,若堆疊還有正數會繼續撞,直到撞不動(空、或頂端是負數、或頂端更大)。 這裡撞到空 → -10 存活。

應用題// APPLY

App 1. 若規則改成「相等時兩顆都存活(擦身而過)」,程式要改哪裡?
App 2. 若小行星可能是 0(靜止,不動也不撞),要如何處理才不破壞邏輯?
App 3. 若問「共發生幾次爆炸(destroy 事件數)」而非最終狀態,怎麼在同一趟裡順便統計?
// ANSWERS
A1. 相撞需要「相向而行且會相遇」。在陣列由左到右的位置關係下,只有左邊向右(+)、右邊向左(−) 兩顆會越靠越近而碰撞。兩正(同向右)、兩負(同向左)永遠等速同向不追撞;「負在左、正在右」則背向而行、越離越遠。用堆疊逐顆入場時,「左邊那顆」正是堆疊頂端、「右邊新來的」正是 ast,所以守門是 top > 0 && ast < 0。
A2. 只有「top 較小」那個 else { pop(); } 分支不 break。因為此時 top 被炸掉,但 ast 這顆還活著、還在往左飛,可能繼續撞到堆疊裡下一顆正數 —— 所以要留在 while 裡再比一次。另外兩個分支(相等、top 較大)都讓 ast 消失或停下,故 break。
A3. survived 記錄「ast 跑完 while 後是否還活著」。while 只負責「撞掉沿路的正數」或「判定 ast 爆炸」;離開 while 後,唯有 ast 沒被判爆(survived)才該入堆疊。若無條件 push,已經爆炸的 ast 會被錯誤放回堆疊,答案就多出不該存在的小行星。
A4. 相等代表兩顆同歸於盡:ast 沒了(survived=false),top 也該消失。若只設 survived=false 卻忘了 pop,那顆本該爆炸的 top 會留在堆疊裡 —— 例如 [8,-8] 會錯誤輸出 [8] 而非 []。所以相等分支要 pop() + break。
A5. 用攤還分析:每顆小行星一生最多被 push 一次、被 pop 一次。while 內每轉一圈(else 分支)都會 pop 掉一顆,而一顆被 pop 後就永久離場、不會再進 while。所以跨整個外層迴圈,while 的總轉數 ≤ 總 pop 次數 ≤ n。外層 O(n) + while 總計 O(n) = O(n),不是 O(n²)。
App 1. 把「相等」分支拿掉(或改成不 pop、不設 survived)。當 top == abs(ast) 不再視為碰撞結算,而是「擦身而過」:此時應停止對撞(ast 穿過不了同大小的?)——依新規則而定。若「相等雙方都存活且互不影響」,則把守門後的比較改為只在 top < abs(ast) 時 pop 續撞、top > abs(ast) 時 ast 爆、top == abs(ast) 時 break 讓 ast 存活入堆疊。核心是重新定義相等的處置。
App 2. 0 靜止:它不主動撞人,也不會被「方向」納入 top > 0 && ast < 0 的判斷(0 既非正也非負)。實務上 LeetCode 735 保證非 0;若允許 0,最簡單是把 0 直接略過不入堆疊(靜止物不參與),或視題意當「不可摧毀的牆」特判。關鍵是別讓 0 誤入 ast < 0 或 top > 0 的分支。
App 3. 設一個計數器 boom。每當有小行星爆炸就 +1:「相等」分支 +2(兩顆);「top 較大」分支 +1(ast);「top 較小」的 pop +1(top)。注意「相等」只算一次事件+2、其餘每次 pop/判爆各 +1。在原本的三個分支各加對應計數即可,不需額外遍歷。
