Hmm, let me think about this for a sec.

A single running string won't work — an inner [ would clobber the outer prefix and count.

This problem reminds me of parsing nested parentheses with a stack: every [ starts a new context, and every ] finishes the most recent one, which is last in, first out. So a stack of (prefix, count) pairs handles it. Each open bracket pushes the outer state; each close bracket pops it and folds the inner string in. It mirrors recursion.

Here's the plan.

// curr = current level's string, repeat = pending count
digit  → repeat = repeat*10 + (c-'0')
'['    → push (curr, repeat); reset curr="", repeat=0
letter → curr += c
']'    → (prev, k) = pop; curr = prev + curr*k

One: a digit grows the pending count, repeat*10 + digit; a letter appends to curr.
Two: a [ pushes (curr, repeat), then resets both.
Three: a ] pops (prev, k), and sets curr = prev + curr×k.

One thing worth flagging — two details. Digits accumulate with *10 for multi-digit counts. And on close I write prev + curr*k, prefix first — reversing it would misplace the outer text.

Alright, let me code this up. One pass over the characters with four branches — [, ], letter, and digit — with a stack<pair<string, int>> holding the outer levels. On a ] I pop the pair, build the inner string k times, and glue it after the prefix.

class Solution {
public:
    string decodeString(string s) {
        string curr = "";
        int repeat = 0;
        stack<pair<string, int>> st;       // (outer prefix, count)

        for (char c : s) {
            if (c == '[') {
                st.push({curr, repeat});          // save the outer state
                repeat = 0; curr = "";        // inner level starts clean
            } else if (c == ']') {
                auto [prev, k] = st.top(); st.pop();  // get the outer level back
                string res = "";
                for (int i = 0; i < k; i++) res += curr;  // inner × k
                curr = prev + res;                 // prefix + expansion
            } else if (isalpha(c)) {
                curr += c;                        // letter joins the current level
            } else {
                repeat = repeat * 10 + (c - '0'); // multi-digit
            }
        }

        return curr;
    }
};

One thing worth flagging — after pushing on [ I reset both curr and repeat, so the inner level starts clean while the outer state waits safely on the stack. Forget the reset and the inner count would keep the outer digits.

• Sequential blocks 2[abc]3[cd]ef — the trailing ef just appends to curr.
• Multi-digit 100[a] gives 100 a's.

Let me think about complexity.

Time is driven by N, the output length: every ] copies its level's result once, so a character is recopied once per level it sits inside — that's O(N × depth), effectively O(N) for shallow nesting. Space is O(N) for the stack and the built strings.

Oh, one more thing — the equivalent recursive parser is shorter: return on ], recurse on [. Each stack frame here is exactly one recursion frame.
