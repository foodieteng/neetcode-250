PART A · 觀念題// 5 題 × 10 分

第 1 題10 分
為什麼遇到 [ 時,必須把 curr 和 repeat 兩個都壓進堆疊?各自代表什麼、之後怎麼用?
解答與說明 · ANSWER▾
curr 是「外層在這個 [ 之前已累積的前綴」,repeat 是「這個內層要重複幾次」。兩者都要等內層掃完、遇到對應 ] 時才用:那時 curr = prev + 內層×k。若只存一個,就會缺前綴(接錯位置)或缺次數(不知重複幾次)。所以進入 [ 必須把兩者一起保存。
第 2 題10 分
] 的展開為什麼是 curr = prev + curr×k 而不是 curr×k + prev?順序反了會錯在哪?
解答與說明 · ANSWER▾
因為外層前綴在時間上先出現、應排在展開結果前面。例如 a2[c]:外層前綴是 a,內層 c×2=cc,正確結果是 a 接 cc = acc。若寫成 curr×k + prev 會得 cca,順序全反。所以是 prev + res。
第 3 題10 分
為什麼數字要 repeat*10 + (c−'0')?單看一位會在什麼輸入上出錯?
解答與說明 · ANSWER▾
因為 k 可能多位數(題目 k 可達 300)。逐字元掃到數字時,用 repeat = repeat*10 + (c−'0') 才能把 1、0、0 累積成 100。若只讀一位,100[x] 會被當成重複 1 次、再把 0、0 當成別的東西,徹底錯亂。
第 4 題10 分
[ 之後為什麼要把 curr、repeat 清空?不清會怎樣?
解答與說明 · ANSWER▾
因為 [ 代表「開始蒐集全新的內層字串、次數也重新算」。curr 不清空,內層會混入外層殘留的字元;repeat 不歸零,下一個內層的次數會接續累加到舊值上。push 保存之後立刻清空,才能讓內層從乾淨狀態開始,而外層狀態安全躺在堆疊裡等它回來。
第 5 題10 分
這題和用遞迴解有什麼對應關係?堆疊裡的一格相當於遞迴的什麼?
解答與說明 · ANSWER▾
完全對應遞迴:每個 [ 相當於「進入一次遞迴呼叫」,堆疊那一格保存的 (prev, k) 就是呼叫者的區域變數(外層前綴與次數);] 相當於「函式返回」,把內層結果乘上 k、接回呼叫者。顯式堆疊只是把遞迴的呼叫堆疊手動攤開,兩者時間/空間同階。

PART B · 手走模擬// 1 題 × 10 分

第 6 題10 分
拿一張紙,照程式手走 2[abc]3[cd]ef:逐步寫出關鍵變數的變化,最後回傳什麼?決定結果的是哪一步?
解答與說明 · ANSWER▾
// 平行 + 尾綴的例子(st 存 (prev,k)) '2': repeat=2 '[': push ("",2); curr="", repeat=0 st=[("",2)] 'a''b''c':curr="abc" ']': pop ("",2); curr = "" + "abc"×2 = "abcabc" st=[] '3': repeat=3 '[': push ("abcabc",3); curr="", repeat=0 st=[("abcabc",3)] 'c''d': curr="cd" ']': pop ("abcabc",3); curr = "abcabc" + "cd"×3 = "abcabccdcdcd" st=[] 'e''f': curr="abcabccdcdcdef" // return "abcabccdcdcdef"
注意第二個 [ 壓入的前綴是 "abcabc"(前一段的展開結果)—— 所以尾巴 3[cd] 展開後正確接在它後面。 最後的 ef 沒有括號,直接接到 curr。堆疊讓「一段接一段」與「巢狀」用同一套規則處理。

PART C · 應用題// 3 題 × 13–14 分

第 7 題13 分
用遞迴 / 指標改寫(不用顯式堆疊):函式簽名與回傳邊界(遇 ] 返回)怎麼設計?
解答與說明 · ANSWER▾
string decode(const string& s, int& i):從位置 i 開始掃,遇 ] 就返回目前累積的字串(並讓呼叫端跳過 ])。掃到數字先讀完整個 k,遇 [ 就 i++ 遞迴取得內層 sub,把 sub×k 接到結果;字母直接接。主函式從 i=0 呼叫。這與堆疊版一一對應,程式更短但受遞迴深度限制。
第 8 題13 分
這裡用一個 (string, int) 堆疊。另種常見寫法用兩個堆疊(字串堆疊 + 次數堆疊),兩者等價嗎?各有何取捨?
解答與說明 · ANSWER▾
等價。兩堆疊版:遇 [ 時 strStack.push(curr)、numStack.push(repeat) 再清空;遇 ] 時 k=numStack.top()、curr = strStack.top() + curr×k 並各自 pop。和「一個 (string,int) 堆疊」只是把兩欄拆成兩容器,語意相同。取捨:pair 版一次 push/pop、耦合清楚;兩堆疊版有時更好讀,但要小心兩者永遠同步 push/pop,否則錯位。
第 9 題14 分
若輸出可能很大導致頻繁字串複製很慢,如何降低常數?(提示:預留容量 / 用 reserve 或改接到外層時避免重建)
解答與說明 · ANSWER▾
主要成本在 res += curr 的重複複製與 prev + res 的重建。可在展開前 res.reserve(curr.size()*k) 一次配足;或用 curr = std::move(prev); curr.reserve(...); 迴圈 append 內層 減少臨時物件。更進階可改成「輸出到單一結果緩衝 + 記錄各層起點/次數」的作法,避免每層重建字串。本題 N ≤ 10⁵,單純寫法已足夠,但講出這些優化點在面試會加分。
