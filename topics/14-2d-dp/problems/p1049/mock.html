Key reframe. Every smash is a subtraction, so if I unroll the whole game, each stone ends up with a + or a − sign, and the leftover is |Σ ±stone|. That's the same as splitting the stones into two piles and taking the difference of their sums. To minimize the difference, I want one pile as close to total/2 as possible.

This problem reminds me of 0/1 knapsack subset-sum: each stone is used at most once, and the question is which sums are reachable. A greedy "smash the two biggest" doesn't optimize globally.

One: compute total, and set target = total / 2, rounded down.
Two: run a boolean knapsack, where dp[s] says whether some subset sums to s, scanning each stone from the target down, and track the best reachable sum.
Three: return total − 2*best.

One thing worth flagging — best is the largest reachable sum not exceeding total/2, so it's the smaller pile; the other pile is total − best, so the gap is total − 2*best. By symmetry I never need sums above half. Does this approach sound good, or would you rather I think of another way?

Alright, let me code this up. The boolean knapsack: a table up to the target, dp[0] = true, and for every stone I mark i reachable if i − stone was, updating best as I go.

class Solution {
public:
    int lastStoneWeightII(vector<int>& stones) {
        int total = accumulate(stones.begin(), stones.end(), 0);
        int target = total / 2;              // aim one pile at half

        vector<bool> dp(target + 1, false);
        dp[0] = true;
        int best = 0;

        for (int stone : stones) {
            for (int i = target; i >= stone; i--) {  // high to low → each stone once
                dp[i] = dp[i] || dp[i - stone];
                best = dp[i] ? max(i, best) : best; // largest reachable subset sum
            }
        }

        return total - 2 * best;            // gap between the two piles
    }
};

Then a bitset variant — same idea, about 64× faster: dp << s, OR-ed back, adds s to every reachable sum at once, and I scan down from the target for the first set bit.

class Solution {
public:
    int lastStoneWeightII(vector<int>& stones) {
        int total = accumulate(stones.begin(), stones.end(), 0);
        int target = total / 2;

        bitset<1501> dp; dp[0] = 1;       // 30×100/2 = 1500 cap
        for (int s : stones) dp |= dp << s;  // every reachable x → x+s reachable too

        for (int i = target; i >= 0; i--)
            if (dp[i]) return total - 2 * i;       // first hit from the top = best
        return total;
    }
};

Both are O(n · total). One thing worth flagging — the inner loop must run high to low, or a stone gets reused and it becomes unbounded knapsack.
