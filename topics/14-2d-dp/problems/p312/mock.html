Hmm, let me think about this for a second.

A naive approach would try every burst order, which is n!. The natural instinct is to pick which balloon to burst first and recurse — but that breaks. When I burst balloon k first, its left and right neighbours become adjacent, so the two halves merge and I can't split into independent subproblems.

This problem reminds me of interval DP, where you split a range at a pivot. The fix is to reverse the question: which balloon bursts last? If k is the last to pop in some range, everything else in that range is already gone, so its neighbours are exactly the range's two boundaries. That coin value is fixed. And because k survived the whole time, it acted as a wall splitting the range into two halves that never interfered.

I'll pad nums with a 1 on each end, so every balloon has neighbours and there's no boundary special-casing. Then I use an open interval:

// dp[i][j] = max coins bursting all balloons strictly between i and j
// (i and j themselves are NOT burst — they're the walls)
dp[i][j] = max over k in (i, j) of
    dp[i][k] + dp[k][j] + nums[i]*nums[k]*nums[j]

dp[i][j] is the max coins from bursting every balloon strictly between i and j — i and j themselves are not burst; they're the walls. It's the max over k between them of dp[i][k] + dp[k][j] + nums[i]·nums[k]·nums[j].

The open interval makes the split seamless: k is the right wall of the left piece and the left wall of the right piece at the same time, so the two pieces tile (i, j) exactly. The answer is dp[0][n+1].

class Solution {
public:
    int maxCoins(vector<int>& nums) {
        int n = nums.size();
        // dp[i][j] = max coins bursting everything in open (i,j); i, j stay as walls
        vector<vector<int>> dp(n + 2, vector<int>(n + 2, 0));

        nums.insert(nums.begin(), 1);    // pad both ends with 1 as sentinel walls
        nums.push_back(1);              // indices now 0..n+1

        for (int L = 1; L <= n; L++) {              // L = #balloons inside (i,j)
            for (int i = 0; i + L + 1 <= n + 1; i++) {
                int j = i + L + 1;              // exactly L balloons between i and j
                for (int k = i + 1; k < j; k++) {   // k = last to burst
                    dp[i][j] = max(dp[i][j],
                        dp[i][k] + dp[k][j] + nums[i] * nums[k] * nums[j]);
                }
            }
        }
        return dp[0][n + 1];                   // the whole open interval, all burst
    }
};

After padding, the indices run from 0 to n+1. The outer loop is L, the number of balloons inside the open interval; the middle loop is the left wall i; the inner loop is k, the last balloon to burst.

One thing worth flagging — j = i + L + 1, not i + L, because the two walls each take an index on top of the L balloons inside. Get that off by one and dp[0][n+1] never gets filled. That's O(n³) time — O(n²) intervals times an O(n) choice of k — and O(n²) space.

Because k is the last to go in this range, so its original neighbours k-1, k+1 are already burst by then. The balloons still standing next to it are the range's untouched walls i and j. That's precisely why the value is fixed and can serve as a DP transition — i and j never burst within this subproblem, so they're stable anchors. Using k-1, k+1 would be the "current neighbours" thinking that this whole reframe exists to escape.
