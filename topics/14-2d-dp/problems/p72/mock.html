Hmm, let me think about this for a second.

A naive approach would recurse on the three choices at every mismatch, which branches three ways and blows up exponentially.

This problem reminds me of two-string prefix DP: a grid where cell (i, j) only cares about the first i characters of word1 and the first j characters of word2, and each cell depends on its neighbours.

Let dp[i][j] = min operations to turn word1[0..i) into word2[0..j). The elegant part is that the three operations map to the three neighbours of a cell.

I
INTERVIEWER

Spell out that mapping.

C
CANDIDATE

When word1[i-1] != word2[j-1], I take 1 + min of three sources:

up    dp[i-1][j]   → delete word1[i-1]  // consume word1
left  dp[i][j-1]   → insert word2[j-1]  // consume word2
diag  dp[i-1][j-1] → replace           // consume both

Up is a delete of word1's character, left is an insert of word2's character, diagonal is a replace.

The rule is "whichever string an operation consumes, that index steps back." Delete only touches word1, so i retreats (up); insert only touches word2, so j retreats (left); replace touches both (diagonal). And when the characters match, they align for free: dp[i][j] = dp[i-1][j-1] with no +1.

P — plan
C
CANDIDATE

Base cases are the distance to the empty string:

dp[i][0] = i  // delete all i chars of word1
dp[0][j] = j  // insert all j chars of word2
answer   = dp[m][n]

The first column is i: delete all i characters of word1. The first row is j: insert all j characters of word2.

So, the plan.
One: build an (m+1) × (n+1) table and fill both edges.
Two: fill row by row — free diagonal on a match, otherwise 1 + min(up, left, diag).
Three: return dp[m][n].

Does this approach sound good, or would you rather I think of another way?

class Solution {
public:
    int minDistance(string word1, string word2) {
        int m = word1.size(), n = word2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));

        for (int i = 1; i <= m; i++) dp[i][0] = i;   // word2 empty → delete all
        for (int j = 1; j <= n; j++) dp[0][j] = j;   // word1 empty → insert all

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (word1[i - 1] == word2[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1];              // match → free diagonal
                } else {
                    dp[i][j] = min({dp[i - 1][j],       // up   → delete
                                    dp[i][j - 1],       // left → insert
                                    dp[i - 1][j - 1]})  // diag → replace
                               + 1;
                }
            }
        }
        return dp[m][n];
    }
};

Two loops set the edges, then a double loop fills the table: on a match, copy the diagonal; otherwise, one plus the min of up, left and diagonal, written as a single min({a, b, c}) over a three-element list.

One thing worth flagging — the + 1 sits outside the min, and it only applies to the mismatch branch. It's O(mn) time and space, and it compresses to O(n) with a single rolling row plus a temp that saves the diagonal before it's overwritten.

I
INTERVIEWER

Why no +1 when the characters match?

C
CANDIDATE

Because a matching pair already aligns — no operation is needed to reconcile them, so I just inherit dp[i-1][j-1] unchanged. It's the only zero-cost transition in the table, and it's what lets the distance drop below max(m, n). If I forced a +1 there, I'd be charging for characters that were already correct.

Let me think about complexity here.

Time and space are both O(mn), and space is reducible to O(min(m, n)) — I'd pick the shorter string as the inner dimension, which is safe because the distance is symmetric.

Oh, one more thing — the structure generalizes cleanly. Weighted edit distance just replaces each +1 with per-operation costs — that's the spell-check and DNA-alignment model. And if replacement were banned, this collapses to m + n − 2·LCS, since the common subsequence is what you keep and everything else is one delete or one insert. Replace is exactly the shortcut that separates this from LCS.
